# tool/docs — парность двуязычной документации (§360)

Запускается из `app/`. CI гоняет в job `checks`
(`.github/workflows/ci.yml`, шаг «Docs parity») — **с `--strict` на каждом
push/PR**.

```
dart run tool/docs/parity_check.dart [--strict]
```

## Зачем

Документация ведётся парами RU/EN:

| EN | RU |
|---|---|
| `README.md` | `README_RU.md` |
| `docs/USER_GUIDE.md` | `docs/USER_GUIDE_RU.md` |

Рабочий порядок — «правим русский, потом переводим», поэтому типовое
расхождение выглядит так: раздел дописали в один язык и забыли во второй. Глазами
это не ловится: оба файла валидны сами по себе, а читатель второго языка просто
не узнаёт, что раздел существует. Чекер сравнивает **скелет**, а не слова.

## Что проверяется

| Проверка | Уровень | Что означает срабатывание |
|---|---|---|
| Число разделов (`##`…`######`) совпадает | fail | Раздел добавлен в один язык и не перенесён во второй |
| Последовательность уровней заголовков совпадает | fail | Раздел вставлен на другом уровне вложенности или потерян |
| Число блоков ``` ``` ``` совпадает | fail | Пример/ASCII-схема потеряна при переводе |

Тексты заголовков **не** сравниваются: `## Recipes` ↔ `## Рецепты` — норма.
Заголовки внутри блоков ``` ``` ``` игнорируются: примеры кода не считаются
содержанием.

## Чего проверка НЕ делает — и почему

**Ссылки не сверяются.** Первая версия сравнивала состав ссылок на файлы репо,
но это ошибка проектирования: перевод законно ведёт на другие адреса. Внешние
ссылки — на локализованную версию (в гайдах MDN: `/ru/` против `/en-US/`),
внутренние — на документ своего языка, как только у него появится пара. Такая
проверка падала бы на **корректной** документации и требовала бы дописывать
исключения при каждой новой паре файлов. Вдобавок на реальном дереве она не
находила ничего: расхождение состава ссылок и так ловится числом разделов.

**Объём текста не сверяется.** Перевод бывает короче или длиннее оригинала;
считать символы — гарантированный ложный сигнал.

## Если упало

Сообщение называет пару файлов, числа и сторону расхождения, например:

```
FAIL: docs/USER_GUIDE.md ↔ docs/USER_GUIDE_RU.md: разное число разделов
(docs/USER_GUIDE.md: 44, docs/USER_GUIDE_RU.md: 43) — в docs/USER_GUIDE.md
на 1 больше. Раздел добавлен в один язык и не перенесён во второй.
```

Чинится переносом недостающего раздела во второй язык — не подгонкой счётчика.
Если раздел намеренно существует только в одном языке, честный путь — добавить
во второй хотя бы короткую версию: пара должна оставаться сопоставимой.

## Добавить новую пару

Дописать в `_pairs` в [parity_check.dart](parity_check.dart) — пути
относительно корня репозитория. Больше ничего не требуется.
