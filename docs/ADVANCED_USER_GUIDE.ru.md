# L×Box — руководство для опытных пользователей

Руководство для тех, кто знает формат конфига sing-box, правит JSON руками и
управляет приложением с компьютера через Debug API.
[Руководство пользователя](USER_GUIDE.ru.md) объясняет интерфейс: серверы,
направления, правила, DNS. Здесь — инструменты, которые работают с самим
конфигом в обход форм: сначала миксины, затем ручная правка, правила Raw
JSON, правила импорта, Debug API и Automation API.

## Миксины

### Миксин добавляет то, чего нет в шаблоне

Приложение собирает конфиг sing-box из шаблона и настроек. Когда в конфиге
нужно то, чего не даёт ни одна форма, — лишний inbound, правило в
определённом месте, поле у группы outbound'ов, — ручная правка в Config
Editor живёт только до следующей пересборки. Миксин — хранимая правка
собранного конфига: путь к цели, действие и JSON-значение. Он применяется
последним шагом каждой сборки, поэтому пересборка его не теряет, а Lock
config не нужен.

Типичный случай: сторонний файрвол вроде Rethink отправляет DNS-запросы на
заданный адрес резолвера, и нужно, чтобы на них отвечал DNS-модуль sing-box
по правилам, которые собрал L×Box. Это два миксина: первый добавляет inbound
`direct` на `127.0.0.1:5354`, второй отправляет трафик этого inbound'а в
`hijack-dns`. Порт 5353 на Android часто занят системным mDNS, поэтому в
примерах 5354; подойдёт любой свободный порт. Миксины целиком — в
[Примерах](#примеры).

Когда сборка применяет миксины: после пресетов, после гардов и автоснятия
битых узлов, перед итоговой проверкой. Включённые миксины применяются сверху
вниз, и каждый видит результат тех, что выше.

### Вкладка Mixins — рядом с Config

Где: ≡ → Config Editor, заголовок экрана Config, вкладка **Mixins** рядом с
**Config**. Вкладка Config показывает конфиг с уже применёнными миксинами:
после пересборки из-за миксина вкладка Config перечитывает текст, если в ней
нет несохранённой ручной правки. На вкладке Mixins кнопка Save и меню ⋮
вкладки Config скрыты.

Вкладка открывается строкой `Edits applied to the built config, top to
bottom. They survive rebuilds.`, под ней — список миксинов. Кнопка (+)
(Add mixin) открывает пустую форму.

### Порядок в списке — порядок применения

В строке списка:

| Элемент | Что делает |
|---|---|
| Ручка ≡ | Перетаскивает миксин выше или ниже; порядок — это порядок применения |
| Имя | Имя миксина; пустое имя показывается как `target → action` |
| `target → action` | Путь и действие, под именем |
| Тумблер справа | Выключенный миксин сборка пропускает |
| `⚠ <причина>` под строкой | Последняя сборка упала из-за этого миксина |

Долгий тап открывает Duplicate и Delete. Duplicate ставит копию сразу под
оригиналом. Delete спрашивает `Delete mixin?`. Тап по строке открывает
форму.

Тумблер, перетаскивание, Duplicate и Delete сохраняются сразу и запускают
пересборку. При работающем VPN новый конфиг доходит до ядра так же, как
любое изменение настроек: перезапуском с баннера на главном экране или сам,
если включено App Settings → General → Auto-restart VPN on settings change.

### Форма: Name, Target, Action, Value, Preview

Заголовок формы — Mixin, кнопка Save — в верхней панели.

**Name** — свободный текст, может быть пустым.

**Target** — путь в конфиге на языке из раздела
[Язык пути выбирает узлы конфига](#язык-пути-выбирает-узлы-конфига).
Под полем — живой статус:

| Статус | Смысл |
|---|---|
| `✓ 1 match` | Путь указывает на один узел |
| `✓ N matches → before first` / `→ after last` | Совпадений несколько; у `before` и `after` статус говорит, куда встанет значение |
| `✗ no match` | В конфиге нет ничего по этому пути |
| `✗ syntax: <message>` | Путь не разбирается |
| `✗ needs a single list` | `append`/`prepend` на не-списке или на нескольких совпадениях |
| `✗ not a list element` | `before`/`after` на ключе объекта, а не на элементе списка |

По мере набора под полем появляется список подсказок; он зависит от позиции
курсора:

| Курсор после | Подсказки |
|---|---|
| начала строки или `.` | Ключи объекта на этом уровне; `[`, если на уровне список |
| `[` | Поля, которые встречаются у элементов списка, и индексы |
| `=` | Значения этого поля у элементов, в порядке появления |
| `,` внутри скобок | Поля, ещё не использованные в этом условии |
| `]` | `.` |

Список фильтруется по набранному фрагменту; тап подставляет пункт и ставит
курсор дальше. Если текст до курсора не разбирается, подсказок нет. Значок
лампочки справа в поле (подсказка Suggestions) включает и выключает
подсказки: закрашенная — включены, контурная — выключены. Выбор запоминается
между открытиями формы и пересборку не запускает. С выключенными подсказками
живой статус работает как прежде.

**Action** — одно из семи действий, см. [Семь действий](#семь-действий). У
`remove` появляется переключатель Whole node / Keys. При Keys вместо поля
Value — поле `Keys, comma-separated`.

**Value** — JSON-редактор с кнопкой Format. Принимает JSON5: комментарии,
висячие запятые. При Save значение приводится к обычному JSON. Ошибка разбора
показывается под полем.

**Preview** — родитель цели после применения миксина, его путь — в заголовке
(`(root)` для корня). Одна строка на элемент, компактный JSON, обрезанный по
ширине экрана, слева маркер:

| Маркер | Смысл |
|---|---|
| (пробел) | Без изменений |
| `+` | Вставлен |
| `~` | Изменён |
| `-` | Удалён |

Тап по строке открывает полный JSON элемента. Для цели-скаляра — одна строка
`было → стало`. Ошибки, которые зависят от значения, — `merge` со значением
не-объектом, дубль тега — показываются строкой `⚠` над Preview; Save они не
блокируют, но сборка упадёт.

Подсказки, статус и предпросмотр берутся из конфига последней сборки в том
виде, каким он был до миксинов, с применёнными включёнными миксинами выше
этого. Так миксин проверяется на том, что он действительно увидит при сборке.

Save неактивна, пока статус показывает ✗, пока Value не разбирается и, у
`remove` с Keys, пока список ключей пуст. Выход из формы с несохранёнными
изменениями спрашивает Discard, Keep или Save.

### Язык пути выбирает узлы конфига

Синтаксис пути — собственный, не JSONPath. Грамматика:

```
path       = "" | segment ("." segment)*
segment    = name | name "[" N "]" | name "[" conditions "]"
conditions = condition ("," condition)*
condition  = field "=" value
field      = name ("." name)*
```

Правила:

- Сегменты соединяются через `.`: `route.rules`, `dns.servers`, `log.level`.
- Пустой путь — корень конфига.
- `name[0]` — элемент списка по индексу; `name.0` означает то же.
- `name[k=v]` — все элементы списка `name`, у которых поле `k` равно `v`.
  Несколько условий — через запятую, верны должны быть все.
- Поле в условии может уходить вглубь элемента:
  `outbounds[tls.enabled=true]`.
- Сравнение: число с числом, `true`/`false` с bool, остальное — как строки с
  учётом регистра.
- Если поле элемента — список, `=` означает «содержит»:
  `route.rules[rule_set=Ads]` совпадает с правилом
  `"rule_set": ["Ads", "Trackers"]`.
- Значение — всё до `,` или `]`. Пробелы внутри допустимы, поэтому теги с
  пробелами пишутся как есть: `outbounds[tag=S2 Fastest]`. Запятой и `]` в
  значении быть не может.
- Регулярок, `!=` и `or` нет. Путь, начинающийся с `$`, зарезервирован и
  считается синтаксической ошибкой.

Путь обозначает набор узлов, а не первое совпадение: `outbounds[type=vless]` —
все VLESS-outbound'ы.

Примеры на тегах типичного конфига (в вашем конфиге теги другие; подсказки
Target показывают настоящие):

| Путь | На что указывает |
|---|---|
| (пусто) | Корень конфига |
| `log.level` | Поле уровня журнала |
| `inbounds` | Список inbound'ов |
| `inbounds[tag=tun-in]` | TUN-inbound |
| `outbounds[0]`, `outbounds.0` | Первый outbound |
| `outbounds[type=vless]` | Все VLESS-outbound'ы |
| `outbounds[tag=PR DE-1]` | Outbound с тегом `PR DE-1` |
| `outbounds[tag=S2 Fastest]` | Группа urltest `S2 Fastest` |
| `outbounds[tls.enabled=true]` | Все outbound'ы с включённым TLS |
| `route.rules[action=hijack-dns]` | Правило перехвата DNS |
| `route.rules[action=resolve,strategy=prefer_ipv4]` | Правила resolve со стратегией `prefer_ipv4` |
| `route.rules[rule_set=Ads]` | Все правила, у которых `rule_set` равен `Ads` или содержит его |
| `route.rules[inbound=tun-in]` | Все правила, у которых список `inbound` содержит `tun-in` |
| `dns.servers[tag=google_udp]` | DNS-сервер `google_udp` |
| `dns.servers[tag=ru-direct:yandex_udp]` | Двоеточие в значении допустимо |

### Семь действий

| Действие | Цель | Что делает |
|---|---|---|
| `append` | Один список | Ставит значение в конец; значение-список добавляет каждый свой элемент по очереди |
| `prepend` | Один список | То же в начало; порядок значения сохраняется |
| `before` | Элементы списка | Ставит значение (или каждый элемент значения-списка, по порядку) на тот же уровень перед **первым** совпавшим |
| `after` | Элементы списка | То же после **последнего** совпавшего |
| `set` | Любой узел | Заменяет узел целиком: скаляр, список или объект. В корне — только объект |
| `merge` | Объект(ы) | Слияние вглубь: ключи значения дописываются или заменяют свои, остальные ключи не трогаются; объект в объект — рекурсивно; список внутри значения заменяет список цели целиком. Значение — только объект |
| `remove`, Whole node (значение `true`) | Любой узел | Удаляет узел: элемент списка выбывает, ключ объекта исчезает. Корень удалить нельзя |
| `remove`, Keys (значение `["key", "a.b"]`) | Объект(ы) | Удаляет только названные ключи; ключ через точку — вглубь элемента; отсутствующий ключ — не ошибка |

`merge` дописывает новые ключи в конец объекта; ядру порядок ключей
безразличен.

### Исход решает число совпадений

| Действие | 0 совпадений | 1 совпадение | Несколько совпадений |
|---|---|---|---|
| `set`, `merge`, `remove` | Ошибка | Применяется | К каждому, одно и то же значение |
| `before` | Ошибка | Перед ним | Перед первым |
| `after` | Ошибка | После него | После последнего |
| `append`, `prepend` | Ошибка | В этот список | Ошибка |

### Примеры

Каждый пример ниже — запись миксина в том виде, в каком её хранят Debug API и
LX Backup. В форме `target` — это Target, `op` — Action, `value` — Value.

**1. DNS-слушатель для другого приложения.** Два миксина, в таком порядке:

```json
{"name": "DNS listener", "target": "inbounds", "op": "append",
 "value": {"type": "direct", "tag": "dns-in", "listen": "127.0.0.1",
           "listen_port": 5354, "override_address": "1.1.1.1", "override_port": 53}}
{"name": "Hijack DNS from dns-in", "target": "route.rules[action=hijack-dns]", "op": "before",
 "value": {"inbound": ["dns-in"], "action": "hijack-dns"}}
```

Первый добавляет inbound. Второй ставит правило перед существующим правилом
`hijack-dns`: всё, что приходит на `dns-in`, уходит в DNS-модуль, а он
отвечает по DNS-правилам конфига. В файрволе DNS-сервер — `127.0.0.1`, порт
`5354`. Проверка с компьютера:

```
adb forward tcp:5354 tcp:5354
dig +tcp @127.0.0.1 -p 5354 example.com
```

Выключение первого миксина убирает `dns-in` из конфига; пару включают и
выключают вместе.

**2. Локальный домен — напрямую.** Правило встаёт сразу после правила resolve
со стратегией `prefer_ipv4`, перед правилами маршрутизации шаблона:

```json
{"name": "NAS direct", "target": "route.rules[action=resolve,strategy=prefer_ipv4]", "op": "after",
 "value": {"domain_suffix": [".nas.home"], "outbound": "direct-out"}}
```

**3. Поле у всех VLESS-outbound'ов:**

```json
{"name": "TFO on VLESS", "target": "outbounds[type=vless]", "op": "merge",
 "value": {"tcp_fast_open": true}}
```

**4. Настройки группы, которых нет в форме:**

```json
{"name": "Fastest: check every minute", "target": "outbounds[tag=S2 Fastest]", "op": "merge",
 "value": {"interval": "1m", "tolerance": 100}}
```

**5. Удалить ключи у одного узла.** В форме: Action `remove`, Keys,
`tcp_fast_open, tls.utls`:

```json
{"name": "PR DE-1 without uTLS", "target": "outbounds[tag=PR DE-1]", "op": "remove",
 "value": ["tcp_fast_open", "tls.utls"]}
```

**6. Удалить правило целиком:**

```json
{"name": "No ad blocking", "target": "route.rules[rule_set=Ads]", "op": "remove", "value": true}
```

**7. Заменить скаляр и добавить ключ верхнего уровня:**

```json
{"name": "Quiet log", "target": "log.level", "op": "set", "value": "warn"}
{"name": "Empty services", "target": "", "op": "merge", "value": {"services": []}}
```

`prepend` на `route.rules` ставит правило перед Traffic Processing (sniff,
hijack-dns). Это допустимо; такое правило видит соединения до сниффинга.

### Миксин с ошибкой останавливает сборку

Миксин, который не удаётся применить, останавливает сборку: конфиг не
собирается, сборка сообщает о фатальной ошибке, под строкой миксина в списке
появляется `⚠`. Ранее собранный конфиг остаётся на месте. Тексты ошибок:

| Текст | Причина |
|---|---|
| `Mixin "<name>": <target>: no match` | По пути ничего нет |
| `Mixin "<name>": <target>: needs a single list` | `append`/`prepend` на не-списке или на нескольких совпадениях |
| `Mixin "<name>": <target>: not a list element` | `before`/`after` на ключе объекта (`inbounds`, `log.level`) |
| `Mixin "<name>": <target>: not an object` | `merge` или `remove` с Keys на не-объекте |
| `Mixin "<name>": <target>: merge needs an object value` | Значение `merge` — не объект |
| `Mixin "<name>": duplicate tag "x" in outbounds` | После всех миксинов у двух элементов один тег |

Пустой путь показывается как `(root)`. Уникальность тегов проверяется
отдельно в `inbounds`, в `outbounds` вместе с `endpoints` (одно пространство
имён, как у ядра) и в `dns.servers`.

После ошибки миксин остаётся включённым: его исправляют или выключают. Путь,
который вчера совпадал, может перестать совпадать, когда обновление подписки
переименует узел; тогда сборка падает с `no match`.

### Миксины, ручная правка и Lock config

Ручная правка на вкладке Config и миксины независимы. Следующая пересборка
отбрасывает ручную правку и применяет миксины заново. Чтобы правка
сохранялась, её записывают миксином.

Lock config останавливает пересборки совсем: конфиг остаётся тем, что
сохранили, и до него не доходят ни настройки, ни миксины. Миксины
пересборки сохраняют и меняют только свои узлы. В повседневной работе
миксины заменяют пару «ручная правка + Lock config»; Lock config остаётся
для проверки конфига, загруженного через Debug API.

### Бэкап и Debug API

Миксины — часть настроек. LX Backup сохраняет их в секции `mixins`. Импорт
добавляет их в конец списка; миксин с теми же `target`, `op` и `value`, что у
существующего, пропускается, дубля не будет.

Debug API отдаёт миксины по `/mixins`: список, создание, `PATCH`, удаление,
перестановка и предпросмотр одного миксина (`GET /mixins/{id}/preview`, те же
данные, что показывает форма). Запись проверяет синтаксис пути и действие;
совпадение проверяет только сборка, потому что цель может появиться после
другого миксина. Запросы и ответы —
[Debug API reference → Mixins](api/debug-api-reference.md#mixins-crud--mixins).
Формальное описание функции —
[docs/spec/features/019-CONFIG_EDITOR/FUNCTIONS/mixins.ru.md](spec/features/019-CONFIG_EDITOR/FUNCTIONS/mixins.ru.md).

### Ограничения

- После перезапуска приложения и до первой сборки форма показывает под
  Target `No config built yet`: без числа совпадений, без подсказок, без
  предпросмотра. Save проверяет только синтаксис пути и Value; совпадения
  проверит следующая сборка.
- Миксины работают с готовым конфигом: автоснятие битых узлов и санитайзер
  outbound'ов их не видят. Дубль тега ловится до ядра; всё остальное, чего
  ядро не принимает (неизвестное поле, неверный тип), ядро сообщает при
  старте VPN. Для тегированного элемента ошибка называет его тег, для
  правила — только индекс.
- Путь, начинающийся с `$`, зарезервирован.
- Группировки миксинов и общего тумблера нет.
- Схема бэкапа десктопного лаунчера пока не объявляет секцию `mixins`; при
  импорте такого бэкапа лаунчер предупреждает о неизвестном поле.

## Другие инструменты опытного пользователя

### Ручная правка в Config Editor и Lock config

Вкладка Config правит собранный конфиг руками; правка живёт до следующей
пересборки. Lock config (debug) закрепляет сохранённый конфиг и останавливает
пересборки. Ручная правка описана в руководстве пользователя:
[Config Editor правит конфиг ядра до следующей пересборки](USER_GUIDE.ru.md#config-editor-правит-конфиг-ядра-до-следующей-пересборки);
Lock config — [ниже](#lock-config-закрепляет-ручной-конфиг).

### Lock config закрепляет ручной конфиг

Настройка **Lock config (debug)** запрещает приложению пересобирать конфиг:
действия в интерфейсе меняют настройки, а файл конфига остаётся тем, что вы
сохранили. Где находится: App Settings → Diagnostics → Lock config (debug).
Тумблер виден, только когда включён Debug API. Выключен по умолчанию.
Включённый тумблер подписан `Pinned. UI actions skip config rebuild — useful
when testing PUT /config overrides.` Выключение Debug API снимает и
закрепление.

> ⚠️ При включённом Lock config смена правил, Направлений, DNS и обновления
> подписок в конфиг не попадают: VPN работает на закреплённом файле. Чтобы
> настройки снова применялись, выключите Lock config.

### Raw JSON и вкладка View — для полей, которых нет в форме

Правило можно написать JSON-фрагментом `route.rules` sing-box: для этого в
Source выберите Raw JSON. Действие задаётся в самом JSON, синтаксис
проверяется при вводе.

Вкладка **View** у правила из формы показывает готовый фрагмент sing-box,
который попадёт в конфиг.

### Правила импорта на вкладке Filters подписки

Вкладка **Filters** хранит правила обработки узлов; правила применяются при
импорте и на каждом обновлении. Правило — это условия и действие. Условие
записывается как `путь оператор значение`, где оператор — contains, equals
или matches (regex). Галки Not и Case-sensitive уточняют условие, а
несколько условий объединяются по AND или OR. Пустой путь ищет по всему
узлу. Действий три:

| Действие | Что делает |
|---|---|
| Disable | Убирает подходящие узлы из маршрутизации |
| Enable | Возвращает их, снимая и ручные выключения |
| Replace | Записывает новое значение по указанному пути — целиком или частью, с группами `$1`, `$2`… из regex: так чинится нестандартный TLS-fingerprint у всех узлов сразу |

Правила применяются по порядку, последнее сработавшее побеждает: связка
«выключить всё → включить NL» работает как белый список. Вкладка **Matches**
в редакторе правила показывает, к каким узлам правило применится и что
изменит, ещё до сохранения.

### Debug API

Где находится: App Settings → Diagnostics → Developer → Debug API.

**Debug API** поднимает HTTP-сервер, через который компьютер читает
состояние приложения, журналы и конфиг и управляет VPN. Сервер слушает только адрес `127.0.0.1`
телефона; с компьютера к нему подключаются командой
`adb forward tcp:9269 tcp:9269`. При первом включении приложение создаёт токен
доступа. Токен виден только на этом экране, в Backup по умолчанию не
попадает; Copy копирует его, Regenerate создаёт новый. Поле Port принимает
значения от 1024 до 49151. По умолчанию порт `9269` — тот же, что в команде
adb forward.

> 📖 [debug-api-reference.md](api/debug-api-reference.md) — запросы Debug API
> и их ответы.

**Lock config (debug)** закрепляет конфиг, загруженный через Debug API:
действия в интерфейсе его не пересобирают. Выключение Debug API снимает и
закрепление.

> ⚠️ Пока конфиг закреплён, правки в Routing, DNS и у серверов в туннель не
> попадают. Снимите Lock config (debug), и следующее действие в интерфейсе
> пересоберёт конфиг из настроек.

Методика диагностики — [DIAGNOSTICS.md](DIAGNOSTICS.md).

### Автоматизация: VPN включается по событиям

Приложения-автоматизаторы — Tasker, MacroDroid, Llama, Automate — управляют
L×Box: включают и выключают VPN и переключают серверы по событиям, без
участия владельца телефона. Типичные сценарии:

- подключение к домашнему Wi-Fi выключает VPN, подключение к чужому или
  публичному — включает;
- запуск конкретного приложения переключает на нужный сервер или Направление;
- расписание или геозона включает и выключает туннель.

Приём команд по умолчанию выключен. Где находится: App Settings →
**Automation** → Accept automation commands. На той же вкладке разрешается
отдавать события L×Box наружу: подключение, отключение, обновление подписки.
После этого в автоматизаторе выберите L×Box как плагин и команду: Start VPN,
Stop VPN, Toggle VPN или Custom… — семь команд, среди них Switch node и
Refresh subscriptions.

> 📖 [AUTOMATION.ru.md](AUTOMATION.ru.md) — полный список команд и событий и
> готовые рецепты, включая управление из shell и ADB.

### Automation открывает VPN для команд других приложений

Вкладка **Automation** позволяет Tasker, MacroDroid и другим автоматизаторам
управлять L×Box и получать его события. Сценарии и порядок настройки — в
разделе [Автоматизация](#автоматизация-vpn-включается-по-событиям); ниже —
то, что есть на вкладке сверх него. Где находится: App Settings →
Automation.

Опция **Accept automation commands** по умолчанию выключена. Её включение
показывает диалог Enable command receiver?. Пока опция включена, любое приложение на телефоне может
управлять VPN широковещательными командами. Выключите её, если
автоматизатором не пользуетесь.

Список **Commands (intent actions)** содержит 10 команд, у каждой — кнопка
копирования. Строка вставляется в действие Send Intent автоматизатора,
получатель — Broadcast Receiver. Четыре команды принимают параметр:

| Команда | Параметр |
|---|---|
| `com.leadaxe.lxbox.SWITCH_NODE` | `tag` — тег узла |
| `com.leadaxe.lxbox.SET_GROUP` | `group` — тег группы, например `vpn-1` |
| `com.leadaxe.lxbox.URLTEST_GROUP` | `group` — тег группы, например `vpn-1` |
| `com.leadaxe.lxbox.REFRESH_SUBS` | `force` |

Секция **Outbound events (emit)** отдаёт события L×Box наружу. Категорий
три, все выключены по умолчанию:

| Категория | События |
|---|---|
| Lifecycle | `VPN_CONNECTED`, `DISCONNECTED`, `ERROR`, `REVOKED`, `UPDATE_AVAILABLE`, `PERMISSION_NEEDED` |
| State | `ACTIVE_NODE_CHANGED`, `ACTIVE_GROUP_CHANGED`, `NODE_ALREADY_ACTIVE` |
| Subscription | `SUB_REFRESHED`, `SUB_REFRESH_FAILED` |

Первое включение категории показывает диалог Emitting events outward:
события видят другие приложения, но секретов подписок и конфига в них нет —
только теги узлов, имена групп и статус. Чтобы автоматизатор узнал
результат команды, включите Lifecycle и State: успех приходит в State, отказ
— событием `VPN_ERROR` в Lifecycle.

Кнопка **Documentation and Tasker recipes** открывает полный список команд и
событий с готовыми рецептами.
