# L×Box v2.12.0

**Починен «мёртвый рунет» при включённом IPv6.** Если туннель раздавал IPv6,
а сеть (оператор/роутер) реального IPv6 наружу не давала — российские сайты,
идущие напрямую (ya.ru, VK, банки), умирали с «Соединение сброшено» (§246).
Теперь у пресетов «Russian domains & IPs» и «Russia-only services» есть галка
**Force IPv4** (включена по умолчанию): российские домены резолвятся только в
IPv4, а IPv6 в туннеле продолжает работать. Для собственных правил появилось
окно **Action & Resolve** (§247): принудительный IPv4 (и другие стратегии
резолва) теперь вешаются на любое своё правило через шестерёнку у Action.
Дефолтная стратегия резолва стала **ipv4_only**, тумблер IPv6 больше не
навязывает prefer_ipv6 (§249). Ядро без изменений — **v1.14.0-lx.2**.

## 🛠 Фиксы

- **Российские сайты не открывались при включённом IPv6** (§246). Цепочка:
  туннель с IPv6 сообщает системе «v6 доступен» → приложения получают
  AAAA-записи и коннектятся по IPv6 → RU-трафик по пресету идёт напрямую
  (direct), мимо туннеля → а там сеть без рабочего глобального IPv6 →
  `network is unreachable`, в браузере ERR_CONNECTION_RESET. Фикс двухслойный
  (галка **Force IPv4** в пресете, по умолчанию включена): DNS-правило пресета
  отвечает только A-записями (приложения не видят AAAA вовсе), плюс
  route-правило `action: resolve` со `strategy: ipv4_only` для доменных
  соединений. Заграничный трафик не затронут — IPv6 в туннеле живёт.
  Проверено на устройстве: dial идёт на IPv4 даже при глобальном prefer_ipv6.

- **VPN не стартовал после удаления канала, на который смотрел пресет**
  (§202). При delete/disable канала самолечение переводило на vpn-1 только
  route_final и outbound обычных правил; пресет с явным override
  (`varsValues['outbound']`) не лечился → dangling outbound → fatal при
  старте. Теперь heal идёт через kind-agnostic getter — пресеты лечатся
  так же, как inline/srs.

- **Битая ссылка resolve-правила на DNS-сервер больше не убивает трафик**
  (§247). Route-правило `{action: resolve, server: <tag>}` со ссылкой на
  сервер, отсутствующий в `dns.servers` (выключен DNS-тоггл пресета, сервер
  удалён в DNS Settings), ядро не ловит на старте — оно валило каждое
  сматчившееся соединение лениво («DNS server not found»). Теперь билдер
  снимает битый `server` с warning — резолв деградирует в обычный
  DNS-роутинг, трафик живёт.

## 🆕 Новое

- **Окно «Action & Resolve» у собственных правил** (§247) — шестерёнка рядом
  с Action-пикером в редакторе inline/srs-правила. Три режима:
  **Route to outbound** (как раньше), **Route + Resolve first** — резолв
  домена перед роутингом с принудительным семейством адресов (например
  ipv4_only — тот же фикс, что в RU-пресетах, для любого своего правила),
  и **Resolve only** (advanced, с предупреждением) — только резолв,
  трафик проваливается к следующим правилам. Настройки: strategy, DNS-сервер,
  и раскрывашка Advanced (disable cache / optimistic cache, rewrite TTL,
  query timeout, client subnet — все поля sing-box 1.14). Внизу окна — живой
  preview правил, которые уедут в конфиг. Правила с активным resolve помечены
  значком ✳ в списке. Поддержано и в Debug API (`/rules`, поле `resolve`).

- **Пресеты могут эмитить несколько route-правил** (§246, для авторов
  шаблона) — `rules`-массив в `selectable_rules` с `#if`-гейтами на элементах;
  порядок сохраняется, outbound-override применяется только к терминальным
  правилам. Одиночная `rule`-форма (Map) работает как раньше.

## ⚙️ Изменения

| Область | Что изменилось |
|---|---|
| **Стратегия резолва по умолчанию** (§249) | Дефолт `dns_strategy`/`resolve_strategy` — **ipv4_only** (IPv6 на туннеле выключен по умолчанию — AAAA приложениям не нужен). Тумблер **Enable IPv6**: включение ставит **prefer_ipv4** (v6 доступен, но v4-first — prefer_ipv6 на сетях с полурабочим v6 давал мёртвые прямые соединения), выключение форсит **ipv4_only**. Стратегия по-прежнему настраивается вручную: DNS Settings → Strategy (тумблер — разовый эффект, не форс). ⚠ Если раньше включали IPv6 — в storage мог остаться prefer_ipv6: проверьте DNS Settings → Strategy или переключите тумблер IPv6 туда-обратно. |
| **Force IPv4 в RU-пресетах** (§246) | Новая галка в «Russian domains & IPs» и «Russia-only services», включена по умолчанию. Выключайте, только если у вашей сети настоящий рабочий IPv6 и хочется v6 на прямых соединениях. |
