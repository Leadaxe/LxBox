# L×Box v2.15.2

**Поддержка AnyTLS.** Добавлен протокол **AnyTLS** (sing-box `type: anytls`) —
анти-DPI мультиплекс с гибким паддингом поверх TLS. Ссылки `anytls://` теперь
импортируются (вставка / «Add server» / QR), а sing-box JSON с `type: anytls`
разбирается в типизированный узел. TLS всегда включён, REALITY (`pbk`/`sid`)
переживает round-trip, поля idle-сессий сохраняются. Плюс фикс: **TLS Fragment**
больше не роняет naive-узлы. Ядро без изменений — **v1.14.0-lx.3**.

## 🆕 Новое

- **Протокол AnyTLS** (§269, [#38](https://github.com/Leadaxe/LxBox/issues/38)).
  Полная поддержка AnyTLS — анти-DPI транспорт с нативным мультиплексом и
  паддингом поверх TLS:
  - импорт ссылки `anytls://password@host:port?sni=..&pbk=..&idle_session_timeout=..`
    (вставка / «Add server» / QR);
  - разбор sing-box JSON `type: anytls` в типизированный узел;
  - TLS всегда включён (AnyTLS без TLS не бывает); поддержка **REALITY**
    (`pbk`/`sid`), uTLS-отпечатка, ALPN;
  - поля idle-сессий (`idle_session_check_interval` / `idle_session_timeout` /
    `min_idle_session`).

  У AnyTLS нет стандартной share-ссылки (sing-box описывает только JSON) — принят
  распространённый Trojan/VLESS-подобный формат.

---

## 🛠 Фиксы

- **TLS Fragment ломал naive-узлы** (§270). При включённом TLS Fragment и
  выбранной naive-ноде VPN не стартовал: ядро отвергало запрос
  (`fragment is not supported on naive outbound`) — naive принимает в TLS
  только `enabled`/`server_name`. Теперь fragment к naive-узлам не применяется,
  для остальных протоколов работает как прежде.
