## ✨ Новое

### Load balance — балансировка нагрузки в auto-группе (§208)

У auto-двойника канала появился **выбор режима** в редакторе канала:

| Режим | Что делает |
|---|---|
| **Fastest** (как было) | один лучший узел по latency — все соединения через него |
| **Load balance** (новое) | раскидывает соединения по **пулу** из N узлов, сессии **липнут** к своему серверу |

Зачем: разгрузить один сервер на больших подписках, параллельно использовать
несколько узлов. Сессии (TLS/авторизация) не прыгают между IP — держатся за свой
узел по ключу `process + domain`.

Под Load balance настраивается:
- **Pool size** — сколько узлов в пуле одновременно;
- **Pool tolerance** — `0` держать пул живых, `>0` отбирать быстрейших;
- **Sticky session** — по чему липнуть: `process / domain / source ip / dest ip / dest port` (чипы; снять все → чистая ротация без липкости).

**View pool** — long-press по auto-ноде → попап с текущим составом пула (какие N
серверов в слотах сейчас + их пинг).

### pprof — диагностика ядра на устройстве (§207)

**App Settings → Diagnostics → Profiling** — кнопки снимают pprof-слепки с живого
ядра sing-box и открывают системный Share:

| Профиль | Для чего |
|---|---|
| **CPU profile (10s)** | ловит нагрев / 100 % CPU (busy-spin в tight-loop) |
| **Heap (inuse_space)** | что реально держит память (GC форсится перед снимком) |
| **Allocations** | что аллоцирует память (источник давления на GC) |
| **Goroutines** (summary / full stacks) | счётчик и стеки горутин — утечки горутин |

`.pb`-файлы открываются через `go tool pprof`. Реализовано через встроенный в
libbox `PProfServer` — **ядро не правилось**. Также доступно через Debug API:
`GET /diag/pprof?profile=heap`.

## 🔧 Изменено

| # | Что | Зачем |
|---|---|---|
| §210 | Ядро **sing-box-lx rc.15**: фиксы балансировщика — sticky-ключ `domain` больше не теряется, слоты пула не сдвигаются при health-check | На rc.14 был перекос — весь трафик схлопывался в один узел (роутер перезаписывал destination до балансировщика). На rc.15 трафик размазывается ровно |
| §209 | Снапшоты ядра (состав пула, группы) работают **и когда приложение свёрнуто** | Раньше unary-запросы шли через клиентов, что засыпают в фоне → отдавали пустоту. Теперь через незасыпающий канал; недоступность = явная ошибка, а не пустой ответ |
| — | Из видимых строк (`/help`, ошибки, UI, логи) убраны внутренние номера задач | Самодостаточный текст для пользователя/агента |
