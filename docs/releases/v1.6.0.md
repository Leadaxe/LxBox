# L×Box v1.6.0

Tech-debt cleanup release. Migrated to current sing-box 1.13.x with full rewrite of the native VPN service architecture. User-facing behavior is unchanged plus one important reliability fix.

## 🔧 Why this release

After ~27 minutes of an active VPN session, every node in the server list would show "err" for ping/latency, even though the VPN tunnel itself remained fully functional and traffic kept flowing through the selected node. Hours-long sessions were silently broken for any user trying to compare nodes or do a manual switch.

This was traced to a goroutine leak in sing-box's DNS cache deduplication logic, fixed upstream in sing-box `v1.12.21+` and `v1.13.0+`. Picking up the fix required a libbox bump, which we used as the trigger for a long-overdue update of our entire native VPN service layer.

## 🐞 Fix

- **Clash delay endpoint hang after ~27 min uptime** ([§039](https://github.com/Leadaxe/LxBox/blob/develop/docs/spec/features/039%20libbox%201.13%20migration/spec.md)). Root cause: DNS cache dedup-lock goroutine leak in sing-box `dns/client.go:144-164` — per-question wait channel blocked **without** `ctx.Done()` awareness; once the upstream DNS transport stalled (any reason), every subsequent waiter parked forever, including the goroutines used by the probe mechanism that updates per-node latencies. Fixed in sing-box upstream commit `aba8346b` ("Fix DNS cache lock goroutine leak").

## 🏗 Architecture

- **libbox: 1.12.12 → 1.13.11.** Major upstream version. Three architectural changes ripple into our Kotlin VPN service:
  - **`BoxService` class is gone.** Sing-box 1.13 unified the runtime owner and the Clash control socket into a single `CommandServer`. We had two objects (`BoxService` for runtime, `CommandServer` for Unix socket); now one `CommandServer` owns the runtime via `startOrReloadService(config, opts)`. Same `pause()`/`wake()`, same `closeService()`, with required two-phase shutdown (`closeService()` → `close()`).
  - **`PlatformInterface` simplified.** Three callbacks (`writeLog`, `packageNameByUid`, `uidByPackageName`) are gone — sing-box now keeps its own UID↔package mapping and returns package names directly via the new `ConnectionOwner` struct (`userId`, `userName`, `processPath`, `androidPackageNames[]`). One callback instead of three; fewer JNI roundtrips.
  - **No more `Seq.destroyRef`.** Go runtime in 1.13 self-cleans refnums; manual destroyRef = double-free. Confirmed against `SagerNet/sing-box-for-android` reference implementation.
- **Two-phase shutdown on `Dispatchers.IO`.** `closeService()` first (stop runtime; throwing — wrapped in `runCatching` that pipes failure back via `setError()` so dashboards can see it), then `close()` (close Unix socket; non-throwing). Order matters: getting it backwards risks Go callbacks deadlocking → ANR.

## 🧹 Code quality

Dart-side wrapper (`lib/vpn/box_vpn_client.dart`) was rewritten to address accumulated tech debt:

- **Type-safe API.** `getVpnStatus()` and `onStatusChanged` now return `TunnelStatus` / `TunnelStatusEvent` (was `String` / `Map<String,dynamic>`). `BackgroundMode` is an enum (was `String 'never|lazy|always'`). `AppInfo` is a typed class in `lib/models/app_info.dart` (was `Map<String, dynamic>`). Parsing happens once at the wrapper boundary; callsites work with typed objects only.
- **MethodChannel timeouts.** Every native call has an explicit per-method timeout (`getVpnStatus` 3s, `startVPN` 30s, `stopVPN` 10s, `getInstalledApps` 15s, the rest 3-5s) with a typed safe-default fallback. On timeout → `AppLog.error` + fallback. Without this, a native deadlock could freeze the Flutter UI on app init while waiting for `getVpnStatus`.
- **Singleton + DI.** `BoxVpnClient.I` (matching `AppLog.I` style) plus `BoxVpnClient.forTest({methods, events})` factory for unit tests with mock channels. Default `BoxVpnClient()` constructor preserved as backward-compatible alias for the singleton.
- **Centralized method-name constants** (`_Methods.saveConfig` etc.) — explicit contract with `VpnPlugin.kt`. Typos in method names are caught at code review, not silently broken at runtime.
- **`wizard_template.json` cleanup.** Removed an invalid `"format": "domain_suffix"` field from an inline rule_set. Sing-box silently zeroed it in both 1.12 and 1.13, but the field isn't defined for inline rule_sets — sing-box 1.14+ may make this a hard reject.

## ⚠ Breaking

None — for end users. Public Dart API surface (`BoxVpnClient`) public methods preserve their semantics; only return types became more specific (subtypes still work where the old `String` did, in most callsites).

For anyone depending on the internal Kotlin `BoxVpnService.kt` implementation (no external dependents at the moment), the `BoxService` field is gone — see migration table in the [feature spec](https://github.com/Leadaxe/LxBox/blob/develop/docs/spec/features/039%20libbox%201.13%20migration/spec.md).

## 🇷🇺 L×Box v1.6.0 — на русском

**Tech-debt релиз.** Под капотом мы перешли на актуальный sing-box 1.13 и переписали обёртку нативного VPN-сервиса. Функционально пользовательский UX не меняется, но решена одна назойливая проблема устойчивости.

### 🐞 Починено

- **Залип endpoint измерения задержки до нод после ~27 минут работы VPN.** Симптом: все ноды в списке показывают "err" для пинга после получаса активной сессии, хотя сам туннель работает нормально и трафик через выбранную ноду идёт. Корень — goroutine leak в sing-box DNS cache (lock без context-cancellation), исправлено upstream в `v1.12.21+` и `v1.13.0+`.

### 🏗 Архитектура

- **libbox 1.12.12 → 1.13.11.** Major-обновление. Под капотом — большая переработка:
  - **Класс `BoxService` удалён** — всё его API поглощено в `CommandServer`. Раньше у нас было два объекта (BoxService для runtime, CommandServer для Clash-сокета); теперь единый `CommandServer` владеет всем. Two-phase shutdown (`closeService()` → `close()`) на `Dispatchers.IO` — обязателен, иначе Go callback'и могут зависнуть → ANR.
  - **`PlatformInterface` упрощён**: убраны три callback'а (`writeLog`, `packageNameByUid`, `uidByPackageName`); sing-box сам ведёт UID↔package mapping и отдаёт package names через новый struct `ConnectionOwner`. Меньше JNI-roundtrip'ов.
  - **`Seq.destroyRef` больше не вызываем** — Go runtime в 1.13 self-cleans refnum'ы; manual destroyRef = double-free.

### 🧹 Качество кода

- **Типизированный Dart wrapper.** `getVpnStatus()` теперь возвращает `TunnelStatus` enum, не `String`. `BackgroundMode` — enum. `AppInfo` — общая typed-модель. Парсинг native-строк делается раз в клиенте, downstream работает с типизированными объектами.
- **Таймауты на critical-path вызовах** (`getVpnStatus` 3s, `startVPN` 30s, и т.д.) — на таймауте логгируем + fallback'имся в безопасный default. Без этого native deadlock мог заблокировать Flutter UI.
- **Singleton + DI** для тестируемости (`BoxVpnClient.I`, `BoxVpnClient.forTest`).
- **Method-name константы** — централизованный контракт с native-стороной.

### ⚠ Что сломалось

Для конечных пользователей — ничего. Публичный API клиента сохранён; изменились только возвращаемые типы (стали более специфичными).
