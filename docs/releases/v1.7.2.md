## 🐞 Fixes

### §050 — F12.3 `readWIFIState` real root cause + final fix

В §049 9 attempt'ов на разных констукторах / pinning / R8-keep-rules — все падали `Unknown reference: 42` cold-start через 1-12 секунд. Истинная причина оказалась проще, чем `Seq` ref-tracker race.

**Real mechanism** (см. [§050 findings.md](../spec/tasks/050-libbox-debug-build/findings.md)):

1. Sing-box (Go) → cgo → `cproxy_PlatformInterface_ReadWIFIState`
2. Java callback `readWIFIState()` → `WifiManager.connectionInfo`
3. **`SecurityException`** при отсутствии location permission (API 29+ требует `ACCESS_BACKGROUND_LOCATION`)
4. Exception проходит через JNI границу **без handler'а** в cproxy code
5. `Seq$RefTracker.incRefnum` пытается cleanup → JNI env уже corrupted
6. `ClassLinker::FindClass` fails → `Runtime::Abort`
7. abort message `"Unknown reference: 42"` — **misleading follow-up effect**, refnum 42 не имеет отношения к real cause

**Что сделано:**

- **Defensive try/catch** `SecurityException + RuntimeException → return null` в `PlatformInterfaceWrapper.readWIFIState`. Sing-box graceful'но получает null (как было раньше до §049 attempts) — как минимум не падает.
- **Permission gate** в `BoxService.startSingbox` после `startOrReloadService` (port из reference SagerNet `BoxService.kt`): если `cs.needWIFIState() && !permission` → `stopAndAlert("alert:permission_location:...")`. Sing-box не запускается без permission'а если config реально использует `wifi_ssid`/`wifi_bssid` правила — Flutter показывает actionable alert вместо silent crash'а.

### §050 — `<unknown ssid>` на Android 13+ (targetSdk≥33)

Даже после grant'а `ACCESS_FINE_LOCATION` / `ACCESS_BACKGROUND_LOCATION`, `WifiInfo.ssid` возвращал `"<unknown ssid>"` → wifi rules не матчились. Google в API 33 отделил Wi-Fi info от location: для apps с `targetSdk≥33` нужен **отдельный `NEARBY_WIFI_DEVICES`** permission ([Android docs](https://developer.android.com/develop/connectivity/wifi/wifi-permissions)).

**Что сделано:**

- Manifest: `<uses-permission android:name="android.permission.NEARBY_WIFI_DEVICES" android:usesPermissionFlags="neverForLocation" />` — `neverForLocation` обязателен для Google Play политики (декларация, что permission используется не для location tracking).
- `BoxService.startSingbox`: на API 33+ проверяются **обе** permission (`ACCESS_BACKGROUND_LOCATION` + `NEARBY_WIFI_DEVICES`); alert содержит comma-list missing permissions для UI parsing'а.
- **Verified on OnePlus Nord 3 / Android 15 / API 36**: после grant'а wifi rule с `wifi_ssid:["lexRouter"], outbound: direct-out` корректно матчится — chrome → api.ipify.org идёт через `outbound/direct[direct-out]`, минуя VPN.

## ✨ New

### §050 — Permission UX flows

Permission grant теперь не «угадай где найти в Settings», а explicit-flow.

**Notification permission explainer** при cold start: показывает explainer dialog ДО system POST_NOTIFICATIONS prompt'а — юзер понимает зачем VPN'у нужны notifications (foreground service / status indicator). Один раз, persisted флаг.

**Wi-Fi permissions dialog** при запуске VPN с wifi rules:
- Парсит comma-list missing permissions из alert prefix
- Кнопка **«Allow Wi-Fi info»** → runtime prompt для `NEARBY_WIFI_DEVICES` (one tap)
- Кнопка **«Open Settings»** → `MANAGE_APP_PERMISSIONS` intent (для `BACKGROUND_LOCATION` который нельзя выдать через runtime prompt). Три fallback стратегии для разных OEM:
  1. `MANAGE_APP_PERMISSIONS` (стандарт Android)
  2. `MANAGE_PERMISSION_APPS` (некоторые OEM)
  3. `ACTION_APPLICATION_DETAILS_SETTINGS` (как fallback fallback'а)

**Battery optimization — one-tap prompt**: primary action поменян с `ACTION_IGNORE_BATTERY_OPTIMIZATION_SETTINGS` (общий список всех apps — юзер сам ищет L×Box) на `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` (системный диалог конкретно про L×Box). Список apps остаётся как fallback для OEM (ColorOS / MIUI / HyperOS), где direct-prompt молча отбрасывается.

### §048 — Live tab system-wide events fix

Раньше при тапе START в Live tab без per-app session показывалось **0 events** — `_pollConnections()` имел early-return `if (_active == null) return;`, и system-wide recording получал только DNS строки из core logs (TCP/UDP open/close никогда). Теперь global recording тоже запускает `_startConnectionPoll()`, события эмитятся через `_emitGlobalStream`. Closed connections тоже идут в global buffer когда recording on.

Idle profiler по-прежнему ничего не делает: ни session, ни global recording — `_maybeStopConnectionPoll()` останавливает таймер только когда **оба** off (симметрично уже существующему `_maybeDetachLogListener`).

### §037 — config_locked toggle в Diagnostics

UI-эквивалент `PUT /settings/config_locked` Debug API endpoint'а: **App Settings → Diagnostics → «Lock config from rebuilds»**. Юзер может pin'нуть текущий sing-box config (например, после `PUT /config` экспериментальной фичи через Debug API) от перезаписи UI-rebuild'ом, и снять lock сам.

Auto-unlocks при отключении Debug API (иначе lock остаётся unactionable — toggle спрятан под Debug API блоком).

## 🏗 Under the hood

### Deferred (F22 part 2)

`writeDebugMessage` drainer pattern был добавлен в v1.7.1 как F22 part 1 — coalesced dispatch вместо per-line `Handler.post`. Запланированные дополнительные оптимизации:

- **Back-pressure cap** — `LOG_QUEUE_MAX = 4096`; `coreLogQueue.offer` дропать если переполнен (текущий `LinkedBlockingQueue` unbounded → OOM risk на heavy debug-mode traffic при slow Dart consumer)
- **Drainer yield** — каждые 200 iterations re-post Runnable вместо continue (предотвращает блок main looper'а на длинных батчах)
- **EventChannel batching** — собирать N строк в `List<String>` и слать одним `sink.success(list)` (сейчас per-line JNI marshal на 100+ строк/сек при busy traffic + Forward sing-box logs ON)
- **AppLog ring buffer** — заменить `List.insert(0)` (O(n) shift) на deque newest-first
- **notifyListeners throttle** до 60Hz (текущий — на каждый log entry)

Не release-blocker. Текущая реализация работает для production load. Бенефиты будут видны при включённом «Forward sing-box logs» (Diagnostics) на heavy traffic.

## 📦 Install

Стандартный путь: GitHub Release Assets (CI-built APK). На устройстве:

1. Скачать `app-arm64-v8a-release.apk` из release assets
2. Установить APK поверх предыдущей версии — **данные сохраняются** (subscriptions, profile, config lock state)
3. После установки тапнуть Connect — ничего не произойдёт без grant'а permissions:
   - Если в config'е НЕТ wifi rules — VPN запустится как обычно
   - Если ЕСТЬ wifi rules (через UI add или `PUT /config`) — появится dialog «Wi-Fi rules need permissions», тапнуть «Allow Wi-Fi info» (runtime prompt) и «Open Settings» для BACKGROUND_LOCATION

**На обновление с v1.7.1 — миграции не требуется.** После обновления:
- Новый блок «Notifications» в Background tab Settings (вместе с Battery)
- Новый toggle «Lock config from rebuilds» в Diagnostics tab
- Live tab в Statistics теперь работает без per-app session
- Battery prompt теперь one-tap (не список всех apps)

## 🇷🇺 LxBox v1.7.2 на русском

**Главное:** §050 — найдена и закрыта real root cause crash'а из §049, который мы 9 attempt'ов пытались пробить через ref-tracking patches. Оказалось — `WifiManager.connectionInfo` бросал `SecurityException` без location permission'а, exception проходил через JNI без handler'а и валил процесс с misleading `"Unknown reference: 42"`. Фикс: try/catch + permission gate + правильные permissions для Android 13+ (`NEARBY_WIFI_DEVICES`).

**Бонусом:**

- Wi-Fi rules `wifi_ssid:` / `wifi_bssid:` теперь реально работают на Android 13+. Verified на OnePlus / Android 15: правило с `outbound: direct-out` направляет трафик мимо VPN когда дома, и VPN остаётся активен на чужих сетях/cellular.
- Permission UX flow: понятный explainer dialog для notifications + actionable buttons для wifi (Allow runtime / Open Settings) + battery one-tap prompt вместо списка всех apps.
- Live tab в Statistics теперь показывает system-wide TCP/UDP events (раньше — только DNS).
- Toggle для §037 config lock'а в Diagnostics — можно pin'нуть экспериментальный config от UI-rebuild'ов и снять lock сам.

**Что НЕ сделано:** F22 part 2 (drainer back-pressure + EventChannel batching) — бенчмарки показали что текущий drainer достаточен для production. Оптимизации не release-blocker, отложены под отдельный коммит/PR.

См. [`docs/spec/tasks/050-libbox-debug-build/spec.md`](../spec/tasks/050-libbox-debug-build/spec.md) и [`findings.md`](../spec/tasks/050-libbox-debug-build/findings.md) — полный investigation log + corrected root cause analysis.
