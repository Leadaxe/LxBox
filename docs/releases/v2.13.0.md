# L×Box v2.13.0

**Канал можно сделать переключаемой detour-прослойкой.** На вкладке Channels
у канала появилась галка **Use as detour** (§248): помеченный ей канал (значок
⚙) становится целью detour для серверов, папок и подписок — и одновременно
исчезает из выбора целей правил. Смысл: переключаешь выбор в этом канале на
главном экране — и **весь детурящийся через него флот мгновенно переезжает на
другой upstream**, без правки каждого сервера. С галкой Auto прослойка сама
находит лучший сервер по urltest. А строки маршрута (в карточке соединения и
профайлере) переписаны так, что читаются **по ходу пакета** слева направо —
видно, куда и через что реально идёт трафик (§251/§252). Ядро без изменений —
**v1.14.0-lx.2**.

## 🆕 Новое

- **Detour-каналы** (§248) — новая роль канала. Галка **Use as detour** в
  редакторе канала превращает его в переключаемую detour-прослойку:
  - канал (значок ⚙) появляется в пикере detour у одиночных серверов, членов
    папок, подписок и папок целиком — рядом со списком серверов;
  - при выборе трафик цели идёт **через канал**, а канал сам решает, какой
    сервер сейчас использовать (обычный selector — вручную с главного экрана;
    Auto — по urltest автоматически);
  - переключил канал на главном экране — пересел весь флот, который через него
    детурится. Один рычаг вместо N правок Node Settings;
  - detour-канал исключён из целей правил (он теперь про транспорт, не про
    маршрут) и не может содержать block; пустой detour-канал деградирует в
    прямое соединение, а не в блокировку;
  - циклы (сервер входит в канал, а канал ведёт обратно на него) билдер
    разрывает автоматически — конфиг не падает;
  - всё доступно и через Debug API (`PATCH /channels/{tag}` с полем `detour`).

- **Строки маршрута читаются по ходу пакета** (§251/§252). В карточке
  соединения и профайлере путь теперь идёт слева направо в порядке движения
  трафика: вход → цепочка хопов → выход → назначение. Пара «канал и кого он
  сейчас выбрал» пишется вместе — `vpn-4 (🇳🇱 Нидерланды)`, а не двумя
  «хопами». Пример:
  `final ⇒ vpn-1 : WARP in → vpn-4 (🇬🇧 England) → vpn-1 (WARP out) → github.com`.

- **Превью цепочки detour в настройках подписок и папок** (§252). Строка
  «Phone → … → Internet» теперь разворачивает всю цепочку detour (цель → её
  собственный detour → … → канал с текущим выбором) — та же детализация, что
  была у одиночных серверов. Видно, куда и через что пойдёт трафик, ещё до
  подключения.

## 🛠 Фиксы

- **VPN не стартовал при включённом FakeIP-пресете и Force IPv4** (§246). Ядро
  1.14 запрещает сочетание устаревшей опции `strategy` в DNS-правиле с
  FakeIP — старт падал с «initialize dns router: Legacy strategy … is
  deprecated». Убрали legacy-`strategy` из DNS-аспекта RU-пресетов;
  принудительный IPv4 по-прежнему работает.

- **Диагностика: причина падения старта больше не теряется** (§250). Поле
  `last_start_error` в Debug API (`GET /state`) держит причину последнего
  сбоя старта до первого успешного подключения — раньше UI гасил её
  мгновенно, и поймать через API было нельзя.

## ⚙️ Изменения

- **Debug API `/channels`** — поле `detour` в GET/POST/PATCH; ответы мутаций
  несут блок `healed` (сколько ссылок вылечено); `/help` и справочник API
  обновлены. Инварианты: `vpn-1` не может быть detour-каналом (409),
  detour-канал не может включать block (409).

- **Storage** — у канала новое поле `detour` (внутри существующего ключа
  `channels`, бэкап-совместимость не затронута). Смена detour-роли, выключение
  или удаление канала автоматически чистят повисшие ссылки (правила → vpn-1,
  detour-ссылки → None) с уведомлением о числе исправленных.

обеих routing-моделях. ~90 новых кейсов; полный сьют — 1734 зелёных.
