# L×Box v2.20.8

A maintenance release. The core moved the `masque` config to the sing-box
standard shape, and the app followed: the HTTP version now lives in its own
`vhttp` key and the TLS options moved into a nested `tls` block. Nothing
changes for you — your saved links, imported configs and existing WARP nodes
keep working exactly as before. The default SNI for MASQUE also changed, which
fixes h3 tunnels that would not come up on some networks.

Технический релиз. Ядро привело конфиг `masque` к стандартной форме sing-box,
приложение — следом: версия HTTP переехала в собственный ключ `vhttp`, а
TLS-опции — во вложенный блок `tls`. Для вас ничего не меняется: сохранённые
ссылки, импортированные конфиги и уже добавленные WARP-узлы продолжают
работать как раньше. Заодно сменился SNI по умолчанию для MASQUE — это чинит
h3-туннели, которые в некоторых сетях не поднимались.

<summary><h2>🇬🇧 English</h2></summary>

## 🔧 Under the hood

**MASQUE moved to the core's new config schema.** The core renamed the fields
of the `masque` outbound: the HTTP version left `network` for its own `vhttp`
key, and the TLS options left the flat root for a nested `tls` block —
`sni` → `tls.server_name`, `skip_cert_verify` → `tls.insecure`, and the three
`fragment` options under `tls` as well. The old names stay accepted until
`v1.14.0-lx.30`, but each outbound using them prints a warning, and mixing an
old and a new name with different values refuses to start.

The app now writes only the new names, and never both — but it still *reads*
both. Links you saved earlier, configs from other people and older backups
parse exactly as before; a node moves to the new spelling the next time it is
saved. Nothing to migrate by hand.

A new `tls.disable_sni` option is understood too: a ClientHello with no SNI at
all. It is not the same as leaving the SNI empty — an empty value gets replaced
by the profile default. There is no switch for it in the interface; set it
through a link, an imported config or the config editor.

**The default SNI for MASQUE changed** from `consumer-masque.cloudflareclient.com`
to `www.cloudflare.com`. This only affects configs with no SNI of their own —
an explicit value still wins. With the previous name the h3 tunnel would not
come up on some networks; the name does not carry any authentication anyway,
since the endpoint is verified by pinning its ECDSA key.

**The HTTP version is no longer stored with the WARP registration.** It belongs
to a node, not to an account: the same keys produce both h3 and h2 nodes, and
the wizard asks for the version on every add. Old records keep their unused
field and it is simply ignored.

**TLS fragmentation now reaches MASQUE nodes** when they run over `h2`
(TCP+TLS). Over h3 there is nothing to fragment — QUIC does not carry TLS over
TCP — so those nodes are skipped silently.

**Diagnostics:** a MASQUE endpoint that accepts QUIC but never answers
CONNECT-IP now reports `masque: CONNECT-IP timed out` instead of a wall of
`http3: parsing frame failed`.

## 🧱 Core

Pinned core `v1.14.0-lx.25-rc.3` → `v1.14.0-lx.25-rc.5`.

## 🔧 Под капотом

**MASQUE переехал на новую схему конфига ядра.** Ядро переименовало поля
outbound'а `masque`: версия HTTP ушла из `network` в собственный ключ `vhttp`,
а TLS-опции — из плоского корня во вложенный блок `tls`: `sni` →
`tls.server_name`, `skip_cert_verify` → `tls.insecure`, туда же три опции
`fragment`. Старые имена принимаются до `v1.14.0-lx.30`, но каждый такой
outbound печатает предупреждение, а старое и новое имя сразу, с разными
значениями, роняют старт.

Приложение теперь пишет только новые имена и никогда оба — но по-прежнему
*читает* оба. Сохранённые ранее ссылки, чужие конфиги и старые бэкапы
разбираются как и раньше; узел переезжает на новое написание при следующем
сохранении. Руками мигрировать нечего.

Понимается и новое поле `tls.disable_sni` — ClientHello вообще без SNI. Это не
то же самое, что пустой SNI: пустой подменяется дефолтом профиля. Отдельного
переключателя в интерфейсе нет — задаётся ссылкой, импортом конфига или через
редактор конфига.

**SNI по умолчанию для MASQUE сменился** с `consumer-masque.cloudflareclient.com`
на `www.cloudflare.com`. Касается только конфигов без своего SNI — заданное
значение по-прежнему сильнее. С прежним именем h3-туннель в некоторых сетях не
поднимался; на аутентификацию имя всё равно не влияет, эндпоинт проверяется
пиннингом его ECDSA-ключа.

**Версия HTTP больше не хранится вместе с WARP-регистрацией.** Она принадлежит
узлу, а не аккаунту: одни и те же ключи дают и h3-, и h2-узлы, а мастер
спрашивает версию при каждом добавлении. В старых записях неиспользуемое поле
остаётся и просто игнорируется.

**Фрагментация TLS теперь доходит и до MASQUE-узлов** — тех, что работают по
`h2` (TCP+TLS). По h3 фрагментировать нечего: QUIC не несёт TLS поверх TCP,
поэтому такие узлы пропускаются молча.

**Диагностика:** MASQUE-эндпоинт, который принял QUIC, но не ответил на
CONNECT-IP, теперь сообщает `masque: CONNECT-IP timed out` вместо простыни
`http3: parsing frame failed`.
