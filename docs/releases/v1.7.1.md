## 🐞 Fixes

### §049 — sing-box wrapper deep audit + atomic CAS lifecycle fix

После многочасового side-by-side diff'а нашего Kotlin wrapper'а vs reference SagerNet/sing-box-for-android (correct commit `3b3883e` для libbox 1.13.11) выявлено 25 findings. 12 применены как fix'ы.

**Главный fix — race condition в lifecycle `fileDescriptor`** (диагностика [§047](../spec/tasks/047-tun-tcp-deterioration-diagnosis.md)):

`@Volatile` гарантирует publish/visibility, но **не атомарность compound-операции** «read-then-close-then-null». Mutations поля шли из 5 call-site'ов (`openTun`, `cleanupStaleResources`, `onRevoke`, `doStop`, `scope.cancel`), и две гонки потоков могли:

1. Прочитать одинаковый non-null `pfd`
2. Вызвать `pfd.close()` оба
3. Между этими событиями kernel мог переиспользовать fd-int
4. Sing-box, державший копию `pfd.fd`, начинал писать в чужой fd
5. Silent ENXIO → TCP-traffic via tun перестаёт работать через 15-30 минут после старта (но DNS / ICMP / sing-box internal `/delay` API продолжали работать — отсюда «плавающий» характер)

**Что сделано:**
- **F2** Replaced `@Volatile var fileDescriptor` → `AtomicReference<ParcelFileDescriptor?>`. Helper `closeFileDescriptor()` использует `getAndSet(null)?.close()` — единственный поток получает non-null PFD, остальные — no-op. Same для `commandServer`.
- **F3** Удалён `cleanupStaleResources()` (superfluous 5-й mutation site, аналога в reference нет — atomic helper'ы защищают без pre-cleanup'а). Также убрана `delay(500)` (была компенсацией для удалённого cleanup'а).
- **F5** `onRevoke` cleanup переведён на atomic helpers.
- **F4** `serviceReload` без status-flap (Started→Starting→Started); reference так и делает.
- **F26** LocalResolver полностью переписан на `DnsResolver.getInstance().query(defaultNetwork, ...)` (port 1:1 из reference). Старый `InetAddress.getAllByName()` шёл через system resolver, который при `tun.auto_route=true` мог рекурсивно идти ЧЕРЕЗ tun. Now bound к underlying network, мимо tun.

### Минорные fix'ы

- **F9** `Libbox.setLocale(Locale.getDefault())` в init — sing-box error messages теперь локализованы.
- **F12.1** `userName` поле в `findConnectionOwner` — Clash API `/connections` теперь видит package name юзера.
- **F12.3** `readWIFIState()` реальный impl (раньше всегда null) — sing-box `wifi_ssid` / `wifi_bssid` правила теперь матчатся.
- **F17** `getSystemProxyStatus()` возвращает реальный state (раньше всегда empty) — Clash dashboard'ы видят корректные available/enabled флаги.

## ✨ New

### §049 F15 — Allow VPN bypass toggle

App Settings → **«Allow VPN bypass»**. Default off (strict tunnel — наш default behavior). Включает `Builder.allowBypass()` для VPN — apps могут explicit'но через `ConnectivityManager.bindProcessToNetwork(network)` обойти tun. Применяется при следующем `openTun()` (старт VPN или reload). Reference (`Settings.allowBypass`) имеет identical toggle.

### §048 — Per-app trace inclusive observer with confidence

Closed 13 attribution gap'ов из live-диагностической сессии 2026-05-09. Per-app trace теперь не drop'ает события — каждое попадает в session с одним из 4 уровней `ConfidenceLevel` (`verified` / `secondary` / `inferred` / `unattributed`). Юзер видит **всё что произошло**, и видит **что точно его app, а что возможно**. **Live system-wide tab** (4-й tab Statistics) — discovery без выбора target.

См. [§048 spec](../spec/tasks/048-perapp-trace-attribution-gaps.md).

### §046 — Tunnel apps split-tunneling

Четвёртая вкладка в `Routing` — OS-level split-tunneling: какие apps идут через VPN-tun, а какие — direct по cellular/wifi (минуя sing-box полностью). 3 mode'а: `Off` / `Allow-list` / `Deny-list`. Native слой не трогали — `BoxVpnService.kt` уже умел читать `options.includePackage`/`excludePackage`.

См. [§046 spec](../spec/features/046%20tunnel%20apps%20split-tunneling/spec.md).

## 🏗 Under the hood

### F1 — split monolith

`BoxVpnService.kt` урезан 805 → **302 LOC** (Android Service hooks + PlatformInterface only). State ownership extracted в новый **`BoxLifecycle.kt`** (468 LOC, аналог reference's `BoxService.kt`). Implements `CommandServerHandler`, owns broadcast receiver, lifecycle methods.

### F22 — coalesced log dispatch

Bounded queue (`LOG_QUEUE_MAX=4096`) + single-pending drainer вместо `coreLogMainHandler.post {}` per line. На busy traffic + debug mode sing-box эмитит 100+ строк/сек → main looper больше не переполняется → меньше Flutter UI thread задержек.

## 📦 Install

Стандартный путь: GitHub Release Assets (CI-built APK). На устройстве:

1. Скачать `app-arm64-v8a-release.apk` из release assets
2. Если установлен старый билд — `Settings → Apps → L×Box → Storage → Clear data`
3. Установить APK (`Open` после скачивания, разрешить «Install unknown apps»)

**На обновление с v1.7.0 — данные сохраняются.** Никакой миграции не требуется. После обновления:

- Новый toggle «Allow VPN bypass» в App Settings (default off)
- Новый tab «Live» в Statistics
- Новый tab «Tunnel apps» в Routing
- §049 fix'ы применяются с следующим start VPN

## 🇷🇺 LxBox v1.7.1 на русском

**Главное:** §049 — найден и закрыт race condition в lifecycle tun-fd, из-за которого после ~8 часов работы VPN TCP через tun начинал плавающе деградировать (DNS / ICMP / sing-box internal все работали, но новые TCP-сокеты не открывались). Race был в `@Volatile var fileDescriptor` мутировавшимся из 5 разных потоков; теперь `AtomicReference` + atomic CAS на close().

**Бонусом:**
- Per-app trace стал inclusive — раньше silently дропал DNS-fail events / WebView traffic / unrecognized package'и. Теперь всё видно с confidence-меткой (verified / secondary / inferred / unattributed). + новый Live tab «всё что происходит на устройстве».
- Routing → Tunnel apps — стандартный Android split-tunneling: какие apps через VPN, какие direct.
- App Settings → «Allow VPN bypass» — opt-in для apps хотящих обойти tun (default off — strict tunnel).
- LocalResolver больше не ходит DNS через tun (мог рекурсивно loop'ать), теперь bound к underlying network.

**Что НЕ сделано:** on-device retest §047 race — требует физический телефон + 30+ min активного use. Если race повторится — следующий уровень анализа в §049 spec под `## Next steps`.

См. [`docs/spec/tasks/049-singbox-wrapper-deep-audit/spec.md`](../spec/tasks/049-singbox-wrapper-deep-audit/spec.md) — полный audit + implementation log + verification.
