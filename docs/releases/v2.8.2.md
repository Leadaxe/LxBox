## ✨ Подписка из файла (§129)

Раньше «Import from file…» пытался прочитать файл как одну запись и на списке
ссылок падал с `Input is not a subscription URL…`. Теперь:

**Как сделать:** ⋮ (меню добавления) → **Import from file…** → выбрать файл.

- Если в файле **больше одной** ноды → создаётся **файловая подписка** (в списке
  с бейджем **file** вместо URL).
- Если **одна** нода → как раньше, добавляется одиночный сервер.

**Что можно положить в файл** — то же, что отдаёт обычная подписка:

| Формат | Пример |
|---|---|
| Список ссылок | `vless://…`, `vmess://…`, `trojan://…`, `ss://…`, по одной на строку |
| base64 | закодированный список ссылок |
| Clash YAML | `proxies:` … |
| JSON-outbounds | массив sing-box outbound-объектов |
| **WireGuard / AmneziaWG** | INI-конфиг (`[Interface]` / `[Peer]`) |

Плюс заголовки в начале файла (`# profile-title: My servers`) подхватываются как
имя/метаданные подписки.

**Как работает:**

- Содержимое файла сохраняется **снапшотом** в кэш подписок. Подписка живёт из
  этого снапшота — при перезапуске приложения ноды поднимаются из кэша, как у
  обычной подписки.
- **Авто-обновление файловую подписку не трогает** (приложение не держит доступ к
  файлу между сессиями). Это сделано намеренно: при массовом авто-апдейте
  онлайн-подписок файловая **не слетит** — её ноды всегда остаются из кэша.
- **Обновить файловую** — вручную: long-press → **Edit source…** → Local file →
  выбрать файл заново (см. ниже).

## 🔧 Редактируемый источник

Долгая просьба — **менять URL подписки** без удаления и пересоздания (сменился
домен провайдера, опечатка). Теперь это часть общего механизма «сменить источник».

**Как:** long-press на подписке → **Edit source…** → попап:

```
( ) Online URL   [https://…            ]
(•) Local file   📄 servers.txt   [Choose…]
                        [Cancel]  [Save]
```

Переключатель **Online URL ↔ Local file** — можно поменять URL, либо перевести
подписку с онлайн на файл (и обратно). `id` подписки сохраняется — имя,
включённость, detour-настройки и привязки к каналам **не теряются**.

**Безопасно:** смена источника **транзакционна**. Старый источник заменяется
**только если новый успешно отдал ноды**. Если новый URL недоступен или файл
пустой/битый — ничего не меняется, подписка остаётся на прежнем источнике со
старыми нодами. Вы **не останетесь без нод** из-за неудачной смены.

## 🐞 Исправления

### Одна битая XHTTP-нода больше не роняет весь конфиг (§217)

Если в подписке попадалась XHTTP-нода с `uplink_http_method=GET` вне режима
`packet-up` (недопустимое для ядра сочетание), **весь** конфиг падал на старте —
туннель вообще не поднимался (`initialize outbound[361]: … can be GET only in
packet-up mode`). Теперь такой параметр приводится к безопасному значению, нода
остаётся рабочей, а рядом с ней в подписке показывается **⚠️** (и запись в лог).
Ядро rc.20 дополнительно страхует это на своей стороне.

### heartbeat не пугает после возврата из фона (§216)

В фоне мониторинг туннеля приостанавливается ради батареи. При возврате в
приложение первая проверка видела «тишину» за всё время сна и писала в DEBUG-лог
пугающее `Heartbeat: silent 2905s`, хотя туннель жив. Теперь первая проверка
после пробуждения не считается сбоем, а в логе — понятное «Resumed — syncing
tunnel…».

## 🔧 Прочее

- **idle-suspend включён по умолчанию (30 s)** (§128). Настройка **Suspend idle
  tunnels** (VPN Settings → System → Optimization) теперь `30 seconds` из коробки
  — экономия памяти/CPU/батареи при многих WireGuard-нодах работает сразу.
  Выключить: **Off**.
- **Ядро sing-box-lx → rc.20** (XHTTP GET-fallback, udpnat2 buffer fix, upstream
  sync). Детали ядра и ловушки при бампе — в [docs/KERNEL.md](KERNEL.md).
