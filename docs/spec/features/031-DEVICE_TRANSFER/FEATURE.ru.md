# Передача на устройство — настройки с телефона на телевизор по локальной сети

LxBox передаёт свои настройки VPN — подписки, серверы, правила маршрутизации,
DNS, раздельное туннелирование — с телефона на Android TV в той же
Wi-Fi-сети в два шага: телевизор показывает QR-код, телефон сканирует его и
отправляет. С пульта ничего не набирается,
через облачные сервисы ничего не идёт, а применяются настройки только после
подтверждения на экране получателя.

| Поле | Значение |
|------|----------|
| Фича | 031-DEVICE_TRANSFER |
| Тип | Продуктовая фича |
| Поглощает | — (новая, [§622](../../tasks/622-device-transfer-phone-to-tv.md)) |
| Состояние | ✅ реализована, 2026-10-16 (§622); ручные проверки подтверждения P4, P7, P8 на эмуляторах TV и телефона не проведены |

## Назначение

Настраивать VPN-клиент пультом мучительно: URL подписок, ссылки на узлы и
правила маршрутизации — длинные строки, а выбора файлов, чтобы загрузить
бэкап, на Android TV нет ([§372](../../tasks/372-android-tv-support.md)).
На телефоне рабочая настройка уже есть, и фича переносит её на телевизор
одним сканированием.

Принципы: **принимает только телевизор** — на телефоне и планшете пункта
приёма нет, там есть выбор файлов и клавиатура; **по умолчанию ничего не слушает** — приёмник существует, только
пока открыт его экран; **сети не доверяем** — локальная сеть может быть
общей, поэтому содержимое шифруется и аутентифицируется ключом, который
есть только в QR-коде; **один путь для входящих настроек** — передача — это
бэкап, доставленный по сети, и применяется он тем же восстановлением, что и
файл бэкапа, с теми же проверками и тем же подтверждением.

## Обещания

- **P1. Пока пользователь не попросил, ничего не слушает.** Приёмник
  открывает порт, только пока открыт экран «Receive settings»; уход с
  экрана, истечение сессии или завершённая передача его закрывают.
  **Свидетель:** юниты «close() is idempotent and the port refuses
  afterwards (P1)», «timeout closes the session and the port (P1)». **Мутация:** приёмник стартует вместе с приложением.
- **P2. Без ключа из QR-кода ничего не принимается.** Содержимое
  шифруется и аутентифицируется одноразовым ключом, который есть только в
  QR-коде на экране получателя. Содержимое, которое этим ключом не
  расшифровывается, отвергается, ничего не применяется. **Свидетель:**
  юниты «wrong key → 403, parse not called; 5th rejection closes (P2, P3)»,
  «corrupted ciphertext → 403», «foreign key → auth error», «corrupted ct →
  auth error», «corrupted nonce → auth error». **Мутация:** приём открытым текстом.
- **P3. Одна сессия — одна передача.** После первого принятого содержимого
  сессия закрывается, повторные попытки отвергаются. Получатель
  обрабатывает один запрос за раз; пришедший в это время отвергается как
  «занято» до чтения содержимого. После фиксированного числа отвергнутых
  попыток — конверт не разобран или не расшифрован — сессия тоже
  закрывается. **Свидетель:** юниты «valid envelope → 200, session closed,
  same parse as backup file (P3, P4)», «second request while the first is
  in processing → 503 busy (P3)», «5 garbage envelopes → 400 each, session
  closed (P3)», «wrong key → 403, parse not called; 5th rejection closes
  (P2, P3)».
  **Мутация:** сессия остаётся открытой после успеха.
- **P4. Передача применяется как бэкап.** Принятое содержимое проходит
  проверку и восстановление бэкапа
  ([017-BACKUP_AND_STORAGE · P4–P9](../017-BACKUP_AND_STORAGE/FEATURE.ru.md#обещания)):
  пользователь видит, что пришло, выбирает на получателе слияние или
  замену и подтверждает; без подтверждения ничего не меняется.
  **Свидетель:** юнит «valid envelope → 200, session closed, same parse as
  backup file (P3, P4)»; подтверждение — ручная проверка на эмуляторе TV (не
  проведена). **Мутация:**
  применение сразу при получении.
- **P5. Что отправлять, выбирает отправитель.** Те же категории, что при
  экспорте бэкапа; ключи Debug API по умолчанию выключены и без явного
  выбора не уходят
  ([017-BACKUP_AND_STORAGE · P1](../017-BACKUP_AND_STORAGE/FEATURE.ru.md#обещания)).
  **Свидетель:** виджет-тест «categories sent default to everything
  except Debug API (P5)».
  **Мутация:** отправка всего.
- **P6. Отказ назван.** Отправитель видит один из случаев: устройство
  недоступно (другая сеть или изоляция клиентов в Wi-Fi), код истёк, код
  не принят, содержимое слишком большое. Получатель видит, почему принятое
  нельзя применить. **Свидетель:** юниты «each answer has its own status», «closed
  receiver port → expired», «nobody answers → unreachable», «body over the
  limit → 413», «decrypted but not a backup → 422 with reason, session stays
  open (P6)». **Мутация:** общее «Error».
- **P7. Работающий VPN не мешает.** Приёмник доступен по локальному адресу
  при поднятом собственном туннеле; отправитель идёт на локальный адрес
  напрямую, не через свой туннель, что бы ни говорили его правила
  маршрутизации. **Свидетель:** ручная проверка с туннелем на обеих
  сторонах (не проведена). Запасной путь без физической сети: юнит «no
  non-VPN network → Dart client delivers to a live receiver». **Мутация:** отправка уходит в туннель отправителя и
  отваливается по таймауту.
- **P8. Приёмник управляется пультом.** Экрану приёма не нужны касания и
  ввод текста: видны QR-код, адрес, оставшееся время и состояние, экран не
  гаснет во время сессии, каждое действие доступно с D-pad.
  **Свидетель:** ручная проверка на эмуляторе TV (не проведена).
  **Мутация:** для
  подтверждения нужно коснуться элемента вне порядка фокуса.
- **P9. Ключ не утекает.** Ключ не пишется в журналы, в журнал запросов и в
  отчёты о падениях. **Свидетель:** юниты «session log never contains the key or the code
  text (P9)», «toString masks the key (P9)».
  **Мутация:** текст QR-кода в журнале.
- **P10. Принимает только TV.** Пункт приёма показывается только на
  устройстве в режиме телевизора (Android TV, Google TV); на телефоне и
  планшете его нет. Пункт отправки показывается только на устройстве с
  камерой. **Свидетель:** юниты «not a TV → no receive item; send only
  with a camera», «TV: receive only, even with a camera»; виджет-тесты «phone
  with camera: Send to TV, no receive item (P10)», «TV: receive item first, no
  Send to TV (P10)»; ручная проверка на эмуляторах TV и телефона (не
  проведена). **Мутация:** пункт приёма на
  телефоне.

## Управляемые параметры

Пользовательских настроек нет. Фиксированные значения:

| Параметр | Значение |
|----------|----------|
| Время жизни сессии | 10 минут |
| Порт | любой свободный, выбирается на сессию |
| Предел размера содержимого | 32 МиБ |
| Отвергнутых попыток (конверт не разобран или не расшифрован) до закрытия сессии | 5 |
| Запросов в обработке одновременно | 1, остальные отвергаются как «занято» |
| Шифрование | AES-256-GCM, nonce 96 бит, одноразовый ключ 256 бит на сессию |

Код передачи (содержимое QR), версия 1:

```
lxbox-transfer:1?a=<ipv4>:<port>[,<ipv4>:<port>…]&k=<ключ, base64url>&n=<имя устройства>
```

`a` — локальные IPv4-адреса получателя (Wi-Fi, Ethernet; без loopback и
туннеля), отправитель пробует их по порядку. `n` показывается отправителю
до отправки.

Содержимое: `POST /transfer` с JSON-конвертом
`{"v":1,"nonce":"<base64>","ct":"<base64>"}`; открытый текст — файл
полного бэкапа ([017-BACKUP_AND_STORAGE](../017-BACKUP_AND_STORAGE/FEATURE.ru.md)),
связанные данные — `lxbox-transfer/1`.

## Входы / Выходы

**Получатель.** Берёт: открытие экрана приёма, локальные адреса
устройства, один HTTP-запрос с конвертом. Отдаёт: QR-код и состояние
сессии на экране; принятый бэкап в предпросмотр восстановления; короткий
ответ отправителю (принято / отказ с причиной).

**Отправитель.** Берёт: выбранные категории, отсканированный код
передачи. Отдаёт: зашифрованный бэкап получателю, результат на экране.

## Поток данных

```
Получатель:  открыт экран → ключ + порт + адреса → QR на экране → ожидание
Отправитель: категории → скан QR → имя устройства → сборка бэкапа → шифрование
             → POST по адресам по очереди → результат
Получатель:  конверт → проверка размера → расшифровка (ключ) → разбор бэкапа
             → ответ отправителю → закрытие сессии → предпросмотр восстановления
             → пользователь: слияние / замена → применение
```

## Правила и гарантии

- Ключ, порт и адреса новые в каждой сессии; QR-код закрытой сессии
  бесполезен.
- Расшифровка идёт до любого разбора: неаутентифицированное содержимое как
  JSON не читается.
- «Принято» получатель отвечает только после успешного разбора бэкапа;
  применит ли его пользователь — дело получателя, обратно не сообщается.
- Уход из предпросмотра без применения выбрасывает принятое; на диск оно
  не пишется.

## Границы

- **Только телефон → TV.** Телефон → телефон и телефон → планшет —
  не передача: эти устройства импортируют файл бэкапа. TV не отправляет.
- **Только одна локальная сеть.** Ни ретрансляции через интернет, ни
  облачного аккаунта, ни обнаружения: QR-код — единственный способ найти
  получателя. Wi-Fi с изоляцией клиентов (часто гостевая сеть) делает
  передачу невозможной; отправитель называет этот случай.
- **Только IPv4** в версии 1.
- **Разово, не синхронизация.** Последующие изменения на телефоне сами на
  телевизор не попадают.
- **Отправителю нужна камера.** Устройство без камеры принимает, но не
  отправляет; ручного ввода кода нет (ключ слишком длинный для набора).
- **Веб-страницы нет.** Настройка получателя из браузера на ноутбуке —
  возможная будущая функция этой фичи, сейчас в неё не входит.
- Свойства устройства, которых нет в бэкапе (тема, состояние конкретного
  устройства), на получателе остаются как были
  ([017-BACKUP_AND_STORAGE · P8](../017-BACKUP_AND_STORAGE/FEATURE.ru.md#обещания)).

## Связанные фичи

- [017-BACKUP_AND_STORAGE](../017-BACKUP_AND_STORAGE/FEATURE.ru.md) —
  формат содержимого, категории, проверка и восстановление; эта фича
  только доставляет файл.
- [001-SUBSCRIPTIONS](../001-SUBSCRIPTIONS/FEATURE.ru.md) — QR-сканер и
  существующие пути импорта (URL, буфер обмена), которые остаются
  альтернативой.
- [010-VPN_SERVICE](../010-VPN_SERVICE/FEATURE.ru.md) — туннель на любой
  стороне не должен глотать локальную передачу (P7).
- [027-DEBUG_API](../027-DEBUG_API/FEATURE.ru.md) — другой локальный
  HTTP-сервер; он остаётся только на loopback, эта фича его не расширяет.

## Заметки по сопровождению

- Сервер Debug API для приёмника не переиспользовать: его обещания (только
  loopback, проверка Host) противоположны тому, что нужно приёмнику.
- Два эмулятора на одном хосте адресов друг друга не видят; ручной
  проверке нужен проброс порта через хост или реальные устройства.
