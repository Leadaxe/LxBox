# Автоматизация — плитка быстрых настроек, команды Tasker и события VPN

LxBox может запускать и останавливать VPN без открытия приложения: из плитки
быстрых настроек, меню иконки приложения или командами Tasker и MacroDroid.
Приложение также рассылает broadcast-события о туннеле, узлах и подписках;
приём команд и события выключены, пока пользователь их не включит.

| Поле | Значение |
|------|----------|
| Фича | 014-AUTOMATION |
| Тип | Продуктовая фича |
| Поглотила | `§032F` `§047F` |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Назначение

Включить туннель не должно требовать «открыть приложение, дождаться экрана,
нажать кнопку». Фича даёт туннелю входы снаружи приложения: одно касание в
системной шторке или в меню иконки на домашнем экране, команды от
автоматизаторов (Tasker, MacroDroid, Llama, Automate, `am broadcast` из
оболочки) и события, по которым автоматизатор узнаёт, что произошло.

Фича защищает три принципа:

- **Закрыто по умолчанию.** Приём команд и отправка событий выключены, пока
  пользователь явно не включил их; включение приёма требует подтверждения.
- **Внешний вход не обходит правила приложения.** Команда извне делает то же,
  что кнопка в приложении, с теми же предусловиями; «Стоп» извне так же
  окончателен, как «Стоп» в приложении.
- **Отказ отвечает, а не молчит.** Автоматизатор, ждущий ответа на команду,
  получает либо событие успеха, либо событие ошибки с кодом.

## Обещания

- **P1. Одно касание плитки переключает туннель.** Выключен → старт, включён →
  стоп; плитка сразу рисует целевое состояние, затем — реальное
  («Connecting…», «Connected», «Stopping…», «Disconnected»). Касание в
  переходной фазе игнорируется. Свидетель: ручная проверка — добавить плитку,
  коснуться при Stopped и при Started, коснуться во время подключения.
  Мутация: касание в фазе «Connecting…» запускает второй старт.
- **P2. Меню иконки отражает состояние.** Выключен — один пункт «Connect»,
  включён — «Disconnect», в переходной фазе — оба. Свидетель: ручная проверка
  долгим нажатием на иконку в трёх состояниях. Мутация: статичный пункт
  «Toggle» без учёта состояния.
- **P3. Разрешение VPN спрашивается один раз и объясняется.** Если системного
  разрешения на VPN ещё нет, быстрое подключение открывает приложение с
  пояснением «разовое разрешение», после согласия стартует туннель и
  возвращает пользователя туда, откуда он пришёл; отказ — сообщение, без
  повторного запроса. В режиме Proxy разрешение не спрашивается. Свидетель:
  ручная проверка на чистой установке. Мутация: попытка показать системный
  диалог прямо из шторки.
- **P4. Сбой быстрых переключателей не ломает туннель.** Ошибка обновления
  плитки или меню иконки (старые версии ОС, прошивки) не мешает старту и
  остановке. `без свидетеля`.
- **P5. Команды извне выключены по умолчанию.** Пока «Accept automation
  commands» выключен, ни прямая команда, ни плагин автоматизатора не
  исполняются. Свидетель: ручная проверка — `am broadcast -a
  com.leadaxe.lxbox.START_VPN` при выключенном переключателе ничего не делает.
  Мутация: приём включён в чистой установке.
- **P6. Предусловия команды проверяются до действия.** Пустой `tag`/`group` →
  `bad_request`; не выбрана группа, опущен туннель или приложение не готово →
  `conflict`; несуществующая группа → `not_found` и никакого
  `ACTIVE_GROUP_CHANGED`. Свидетель: юниты «пустой tag → BadRequest», «без
  home → Conflict», «группа выбрана, туннель опущен → Conflict», «несуществующая
  группа → NotFound (без ложного события)». Мутация: `SET_GROUP` на
  несуществующую группу эмитит смену группы.
- **P7. Провал команды отвечает событием без утечек.** Отказ команды даёт
  `VPN_ERROR` с `code`/`message`; внутренняя ошибка отдаётся как
  `error`/`internal error`, подробности — только в журнал. Свидетель: юниты
  «DebugError → его code/message», «произвольное исключение → generic (детали
  не утекают)». Мутация: в `message` уходит текст исключения.
- **P8. Повторный выбор активного узла — подтверждение, а не переключение.**
  `SWITCH_NODE` на уже активный узел не рвёт соединения и отвечает
  `NODE_ALREADY_ACTIVE`. Свидетель: юнит «switchNode на уже активную ноду —
  no-op + NODE_ALREADY_ACTIVE». Мутация: повторный re-select узла.
- **P9. События уходят только по включённым категориям.** Lifecycle, State,
  Subscription включаются независимо; все выключены по умолчанию.
  Свидетель: юниты «all OFF — emit no-op», «lifecycle gate independent of
  state/subs», «state gate emits node/group only». Мутация: общий гейт на все
  категории.
- **P10. Сбои подписки не заспамливают.** `SUB_REFRESH_FAILED` — не чаще раза в
  минуту на подписку; остальные события без ограничения. Свидетель: юниты
  «SUB_REFRESH_FAILED capped 1/min per sub_id», «SUB_REFRESHED not throttled».
  Мутация: ограничение общее на все подписки.
- **P11. «Стоп» извне окончателен.** Остановка с плитки, из меню иконки,
  командой или плагином гасит идущий цикл страховки узлов — туннель не
  поднимается обратно. Свидетель: юнит «нативный Stop (vpn-stop-requested) в
  фазе checking → старта нет». Мутация: внешний стоп не сообщается приложению.
- **P12. Условие автоматизатора отвечает сразу.** Проверки «VPN is up»,
  «Active node =», «Active group =» отвечают без запуска интерфейса;
  нет данных или значения → «неизвестно», профиль не активируется. Свидетель:
  ручная проверка — условие в MacroDroid/Tasker при закрытом приложении.
  Мутация: ответ ждёт запуска интерфейса.
- **P13. События не несут секретов.** Только метки: теги узлов, имена групп,
  статус, маскированный хост подписки. `без свидетеля`.

## Контролируемые параметры

| Настройка | Значения | Дефолт |
|-----------|----------|--------|
| Accept automation commands | вкл/выкл; включение — через диалог-предупреждение | выкл |
| Emit: Lifecycle / State / Subscription | вкл/выкл каждая; первое включение — через пояснение | все выкл |
| Quick Settings tile → Add | системный запрос добавить плитку (Android 13+) | — |
| Первый запуск: предложение добавить плитку | показывается один раз, где ОС умеет | — |

Ключей конфига ядра фича не отдаёт. Публичные контракты — строки команд и
событий, формат настроек плагина (см. функции). Источник правды для
пользователя — `docs/AUTOMATION.md` (+ `AUTOMATION.ru.md`).

## Входы / Выходы

**Входы:** касание плитки и её долгое нажатие; пункт меню иконки; команды
`com.leadaxe.lxbox.<ACTION>` с extras; вызовы плагина автоматизатора (действие и
проверка условия); статус туннеля; смены узла/группы, итоги обновления
подписок, найденное обновление приложения.

**Выходы:** старт/стоп туннеля и действия приложения (смена узла и группы,
пересборка конфига, обновление подписок, сброс сети, URL-тест); вид плитки и
состав меню иконки; события `com.leadaxe.lxbox.event.<EVENT>`; ответ условия
(выполнено / не выполнено / неизвестно); строки журнала с фильтром
`automation`.

## Data flow

```
касание плитки / пункт меню / команда / плагин
  → приём (быстрые входы — всегда; команды — только при включённом приёме)
  → старт/стоп/переключение: сразу в службу туннеля (без интерфейса);
    нет разрешения VPN → приложение открывается ради разового согласия
  → остальные команды → общие обработчики (те же, что у Debug API)
      → предусловия → действие | ошибка → VPN_ERROR(code, message)
  → смена статуса / узла / группы / подписки
      → зеркало для условий плагина и списков выбора
      → событие, если категория включена (с ограничением частоты)
      → перерисовка плитки и меню иконки
```

## Правила и гарантии

- Старт, стоп, переключение туннеля — одинаковы для всех внешних входов;
  прочие команды — те же обработчики и коды ошибок, что у Debug API.
- `START_VPN` при поднятом туннеле ничего не делает; `TOGGLE_VPN` без
  разрешения VPN открывает приложение ради согласия.
- Успех команды подтверждается профильным событием (State), провал — `VPN_ERROR`
  (Lifecycle); для «запрос-ответ» нужны обе категории.
- Барьер приёма один — главный переключатель; разрешения «только для
  доверенных приложений» нет, события открыты любому подписчику.

## Границы

- Не делает: выбор узла или группы с плитки; виджет на домашнем экране;
  часы и автомобильные интерфейсы; SDK для сторонних разработчиков;
  фильтр «доверенных» отправителей.
- Health-события (`HEARTBEAT_FAILED`, `LATENCY_DEGRADED`, `UNATTRIBUTED_BURST`) и
  `PERMISSION_NEEDED` — имена зарезервированы, источника нет; тумблера
  категории Health в настройках нет.
- Команды, кроме старта/стопа/переключения, и все события требуют живого
  приложения; при выгруженном интерфейсе команда пропускается без ответа.
- `ACTIVE_NODE_CHANGED` приходит только на явный выбор узла, `reason` всегда
  `user`; смены автовыбором и автоматизацией с `reason` `urltest` / `automation`
  (`047F`) — не планируются (решение владельца 2026-09-29, аудит [591](../../tasks/591-spec-kit-revision-audit.md)).
- Уведомление службы с кнопками Stop / Reconnect — 010-VPN_SERVICE.
- Удалённое управление по HTTP с токеном — Debug API,
  [027-DEBUG_API](../027-DEBUG_API/FEATURE.ru.md).
- **Зависит от возможностей ОС:** плитка шторки, динамическое меню иконки,
  системный запрос на добавление плитки (Android 13+), разовый диалог
  разрешения VPN, доставка широковещательных команд и событий, прошивки с
  запретом автозапуска (MIUI, ColorOS). Живое обновление плитки и меню
  гарантируется с Android 11; на более старых плитка обновляется при открытии
  шторки, меню иконки нет.

## Связанные фичи

- [010-VPN_SERVICE](../010-VPN_SERVICE/FEATURE.ru.md) — служба туннеля,
  которой внешний старт/стоп управляет напрямую; её уведомление с кнопками

- [027-DEBUG_API](../027-DEBUG_API/FEATURE.ru.md) — Debug API, чьи

## Особенности сопровождения

- Имена команд, событий, extras и формат настроек плагина — публичный API:
  переименование ломает сценарии пользователей молча. Меняется контракт —
  правится `docs/AUTOMATION.md` и его русская версия в том же изменении.
- Все внешние входы старта обязаны одинаково проверять режим: в Proxy запрос
  разрешения VPN рвёт чужой VPN (§192). Новый вход — проверить все.
- Новый путь «Стоп» мимо приложения обязан сообщить приложению об остановке,
  иначе цикл страховки поднимет туннель обратно (§510 M2).
- Ограничение частоты проверяется по настенным часам; ровно 60-секундную
  границу юнит не ловит (§219).
