# Приём команд — управление LxBox из Tasker и shell

Приём выключен, пока пользователь не включит «Accept automation commands».

| Поле | Значение |
|------|----------|
| Фича | [014-AUTOMATION](../FEATURE.ru.md) |
| Обещания | P5, P6, P7, P8, P11 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Принимает публичные команды от автоматизаторов и оболочки (`am broadcast`,
Tasker «Send Intent», цель — Broadcast Receiver) и исполняет их так же, как
соответствующее действие в приложении или в Debug API. Список команд с
кнопкой копирования показан в App Settings → Automation.

## Параметры

| Настройка | Значения | Дефолт |
|-----------|----------|--------|
| Accept automation commands | вкл/выкл; включение — после предупреждения «любое приложение на устройстве сможет управлять VPN» | выкл |

Команды (префикс `com.leadaxe.lxbox.`):

| Команда | Extra | Действие | Требует |
|---------|-------|----------|---------|
| `START_VPN` | — | старт; при поднятом — ничего | разрешение VPN (кроме Proxy) |
| `STOP_VPN` | — | стоп | — |
| `TOGGLE_VPN` | — | переключить относительно статуса | — |
| `SWITCH_NODE` | `tag` (String) | активный узел в текущей группе | выбранная группа, туннель поднят |
| `SET_GROUP` | `group` (String) | активная группа | группа существует |
| `REBUILD_CONFIG` | — | пересобрать конфиг из подписок | конфиг не заблокирован для отладки |
| `REFRESH_SUBS` | `force` (Bool) | обновить подписки | обновлятель готов |
| `RESET_NETWORK` | — | сброс соединений, DNS, переподключение сокетов | туннель поднят |
| `URLTEST_GROUP` | `group` (String) | URL-тест группы | туннель поднят |

## Входы / Выходы

**Входы:** команда с extras; состояние приложения (группа, узлы, туннель).
**Выходы:** действие; при провале — `VPN_ERROR` (см. «Исходящие события»);
журнал: `[automation] action <name> → ok / ERROR <code>`; факт приёма — только
в системном журнале под меткой `LxBoxIntent`.

## Правила и инварианты

- Пока приём выключен, команды не доходят ни до одного обработчика — это
  единственный барьер; отдельного «пропуска» для приложений нет.
- `START_VPN`, `STOP_VPN`, `TOGGLE_VPN` исполняются без интерфейса приложения.
  `TOGGLE_VPN` без разрешения VPN открывает приложение ради согласия (как
  плитка); `START_VPN` согласие не запрашивает — старт без разрешения
  кончается ошибкой туннеля.
- Остальные команды исполняются общими обработчиками с кодами ошибок Debug API:
  пустой `tag`/`group` → `bad_request`; нет группы, опущен туннель, блокировка
  конфига, приложение не готово → `conflict`; нет группы с таким именем →
  `not_found`; сбой сборки конфига → ошибка ядра/сборки. Каждый провал —
  `VPN_ERROR`; сырое исключение наружу не уходит.
- `SET_GROUP` на несуществующую группу не меняет группу и не шлёт
  `ACTIVE_GROUP_CHANGED`.
- `SWITCH_NODE` на уже активный узел соединения не рвёт и отвечает
  `NODE_ALREADY_ACTIVE`.
- `force` принимает логическое значение; строковые `true`/`1`/`yes` читаются
  как «да», всё остальное — «нет».
- Любой «Стоп» извне гасит идущий цикл страховки узлов.
- Приём никогда не роняет процесс: ошибка разбора команды пишется в журнал.

## Границы

- Команды без обязательного extra (`SWITCH_NODE` без `tag` и т.п.) и
  неизвестные команды отбрасываются с записью в системный журнал, без
  `VPN_ERROR`.
- Команды, кроме старта/стопа/переключения, требуют загруженного интерфейса
  приложения; иначе пропускаются без ответа.
- Нет ответа «в тот же вызов»: результат узнаётся только из событий.
- Нет проверки отправителя и нет разрешений по командам.
- Зависит от возможностей ОС: доставка широковещательных команд, запрет
  автозапуска в прошивках.
