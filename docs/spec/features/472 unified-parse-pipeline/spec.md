## 1. Зачем

Сегодня узел попадает в модель двумя независимыми путями:

- тринадцать URI-парсеров (`services/parser/uri_parsers/*`, `transport.dart`)
  строят `NodeSpec` напрямую из ссылки, и каждый несёт свои правила значений;
- вход JSON (`parseSingboxEntry`, Xray-конвертер в `json_parsers.dart`) строит
  ту же модель из карты — со своей копией тех же правил.

Санитайзер реестра (фича 460) приставлен сбоку: при разборе он видит
`emit()` уже построенной модели, а модель сама фильтр. Что из этого выходит,
показал один день 18.09.2026: нормализация gRPC жила в трёх местах (§468),
obfs-коды hysteria2 терялись на JSON-пути (§469), `value` у гейта запрета не
ставился вовсе (§469), а коды мусора у JSON-узла (`flow_deprecated`,
`unknown_key`, `tls_field_unsupported_naive`, `reality_short_id_invalid`) на
узел не попадают — их знает только гард сборки, и в шторке Warnings их нет
(§470). Раннер корпуса вынужден склеивать два пути сам.

У лаунчера путь один: вход → карта sing-box → санитайзер по реестру → тело.
Правило записано один раз, в реестре.

## 2. Решение

Конвейер на входе — как у лаунчера. Типизированная модель остаётся.

```
ссылка ──маппер──┐
                 ├─► сырая карта ─► санитайзер по реестру ─► чистая карта ─► parseSingboxEntry ─► NodeSpec
JSON / Xray ─────┘                     │
                                       └─► warnings (code, path, value) ─► NodeSpec.warnings
```

- **Маппер** переводит диалект ссылки в карту sing-box и **не судит
  значения**: алиасы параметров, userinfo, порт, транспорт. Правила перевода
  описаны секцией `mapper` реестра; исполняем их кодом, реестр — норма и
  предмет сверки (тест: каждое правило `mapper` покрыто).
- **Санитайзер** — единственный судья значений. Рукописные правила из
  парсеров уходят по мере переезда протокола (спека 460, «Осталось на W2»,
  п. 3). Гейты `min_core`/`platform` при разборе выключены, как в W2a.
- **`parseSingboxEntry`** — единственный путь «карта → модель». Он уже
  написан; по мере переезда из него уходят правила, которые исполнил
  санитайзер, остаётся приведение к типам модели.
- **`NodeSpec` не уходит.** На нём стоят формы вкладки Settings, `toUri()`,
  identity, цепочки, WARP, detour. Модель — типизированное представление
  чистой карты, а не место, где принимаются решения о значениях.
- **`rawSource` не меняется**: у ссылки — ссылка, у JSON — JSON (§454–§456).
  Узел `origin.kind: json` по-прежнему уходит в ядро дословно (§455);
  конвейер даёт ему предупреждения, тело не трогает.

Чего НЕ делаем: не заменяем модель картой; не генерируем маппер из реестра
(возможно позже, отдельным решением); не меняем формат хранения; экраны не
трогаем — шторка W2b и показ уровней §471 получают больше кодов сами.

## 3. Инварианты каждого шага

1. Корпус лаунчера зелёный целиком (URI и тела, `warnings[]` сверяются),
   новых per-app override не заводить.
2. Golden-конфиги (`rich_v0`, `avd_v0` и прочие) байт в байт, без
   перегенерации. Если шаг требует перегенерации — это отдельное решение
   владельца с диффом в отчёте.
3. `parseUri(spec.toUri()) ≈ spec` для переезжающего протокола.
4. Identity узла не меняется (иначе у пользователей слетят выбор узла,
   отключения и цепочки): тест на identity-хеш по фикстурам протокола до и
   после.
5. Перф: разбор 2000 узлов — не хуже ×1,5 к текущему (замер W2a: 42 мс
   разбор + 95 мс аннотация).
6. Один шаг — один протокол (или один слой) — один коммит, перед каждым
   полный зелёный прогон. Между шагами приложение рабочее.

## 7. Что вышло: шаг 1 (18.09.2026, `e00b09b9`)

JSON-половина: санитайзер реестра идёт по ДОСЛОВНОЙ карте узла, его коды
встают на `NodeSpec.warnings`, раннер тел читает один источник.

### 7.1 Что изменилось в конвейере

У JSON-входа проходов санитайзера стало ДВА, и порядок между ними значим
(`parse_all.dart`):

1. `annotateAllFromRawBody` (новый, `parse_warnings.dart`) — по дословной
   карте провайдера. Её узел уже носит: это `rawSource` (§454–§456), объект
   outbound'а как он пришёл. В ней ещё лежит то, что типизированный парсер
   снимает по дороге в модель: ключ вне схемы, `flow` из чёрного списка,
   TLS-поле, запрещённое схеме, значение не того типа.
2. `annotateAllWithRegistry` (был, §460 W2a) — по `emit()` модели. Им
   по-прежнему судятся URI/INI-узлы, у которых дословной карты нет, и им же
   ловятся значения, которые поставил САМ разбор (нормализация, дефолты
   `all_or_nothing`).

Дословный идёт первым: при совпадении пары `(code, path)` остаётся пришедшая
раньше, а её `value` называет то, что лежало в теле, а не то, во что разбор это
превратил.

**Границы шага соблюдены.** Тело узла не меняется — очищенную карту разбор
выбрасывает, чистит по-прежнему гард сборки (`builder/registry_gate.dart`
не тронут), `rawSource` остаётся дословным. Гейты `min_core`/`platform` при
разборе выключены на обоих проходах. `emit()` не менялся.

**Дедуп стал точнее.** Раньше рукописный класс закрывал свой код ЦЕЛИКОМ. Это
годилось, пока коды приходили по одному, но санитайзер по дословной карте шлёт
`tls_field_unsupported_naive` сразу на шесть путей одного узла, и грубый дедуп
съел бы весь набор из-за одного рукописного `InsecureTlsWarning`. Теперь дедуп
по паре `(code, path)`: класс, который путь несёт, закрывает только свой путь;
класс без пути — по-прежнему код целиком (приписать ему адрес было бы
выдумкой, а `path` нормативен). Остаётся одна запись, и предпочтение у той,
что несёт путь. Таблица путей рукописных классов переехала из раннера
(`corpus_warnings.dart`, `_legacyWarningPath`) в lib
(`warning_codes.dart`, `handwrittenWarningPath`) — тем же порядком, каким туда
переехала `kWarningCodes`, и по той же причине: второй потребитель.

### 7.2 Xray-JSON — остаётся на шаг 8

У Xray-узла `rawSource` — pretty-print объекта **Xray**
(`json_parsers.dart`, `_prettyJson(o)`), а санитайзер судит карту **sing-box**.
Общих ключей у них нет даже для типа записи: `protocol` против `type`,
`streamSettings` против `transport`, `settings.vnext[].users[]` против `uuid`.
Дословной sing-box-карты у Xray-узла не существует, пока её не построит маппер
«Xray-карта → sing-box-карта» — это шаг 8. Судить дословную Xray-карту
sing-box-схемой значило бы выдать `unknown_key` на каждый законный ключ Xray.

Признак, по которому проход опознаёт свой вход, — JSON-объект с полем `type`:
ссылка и INI не начинаются с `{`, Xray поля `type` не несёт.

### 7.3 Раннер тел

`_allWarningsOf` и `_rawBodyOf` из `body_contract_test.dart` удалены, сверка
читает `matched.first.warnings`. Ожидания корпуса не менялись ни на кейс:
коды, пути, значения и порядок сошлись с контрактом теми же, какими их давало
объединение двух путей. Список `_pendingWarningNodes` остался пустым.

Кодов на узле в кейсах §470 (было → стало): `vless_junk_pair` 0 → 3,
`manual_object_junk` 0 → 2, `outbound_array_tls_fields` 1 → 8 (узел
`naive-junk-tls` 0 → 6, `vless-reality-key-share-junk` 0 → 1, у
`trojan-full-tls` `field_conflict` как был), пары QUIC (`hysteria2`, `tuic`)
без изменений — их коды ставил §469 на пути разбора.

## 8. Что вышло: шаг 2 (18.09.2026, `ac68e040`)

Каркас маппера и конвейер целиком; пилот — trojan. Остальные двенадцать схем
идут прежним путём, `parseUri` маршрутизирует по схеме
(`kPipelineSchemes`).

### 8.2 Решение по второму проходу

Проход по `emit()` (`annotateAllWithRegistry`) **не снят**, а пропускается
адресно для узлов конвейера (`isPipelineParsed`).

Снять целиком нельзя: им судятся URI/INI-узлы двенадцати непереехавших схем и
значения, которые ставит САМ разбор. Оставить на переехавших — тоже: дедуп по
`(code, path)` дубли бы снял, но дело не в дублях, а в `value`. Санитайзер
конвейера видит сырое значение ссылки (`fp=HelloChrome_120`), проход по
`emit()` — уже канонизированное (`chrome`); выигрывает пришедший первым, то
есть ответ решался бы порядком вызовов, а не правилом. С отметкой источник
кодов у такого узла ровно один, и `value` называет написанное автором.

Отметка — `Expando`, не поле модели и не запись в `warnings`: `NodeSpec` это
хранимая форма узла, служебный флаг в ней уехал бы в бэкап (§221) и в
identity.

### 8.3 Снятые рукописные правила (пять) и коды из реестра

Из TROJAN-пути; `transport.dart` не тронут — по нему продолжают ходить
остальные схемы (и `parseTrojanTls` всё ещё зовёт `http_parser.dart`).

| Было рукописным | Стало правилом реестра | Код |
|---|---|---|
| `_guardUrlPath` — битый percent-путь снимался вручную | `transports.json` → `path`, `format: url_path` | `type_invalid` с `path` и значением |
| `normalizeTlsFingerprint` — мусорный `fp` → `chrome` + класс | `tls.json` → `utls.fingerprint`: enum + `on_invalid: coerce chrome` | `utls_fp_unknown` (был `UnknownFingerprintWarning` без адреса) |
| `InsecureTlsWarning` при `insecure` | `tls.json` → `insecure` | код реестра с путём `tls.insecure` |
| `_normalizeAlpn` — drop элемента, не похожего на ALPN-id | `tls.json` → `alpn`, `listable_string` | — (значение проходит, как и раньше) |
| `TlsSpec.disabled` → `tls:{enabled:false}` в эмиссии | маппер блока не кладёт вовсе | — (правило `security_none_no_tls`, SPEC 045) |

Рукописным осталось то, что судить нечем, — ПЕРЕВОД написания: алиасы
параметров (`sni`/`peer`/`host`, семейство `insecure`), псевдонимы uTLS
(`hellofirefox_auto` → `firefox`), `?ed=N` хвостом пути, раскрутка
многократного percent-кодирования ALPN и пути. Это по определению работа
маппера, и реестр описывает её секцией `mapper`, а не правилами значений.
Раскрутка ALPN переехала В МАППЕР из `_normalizeAlpn` (реестр зовёт
`tls.alpn` listable без нормализации — «пишется в той форме, в какой
пришло»), а суждение «элемент не похож на ALPN-id» снято: его там не было и у
Go.

### 8.4 Покрытие секции `mapper`

`test/parser/mapper_rules_coverage_test.dart` — страж: для каждой переехавшей
схемы каждое mapper-правило реестра обязано быть либо покрыто тестом в этом
же файле, либо названо в `_knownGaps` с причиной. Правил, относящихся к
trojan, семь; шесть покрыты, одно в расхождениях:

- `sni_heuristic_falls_back_to_server` — `sni` без `.` и `:` должен уступать
  адресу сервера. **В LxBox не реализовано ни на одном входе trojan** — ни
  старым парсером, ни конвейером (у hysteria2 и anytls та же эвристика есть).
  Включение изменило бы тела и identity живых узлов, поэтому это отдельное
  решение владельца, а не попутная правка шага 2.

## 10. Что вышло: шаг 4 (18.09.2026, `169c8d76` + vmess/ss)

Две схемы, два коммита. vmess — самая «неурийная» из всех: ссылка это
контейнер, и форм у него две. shadowsocks — первая схема, у которой после
переезда не осталось рукописных правил значения ВОВСЕ.

### 10.1 Маппер принимает ТЕКСТ, а не `Uri`

Шаги 2 и 3 передавали мапперу `Uri`: у trojan и vless ссылка и есть URI.
У vmess и shadowsocks это не так, и разница не косметическая. `Uri`
приводит authority к нижнему регистру, а за `vmess://` в том самом месте
лежит base64: `eyJ2IjoiMiJ9` становится `eyj2ijoimij9` и не декодируется
вовсе. Та же беда у legacy-формы `ss://base64(method:password@host:port)`.

Поэтому `typedef UriMapper` теперь принимает исходный текст, а общего
`Uri.tryParse` в конвейере нет: trojan и vless зовут его сами первой
строкой. Изменение на четыре строки, но без него шаг не делается.

Вторая ловушка того же рода — **тег-фолбэк**. Он строился по имени схемы, и
у первых трёх схем имя схемы совпадало с именем типа тела. У shadowsocks
нет: ссылка `ss://`, тело `shadowsocks`. Возьми конвейер имя схемы —
безымянный узел получил бы тег `ss-host-8388` вместо
`shadowsocks-host-8388`, а тег И ЕСТЬ identity (`node_hash.dart`), то есть
у живых узлов слетели бы выбор, отключения и цепочки. Фолбэк теперь
строится по `body['type']`, и на это есть тест.

### 10.2 vmess: снятые правила и что осталось

Маппер (`mappers/vmess_mapper.dart`) переводит ОБА диалекта в одну карту:
base64-JSON v2rayN и legacy cleartext (`method:uuid@host:port?query`,
правило реестра `legacy_cleartext_fallback`). Ветки по диалекту внутри
общих частей нет ни одной — различие выражено тем, что `tlsMapFromQuery` и
`transportMapFromQuery` принимают `Map<String, String>`: объект v2rayN
приводится к той же плоской карте «имя → строка», что и query.

Обобщение общих частей потребовалось ровно одно — **`sniAliases`**: цепочка
SNI у контейнера это `sni` → `host` → сервер, у share-URI — `sni` → `peer`
→ `host` → сервер (ключ `host` у контейнера адресует транспорт). Аргумент,
а не ветка; инварианты trojan и vless остались зелёными.

| Было рукописным | Стало правилом реестра | Код |
|---|---|---|
| `normalizeTlsFingerprint` — мусорный `fp` → `chrome` | `tls.json` → `utls.fingerprint`, enum + `on_invalid: coerce chrome` | `utls_fp_unknown` (был `UnknownFingerprintWarning` без адреса и значения) |
| `InsecureTlsWarning` при `insecure` | `tls.json` → `insecure` | код реестра с путём `tls.insecure` |
| `_guardUrlPath` — битый percent-путь транспорта | `transports.json` → `path`, `format: url_path` | `type_invalid` |
| `_normalizeAlpn` — drop элемента, не похожего на ALPN-id | `tls.json` → `alpn`, `listable_string` | — (значение проходит) |
| `TlsSpec.disabled` → `tls:{enabled:false}` в эмиссии | маппер блока не кладёт вовсе | — (`security_none_no_tls`, SPEC 045) |

Рукописным остался ПЕРЕВОД написания — работа маппера по определению:
выбор формы, имена ключей контейнера (`add`/`id`/`aid`/`scy`), `net=h2` как
«TLS включён принудительно», `chacha20-ietf-poly1305` как имя того же шифра
в диалекте Xray.

Одно поведение при этом СТАЛО ШИРЕ, и намеренно: `insecure` в контейнере
раньше читался ровно как `'1'` или булево `true` (`parseVmessTls`), а общая
часть принимает всё семейство имён и тройку истины `1|true|yes` — то есть
целевой набор, записанный реестром (`tls.json` /tls/params/insecure, DRIFT
§2(a), «объединение обоих проектов»). Корпус этот путь не покрывает ни одним
кейсом, `true`/`'1'` дают прежний результат, а `'true'`/`'yes'` прежде молча
терялись — расширение идёт в сторону контракта, не от него.

> **ЗАКРЫТО §474 (контракт 1.1.7, §24.16).** Лаунчер решил в пользу кода:
> подмена больше не молчит. У `security` появился собственный
> `vmess_security_unknown` (warning) вместо общего `type_invalid` — поле не

### 10.3 shadowsocks: рукописных правил значения не осталось

Три формы записи — SIP002, legacy (вся запись в base64) и SS2022 — это

## 11. Что вышло: шаг 5 (18.09.2026, hysteria2 + tuic)

Два коммита, по схеме на каждый.

Первые QUIC-схемы. Главное отличие от шагов 2–4 структурное: до этого шага
запрещённые на QUIC блоки `tls.utls`/`tls.reality` срезал ЭМИТТЕР, то есть
раньше судьи, и правило реестра до них не доезжало вовсе.

### 11.1 `forbiddenTlsBlockWarnings` на пути ссылки — снят

Санитайзер разбора (W2a) смотрел на `emit()` уже построенной модели, а
`emitHysteria2`/`emitTuic` зовут `TlsSpec.toSingboxForQuic`, где блоков уже
нет. Поэтому §469 ставил `tls_not_applicable_quic` рукописным проходом:
парсер спрашивал у реестра схему `tls`, шёл по её `order` и на каждом поле с
подходящим `forbidden_for` заводил код сам.

На конвейере этого не нужно. Маппер кладёт `utls` и `reality` в сырую карту
ОБЫЧНЫМ порядком — тем же вызовом `tlsMapFromQuery`, что у trojan и vless, —
и санитайзер снимает их правилом `forbidden_for`/`forbidden_codes`, по одному
коду на блок, со значением по CANON §6. Маппер о QUIC не знает ничего.

Проверено, что подмены не произошло: `value` кода совпал с эталоном старого
пути ПОБУКВЕННО (`map[enabled:true fingerprint:chrome]`), включая обрезку
длинного ключа REALITY на 64 руны. Рендер общий (`renderWarningValue`), и
рукописный проход звал его же.

**Что осталось.** Сама функция `forbiddenTlsBlockWarnings` жива ради ОДНОГО
вызывающего — ветки **masque** в `json_parsers.dart` (переезжает шагом 7).
Hysteria v1 своего парсера в LxBox не имеет вовсе (схема помечена
`extension: desktop`, §469), а ветка `case 'hysteria'` у Xray-конвертера
строит `Hysteria2Spec`. Снять функцию целиком — работа шага 7.

**`toSingboxForQuic` НЕ снят** (п. «в» задания). Модель узла может получить
отпечаток не только из ссылки: форма вкладки Settings пишет `TlsSpec`
напрямую, и эмиттер обязан остаться последней преградой. Он больше не
единственная преграда — но по-прежнему преграда.

### 11.2 Дефект: вложенный `required` ронял ВЕСЬ узел

Нашёлся сразу, первым же прогоном: hysteria2-ссылка с `obfs=gecko` без
`obfs-password=` перестала давать узел вовсе.

Санитайзер читал `required` одинаково на всех уровнях: нет обязательного поля
— `dropNode`. На КОРНЕ тела это верно (нет `uuid` у vless — ядро запись не
примет). Внутри вложенного объекта единица отказа другая, и реестр пишет это
прямо у `hysteria2.obfs.password`:

> отсутствие пароля снимает блок obfs целиком (**узел живёт** без обфускации)

То же говорит текст самого кода `obfs_password_missing` в `warnings.json`
(«the node connects without obfuscation») и ожидание корпуса
`uri/hysteria2/obfs_no_password_dropped` — тело узла плюс один код. И то же
правило у `tls.reality.public_key`:

> public_key здесь required, поэтому мусорный pbk снимает блок целиком и узел
> деградирует до plain TLS

Исправлено: `required` без поля роняет узел только на корне (`prefix.isEmpty`),
внутри объекта снимается сам объект (флаг `dropObject`, гасится перед каждым
спуском). Четыре вложенных `required` в реестре — `obfs.type`,
`obfs.password`, `reality.public_key`, `brutal.{up,down}_mbps` — и все четыре
описывают деградацию блока, а не отбраковку записи.

Заодно разошлась ФОРМА кода. Общий `field_missing` — про узел, адреса у него
нет, имя поля лежит в `params.field`. Код, объявленный у поля своим `code`, —
про блок, и адресуется полем: корпус ждёт `path: obfs.password`. Теперь так и
приходит, с `params.type` (какую обфускацию сняли) для текста сообщения.

**Почему не замечали.** На пути ссылки obfs собирал рукописный
`normalizeHysteria2Obfs` ДО санитайзера, и тот видел уже чистое тело. На пути
JSON санитайзер по дословной карте (шаг 1) узел ронял — но кейса «obfs без
пароля» в корпусе ТЕЛ нет ни одного, а ожидание URI-половины проверяет другой
путь. Ровно тот класс молчания, ради которого фича и делается.

Ожидание теста `body_sanitizer_test.dart` переписано с обоснованием; корневое
правило (`vless без uuid → drop_node`) не тронуто и зелено.

### 11.3 hysteria2: снятые правила и что осталось

`hysteria2_parser.dart` стал строкой вызова конвейера. Маппер
(`mappers/hysteria2_mapper.dart`) переводит диалект, включая то, чего у
TCP-схем не было: base64-обёртку всего тела ссылки, алиас схемы `hy2://` и
multi-port прямо в authority (`host:443,20000-30000` — строка, которую
`Uri.parse` не читает вовсе).

| Было рукописным | Стало правилом реестра | Код |
|---|---|---|
| `forbiddenTlsBlockWarnings` — рукописный проход по `tls.utls`/`tls.reality` (§469) | `tls.json` → `forbidden_for` + `forbidden_codes`, исполняет САНИТАЙЗЕР | `tls_not_applicable_quic`, по одному на блок |
| `normalizeHysteria2Obfs` — тип вне `salamander|gecko` | `hysteria2.json` → `obfs.type`, enum + `on_invalid: drop` | `obfs_unknown` (был без пути и значения) |
| `normalizeHysteria2Obfs` — obfs без пароля | `hysteria2.json` → `obfs.password`, `required` + собственный `code` | `obfs_password_missing` (был без пути) |
| рукописная пара `field_requires` на размерах пакетов не-gecko | `hysteria2.json` → `obfs.{min,max}_packet_size`, `requires` с `equals: gecko` | `field_requires` |
| `normalizeTlsFingerprint` — мусорный `fp` → `chrome` | блок снимает `forbidden_for` целиком, до нормализации | — (см. 11.6) |
| `InsecureTlsWarning` при `insecure` | `tls.json` → `insecure`, `advisory` (§474) | `tls_insecure` с путём и значением |
| `isValidRealityPublicKey` — гейт REALITY ради `value` кода | `tls.json` → `reality`, `forbidden_for` судит блок целиком | `tls_not_applicable_quic` |

Рукописным остался ПЕРЕВОД написания — работа маппера по определению: алиас
схемы, base64-обёртка, восстановление authority, раскладка плоских `obfs-*` во
вложенный объект, оба написания полосы (`upmbps`/`up_mbps`, §464), форма
диапазона портов (`mport_range_spec`) и эвристика SNI.

**Запросов к лаунчеру у hysteria2 нет:** рукописных СУЖДЕНИЙ о значении не
осталось ни одного.

**§453 dial-полей маппер не отдаёт.** У trojan/vless/ss они уезжают в тело
через `extensionFields`; здесь — нет, и намеренно: TCP keep-alive поверх QUIC
смысла не имеет (транспорт UDP), `Hysteria2Spec` такого поля не знает вовсе, и
прежний парсер его не читал. Заведи мы его — ключи легли бы в тело, а модель
молча их потеряла бы.

### 11.4 Эвристика SNI — аргумент, а не общее поведение

У hysteria2 правило `sni_heuristic_falls_back_to_server` РЕАЛИЗОВАНО (имя без
точки и двоеточия либо `🔒` уступает адресу сервера), а у trojan, vless и
vmess его нет ни на одном входе — включение сдвинуло бы тела и identity живых
узлов. Общая часть получила аргумент `sniHeuristic`, поведение сохранено байт
в байт.

Страж покрытия (`mapper_rules_coverage_test.dart`) научился этой разнице:
ключ расхождения теперь может быть `правило@схема`. Прежний общий ключ
объявлял бы правило нереализованным у ВСЕХ схем, в том числе у той, где оно
работает, — и пропустил бы его пропажу.

### 11.10 tuic: два изменения поведения, оба намеренные

**1. `uuid` не в форме UUID — узел отбраковывается.** Реестр объявляет у поля
`format: uuid` с `on_invalid: drop`, и само поле `required`. Ядро отвечает на
мусорный uuid «invalid uuid» — фаталом на ВЕСЬ конфиг, то есть такой узел
уносил с собой и все остальные, а понять, какой из них виноват, было неоткуда.

Корпус эту границу провёл сам ещё в SPEC 131 W2c: заглушки `u` в его кейсах
заменены настоящими UUID с пометкой «ядро отвергает их фаталом на весь конфиг
… то есть кейс нормировал тело, которое не запускается». **Ни одного
корпусного кейса с мусорным uuid сегодня нет**, и identity всех 13
разбираемых кейсов корпуса сошлась. Затронуты только семь ссылок внутри
`app/test`, все с заглушками (`u`, `aaaa-bbbb`, `uuid-1`); они заменены
настоящими UUID — ровно так, как это сделал корпус, и по той же причине.

Попутно вскрылась асимметрия санитайзера: обязательное поле, СНЯТОЕ как
негодное, он обязательным больше не считал — `required` проверялся только у
ОТСУТСТВУЮЩЕГО ключа. Узел уезжал с пустым `uuid: ""`: ни прежнего поведения,
ни честной отбраковки. Теперь снятое обязательное поле равносильно
отсутствующему, и граница та же — на корне уходит узел, внутри объекта сам
объект.

**2. `disable_sni=1` объявляет себя в теле.** Прежде тело выходило как
`tls: {enabled: true}`: имя сервера снято, а сам факт «SNI выключен» не
выражен ничем. Теперь маппер кладёт ключ `disable_sni` — он описан реестром
(`tls.json`, bool), ядро его понимает, и тот же узел, пришедший
sing-box-объектом, нёс его и раньше (сквозной ключ, `kTlsPassthroughKeys`).
Прежняя форма теряла разницу между «SNI выключен» и «имя просто не задано», и
`toUri()` не мог вернуть `disable_sni=1`. Кейса на это ни в корпусе, ни в
тестах не было ни одного.

Заодно `_tlsFromSingbox` перестал подставлять адрес сервера в `server_name`
при `disable_sni: true`: подставлять нечего, расширение не отправляется.
Явное имя, если автор его написал, сохраняется — это его данные.

### 12.1 anytls: снятые правила и два отличия от vless

TLS-часть у anytls читается по конвенции VLESS — REALITY, дефолт отпечатка
`random`, алиас `fingerprint`, — то есть теми же аргументами общих частей.
Отличий ровно два, и оба выражены в маппере, а не ветками внутри общих
частей.

**`security=none` не выключает TLS.** AnyTLS живёт только поверх TLS
(`body.fields.tls` → `required`, ядро отвечает `C.ErrTLSRequired`), и ключ
снимается ДО чтения блока. Правило реестра `security_none_no_tls` числит
anytls в `applies_to`, но исполнять его нельзя по существу схемы: сними
маппер блок — узел уехал бы без TLS, потеряв заодно `sni`, `alpn` и
`insecure`, которые автор написал рядом. Корпус нормирует обратное
(`security_none_params_kept`), и расхождение названо в `_knownGaps` стража
покрытия ключом `security_none_no_tls@anytls`.

**Эвристика SNI включена** (`sniHeuristic: true`, как у hysteria2) — заметка
11.13 сработала. Цепочка алиасов при этом сужена до `sni` → `peer`: дефолт
общей части (`sni`/`peer`/`host`) добавил бы источник, которого у anytls не
было, — транспорта у схемы не бывает, и `parseVlessTls` читал ровно два
имени.

| Было рукописным | Стало правилом реестра | Код |
|---|---|---|
| `AnyTlsMinIdleInvalidWarning` — `min_idle_session` не неотрицательное целое | `anytls.json` → `min_idle_session`, `min: 0` + `on_invalid: drop` | `anytls_min_idle_invalid` (был без пути и значения) |
| `normalizeTlsFingerprint` — мусорный `fp` → `chrome` | `tls.json` → `utls.fingerprint`, enum + `on_invalid: coerce chrome` | `utls_fp_unknown` |
| `InsecureTlsWarning` при `insecure` | `tls.json` → `insecure`, `advisory` (§474) | `tls_insecure` с путём и значением |
| `isValidRealityPublicKey` — гейт REALITY по §169 | `tls.json` → `reality.public_key`, `format: base64_32` | `reality_pbk_invalid` |
| `realityShortIdWouldDegrade` + `normalizeRealityShortId` | `tls.json` → `reality.short_id`, `format: hex` + `normalize: hex_only` | `reality_short_id_invalid` |
| `_keyShareFromQuery` — enum `hybrid`/`classical` | `tls.json` → `reality.key_share` | `reality_key_share_invalid` |
| `alpnFromQuery` — drop элемента, не похожего на ALPN-id | `tls.json` → `alpn`, `listable_string` | — (значение проходит) |

Рукописным остался ПЕРЕВОД написания: пароль из userinfo целиком (двоеточие
внутри пароля законно), снятие `security`, голое число duration-полей как
секунды, эвристика SNI.

### 12.2 naive, socks, ssh: судить оказалось нечем

У трёх схем рукописных правил значения не было НИ ОДНОГО, и это не упущение
прежних парсеров, а состав схем.

- **naive.** Собственных query-параметров всего два — `extra-headers` и
  `padding`, оба про структуру. TLS-параметров диалект naive не знает вовсе
  (`uri.query` реестра их не перечисляет), поэтому и знаменитый allowlist
  §454/§270 на входе ССЫЛКИ не срабатывает: полям неоткуда взяться. Реестр
  держит его правилом `forbidden_for: ["naive"]` с кодом
  `tls_field_unsupported_naive` на семнадцати полях `tls.json`, и исполняет
  его санитайзер на входе ТЕЛА — там, где такие поля реально приходят (это
  работает с шага 1). Маппер кладёт ровно то, что клал прежний парсер:
  `enabled` + имя сервера из адреса.
- **socks.** `uri.query` пуст; query читается только ради §453-полей.
- **ssh.** Все поля тела — `string` или `listable_string` без enum'ов и
  форматов.

**Схема может нести ТЕЛО, а не только написание.** У `hy2` (шаг 5) имя схемы
было алиасом, и таблица мапперов вела обе записи в одну функцию. Здесь не
так: `naive+quic` отличается от `naive+https` телом (`quic: true` +
`quic_congestion_control: bbr`), а `proxy-https` от `proxy-http` — наличием
блока `tls` вообще. Поэтому у naive две записи с разными функциями, а у http
четыре записи (§268 плюс-формы) с одной: там различие читается из самого
текста схемы. Алиасы, которые не меняют ничего (`socks5`, плюс-формы),
делят маппер.

### 12.3 §466 — приватный ключ ssh в query

Форма хранения не менялась: ключ едет параметром ссылки, потому что хранение
узла это его текст. Многострочный PEM приходит percent-кодированным, и
`Uri.queryParameters` раскодирует его РОВНО ОДИН РАЗ — этого достаточно, и
больше делать нельзя: раскрутка до стабильной точки (как у ALPN) испортила бы
ключ, в котором законно встречается `%`. Проверено побайтно на круге —
`\n` и `+` внутри base64 сохраняются
(`ssh_pipeline_invariants_test.dart`).

### 12.4 Три дефекта, которые вскрыл переезд

Совет шага 3 — «сверить ветку `json_parsers.dart` с `body.fields` реестра ДО
переезда» — сработал трижды. Все три одного класса: **эмиттер поле пишет, а
`parseSingboxEntry` его не читает**, то есть узел, пересохранённый через JSON
или отредактированный во вкладке JSON, терял настройку молча.

- **`quic` у naive.** `emitNaive` пишет `quic: true` +
  `quic_congestion_control: bbr`, ветка не читала вовсе: узел
  `naive+quic://` возвращался к HTTP/2 и соединения не поднимал.
  `quic_congestion_control` обратно в модель не идёт намеренно — поля у
  `NaiveSpec` нет, значение у ядра одно, и эмиттер ставит его сам по `quic`.
- **`host_key_algorithms` у ssh.** `emitSsh` пишет, ветка не читала — список
  алгоритмов host-ключа пропадал.
- **Жёсткий каст `min_idle_session` у anytls ронял ВЕСЬ узел.** Ветка читала
  поле как `entry['min_idle_session'] as num?`, и на любом нечисловом
  значении каст бросал; `parseUri`/`parseSingboxEntry` исключение ловят и
  отдают `null` — узел исчезал целиком и молча. Задеть это могло и тело
  провайдера (`"min_idle_session": "3"` строкой — обычное дело у
  агрегаторов), и ссылку на конвейере, где сырое значение обязано доехать до
  санитайзера СО СВОИМ написанием. Исправлено общим `_asInt`, который в
  файле уже был.

### 12.5 Изменений поведения нет

Ни у одной из пяти схем узел, который раньше жил, не стал отбраковываться, и
наоборот; ни одно поле не перестало уезжать в ядро и не начало. Единственная
правка, которая ШИРЕ прежнего, — исправление дефекта `min_idle_session`
(12.4): узел, который прежде исчезал молча, теперь живёт. Это восстановление
работоспособности, а не смена правила, и корпус его не покрывал ни одним
кейсом.

### 12.6 Запрос к лаунчеру: мёртвое поле `version` у socks

`parseSingboxEntry` в socks-ветке его НЕ читает. Реестр называет это прямо

Это тот же класс, что три дефекта 12.4, но чинить его этим шагом нельзя:

`version: "4"`, чтобы у обеих сторон он был нормирован. До ответа поле
остаётся мёртвым, как и записано в реестре.

### 13.1 masque: снятое правило было последним

`masque_parser.dart` стал строкой вызова конвейера.

| Было рукописным | Стало правилом реестра | Код |
|---|---|---|
| форс `vhttp` вне `h3|h2|auto` в `h3` + `MasqueVhttpInvalidWarning` | `protocols/masque.json` → `body.fields.vhttp`, enum + `on_invalid: coerce h3` | `masque_vhttp_invalid` (был без пути и значения) |

Рукописным остался ПЕРЕВОД написания: приватный ключ в userinfo с фолбэком из
query, `address=` списком в пару `ip`/`ipv6`, `keep_alive` →
`keep_alive_period`, снятые legacy-имена `network=`/`server_name=` (0.8.0,
D-078).

**Три дефолта пишутся ЯВНО** — `vhttp: h3`, `profile: cloudflare`, `mtu: 1280`.
Реестр объявляет их `default`, но `default` по CANON §2.4 в тело не
материализуется, а корпус их присутствия ждёт. У `vhttp` это к тому же не
дефолт ядра: у ядра `auto`, и правило `vhttp_empty_defaults_to_h3` называет
расхождение прямо — «значение входит в identity-хеш живых MASQUE-узлов».
Положись маппер на реестр, identity сдвинулась бы у всех.

**Запросов к лаунчеру у masque нет.**

### 13.2 `forbiddenTlsBlockWarnings` снята ЦЕЛИКОМ

Шаг 5 оставил функцию ради одного вызывающего — ветки `masque` в
`json_parsers.dart` (11.8). Переезд схемы снял и его, по той же причине, что у
hysteria2 и tuic: это не дубль, а лишний ПРОИЗВОДИТЕЛЬ. С шага 1 у JSON-узла
есть проход по дословной карте (`annotateFromRawBody`), и правило
`forbidden_for` санитайзер исполняет по тому же телу, с тем же `value`; дедуп
по `(code, path)` дубль снимал, поэтому видно ничего не было.

Вместе с функцией ушли `tlsBlocksOfBody` и `utlsBlockOf` — вызывающих у них не
осталось. Тестов НА НЕЁ не было ни одного (её проверяли через узлы), поэтому
удалять было нечего; равенство пары uri↔body стережёт тест шага 5.

### 13.3 Дедуп-тест переехал на ИСКУССТВЕННОГО производителя

Заметка 12.9 сработала: кандидатов не осталось. Пример
(`parse_warnings_test.dart`) построен так: узел из sing-box-ТЕЛА конвейером не
разбирается (`isPipelineParsed` на нём ложь), значит `annotateWithRegistry` по
нему идёт и даёт `anytls_min_idle_invalid` на `min_idle_session`; рукописный
класс с той же парой на узел ставится руками. Смысл сохранён целиком: два
производителя, одна пара `(code, path)`, одна запись, и путь у неё есть.
Контроль без рукописного класса стоит рядом — иначе тест зеленел бы и на
молчащем реестре.

### 13.4 Долг §473 закрыт: кламп MTU исполняет санитайзер

Сняты РАЗОМ `awgClampMtu` (`uri_utils.dart`), `awgMtuByRegistry` и
`awgMtuWarnings` (`registry.dart`, `parse_warnings.dart`) со всеми вызовами.
Потолок и дефолт исполняет `body_sanitizer.dart` — по телу, на всех входах,
правилами `max_when`/`default_when`.

**Граница W2a проверена и она не мешает.** Санитайзер разбора тело НЕ
переписывает только в проходах-аннотаторах (`annotateWithRegistry`,
`annotateFromRawBody` — там очищенная карта выбрасывается). В КОНВЕЙЕРЕ он
переписывает: `parseUriViaPipeline` кормит `parseSingboxEntry` именно
очищенной картой, и `_applyMaxWhen` возвращает потолок как значение поля. Для
`default_when` то же самое. Исключение `except_sources: ["singbox"]` конвейера
не касается: `sanitize()` зовётся без `source`, то есть с консервативным
`BodySource.other`, и вход ссылки/INI получает ЗАМЕНУ, как и требует корпус.

**Два случая, до которых санитайзер не достаёт**, остались за конвейером
(`mappers/uri_pipeline.dart`), и оба опасны молчанием — AWG-узел без потолка
поднимает туннель, по которому не идут данные:

1. **Вход ПРОСИЛ AmneziaWG, но не донёс ни одного годного AWG-поля.** Условие
   `when.any_set` судит наличие ключа В ТЕЛЕ, а `jc=abc` вместе с одиноким
   `jmin` не оставляет там ничего (кейсы корпуса `awg_bad_numeric_skipped`,
   `awg_jc_invalid_dropped` — оба ждут `mtu: 1280`). Род узла знает только
   маппер, и он сообщает его отдельным полем `UriMapping.kindIsAwg` — §463, то
   же основание, что у прежнего рукописного `isAwg`.
   Отдать санитайзеру СЫРЫЕ значения вместо разобранных нельзя: реестр
   объявляет у `jc` свой `on_invalid.code`, и узел получил бы код там, где Go
   молчит (`applyAWGFields` роняет битые числа молча), а `h1`–`h4` дали бы
   `type_invalid` вместо `awg_header_invalid`. Корпус нормирует тишину.
2. **Реестр не загружен** — санитайзер не работает вовсе. Здесь обязано
   сработать запасное число `kAwgMtuFallback`, и оно СОХРАНЕНО: решение
   §473 («молчание тут не безопасно, в отличие от кодов») в силе. Закрыто
   тремя тестами в `awg_test.dart` — файле, который реестр не грузит по
   построению.

Число 1280 в Dart не появилось ни там, ни там: и потолок, и имя кода читаются
из реестра (`awgMtuCeilingByRegistry`, `awgMtuClampCodeByRegistry`).

### 13.5 wireguard/AWG: что осталось рукописным СУЖДЕНИЕМ — четыре запроса

Единственная схема, у которой после переезда рукописные суждения остались. Все
четыре — про то, чего реестр СЕГОДНЯ не описывает, а не про несогласие.

1. **`h1`–`h4`: годность значения и нормализация перевёрнутой пары.** Реестр
   числит их типом `awg_range` без ограничений — «ЧИСЛО либо строка min-max».
   Отбраковку мусора (`h2=a-b`, `h3=-5`, `h4=1-2-3`) и своп границ
   (`300-200` → `200-300`, D-031 — без него одна нода даёт два хеша) делает
   `Awg.fromQuery`. **Просьба:** описать `awg_range` формой значения, чтобы
   негодное снимал санитайзер, и назвать, нормализуется ли порядок границ.
   Отдельно: код `awg_header_invalid` ставится ПОФАКТОРНО, по одному на битый
   заголовок (§463) — человек читает четыре имени, а конверт корпуса несёт
   одну запись без пути (`awg_ranged_h_broken_dropped`). Эту разницу надо
   сохранить при любом ответе.
2. **Битые `jc`/`jmin`/`jmax`/`s1`–`s4` снимаются МОЛЧА** — эталон Go
   `applyAWGFields`. Реестр объявляет у них `on_invalid.code`
   (`awg_header_invalid` / `awg3_field_invalid`), и отдай маппер сырую строку
   санитайзеру, узел получил бы код там, где вторая сторона молчит, а корпус
   ждёт тишины (`awg_jc_invalid_dropped` — там ОДИН код, и он про `jmin`,
   снятый правилом `requires`). **Просьба:** решить, кто прав — снять
   `on_invalid.code` у этих полей либо дополнить ожидания корпуса кодами.
3. **Битый `presharedkey` ОТБРАКОВЫВАЕТ УЗЕЛ.** Это требование КОРПУСА:
   `uri/wireguard/junk_presharedkey_rejected` ждёт `dropped: parse_error`, а не
   узел с одним кодом. Реестр же объявляет у `peers[].pre_shared_key`
   `on_invalid: {action: drop}` — снял бы ПОЛЕ и оставил узел жить без общего
   ключа, а такой туннель к серверу с psk не поднимется вовсе. **Просьба:**
   привести записи в соответствие — либо `drop_node` в реестре, либо кейс
   корпуса переписать на узел с кодом.
4. **Узел выбрасывается при битом ключе защиты заголовка или паддинге короче
   12 байт** (`awg3NodeError`, §421): ядро отвергло бы конфиг ЦЕЛИКОМ. Реестр
   описывает `header_protection_key` форматом `base64_32` с `action: drop` —
   то есть снял бы поле и оставил узел жить без защиты заголовка, а это тихо
   сломанный туннель. Правила «паддинг ≥ 12 при заданном ключе» реестр не
   знает вовсе. **Просьба:** форма отказа на УЗЕЛ у этого поля и правило связи
   с `s1`–`s4`.

Сверх того рукописной осталась **нормализация ключей WireGuard**
(`normalizeWGKey`: любая из четырёх форм base64 → std-base64 с padding). Это
не суждение, а перевод написания, и снять его нельзя: корпус нормирует именно
её результат (`uri_psk_keepalive` — ключ `…ccC=` в теле становится `…ccA=`, те
же 32 байта в канонической записи). Реестр про написание молчит:
`format: base64_32` только ПРОВЕРЯЕТ, и проверяет строгим декодером, для
которого `…ccC=` вообще не base64. Без нормализации одна нода давала бы два
identity-хеша (D-030).

### 13.6 INI — ещё один маппер; Amnezia-контейнер в шаг НЕ входит

**INI переехал** (`mapWireguardIni`, точка входа `parseIniViaPipeline`). Форма
интерфейса это позволила с шага 4: `UriMapper` принимает ИСХОДНЫЙ ТЕКСТ, и
маппер INI отличается от маппера ссылки ровно разбором входа — выход у обоих
один, карта sing-box. Маршрутизация тоже осталась снаружи: INI схемы не несёт,
и формат опознаётся раньше, на входе приложения (`parse_all.dart`,
`body_decoder.dart`).

Синтетического `wg://` внутри БОЛЬШЕ НЕТ. Он был промежуточной формой (§3.3,
затем §456) и стоил двух лишних превращений текста — сборки query с
percent-кодированием и обратного разбора её же. Общее ядро обоих входов —
`_mapWireguardParams`: плоская карта «имя параметра → значение» плюс адрес
пира. Имена параметров у INI те же, что в query ссылки, поэтому AWG-поля
читает тот же `Awg.fromQuery`.

**Поведение не менялось ни в чём.** `rawSource` — текст INI байт в байт
(§456); имя по убыванию силы — комментарий под `[Peer]` без `=`, затем
`nameHint`, затем `WireGuard`; `DNS` из `[Interface]` по-прежнему не уезжает в
тело (у sing-box endpoint такого поля нет); голый IPv6 в `Endpoint` без скобок
по-прежнему берётся хостом целиком (§219).

**Amnezia-контейнер (`vpn://`, код `amnezia_container_choice`) в этот шаг НЕ
входит, и отдельного переезда ему не нужно.** Он не третий вход, а
РАСПАКОВЩИК: `amnezia_link.dart` декодирует профиль (base64 → qCompress →
JSON), достаёт из `containers[]` готовые INI-тексты и отдаёт каждый в
`parseWireguardIni`. Своих правил значений у него нет ни одного — есть выбор
контейнера (`defaultContainer` предпочтён), подстановка `$PRIMARY_DNS` и
перенос `last_config.mtu` в текст INI, и всё это работа НАД ТЕКСТОМ, до
всякого разбора. Вместе с INI он поехал конвейером сам; закрыто тестом в
`wireguard_pipeline_invariants_test.dart`.

### 13.7 Дефект, который вскрыл переезд: порядок AWG-ключей в теле

`Awg.fromQuery` вставлял в набор сначала AWG 3.x, потом числовые AWG2;
`Awg.fromJson` — наоборот. Порядок вставки становится порядком ключей в теле
(`writeInto` это `addAll`), а тело сравнивается БАЙТ В БАЙТ golden-эталонами.
Пока ссылка шла своим парсером, обе воронки жили порознь и расхождение было не
видно; на конвейере ссылка идёт через `parseSingboxEntry`, то есть через
`fromJson`, и эталон `avd_v0.config.json` сдвинулся бы на ровном месте —
девять ключей переехали бы вниз без единого изменения значения.

Исправлено в `fromJson`: порядок тот же, что у `fromQuery`. Корпус нормирует
именно его (`awg3_full_params`, `amnezia_vpn_awg3`, оба `awg_conf_base64`).
Golden НЕ перегенерирован. Identity от порядка не зависит
(`legacyNodeIdentityHash` сортирует ключи), но эталон — зависит.

## 14. Что вышло: шаг 8 (19.09.2026, Xray-JSON)

Последний вход на конвейере. Xray-конвертер стал маппером «карта Xray → карта
sing-box», дальше общий путь: санитайзер по реестру → `parseSingboxEntry` →
`NodeSpec`. Рукописных правил значения на этом входе не осталось ни одного.

### 14.1 Единственный вход, у которого исходный диалект — ОБЪЕКТ

Шаги 2–7 переводили текст: ссылку или INI. У Xray вход — разобранный JSON, и
разница не косметическая. Маппер принимает `Map`, а не `String`, поэтому
`typedef UriMapper` ему не подходит: у него своя пара
(`mapXrayOutbound` → `XrayMapping`) и своя точка входа в конвейер
(`parseXrayViaPipeline`), а ядро конвейера общее — то же `_runPipeline`.

Отличий от `parseIniViaPipeline` три, и все они про устройство входа:

1. **Маппер отрабатывает СНАРУЖИ.** Разбор элемента подписки — порядок узлов
   §321, дедуп §404, цепочки `dialerProxy`, имена §310/§322 — принадлежит
   `parseXrayElement`, и он же зовёт маппер. Конвейер получает готовую карту.
2. **`label` считает вызывающий**: имя Xray-узла приходит от ЭЛЕМЕНТА
   (`remarks` плюс правила §322), а не из фрагмента ссылки.
3. **Вердикт `drop_node` уезжает НАРУЖУ** (`XrayDropVerdict`): `null` от
   конвейера сам по себе не отличает «узел отбракован правилом» от «тела
   нет», а `dropped[]` принадлежит вызывающему.

`rawSource` остался pretty-print ИСХОДНОГО объекта Xray байт в байт (§454).
Карта sing-box — рабочая форма конвейера, а не то, что прислал провайдер; по
отсутствию в `rawSource` ключа `type` проход шага 1 по-прежнему опознаёт, что
это не его карта (7.2), и на Xray-узел не идёт.

### 14.2 Снятые рукописные правила (шесть) и коды из реестра

| Было рукописным | Стало правилом реестра | Код |
|---|---|---|
| `normalizeTlsFingerprint` — мусорный `fingerprint` → `chrome` + класс | `tls.json` → `utls.fingerprint`, enum + `on_invalid: coerce chrome` | `utls_fp_unknown` (был `UnknownFingerprintWarning` без адреса и значения) |
| `RealityFingerprintWarning` — отпечаток без гибридного key share | `tls.json` → `utls.fingerprint`, `advisory` с `except` | `reality_fp_not_chrome` (тот же код, теперь с путём и значением) |
| `normalizeVmessSecurity` — значение вне enum ядра | `protocols/vmess.json` → `security`, enum + `on_invalid: coerce auto` | `vmess_security_unknown` (подмена шла МОЛЧА, в лог) |
| `isValidRealityPublicKey` — гейт REALITY по §169 | `tls.json` → `reality.public_key`, `format: base64_32` | `reality_pbk_invalid` (REALITY деградировал до plain TLS молча) |
| `normalizeRealityShortId` | `tls.json` → `reality.short_id`, `format: hex`, `len_parity: even` | `reality_short_id_invalid` (кода не было вовсе) |
| `VisionWithTransportWarning` — `flow` при живом транспорте | `vless.json` → `flow.conflicts` (§474, декларант) | `vision_with_transport` (тот же код, теперь с путём) |

Сверх них Xray-узел впервые получил коды, которых на этом входе не было НИ
ОДНОГО: `flow_deprecated`, `xhttp_param_reset`, `type_invalid` на битом пути
транспорта, `ss_method_legacy`, `tls_insecure`. Раньше их знал только гард
сборки, и в шторке Warnings у Xray-узла было пусто (§470).

**Рукописным осталось то, что судить нечем, — ПЕРЕВОД написания:** раскладка
`flow=xtls-rprx-vision-udp443` на два поля, имена транспортов Xray
(`h2` → `http`, `splithttp` → `xhttp`, `headerType=http` поверх tcp), early
data хвостом пути, псевдонимы uTLS, секунды `sockopt` → duration. Это по
определению работа маппера, и реестр описывает её секцией `mapper`.

Плюс ДВА правила, которые маппер исполняет сам, хотя они про значения, — и оба
названы в коде:

- **`quic_has_no_utls_or_reality`** (`hysteria.json` mapper): у QUIC нет
  TLS-рукопожатия, и блоков `utls`/`reality` в теле не бывает. Снимает их
  маппер, а не санитайзер: прежняя ветка отпечаток читала, но `Hysteria2Spec`
  его не эмитил — то есть в теле его не было никогда. Отдай маппер блок судье,
  узел получил бы `tls_not_applicable_quic` там, где раньше стояла тишина.
- **обязательный ключ `security` у vmess**: поле `required` с дефолтом `auto`,
  а `default` реестра тело не наполняет (материализуется только
  `default_when`, CANON §2.4). Опущенный ключ снял бы узел кодом
  `field_missing` — ровно это и вышло при первом заходе шага. Написание общее
  с маппером ссылки (`_securitySpelling`).

### 14.3 Вход — `xray`, а не `singbox`

Санитайзер конвейера получает `BodySource.other` на ВСЕХ своих входах, включая
Xray. Исключение `except_sources: ["singbox"]` у потолка `mtu` (§473)
относится к телу, написанному в форме ЯДРА самим человеком или подпиской, а
карту Xray-узла собрал наш маппер — основание там по владению, а не по
технике. Словарь `sources` реестра различает входы тоньше
(`uri`/`singbox`/`xray`/`wgconf`/`amnezia`), но правило сегодня одно и делит
ровно надвое; перечисление `BodySource` расширять под несуществующее второе
правило не стали — та же граница, что записана в его doc-комментарии.

### 14.4 Три дефекта, которые вскрыл переезд

- **Битый percent-путь транспорта уезжал в ядро.** `/bad%zz` в `wsSettings`
  оставался в теле Xray-узла, а ядро на нём роняет ВЕСЬ config.json («ws:
  parse path: invalid URL escape»), то есть один узел подписки уносил с собой
  весь VPN. На входе ссылки правило работает с шага 2 и нормировано корпусом
  (`uri/trojan/ws_path_broken_percent_kept`: поле снято, код `type_invalid`,
  узел жив), на Xray-входе судьи не было вовсе. Единственный случай, где тело
  и identity Xray-узла СДВИНУЛИСЬ, — и сдвинулись в сторону корпуса.
- **`streamSettings: "none"` едва не ожил.** Прежние ветки читали поле жёстким
  кастом (`as Map?`), и мусорный ТИП бросал — вызывающий пропускал такой
  outbound, называя протокол в `UnsupportedProtocolWarning`. Первый заход
  шага прочёл его мягко (`is Map`), и из битой записи получился РАБОЧИЙ узел
  без транспорта и TLS, которого провайдер не присылал. Каст вернули жёстким,
  на это есть тест.
- **Отрицательный `sockopt` терял `disable_tcp_keep_alive`.** Любое
  отрицательное значение у Xray значит `SO_KEEPALIVE=0`
  (`sockopt_linux.go:143`), и `tcpKeepAliveFromXraySockopt` переводил его в
  `disabled`. Первый заход шага отбрасывал такие значения как «не задано»;
  поймал `tcp_keep_alive_test.dart`.

### 14.5 Что НЕ перенесено намеренно — и запрос к лаунчеру

Два поля Xray-диалекта прежняя ветка не читала, и шаг 8 их читать не начал:
перенос сдвинул бы ТЕЛО и identity живых узлов, а корпус этого входа таких
кейсов не несёт. Оба — разрыв ВХОДОВ, а не решение.

1. **`realitySettings.keyShare`.** На входе sing-box поле читается (§457,
   `_realityKeyShare`), на Xray — никогда не читалось. Узел с
   `keyShare: "hybrid"` уезжает без него, а гибридный key share решает,
   примет ли REALITY-сервер Xray ≥ v26.9.8 рукопожатие (SPEC 083): без него
   сервер молча проксирует соединение на камуфляжный сайт. **Просьба:** кейс
   корпуса на `body/xray` с `keyShare`, чтобы перенос был нормирован, а не
   попутной правкой с необъявленным сдвигом identity.
2. **`tlsSettings.alpn`.** Та же история: sing-box-вход список читает, Xray —
   нет. У Xray-подписок ALPN встречается часто. **Просьба:** кейс корпуса и
   ответ, что делать со сдвигом identity у живых узлов.

Оба вопроса одного рода с §473: правило есть у одного входа и нет у другого, и
решать, выравнивать ли их, — не дело шага переезда.

| битый `pbk` | REALITY молча деградировал | `reality_pbk_invalid`, тело то же |
| нечётный `short_id` | кода не было | `reality_short_id_invalid` |
| `security` vmess вне enum | подмена молча, в лог | `vmess_security_unknown` |
| `mode` XHTTP вне enum | `XhttpParamResetWarning` без адреса | `xhttp_param_reset` с `path` и `value` |
| битый путь транспорта | кода не было, путь ехал в ядро | `type_invalid`, поле снято (14.4) |
| негодный `encryption` | код от второго прохода, узел ЖИЛ | `vless_encryption_invalid` + узел отбракован при разборе (§477) |
| `fingerprint` у hysteria2 | `UnknownFingerprintWarning` | кода нет: блока `utls` у QUIC не бывает (14.2) |

### 14.8 Изменение поведения — одно

**Негодная форма `vless.encryption` на Xray-входе ТЕПЕРЬ ОТБРАКОВЫВАЕТ УЗЕЛ
при разборе** (`explicitDropNode`, причина в `dropped[]` кодом
`vless_encryption_invalid` и тегом записи). Раньше такой узел код получал —
его ставил второй проход, по `emit()`, — и в ядро не уезжал (снимал гард
сборки), но в списке стоял рабочим. Разница в МОМЕНТЕ: узел снимается при
разборе, а не перед стартом. Ровно это заметка шага 8 и обещала: правило уже
было в реестре, но исполнял его проход по дословной карте, которой у
Xray-узла не существовало.

Отбраковка не молчалива: если в элементе выжил сосед, причина висит на нём
(§404 P3), и `dropped[]` тогда пуст — иначе человек прочёл бы одно сообщение
дважды.

### 14.9 Список для шага 9 (чистка)

**Функции без вызывающих в `lib/`** — к прежнему списку (12.10) прибавилась
ОДНА. Проверено `grep`'ом по всему `lib/`, а не по памяти заметки 13.12: та
обещала, что шаг 8 освободит `normalizeTlsFingerprint` и
`normalizeVmessSecurity`, и ошиблась — у обеих остался вызывающий, о котором
заметка не знала.

- **`tcpKeepAliveFromXraySockopt`** — единственным вызывающим был
  Xray-конвертер; перевод секунд теперь делает маппер. Осиротела полностью.
- Ранее осиротели: **`parseVlessTls`**, **`parseTrojanTls`**, **`parseVmessTls`**,
  **`alpnFromQuery`** (12.10, 10.7).

**НЕ осиротели, вопреки заметке 13.12** — их зовёт ветка sing-box-входа
(`parseSingboxEntry`, `_tlsFromSingbox`), которая на конвейер НЕ переезжала и
в план шагов не входила:

- **`normalizeTlsFingerprint`** — `json_parsers.dart:1313`.
- **`normalizeVmessSecurity`** — `json_parsers.dart:787`.
- **`isValidRealityPublicKey`** — `json_parsers.dart:1355`, плюс
  `transport.dart` и post-step сборки `heal_invalid_reality.dart`.

Снять их можно будет только вместе с переездом sing-box-входа на конвейер, а
это отдельное решение: у того входа тело УЖЕ в форме ядра, и проход по
дословной карте (шаг 1) его судит — второй судья там не нужен, нужен разбор
того же тела в модель.

**Рукописные классы предупреждений** — проверено `grep`'ом по `lib/`; без
производителя остался РОВНО ОДИН (**шаг 9 это опроверг: их девять, см. 15.2 и
15.3 — заметка считала только новые сироты шага 8, а не все**):

- **`VisionWithTransportWarning`** — ставил только Xray-путь, теперь код
  приходит из реестра (`vision_with_transport`). Производителей нет.
- **`UnknownFingerprintWarning`** и **`RealityFingerprintWarning`** — их
  по-прежнему ставит `normalizeTlsFingerprint`, а её зовёт sing-box-ветка
  (см. выше). Снимутся вместе с ней.
- **`XhttpParamResetWarning`** — производитель не в разборе, а в ЭМИССИИ
  (`transport_spec.dart`), и переезд его не касается вовсе.

Снимать их надо вместе с записями в `handwrittenWarningPath`
(`warning_codes.dart`) и в таблицах дедупа: класс без производителя молча
перестаёт закрывать свой `(code, path)`, и это не видно, пока не разойдётся
с корпусом.

**Рукописный остаток, который НЕ снимается** (он и не про значения): перевод
написания в мапперах — по определению их работа; `normalizeWGKey` (13.5);
четыре запроса по AWG (13.5) и два по Xray (14.5) — они ждут ответа лаунчера,
а не чистки.

## 15. Что вышло: шаг 9 (19.09.2026, чистка)

Шаг без нового поведения: снят код, у которого после шагов 1–8 не осталось
ни одного вызывающего в `lib/`. Каждый кандидат проверен `grep`'ом по
`lib/` и `test/`, а не по списку 14.9 — и список оказался неполон (15.2).

### 15.8 Дальше — фича 480

Схемные мапперы (`mappers/*_mapper.dart`) — **временные**. Их правила сегодня
исполняет код, а норма лежит в секции `mapper` реестра; фича 480 заменит их

правка формы маппера была бы выброшена вместе с ним.
