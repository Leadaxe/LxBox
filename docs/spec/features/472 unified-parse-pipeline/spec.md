## 1. Зачем

Сегодня узел попадает в модель двумя независимыми путями:

- тринадцать URI-парсеров (`services/parser/uri_parsers/*`, `transport.dart`)
  строят `NodeSpec` напрямую из ссылки, и каждый несёт свои правила значений;
- вход JSON (`parseSingboxEntry`, Xray-конвертер в `json_parsers.dart`) строит
  ту же модель из карты — со своей копией тех же правил.

Санитайзер реестра (фича 460) приставлен сбоку: при разборе он видит
`emit()` уже построенной модели, а модель сама фильтр. Что из этого выходит,
показал один день 18.09.2026: нормализация gRPC жила в трёх местах (§468),
obfs-коды hysteria2 терялись на JSON-пути (§469), `value` у гейта запрета не
ставился вовсе (§469), а коды мусора у JSON-узла (`flow_deprecated`,
`unknown_key`, `tls_field_unsupported_naive`, `reality_short_id_invalid`) на
узел не попадают — их знает только гард сборки, и в шторке Warnings их нет
(§470). Раннер корпуса вынужден склеивать два пути сам.

У лаунчера путь один: вход → карта sing-box → санитайзер по реестру → тело.
Правило записано один раз, в реестре.

## 2. Решение

Конвейер на входе — как у лаунчера. Типизированная модель остаётся.

```
ссылка ──маппер──┐
                 ├─► сырая карта ─► санитайзер по реестру ─► чистая карта ─► parseSingboxEntry ─► NodeSpec
JSON / Xray ─────┘                     │
                                       └─► warnings (code, path, value) ─► NodeSpec.warnings
```

- **Маппер** переводит диалект ссылки в карту sing-box и **не судит
  значения**: алиасы параметров, userinfo, порт, транспорт. Правила перевода
  описаны секцией `mapper` реестра; исполняем их кодом, реестр — норма и
  предмет сверки (тест: каждое правило `mapper` покрыто).
- **Санитайзер** — единственный судья значений. Рукописные правила из
  парсеров уходят по мере переезда протокола (спека 460, «Осталось на W2»,
  п. 3). Гейты `min_core`/`platform` при разборе выключены, как в W2a.
- **`parseSingboxEntry`** — единственный путь «карта → модель». Он уже
  написан; по мере переезда из него уходят правила, которые исполнил
  санитайзер, остаётся приведение к типам модели.
- **`NodeSpec` не уходит.** На нём стоят формы вкладки Settings, `toUri()`,
  identity, цепочки, WARP, detour. Модель — типизированное представление
  чистой карты, а не место, где принимаются решения о значениях.
- **`rawSource` не меняется**: у ссылки — ссылка, у JSON — JSON (§454–§456).
  Узел `origin.kind: json` по-прежнему уходит в ядро дословно (§455);
  конвейер даёт ему предупреждения, тело не трогает.

Чего НЕ делаем: не заменяем модель картой; не генерируем маппер из реестра
(возможно позже, отдельным решением); не меняем формат хранения; экраны не
трогаем — шторка W2b и показ уровней §471 получают больше кодов сами.

## 3. Инварианты каждого шага

1. Корпус лаунчера зелёный целиком (URI и тела, `warnings[]` сверяются),
   новых per-app override не заводить.
2. Golden-конфиги (`rich_v0`, `avd_v0` и прочие) байт в байт, без
   перегенерации. Если шаг требует перегенерации — это отдельное решение
   владельца с диффом в отчёте.
3. `parseUri(spec.toUri()) ≈ spec` для переезжающего протокола.
4. Identity узла не меняется (иначе у пользователей слетят выбор узла,
   отключения и цепочки): тест на identity-хеш по фикстурам протокола до и
   после.
5. Перф: разбор 2000 узлов — не хуже ×1,5 к текущему (замер W2a: 42 мс
   разбор + 95 мс аннотация).
6. Один шаг — один протокол (или один слой) — один коммит, перед каждым
   полный зелёный прогон. Между шагами приложение рабочее.

## 7. Что вышло: шаг 1 (18.09.2026, `e00b09b9`)

JSON-половина: санитайзер реестра идёт по ДОСЛОВНОЙ карте узла, его коды
встают на `NodeSpec.warnings`, раннер тел читает один источник.

### 7.1 Что изменилось в конвейере

У JSON-входа проходов санитайзера стало ДВА, и порядок между ними значим
(`parse_all.dart`):

1. `annotateAllFromRawBody` (новый, `parse_warnings.dart`) — по дословной
   карте провайдера. Её узел уже носит: это `rawSource` (§454–§456), объект
   outbound'а как он пришёл. В ней ещё лежит то, что типизированный парсер
   снимает по дороге в модель: ключ вне схемы, `flow` из чёрного списка,
   TLS-поле, запрещённое схеме, значение не того типа.
2. `annotateAllWithRegistry` (был, §460 W2a) — по `emit()` модели. Им
   по-прежнему судятся URI/INI-узлы, у которых дословной карты нет, и им же
   ловятся значения, которые поставил САМ разбор (нормализация, дефолты
   `all_or_nothing`).

Дословный идёт первым: при совпадении пары `(code, path)` остаётся пришедшая
раньше, а её `value` называет то, что лежало в теле, а не то, во что разбор это
превратил.

**Границы шага соблюдены.** Тело узла не меняется — очищенную карту разбор
выбрасывает, чистит по-прежнему гард сборки (`builder/registry_gate.dart`
не тронут), `rawSource` остаётся дословным. Гейты `min_core`/`platform` при
разборе выключены на обоих проходах. `emit()` не менялся.

**Дедуп стал точнее.** Раньше рукописный класс закрывал свой код ЦЕЛИКОМ. Это
годилось, пока коды приходили по одному, но санитайзер по дословной карте шлёт
`tls_field_unsupported_naive` сразу на шесть путей одного узла, и грубый дедуп
съел бы весь набор из-за одного рукописного `InsecureTlsWarning`. Теперь дедуп
по паре `(code, path)`: класс, который путь несёт, закрывает только свой путь;
класс без пути — по-прежнему код целиком (приписать ему адрес было бы
выдумкой, а `path` нормативен). Остаётся одна запись, и предпочтение у той,
что несёт путь. Таблица путей рукописных классов переехала из раннера
(`corpus_warnings.dart`, `_legacyWarningPath`) в lib
(`warning_codes.dart`, `handwrittenWarningPath`) — тем же порядком, каким туда
переехала `kWarningCodes`, и по той же причине: второй потребитель.

### 7.2 Xray-JSON — остаётся на шаг 8

У Xray-узла `rawSource` — pretty-print объекта **Xray**
(`json_parsers.dart`, `_prettyJson(o)`), а санитайзер судит карту **sing-box**.
Общих ключей у них нет даже для типа записи: `protocol` против `type`,
`streamSettings` против `transport`, `settings.vnext[].users[]` против `uuid`.
Дословной sing-box-карты у Xray-узла не существует, пока её не построит маппер
«Xray-карта → sing-box-карта» — это шаг 8. Судить дословную Xray-карту
sing-box-схемой значило бы выдать `unknown_key` на каждый законный ключ Xray.

Признак, по которому проход опознаёт свой вход, — JSON-объект с полем `type`:
ссылка и INI не начинаются с `{`, Xray поля `type` не несёт.

### 7.3 Раннер тел

`_allWarningsOf` и `_rawBodyOf` из `body_contract_test.dart` удалены, сверка
читает `matched.first.warnings`. Ожидания корпуса не менялись ни на кейс:
коды, пути, значения и порядок сошлись с контрактом теми же, какими их давало
объединение двух путей. Список `_pendingWarningNodes` остался пустым.

Кодов на узле в кейсах §470 (было → стало): `vless_junk_pair` 0 → 3,
`manual_object_junk` 0 → 2, `outbound_array_tls_fields` 1 → 8 (узел
`naive-junk-tls` 0 → 6, `vless-reality-key-share-junk` 0 → 1, у
`trojan-full-tls` `field_conflict` как был), пары QUIC (`hysteria2`, `tuic`)
без изменений — их коды ставил §469 на пути разбора.

## 8. Что вышло: шаг 2 (18.09.2026, `ac68e040`)

Каркас маппера и конвейер целиком; пилот — trojan. Остальные двенадцать схем
идут прежним путём, `parseUri` маршрутизирует по схеме
(`kPipelineSchemes`).

### 8.2 Решение по второму проходу

Проход по `emit()` (`annotateAllWithRegistry`) **не снят**, а пропускается
адресно для узлов конвейера (`isPipelineParsed`).

Снять целиком нельзя: им судятся URI/INI-узлы двенадцати непереехавших схем и
значения, которые ставит САМ разбор. Оставить на переехавших — тоже: дедуп по
`(code, path)` дубли бы снял, но дело не в дублях, а в `value`. Санитайзер
конвейера видит сырое значение ссылки (`fp=HelloChrome_120`), проход по
`emit()` — уже канонизированное (`chrome`); выигрывает пришедший первым, то
есть ответ решался бы порядком вызовов, а не правилом. С отметкой источник
кодов у такого узла ровно один, и `value` называет написанное автором.

Отметка — `Expando`, не поле модели и не запись в `warnings`: `NodeSpec` это
хранимая форма узла, служебный флаг в ней уехал бы в бэкап (§221) и в
identity.

### 8.3 Снятые рукописные правила (пять) и коды из реестра

Из TROJAN-пути; `transport.dart` не тронут — по нему продолжают ходить
остальные схемы (и `parseTrojanTls` всё ещё зовёт `http_parser.dart`).

| Было рукописным | Стало правилом реестра | Код |
|---|---|---|
| `_guardUrlPath` — битый percent-путь снимался вручную | `transports.json` → `path`, `format: url_path` | `type_invalid` с `path` и значением |
| `normalizeTlsFingerprint` — мусорный `fp` → `chrome` + класс | `tls.json` → `utls.fingerprint`: enum + `on_invalid: coerce chrome` | `utls_fp_unknown` (был `UnknownFingerprintWarning` без адреса) |
| `InsecureTlsWarning` при `insecure` | `tls.json` → `insecure` | код реестра с путём `tls.insecure` |
| `_normalizeAlpn` — drop элемента, не похожего на ALPN-id | `tls.json` → `alpn`, `listable_string` | — (значение проходит, как и раньше) |
| `TlsSpec.disabled` → `tls:{enabled:false}` в эмиссии | маппер блока не кладёт вовсе | — (правило `security_none_no_tls`, SPEC 045) |

Рукописным осталось то, что судить нечем, — ПЕРЕВОД написания: алиасы
параметров (`sni`/`peer`/`host`, семейство `insecure`), псевдонимы uTLS
(`hellofirefox_auto` → `firefox`), `?ed=N` хвостом пути, раскрутка
многократного percent-кодирования ALPN и пути. Это по определению работа
маппера, и реестр описывает её секцией `mapper`, а не правилами значений.
Раскрутка ALPN переехала В МАППЕР из `_normalizeAlpn` (реестр зовёт
`tls.alpn` listable без нормализации — «пишется в той форме, в какой
пришло»), а суждение «элемент не похож на ALPN-id» снято: его там не было и у
Go.

### 8.4 Покрытие секции `mapper`

`test/parser/mapper_rules_coverage_test.dart` — страж: для каждой переехавшей
схемы каждое mapper-правило реестра обязано быть либо покрыто тестом в этом
же файле, либо названо в `_knownGaps` с причиной. Правил, относящихся к
trojan, семь; шесть покрыты, одно в расхождениях:

- `sni_heuristic_falls_back_to_server` — `sni` без `.` и `:` должен уступать
  адресу сервера. **В LxBox не реализовано ни на одном входе trojan** — ни
  старым парсером, ни конвейером (у hysteria2 и anytls та же эвристика есть).
  Включение изменило бы тела и identity живых узлов, поэтому это отдельное
  решение владельца, а не попутная правка шага 2.
