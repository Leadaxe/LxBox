## 1. Зачем

Провайдеры кладут в подписку **пул с автовыбором**. Liberty:

```jsonc
{
  "remarks": "🇪🇺 🚀Авто | Лучший сервер ⚡⚡",
  "outbounds": [ /* 15 vless, теги proxy-<ip>-direct */ ],
  "routing": {
    "rules": [ /* ... */,
      { "network": "tcp,udp", "balancerTag": "Auto_Balancer" } ],
    "balancers": [{
      "tag": "Auto_Balancer",
      "selector": ["proxy"],
      "strategy": { "type": "leastLoad", "settings": {
        "maxRTT": "1500ms", "expected": 7,
        "baselines": ["200ms","500ms"], "tolerance": 0,
        "costs": [{ "regexp": true, "match": "bypass", "value": 3.0 }] } },
      "fallbackTag": "proxy-45-196-31-125-direct"
    }]
  },
  "burstObservatory": {
    "pingConfig": { "destination": "http://www.gstatic.com/generate_204",
                    "interval": "2m", "timeout": "3s", "sampling": 3 },
    "subjectSelector": ["proxy"]
  }
}
```

Три секции связаны **исключительно префиксом тега `proxy`**: обсерватория
меряет, балансировщик выбирает, правило применяет. Списка членов нигде нет —
членство выводится из имени.

Сейчас мы читаем только `outbounds`. Пул приезжает 15 отдельными узлами,
логика выбора теряется. Пользователь видит 15 строк вместо одной «Авто».

**Задача:** пул из подписки становится **одним узлом** в списке серверов,
который внутри себя `urltest`.

---

## 2. Ключевое ограничение

> **Узел-балансировщик не выносится за пределы своего контейнера.**

Он ссылается на членов, которые живут в той же подписке/папке. Вынести его
наружу — значит оставить висячие ссылки.

Отсюда запреты:

| операция | обычный узел | балансировщик |
|---|---|---|
| Ungroup (член папки → одиночный) | да | **нет** |
| Move в другую папку | да | **нет** |
| Копировать ссылку / QR | да | **нет** (URI есть, но он не переносим — §7) |
| Редактировать как сервер | да | **нет** (нет `server:port`) |
| Выключить (§283) | да | да |
| Быть целью detour | да | **нет** (см. §5) |

Механически границу держит **билдер**: резолв состава идёт по узлам текущего
контейнера и дальше не смотрит. Отдельного поля-владельца на узле нет — оно
дублировало бы эту границу и могло с ней разойтись (было в первой редакции
ТЗ, снято 31.07.2026 как неиспользуемое).

Остальные запреты — гейты UI, а не механика: `autogroup://`-форма существует
ради хранения (§7), и вставленная в чужую папку она соберёт уже её узлы.

## 3. Модель

Новый вариант sealed `NodeSpec`:

```dart
final class AutoSelectSpec extends NodeSpec {
  /// Как набирается пул. См. §3.1.
  final AutoSelectMembership membership;
  /// Параметры urltest, смапленные из Xray-стратегии (§4).
  final AutoSelectParams params;
  /// §321 P6 — теги провайдера → идентичности, для резолва правила из
  /// `selector`. Только из своего элемента подписки (§3.2.1).
  final Map<String, String> tagSynonyms;
}

sealed class AutoSelectMembership {}

/// Явный список: пользователь отметил членов галочками, либо список
/// развёрнут из Xray-`selector` на импорте (§3.2).
final class ExplicitMembers extends AutoSelectMembership {
  /// §321-идентичности `protocol|server|port|credential`, НЕ теги.
  final List<String> keys;
}

/// Правило: include набирает, exclude вычитает. Оба regex по ИТОГОВОМУ
/// тегу узла — тот же принцип, что `node_filter` каналов (§125, §048).
final class RuleMembers extends AutoSelectMembership {
  final String include;  // пусто = все члены контейнера
  final String exclude;  // пусто = не вычитать
}
```

### 3.1 Три режима членства

| режим | когда | что хранится |
|---|---|---|
| **все члены контейнера** | `RuleMembers('', '')` — дефолт для новой папки | ничего |
| **правило** | ручное, **и импорт из Xray** (§3.2) | два regex |
| **явный список** | пользователь отметил галочками | идентичности |

Include и exclude применяются **подряд**: сначала include набирает из членов
контейнера, потом exclude вычитает из набранного. Пустой include = все.

Режим — выбор пользователя: узел, приехавший из подписки правилом, можно
переключить в явный список (правило развернётся в текущий состав) и обратно.

Битый regex → трактуем как пустой (не роняем узел), как в `nodesFor`
([build_config.dart:582](../../../../app/lib/services/builder/build_config.dart)).

**Область — только свой контейнер** (§2). Правило не может дотянуться до
узлов соседней подписки: набор кандидатов — те, что билдер собрал, обходя
этот контейнер.

### 3.2 Импорт из Xray: `selector` → include-правило

Провайдер задаёт членство префиксом тега (`selector: ["proxy"]`). Это
**правило**, а не список — переносим его правилом:

```
selector: ["proxy"]   →   RuleMembers(include: '^(proxy)', exclude: '')
```

Несколько префиксов — альтернатива: `["proxy","backup"]` → `^(proxy|backup)`.

**Почему не замороженный список.** При обновлении подписки всё пересобирается
само: парсинг → таблица синонимов → include проходит по свежему набору.
Меняется и то, и другое: провайдер добавляет узлы в пул **и** правит сам
`selector` (`["proxy"]` → `["proxy","backup"]`). Оба изменения подхватываются
без участия пользователя; замороженный список пришлось бы чинить руками.

### 3.2.1 Проблема: правило написано на чужих тегах

`^(proxy)` матчит теги **провайдера** (`proxy-45-196-208-40-direct`), а в
нашей модели их нет: после §321-дедупа этот сервер выжил под именем
`L: 🇪🇸⚡Испания` — элемент «Испания» короче и по P2 обработался раньше.

**Решение — таблица синонимов (§321 P6).** При дедупе известно, что оба тега
принадлежат одному серверу; сейчас эта связь выбрасывается. Копим её:

```
идентичность                        →  теги, под которыми встречался
vless|45.196.208.40|443|<uuid>      →  { proxy,                          (Испания)
                                         proxy-45-196-208-40-direct,     (Лучший)
                                         proxy-decoy-45-196-208-40-… }   (БС)
```

Резолв `RuleMembers` идёт по **объединению** имён каждого узла:

```
член пула  ⇔  include матчит ХОТЬ ОДИН из:
               • итоговый тег узла        (L: 🇪🇸⚡Испания)
               • любой его синоним        (proxy-45-196-208-40-direct, …)
             И exclude не матчит ни один
```

Отсюда `^(proxy)` находит «Испанию» через синоним, а пользовательское
правило вида `Финлянд` — через итоговое имя. Оба вида правил работают на
одном механизме.

**Порядок обработки перестаёт быть важен.** Таблица работает при любой
сортировке: тег, встреченный где угодно в подписке, находит свой сервер.
P2-сортировка остаётся ради **имён**, а не ради резолва.

**Синонимы узла — только из СВОЕГО элемента.** Найдено при реализации
30.07.2026: таблица, накопленная по всей подписке, растаскивает в пул всё
подряд. У Liberty тег `proxy` носят 31 элемент, и `^(proxy)` набрал 22 члена
в «Лучший сервер» (вместо 15) и 15 в «БС-1» (вместо 3). `selector` написан в
границах одного конфига — значит и резолв ограничен теми тегами, что были в
элементе балансировщика. Кандидат вне этого набора отбрасывается до матчинга.

**Таблица живёт при узле, а не глобально.** Пересобирается на каждом
парсинге подписки; в storage уходит вместе с узлами подписки (как
`sourceCompact` §302 — производное от тела, не пользовательские данные).

### 3.2.2 Кто выигрывает при обновлении

**Подписка. Всегда.** Решение юзера 31.07.2026.

Правило и параметры перечитываются из `selector`/`strategy` на каждом
обновлении; правка пользователя её не переживает — ровно как остальной состав
подписки. Флага «трогали руками» нет: он был в первой редакции ТЗ и снят как
лишнее состояние.

Следствие, которое надо знать: `interval: 2m` у Liberty — их энергетика, и
подкрутить её на узле подписки насовсем нельзя (интервал обновления — 3 часа).
Кому нужны свои параметры — заводит узел автовыбора в папке (§6.1), там
источника правды снаружи нет.

### 3.2.3 Правила импорта меняют идентичность (§302)

Правило REPLACE патчит `patchedJson`, и **в конфиг уходит патч**, а не
исходный узел. Значит замена `server`/`uuid` меняет §321-идентичность — а
синонимы группы собраны до применения правил и указывают на прежний адрес.

Поэтому: `nodeIdentityKey` считает ключ **от патча**, если он есть
(`nodeIdentityKeyRaw` отдаёт доправочный — по нему строится карта «было →
стало»), а контроллер после применения правил перемапливает `tagSynonyms`
затронутых узлов. Без этого пул автовыбора становится висячим при любом
REPLACE по адресу.

### Почему не `server`/`port`

`NodeSpec` требует `server`/`port` — у группы их нет. Решение: **пустая
строка и 0**, плюс геттер `isGroup` (по образцу §317/§319, где DNS-группа
тоже оказалась не сервером).

Альтернатива — вынести `server`/`port` из базового класса в подтипы — правит
все 14 вариантов и весь UI. Отвергнута: цена несопоставима.

**Инвариант:** `server.isEmpty && port == 0` ⇔ `isGroup`. Проверяется тестом.

### 3.3 Резолв на билде

Оба режима дают на выходе список тегов:

- `ExplicitMembers` — ключ → узел контейнера с такой идентичностью;
- `RuleMembers` — include/exclude по **итоговому тегу И синонимам** (§3.2.1).

Не найденный ключ / не сматчившийся узел — пропускается (узел выключен §283
или исчез из подписки). Пул пуст после резолва → узел не эмитится (§5).

## 4. Маппинг Xray → наш urltest

У нас уже есть `ChannelAuto` ([channel.dart:94](../../../../app/lib/models/channel.dart))
с `mode`/`pool`/`poolTolerance`/`stickyHash` (§208). Переиспользуем его поля.

### Стратегия

| Xray `strategy.type` | наш `mode` | обоснование |
|---|---|---|
| `leastPing` | `least_test` | прямое соответствие |
| `leastLoad`, `expected` > 1 | `round_robin` | ближайшее по смыслу: несколько узлов в работе |
| **любая, `expected` ≤ 1** | **`least_test`** | «держи ОДНОГО живого» — это простой urltest, см. ниже |
| `random` | `round_robin` + sticky `["none"]` | чистая ротация |
| `roundRobin` | `round_robin` | прямое |
| отсутствует | `least_test` | дефолт Xray |

**`leastLoad` ≈ `round_robin`.** Ближе, чем кажется: по документации Xray
`expected` — «число лучших узлов, трафик распределяется между ними
**случайно**». То есть у обоих есть пул из N и раздача по нему; отличается
**критерий отбора** в пул — Xray берёт по стабильности задержки
(`baselines` = допустимое СКО RTT), мы по здоровью и окну от лучшего.

Warning не выдаём (решение юзера 30.07.2026: не сыпать предупреждениями
там, где выбор всё равно безальтернативен).

### Числовые параметры

| Xray | наш | правило |
|---|---|---|
| `settings.expected` | `balancer.pool` | напрямую; `0`/нет → 3 (наш дефолт). При `expected ≤ 1` режим = `least_test`, и `pool` вообще не эмитится |
| `settings.maxRTT` | `balancer.pool_tolerance` | `"1500ms"` → `1500`, кламп **15000** |
| `settings.baselines` | — | допустимое СКО RTT — аналога нет, отбрасываем |
| `settings.costs` | — | вес узла (больше = реже выбирается), аналога нет |
| `settings.tolerance` | — | **доля отказов** (0.01 = 1%), не мс |
| `fallbackTag` | — | обычный участник пула, см. ниже |

> Значения полей сверены с документацией Xray
> ([routing](https://xtls.github.io/en/config/routing.html),
> [observatory](https://xtls.github.io/en/config/observatory.html)),
> 30.07.2026.

**`expected: 1` → `least_test`, а не пул из одного.** Решение юзера
31.07.2026. Балансировщику с пулом из одного нечего балансировать: Xray здесь
говорит «держи одного живого», что и есть наш простой urltest. Так настроены
все шесть «БС»-групп Liberty (`WL_Balancer`, `expected: 1`, `maxRTT: 5s`) —
после правки они эмитятся бит-в-бит апстримом, без `mode` и `balancer`.

Обратная сторона у Xray видна в тех же «БС»: `costs` штрафует
`vkvideo-cdn-online` весом 10, а `fallbackTag` указывает на него же —
domain-fronting как страховка, когда оба decoy легли. Ни `costs`, ни
`fallbackTag` мы не переносим (§4), так что у нас это просто третий
равноправный член пула.

**`expected` > числа узлов** — не ошибка: пул схлопывается до доступных
(`min(pool, len(nodes))`, §208).

**`maxRTT` → `pool_tolerance`: числа совпадают, смысл нет.** У Xray это
**абсолютный потолок** (медленнее — выбыл), у нас — **окно относительно
лучшего** (в пределах N мс от минимума):

```
maxRTT: 1500ms, лучший узел 100 мс
  Xray            → пускает всё до 1500
  pool_tolerance  → пускает всё до 1600   (100 + 1500)
```

Расхождение растёт с разбросом задержек. Маппим 1:1 сознательно (решение
юзера 30.07.2026): точнее пересчитать нельзя — минимум по пулу на парсинге
неизвестен. Верхняя граница `pool_tolerance` — 15000 (SPEC 019,
device-verified), значения выше клампим.

### Обсерватория → пробы

| Xray | наш |
|---|---|
| `pingConfig.destination` | `url` |
| `pingConfig.interval` | `interval` (`"2m"` → `2m`) |
| `pingConfig.timeout` | — (нет поля; дефолт Xray 5s) |
| `pingConfig.sampling` | — (размер буфера последних результатов) |
| `subjectSelector` | — (членство уже в `memberKeys`) |

**`interval ≤ idle_timeout`** — апстрим-требование (§208), иначе ядро не
стартует. Liberty даёт `2m`, наш дефолт `idle_timeout` больше — проходит.
Проверять на билде обязательно.

### `fallbackTag` без соответствия

У sing-box urltest фолбэка нет: когда все мертвы, берётся первый в списке.
Решение: **ставим `fallbackTag`-член первым** в `memberKeys`. Поведение
совпадает без новых полей.

## 4.1 Формат эмиссии: `balancer{}` вложенный

**Device-найдено 31.07.2026.** Первая реализация писала `pool`,
`pool_tolerance` и `sticky_hash` **плоско** в urltest — ядро отвергло их как
unknown field, и не стартовал **весь конфиг**, а не одна группа.

Правильно (как §208 эмитит канал, `build_config.dart:690`):

```jsonc
{
  "type": "urltest", "tag": "…", "outbounds": [ … ],
  "url": "…", "interval": "…", "tolerance": 50, "idle_timeout": "…",
  "mode": "round_robin",              // ТОЛЬКО под round_robin
  "balancer": {                       // вложенный объект, не плоские поля
    "pool": 7,
    "pool_tolerance": 1500,
    "sticky_hash": ["process", "domain"]
  }
}
```

- `least_test` → **ни `mode`, ни `balancer`** (бит-в-бит апстрим, нулевой
  diff). `balancer` без `round_robin` роняет старт так же.
- Снятая липкость → sentinel `["none"]`, не `[]`: ядро ре-маршалит конфиг и
  схлопывает пустой массив в nil, неотличимо от «поле опущено» → дефолт
  `["process","domain"]` (§210).

**Урок.** Я писал `AutoSelectParams.toJson` с нуля вместо того, чтобы
посмотреть, как тот же балансировщик эмитит канал. Тестов на формат не было —
проверялись значения после парсинга, а не то, что уходит в ядро. Добавлены
три теста в `xray_auto_select_test.dart` (группа «формат эмиссии urltest»).

### Два поля из §208 — добавлены 31.07.2026

| поле | откуда берётся | где настраивается |
|---|---|---|
| `passive_check` | **глобальная** настройка приложения | Настройки → «Passive health check» |
| `interrupt_exist_connections` | поле узла | редактор группы → Advanced |

**`passive_check` — глобальный, не per-node.** Один тумблер на все
urltest-группы конфига (§272). Каналы получают его прямо в `buildConfig`
(`settings.passiveCheck`), а группы §322 эмитит `ServerList.build`, куда
настройки не доходят. Проброшен через **новый геттер `EmitContext.passiveCheck`**
с дефолтом `false` — так не ломаются существующие реализации интерфейса
(в том числе `_FakeCtx` в тестах). Эмитим только при `true`: отсутствие =
`false` = апстрим-поведение (omitempty у ядра).

Для пула из 15 узлов с интервалом 2 минуты это главная статья расхода
батареи — без него активная группа будит все 15 узлов каждые две минуты.

**Грабля с `implements`.** Дефолтное тело геттера в абстрактном классе
спасает только наследников через `extends`. Все три `_FakeCtx` в тестах —
`implements EmitContext`, а он требует явную реализацию **каждого** члена:
два тестовых контекста перестали компилироваться. `flutter analyze lib/`
этого не показывает — нужен `flutter analyze` без аргумента (та же грабля,
что «CI analyze = весь проект»). Симптом в прогоне выглядел как «-2 теста»
без внятного сообщения: файл не собрался целиком.

**`interrupt_exist_connections` — эмитим всегда**, как канал: значение видно
в конфиге. Дефолт `false` (соединения доживают на прежнем узле) — дефолт
ядра. В URI пишется только при `true` (`interrupt=1`), чтобы форма оставалась
короткой.

## 5. Билд

`AutoSelectSpec` эмитит **urltest-outbound**, не прокси:

```jsonc
{
  "tag": "L: 🇪🇺 🚀Авто | Лучший сервер ⚡⚡",
  "type": "urltest",
  "outbounds": ["L: 🇪🇸⚡Испания", "L: 🇩🇪⚡Германия", "…"],
  "url": "http://www.gstatic.com/generate_204",
  "interval": "2m",
  "mode": "round_robin",
  "balancer": { "pool": 7, "pool_tolerance": 1500,
                "sticky_hash": ["process","domain"] }
}
```

### Порядок эмиссии

urltest обязан идти **после** своих членов — иначе ядро не разрешит теги.
Билдер сортирует: сначала payload-узлы, потом группы.

### Пустой пул = fatal

`urltest` без outbound'ов роняет старт ядра
([validator.dart:166](../../../../app/lib/services/builder/validator.dart)).
Достижимо: все члены выключены §283, или подписка обновилась и пул опустел.

**Решение:** пул после резолва пуст → узел **не эмитится вовсе** + warning.
Не эмитить безопаснее, чем эмитить пустую группу.

Если на такой узел ссылается канал — сработает существующий механизм §274
(канал без нод → fallback на block).

### Циклы

Балансировщик может ссылаться только на payload-узлы **своего контейнера**.
Ссылка на другой балансировщик запрещена структурно: `memberKeys` содержит
§321-идентичности, а у групп идентичности нет (`server` пуст).

То есть цикл невозможен по построению, а не по проверке. §254 не трогаем.

**Detour:** балансировщик не может быть целью detour. У sing-box detour
указывает на outbound, и технически urltest подошёл бы, но цепочка через
ротирующуюся группу непредсказуема. Гейт на UI + чистка на билде (образец
§319: только UI мало — ключ уже может лежать в storage).

### Список серверов

Балансировщик — строка со значком группы. Отличия от обычного узла:

|---|---|---|

### Члены пула

**Решение: члены видны наравне с балансировщиком.**

Обоснование: после §321-дедупа они и так самостоятельные узлы, найденные
раньше по P2 (у Liberty 14 из 15 = страны). Прятать их — значит скрыть

к конкретной стране.

На Liberty список: 37 узлов + 7 балансировщиков = 44 строки. Против 61
сейчас, и одна строка «Авто» вместо 15.

### Редактор узла: вкладка «Members»

Экран правки — вкладки, как у `dns_server_edit` (§312/§317). Две:
**Members** (состав) и **Strategy** (параметры §4).

На вкладке Members — переключатель режима (§3.1) и под ним **живое превью**.
Образец — редактор канала
([channel_edit_screen.dart:255](../../../../app/lib/screens/channel_edit_screen.dart)):
regex компилируется один раз за `build`, валидность выводится из результата,
список пересчитывается на каждый ввод.

```
Mode:  ( ) All servers   (•) Rule   ( ) Pick manually

Include  [^(proxy)                    ]     ← §3.2: приехало из selector
Exclude  [                            ]

──────────────────────────────────────────
Matched  12 of 37                    [Show]
  ✓ 🇪🇸⚡Испания          ← proxy-45-196-208-40-direct
  ✓ 🇩🇪⚡Германия         ← proxy-154-222-9-195-direct
  ✗ 🇷🇺💳Россия
  …
```

Требования к превью:

- **Показывает и то, что вошло, и то, что нет** — иначе непонятно, почему
  узел не в пуле (просьба юзера 30.07.2026).
- **Причина попадания** — когда узел сматчился синонимом, а не своим именем
  (`← proxy-45-196-208-40-direct`), это видно. Без этого правило `^(proxy)`
  на списке из русских имён выглядит колдовством.
- **Битый regex** — поле красное, превью показывает состав как при пустом
  правиле (не пустой список: пользователь ещё дописывает).
- В режиме **Pick manually** тот же список, но галочки кликабельны.

Счётчик «Matched N of M» дублируется в подписи строки узла в общем списке —
чтобы не заходить в редактор ради проверки.

§319: гейт ранним return, а не «немой» disabled-элемент.

## 6.1 Различитель: тег канала, а не тип

**Device-найдено 31.07.2026.** Ядру и auto-двойник канала, и наш узел
автовыбора приходят одинаковым `type: urltest` — своего типа у sing-box нет.
UI ветвился по типу, поэтому наши группы получали чужое обращение:

- имя подменялось на «✨ Auto» вместо `🇪🇺 Авто | Лучший сервер ⚡⚡`;
- узел уезжал в верхнюю pinned-секцию к direct/block.

**Различитель — тег.** Auto-двойник канала всегда `vpn-N-auto`, его генерит
билдер (`Channel.autoTag`); тег группы §322 собирается из её имени и совпасть
не может. `HomeController` копит `_channelAutoTags` рядом с
`_roundRobinAutoTags` (§208) и отдаёт двумя путями:

| потребитель | как получает | что гейтит |
|---|---|---|
| `NodeRow` | `NodeViewItem.isChannelAuto` | подмену имени + иконку «✨» |
| `HomeState._computePinned` | `HomeState.channelAutoTags` | пин в верхнюю секцию |

Тег — строгий идентификатор (§243 «name = tag»), поэтому завязка на него, а
не на форму имени, законна.

**Следствие для тестов.** `HomeState` теперь пинит `urltest` только при
наличии тега в `channelAutoTags` — 22 существующих кейса в
`home_state_sort_test.dart` пришлось дополнить этим набором. Забыть его =
получить «двойник канала не пинится», что и произошло при первом прогоне.

### Что у группы §322 в UI

Меню наследуется целиком — оно уже гейтилось по `isUrltestGroup`, то есть по
типу, и для группы работает без правок:

| пункт | источник | статус для §322 |
|---|---|---|
| Ping | всегда | есть |
| Use this node | всегда | есть |
| Run URLTest | `isUrltestGroup` | есть |
| Select server (§203) | `urltestNow != null` | есть |
| View pool (§208) | `isRoundRobinAuto` | есть — гейт расширен, см. ниже |
| View details | всегда | есть |
| Copy URI | `!_isSpecial` | **есть** (у двойника канала скрыт) |

Подзаголовок «→ выбранный сервер» рисуется сам: `NodeViewItem.urltestNow`
берётся из `CcGroup.selected`, а ядро отдаёт его для любой urltest-группы.

### Метка режима в подзаголовке

У группы своего протокола нет — её члены разнородны. Раньше на месте
протокола показывался протокол **выбранного** узла (`VLESS·TCP·REALITY`):
строка описывает не эту сущность и меняется под пользователем при каждом
переключении.

Вместо него — метка режима, и живёт она **в подзаголовке слева от стрелки**
(`autoGroupLabel`, отдельное поле `NodeViewItem`, не `protocolLabel`):

```
🇪🇺 Авто | Лучший сервер ⚡⚡
🔀 [15/7] → 🇩🇪⚡Германия          ← всего 15 узлов, в работе пул из 7

🇳🇱⚪Нидерланды (БС-0) ☁️
🎯 [3] → 🇳🇱⚡Нидерланды           ← выбирает одного быстрейшего из 3
```

| метка | режим | что показывает |
|---|---|---|
| `🎯 [N]` | least_test | состав: из скольких выбирает |
| `🔀 [N/P]` | round_robin | состав / размер пула |

Режим определяется наличием `balancer{}` — он эмитится только под round_robin
(§4.1). `N` — длина `outbounds` после резолва, `P` — `balancer.pool`.
`P > N` показываем как есть: ядро схлопнет пул до доступных, врать «7 из 3»
не наше дело.

Двойника канала это не касается: у него уже есть подменённое имя «✨ Auto».

### Значки живого пула (`poolBadge`)

К метке дописываются значки членов, которые ядро **реально держит в работе**:

```
🔀 [15/7] 🇩🇪, 🇳🇱[2], 🇫🇮
🎯 [3] 🇳🇱, 🇫🇮
```

Повторы схлопываются с числом (`🇳🇱[2]` — два нидерландских узла в пуле).
Порядок — как отдало ядро, не алфавитный.

**Источник — `getPool` (§208), не конфиг.** В конфиге весь состав (15), а в
работе только `pool` штук (7) — показывать состав было бы враньём.

`getPool` — **unary-RPC, не стрим**: само ничего не приходит, спрашиваем мы.
Дёргать на каждый ребилд строки нельзя, поэтому **ленивый кэш** в
`HomeController`:

| когда | что происходит |
|---|---|
| строка группы впервые рисуется при `tunnelUp` | запрос уходит в фон, метка пока без значков |
| ответ приехал | `notifyListeners` → строка дорисовывается |
| сменился `pingBatchGen` | кэш сброшен, следующий ребилд тянет заново |
| туннель опущен | не запрашиваем вовсе — значков нет, и это верно |

**Периодического опроса нет.** Стоимость — один RPC на видимую группу за
пинг-раунд (у Liberty 7 групп). `pingBatchGen` инкрементится на завершение
массового пинга и ручного URLTest — то есть ровно тогда, когда задержки, а с
ними и состав пула, могли поменяться.

Компромисс, принятый осознанно (юзер, 31.07.2026): ядро ротирует пул по
своему `interval` (2 минуты у «Лучшего»), чаще наших пинг-раундов, так что
между ними значки могут быть слегка несвежими. Лечится только таймером — а
это уже периодический опрос, которого мы избегаем.

**`poolBadge` — regexp пользователя, UI-only.** Хранится полем
`AutoSelectSpec`, в конфиг **не уходит** (ядро о нём не знает), в
`autogroup://` едет как `badge=`. Дефолт — первый флаг-эмодзи:

```
[\u{1F1E6}-\u{1F1FF}]{2}
```

Флаг в Unicode — пара Regional Indicator Symbol, отсюда `{2}`; в Dart нужен
`RegExp(..., unicode: true)`. Годится любой другой шаблон — например
`\(([A-Z]{2})\)` для кода страны в скобках.

Ничего не нашлось → узел просто не даёт значка. Пустой regexp или битый →
значков нет вовсе, строка остаётся с одной меткой (не роняем, как `nodeFilter`
§125). Настраивается в редакторе группы → Advanced.

**`View pool` для §322.** `isRoundRobinAuto` знал только каналы. Расширен:
`true`, если тег среди round_robin-каналов **или** в конфиге у outbound'а есть
`balancer{}` — а он эмитится только под round_robin (§4.1). Так пункт
появляется у «Лучшего сервера» (pool 7) и не появляется у шести «БС»
(`expected: 1` → least_test, §4).

## 6.2 Группа и auto-двойник канала

**Узел автовыбора не попадает в `vpn-N-auto`.** `urltest` внутри `urltest`
бессмысленен: внешняя группа мерила бы уже выбранный внутренней узел, а не
сервер — и «лучший» считался бы по задержке до чужого выбора.

Тонкость: в **selector** канала группа попадать должна (выбрать её руками —
законно), а в его urltest-двойник — нет. До 31.07.2026 оба набора брались из
одного `selectorTags`, поэтому группа протекала в двойник.

Отсекается по **типу**, прямо в `_buildChannelGroups`:

```dart
final groupTags = {
  for (final e in nodeEntries)
    if (e['type'] == 'urltest') e['tag'] as String,
};
```

`nodeEntries` — эмитированные entry, они уже приходят в функцию (оттуда же
AWG-advisory читает типы). Никакой дополнительной передачи данных не нужно.

**Снятая переусложнённость (юзер, 31.07.2026).** Первая реализация вела учёт
через `EmitContext.markNotUrltestMember` + поле-накопитель в `_BuildCtx` +
второй параметр `urltestTags` + перегрузку `nodesFor(c, {base})`. Всё это
заменяется тремя строками выше. Побочно ушла и грабля с `implements`: новый
метод интерфейса требовал реализации в трёх тестовых `_FakeCtx`, два из них
молча переставали компилироваться.

## 7. Storage: синтетический `autogroup://`

Решение юзера 31.07.2026. Узел автовыбора хранится **обычным членом папки** —
его URI лежит в `FolderMember.raw` и парсится обратно при загрузке.

```
autogroup://?include=%5E%28proxy%29&exclude=decoy&mode=round_robin
            &pool=7&pool_tolerance=1500&sticky=process%2Cdomain#Мой%20авто
```

- Дефолтные значения в URI **не пишутся** — читаемость, `fromUri`
  подставит те же дефолты из `AutoSelectParams`.
- `members=` (через запятую) — режим явного списка, иначе режим правила.
- `sticky=` с пустым значением ≠ отсутствие ключа: это осознанно снятые чипы,
  эмиссия превратит их в sentinel `["none"]` (§208/§210).
- Фрагмент — имя узла (percent-encoded, эмодзи переживают).

**Почему так.** Альтернативы — поле `auto` рядом с `raw` или отдельный список
в `FolderServers` — требовали правок модели папки и §221-симметрии backup.
URI-форма не потребовала **ни одной**: `FolderMember._parseFirst` уже зовёт
`parseAll`, а тот — `parseUri`. Reorder, enable/disable, персист работают как
у обычного члена.

**Цена.** Форму можно скопировать и вставить в чужую папку — там правило
наберёт уже её узлы. Ограничение §2 держится гейтами UI (не показываем
«копировать ссылку» у группы), а не механикой. Это осознанный размен.

**§221 backup-симметрия не затрагивается** — новых ключей в storage нет,
`autogroup://` едет внутри `members[].raw`.

Подписочный узел по-прежнему **не сериализуется** — реконструируется парсером
из `routing.balancers` при каждом обновлении (§3.2.2).
