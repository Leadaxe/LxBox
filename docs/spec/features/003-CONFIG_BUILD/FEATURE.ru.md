# FEATURE 003 — CONFIG_BUILD — сборка конфига ядра из узлов и настроек

| Поле | Значение |
|------|----------|
| Тип | Продуктовая фича |
| Поглотила | `§076F` (жизненный цикл настроек и конфига: флаг устаревания, плашки, пересборка на возврате), `§120F` (движок шаблона: типизированные переменные, `#if`, ref-переменные) |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Назначение

Пользователь не пишет JSON для ядра. Он выбирает узлы, включает пресеты,
двигает тумблеры — а приложение превращает это в один конфиг sing-box. Фича
держит сам механизм превращения: шаблон конфига, поставляемый внутри
приложения; язык этого шаблона (переменные с объявленным типом, условия,
повторы по узлам); конвейер стадий, который собирает узлы, группы, правила
и DNS в целое; проверку результата перед стартом; и жизненный цикл
«изменил настройку → конфиг пересобран → ядро на новом конфиге».

Три принципа, которые фича защищает:

1. **Конфиг, который не примет ядро, не сохраняется и до ядра не доходит.**
   Что можно починить деградацией — чинится с предупреждением; что нельзя —
   fatal с понятной причиной, на диске остаётся прежний конфиг.
2. **Правка настройки не теряется.** Изменение видно следующей сборке сразу,
   флаг «конфиг устарел» гаснет только от успешной сборки, переживает
   убийство процесса.
3. **Плашка не врёт.** «Конфиг изменился» показывается, только когда ядро
   действительно крутит другой конфиг; ложные плашки — дефект.

## Обещания

- **P1. Значение переменной приводится по объявленному типу, а не по виду.**
  `bool`/`int` приводятся, `text`/`secret`/`enum`/`outbound`/`dns_servers`
  идут строкой дословно: пароль `1234` остаётся строкой, `urltest_tolerance`
  уходит числом. Свидетель: юниты «secret/text: НЕ коэрсятся даже если
  выглядят как число/bool», «urltest_tolerance подставляется числом, а не
  строкой». Мутация: угадывать тип по содержимому строки.
- **P2. В конфиг не уходит значение, которое ядро отвергнет.** `int`
  зажимается в 0..65535; у переменной с границами (`dns_cache_capacity`
  1024..65535) значение вне границ заменяется умолчанием; пустое
  обязательное — умолчанием (кроме `secret` и необязательных). Свидетель:
  юниты «int зажимается в 0..65535», «размер кэша вне границ не попадает в
  конфиг — действует 4000», «пустое обязательное int → умолчание»,
  «пустое необязательное умолчанием не заменяется». Мутация:
  подставлять сохранённую строку как есть.
- **P3. Условие вычисляется лениво, ложное без `#else` убирает узел.**
  Отброшенная ветка не обходится; элемент массива выпадает, ключ снимается.
  Свидетель: юниты «внешнее условие ложно — вложенное в отброшенной ветке
  не влияет», «ложно без else — элемент выпадает», корпус контракта
  по движку шаблона. Мутация: обходить обе ветки.
- **P4. Кривой поставляемый шаблон отвергается при загрузке, а не при
  сборке.** Исключение: пресет с неполным `for_each` снимается один, шаблон
  живёт. Свидетель: юниты «поставляемый шаблон проходит проверку»,
  «сломанный #enable поставляемого шаблона отвергается на загрузке»,
  «for_each без as — снимается только этот пресет». Мутация: валидация
  только в сборке.
- **P5. Неизвестное в рантайме не роняет сборку, но видно.** Необъявленное
  `@имя` остаётся литералом, неизвестная `#`-директива снимается — оба с
  кодом предупреждения; предупреждения шаблона идут первыми в отчёте сборки
  и сохранение не блокируют. Свидетель: юниты «неизвестное @имя →
  плейсхолдер остаётся», «неизвестный #-ключ-сосед снимается», виджет-тест
  «N предупреждений — снек, кнопка открывает шторку». Мутация: тихий дроп.
- **P6. Ref-переменная пресета читает глобальное значение.** Своё значение
  в записи пресета игнорируется. Свидетель: юниты «ref-переменная: значение
  из глобальных → включён», «глобального значения нет, есть только в записи
  пресета → выключен». Мутация: читать ref из записи пресета.
- **P7. `for_each` даёт одно тело на каждый узел, реально попавший в
  конфиг.** Ноль узлов — пресет пуст; `filter` (например `skip_presets`)
  исключает узел. Свидетель: юниты «ноль узлов — пресет пуст», «два узла —
  повторы подряд в порядке узлов, теги без неймспейса», «filter ложен
  (skip_presets)». Мутация: обслуживать выключенный или снятый гейтом узел.
- **P8. Чинимое чинится деградацией до проверки.** Висячий detour, член-
  призрак группы, `route.final` на исчезнувшее Направление (→ `vpn-1`),
  `resolve` на пропавший DNS-сервер, неизвестный uTLS-отпечаток (→
  `chrome`), битый REALITY — снимаются/заменяются с предупреждением.
  Свидетель: юниты «несколько битых detour → все сняты, валидный уцелел»,
  «resolve со ссылкой на отсутствующий сервер → server снят», «мусорный
  отпечаток → chrome с записью», «нечётный short_id очищен, узел и конфиг
  живы». Мутация: оставить ссылку — fatal ядра на старте.
- **P9. Нечинимое — fatal, конфиг не сохраняется.** Висячая ссылка правила,
  `route.final`, detour, `dns.final`/резолвера; пустой urltest; `default`
  селектора вне состава; кольцо detour/групп. Свидетель: юниты «висячая
  ссылка правила → fatal», «кольцо через селектор узел→группа→узел — один
  виновник»; «не сохраняется» — ручная: собрать кольцо detour → Start →
  шторка с виновниками, VPN не стартует. Мутация: вернуть JSON при fatal.
- **P10. Правка видна следующей сборке сразу.** Мутация на экране настроек
  сразу попадает в хранилище в памяти; запись на диск — при уходе с экрана
  или сворачивании. Свидетель: юниты «поставленные правила видны читателю до
  записи на диск», «правка сразу поднимает флаг и ставится в память».
  Мутация: отдавать сборке состояние только после записи на диск.
- **P11. Флаг «конфиг устарел» не теряется и не зажигается зря.** Гаснет
  только успешной сборкой; мутация во время сборки его сохраняет; запись на
  диск после сборки его не переподнимает; неудачный или пустой фетч подписки
  его не зажигает. Свидетель: юниты «переключение подписки во время
  сборки не теряет флаг», «запись при уходе с экрана не переподнимает флаг
  после пересборки», «фейлы фетча не поднимают флаг», «тот же состав
  повторно — флаг не поднят». Мутация: гасить флаг в начале сборки.
- **P12. Устаревание переживает убийство процесса.** На запуске флаг
  восстанавливается сравнением времени изменения настроек и конфига (с
  точностью до секунды) и конфиг тихо пересобирается. Свидетель: юниты
  «свежий конфиг в каталоге нативной части → не устарел», «запись настроек
  при поднятом флаге не трогает конфиг (честно устарел)», «правка → снятие
  флага пересборкой → запись → чисто». Мутация: искать конфиг не в том каталоге
  (§414) — вечное «грязно».
- **P13. Старт VPN — на актуальном конфиге.** Есть незаписанные изменения
  или сборка в полёте — Start сначала дожидается/делает пересборку (одну на
  все триггеры). Свидетель: без автотеста — ручная: правка правила → сразу
  Start → в журнале «Config built» раньше старта ядра.
- **P14. Плашки взаимоисключающие.** Синяя «Settings changed — tap to
  rebuild config» — флаг поднят и сборка не идёт; «Config changed — restart
  VPN to apply» — туннель поднят, флаг снят, сохранённый конфиг разошёлся с
  работающим и не идёт автоприменение. Свидетель: юниты «флаг поднят, но
  идёт сборка — плашки нет», «restart не показывается при поднятом флаге»,
  «restart не показывается при выключенном туннеле», «restart подавлен на
  окно автоприменения». Мутация: обе плашки сразу.
- **P15. «Restart» не зажигается, если ядро уже на этом конфиге.**
  Сохранённый конфиг сравнивается с работающим в канонической форме ядра;
  нет ответа — плашка остаётся (лишняя лучше пропущенной). Свидетель: юниты
  «формы совпали → свежий», «нет снапшота работающего → неизвестно, не
  свежий».
  Мутация: сравнивать байты файла с прошлой сборкой.
- **P16. Автоперезапуск — только когда есть что применять.** Галка вкл,
  туннель поднят, конфиг разошёлся с работающим, пересборка удалась, не
  кулдаун. Свидетель: юниты «все условия выполнены → перезапуск», «туннель
  лежит → нет», «ядро уже на этом конфиге → нет», «кулдаун → пропуск,
  плашка остаётся запасным путём». Мутация: перезапуск на каждую сборку.
- **P17. Выбор члена своей группы применяется вживую.** Ядро переключается
  сразу, плашки нет; выбор сохраняется и попадает в конфиг на следующем
  старте. Свидетель: юнит «живой выбор: состояние записано, конфиг ждёт
  пересборки на старте». Мутация: поднимать флаг устаревания.

## Контролируемые параметры

| Настройка | Значения | Умолчание | Ключ конфига ядра |
|---|---|---|---|
| Log level | `trace`…`panic` | `warn` | `log.level` |
| Certificate store | `system` · `mozilla` · `chrome` | `system` | `certificate.store` |
| Auto-detect interface | вкл/выкл | вкл | `route.auto_detect_interface` |
| TUN: IPv4 address | CIDR | `172.16.0.1/30` | `inbounds[tun-in].address[0]` |
| TUN: Enable IPv6 | вкл/выкл; при включении стратегии → `prefer_ipv4`, при выключении → `ipv4_only` | выкл | `address[1]` = IPv6 address |
| TUN: IPv6 address | CIDR | `fdfe:dcba:9876::1/126` | `inbounds[tun-in].address[1]` |
| TUN: Custom tunnel routes | вкл/выкл | выкл | `route_address` (четыре половинки v4/v6) |
| TUN: interface / MTU / Stack | имя · int · `system`/`gvisor`/`mixed` | `lxbox` · 1492 · `system` | `interface_name` · `mtu` · `stack` |
| TUN: Auto route / Strict route | вкл/выкл | вкл / выкл | `auto_route` · `strict_route` |
| Auto-restart VPN on settings change | вкл/выкл | выкл | — (поведение применения) |

Неизменяемые ключи каркаса шаблона: `log.timestamp: true`,
`route.find_process: true`, `outbounds` `direct-out` и `block`,
`experimental.cache_file` (`enabled`, `path: cache.db`, `store_fakeip`),
`services: [{type: oom-killer}]`. Переменные секций DNS, VPN Mode, TLS
Fragmentation, Auto Proxy и пресетов — в своих фичах (см. Границы).

## Входы / Выходы

**Входы:** поставляемый шаблон (секции переменных, каркас `config`,
каталог пресетов, шаблоны групп, DNS-каталог) с оверлеем отображаемых
текстов локали; значения переменных пользователя; источники узлов;
Направления и цепочки; правила и записи пресетов; DNS-записи; режим VPN,
split tunneling, параметры сна туннелей; версия ядра и его теги сборки;
снапшот работающего конфига ядра.

**Выходы:** итоговый JSON для ядра (сохраняется только без fatal);
предупреждения сборки (коды шаблона первыми, затем деградации); fatal-
причины; значения, которые сборка сама исправила и просит сохранить
(умолчания резолверов DNS); карта «финальный тег → исходный узел»;
плашки на главном экране, снек «Config rebuilt: N nodes».

## Data flow

```
 настройки ─┐                           изменение на экране
 шаблон ────┼─► ПЕРЕМЕННЫЕ               │ хранилище в памяти + флаг «устарел»
 узлы ──────┘   (умолчание ← значение,   ▼
                тип, границы, режим VPN) триггер: возврат на главный · тап по
                    ▼                    синей плашке · Start · запуск · подписка
 КАРКАС: копия config шаблона, подстановка @var и условий
                    ▼
 УЗЛЫ: теги (резерв Направлений) → detour-ссылки → гейт реестра ядра →
       свёртки источников → цепочки → группы Направлений
                    ▼
 ПРЕСЕТЫ И ПРАВИЛА (порядок оси, for_each) → lx.wg → route.final
                    ▼
 POST-STEPS: уступки detour · TLS-трансформации · DNS · split tunneling ·
             миграция тегов · лечения · граф-санитайзер
                    ▼
 ПРОВЕРКА ── fatal → отказ, конфиг на диске прежний, причина в снеке/шторке
                    ▼
 сохранение ─► сравнение с работающим ─► «restart» / автоперезапуск / ничего
```

## Правила и гарантии

- Метаданные переменной (тип, умолчание, варианты) — только из шаблона;
  хранение держит лишь значение. Значение, равное умолчанию, в записях
  пресетов и шаблонных DNS-серверов не хранится.
- Сборка — одна точка: все пути (возврат на главный, плашка, Start,
  запуск, реакция подписки, Debug API) идут через неё и делят одну текущую
  пересборку.
- Флаг «устарел» — один на процесс, не хранится на диске; при запуске
  выводится из времени изменения файлов.
- Если конфиг закреплён через Debug API (`PUT /config`), пересборки
  молча не происходят — см. [019-CONFIG_EDITOR](../019-CONFIG_EDITOR/FEATURE.ru.md).
- Настройки вне конфига (тактильный отклик, язык) флаг не поднимают.

## Особенности сопровождения

- Экран, который сохраняет на уходе, обязан класть правку в память сразу:
  возврат на главный срабатывает в момент pop, а уход экрана — на ~300 мс
  позже; иначе конфиг отстаёт на один визит (§107).
- Гасить флаг «устарел» можно только по итогам сборки и только если состав
  не менялся под ней (§360); повторная постановка правки при уходе с экрана
  не должна снова зажигать флаг (§338).
- Время изменения конфига выравнивается к времени настроек, а не к «сейчас»:
  секундная точность файловой системы иначе даёт ложное «грязно» (§113).
- Ключ `#if` с суффиксом (`#if1`, `#if tun-only`) — единственный способ
  повесить два условия на один объект: второй одноимённый ключ JSON молча
  затирает первый.
- `reject` в `outbound` пресета — не тег: сборка сама переводит его в
  `action: reject`, иначе висячая ссылка.
