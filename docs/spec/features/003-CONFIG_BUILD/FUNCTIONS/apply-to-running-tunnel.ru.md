# Применение к работающему туннелю

| Поле | Значение |
|------|----------|
| Фича | [003-CONFIG_BUILD](../FEATURE.ru.md) |
| Обещания | P14 P15 P16 P17 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Отвечает на вопрос «ядро уже работает на моих настройках?» и доводит
изменение до ядра: показывает честную плашку, по желанию перезапускает
туннель сам, а то, что ядро умеет менять на лету, меняет без разрыва.

## Параметры

| Настройка | Значения | Умолчание |
|---|---|---|
| Auto-restart VPN on settings change | вкл/выкл | выкл |

Подпись в настройках предупреждает: каждое применение рвёт туннель
примерно на 3 с и закрывает открытые соединения. Включённая галка
перекрывает выбор реакции у каждой подписки — применяется всё.

**Что применяется как:**

| Изменение | Применение |
|---|---|
| Настройки, входящие в конфиг (переменные шаблона, правила, DNS, Tunnel apps, узлы и источники) | Пересборка ([жизненный цикл](settings-lifecycle.ru.md)); при поднятом туннеле — плашка «restart» или автоперезапуск |
| Режим VPN, адрес, порт, авторизация прокси | Пересборка + сразу флаг «нужен перезапуск» при поднятом туннеле |
| Allow bypass, Keep on exit, Background mode | В конфиг не входят; берутся при следующем подъёме туннеля; при поднятом туннеле — флаг «нужен перезапуск», при лежащем — ничего |
| Выбор члена своей ручной группы (узел папки, группа подписки) | Сразу в ядре, без разрыва и без плашки; запоминается и попадает в конфиг на следующем Start |
| Выбор узла в Направлении | Сразу в ядре ([007-NODE_LIST](../../007-NODE_LIST/FEATURE.ru.md)) |
| Настройки приложения (язык, тактильный отклик…) | Вне конфига, ничего не требуют |

## Входы / Выходы

**Входы:** результат сохранения конфига; состояние туннеля; снапшот
работающего конфига от ядра (`GetRunningConfig`) и каноническая форма
сохранённого (`FormatConfig`); галка автоперезапуска.
**Выходы:** плашки главного экрана, перезагрузка ядра на месте, текст снека
пересборки: «Config rebuilt: N nodes» / «… — reloading VPN» / «… — restart
VPN to apply».

## Правила и инварианты

- **Синяя плашка** «Settings changed — tap to rebuild config»: флаг
  «устарел» поднят и сборка не идёт. Тап — пересборка.
- **Плашка «Config changed — restart VPN to apply»**: туннель поднят, флаг
  «устарел» снят, флаг «нужен перезапуск» стоит, автоприменение не идёт.
  Тап — остановка VPN (при >3 активных соединениях — с подтверждением
  «Stop VPN?»); плашка гаснет при реальной смене состояния туннеля.
- Две эти плашки одновременно не показываются.
- **Флаг «нужен перезапуск»** ставит сохранение конфига, если туннель
  поднят и конфиг изменился в канонической форме; гасит — сохранение
  конфига, совпавшего с предыдущим, любой подъём/остановка туннеля и
  успешная перезагрузка ядра.
- **Сравнение с работающим.** При поднятом туннеле сохранённый конфиг (с
  наложенными нативными докрутками: свой пакет в `include_package` в
  allow-режиме, `auto_redirect`) приводится к канонической форме ядра и
  сравнивается со снапшотом работающего: совпало — флаг гасится. Нет
  снапшота, старое ядро, сбой — «неизвестно», флаг остаётся.
- **Автоперезапуск** — после любой успешной пересборки, если галка вкл,
  туннель поднят и флаг «нужен перезапуск» стоит. Идёт перезагрузкой ядра
  на месте; на время применения плашка «restart» подавлена. Кулдаун
  перезагрузки (3 с) пропускает применение — плашка возвращается как
  запасной путь, причина пишется в журнал.
- **Кнопка ⟳ рядом со статусом:** туннель лежит — пересборка + старт;
  поднят и есть изменения — пересборка + переподключение; поднят без
  изменений — перезагрузка ядра на месте. Долгое нажатие — меню явных
  действий.
- Лежащий туннель плашку «restart» не показывает: конфиг подхватится
  на Start.

## Границы

- Сама перезагрузка ядра, её кулдаун и переподключение —
  [010-VPN_SERVICE](../../010-VPN_SERVICE/FEATURE.ru.md).
- Реакция на автообновление подписки (rebuild/reload по подписке) —
  [001-SUBSCRIPTIONS](../../001-SUBSCRIPTIONS/FEATURE.ru.md).
- Применение нативных настроек туннеля зависит от возможностей ОС: они
  действуют только при установке туннеля.
