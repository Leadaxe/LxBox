# Жизненный цикл настроек

| Поле | Значение |
|------|----------|
| Фича | [003-CONFIG_BUILD](../FEATURE.ru.md) |
| Обещания | P10 P11 P12 P13 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Гарантирует, что изменённая настройка доезжает до сохранённого конфига:
отмечает конфиг устаревшим, копит правки без лишних записей на диск и
пересобирает конфиг в нужный момент — сам, без кнопки «Применить».
Состояние живёт в трёх слоях: настройки в памяти → файл настроек → файл
конфига ядра; четвёртый — работающий туннель — ведёт
[применение к туннелю](apply-to-running-tunnel.ru.md).

## Параметры

Своих настроек нет. Настройка `auto_rebuild` удалена: пересборка при
возврате на главный экран всегда автоматическая.

Два способа сохранения у экранов:

| Способ | Где | Поведение |
|---|---|---|
| Отложенный | VPN Settings (переменные шаблона, режим VPN), Routing, DNS, Tunnel apps | Каждая правка сразу уходит в настройки в памяти и поднимает флаг; на диск — одной записью при уходе с экрана или сворачивании приложения |
| Немедленный | Подписки и серверы, редактор правила (Save), фильтр узлов (Apply), настройки приложения | Запись сразу; конфиг-значимые записи поднимают флаг |

## Входы / Выходы

**Входы:** правки на экранах, записи источников (добавление, удаление,
включение, фетч с новым составом), Debug API, импорт резервной копии,
загрузка набора настроек, запуск приложения.
**Выходы:** флаг «конфиг устарел»; пересобранный и сохранённый конфиг;
снек «Config rebuilt: N nodes» при сборке по действию пользователя.

## Правила и инварианты

- **Флаг «устарел»** поднимается правкой конфиг-значимой настройки, гаснет
  только успешной сборкой. Сборка гасит его, лишь если состав источников не
  поменялся под ней; не сохранился файл — флаг возвращается.
- Флаг не поднимают: пометка попытки фетча, неудачный фетч, фетч с тем же
  составом, фетч выключенной подписки, настройки приложения, служебные
  записи самой сборки.
- **Staging.** Правка на экране с отложенной записью видна любому читателю
  (пересборка на возврате, Start, запуск) сразу, не дожидаясь записи на
  диск. Запись при уходе с экрана лишь дожидается последней постановки и
  не зажигает флаг заново.
- **Триггеры пересборки** (все — одна общая пересборка, повторный триггер
  присоединяется к идущей):
  - возврат на главный экран любым способом (назад, жест, выход из
    вложенной цепочки экранов — срабатывает на последнем шаге), если флаг
    поднят; если идёт фетч или сборка — пересборка догоняет, когда они
    закончатся;
  - тап по синей плашке;
  - Start: при поднятом флаге или непримененном выборе члена группы —
    сначала пересборка;
  - холодный запуск, когда источники есть, а конфига нет или флаг поднят —
    тихая пересборка после восстановления узлов подписок из кэша;
  - реакция на обновление подписки ([001-SUBSCRIPTIONS](../../001-SUBSCRIPTIONS/FEATURE.ru.md)).
- **После убийства процесса.** Флаг в файл не пишется. На запуске он
  выводится сравнением времени изменения файла настроек и файла конфига
  (с точностью до секунды): настройки новее или конфига нет — устарел.
  Запись настроек при снятом флаге выравнивает время конфига по времени
  настроек, чтобы не было ложного «устарел».
- Холодный запуск с работающим туннелем, но непрочитанным конфигом — не
  пересборка, а постоянная плашка «Config loading error» (тап — стоп).
- Загрузка набора настроек поднимает флаг, и конфиг собирается из
  настроек нового набора.

## Границы

- Что показывают плашки и как изменения доходят до ядра —
  [применение к туннелю](apply-to-running-tunnel.ru.md).
- Атомарность записи файлов, резервная копия, импорт —
  [017-BACKUP_AND_STORAGE](../../017-BACKUP_AND_STORAGE/FEATURE.ru.md);
  наборы настроек — [018-WORKSPACES](../../018-WORKSPACES/FEATURE.ru.md).
- Приложение, убитое в момент правки до ухода с экрана и до сворачивания,
  теряет эту правку — зависит от возможностей ОС (момент уведомления о
  сворачивании).
