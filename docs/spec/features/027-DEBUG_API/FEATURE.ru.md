# Debug API — локальный HTTP-интерфейс для автоматизации и диагностики

LxBox поднимает защищённый токеном HTTP-сервер на адресе самого устройства,
через который разработчик, тестовый скрипт или ИИ-агент читает всё состояние
приложения и меняет его без экрана: конфиг sing-box, подписки, правила
маршрутизации, Направления, цепочки, DNS, журналы и отчёты о сбоях. По
умолчанию выключен, с хоста доступен только через `adb forward`.

| Поле | Значение |
|------|----------|
| Фича | 027-DEBUG_API |
| Тип | Продуктовая фича (интерфейс разработчика) |
| Поглотила | `§031F` (часть `§043F` про Debug API) |
| Состояние | ✅ написана по коду, 2026-09-29 |

## Назначение

Воспроизвести жалобу, прогнать автотест, попробовать конфиг, который
приложение само собрать не умеет, — всему этому нужен полный доступ к
состоянию приложения с хоста, без тапов. Debug API даёт его обычным HTTP на
`127.0.0.1:<port>`: у каждой области, которую правит интерфейс, — источники,
правила, Направления, цепочки, папки, DNS, режим VPN, приложения туннеля, —
есть маршруты через тех же владельцев, что и экраны; сверху — маршруты чтения
улик (журналы, дамп, отчёты о сбоях, снимки памяти, pprof) и триггеры (старт,
стоп, URLTest, пересборка, сброс сети).

Фича защищает три принципа:

- **Корневой доступ by design, за явными воротами.** За токеном API видит и
  меняет всё, включая секреты; маскирование — удобство, а не граница. Сами
  ворота — выключен по умолчанию, только loopback, токен 128 бит, проверка
  имени хоста — то, что проверяет аудит.
- **Карта не врёт.** `/help` перечисляет каждый смонтированный префикс, коды
  ошибок — зафиксированный контракт, маршрут не считается готовым, пока его
  нет в `/help` и в справочнике.
- **Записи — это записи интерфейса.** Маршрут меняет данные через владеющий
  сервис, действует тот же рубеж проверки, что у формы, отвергнутая запись
  ничего не меняет, а `?rebuild=true` превращает любую запись в «изменить +
  пересобрать конфиг» одним вызовом.

## Обещания

- **P1. Debug API закрыт по умолчанию.** Выключен до явного включения; слушает
  только адрес самого устройства; токен — 32 hex-символа (128 бит), создаётся
  при первом включении; с пустым токеном сервер не стартует, а каждый
  защищённый маршрут даёт 401. Свидетель: юниты «даёт 32 hex символа», «разные
  токены при последовательных вызовах», «пустой token → Unauthorized даже с
  Bearer»; loopback — ручная проверка (запрос по LAN-адресу устройства не
  соединяется). Мутация: пустой токен допускает старт.
- **P2. Без токена — только /ping и /help.** Остальное без точного заголовка
  `Authorization: Bearer <token>` даёт 401. Свидетель: юниты «GET /state без
  токена → 401», «/ping пропускает без auth», «схема должна быть именно
  `Bearer `, не `bearer`». Мутация: регистронезависимая схема.
- **P3. Чужое имя хоста отвергается первым.** Запрос с Host не `127.0.0.1` /
  `localhost` получает 403 даже с верным токеном и даже на `/ping`; порт в
  заголовке и регистр игнорируются. Свидетель: юниты «evil.com →
  InvalidHost», «GET /ping с Host: evil.com → 403», «отбрасывает port из
  header», «игнорирует регистр». Мутация: проверка хоста после авторизации
  только для защищённых путей.
- **P4. Доступ нельзя потерять через сам API и импорт бэкапа.** Ключи
  включения, порта и токена не пишутся через `/settings/vars` (409); импорт с
  заменой, где их нет, сохраняет текущие. Свидетель: юниты «replaceRaw
  merge=false keeps device Debug API keys absent in snapshot», «Debug API keys
  from snapshot win»; запрет в `/settings/vars` — `без свидетеля`. Мутация:
  импорт с заменой переписывает `vars` целиком.
- **P5. Файловые маршруты не выходят за свои каталоги.** Имена с обходом пути
  и имена вне белого списка отвергаются (404/400). Свидетель: юниты «traversal
  в &file= отвергается», «не-whitelist имя → 404, даже если файл существует»,
  «traversal на /files/local тоже отвергается». Мутация: имя файла склеивается
  с каталогом без проверки.
- **P6. Зависший обработчик не вешает сервер.** Через 30 с клиент получает 504
  `timeout`. Свидетель: юнит «долгий handler → RequestTimeout». Мутация:
  ожидание без срока.
- **P7. Секрет не утекает в копируемые снимки.** Токен в снимке хранения —
  `***`; адреса подписок и тела узлов замаскированы до `?reveal=true`;
  чувствительные параметры запроса маскируются в журнале запросов. Свидетель:
  юниты «debug_token маскируется, остальные vars pass-through», «пустой
  debug_token остаётся пустой строкой», «без reveal — uri не отдаётся»; журнал
  запросов — `без свидетеля`. Мутация: снимок хранения без скраббера.
- **P8. Остановка сервера закрывает порт.** После остановки (выключение,
  смена порта или токена) новое соединение отвергается; сервер поднимается на
  новых значениях. Свидетель: юнит «stop() прерывает listen — connect refused
  после»; перезапуск на новом порту — ручная проверка. Мутация: старый
  слушатель жив после смены порта.
- **P9. Маршрутизация по самому длинному префиксу, не по подстроке.**
  `/subs/{id}/rules` попадает в обработчик подписок, `/statex` не попадает в
  `/state`; несмонтированный префикс — 404 `not_found`. Свидетель: юниты
  «longest-prefix wins», «не матчит по substring», «404 NotFound если префикс
  не замаунчен», «GET /unknown/path → 404 not_found». Мутация: побеждает
  первое совпадение.
- **P10. Карта не врёт и читается машиной.** Каждый смонтированный префикс
  есть в `/help?format=json`, каждый путь оттуда разрешается в смонтированный
  маршрут, JSON всегда сериализуется (каждый вложенный ключ — строка), текст —
  markdown. Свидетель: юниты «каждый смонтированный префикс роутера есть в
  /help?format=json», «/help json и text содержат реальные пути», «все ключи
  вложенных Map — String», «/help?format=text → markdown, работает». Мутация:
  маршрут без записи в `/help`.
- **P11. Коды ошибок — зафиксированный контракт; неизвестный сбой — 500 без
  подробностей.** Конверт — `{"error":{"code","message"}}`; 400
  `bad_request`, 401 `unauthorized`, 403 `invalid_host`, 404 `not_found`, 409
  `conflict`, 413 `payload_too_large`, 502 `upstream_error`, 504 `timeout`;
  неклассифицированное исключение — 500 `internal`, стек в журнале
  приложения, не в ответе. Свидетель: юниты «форма — {error: {code,
  message}}», «коды стабильные (API contract)», «обычный exception →
  InternalError (500)». Мутация: переименованный код; стек в ответе.
- **P12. Ввод проверяется единообразно.** Отсутствующий или пустой
  обязательный параметр запроса, не число там, где ждут число, тело не
  JSON-объект, неподдержанный метод — 400. Свидетель: юниты «requiredQuery
  бросает BadRequest если отсутствует», «qInt невалидный → BadRequest»,
  «jsonBodyAsMap — массив (не объект) → BadRequest», «неподдержанный метод →
  400». Мутация: отсутствующий параметр читается как пустая строка.
- **P13. Отвергнутая запись ничего не меняет.** Проверка идёт до записи; при
  400 хранение остаётся как было. Свидетель: юниты «POST с одной позицией →
  400 И НИЧЕГО НЕ ЗАПИСАНО», «→ 400 с образцом записи, хранение не тронуто»,
  «PATCH member: битый raw → 400, старое остаётся». Мутация: сперва запись,
  потом проверка.
- **P14. Нет предусловия — 409, а не тихое ничего.** Не поднят туннель, идёт
  прогон страховки, защищённое Направление: запись отвергается с машинным
  сообщением. Свидетель: юниты «group scope, tunnel down → Conflict», «идущий
  прогон → 409, фаза не сбрасывается», «vpn-1 нельзя выключить → 409».
  Мутация: 200 без действия.
- **P15. `?rebuild=true` пересобирает после записи, и неудачная пересборка её
  не откатывает.** Статус записи остаётся 200/201; итог — `rebuilt` +
  `config_bytes` или `rebuild_error`. Свидетель: юниты «?rebuild=true — write
  доезжает до storage», «?rebuild=false / без флага — обычный ответ»;
  `rebuild_error` под своим ключом — `без свидетеля`. Мутация: неудачная
  пересборка откатывает запись.
- **P16. Запись — это запись интерфейса.** Изменения через API сразу видны
  живым экранам и переживают перезагрузку контроллера. Свидетель: юниты
  «PATCH /directions/{tag}: flag-unset зеркалится в entries», «DELETE
  /directions/{tag}: heal зеркалится в entries», «правила и identity переживают
  перезагрузку контроллера (persist)». Мутация: запись в хранение, которую
  экран увидит только после перезапуска.
- **P17. Headless-старт не требует интерфейса.** `POST /action/start-vpn`
  работает до появления контроллера подписок (200, туннель стартует), а не
  409. Свидетель: юнит «без контроллера подписок → 200 и startVPN, а не 409».
  Мутация: старт отвергается до открытия главного экрана.

## Контролируемые параметры

| Настройка | Где | Значения | Дефолт | Когда действует |
|-----------|-----|----------|--------|-----------------|
| Debug API | App Settings → Diagnostics → Developer | вкл/выкл | выкл | сразу |
| Port | там же | 1024..49151, иначе ошибка под полем | 9269 | сразу (сервер перезапускается) |
| Token | там же, Copy / Regenerate | 32 hex | создаётся при первом включении | сразу; старый даёт 401 |
| Lock config (debug) | там же, виден только при включённом Debug API | вкл/выкл | выкл; снимается выключением Debug API | сразу |

Фиксированные значения (контракт): адрес `127.0.0.1`; срок обработки запроса
30 с; тело запроса до 1 МиБ; пути без токена — `/ping`, `/help`; тип ответа
`application/json; charset=utf-8` (текст или файл там, где маршрут это
объявляет).

Ключей конфига ядра фича не порождает: она читает и пишет те же настройки,
что экраны.

## Входы / Выходы

**Входы:** HTTP-запросы на `127.0.0.1:<port>` с `Authorization: Bearer
<token>`; переключатель, порт и токен из App Settings; открытие главного
экрана (сервер поднимается).

**Выходы:** JSON-ответы; текст (`/help`) и файлы (SRS, отчёты, снимки, pprof);
строки в журнале приложения — по одной на запрос (метод, путь, запрос,
статус, время) и жизненный цикл сервера (слушает, остановлен, порт занят);
побочные эффекты в приложении — те же, что у соответствующего действия
интерфейса.

## Data flow

```
App Settings → включение / порт / токен → (пере)запуск сервера на 127.0.0.1:<port>
HTTP → маппер ошибок → журнал запросов → проверка Host (403) → токен (401)
     → срок 30 с (504) → маршрут по самому длинному префиксу (404) → обработчик
обработчик → владеющий сервис (тот же, что у экрана) → хранение
        → [?rebuild=true] → сборка конфига → сохранение → rebuilt / rebuild_error
        → JSON {"ok":true,"action":…} | {"error":{"code","message"}}
```

## Правила и гарантии

- Порядок проверок: имя хоста → токен → срок → маршрут. Отвергнутый запрос
  пишется в журнал с итоговым статусом; 5xx — warning, остальное — debug.
- Сервер стартует при открытии главного экрана и при каждом изменении
  переключателя, порта или токена; занятый порт — ошибка в журнале
  приложения, не сбой приложения; включение без токена создаёт его.
- Выключение API снимает Lock config, чтобы закреплённый конфиг никогда не
  остался без способа открепить его (019-CONFIG_EDITOR · P7).
- Ключи со словами `token`, `secret`, `auth`, `key` в имени маскируются в
  журнале запросов; `/config`, `/backup/export` и `?reveal=true` отдают секреты
  как есть — намеренно.
- Любая запись принимает `?rebuild=true`; несколько записей дешевле делать без
  флага плюс один `POST /action/rebuild-config`.
- Конфиг-значимая запись без пересборки оставляет приложение с устаревшим
  конфигом: главный экран показывает плашку «config changed», как после той же
  правки в интерфейсе, а следующая пересборка подхватывает изменение.

## Границы

- Доступа из сети нет: только адрес устройства и `adb forward`; loopback общий
  для всех приложений устройства, так что там защищает только токен. Зависит
  от возможностей ОС: жизнь процесса приложения.
- Семантика каждой области — что значит правило, Направление, цепочка,
  подписка — принадлежит владеющим фичам ([route-map.md](FUNCTIONS/route-map.ru.md));
  эта фича владеет транспортом, воротами, контрактом ошибок и картой.
- Журналы, отчёты о сбоях, дамп, живые события и уведомления —
  [013-DIAGNOSTICS](../013-DIAGNOSTICS/FEATURE.ru.md); здесь только их
  маршруты.
- Закрепление конфига (`PUT /config` + Lock config) —
  [019-CONFIG_EDITOR](../019-CONFIG_EDITOR/FUNCTIONS/config-pin.ru.md).
- Внешнее управление из приложений автоматизации и плитки —
  [014-AUTOMATION](../014-AUTOMATION/FEATURE.ru.md); Debug API — не
  пользовательский интерфейс.
- MCP-обёртка над API (`§035F`) — отменена, не реализована. Маршруты Clash API
  (`/clash/*`, `/state/clash`) — удалены (§122), 404. Потоковой выдачи
  журналов нет; единственный поток — `/profiler/live/stream`.
- Полный справочник маршрутов —
  [`docs/api/debug-api-reference.md`](../../../api/debug-api-reference.md);
  фича его не дублирует.

## Особенности сопровождения

- Карта возможностей в `/help` пишется руками; генератора из роутера нет.
  Правило: новый маршрут = запись в `/help` (text и JSON) + строка в
  справочнике. Известные пробелы собраны в задаче 589.
- Скраббер в `/state/storage` — denylist: новый чувствительный ключ надо
  добавить в него и в тест, иначе он отдаётся как есть.
- API — корневой доступ by design: аудит проверяет границу (токен, bind,
  default-off, хост), а не маскирование секретов за ней. Маскировать
  `warp_account` / `masque_account` «как security-фикс» — ложная граница: те же
  данные лежат сырыми в `/backup/export`.
- Срок обработчика 30 с: пробы папок и цепочек последовательны, поэтому на
  больших входах снижать `timeout_ms`, а не поднимать срок.
