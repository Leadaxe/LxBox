# Операции записи — изменение приложения через тех же владельцев, что у интерфейса

Каждую область, которую правят экраны, можно записать по HTTP; запись идёт
через владеющий сервис, проверяется до того, как ляжет, и может пересобрать
конфиг тем же вызовом.

| Поле | Значение |
|------|----------|
| Фича | [027-DEBUG_API](../FEATURE.ru.md) |
| Обещания | P11–P16 |
| Состояние | ✅ написана по коду, 2026-09-29 |

## Что делает

Даёт скрипту или агенту менять то, что пользователь менял бы руками:
настройки (`/settings/*`), свои правила (`/rules`), источники и их правила
импорта (`/subs`, `/folders`), Направления и цепочки (`/directions`,
`/chains`), историю Wi-Fi, состояние ленты поддержки, импорт бэкапа и сам
конфиг (`PUT /config`). Записи отвечают единым конвертом и зафиксированным
набором кодов ошибок, так что вызывающий ветвится по коду, не разбирая
сообщение.

## Параметры

| Параметр | Где | Значения | Эффект |
|----------|-----|----------|--------|
| `?rebuild=true` | любая запись | `true`/`1`/`yes` | пересобрать конфиг из настроек после записи; в ответе появляются `rebuilt` и `config_bytes` либо `rebuild_error` |
| `?reveal=true` | записи, возвращающие снимок (`/subs`, `/folders`) | bool | возвращённый снимок несёт секреты (адреса, тела узлов) |
| `merge`, `rebuild` | `POST /backup/import` | bool, по умолчанию `false` | слияние вместо замены; пересборка после восстановления |
| `keep_servers` | `DELETE /folders/{id}` | bool | члены становятся одиночными серверами, а не удаляются |
| Тело | `PUT`/`POST`/`PATCH` | JSON-объект (`Content-Type: application/json`); `PUT /config` — сырой объект конфига; `PUT /settings/vars/{key}` — `{"value":"…"}` | тело не объект, неверный тип поля или неизвестное значение перечисления — 400 |

Любой параметр `bool` читает `true`, `1` и `yes` (без учёта регистра) как истину;
любое другое значение, включая `on`, — ложь.

Пределы: тело до 1 МиБ (413); срок обработчика 30 с (504).

## Входы / Выходы

**Входы:** запросы `POST`/`PUT`/`PATCH`/`DELETE` с JSON-телом и флагами
запроса выше.

**Выходы:** `{"ok":true,"action":"<name>",…}` с полями самой области
(созданный id или тег, свежий снимок, счётчики `healed`, `dangling_refs`,
`rebuild_needed`) и, с `?rebuild=true`, `rebuilt:true, config_bytes:N` либо
`rebuilt:false, rebuild_error:"…"`; создание отвечает 201. Ошибки:
`{"error":{"code","message"}}`; отвергнутый `POST /subs` добавляет
верхнеуровневый `dropped[]` с причинами отбраковки.

| Статус | Код | Когда |
|--------|-----|-------|
| 400 | `bad_request` | нет или неверный параметр запроса, битый JSON, неверный тип поля, находка проверки (цепочка `tooFewHops`, неизменяемый `tag`, битый regex), неподдержанный метод |
| 404 | `not_found` | неизвестный подпуть, id, тег или индекс |
| 409 | `conflict` | нет предусловия: туннель не поднят, идёт прогон страховки, выключение или удаление `vpn-1`, занятый или служебный тег, защищённый var `debug_*`, пересборка при включённом Lock config |
| 413 | `payload_too_large` | тело больше 1 МиБ |
| 502 | `upstream_error` | ядро, нативная сторона или сохранение конфига отказали |
| 504 | `timeout` | обработчик не уложился в 30 с |
| 500 | `internal` | неклассифицированный сбой; детали в журнале приложения |

## Правила и инварианты

- **Проверка до записи; отказ ничего не меняет.** Тот же рубеж, что у формы:
  цепочка с одной позицией, самоссылка или ссылка вперёд — 400, список не
  изменился; запись DNS в старой форме — 400, хранение не тронуто; член папки,
  чей новый `raw` не разбирается, остаётся со старым.
- **Записи идут через владельцев.** Источники — через владельца подписок
  (автомат загрузки, оповещение интерфейса), Направления и цепочки — через
  владельца Направлений (живые записи ресинкаются, `healed` сообщает о
  сброшенных ссылках), `app_language` — через владельца локали. Общая запись
  `/settings/vars/{key}` — простая запись переменной, кроме защищённых ключей
  `debug_*` (409).
- **Конфиг-значимые записи помечают конфиг устаревшим.** Запись переменной
  шаблона, `vpn_mode`, `tun_apps`, `dns_options`, правил или источников без
  `?rebuild=true` поднимает на главном экране ту же плашку «config changed»,
  что и правка в интерфейсе; `tun_apps` вдобавок отвечает
  `rebuild_needed:true`, потому что туннель надо поднять заново.
  `?rebuild=true` снимает плашку тем же вызовом; несколько записей дешевле
  делать без флага плюс один `POST /action/rebuild-config`.
- **`?rebuild=true` никогда не откатывает запись.** Запись отвечает 200/201,
  даже если пересборка не удалась; неудача — `rebuild_error` под своим ключом.
  При включённом Lock config явный маршрут пересборки отвечает 409, а
  пересборка по флагу тихо возвращает `rebuilt:false`.
- **`PUT /config` временный, пока не закреплён.** Он заменяет сохранённый
  конфиг байт в байт (проверяется только как JSON-объект; семантические
  ошибки ядро сообщит при перезагрузке), и следующая пересборка из любого
  источника его стирает; `PUT /settings/config_locked {"locked":true}`
  закрепляет — [019-CONFIG_EDITOR](../../019-CONFIG_EDITOR/FUNCTIONS/config-pin.ru.md).
- **Позиционные коллекции возвращают свежий снимок.** У членов папок и правил
  импорта нет id; каждая запись отвечает всей коллекцией, а следующий вызов
  берёт индексы из неё.
- **Только полные перестановки.** Маршруты `reorder` требуют ровно текущий
  набор id, тегов или индексов; неполный список — 400.

## Границы

- Транзакций между маршрутами нет: две записи — два независимых коммита;
  атомарность действует внутри одного запроса.
- Оптимистичных блокировок и версий нет: побеждает последняя запись, в том
  числе против одновременной правки в интерфейсе.
- Тела узлов подписок через API не правятся (они приходят из загрузки); тело
  одиночного сервера правится через `PATCH /folders/{id}/members/{idx}` или
  заменой источника.
- Что значит конкретное поле — контракт владеющей фичи
  ([route-map.md](route-map.ru.md)).
