# Самодокументация — карта возможностей, которую отдаёт сам сервер

`GET /help` возвращает карту всех маршрутов текстом или JSON без токена, так
что агент узнаёт, что умеет API, ещё до того, как получит секрет.

| Поле | Значение |
|------|----------|
| Фича | [027-DEBUG_API](../FEATURE.ru.md) |
| Обещания | P10 |
| Состояние | ✅ написана по коду, 2026-09-29 |

## Что делает

Отдаёт написанную руками карту возможностей: каждый префикс и подмаршрут, его
метод, параметры, форму тела и описание в одну строку, а также факты об
авторизации и транспорте (заголовок, адрес привязки, порт по умолчанию,
проверка хоста). Текст — для человека или LLM, читающих ответ напрямую; JSON
— для инструментов, которые строят вызовы по списку `{method, path, params,
body, description}`.

## Параметры

| Параметр | Значения | Дефолт |
|----------|----------|--------|
| `format` | `text` — markdown; `json` — структура; что-то иное — 400 простым текстом | `text` |

Токен не нужен: `/help` и `/ping` — два пути без авторизации; проверка хоста
действует и здесь.

## Входы / Выходы

**Входы:** `GET /help[?format=text|json]`.

**Выходы:** `text/markdown` — разделы Health, State, Device, Config, Pool,
Logs, Actions, WARP, Rules, Subscriptions, Nodes, Directions, Chains, Folders,
Core-rejected nodes, Wi-Fi history, Files, Traffic Profiler, Support feed,
Diagnostics, Settings, Backup, Errors, Quick Examples, Notes; либо JSON
`{server, docs, auth, transport, endpoints:[{method, path, auth?, params?,
body?, description, response?}]}` с отступами.

## Правила и инварианты

- **Паритет с роутером проверяется с двух сторон.** У каждого смонтированного
  префикса должна быть хотя бы одна запись в JSON (`path == prefix` или под
  ним); каждый путь из JSON после подстановки `{id}`/`{tag}`/`{idx}` должен
  разрешаться в смонтированный маршрут. Маршрут, добавленный без записи в
  `/help`, роняет юнит-тест.
- **Карта пишется руками.** Генератора из роутера или из справочника нет;
  текстовая и JSON-формы — два отдельных литерала, правятся вместе. В
  JSON-форме каждый вложенный ключ обязан быть строкой — это держит тест
  сериализации.
- **Правило для нового маршрута: запись в `/help` (text и JSON) + строка в
  справочнике.** Справочник
  ([`docs/api/debug-api-reference.md`](../../../../api/debug-api-reference.md))
  намеренно шире (примеры, сценарии, семантика); `/help` — короткая карта. При
  расхождении прав код, правятся оба.
- **Известные пробелы** (задача 589, открыта): в JSON-форме нет
  `POST /settings/rebuild-config`, `GET /files/external` и параметра `source`
  у `POST /logs/clear`; в разделе Errors нет кодов 413/502/504;
  `POST /subs/reorder`, `GET /subs`, `/settings/enabled_groups`,
  `GET /diag/stderr` и перечень полей `warnings` описаны по старому поведению.
  Та же задача добавляет тест паритета «каждый путь из `/help?format=json`
  встречается в справочнике».
- **Текстовая форма — первое чтение агента.** В ней описана подготовка
  (`adb forward tcp:9269 tcp:9269`, заголовок `Authorization`, откуда
  копируется токен), а в конце — готовые примеры и заметки (теги с эмодзи
  надо URL-кодировать, времена — ISO-8601 UTC, токен стабилен до Regenerate).

## Границы

- `/help` описывает маршруты, а не семантику областей: что значит поле
  правила или позиция цепочки — во владеющей фиче и в справочнике.
- Выдачи OpenAPI или MCP нет; JSON-форма — сырьё для них, а MCP-обёртка
  (`§035F`) отменена.
- Паритет содержимого со справочником пока не тестируется (задача 589);
  тестируется только паритет с роутером.
