# Доступ и безопасность — ворота перед корневым доступом

Сервер по умолчанию выключен, слушает только адрес самого устройства и
отвечает только на токен в 128 бит; всё за этими воротами намеренно открыто.

| Поле | Значение |
|------|----------|
| Фича | [027-DEBUG_API](../FEATURE.ru.md) |
| Обещания | P1–P8 |
| Состояние | ✅ написана по коду, 2026-09-29 |

## Что делает

Решает, кому можно говорить с Debug API и через что проходит запрос, прежде
чем его увидит обработчик: переключатель включения, привязка к loopback,
порт, bearer-токен, проверка имени хоста, срок запроса и предел тела. Заодно
не даёт секрету утечь случайно — маскирует его в копируемых снимках и в
журнале запросов — и следит, чтобы API не мог отрезать разработчика от
самого себя.

## Параметры

| Настройка | Где | Значения | Дефолт |
|-----------|-----|----------|--------|
| Debug API | App Settings → Diagnostics → Developer | вкл/выкл | выкл |
| Port | там же | 1024..49151, иначе ошибка под полем; сохранённое значение вне диапазона читается как 9269 | 9269 |
| Token | там же, Copy / Regenerate | 32 hex (128 бит, криптостойкий генератор) | создаётся при первом включении |
| Lock config (debug) | там же, только при включённом API | вкл/выкл | выкл |

Фиксированные значения: адрес `127.0.0.1`; срок обработки запроса 30 с; тело
запроса до 1 МиБ (конфиг 70–300 КБ помещается, тела CRUD — меньше 4 КБ); пути
без токена — `/ping`, `/help`.

## Входы / Выходы

**Входы:** HTTP-запросы на `127.0.0.1:<port>`; заголовки `Host` и
`Authorization`; переключатель, порт и токен из App Settings.

**Выходы:** запрос, переданный маршруту, либо конверт ошибки: 403
`invalid_host`, 401 `unauthorized`, 413 `payload_too_large`, 504 `timeout`,
500 `internal`. Строки в журнале приложения: `Debug API: listening on
127.0.0.1:<port>`, `Debug API: stopped`, `Debug API: bind failed on :<port>`,
`Debug API: token empty — refusing to start`; по строке на запрос
`[debug-api] <method> <path>?<query> → <status> <ms>ms`.

## Правила и инварианты

- **Порядок проверок: имя хоста → токен → срок → маршрут.** Host не
  `127.0.0.1` / `localhost` (порт в заголовке и регистр игнорируются) — 403
  даже с верным токеном и даже на `/ping`: это защита от DNS rebinding из
  браузера. Нет точного `Authorization: Bearer <token>` — 401; схема
  регистрозависима. Дольше 30 с — 504; обработчик бросается, сервер продолжает
  обслуживать.
- **Fail-closed.** Пустой токен не даёт серверу стартовать, а если сервер с
  ним всё же работает — каждый защищённый маршрут даёт 401. Включение без
  токена создаёт его; Regenerate сразу делает старые команды 401.
- **Перезапуск на каждое изменение.** Смена переключателя, порта или токена
  останавливает старый слушатель (открытые соединения рвутся) и биндится
  заново; занятый порт — ошибка в журнале приложения, само приложение
  работает. Сервер поднимается и при открытии главного экрана, так что скрипт,
  запускающий приложение, может ждать `/ping`.
- **API не может запереть сам себя.** `debug_enabled`, `debug_port` и
  `debug_token` отвергаются в `PUT`/`DELETE /settings/vars/{key}` (409 «managed
  via App Settings UI only»); экспорт бэкапа не включает их, пока не отмечен
  «Debug API config»; импорт с заменой, где их нет, сохраняет значения
  устройства. Выключение API снимает Lock config, чтобы закреплённый конфиг не
  остался без способа открепить его.
- **Файловые маршруты не выходят из своих каталогов.** `/files/local` отдаёт
  только белый список имён; `/files/crash`, `/files/oom` и `&file=` отвергают
  `..`, абсолютные пути и разделители — 400/404, никогда не файл вне архива.
- **Маскирование — удобство, а не граница.** `/state/storage` отдаёт
  `debug_token` как `***`, адреса подписок как `scheme://host/***`, тело
  одиночного сервера — длиной в байтах, членов папки — счётчиком; `/state/subs`
  и `/subs/{id}` снимают маску по `?reveal=true`; `/nodes/link` отдаёт URI
  только с `?reveal=true`. `/config`, `/backup/export`, `warp_account` и
  `masque_account` отдаются сырыми намеренно — те же данные лежат в одном
  маршруте рядом, а маска лишь замедлила бы диагностику.
- **Журнал запросов не несёт секретов.** Значения ключей запроса, содержащих
  `token`, `secret`, `auth`, и ключа `key` пишутся как `***`; строки 5xx —
  warning, остальные — debug. Запросы, отвергнутые до конвейера (слишком
  большое тело), тоже попадают в журнал.
- **Ошибки типизированы.** Классифицированный сбой становится своим конвертом;
  всё остальное — 500 `internal` с общим сообщением, а стек уходит только в
  журнал приложения.

## Границы

- Доступа из сети нет: только адрес устройства и `adb forward`. Loopback общий
  для всех приложений устройства — там защищает только токен. Зависит от
  возможностей ОС: жизнь процесса приложения.
- Нет ограничения частоты, срока жизни токена и прав по маршрутам: один токен
  — корень.
- MCP-обёртка над API (`§035F`) — отменена, не реализована.
- Граница аудита — ворота (default-off, bind, токен, хост); то, что видно за
  ними, — не находка.
