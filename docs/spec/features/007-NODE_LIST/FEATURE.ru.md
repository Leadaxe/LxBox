# FEATURE 007 — NODE_LIST — главный экран: список узлов, выбор, фильтры, порядок, папки

| Поле | Значение |
|------|----------|
| Тип | Продуктовая фича |
| Поглотила | `§003F` `§048F` `§070F` `§071F` `§234F` `§236F` `§565F` (фаза B `§565F` — задача 568) |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Назначение

Главный экран — место, где человек **видит, через что сейчас идёт трафик, и
меняет это одним нажатием**. Узлы показываются списком выбранного
**Направления** (selector-группы ядра); активный узел закреплён сверху; выбор
другого узла применяется в работающем ядре без перезапуска туннеля.

Вокруг списка — инструменты, чтобы в сотнях узлов найти нужный: фильтры
(регекс и эмодзи, протокол, транспорт/безопасность, источник, порог пинга,
detour), четыре режима сортировки и ручной порядок перетаскиванием. На экране
источников живут **папки** — контейнеры одиночных серверов с общим
выключателем и тестом «пачкой» без запуска VPN — и **свёртка** источника в
одну группу ручного или авто-выбора.

Принципы, которые фича защищает:

1. **Выбор узла — не правка конфига.** Переключение в Направлении идёт в
   живом ядре; туннель не перезапускается, конфиг не помечается изменённым.
2. **Служебное всегда видно и всегда на месте.** Direct, двойник автовыбора
   Направления, block и активный узел — наверху при любой сортировке;
   фильтр их не прячет.
3. **Вид не меняет маршрут.** Фильтры, сортировка, колонки и ручной порядок
   влияют только на отображение (и на порядок массового пинга); в конфиг
   ядра они не попадают и конфиг изменённым не помечают.

Откуда берутся узлы — [001-SUBSCRIPTIONS](../001-SUBSCRIPTIONS/FEATURE.ru.md);
пинг, URLTest и здоровье узла — [009-NODE_HEALTH](../009-NODE_HEALTH/FEATURE.ru.md);
правка узла — [008-NODE_EDITOR](../008-NODE_EDITOR/FEATURE.ru.md); статистика и
трафик — [012-LIVE_STATE](../012-LIVE_STATE/FEATURE.ru.md).

## Обещания

- **P1. Выбор узла применяется вживую.** Выбор другого узла в Направлении
  при поднятом туннеле уходит в ядро `SelectOutbound`, затем список
  подтягивает свежий снимок групп; туннель не перезапускается.
  Свидетель: юнит «выбор другой ноды идёт в ядро select-вызовом».
  Мутация: пересобирать конфиг на выбор узла.
- **P2. Повторный выбор активного узла — пустая операция.** Ядро не
  вызывается, соединения не рвутся. Свидетель: юнит «выбор уже
  активной ноды — no-op, событие „уже активен“». Мутация: убрать сравнение с текущим активным.
- **P3. Активный узел закреплён сверху.** При любой сортировке он стоит
  сразу после direct / двойников автовыбора / block и не дублируется, если
  сам служебный. Свидетель: юниты группы «§196 — активная нода пинится после
  direct/auto» (latency, A–Z, default, дубль, отсутствует в списке).
  Мутация: сортировать активный вместе с остальными.
- **P4. Служебные узлы наверху по типу, а не по имени.** Direct (тумблер
  «Pin DIRECT»), двойник автовыбора Направления (тумблер «Pin AUTO»), block —
  всегда; узел автовыбора подписки/папки остаётся на своём месте.
  Свидетель: юниты «§125 — auto-двойник пинится по типу urltest», «узел
  автовыбора §322 НЕ пинится», «block пинится при любой сортировке».
  Мутация: закреплять по литералу тега `direct-out`.
- **P5. Фильтр не прячет шасси.** Направления, их двойники, direct/block/dns
  видны при любом фильтре; узел автовыбора подписки фильтруется наравне с
  обычными. Свидетель: юниты «шасси видно при любом regex», «regex не по
  имени — авто-узел подписки уходит». Мутация: короткозамыкать все urltest.
- **P6. Категории фильтра складываются по И, внутри категории — по ИЛИ;
  `!` инвертирует категорию.** Неизвестный протокол/транспорт при активном
  фильтре не проходит; неизмеренный узел всегда проходит порог пинга; регекс
  без учёта регистра. Свидетель: юниты «фильтр: AND combine»,
  «unknown proto при active filter → false», «delay == null → true», «match —
  true (case-insensitive)». Мутация: считать непинговавшийся узел медленным.
- **P7. Принадлежность источнику — по префиксу тега.** Узел относится к
  подписке/папке, если его тег начинается с «префикс + пробел»; источник без
  префикса в фильтре не участвует; общий префикс даёт узел обоим.
  Свидетель: юниты «пустой префикс → НЕ участвует», «префикс без
  последующего пробела → НЕ матчит», «подписка и папка с одним префиксом →
  матчит обе». Мутация: сравнивать префикс без разделителя.
- **P8. Фильтр помнится за Направлением в пределах сессии.** Смена A→B→A
  возвращает фильтр A; detour-фильтр и «показывать несовпавшие» — общие.
  Свидетель: юниты «фильтр Направления A восстанавливается после A→B→A»,
  «detour/show-non-matching глобальны». Мутация: один фильтр на все
  Направления. Сброс при перезапуске приложения — `без свидетеля`.
- **P9. Ручной порядок живёт между режимами и перезапусками.** Уход из
  «Custom» порядок не стирает; новые узлы встают в конец, исчезнувшие
  выпадают; режим и порядок восстанавливаются после перезапуска и конфиг
  изменённым не помечают. Свидетель: юниты «новая нода → конец», «удалённая
  нода отфильтрована», «не-config сейверы (sort/ping) НЕ поднимают флаг»;
  переживание перезапуска — ручная проверка (Custom, перетащить, убить
  приложение, открыть — порядок тот же). Мутация: сбрасывать порядок при
  cycle.
- **P10. Две колонки только на широком экране и не в ручном режиме.**
  ≥ 600 dp и включённый тумблер — две колонки построчно; «Custom» — всегда
  одна. Свидетель: юниты «599 dp — одна», «600 dp — две», «ручная сортировка
  остаётся одноколоночной». Мутация: строгое `> 600`.
- **P11. Подсказка «Add a server» — по нулю серверов, а не по пустому
  файлу конфига.** Показывается при выключенном VPN, если нет ни одного
  реального узла ни в конфиге, ни в источниках. Свидетель: юниты «шаблонный
  конфиг без серверов → гайд», «окно „сервер добавлен, конфиг ещё не
  пересобран“ → без гайда», «туннель up → никогда». Мутация: вернуть
  предикат «конфиг пуст».
- **P12. Группа ручного рода остаётся selector с выбором.** Группа
  `selector` из подписки или папки уходит в ядро как `selector` с `default`;
  выпавший член снимает `default` (ядро берёт первого) одной строкой отчёта;
  выбор члена у группы подписки/папки сохраняется и переживает перезапуск.
  Свидетель: юниты «тело ядра: type selector, состав и default», «выпавший
  default снят, код один», «выбор у группы подписки хранится и накладывается
  на сборку». Мутация: сворачивать selector в urltest.
- **P13. Свёртка источника разворачивается по режиму.** `manual` — один
  selector, `auto` — urltest под тем же именем, `both` — `<tag>-auto` и
  selector с ним первым и по умолчанию; ноль узлов — групп нет, правила на
  свёртку уходят в `route.final`; имя, занятое Направлением, — источник не
  свёрнут. Свидетель: юниты сборки свёртки «both: автовыбор <tag>-auto, затем
  селектор», «ноль узлов: один replace_group_empty», «тег свёртки =
  Направление: источник не свёрнут». Мутация: писать пустую группу.
- **P14. Папка — один выключатель на всех.** Выключенная папка или член в
  конфиг не попадают; ввод сплитится на членов 1:1; «Keep servers» при
  удалении выносит членов одиночными. Свидетель: юниты «выключенная папка не
  эмитит ничего», «вход сплитится на членов 1:1», «удаление папки с Keep
  servers выносит членов одиночными». Мутация: хранить папку одним телом.
- **P15. Тест папки — отдельная сессия ядра, не при VPN.** При поднятом VPN
  тест не стартует (диалог «VPN is running» с «Stop VPN»); без VPN
  тестируются все члены, включая выключенных; битые получают вердикт до
  ядра. Свидетель: юниты «VPN запущен: маркер-гейт, боевое ядро не
  зовётся», «ВСЕ члены (включая выключенных) попадают в конфиг», «битые
  члены получают вердикт до ядра». Мутация: тестировать через боевое ядро.
- **P16. Результат теста привязан к узлу, а не к строке.** Удаление или
  перестановка соседа не переносит чужой результат. Свидетель: юнит «ключ не
  зависит от позиции: удаление соседа не двигает остальные». Мутация: ключ
  по индексу.
- **P17. Обрыв соединений при переключении — только по тумблеру.** При
  включённом «Interrupt connections on switch» после выбора узла живые
  соединения этого Направления закрываются; по умолчанию — нет.
  `без свидетеля`.

не больше 1 naive- и 4 WireGuard-записей на один запуск тестового ядра.

**Ключи и RPC ядра, которые фича отдаёт/использует:** outbound `selector`
(`outbounds`, `default`, у свёртки `interrupt_exist_connections: true`),
`urltest` (двойник `<tag>-auto`), `route.final` (стартовое Направление и
приёмник правил выпавшей свёртки). RPC: `SelectOutbound`, снимок и поток
групп, `CloseConnection` (обрыв при переключении), `URLTestOutbound` (тест
папки в отдельной сессии).

## Входы / Выходы

**Входы:** снимок групп ядра (теги, типы, члены, текущий выбор; только при
поднятом туннеле), собранный конфиг (типы узлов, транспорт/безопасность,
detour-связи), записи источников (префиксы, папки, свёртки, выбор членов
групп), замеры пинга, жесты пользователя.

**Выходы:** выбор узла в ядре; сохранённый выбор члена группы источника;
изменения папок и свёрток в источниках (→ пересборка конфига); порядок
массового пинга = порядок видимого списка; сохранённые режим сортировки и
ручной порядок.

## Data flow

```
снимок групп ядра ─► Направления (selector, без GLOBAL) ─► выбранное Направление
        │                                                      │
        └── члены + выбор ──► закреплённая секция ─► сортировка ─► detour-пул
                                                                  │
                    фильтр (регекс/протокол/вариант/источник/пинг) ┘
                                   │
                  совпавшие ─► (+ несовпавшие приглушённо | скрыты) ─► список
                                   │
       выбор узла ─► SelectOutbound ─► свежий снимок ─► ACTIVE
                                   └─► группа источника ─► запомнить выбор
```

Папки и свёртки идут другим путём: правка на экране источников →
[сборка конфига](../003-CONFIG_BUILD/FEATURE.ru.md) → новые группы в снимке ядра.

## Правила и гарантии

- Список узлов строится только из снимка ядра: при выключенном VPN узлов нет,
  вместо списка — «Tap to connect» или подсказка «Add a server».
- Пустой снимок групп поверх уже заполненного при живом туннеле
  игнорируется (шум гонки ядра); свайп вниз заново тянет снимок.
- Направление, исчезнувшее из снимка, заменяется `route.final`, иначе первым.
- Нажатие по строке только подсвечивает узел; выбор — кнопкой ▷ или
  «Use this node» в меню, и только при поднятом туннеле.
- Закреплённые строки не перетаскиваются, в них нельзя «уронить» строку.
- Перетаскивание в любом режиме переводит сортировку в «Custom».
- Фильтр, сортировка и колонки конфиг ядра не меняют.

## Особенности сопровождения

- **Узлы выбранного Направления — это члены selector-группы ядра**, а не
  список из источников. Всё, что не попало в группу (выключено, отбраковано,
  свёрнуто), на главном не видно — искать причину надо в сборке.
- **Принадлежность источнику восстанавливается по префиксу тега.** Без
  префикса подписки/папки фильтр по источникам к ней неприменим, её узлы
  попадают в «прочие». Синтетического чипа «Custom» больше нет.
- **Перетаскивание фиксирует видимый порядок.** Новый ручной порядок —
  ровно отображаемый список: совпавшие с фильтром впереди, скрытые фильтром
  узлы в него не входят и потом уходят в конец.
- **Режимы тумблеров закрепления и «Re-sort on manual ping» — на сессию**,
  а режим сортировки и ручной порядок — сохраняются. Разная долговечность
  соседних настроек в одной шторке — осознанна, но удивляет.
- **Выбор члена группы подписки при живом туннеле** не помечает конфиг
  устаревшим, но следующий старт VPN пересобирает конфиг — иначе выбор
  потерялся бы.
