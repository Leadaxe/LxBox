# §234 — Server folders (папки серверов)

> **СТАТУС: РЕАЛИЗОВАНО, device-verified** (04.07.2026, CPH2411,
> v2.10.2-dev.3+1092). Источник — фидбэк 4PDA (evgeny1503): N отдельных
> файлов-конфигов → N нод россыпью на вкладке серверов; хочется папки с
> общим вкл/выкл и переносом серверов между ними.
> Тесты: `test/subscription/folder_test.dart` (модель/операции/builder).

## Зачем

1. Юзер импортирует много одиночных конфигов (типовой случай — по одному
   файлу на сервер от провайдера) → плоская куча на вкладке серверов.
   Нужна **папка**: контейнер ручных серверов с общим toggle, именем и
   настройками на всех.
2. §129 (file-подписка) покрывает только «один файл с N нодами». Не покрыты:
   группировка уже добавленных одиночных серверов задним числом, импорт
   нескольких файлов разом, перенос серверов между контейнерами.
3. Заодно — мелкий QoL из того же фидбэка: при импорте из файла предлагать
   имя сервера по имени файла.

## Терминология (ЖЁСТКО)

- Новая сущность — **folder** (в UI и в коде). НЕ «group»: слово занято
  selector/urltest-группами ядра, а пользовательские выходы §125 зовутся
  **channels/каналы** — их «группами» не называть ни в UI, ни в коде.
- Папка ≠ канал: папка владеет **составом** нод, канал — **маршрутный выход**
  (фильтр по regex на итоговом tag'е). Они дружат через `tag_prefix` (ниже).

## Модель

Третий подтип sealed `ServerList` — `FolderServers`, `type: "folder"`:

| Поле | Откуда | Примечание |
|---|---|---|
| `id`, `name`, `enabled` | база `ServerList` | toggle всей папки = `enabled` (каскад, как у подписки) |
| `tag_prefix` | база | префикс тегов всех членов; синергия с каналами: prefix `proton-` + канал `node_filter: "^proton-"` → вся папка в канале |
| `detour_policy` | база | одна политика на всю папку (те же 5 полей) |
| `members[]` | **новое** | список членов, порядок = порядок в UI |

### `members[]` — состав папки

```jsonc
{ "raw": "<фрагмент>", "enabled": true }
```

- `raw` — самодостаточный парсируемый фрагмент: одна URI-строка ИЛИ целый
  WG/AWG-INI (многострочный). Именно поэтому НЕ один `rawBody` на папку —
  line-append/remove сломал бы INI. Объект вместо параллельных массивов
  `raw_bodies[]`+`disabled[]` — чтобы reorder/remove двигал член целиком.
- **member ↔ нода строго 1:1.** Если добавляемый фрагмент парсится в
  несколько нод (multi-line paste, файл с N URI) — сплитим на N членов в
  момент импорта. Инвариант упрощает всё: toggle, reorder, отображение.
- `enabled: false` → нода члена не эмитится в конфиг вообще (точечный
  аналог выключенного списка).
- `nodes` папки реконструируются parse'ом каждого включённого `member.raw`
  (тот же механизм, что `UserServer.rawBody` — re-parse при загрузке,
  члены не дублируются в сериализацию).

### Storage

Внутри существующего `server_lists[]` — просто новый `type`. Ни нового
top-level ключа, ни миграции: **§221 backup-симметрия не затрагивается**
(`server_lists` уже и в allowlist, и в export-категории). STORAGE.md —
дополнить раздел `server_lists` подтипом `folder`.

## Операции (полный согласованный список)

| Операция | Семантика |
|---|---|
| Create folder | пустая папка из меню добавления |
| Rename folder | правка `name` |
| Toggle папки | `enabled` — гасит/включает все члены разом |
| Delete folder | диалог: **Delete folder & servers** / **Keep servers** (члены выносятся в одиночные `UserServer`) |
| Add в папку | 4 пути: paste / QR / **файлы (multi-select!)** / URL-снапшот (ниже) |
| Toggle члена | `member.enabled` |
| Edit члена | правка `raw`-фрагмента и имени (имя = итоговый tag; rename меняет tag → влияет на `node_filter` каналов — как у любого сервера, известное поведение) |
| Move член → другая папка | член переезжает целиком |
| Ungroup члена | член → одиночный `UserServer` (`raw_body = member.raw`, `origin: manual`, дефолтные prefix/policy) |
| Move одиночный сервер → папка | `raw_body` становится `member.raw`, одиночная запись удаляется. **Личные `tag_prefix`/`detour_policy` отбрасываются — действуют папочные.** Это осознанный trade-off («настроил один раз на всех»), НЕ баг |
| Reorder членов | ручной drag внутри папки |
| Reorder папок | уже работает — папка = запись `server_lists` (§098) |

### Импорт по URL — одноразовый снапшот

Fetch → parse → ноды ложатся статичными членами. **Ни meta, ни auto-update;
URL не сохраняется.** В UI пометить: "Fetched once, won't auto-update".
Хочешь обновлений — создавай подписку. (Держит папку простой и не плодит
полуподписки.)

### Имя по имени файла (QoL, входит в фичу)

- Импорт файла в папку: имя члена (если у ноды нет своего `#fragment`-имени)
  = имя файла без расширения.
- Обычный импорт одиночного файла (≤1 нода, старый путь `addFromInput`):
  prefill имени сервера = имя файла без расширения.

## UX

Вкладка серверов, по образцу подписки (никаких вложенных секций):

```
[Folder tile]  (⌥ toggle)  Proton      10 nodes (2 off)
   тап → folder detail screen
```

**Folder detail** (зеркалит subscription detail):
- список членов: per-member toggle, long-press меню (Edit / Move to folder… /
  Ungroup / Delete), drag-reorder;
- кнопка Add (paste / QR / files / URL);
- вкладка Settings: name, `tag_prefix`, `detour_policy` — те же виджеты,
  что у подписки.

Одиночный сервер: long-press → **Move to folder…** (список папок + «New
folder…»).

## Инварианты

1. **Подписка не кладётся в папку; смешанных папок нет.** Подписка сама
   владеет составом (update перезаписывает `nodes`) — она уже контейнер.
   «Подписка + ручные серверы как одна маршрутная единица» = канал §125
   (общий префикс/regex), не папка.
2. **Вложенности нет.** Один уровень.
3. **Одиночный `UserServer` остаётся как есть** — папка опциональна,
   миграция не нужна.
4. **Builder концептуально не меняется**: `folder.build()` = итерация нод
   включённых членов (существующий `ServerListBuild`-контур); каналы
   фильтруют по итоговому tag'у как раньше.
5. Дедупликации членов нет (две одинаковые ноды — законно, как и сейчас
   два одинаковых сервера).

## Per-node toggle для подписок — ВНЕ скоупа

Механизм `member.enabled` здесь — только для папок. Точечное выключение нод
внутри подписки (старая боль «ручной выбор слетает после обновления») —
отдельная задача поверх идеи `disabled_tags[]` на `SubscriptionServers`:
там свои грабли (теги меняются при update → протухшие записи).

## Критерий готовности (сценарий с форума)

10 файлов по одному Proton-конфигу → multi-select → папка «Proton» с 10
членами (имена из файлов) → toggle папки гасит все 10 → канал ловит папку
по `tag_prefix`.

## Что НЕ делаем

- Вложенные папки; папки для подписок; подписка внутри папки.
- Авто-обновление URL-импорта (это подписка).
- Per-member override `tag_prefix`. (Per-member **detour** добавлен позже — §237: личный detour члена + политика папки поверх, тап по члену открывает полный Node Settings.)
- Дедупликация членов.
