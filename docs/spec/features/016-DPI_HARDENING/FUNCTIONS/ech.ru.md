# ECH (Encrypted Client Hello)

| Поле | Значение |
|------|----------|
| Фича | [016-DPI_HARDENING](../FEATURE.ru.md) |
| Обещания | P10 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

ECH прячет настоящий SNI в зашифрованной части ClientHello; DPI видит
только внешнее имя фронта. Приложение ECH **не включает само** и не
даёт для него переключателя: блок `tls.ech` доезжает до ядра, только
если его явно принёс JSON узла, а Xray-параметр ссылки `ech=`
отбрасывается с объяснением. Задуманная в §045F галка «Enable ECH» на
узле и разбор `?ech=1`/`?ech=<base64>` не реализованы.

## Параметры

| Вход | Что происходит | Ключ ядра |
|---|---|---|
| sing-box JSON `tls.ech{…}` | копируется как есть (объект), внутрь приложение не смотрит | `tls.ech` (`enabled`, `config`, `config_path`, `query_server_name`) |
| Xray-JSON `tlsSettings.echConfigList` | строки → `tls.ech.config`, `enabled: true` выводится | `tls.ech` |
| Ссылка `ech=<name>+<resolver>` или `ech=<name>` | не маппится; код `ech_ignored` (info) со значением `<name>` | — |
| Ссылка `ech=` пусто / `none` | ничего, кода нет | — |
| `echfq` | не читается | — |

## Входы / Выходы

**Входы:** JSON узла; параметры ссылки.
**Выходы:** `tls.ech{}` в outbound'е (порядок полей — как в структуре
ядра); код `ech_ignored` в уведомлениях узла.

## Правила и инварианты

- Почему `ech=` ссылки не применяется: Xray-форма несёт не ключ этого
  сервера, а имя публичного ECH-пробника, у которого надо спросить
  конфиг по DNS. Подписки кладут туда чужие имена (`ip.gs`,
  `encryptedsni.com`), их конфиг выдан для `public_name` другого фронта —
  рукопожатие с ним не состоится. Отката на обычный TLS у ядра нет,
  проверить пригодность до подключения нельзя. Замер: тот же узел с
  `ech` мёртв, без него — жив.
- `echfq` (pq-signature-schemes Xray) не читается: парная опция ядра
  снята и при `true` роняла бы конфиг.
- Не-объектный `tls.ech` в JSON отбрасывается молча; блок с
  `enabled: false` снимается.
- `tls.ech.enabled` конфликтует с `tls.reality.enabled`; у MASQUE ECH
  снимается (`masque_tls_field_ignored`); naive читает блок целиком.
- В ссылку при экспорте `ech` не пишется никогда.
- Остальное в узле (SNI, транспорт, REALITY) от наличия `ech=` не
  меняется.
- Отдельного гейта у mixed-case SNI для ECH-узлов нет: `server_name`
  такого узла рандомизируется, как у обычного TLS.

## Границы

- Глобального «ECH для всех» нет и не будет: сервер без поддержки ECH
  падает непонятной ошибкой рукопожатия.
- Авто-откат «ECH не прошёл → без ECH» ядро не даёт; приложение тоже.
- Сборка ECH в ядре — всегда (отдельного build-тега нет).
- `echConfigList` из Xray-JSON юнитом приложения не покрыт (есть только
  в корпусе контракта).
