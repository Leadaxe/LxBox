# Автоотключение узлов, отвергнутых ядром — VPN стартует и с битым узлом

Когда ядро sing-box отвергает конфиг из-за одного невалидного узла,
приложение выключает этот узел с причиной от ядра и поднимает VPN на
остальных.

| Поле | Значение |
|------|----------|
| Фича | [009-NODE_HEALTH](../FEATURE.ru.md) |
| Обещания | P14, P15, P16 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Ядро отказывается стартовать целиком, если хоть один узел конфига негоден.
По нажатию Start приложение распознаёт узел, названный в отказе, выключает
его тем же выключателем, что и пользователь, с дословной причиной ядра,
тихо находит остальных негодных и поднимает VPN на оставшихся.

## Параметры

| Параметр | Значение |
|----------|----------|
| Предел кругов до вопроса | 10 |
| Триггер | кнопка Start; Debug-старт с флагом страховки |

Пользовательских настроек нет.

## Входы / Выходы

**Входы:** текст отказа ядра на старте и на `checkConfig`; теги собранного
конфига; ответ человека на вопрос предела; отмена.

**Выходы:** выключенные узлы с предупреждением `core_rejected`
(`params.reason` — текст ядра без префикса); кнопка Start в фазе проверки —
«Checking servers… (%d disabled)» с отменой; плашка на главном; значок и
причина в списке узлов, в строке сервера и счётчик на строке
подписки/папки.

## Правила и инварианты

- **Дерево.** Старт принят → конец, ни одной проверки. Отказ не про узел
  (inbound, dns, route), без тега (ядро старше `lx.7`) или с тегом, которого
  нет в конфиге → обычная ошибка. Отказ называет узел → выключить → круги
  `checkConfig` без туннеля: назван новый узел → выключить и дальше; назван
  уже выключенный или ошибка не про узел → ошибка, конец; чисто → финальный
  старт. Отказ финального старта — ошибка; названный узел выключается, но
  третьего старта нет.
- **Разбор.** Строка `initialize <outbound|endpoint>[<i>] <type>[<tag>]:
  <text>` ищется в любом месте сообщения. Тег может содержать `]: `,
  поэтому кандидаты перебираются справа налево, побеждает первый,
  совпавший с тегом конфига. Индекс `<i>` для сопоставления не используется.
- **Тег → узел.** Для производных записей (хоп цепочки, член папки, WARP,
  узел подписки с префиксом) выключается исходный узел. «Тот же узел» —
  сравнение по ссылке на узел, не по тегу: тёзки `Dup`/`Dup-1` не обрывают
  цикл.
- **Предел.** После 10 кругов — вопрос «10 servers disabled — there may be
  more» с кнопками Stop / Keep checking. Keep checking снимает предел до
  конца этого Start; Stop и закрытие мимо кнопок — VPN не поднят,
  выключенные остаются выключенными. Отмена кнопкой или любой Stop в фазе
  проверки — тот же итог; круг доигрывает до конца.
- **Плашка.** «1 server disabled» / «%d servers disabled», до трёх имён и
  `+N more`, кнопка Show — список выключенных; тап по строке открывает детали
  узла на вкладке Diagnostics у уведомлений; удалённый узел — неактивная
  строка. Живёт до ×, Stop/Disconnected, следующего Start или перезапуска
  приложения. «Включить всё обратно» нет — ядро отвергло бы снова.
- **Вердикт привязан к телу.** То же тело (перезапуск, кэш, обновление с тем
  же телом) — держится. Тело изменилось (обновление подписки, правка
  пользователем, в т.ч. переименование) или старого тела нет — вердикт снят,
  узел включён, следующий старт проверит заново. Обновление ядра вердикты не
  снимает. Пользователь включил тумблер — вердикт снят.
- Узел, выключенный человеком (без вердикта), автоматика не трогает никогда.
- **Бэкап.** Вердикт и выключение страховкой в файл не пишутся; ручное
  выключение экспортируется. Импорт файла с вердиктом его отбрасывает.
- Ошибки времени работы (таймаут, пинг, отказ сервера) узел не выключают.
- Автозапуск, плитка, Intent API, переподключение и смена набора настроек
  стартуют без автоматики: отказ нового конфига ждёт Start.

## Границы

- Грамматики протоколов в приложении не дублируются: это второй эшелон после
  проверок реестра при разборе ([002-NODE_IMPORT](../../002-NODE_IMPORT/FEATURE.ru.md)).
- Тексты уведомлений и их группировка — [013-DIAGNOSTICS](../../013-DIAGNOSTICS/FEATURE.ru.md).
- Выключатели узлов — [001-SUBSCRIPTIONS](../../001-SUBSCRIPTIONS/FEATURE.ru.md).
- Зависит от возможностей ОС: старт туннеля без интерфейса — там вопросу
  предела некому показаться.
