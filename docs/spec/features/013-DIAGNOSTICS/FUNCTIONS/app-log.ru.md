# Журнал приложения

| Поле | Значение |
|------|----------|
| Фича | [013-DIAGNOSTICS](../FEATURE.ru.md) |
| Обещания | P1, P2, P3 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Хранит сообщения приложения и строки ядра в одном журнале с двумя
независимыми источниками (`app`, `core`), показывает их на вкладке Log экрана
Debug и отдаёт наружу — в дамп и в Debug API. Предупреждения и ошибки
сохраняются на диск и переживают перезапуск и падение процесса: видно, что
приложение делало перед смертью.

## Параметры

Своих настроек нет. Фиксированные значения:

| Что | `app` | `core` |
|-----|-------|--------|
| Записей в памяти | 300 | 500 |
| Сохраняется на диск | warning, error | warning, error |
| Потолок файла | 200 строк / 64 КБ | 200 строк / 64 КБ |

Уровни записей: `debug`, `info`, `warning`, `error`.

## Входы / Выходы

**Входы:** сообщения приложения (включая строки журнала запросов Debug API);
строки ядра — см. [журнал ядра](core-log.ru.md); сохранённые записи прошлой сессии.
**Выходы:** вкладка Log (фильтр источника All / Core / App, чипы уровней, поиск
по тексту без учёта регистра, Copy log, Clear); поле `debug_log` дампа;
`GET /logs`, `/logs/app`, `/logs/core`, `POST /logs/clear`, `GET /diag/applog`.

## Правила и инварианты

- Квота своя у каждого источника: переполнение вытесняет старейшую запись
  только своего источника.
- Смешанный вид — слияние по времени, новые сверху; вид одного источника —
  без слияния.
- Пустые и пробельные сообщения не записываются; текст обрезается по краям.
- На диск уходят только warning и error текущей сессии; после перезапуска они
  загружаются с пометкой «↑ prev session» (курсив, `prev_session: true` в дампе и
  `/diag/applog`). В файл снова попадают только записи новой сессии — как только
  в ней появится первое предупреждение, диск хранит уже её.
- Если первая же сохраняемая строка больше 64 КБ, она всё равно пишется: пустой
  файл хуже чуть превышенного.
- Битая строка сохранённого файла пропускается, остальные читаются.
- Clear очищает оба источника в памяти и на диске; `POST /logs/clear?source=…` —
  только один.
- Debug API: `limit` 1..1000 (по умолчанию 200), `source=app|core`, `q` —
  подстрока без учёта регистра, `level` — список через запятую; неизвестный
  источник или уровень — 400. Фильтры складываются по «И».
- `GET /diag/applog?prev=true|false|all` — только прошлая сессия, только текущая
  или всё.
- Экран обновляется не чаще ~60 раз в секунду, даже на потоке сотен строк ядра.

## Границы

- Настраиваемых квот и отдельных вкладок по источникам нет — намеренно.
- Потоковой выдачи журнала (SSE/WebSocket) в Debug API нет.
- Что и с каким уровнем приходит от ядра — [журнал ядра](core-log.ru.md).
- Зависит от возможностей ОС: запись в каталог приложения.
