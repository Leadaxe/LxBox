# Отчёты о сбоях — паники ядра, снимки памяти и причины завершения процесса

Заранее ничего включать не нужно: улики пишут ядро и ОС в момент сбоя.

| Поле | Значение |
|------|----------|
| Фича | [013-DIAGNOSTICS](../FEATURE.ru.md) |
| Обещания | P7, P8, P9 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Собирает улики о том, что ядро или процесс умерли, и отдаёт их пользователю
в один тап: отчёты о панике ядра (трейс, метаданные, конфиг на момент падения),
снимки памяти, которые ядро делает само при приближении к лимиту памяти, и
системные причины завершения процесса. После паники ядра главный экран один
раз предлагает поделиться отчётом.

## Параметры

Своих настроек нет. Фиксированные значения:

| Что | Значение |
|-----|----------|
| Архив отчётов о панике | 10 свежих |
| Архив снимков памяти | 5 свежих (снимок ~750 КБ) |
| Когда ротация | при каждом старте приложения |
| Причины завершения процесса | последние 5, Android 11+ |

## Входы / Выходы

**Входы:** текущий отчёт ядра `CrashReport-lxbox.log`; архив
`crash_reports/<время>/` (`go.log`, `metadata.json`, `configuration.json`;
ранние сборки — плоский файл); снимки `oom_reports/<время>/`; системная история
завершений процесса.

**Выходы:**
- плашка на главном «The core crashed last session — tap to share the report»;
- экран Debug, вкладка **Crashes**: список (время, размер, версия ядра или
  «current session»), просмотр трейса с копированием, share;
- вкладка **OOM**: список (время, размер, RSS), сводка «N snapshots · размер»,
  просмотр полей памяти и журнала ядра на момент снимка, share, «Delete all
  OOM reports» с подтверждением;
- Debug API: `/files/crash/list`, `/files/crash?name=`, `/files/local?name=
  CrashReport-lxbox.log[.old]`, `/files/oom/list`, `/files/oom?name=[&file=]`,
  `/diag/stderr` (текущий отчёт), `/diag/exit-info`;
- поля `stderr_log`, `crash_archive`, `oom_reports`, `exit_info` в
  [дампе](diagnostic-dump.ru.md).

## Правила и инварианты

- Пустой текущий отчёт — «паник не было» (ядро пересоздаёт его на каждом
  запуске); в список он не попадает. Каталог архива без `go.log` — не отчёт,
  не показывается.
- Список — новые сверху; архивные и текущий вместе.
- Share архивного отчёта отдаёт все файлы каталога, каждое имя с префиксом
  времени сбоя (в переписке `go.log` разных сбоев различимы); при неудаче —
  снекбар «Share failed».
- Плашка: показывается, если самый свежий отчёт не совпадает с отметкой
  «показано» (имя + время файла). Тап — share и отметка; закрытие — отметка.
  Отметка пишется в любом случае, даже если share сорвался.
- Ротация удаляет отчёт каталогом целиком; текущий отчёт не трогает; занятый
  файл пропускается без сбоя старта.
- Снимок памяти без `metadata.json` — недописан, не показывается; битый
  `metadata.json` — снимок виден с пустыми полями; размер снимка — весь каталог.
- `/files/*` отвергают имена с обходом пути и имена вне белого списка; нет
  архива — `[]`, а не ошибка.
- Причины завершения: время, причина (`CRASH`, `CRASH_NATIVE`, `ANR`,
  `LOW_MEMORY`, `SIGNALED`, `EXIT_SELF`, …), описание, память, код, трейс если
  система его приложила; на старых версиях ОС — пустой список.
- Вкладка Crashes есть всегда; пустая говорит «No crash reports» и что канал
  покрывает только паники ядра.

## Границы

- Нативные сбои вне Go, аборт из обратного вызова и убийство системой отчёта не
  оставляют: пустой отчёт рядом с системным «надгробием» — сам по себе вывод.
- Сброс кэшей ядра после падения —
  [010-VPN_SERVICE → восстановление](../../010-VPN_SERVICE/FUNCTIONS/recovery.ru.md).
- Для снимков памяти плашки нет: снимок штатен и внимания не требует.
- Зависит от возможностей ОС: история завершений (Android 11+), системный share.
