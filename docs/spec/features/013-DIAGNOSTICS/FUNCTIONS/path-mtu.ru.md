# Path MTU — наибольший пакет, который пропускает сеть пользователя

Замер у узла direct, мимо туннеля и без ядра.

| Поле | Значение |
|------|----------|
| Фича | [013-DIAGNOSTICS](../FEATURE.ru.md) |
| Обещания | P25 |
| Состояние | ✅ написана вместе с кодом, 2026-11-10 |

## Что делает

Отвечает на «всё висит» в сети, которая молча роняет крупные пакеты: чёрная
дыра оператора около 1280–1340 байт убивает туннели WireGuard / AWG / MASQUE с
MTU по умолчанию. Остров **Path MTU** на вкладке Diagnostics узла `direct`
шлёт ping-пакеты разного размера с запретом фрагментации по физической сети и
показывает наибольший IP-пакет, на который пришёл ответ, и MTU, который
ставить узлам-туннелям.

## Параметры

| Параметр | Значение |
|----------|----------|
| Цель | поле, по умолчанию `8.8.8.8`; IP или имя хоста (резолв через DNS физической сети, не туннеля) |
| Верхняя граница | MTU физического интерфейса; 1500, если система его не сообщила |
| Нижний пол | 576 (IPv4-цель) / 1280 (IPv6-цель) |
| Проба достижимости | 84 байта |
| Попыток на размер | до 2, таймаут 1 с; «не влезает в интерфейс» не повторяется |

## Входы / Выходы

**Входы:** поле Target, кнопка Run / Stop; физическая сеть (интерфейс,
транспорт, MTU).

**Выходы:**

| Что видно | Когда |
|-----------|-------|
| «Interface  wlan0 (Wi-Fi) · MTU 1500» | сразу, до запуска |
| «Path MTU N» + «Network drops packets above N» | режется что-то ниже MTU интерфейса |
| «Path MTU N» + «Nothing is cut on the way» | прошёл сам MTU интерфейса |
| «Recommended tunnel MTU»: WireGuard / AWG ≤ N − 60 (IPv6-цель: − 80), MASQUE ≤ N − 51 | при результате |
| «Path MTU below 576/1280» | не прошёл даже пол |
| «Target does not answer ping» | маленький пакет дважды без ответа; без чисел и рекомендации |
| «No network» | нет физической сети |
| «Probes (N)», свёрнуто: «размер · ok 38 ms / no reply / does not fit the interface» | после первой пробы; дописывается по мере прихода |
| Кнопка копирования | копирует отчёт текстом целиком, с пробами |

Debug API: `POST /action/pathmtu[?target=]` — тот же поиск, ответ JSON
([справочник](../../../../api/debug-api-reference.md)).

## Правила и инварианты

- Результат — размер **IP-пакета целиком**, не нагрузка ping.
- Работает при включённом и выключенном VPN: пробы идут через ICMP-сокет,
  привязанный к физической сети (и защищённый от туннеля, когда VPN поднят);
  системный `ping` не используется.
- Поиск: маленький пакет, затем MTU интерфейса (прошёл — конец), затем пол,
  затем бинарный поиск до разницы 1.
- Годится ответ любой длины (часть серверов обрезает эхо).
- Stop срабатывает между пробами; уход с экрана останавливает замер.
- Только у узла `direct`: через прокси-узлы ICMP не ходит.

## Границы

- Замер туда и обратно: ответ того же размера должен вернуться.
- Путь до цели может отличаться от пути до сервера узла — для этого поле Target.
- Always-on VPN с «Блокировать соединения без VPN» может запретить обход
  туннеля: результат — «Target does not answer ping».
- Замер через прокси-узлы и участки цепочек — не делается.
- HTTP-проверка над островом — [диагностика узла](../../009-NODE_HEALTH/FUNCTIONS/node-diagnostics.ru.md).
