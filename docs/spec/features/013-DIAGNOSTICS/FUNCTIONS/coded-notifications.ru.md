# Уведомления с кодами — сгруппированные сообщения с кодом, причиной и решением

Коды берутся из реестра контракта и не меняются между версиями.

| Поле | Значение |
|------|----------|
| Фича | [013-DIAGNOSTICS](../FEATURE.ru.md) |
| Обещания | P22, P23 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Показывает пользователю уведомления, у которых есть устойчивый код из реестра
контракта: что случилось, почему и что делать, — так, чтобы десяток однотипных
записей читался как одна. Отдельно — показывает системные уведомления, которые
присылает само ядро (например, «войдите по ссылке» для узла Tailscale), и
открывает их ссылку по тапу.

## Параметры

Своих настроек нет. Уровни уведомлений: `error` → «Errors», `warning` →
«Warnings», `info` → «Info»; порядок — от старшего.

## Входы / Выходы

**Входы:** уведомления узла с кодом, путём поля, значением и параметрами
(какие коды и когда получает узел — [009-NODE_HEALTH](../../009-NODE_HEALTH/FEATURE.ru.md));
уведомления ядра: канал, заголовок, текст, подзаголовок, ссылка, номер.

**Выходы:**
- один компонент на трёх поверхностях: раздел Notifications вкладки
  Diagnostics узла, шторка «Notifications» из списка узлов, шторка отказа ввода;
- строка под узлом в списке: заголовок кода старшего уровня, «+N more» по
  error и warning; только info — приглушённый значок без строки;
- ссылка **Details** на страницу кода в документации контракта
  (`…/docs/contract/warnings.ru.md#<code>`);
- Debug API: `GET /core_reject/notifications[?tag=]`, `GET /subs/{id}?warnings=true`
  — `{code, severity, path, value, params, title_en, text_en}`, тексты всегда
  на английском;
- системное уведомление ядра с действием «открыть ссылку»; строка
  `platform notification: <заголовок> (<ссылка>)` в журнале ядра.

## Правила и инварианты

- Шапка — счётчики по уровням (нулевых нет); они считают записи, а не группы.
  Подзаголовок уровня — только когда уровней больше одного.
- Внутри уровня записи одного кода (2 и больше) — одна плитка-группа: заголовок
  кода, число записей, по строке на запись (путь, иначе «Entry: <запись>», иначе
  текст; значение через ` = `), разбор и Details — один раз на группу.
- Подстановка в тексты группы (`path`, `value`, каждый параметр) — значение,
  если оно одинаково у всех записей, иначе `…`: разбор не приписывается одному
  случайному полю.
- Запись без кода и код, встреченный один раз, — обычная плитка. Порядок групп и
  плиток — по первому вхождению кода. Разные уровни в группу не сливаются.
- Код без текстов в реестре — заголовок из текста записи, без блоков разбора.
- Секретные значения маскируются и в строке записи, и в текстах группы.
- Единственная плитка открыта сразу; несколько — свёрнуты, тап раскрывает.
- Уведомление ядра: канал создаётся по его идентификатору (без него — общий
  канал ядра), высокая важность, закрывается тапом; повтор с тем же номером
  заменяет прежнее; отмена ядром снимает его. Без ссылки — уведомление без
  действия.

## Границы

- Сводки «код → список узлов» по всей подписке нет — решение владельца.
- Какие уведомления получает узел, проверки узла, автоотключение отвергнутых
  ядром — [009-NODE_HEALTH](../../009-NODE_HEALTH/FEATURE.ru.md).
- Без разрешения на уведомления системное уведомление не видно; ссылка всё
  равно доступна в журнале ядра.
- Зависит от возможностей ОС: каналы и разрешение уведомлений, открытие ссылки
  внешним приложением.
