# Живые события — запись сетевых событий всех приложений для разбора

Это та же запись, что и [028-TRAFFIC_PROFILER](../../028-TRAFFIC_PROFILER/FEATURE.ru.md),
описанная здесь как инструмент диагностики.

| Поле | Значение |
|------|----------|
| Фича | [013-DIAGNOSTICS](../FEATURE.ru.md) |
| Обещания | P20, P21 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Записывает по явной команде все сетевые события устройства — открытие и
закрытие TCP/UDP-соединений, DNS-ответы и отказы — с приложением-владельцем и
цепочкой маршрутизации каждого события. Отвечает на вопрос «что вообще
происходит на устройстве сейчас», когда неизвестно, какое приложение виновато.
Вкладка **Profiler** экрана Stats и маршруты `/profiler/live*` Debug API.

## Параметры

| Настройка | Где | Значения | Дефолт |
|-----------|-----|----------|--------|
| Live retention window | Profiler → значок истории | 1m / 10m / 1h | 10m |

Фиксированные значения:

| Что | Значение |
|-----|----------|
| Потолок буфера | 20 000 событий |
| Буфер событий без владельца | 50 |
| Плашка «без владельца» | больше 5 за 30 с |
| Плашка «DNS failing» | окно 30 с, отказов ≥ 20 % и ≥ 3, при живой связи |
| Перерисовка списка | не чаще раза в 700 мс |

## Входы / Выходы

**Входы:** START/STOP в шапке вкладки или `POST /profiler/live/start|stop`;
поток соединений и поток DNS-запросов ядра.
**Выходы:**
- шапка «Recording system-wide events · мм:сс · N events» / «Not recording»;
- общий обозреватель событий (Live / Aggregated, фильтр по приложениям, типам,
  тексту; пауза; детали события);
- экспорт «Share N events (JSON)» / «Copy JSON to clipboard»;
- плашки «N unattributed events / 30s …», «N% of DNS queries failing while the
  connection is alive — tap to fix» (лист-подсказка с «Open DNS settings» и
  «Enable FakeIP»), «DNS / router events off» при выключенной пересылке журнала
  ядра;
- Debug API: `/profiler/live?seconds=N` (по умолчанию 60), `/profiler/live/state`,
  `/profiler/live/stream` (SSE), `/profiler/live/unattributed`.

## Правила и инварианты

- Без START ничего не пишется и не подписывается; STOP замораживает буфер
  (список остаётся), новый START его очищает.
- Запись идёт и при уходе с вкладки и сворачивании приложения — до STOP или
  смерти процесса.
- Окно хранения меняется на лету и сохраняется; старые события подрезаются
  при следующей чистке. Буфер сверх потолка теряет старейшие.
- Каждое событие несёт уровень уверенности в владельце (`verified`,
  `secondary`, `inferred`, `unattributed`) и цепочку маршрутизации
  (`routingLine`, `outboundChain`, `detourChain`).
- Успешные DNS-ответы без владельца плашку «без владельца» не зажигают — только
  отказы и соединения без владельца.
- «DNS failing» не зажигается при простое: без активности соединений в окне
  отказы не считаются поломкой.
- Фильтр вкладки живёт всю сессию приложения и переживает переходы между
  экранами.
- Перерисовка отстаёт от потока не больше чем на 700 мс; события при этом не
  теряются — копятся в буфере.

## Границы

- Список соединений, трафик, статистика и статус — 012-LIVE_STATE.
- Исторических сессий по отдельному приложению нет (снято, §288): разбор
  одного приложения — фильтром.
- Зависит от возможностей ОС: определение приложения-владельца соединения
  (на части версий ОС для коротких соединений не успевает).
