# Профилирование ядра — pprof-снимки живого ядра sing-box

Снимки снимаются только при поднятом туннеле.

| Поле | Значение |
|------|----------|
| Фича | [013-DIAGNOSTICS](../FEATURE.ru.md) |
| Обещания | P24 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Снимает с живого ядра стандартные pprof-снимки — стеки горутин, CPU-профиль,
кучу, аллокации — и отдаёт их файлом через системный share или по Debug API.
Нужен для жалоб «телефон греется», «ядро съело память», «зависло»: снимок
делается на устройстве пользователя в момент проблемы, без сборки отладочной
версии.

## Параметры

Своих настроек нет. Набор снимков на вкладке **Profiling** экрана Debug:

| Кнопка | Что снимается | Формат |
|--------|---------------|--------|
| Capture Goroutines (summary) | `goroutine?debug=1` | текст |
| Capture Goroutines (full stacks) | `goroutine?debug=2` | текст |
| Capture CPU profile (10s) | `profile?seconds=10` (блокирует на 10 с) | `.pb` |
| Capture Heap (inuse_space) | `heap?gc=1` | `.pb` |
| Capture Allocations | `allocs` | `.pb` |

Debug API: `GET /diag/pprof?profile=P&query=Q`, `P` — `goroutine` |
`profile` | `heap` | `allocs` | `block` | `mutex` | `threadcreate` (по умолчанию
`goroutine`); `query` — сырой pprof-запрос; по умолчанию `debug=2` / `seconds=10`
/ `gc=1` / пусто. Длительность CPU-профиля ограничена 1..60 с.

## Входы / Выходы

**Входы:** нажатие кнопки или запрос API; живое ядро.
**Выходы:** файл снимка с отметкой времени в имени (без двоеточий) через
системный share; текст для `goroutine?debug=…`, иначе бинарный `.pb` для
`go tool pprof`; подсказка на экране, как открыть бинарный профиль.

## Правила и инварианты

- Без поднятого туннеля снимок не снимается: «VPN must be running to capture a
  profile.»
- Одновременно идёт один снимок: остальные кнопки неактивны, у блокирующего
  CPU-профиля — индикатор и «Profiling for 10s…».
- Сервер снимков внутри ядра поднимается на адресе устройства только на время
  одного запроса (первый свободный порт из 6060..6065) и сразу гасится: в
  обычной работе ничего не слушает.
- Пустой ответ — «Profile was empty (timeout?).»; ошибка — «Capture failed: …».
- Неизвестный профиль в API — 400 со списком допустимых.
- Стеки горутин при живом туннеле также попадают в
  [дамп](diagnostic-dump.ru.md); CPU-профиль — нет.

## Границы

- При полной блокировке рантайма ядра сервер снимков не ответит — снимок
  упрётся в срок; цель канала — «ядро крутится вхолостую», а не взаимоблокировка.
- Снимки памяти, которые ядро делает само при давлении памяти, —
  [отчёты о сбоях](crash-reports.ru.md).
- Зависит от возможностей ОС: системный share.
