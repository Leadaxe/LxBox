# Дамп диагностики

| Поле | Значение |
|------|----------|
| Фича | [013-DIAGNOSTICS](../FEATURE.ru.md) |
| Обещания | P10, P11 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Одной кнопкой собирает всё, что нужно для разбора жалобы, в один JSON-файл и
открывает системный share: пользователь отдаёт один файл, разработчику не нужно
просить «ещё вот это».

## Параметры

Своих настроек нет. Точки входа: значок **Share dump** на экране Debug и
`GET /diag/dump` (тот же файл). Фиксированные значения:

| Что | Значение |
|-----|----------|
| Хвост системного журнала | 1000 строк уровня Error и выше, срок 2 с |
| Тело отчёта о панике в дампе | до 64 КБ, обрезанное помечено `truncated` |
| Тела снимков памяти | только 5 свежих; остальные — сводка |
| Имя файла | `lxbox-dump-<ГГГГ-ММ-ДДTчч-мм-сс>.json` |

## Входы / Выходы

**Входы:** сохранённый конфиг ядра; переменные настроек; источники узлов;
[журнал](app-log.ru.md); [отчёты о сбоях](crash-reports.ru.md); хвост системного
журнала своего процесса; стеки горутин живого ядра.

**Выходы:** JSON со полями:

| Поле | Что |
|------|-----|
| `generated_at`, `app` | время сборки, `lxbox` |
| `app_version`, `app_build`, `core_version` | чем снят дамп |
| `vars` | все переменные настроек |
| `server_lists` | записи источников + теги и число узлов (без полных узлов) |
| `config` | сохранённый конфиг ядра |
| `debug_log` | журнал обоих источников, `prev_session` у записей прошлой сессии |
| `stderr_log` | текущий отчёт о панике или `null` |
| `crash_archive` | архивные отчёты с телами |
| `oom_reports` | сводка снимков; у 5 свежих — все файлы |
| `exit_info` | причины завершения процесса |
| `logcat_tail` | хвост системного журнала своего процесса |
| `goroutines_stack` | стеки горутин, только при поднятом туннеле |

## Правила и инварианты

- Каждое поле собирается best-effort: недоступный канал даёт `null`/пустой
  список, дамп всё равно собирается.
- Файлы снимка памяти: текстовые (`metadata.json`, `connections.json`,
  `configuration.json`, `go.log`, `cmdline`) — как есть; бинарные профили и
  незнакомые файлы — `gzip+base64` с исходным размером; `go.log` сверх лимита —
  хвост и флаг обрезки.
- Источники берутся в том виде, в каком их видит интерфейс (с разобранными
  узлами); если интерфейс ещё не поднят — из хранения.
- Хвост системного журнала: только свой процесс, фильтрация — системой, без
  особого разрешения; через `/diag/logcat?count=50..5000&level=V|D|I|W|E|F`
  можно взять больше.
- Пока дамп собирается, кнопка показывает прогресс и повторно не жмётся;
  ошибка — снекбар «Share failed: …».

## Границы

- CPU-профиль в дамп не входит — он снимается отдельно, см.
  [профилирование](core-profiling.ru.md).
- Дамп не маскирует содержимое: конфиг с ключами, адреса подписок и
  переменные уходят как есть (см. отчёт о расхождениях).
- Зависит от возможностей ОС: доступ к системному журналу своего процесса,
  история завершений (Android 11+), системный share.
