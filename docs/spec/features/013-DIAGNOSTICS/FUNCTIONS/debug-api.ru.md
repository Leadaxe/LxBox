# Debug API

| Поле | Значение |
|------|----------|
| Фича | [013-DIAGNOSTICS](../FEATURE.ru.md) |
| Обещания | P12–P19 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Локальный HTTP-сервер на устройстве, через который разработчик с хоста (по
`adb forward`) читает всё состояние приложения и меняет его без экрана: для
разбора жалоб, автотестов и экспериментов с конфигом. Полный перечень
маршрутов — контракт в
[`docs/api/debug-api-reference.md`](../../../../api/debug-api-reference.md) и
в самом сервере (`GET /help`).

## Параметры

| Настройка | Где | Значения | Дефолт |
|-----------|-----|----------|--------|
| Debug API | App Settings → Diagnostics → Developer | вкл/выкл | выкл |
| Port | там же | 1024..49151, иначе ошибка под полем | 9269 |
| Token | там же, Copy / Regenerate | 32 hex (128 бит) | создаётся при первом включении |
| Lock config (debug) | там же, только при включённом API | вкл/выкл | выкл |

Фиксированные значения: адрес `127.0.0.1`; срок обработки запроса 30 с; тело
запроса до 1 МиБ.

## Входы / Выходы

**Входы:** HTTP-запросы на `127.0.0.1:<port>`.
**Выходы:** JSON (`application/json; charset=utf-8`), текст или файл. Записи
отвечают `{"ok":true,"action":"…",…}`; ошибки — `{"error":{"code","message"}}`.

| Группа | Что можно |
|--------|-----------|
| `/ping`, `/help` | проверка жизни; карта API (`?format=json`) — без токена |
| `/state*`, `/device`, `/pool` | прочитать состояние, хранение (со скраббером), устройство и версии |
| `/config*` | прочитать сохранённый и работающий конфиг; `PUT /config` — заменить сохранённый |
| `/logs*`, `/diag/*`, `/files/*` | журналы, дамп, причины завершения, системный журнал, отчёты, снимки, pprof |
| `/action/*` | старт/стоп/переподключение туннеля, URLTest, пересборка, сброс сети и др. |
| `/rules`, `/subs`, `/nodes`, `/directions`, `/chains`, `/folders`, `/warp`, `/settings/*`, `/wifi_history`, `/backup/*` | чтение и CRUD доменов теми же путями, что у интерфейса |
| `/core_reject/*`, `/profiler/*`, `/support/*` | наблюдать и вести страховку старта, запись событий, ленту поддержки |

## Правила и инварианты

- Порядок проверок: имя хоста → токен → срок. Host не `127.0.0.1`/`localhost`
  (порт в заголовке игнорируется, регистр тоже) — 403 `invalid_host`; нет
  точного `Authorization: Bearer <token>` — 401 `unauthorized`; дольше 30 с —
  504 `timeout`.
- Коды ошибок стабильны: 400 `bad_request`, 401, 403, 404 `not_found`, 409
  `conflict` (нет предусловия: туннель не поднят и т. п.), 413
  `payload_too_large`, 502 `upstream_error`, 504, 500 `internal` (детали — в
  журнале приложения, не в ответе).
- Включение без токена создаёт токен; Regenerate делает старые команды 401;
  смена порта или токена перезапускает сервер; занятый порт — ошибка в журнале,
  не сбой приложения.
- Выключение API снимает Lock config: иначе блокировку нечем было бы снять.
- Lock config: пересборка конфига из настроек тихо пропускается — ручной
  `PUT /config` живёт до снятия блокировки.
- Ключи `debug_enabled` / `debug_port` / `debug_token` через `/settings/vars`
  не пишутся (409); экспорт бэкапа по умолчанию их не включает; импорт с
  заменой, где их нет, сохраняет текущие.
- Снимок хранения маскирует токен (`***`), адреса подписок — маской, снимается
  `?reveal=true`; `/config` отдаёт секреты как есть — намеренно.
- Каждый запрос пишется в журнал приложения: метод, путь, запрос, статус,
  время; значения ключей с `token`/`secret`/`auth`/`key` — `***`; 5xx —
  warning, остальное — debug.
- Любая запись принимает `?rebuild=true` — пересборка конфига после записи
  (`rebuilt`, `config_bytes` или `rebuild_error` в ответе).
- Сервер работает, пока жив процесс приложения; поднимается при открытии
  главного экрана.

## Границы

- Доступа из сети нет: только адрес устройства и `adb forward`.
- Loopback общий для всех приложений устройства — защищает только токен.
- MCP-обёртка над API (`§035F`) — отменена, не реализована.
- Маршрутов Clash API больше нет (§122) — 404.
- Зависит от возможностей ОС: жизнь процесса приложения.
