## Мотив

Оператор: «directions — более верный термин, каналы используются в сетевой
терминологии по-другому» и «directions — более свежая замена Channel, надо
провести рефакторинг на мобиле как на лаунчере».

Направление (Direction) — именованная точка выбора маршрута, на которую
ссылаются правила. `Channel` LxBox уже почти совпадает с канонической формой
(`contract/schema/direction.schema.json`): label / enabled / nodeFilter
(тело regex) / nodeFilterInvert / defaultFilter / includeDirect /
includeBlock / auto. Не хватает:

1. **произвольные теги** — сейчас жёстко `vpn-1..vpn-10` (`kMaxChannels`,
   `channelNumberOf` в `app/lib/models/channel.dart:19-31`);
2. **include[]** — другие Направления опциями селектора (в лаунчере
   разрешены только стоящие ВЫШЕ по списку — циклы исключаются порядком);
3. сам термин в коде и UI.

## Как лаунчер решает то же самое (референсы)

- Модель: `core/config/configtypes/types.go` — `Direction`, `SourceChain`,
  `ChainStripKeys/Default`.
- Бэкап направлений: `core/backup/directions.go` — export MERGED-телом,
  import ПЕРВЫМИ (цели пополняются до разбора правил), занятый тег → не
  применяется с warning; правило на несуществующую цель — выключено.
- Цепочка узлом: `core/config/chain_nodes.go` (разрешение ПОСЛЕ загрузки
  всех источников; ссылка только на цепочку ВЫШЕ по списку), эмиссия
  `chain_generator.go` (ChainOutboundObject), инварианты ядра
  (`protocol/chain/chain.go:85-100`): ≥2 позиций, без пустых/дублей/само-
  ссылки; вложенная цепочка только позицией 0; каталог strip закрыт.
- Проба ядра: launcher `core/core_chain_capability.go` по тегам сборки; на
  мобиле тегов не видно — гейт по `Libbox.version()` ≥ 1.14.0-lx.27-rc.5.
- Детур в цепочке (проверено на ядре): позиция 0 — свой detour РАБОТАЕТ
  (путь длиннее показанного, предупреждение); позиции ≥1 — detour
  перезаписывается безусловно (`protocol/chain/transform.go:110`), справка.

## Диагностика цепочек — факты от ядра (sing-box-lx, 24.08.2026, по коду rc.6)

- **Тег-схема `<chain>#<i>` — контракт ядра** (SPEC 073 строки 27, 83–84 +
  шапка `protocol/chain/chain.go`): хоп i адресуем по тегу, Start-время
  резервирует имена. Послойная проба мобилы/лаунчера опирается на это законно.
- **`context deadline exceeded` на dial через хоп = 15s-потолок** netstack-dial
  WG (SPEC 052). Не «висит вечно», а «SYN/хендшейк не прошли за 15s».
- **Глухое окно ≤ ~30s**: тихая смерть UDP-пути (NAT-флап qemu / протухший
  NAT CF-egress) не даёт ошибок; предохранитель — QUIC idle 30s → teardown →
  передозвон на свежем сокете. Dial'ы в окне ловят свой 15s-deadline.
  idle-механики (masque idle-suspend, chain idle_timeout) причиной deadline'ов
  НЕ являются: восстановление быстрое и логируемое, WG переживает
  пересоздание несущего без ре-хендшейка (роуминг).
- **Что грепать** (scope-логгеры `chain[<tag>]#<i>/<leaf>`):
  masque: `idle-suspend tunnel after`, `h3 tunnel established`, `tunnel … failed`;
  wg (Debug, lowercase): `handshake did not complete after 5 seconds, retrying`,
  `…giving up`, ClientBind `connect to server:` / `read packet:`;
  цепочка: `clone created:` / `clone evicted: … (idle)`.
  Дискриминатор: WG-ретраи при тишине masque = путь глух ниже WG (NAT по
  внутреннему потоку); тишина везде + через ~30s `tunnel failed` = тихая
  смерть QUIC-пути; `idle-suspend`/`evicted` рядом = холодный старт, не сбой.
- **Конфиг-дискриминатор NAT-гипотезы**: `persistent_keepalive: 25` у WG-узла;
  исчезли deadline'ы → NAT-таймаут, нет → лосс датаграмм.
- **Проба греет слои**: интервал автопробы < min(masque idle, chain idle,
  ~30s NAT-окна) прячет холодные старты целиком.
- **Раскладка UDP-хопов — УТОЧНЕНО ядром (SPEC 074, vhttp)**: первая версия
  правила («UDP-туннели только входными хопами») была избыточно строгой.
  Точная картина:
  - `MASQUE via VLESS: deadline` СТАБИЛЬНО = сигнатура дефолта `vhttp: h3`
    (фиксированный h3 шлёт QUIC-датаграммы через TCP-хоп без бюджета
    хендшейка — «unbounded handshake», outbound.go:136). ЛЕЧЕНИЕ ШТАТНОЕ:
    `vhttp: auto` — h3-нога с бюджетом 3s, фолбэк на h2=TCP (через VLESS
    работает), победитель запоминается на процесс. Ограничение: h2-нога
    только у profile: warp; на standard auto деградирует в h3-only с Warn.
  - WG — UDP-only, альтернативной ноги нет: «за TCP-хопом нужен сервер с
    реальным UDP-проксированием» остаётся верным. Причём negative-ack в
    VLESS НЕ существует (dial «успешен» сразу после TCP+REALITY; сервер
    либо проксирует, либо молча дропает — частый кейс: Xray умеет,
    egress-firewall режет) — детектора «сервер не умеет UDP» нет и не
    построить; auto-фолбэк = лучший доступный дискриминатор.
  - Статическая Start-валидация network-совместимости соседних позиций НЕ
    поможет: VLESS честно объявляет Network()=[tcp,udp], проблема на
    сервере. В ядро не просить.
  Подсказка формы (кандидат): MASQUE позицией ≥1 → рекомендовать
  `vhttp: auto`; WG позицией ≥1 за TCP-хопом → предупреждение про
  UDP-проксирование сервером.
- Ядро добавит (по кивку владельца): Warn-строки причин смерти пампов masque
  (сейчас умирают молча) и комментарий-якорь у `hopTag()`.
