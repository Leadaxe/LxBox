# Процесс перевода — добавление строки или языка и четыре проверки CI

Добавить язык в LxBox — это один словарь интерфейса, один оверлей шаблона,
один файл нативных строк и несколько объявлений; добавить строку — один
английский литерал в коде и по записи на язык. Четыре проверки идут в строгом
режиме на каждый push и роняют сборку на всём неполном.

| Поле | Значение |
|------|----------|
| Фича | [029-LOCALIZATION](../FEATURE.ru.md) |
| Обещания | P13, P14, P15 |
| Состояние | ✅ написана по коду, 2026-09-29 |

## Что делает

Держит код и файлы каждого языка полными друг относительно друга. Процедура
разработчика зафиксирована (`docs/l10n.md`), а проверки находят языки по
каталогам, поэтому новый язык под гейтами с момента появления его файлов.

## Параметры

Пользовательских настроек нет. Режимы проверок: обычный (предупреждения) и
`--strict` (CI: каждое предупреждение — падение). Базовая линия
захардкоженных строк пуста; `--write-baseline` переписывает её для хотфикса в
том же файле.

| Проверка | Смотрит на | Падает на |
|----------|------------|-----------|
| словарь интерфейса | каждый вызов локализатора в коде против `ui.json` каждого языка | отсутствующий ключ, осиротевший ключ, неиспользуемая особая форма (strict); ключ, вызываемый и просто, и во множественном числе, неверная форма значения, неполный набор форм, индекс особой формы, которого нет в словаре, набор подстановок, отличающийся между ключом и переводом или между формами (всегда) |
| оверлей шаблона | отображаемые тексты, извлечённые из `wizard_template.json`, против `template.json` каждого языка | неизвестный ключ, пустое значение, значение с `@` в начале или `{` (всегда); непереведённый текст (strict) |
| захардкоженные строки | строковые литералы в отображаемых позициях: текстовые виджеты, подсказки, подписи, зарегистрированные хелперы снэкбаров и диалогов, включая каждую ветвь тернарника или switch | любой отображаемый литерал без исключения (базовая линия пуста); литерал без букв игнорируется |
| нативные строки | вызовы уведомления, тоста, ярлыка, плитки и stop-alert и подписи манифеста в нативном коде; `strings.xml` каждого языкового каталога против английского | литерал в нативном отображаемом вызове, подпись без ресурса, отсутствующий или осиротевший ключ, отличающийся набор подстановок `%n$s` |

## Входы / Выходы

**Входы:** код, `wizard_template.json`, словари и оверлеи каждого языкового
каталога, нативные строки каждого языкового каталога, реестр хелперов и
allowlist машинных поверхностей.
**Выходы:** зелёный проход или список находок по видам; красная сборка при
находке в строгом режиме.

## Правила и инварианты

- Новая строка интерфейса: написать английский литерал в месте показа, затем
  добавить запись с теми же подстановками под этим текстом в `ui.json`
  каждого языка. Отсутствующая запись в рантайме падает в английский, а в CI
  роняет проверку для этого языка.
- Правка английского текста переименовывает ключ: старая запись становится
  осиротевшей, новая — отсутствующей на каждом языке, пока словари не
  догонят. Отображаемые тексты шаблона работают так же; шага регенерации нет,
  проверка извлекает ключи из шаблона на каждом запуске.
- Новый язык от начала до конца: (1) словарь интерфейса со всеми ключами,
  которые проверка перечисляет как отсутствующие, множественное число в
  формах языка, (2) оверлей шаблона со всеми извлечёнными отображаемыми
  текстами, (3) файл нативных строк со всеми переводимыми ключами, (4) язык в
  объявлении локалей Android 13+, в списке поддержанных и в трёх валидаторах,
  которые иначе сбросят настройку в System default, плюс таблица форм
  множественного числа в проверке, (5) эндоним в переключателе языков с
  пометкой исключения, (6) объявление каталога ассетов, чтобы файлы попали в
  сборку, затем четыре проверки в строгом режиме и тесты локализации. Правило
  множественного числа нового языка добавляется в одном месте для рантайма и
  зеркалится в проверке.
- Каждый словарь, который приложение объявляет, обязан загружаться и
  разбираться; тест загружает каждый оверлей шаблона из сборки, а словари
  интерфейса тесты загружают целиком.
- Машинные поверхности: английский рендер разрешён только в модельных типах и
  в перечисленных модулях машинных поверхностей (автоматизация, Debug API,
  сборка конфига, контроллеры главного экрана и подписок); в другом месте он
  роняет проверку. Экран, читающий тексты шаблона один раз при создании, тоже
  роняет проверку — тексты перечитываются при каждой смене языка.
- Хелпер снэкбара или диалога с отображаемым параметром регистрируется для
  проверки захардкоженных строк; незарегистрированный хелпер — дыра.
- Динамический ключ (переменная, интерполяция) считается, но не проверяется.
- Путь хотфикса: переформулировка существующего литерала сохраняет число
  сайтов файла; базовая линия запрещает рост, а не изменения.

Чеклист перед push: английский литерал в месте показа · в `ui.json` каждого
языка есть запись с теми же подстановками · у множественного числа есть все
формы каждого языка · контекстный вариант использует особый индекс, и он есть
в словаре · отображаемый текст шаблона есть в каждом `template.json` ·
нативный текст есть в каждом `strings.xml` · исключения несут причину ·
четыре проверки проходят в строгом режиме · тесты локализации проходят.

## Границы

- Ни памяти переводов, ни машинного перевода, ни внешнего сервиса; переводы
  правятся руками в репозитории.
- Проверки читают код статически: строка, попадающая в виджет через
  переменную, хелпер, неизвестный реестру, или нативный вызов вне
  перечисленных шаблонов не видна (известные случаи — в Особенностях
  сопровождения фичи).
- Сама задача CI — [023-BUILD_CI_RELEASE](../../023-BUILD_CI_RELEASE/FEATURE.ru.md).
