# Английский как ключ — словари, подстановки, множественное число и английский fallback

В LxBox нет идентификаторов строк: английский текст, написанный в коде, и
есть ключ перевода, каждый другой язык — словарь `ui.json` с этим текстом в
роли ключа, а всё, чего в словаре нет, показывается по-английски.

| Поле | Значение |
|------|----------|
| Фича | [029-LOCALIZATION](../FEATURE.ru.md) |
| Обещания | P7, P8, P9, P10, P11 |
| Состояние | ✅ написана по коду, 2026-09-29 |

## Что делает

Превращает английский текст с аргументами в текст активного языка: ищет
английский текст в словаре языка, выбирает форму множественного числа или
особую форму, подставляет значения, а если любой шаг не удался — печатает
английский текст с той же подстановкой. Та же модель покрывает отображаемые
тексты шаблона конфига через оверлей по языку.

## Параметры

Пользовательских настроек нет. Контракты:

| Файл | Форма | Примечания |
|------|-------|------------|
| `assets/l10n/<tag>/ui.json` | плоская карта: английский текст → `{"value": …, "special": {"N": {"value": …}}}` | `value` — строка или объект множественного числа с формами языка |
| `assets/l10n/<tag>/template.json` | плоская карта: английский отображаемый текст → `{"value": "…"}` | только простые строки; `@…` и `{` отвергаются |
| `<tag>` | `ru`, `zh` | файла `en` нет: английский живёт в коде и в шаблоне |

Формы множественного числа: русский `one`/`few`/`many`/`other` (CLDR),
английский `one`/`other`, китайский — только `other`. Сегодня: 1703 ключа
интерфейса на язык, из них 81 множественное число и 8 особых форм; 219 ключей
шаблона.

## Входы / Выходы

**Входы:** английский текст, необязательный индекс особой формы, аргументы
(для множественного числа первым — счётчик); словарь активного языка;
декодированный шаблон и его оверлей.
**Выходы:** отображаемый текст; локализованный шаблон до разбора; английский
рендер того же объекта для машинных поверхностей.

## Правила и инварианты

- Поиск: словарь → запись по английскому тексту → форма 0 — корневой
  `value`, форма N ≥ 1 — `special["N"].value`. Нет словаря (английский или
  отсутствующий файл), нет записи, нет формы — шаблоном становится сам
  английский текст.
- Простой вызов, встретивший объект множественного числа, или вызов
  множественного числа, встретивший простую строку, падает в английский
  текст; сырой JSON на экран не попадает.
- Подстановки: `%s` и `%d` по порядку появления, `%1$s` / `%2$d` по явной
  позиции, `%%` — литеральный процент; `%d` отбрасывает дробную часть.
  Недостающий аргумент печатает пустое место, никогда — подстановку. Одинокий
  `%` печатается как есть.
- Множественное число берёт счётчик первым аргументом подстановки и выбирает
  форму по правилам языка; дробь в русском уходит в `other`; неполный объект
  форм деградирует в любую имеющуюся форму, а не бросает.
- Особые формы — для одного английского текста, который в двух местах должен
  читаться по-разному («OK» как «ОК» в диалоге и как латинский термин в
  другом месте): код называет индекс, словарь несёт вариант; индекс, которого
  в словаре нет, падает в английский текст.
- Два объекта, два рендера: сохранённая ошибка или предупреждение на экране
  отрисовывается на активном языке, а для журнала, Debug API и автоматизации —
  по-английски; английский рендер от языка не меняется.
- Оверлей шаблона: применяется к декодированному шаблону до разбора, только к
  отображаемым полям (названия пресетов, подсказки, подписи опций, описания
  правил), ключ — сам английский текст; машинные поля (конфиг, теги, значения,
  имена-идентификаторы) не посещаются, поэтому выдаваемый конфиг байт-в-байт
  тот же. Значение оверлея, начинающееся с `@` или содержащее `{`,
  игнорируется (оно стало бы ссылкой на переменную или подстановкой).
  Повторяющийся английский текст — один ключ. Тела пресетов внутри условных и
  шаблонных ветвей тоже посещаются.
- Живые подписи из шаблона (имена правил из пресетов) выводятся заново при
  смене языка без пересборки конфига; условия inline-правил — текст
  пользователя, они не трогаются.
- Формат даты и времени следует активному языку.
- Как писать строку в коде: вызвать локализатор с английским литералом в
  месте показа — контекст экрана не нужен, так что это доступно сервисам и
  парсерам; счётчик идёт через вызов множественного числа с `%d`;
  переставляемые аргументы используют позиционные подстановки; текст,
  сохраняемый на потом, идёт через типизированное сообщение, отрисовываемое в
  момент показа; соседние литералы образуют один ключ; текст, который нельзя
  переводить (wire-тег, единица, эндоним, термин протокола), несёт
  `// l10n-exempt: <причина>` на своей строке или строкой выше — «потом» не
  причина. Ключ, собранный из переменной, проверить нельзя, его следует
  избегать.

## Границы

- Словарь в рантайме только для чтения: ни правки в приложении, ни удалённого
  обновления.
- Какие строки нативные или ядра, а не словарные —
  [native-and-core-strings](native-and-core-strings.ru.md); как ключ попадает
  во все словари — [translation-workflow](translation-workflow.ru.md).
- Сам язык шаблона (`#if`, `for_each`, переменные) —
  [003-CONFIG_BUILD](../../003-CONFIG_BUILD/FEATURE.ru.md).
- Род и падежное согласование сверх форм множественного числа не
  моделируются.
