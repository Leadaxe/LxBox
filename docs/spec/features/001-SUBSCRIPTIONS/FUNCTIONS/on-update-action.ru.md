# Действие при обновлении — пересборка, перезагрузка ядра или ожидание при смене узлов подписки

Когда обновление меняет узлы подписки, её настройка «On update» решает: пересобрать конфиг,
пересобрать и перезагрузить его в ядре или дождаться следующей пересборки.

| Поле | Значение |
|------|----------|
| Фича | [001-SUBSCRIPTIONS](../FEATURE.ru.md) |
| Обещания | P6, P11 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Решает, что делать с конфигом, когда подписка обновилась и **её состав
изменился**: только пересобрать, пересобрать и перечитать в ядре на ходу или
ничего не делать до следующей обычной пересборки. Нужна, чтобы подписка с
часовым интервалом не поднимала плашку «restart to apply» каждый час у
пользователя, который ничего не трогал.

## Параметры

| Параметр | Значения | Дефолт |
|---|---|---|
| On update (подписка → Settings) | **Rebuild config — apply manually** · **Rebuild and reload core — brief connection drop** · **Do nothing — apply on next rebuild** | Rebuild |
| Auto-restart VPN on settings change (глобальная, чужая) | вкл → для всех подписок действует Reload, строка «On update» скрыта | выкл |

Выбор подписки при включённой глобальной галке не стирается — выключение
галки возвращает его.

## Входы / Выходы

**Вход:** итог обновления подписки — «состав изменился» да/нет.
**Выход:** пересборка конфига без снэкбара; при Reload и поднятом туннеле —
перечитывание конфига ядром на ходу (разрыв ≈ 3 с, открытые TCP рвутся).

## Правила и инварианты

- **Состав** = узлы подписки в порядке следования (по отпечатку содержимого)
  плюс набор отметок выключенных узлов. Имя, время, метаданные, статус в
  состав не входят. Тот же состав → реакции нет и конфиг не помечается
  изменённым, хотя время обновления сохраняется.
- Реакция только у **включённой** подписки: выключенная в конфиг не входит.
- Автоматический проход копит реакции и применяет **одну** в конце:
  хотя бы одна Reload → Reload, иначе хотя бы одна Rebuild → Rebuild.
- Ручное обновление одной подписки применяет её реакцию сразу, по тем же
  условиям (изменился состав, подписка включена).
- Reload выполняется, только если туннель поднят и пересобранный конфиг
  отличается от работающего; в пределах cooldown перезагрузки — пропуск,
  остаётся плашка.
- Пересборка в полёте дожидается, затем выполняется своя — чтобы не
  применить конфиг, собранный до записи новых узлов.
- Do nothing: узлы обновлены, конфиг помечен изменённым; применится при
  возврате на главный, Start или ручном Apply.
- Ошибка реакции не роняет проход апдейтера.

## Границы

- Сама пересборка и сравнение с работающим конфигом —
  [003-CONFIG_BUILD](../../003-CONFIG_BUILD/FEATURE.ru.md); перезагрузка ядра —
  [010-VPN_SERVICE](../../010-VPN_SERVICE/FEATURE.ru.md).
- «Update all» после прохода пересобирает и сохраняет конфиг всегда.
