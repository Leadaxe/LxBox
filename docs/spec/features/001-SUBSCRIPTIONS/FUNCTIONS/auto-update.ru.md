# Автообновление подписок — обновление по расписанию и по событиям

Подписки обновляются при старте приложения, возврате из фона, подключении и остановке VPN и по
часовому таймеру — в пределах интервала подписки и антиспам-ограничений.

| Поле | Значение |
|------|----------|
| Фича | [001-SUBSCRIPTIONS](../FEATURE.ru.md) |
| Обещания | P3, P4, P5, P6, P14, P15 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Держит подписки свежими без участия пользователя и **не спамит провайдеру**.
Все триггеры сходятся в один проход, который решает по каждой подписке одним
правилом «пора ли». Ручное обновление — тот же путь, но в обход ограничений.

## Параметры

| Параметр | Значения | Дефолт |
|---|---|---|
| Auto-update subscriptions | вкл/выкл (Настройки → Subscriptions и меню экрана источников) | вкл |
| Update disabled subscriptions | вкл/выкл; доступна только при включённом автообновлении | выкл |
| Update interval (подписка) | `-1` Don't auto-update · `0` Never (respect server) · 1, 3, 6, 12, 24, 48, 72, 168 ч | 24 ч; файловая `-1` |

Константы: min-retry 15 мин · потолок провалов 5 за сессию · пауза между
подписками 10 с ± 2 с · периодический тик 1 ч · задержка после VPN 2 мин.

## Входы / Выходы

**Триггеры:**

| Триггер | Когда | Ограничения |
|---|---|---|
| appStart | после загрузки источников на старте | все |
| resumed | приложение вернулось из фона | все |
| periodic | раз в час, пока процесс жив | все |
| vpnConnected | через 2 мин после подключения туннеля | все |
| vpnStopped | сразу при уходе туннеля из «подключён» | все |
| «Update all» | кнопка на экране источников | обходит всё, кроме гейта выключенных |
| «Update» / «Refresh now» / «Reset fail count & retry» | одна подписка | обходит всё |

**Выход:** обновлённые подписки ([запрос и кэш](fetch-cache-offline.ru.md)),
одна агрегированная [реакция](on-update-action.ru.md) на проход.

## Правила и инварианты

Решение «пора ли» для автоматического триггера, по порядку:

1. Автообновление выключено → проход не начинается.
2. Подписка выключена и «Update disabled subscriptions» выкл → нет
   (этот гейт действует и на «Update all»).
3. ≥ 5 провалов подряд в этой сессии → нет (кроме ручного).
4. Ручной → да.
5. Интервал ≤ 0 → нет.
6. С последней попытки < 15 мин → нет.
7. Успеха не было → да; иначе — да, если с успеха прошло ≥ интервала.

- Проходы не идут параллельно: новый триггер во время прохода пропускается.
  Внутри прохода подписки идут последовательно. URL запрашивается один раз
  за проход: остальные записи с тем же URL берут первый успешный ответ (каждая
  разбирается своими правилами, без паузы перед ними); если запрос не удался,
  в этом проходе они пропускаются.
- Серверный `profile-update-interval` меняет интервал подписки при `0` и
  `N>0`; при `-1` игнорируется. Отрицательное или нечисловое значение
  заголовка игнорируется; отрицательный интервал, принятый от сервера раньше
  (меньше `-1`), на следующем успехе заменяется серверным значением или 24 ч.
- Потолок провалов живёт в памяти: сбрасывается перезапуском, ручным
  обновлением подписки, «Reset fail count & retry» и «Update all».
  Число провалов подряд для показа («(N fails)») хранится отдельно и
  обнуляется первым успехом.
- Идёт запрос подписки → повторный запрос той же подписки не стартует.
  Статус «обновляется», оставшийся от убитого процесса, на старте
  превращается в «ошибка».
- Переключение пространства прерывает проход: между подписками и в паузе
  (реакция ≈ ¼ с); новые проходы после этого не начинаются.
- Тактильный отклик и снэкбары — только для ручных обновлений; автоматические
  тихие.
- После «Update all» конфиг пересобирается и сохраняется, снэкбар «Config
  generated: N nodes». Если проход уже идёт, «Update all» ничего не делает и
  сообщает «Subscriptions are already updating. Try again later.» (без
  пересборки и снэкбара об успехе).

## Границы

- Обновления выгруженного приложения нет; сколько процесс живёт свёрнутым,
  зависит от возможностей ОС. Возврат из фона закрывает этот пробел.
- Экспоненциального backoff между проходами нет — его роль играет потолок 5.
- Файловая подписка в проходе по сети не запрашивается (её снапшот
  разбирается заново, см. [файловая подписка](file-subscription.ru.md)).
