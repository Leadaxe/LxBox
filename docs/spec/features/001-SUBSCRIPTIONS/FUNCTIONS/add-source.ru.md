# Добавление источника — URL подписок, ссылки, QR-коды и файлы

URL, вставленный текст, QR-код или файл превращается в подписку, одиночный сервер, папку или
файловую подписку в списке источников.

| Поле | Значение |
|------|----------|
| Фича | [001-SUBSCRIPTIONS](../FEATURE.ru.md) |
| Обещания | — (опирается на P1 при первом запросе) |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Принимает от пользователя источник узлов и заводит под него запись в общем
списке источников: подписку по URL, одиночный сервер, папку или файловую
подписку. После успешного добавления конфиг пересобирается, новая запись
прокручивается в видимую область и подсвечивается.

## Параметры

Своих настроек нет. Точки входа на экране источников:

| Вход | Что происходит |
|---|---|
| Поле ввода + «+» | текст классифицируется и добавляется сразу |
| «+» при пустом поле / «Paste from clipboard» | буфер → анализ → диалог подтверждения |
| «Scan QR code» (если есть камера) | строка из QR → тот же анализ и подтверждение |
| «Import from file…» | один файл → см. ниже; несколько → новая папка |
| «Get Public Test Servers» | список из community-манифеста; выбор подставляет источник в поле ввода |

## Входы / Выходы

**Вход:** строка или содержимое файла.
**Классификация** (порядок проверки):

1. `http://` / `https://` → **подписка по URL**. Запись создаётся с пустым
   именем и сразу запрашивается; имя подставится из `profile-title`, иначе в
   списке виден хост.
2. WireGuard-конфиг, контейнер Amnezia, ссылка на один узел, JSON — **одиночный
   сервер** (разбор — [002-NODE_IMPORT](../../002-NODE_IMPORT/FEATURE.ru.md)).
3. Иначе — «not recognized».

**Импорт одного файла:** если в нём > 1 узла — создаётся
[файловая подписка](file-subscription.ru.md) с именем из `profile-title` или имени
файла без расширения; ≤ 1 узла — одиночный сервер, имя файла становится
подсказкой имени узла (файл с одним узлом не становится файловой подпиской
из одного узла; ничего не теряется — узел добавляется как есть). **Несколько файлов** → новая папка, по серверу из
каждого файла; пустые файлы перечисляются в сообщении.

**Выход:** новая запись; снэкбар «Config regenerated: N nodes» (или «…& applied»).

## Правила и инварианты

- Буфер и QR — недоверенный ввод: до записи показывается диалог с
  распознанным типом (Subscription URL + хост, WireGuard config + endpoint,
  ссылка, JSON) и числом записей, которые не станут узлами, с причинами.
- Нераспознанный буфер → диалог «неизвестный формат» с превью текста.
- Пустой буфер → «Clipboard is empty»; пустой файл → «File is empty».
- Уход с экрана с непустым полем ввода спрашивает «Discard input?».
- Ошибка разбора одиночного ввода открывает шторку с причиной отказа.
- Подписка по URL добавляется **даже если первый запрос не удался**: запись
  остаётся со статусом ошибки и ретраится обычным порядком.
- Одинаковый URL можно добавить дважды — дедупа записей нет.
- Префикс тегов из эмодзи имени ([647](../../../tasks/647-subscription-emoji-tag-prefix.md)):
  когда у подписки впервые появляется непустое имя (из `profile-title` /
  `Content-Disposition` при первом успешном обновлении либо из `profile-title` /
  имени файла при импорте файла), а префикс тегов пустой, префиксом становится
  группа эмодзи из имени. Группа начинается с первого эмодзи и забирает
  следующие эмодзи — вплотную или через меньше чем 3 разделителя (пробел, `·`,
  `|` …); текст или разрыв длиннее её обрывают; не больше 4 графемных
  кластеров. `©`, `™`, `★` без эмодзи-представления не в счёт. Если такой
  префикс уже есть у другого источника, дописывается индекс без пробела:
  `🗽2`, `🗽3`, … Срабатывает один раз: у подписки с именем, с непустым
  префиксом, при переименовании и после очистки префикса пользователем — нет;
  одиночным серверам префикс не ставится.

## Границы

- Какие форматы распознаются и как — 002-NODE_IMPORT.
- Папки и одиночные серверы как сущности — [007-NODE_LIST](../../007-NODE_LIST/FEATURE.ru.md),
  [008-NODE_EDITOR](../../008-NODE_EDITOR/FEATURE.ru.md).
- Выбор файла и камера — зависят от возможностей ОС; без файлового
  менеджера показывается подсказка.
- Пресета «Get Free VPN» с автонастройкой правил (из `§010F`) в приложении нет
  и не планируется (решение владельца 2026-09-29, аудит [591](../../../tasks/591-spec-kit-revision-audit.md));
  публичные списки только подставляют URL в поле.
