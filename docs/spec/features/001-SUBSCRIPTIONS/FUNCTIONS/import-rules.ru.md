# Правила импорта подписки — выключение, включение и правка узлов при каждом обновлении

Правила импорта находят узлы подписки по полям их JSON и выключают, включают или правят их при
каждом разборе тела подписки.

| Поле | Значение |
|------|----------|
| Фича | [001-SUBSCRIPTIONS](../FEATURE.ru.md) |
| Обещания | P12 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Даёт подписке набор правил «если узел такой — выключи / включи / замени
поле», которые применяются к **каждому разбору её тела**. Правила работают над
каноническим JSON узла, а не над текстом тела, поэтому одно правило одинаково
действует на URI-списки, Xray-JSON и INI.

## Параметры

Подписка → вкладка Filters:

| Параметр | Значения | Дефолт |
|---|---|---|
| Enable import rules | общий тумблер набора | вкл |
| Правило вкл/выкл | на каждом правиле | вкл |
| Условия | путь в JSON узла (`tag`, `server_port`, `tls.utls.fingerprint`; пусто = искать везде) · `contains` / `equals` / `matches` (regex) · отрицание · регистрозависимость | `contains`, без учёта регистра |
| Объединение условий | AND / OR | AND |
| Действие | **Disable** · **Enable** · **Replace** | Replace |
| Replace | Target path (пусто = по всему узлу) · Set whole value / Substitute part · Find inside the value · New value с карманами `$1…$9`, `$$` = `$` | Set whole value |

## Входы / Выходы

**Вход:** разобранные узлы подписки и её правила.
**Выход:** итог по узлу — «выключить», «включить принудительно» или ничего;
патченый JSON узла (уходит в конфиг); следы замен «путь: было → стало»
(видны при просмотре узла, узел помечен «Modified by import rules»).

## Правила и инварианты

- Правила идут сверху вниз; Replace меняет JSON, следующее правило видит
  изменённый вид.
- Enable/Disable: **последнее сработавшее побеждает** — «выключить всё» +
  точечные Enable дают белый список, и наоборот.
- Итог Disable ставит отметку ([node-disable.md](node-disable.ru.md)), итог Enable
  снимает её — включая ручную; применяется после TTL-очистки, то есть правило
  сильнее очистки и ручного выбора.
- Каждое применение начинается с чистого узла: повтор не накапливает замены.
- Replace не меняет ключ отметки (имя узла), даже если меняет сервер или ключи.
- Несуществующий путь: условие ложно (с отрицанием — истинно), замена по нему
  не пишется. Тип значения сохраняется (порт остаётся числом). Путь,
  указывающий не на лист, сравнивается как компактный JSON.
- Непригодное правило (нет условий, пустой паттерн, битый regex, «Set whole
  value» без пути, «по всему узлу» без паттерна поиска) пропускается и
  помечается «invalid pattern — skipped»; редактор не даёт его сохранить.
- Изменение правил существующие узлы не пересчитывает: показывается
  «Rules changed. Refresh the subscription to apply them.» с кнопкой Apply,
  которая обновляет подписку по сети; итог — сколько узлов пришло и сколько
  выключено.
- Регидрация на старте применяет Replace к узлам из кэша; отметки
  Disable/Enable пересчитываются только на успешном сетевом обновлении.
- Во вкладке редактора «Matches» — предпросмотр совпадений на текущих узлах.

## Границы

- К папкам и одиночным серверам не применяются.
- Разбор тела до правил — [002-NODE_IMPORT](../../002-NODE_IMPORT/FEATURE.ru.md).
