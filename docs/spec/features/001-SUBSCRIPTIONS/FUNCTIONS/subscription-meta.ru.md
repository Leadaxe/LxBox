# Метаданные подписки — трафик, срок действия, имя и ссылки поддержки от провайдера

Приложение берёт из заголовков ответа провайдера или комментариев в начале тела трафик, срок
действия, имя, интервал обновления, описание и ссылки поддержки и показывает их в шапке подписки.

| Поле | Значение |
|------|----------|
| Фича | [001-SUBSCRIPTIONS](../FEATURE.ru.md) |
| Обещания | P4, P13 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Читает из ответа провайдера служебные сведения о подписке и показывает их
пользователю: сколько трафика израсходовано из лимита, когда истекает срок,
как подписка называется, куда обращаться в поддержку, как часто
провайдер советует обновляться.

## Параметры

Своих настроек нет.

## Входы / Выходы

**Вход — заголовки ответа** (регистр имён не важен):

| Заголовок | Что даёт |
|---|---|
| `subscription-userinfo` | `upload=…; download=…; total=…; expire=…` — байты и unix-секунды |
| `profile-title` | имя подписки; значение `base64:…` декодируется |
| `Content-Disposition` | запасное имя: `filename*=UTF-8''…` → `filename="…"` → `filename=…`; расширения `.txt .yaml .yml .json .conf` срезаются |
| `profile-update-interval` | интервал обновления в часах |
| `support-url` | ссылка поддержки |
| `profile-web-page-url` | страница провайдера |
| `announce` | описание подписки (например, легенда к эмодзи в именах узлов); значение `base64:…` декодируется как UTF-8, иначе берётся как есть |

Если заголовков нет, те же ключи берутся из строк-комментариев в начале тела
(`#`, `//`, `;` + `key: value`); чтение останавливается на первой
некомментарной строке, посторонние ключи игнорируются. HTTP-заголовки
приоритетнее.

**Выход (шапка подписки):** `N nodes` (`N +D⚙ nodes` при detour-узлах),
«M off», полоса «used / total» при ненулевом лимите, «Expires: N days left /
N hours left / Expired», текст описания, чипы «Support» (иконка Telegram для `t.me`) и «Web
page», строка «N entries dropped».

## Правила и инварианты

- `upload`/`download`/`total`: непарсимое → 0. `expire`: непарсимое или
  отсутствующее → «срока нет»; `expire=0` показывается как отсутствие срока.
- Имя из `profile-title` (или `Content-Disposition`) ставится только при
  первом успешном обновлении подписки без имени; переименование
  пользователем не перетирается. Без имени показывается хост URL.
- Метаданные заменяются целиком на каждом успешном ответе; провал и пустой
  ответ их не трогают.
- `profile-update-interval` меняет интервал подписки, если её интервал не
  `-1` ([auto-update.md](auto-update.ru.md)).
- Использовано = upload + download; полоса ограничена 100 %.
- Пороговых предупреждений об истечении срока или трафика нет — только показ.
- `announce`: `\r\n` → `\n`, обрезка пробелов по краям всего текста, больше
  двух переводов строки подряд схлопываются в два, хранится не больше 2000
  символов (графем). Пустой результат или битый base64 — поля нет (битый
  base64 — предупреждение в AppLog), подписка обновляется как обычно.
- Описание показывается под строкой «Expires», над чипами «Support» / «Web
  page», стилем соседних строк шапки, как есть: многострочно, без перевода, без
  разметки, ссылки не кликабельны. В свёрнутом виде — не больше 4 строк с
  многоточием; длинный текст раскрывается тапом и сворачивается повторным,
  короткий на тап не реагирует. Поля нет — блока нет.
- Вкладка Source, блок Response headers: значение `base64:…`, которое
  расшифровывается в UTF-8 (тем же декодером, что `profile-title`), показано
  расшифрованным; под именем заголовка — мелкая подпись `base64` с пунктирным
  подчёркиванием. Тап по подписи переключает значение строки между
  расшифрованным и исходным; состояние своё у строки и между открытиями экрана
  не сохраняется. Значение без префикса, с битым base64 или не-UTF-8 —
  как есть, без подписи. Копирование блока — в исходном виде.

## Границы

- Метаданные не влияют на конфиг ядра и на «состав» подписки.
- Файловая подписка берёт метаданные из комментариев в начале файла при
  импорте; дальше они не меняются.
