# Файловая подписка и смена источника — узлы из файла, безопасная смена URL и режима

Файл с несколькими узлами становится подпиской, а у любой подписки можно сменить URL или перейти
между режимами online и file, не потеряв узлы.

| Поле | Значение |
|------|----------|
| Фича | [001-SUBSCRIPTIONS](../FEATURE.ru.md) |
| Обещания | P2, P4, P8 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

1. **Файловая подписка** — файл со списком узлов живёт как обычная подписка:
   переключатель, настройки, отметки узлов, правила. Источник — снапшот
   содержимого файла, сделанный при импорте; сам файл больше не читается.
2. **Смена источника** («Edit source…») — у существующей подписки можно
   заменить URL (сменился домен провайдера, опечатка) или перейти между
   режимами online ↔ file, не теряя имени, включённости, настроек и отметок.

## Параметры

| Параметр | Значения |
|---|---|
| Режим в диалоге Edit source | Online URL (поле `http(s)://`) / Local file (кнопка Choose…) |
| Интервал после смены | → file: `-1`; → online: прежний, если был > 0, иначе 24 ч |

Вход в диалог — пункт «Edit source…» в меню записи и тап по строке
URL / «Source: local file» во вкладке Settings подписки.

## Входы / Выходы

**Вход:** текст файла или новый URL.
**Выход:** подписка с новым источником, свежими узлами и метаданными,
статусом OK; снапшот прежнего источника удалён.

## Правила и инварианты

- Создание при импорте — только при > 1 узле в файле; при смене источника
  достаточно ≥ 1 узла.
- **Транзакционность:** новый источник сначала загружается и разбирается;
  адрес, узлы и кэш подменяются только если узлов ≥ 1. Иначе — ничего не
  меняется, сообщение «Couldn't load new source — keeping current».
- Смена URL на тот же не удаляет кэш; каждая смена на файл создаёт новый
  внутренний ключ `file:<uuid>`.
- При переходе на новый URL его ответ в кэш не пишется — кэш появится на
  следующем успешном обновлении; до него офлайн-старт этой подписки узлов не
  поднимет — известный дефект, кандидат в задачу.
- При смене URL сохраняется Custom-идентичность подписки — новый адрес
  запрашивается ею же.
- Отметки выключенных узлов переживают смену источника (та же запись).
- Файловая подписка создаётся с интервалом `-1`; автоматические и ручные
  «обновить» для неё ничего не делают и не меняют статус.
- После перезапуска узлы файловой подписки поднимаются из её снапшота.
- TTL-очистка отметок для файловой подписки не выполняется — нет внешнего
  сигнала, что узел ушёл.
- В списке вместо интервала показывается бейдж «file»; «Share URL…» скрыт;
  в журнале источник виден как `file:<local>`.
- Диалог требует выбрать файл в режиме file и валидный `http(s)://` в режиме
  online, иначе подсказка без запроса.

## Границы

- Постоянного доступа к файлу на диске нет: обновить файловую подписку можно
  только повторным выбором файла.
- Разбор содержимого файла — [002-NODE_IMPORT](../../002-NODE_IMPORT/FEATURE.ru.md).
