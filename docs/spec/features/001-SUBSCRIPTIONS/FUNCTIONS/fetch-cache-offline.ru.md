# Запрос, кэш и офлайн-старт

| Поле | Значение |
|------|----------|
| Фича | [001-SUBSCRIPTIONS](../FEATURE.ru.md) |
| Обещания | P1, P8, P15 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Выполняет одно обновление подписки и гарантирует, что **рабочий список узлов
не теряется** ни при провале запроса, ни при перезапуске без сети. Последний
успешный ответ (тело и заголовки) хранится на устройстве и служит источником
узлов на старте и содержимым вкладки Source.

## Параметры

Своих настроек нет. Константы запроса: 3 попытки, паузы 1 с и 3 с, таймаут
попытки 9 с (худший случай ≈ 31 с). Ответ 4xx не повторяется; 5xx, сетевые
ошибки и таймауты — повторяются.

## Входы / Выходы

**Вход:** подписка (URL + идентичность, см. [fetch-identity.md](fetch-identity.ru.md)).

**Выход по исходу:**

| Исход | Узлы | Кэш тела | Статус | Показ в списке |
|---|---|---|---|---|
| ≥ 1 узел | новые | перезаписан | OK, время успеха | `N nodes` |
| 0 узлов при HTTP 200 | прежние | прежний | ошибка, провалов +1 | `N nodes (update failed: 0 parsed)` или `0 nodes — <подсказка>` |
| HTTP-ошибка / сеть | прежние | прежний | ошибка, провалов +1 | `N nodes (update failed)` или текст ошибки |
| После перезапуска | из кэша | — | как было сохранено | `N nodes (cached)` |

Строка списка: число узлов · интервал · «N ago» / «never» · «(N fails)».
Вкладка Settings подписки: OK / Failed (N in a row) / Refreshing… / Never
updated, «Last success · Last attempt · N nodes», кнопка «Refresh now».

## Правила и инварианты

- **Пометка попытки до сети:** статус «обновляется» и время попытки
  сохраняются до запроса, поэтому перезапуски не дают повторных запросов
  раньше 15 мин.
- **Ответ 200 без узлов — провал**, не успех: кэш и узлы не трогаются, в
  журнал пишется подсказка, что пришло вместо подписки (HTML, challenge…).
- Причины отбраковки записей последнего разбора показываются в сводке
  подписки («N entries dropped») — и при успехе, и при пустом ответе.
- Кэш пишется атомарно (временный файл → переименование): убитый процесс не
  оставит обрезанное тело. Сбой записи кэша обновление не роняет.
- **Регидрация на старте:** подписки без узлов поднимаются из кэша, с теми же
  правилами импорта. Правка пользователя, сделанная во время регидрации
  (переупорядочивание, переименование, удаление), не затирается. Отметки
  узлов на регидрации не чистятся. Кэш, разобранный в 0 узлов, оставляет
  подписку пустой с записью в журнале.
- Провал и пустой ответ не помечают конфиг изменённым; успех — только при
  изменившемся составе включённой подписки ([on-update-action.md](on-update-action.ru.md)).
- Вкладка Source показывает сохранённые заголовки и тело; «Re-fetch live»
  делает живой запрос с той же идентичностью, в кэш не пишет. Важные
  заголовки (`profile-*`, `support-url`, `subscription-userinfo`,
  `content-type`) показаны отдельно, прочие — под раскрывашкой.
- Ответ, пришедший после переключения пространства, отбрасывается.

## Границы

- Кэш сбрасывается очисткой данных приложения; не бэкапится.
- Файловая подписка не запрашивается — её кэш и есть источник
  ([file-subscription.md](file-subscription.ru.md)).
- Разбор тела и подсказка «что пришло» — [002-NODE_IMPORT](../../002-NODE_IMPORT/FEATURE.ru.md).
