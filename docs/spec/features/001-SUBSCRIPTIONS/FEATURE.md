# FEATURE 001 — SUBSCRIPTIONS — источники узлов и их обновление

| Поле | Значение |
|------|----------|
| Тип | Продуктовая фича |
| Поглотила | `§006F` `§010F` `§027F` `§118F` `§129F` `§283F` (`§123F` — модель каналов ядра, отнесена к 012-LIVE_STATE) |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Назначение

Узлы приходят в приложение из **источников**: подписка по URL провайдера,
файл со списком узлов, текст из буфера обмена или QR-кода. Фича отвечает за
то, чтобы источник был добавлен, **сам поддерживался в свежем виде** и при этом
никогда не оставлял пользователя без узлов.

Три принципа, которые фича защищает:

1. **Не оставаться без узлов.** Любой провал — сеть, HTTP-ошибка, пустой или
   мусорный ответ, неудачная смена адреса — оставляет последний рабочий список.
   Узлы переживают перезапуск и старт без сети.
2. **Не спамить провайдеру.** Каждый автоматический запрос оправдан интервалом,
   у каждой серии провалов есть потолок, параллельные запросы одной подписки
   схлопываются.
3. **Представляться панели правильно.** Запрос несёт узнаваемый User-Agent и,
   по желанию пользователя, HWID-заголовки — от этого зависит, какой формат
   и сколько «устройств» панель отдаст.

Как тело подписки превращается в узлы — фича
[002-NODE_IMPORT](../002-NODE_IMPORT/FEATURE.md); здесь тело — чёрный ящик,
который либо дал ≥1 узел, либо нет. Как узлы показываются и выбираются на
главном экране — [007-NODE_LIST](../007-NODE_LIST/FEATURE.md).

## Обещания

- **P1. Провал обновления не трогает рабочий список.** Сетевая ошибка, HTTP
  4xx/5xx или ответ 200, разобранный в 0 узлов, оставляют прежние узлы, прежний
  кэш тела и время последнего успеха; меняются только статус «ошибка», время
  попытки и счётчик провалов подряд.
  Свидетель: юниты «200 с мусорным телом → узлы/кэш/счётчик сохранены, failed»,
  «HTTP 500 → узлы сохранены, failed». Мутация: записывать результат разбора
  без проверки на пустоту.
- **P2. Смена источника транзакционна.** Новый URL или файл применяется только
  если дал ≥1 узел; иначе подписка остаётся на старом источнике со старыми
  узлами, пользователь видит «Couldn't load new source — keeping current».
  Свидетель: юниты «online → online (fetch fail): полный откат», «file → online
  (успех): коммит + чистка старого кэша». Мутация: подменить адрес до загрузки.
- **P3. Автообновление не чаще, чем разрешено.** Автоматический триггер
  обновляет подписку, только если прошёл её интервал с последнего успеха, с
  последней попытки прошло ≥ 15 мин и в этой сессии было < 5 провалов подряд.
  Ручное обновление обходит все три ограничения.
  Свидетель: юниты группы «shouldUpdate» (min-retry, fail-cap, интервал, force).
  Мутация: убрать проверку времени последней попытки.
- **P4. Интервал «Don't auto-update» сервер не переубедит.** При `-1` заголовок
  `profile-update-interval` игнорируется, при `0` и `N>0` — принимается.
  Файловая подписка создаётся с `-1`.
  Свидетель: юниты «interval=-1 → игнорирует серверный profile-update-interval»,
  «interval ≤ 0 → never auto (но force работает)». Мутация: применять серверный
  интервал безусловно.
- **P5. Один проход за раз, пауза между подписками.** Автоматические и
  «обновить все» проходы не идут параллельно; подписки внутри прохода
  запрашиваются последовательно с паузой 10 с ± 2 с. Свидетель — ручная
  проверка: две подписки, «Update all», в журнале приложения строки «Fetching
  subscription» разнесены на ≥ 8 с. Мутация: запускать запросы параллельно.
- **P6. Выключенная подписка не мешает.** Без настройки «Update disabled
  subscriptions» она не обновляется ни автоматически, ни через «обновить все»;
  с настройкой — обновляется, но её новый состав не помечает конфиг
  изменённым и не вызывает реакцию. Свидетель: юниты «выключенная: без галки
  skip, с галкой обновляется», «force выключенную БЕЗ галки не размораживает»,
  «выключенная подписка с новым составом → dirty остаётся false». Мутация:
  поставить гейт выключенных ниже `force`.
- **P7. Запрос узнаваем панелью.** По умолчанию User-Agent =
  `LxBox-android/<версия>` и не содержит подстроки `singbox`; HWID-заголовки
  уходят только при включённом «Send HWID» и непустом HWID; в режиме Custom
  подписка шлёт только свой слепок, глобальные значения игнорируются.
  Свидетель: юниты «никогда не содержит singbox», «sendHwid=false → пусто»,
  «Custom → слепок уходит в заголовки, глобальный игнорируется». Мутация:
  добавить `singbox` в UA.
- **P8. Офлайн-старт.** После перезапуска узлы подписок восстанавливаются из
  кэша последнего успешного ответа без сети (с пометкой «(cached)»); для
  файловой подписки — из её снапшота.
  Свидетель: юниты «init → восстанавливает ноды из кеша», «старт: ноды пусты →
  поднимаются из кэша по file:url». Мутация: не читать кэш на старте.
- **P9. Отметка «узел выключен» следует за именем узла.** Выключенный узел
  подписки виден в списке, но не попадает в конфиг; отметка переживает
  обновление и перезапуск, переживает смену адреса провайдером под тем же
  именем, теряется при переименовании; тёзки выключаются раздельно.
  Свидетель: юниты «отметка переживает РОТАЦИЮ адреса», «ПЕРЕИМЕНОВАНИЕ отметку
  теряет», «тёзки X / X-2 гасятся РАЗДЕЛЬНО», «выключенная нода не эмитится».
  Мутация: вернуть ключом отметки хеш содержимого.
- **P10. Спящие отметки истекают по TTL.** Отметка узла, которого нет в
  подписке дольше `clamp(3 × интервал, 24 ч, 30 сут)`, удаляется — но только на
  успешном сетевом обновлении. Свидетель: юниты «таблица порогов», «отсутствует
  дольше порога → удалена», «порог не истёк → на месте». Часть «только на
  успешном сетевом» — `без свидетеля` (провал, регидрация и файловая подписка
  не проверяются). Мутация: чистить отметки на регидрации из кэша.
- **P11. Реакция только на реальное изменение.** Пересборка/перезагрузка ядра
  после обновления случается, только если состав узлов включённой подписки
  изменился; за проход — одна реакция, `reload` побеждает `rebuild`.
  Провал обновления конфиг изменённым не помечает.
  Свидетель: юниты «тот же состав повторно → dirty остаётся false», «три
  reload-подписки → один reload, не три», «network error → флаг остаётся
  false». Мутация: реагировать на каждый успешный запрос.
- **P12. Правила импорта детерминированы.** Правила подписки применяются
  сверху вниз к каждому разбору с чистого узла; последняя сработавшая
  Enable/Disable побеждает; Enable снимает и ручную отметку.
  Свидетель: юниты «последнее сработавшее правило побеждает», «повторное
  применение стартует с чистого узла», «enable снимает отметку — в том числе
  ручную». Мутация: применять правила к уже патченому узлу.
- **P13. Метаданные читаются терпимо.** Непарсимый `expire` = «без срока», а не
  1970 год; имя — `profile-title`, иначе имя файла из `Content-Disposition`;
  при отсутствии HTTP-заголовков берутся `# key: value` из начала тела.
  Свидетель: юниты «непарсимый expire → null», «profile-title имеет приоритет
  над content-disposition», «inline profile-title from body comments».
  Мутация: парсить `expire` с дефолтом 0.
- **P14. Переключение пространства прерывает обновление.** Идущий проход
  останавливается между подписками, ответ, пришедший после переключения, в
  новое пространство не пишется. Свидетель: юниты «halt прерывает идущий
  проход между подписками», «отложенный фетч старого контроллера не трогает
  новый слот». Мутация: не проверять отмену в паузе между подписками.
- **P15. Зависшее «обновляется» не блокирует подписку навсегда.** Если процесс
  убит во время запроса, на следующем старте статус становится «ошибка», а
  окно 15 мин считается от той попытки. Повторное нажатие «обновить», пока
  запрос идёт, второго запроса не делает. `без свидетеля`.

## Контролируемые параметры

| Параметр | Где | Значения | Дефолт |
|---|---|---|---|
| Auto-update subscriptions | Настройки → Subscriptions; дубль в меню экрана источников | вкл/выкл | вкл |
| Update disabled subscriptions | там же; активна только при включённом автообновлении | вкл/выкл | выкл |
| Custom User-Agent (глобальный) | Настройки → Subscriptions | строка; пусто = `LxBox-android/<версия>` | пусто |
| Send HWID | Настройки → Subscriptions | вкл/выкл | выкл |
| HWID · `x-hwid` | там же, кнопка Regenerate | UUIDv4, генерируется при первом показе | — |
| `x-device-os` / `x-ver-os` / `x-device-model` | там же | строка; пусто = значение устройства | `android` / версия ОС / модель |
| Update interval (на подписке) | Подписка → Settings | `-1` Don't auto-update · `0` Never (respect server) · 1/3/6/12/24/48/72/168 ч | 24 ч (онлайн), `-1` (файл) |
| On update (на подписке) | Подписка → Settings; скрыта при «Auto-restart VPN on settings change» | Rebuild · Reload · Do nothing | Rebuild |
| Custom identity (на подписке) | Подписка → Settings → Fetch identity | Default / Custom (свой UA, HWID, device-meta) | Default |
| Import rules (на подписке) | Подписка → Filters | список правил + общий тумблер | пусто, тумблер вкл |
| Узел вкл/выкл | Подписка → Nodes | переключатель на узле, «вкл/выкл все» | вкл |

Фиксированные константы: пауза между подписками 10 с ± 2 с; min-retry 15 мин;
потолок провалов за сессию 5; периодический тик 1 ч; задержка после
подключения VPN 2 мин; 3 попытки запроса с паузами 1 с и 3 с, таймаут попытки
9 с; 4xx не повторяется.

Ключей конфига ядра фича не отдаёт: выключенная подписка или выключенный узел
просто не попадают в сборку ([003-CONFIG_BUILD](../003-CONFIG_BUILD/FEATURE.md)).

## Входы / Выходы

**Входы:** URL `http(s)://…`; текст из буфера, QR-кода или файла (формат
определяет [002-NODE_IMPORT](../002-NODE_IMPORT/FEATURE.md)); ответ HTTP —
тело и заголовки `subscription-userinfo`, `profile-title`,
`profile-update-interval`, `profile-web-page-url`, `support-url`,
`Content-Disposition`; события: старт приложения, возврат из фона, VPN
подключён/остановлен, часовой тик, ручное «обновить».

**Выходы:** список источников с узлами, статусом, временем обновления,
счётчиком провалов; метаданные (трафик, срок, ссылки поддержки); отметки
выключенных узлов; сигнал «состав изменился» → пересборка / перезагрузка ядра
по «On update»; события автоматизации «подписка обновлена / не обновилась»
([014-AUTOMATION](../014-AUTOMATION/FEATURE.md)).

## Data flow

```
ввод (URL | буфер | QR | файл)
  → классификация: URL подписки / одиночный узел / файл >1 узла → файловая подписка
  → запрос (идентичность: Default | Custom) ── 3 попытки ──┐
  → разбор тела (002) → ≥1 узел?                          │ нет/ошибка
        да: правила импорта → отметки (миграция, TTL, правила)   → статус failed,
            → кэш тела на диск → статус ok → «состав изменился?» старые узлы и кэш
                 → да и подписка включена: реакция On update
старт приложения: чтение источников → «обновляется» → failed
                  → регидрация узлов из кэша → проход автообновления (appStart)
```

## Правила и гарантии

- Время последнего успеха меняется только на успехе; время попытки — на
  каждой попытке; счётчик провалов подряд обнуляется любым успехом.
- Файловая подписка не читает файл заново: автоматическое и ручное «обновить»
  для неё — no-op, свежесть — только через «Edit source».
- Серверный `profile-update-interval` принимается при интервале `0` и `N>0`.
- Имя подписки берётся из `profile-title` только при первом успехе, когда имя
  пусто; дальше — пользовательское. Без имени показывается хост URL.
- Метаданные заменяются целиком на каждом успешном ответе.
- Потолок провалов живёт в памяти и сбрасывается перезапуском, пунктом «Reset
  fail count & retry», ручным обновлением подписки и «обновить все».
- В журнал URL попадает только как `схема://хост/***`, файловая — `file:<local>`.
- Пересборка конфига сама по себе никогда не делает HTTP.

## Границы

- Фоновое обновление выгруженного приложения не делается: таймер тикает, пока
  процесс жив; момент возврата из фона — отдельный триггер. Как долго процесс
  живёт свёрнутым — зависит от возможностей ОС.
- Разбор форматов тела, дедуп узлов, отбраковка записей — 002-NODE_IMPORT.
- Проверка доступности узлов и массовое выключение по её итогам (кнопки на
  экране подписки) — [009-NODE_HEALTH](../009-NODE_HEALTH/FEATURE.md); здесь
  только общая карта отметок.
- Автовыключение узлов, отвергнутых ядром, — 009-NODE_HEALTH; вердикт хранится
  рядом с отметкой и снимается, когда пользователь включает узел.
- Префикс тегов, detour-настройки и свёртка подписки в группу —
  [006-DETOUR_AND_BALANCE](../006-DETOUR_AND_BALANCE/FEATURE.md) и 007.
- Папки ручных серверов и одиночные серверы — 007/008; сюда входит только
  создание их из вставки/файла.
- Хранение и бэкап записей подписки —
  [017-BACKUP_AND_STORAGE](../017-BACKUP_AND_STORAGE/FEATURE.md).
- Выбор файла и камера для QR — зависят от возможностей ОС (на ТВ без
  файлового менеджера — подсказка вместо выбора).

## Особенности сопровождения

- **Ответ 200 ≠ успех.** HTML-заглушка, DDoS-challenge, чужой формат дают
  0 узлов — это провал, кэш не перезаписывается. Любой новый путь записи
  результата обязан держать эту проверку.
- **Отметка = имя узла внутри источника**, тёзки нумеруются `X`, `X-2`, `X-3`
  по порядку разбора. Карту идентичностей считать только от полного списка
  источника: подмножество даст другие номера. Старые отметки-хеши (64 hex)
  переезжают на имя при первом разборе.
- **«Состав» = упорядоченные узлы + набор отметок.** Метаданные подписки в него
  не входят; иначе синяя плашка «Settings changed» будет раз в час.
- **Пометка попытки пишется до сети** — без неё рестарты приложения дёргали бы
  провайдера на каждом старте.
- **UA без бренд-токена** ломает часть панелей (отдают формат, который
  разбирается хуже); это предупреждение показывается у поля, но не блокирует.
- **Переключение пространства** (Workspaces) обязано остановить апдейтер до
  смены сцены: пауза между подписками прерывается за ~¼ с.
