# Коды предупреждений — один словарь причин, общий с лаунчером

Каждая деградация узла — снятое поле, заменённое значение, отброшенная запись, отказ ядра — это
код из одного словаря с заголовком, текстом, причиной, способом исправления и страницей
«Learn more».

| Поле | Значение |
|------|----------|
| Фича | [025-CONTRACT_REGISTRY](../FEATURE.ru.md) |
| Обещания | P11 P12 P13 P14 |
| Состояние | ✅ написана по коду, 2026-09-29 |

## Что делает

Даёт каждому событию стабильное имя, которым пользуются оба приложения, и превращает это имя в то,
что видит пользователь: короткий заголовок на строке узла, карточку «What happened / Why it
happens / What you can do», кнопку «Details», открывающую страницу кода, и машинную форму в
Debug API. Словарь — `docs/contract/warnings.md`, байт-в-байт зеркало сгенерированной страницы
лаунчера; здесь он не правится.

## Параметры

| Уровень | Цвет и место | Смысл |
|---|---|---|
| `error` | красный; в отбраковке источника, шторке отказов ядра, отчёте сборки | запись не узел или вне конфига |
| `warning` | жёлтый; текстом на строке узла | узел жив, поле снято или заменено |
| `info` | приглушённый значок; на строке только значком, текст в карточке | справка: снято лишнее, служебная строка, подстановка |

| Где показываются коды | Что показывается |
|---|---|
| Строка узла (список, подписка, главный экран) | старший уровень: заголовок старшего кода, «+N more» только по error и warning; только info — значок перед протоколом |
| Шторка уведомлений и раздел Notifications экрана узла | счётчики по уровням, подразделы Errors → Warnings → Info, записи одного кода сгруппированы, каждая разворачивается в карточку |
| Карточка кода | заголовок; «What happened» с `path` и `value`; «Why it happens»; «What you can do» шагами; «Details» → `docs/contract/warnings.md#<code>` в ветке `main` |
| Диалоги вставки и одиночного ввода | причина отбраковки со строкой владельца (запись, строка ссылки, контейнер) |
| Debug API `GET /subs/{id}?warnings=true` | по узлу: `code, severity, path, value, params, applied, title_en, text_en` — пиненный английский; узлы без кодов дают `[]` |
| Debug API `GET /core_reject/notifications[?tag=]` | сохранённые коды отказов ядра так, как их отрисуют строка и карточка |

Размер словаря на контракте `1.1.99`: 108 кодов — 24 `error`, 54 `warning`, 30 `info`.
Тексты: `title_en/ru`, `text_en/ru`, необязательные `cause_*`, `fix_*[]`, `params[]`; `path` и
`value` — неявные подстановки.

## Входы / Выходы

**Входы:** код с `path`, `value`, параметрами и тегом владельца — от конвейера разбора, гейта
сборки, автомата отказов ядра или класса приложения; активная локаль.
**Выходы:** текст строки, блоки карточки, ссылка, карта Debug API.

## Правила и инварианты

- **Коды — стабильные имена.** Код — идентификатор конформанса, общий с корпусом лаунчера; он не
  меняет смысла, а выведенный из оборота код снимается в реестре, а не переименовывается в коде.
  Новое событие сначала получает код у лаунчера.
- **Severity берётся из реестра**, не из приложения; код, которого в реестре нет, — `warning`.
- **Незнакомый код показывается самим кодом**; у карточки без текстов реестра нет ни блоков, ни
  ссылки «Details». Незаполненный `{плейсхолдер}` остаётся виден намеренно.
- **Секреты остаются замаскированы** в карточке и в Debug API: `value` поля `secret` — `***`,
  даже если код пришёл не из санитайзера.
- **`applied: false`** заменяет «What happened» строкой «узел написан руками, приложение ничего в
  нём не меняло»; причина и способ исправления по-прежнему из реестра.
- **Счётчики считают записи, а не группы**, поэтому число совпадает со значками в списках.
- **Debug API не зависит от локали**: всегда `title_en` и `text_en`, какое бы ни было устройство.
- **Коды только приложения** (`duplicate`, `unknown_node_type`) держат тексты в приложении и не
  имеют `path`/`value`/`title_en`; `text_en` есть всегда.
- Язык: локаль `ru` читает `*_ru`, любая другая — `*_en`.
