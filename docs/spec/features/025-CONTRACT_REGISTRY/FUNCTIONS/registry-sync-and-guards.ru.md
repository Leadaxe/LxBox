# Синк реестра и стражи — контракт как поставка, которая не расходится молча

Реестр — версионированная поставка из репозитория лаунчера: один скрипт её копирует, один
lock-файл пинит, два зеркала везут, а набор стражей роняет сборку, когда что-то из этого расходится.

| Поле | Значение |
|------|----------|
| Фича | [025-CONTRACT_REGISTRY](../FEATURE.ru.md) |
| Обещания | P15 P16 P17 P18 P19 |
| Состояние | ✅ написана по коду, 2026-09-29 |

## Что делает

Делает «какой контракт исполняет эта сборка» фактом, который читается из дерева и проверяется CI,
и не даёт пропустить ручную правку любой копии. Источник контракта — репозиторий лаунчера
(`contract/`); у приложения только копии.

## Параметры

| Место | Что это | В git |
|---|---|---|
| репозиторий лаунчера, `contract/` | источник; каждая правка идёт туда | нет (чужой репозиторий) |
| `app/contract/` | вендорная копия: реестр, схема, документы, корпус | нет (gitignored) |
| `app/contract.lock` | `source`, `launcher_repo`, `source_sha`, `synced_at`, `sha256` копии | да |
| `app/assets/contract/` | зеркало в APK: `VERSION`, `registry/*.json`, `registry/protocols/*.json` | да |
| `docs/contract/` | байт-в-байт зеркало сгенерированных страниц (`index.md`, `warnings.md`, `protocols/*.md`) + сгенерированный `README.md` с версией, хешем и датой | да |

Текущее состояние: контракт `1.1.99`, `source_sha 6d53d58a`, синк `2026-09-27T22:22:09Z`,
`sha256 388251fc…`.

Режимы `app/tool/sync_contract.sh`:

| Вызов | Режим | Эффект |
|---|---|---|
| без аргументов | восстановление | пересобирает `app/contract/` из коммита лаунчера, записанного в lock, и сверяет хеш; зеркала и lock не трогаются |
| `--to <sha>` | бамп | копирует этот коммит лаунчера, переписывает lock и оба зеркала |
| `LX_CONTRACT_SRC=<путь>` | бамп | то же из рабочего каталога лаунчера |

## Входы / Выходы

**Входы:** коммит или каталог лаунчера; lock; дерево на диске.
**Выходы:** копия, lock, два зеркала; вердикты стражей в CI и в локальном прогоне тестов.

## Правила и инварианты

- **Хеш дерева считается по содержимому файлов** в байтовом порядке путей (имена не хешируются);
  сверка lock считает его так же, как скрипт.
- **Восстановление безопасно по умолчанию**: без аргументов скрипт никогда не тянет рабочее дерево
  лаунчера; бамп — явный.
- **Зеркала пересобираются только бампом**; ручная правка расходится с копией, роняет сверку lock
  и затирается следующим синком.
- **Сборка работает без репозитория лаунчера**: у CI и F-Droid копии нет; APK читает
  закоммиченное зеркало, поэтому реестровые тесты обязаны быть зелёными на одном зеркале.

| Страж | Что ловит | Где идёт |
|---|---|---|
| Сверка lock (`check_contract_lock`) | копия ≠ хеш lock; зеркало приложения ≠ копия файл в файл; зеркало документации ≠ сгенерированные страницы | CI-шаг «Contract lock» (без копии на CI — сообщает и проходит); локально с копией |
| Реестровые тесты ([486](../../../tasks/486-ci-registry-tests.md)) | словарь в коде разошёлся с реестром: отпечатки uTLS, коды бэкапа в обе стороны, лимиты; схемы тел грузятся и раскрываются; тексты всех кодов заполнены | CI, на зеркале, не скипаются |
| Тест зеркала документации | код без якоря в `warnings.md`; README зеркала называет другую версию | CI |
| Страж dart-ссылок ([491](../../../tasks/491-registry-dart-refs.md)) | `refs.dart` в записях реестра указывает на удалённый файл; протухшие — только из allowlist, который падает, когда запись снова становится верной | CI |
| Страж круга (476) | поле реестра, которое модель молча теряет | CI |
| Страж пропуска корпуса | перечисляет корпусные сьюты, пропущенные за отсутствием копии; утверждает, что зеркало есть | CI (громкий пропуск, зелёный) |
| Корпус конформанса (`contract/corpus/**`, [529](../../../tasks/529-contract-corpus-local-reds-triage.md)) | общее поведение разошлось с лаунчером: URI-кейсы, тела подписок, бэкапы, шаблоны, инварианты конвейера по схемам | только локально, с копией |
| Корпус публичных подписок ([525](../../../tasks/525-public-subscriptions-corpus.md)) | числа разбора уехали от эталона на 68 реальных списках | отдельный неблокирующий CI-джоб |

- Новая схема, форма тела или конструкция шаблона добавляется **вместе с фикстурой корпуса**;
  иначе другая сторона узнаёт о ней от пользователя.
- Обратная связь лаунчеру: недостающие ожидания корпуса и расхождения реестра уходят запросами
  (529, заметка в allowlist dart-ссылок).

## Границы

- Пин ядра, поставка AAR и ритуал приёма ядра (где синк — шаг 2) —
  [021-CORE_CONTRACT](../../021-CORE_CONTRACT/FEATURE.ru.md).
- CI-джобы и релизные проверки — [023-BUILD_CI_RELEASE](../../023-BUILD_CI_RELEASE/FEATURE.ru.md);
  свежий worktree не содержит ни AAR, ни копии.
- Процесс контракта целиком — `docs/CONTRACT.md`; сгенерированные страницы — `docs/contract/`.
- Корпус на CI не идёт; его красные кейсы видны только локально.
