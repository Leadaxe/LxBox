# Предупреждения разбора — коды причин для снятых полей и отброшенных записей

Каждое поле, которое разбор снял или заменил, и каждая отброшенная запись получают код с текстом из
реестра, общего с лаунчером.

| Поле | Значение |
|------|----------|
| Фича | [025-CONTRACT_REGISTRY](../FEATURE.ru.md) |
| Обещания | P2 P4 P5 P14 |
| Состояние | ✅ написана по коду, 2026-09-29 |

## Что делает

Объясняет пользователю, что разбор сделал с его данными: какое поле снято
или заменено, какой узел отброшен и почему. Коды и тексты общие с лаунчером —
одно событие называется одинаково в обоих приложениях. Сам словарь, уровни и
места показа кодов описаны в [warning-codes.md](warning-codes.ru.md).

## Параметры

| Уровень | Где живёт | Смысл |
|---------|-----------|-------|
| `error` | в отбраковке `dropped[]` источника | запись узлом не стала |
| `warning` | на узле | узел жив, поле снято или заменено |
| `info` | на узле или в отбраковке | справка: снято лишнее, служебная строка, баннер |

У кода: `code`, `path` (путь поля в теле), `value` (что было написано),
параметры подстановки, владелец (тег записи, строка ссылки, номер
контейнера). Текст — из реестра: короткий заголовок, развёрнутый текст,
«почему», «что сделать», ссылка «Learn more» на зеркало документации
контракта. Языки — `en`, `ru`; прочие локали получают `en`.

## Входы / Выходы

**Вход:** вердикты санитайзера, мапперов, дедупа, декодера.
**Выход:** список кодов на узле; список отбраковки источника.

## Правила и инварианты

- **Два прохода санитайзера.** По дословной карте JSON-записи — видит мусор
  провайдера (ключ вне схемы, запрещённый `flow`, чужое TLS-поле); по
  итоговому телу — видит значения, поставленные разбором, и всё тело
  ссылки/INI. При совпадении пары `(code, path)` остаётся дословная запись.
- **Одна пара `(code, path)` — одна запись**, рукописный код и код реестра
  не дублируются.
- **Код отбраковки — первый `error` по порядку полей тела**; нет ни одного —
  `type_invalid` с тегом.
- **Отбраковка — только в `dropped[]` источника**, на соседний рабочий узел
  не переносится.
- **Секреты:** `value` поля с признаком `secret` — `***` и в тексте, и в
  отбраковке, и в журнале.
- **Незнакомый код** показывается самим кодом с severity `warning`;
  незаполненный плейсхолдер текста остаётся как есть.
- **Коды пересчитываются при каждой загрузке**, не хранятся.
- Причины показываются пользователю, когда вставка или тело не дали ни одного
  узла; при живых узлах отбраковка видна в сводке источника
  ([001-SUBSCRIPTIONS](../../001-SUBSCRIPTIONS/FEATURE.ru.md)).

Характерные коды разбора: `scheme_unsupported`, `protocol_unsupported`,
`form_unrecognized`, `field_missing`, `type_invalid`, `uri_too_long`,
`core_rejected`, `duplicates_collapsed`, `provider_banner_link`, `unknown_key`,
`flow_deprecated`, `tls_not_applicable_quic`, `obfs_unknown`, `awg_mtu_clamped`,
`awg_mtu_high`, `wgconf_dns_ignored`, `detour_*`, `dialer_proxy_unusable`,
`unknown_node_type`. Полный словарь — `docs/contract/warnings.md`;
`unknown_node_type` — единственный собственный код приложения, в общем словаре его
нет (прежний собственный `duplicate` стал словарным `duplicates_collapsed`,
контракт 1.1.102, задача 589).

## Границы

- Какой код даёт конкретный дефект ссылки, тела или `.conf` — [002-NODE_IMPORT](../../002-NODE_IMPORT/FEATURE.ru.md)
  (его обещание [002-NODE_IMPORT · P5](../../002-NODE_IMPORT/FEATURE.ru.md#обещания) называет потерю).
- Показ кодов на строке узла и карточка «Why / What to do / Learn more» —
  [warning-codes.md](warning-codes.ru.md), [007-NODE_LIST](../../007-NODE_LIST/FEATURE.ru.md).
- Коды гейта сборки — [registry-gate.md](registry-gate.ru.md); отказы ядра после старта —
  [009-NODE_HEALTH](../../009-NODE_HEALTH/FEATURE.ru.md).
- Словарь кодов правится у лаунчера и приезжает синком.
