# Импорт узлов — ссылки, Xray и sing-box JSON, конфиги WireGuard и AmneziaWG в единой модели узла

LxBox разбирает share-ссылки прокси, JSON Xray и sing-box, конфиги WireGuard и AmneziaWG и профили
Amnezia `vpn://` в узлы sing-box. Поддерживаются схемы VLESS с REALITY, VMess, Trojan, Shadowsocks,
Hysteria2, TUIC, AnyTLS, SOCKS, HTTP, SSH, NaiveProxy, WireGuard и MASQUE. Каждая запись, не ставшая
узлом, получает код причины, а любой узел можно выгрузить обратно в share-ссылку. Правила разбора
берутся из реестра контракта, общего с лаунчером, поэтому оба приложения превращают один и тот же
ввод в один и тот же узел.

## Назначение

Узлы приходят в L×Box десятком форм: share-ссылка любого протокола, тело
подписки (список ссылок, base64, JSON), конфиг Xray или sing-box целиком,
файл `.conf` WireGuard/AmneziaWG, ссылка-профиль Amnezia `vpn://`. Фича
превращает любую из них в **один** вид узла — тело в форме ядра sing-box
(outbound или endpoint) с именем, источником и списком предупреждений — и
умеет обратно: собрать из узла share-ссылку.

Защищаемые принципы:

- **Одно правило — одно место.** Что считается допустимым значением поля,
  какие схемы ссылки есть и как они пишутся, какой текст у предупреждения —
  решает реестр контракта, общий с лаунчером. Приложение исполняет его, а не
  держит свою копию.
- **Ни одной молчаливой потери.** Запись, которая не стала узлом, называется
  кодом с причиной; одна битая запись не роняет соседей.
- **Узел, которого ядро не примет, не доживает до старта.** Он снимается при
  разборе, а не валит весь конфиг потом.

## Обещания

- **P1. Любая поддерживаемая схема ссылки даёт узел.** Набор схем и их
  написаний (`vless`, `vmess`, `trojan`, `ss`, `hysteria2`/`hy2`, `tuic`,
  `anytls`, `socks`/`socks5`/`socks4`/`socks4a`, `proxy-http(s)`/`proxy+http(s)`,
  `ssh`, `naive+https`/`naive+quic`, `wireguard`/`wg`/`awg`/`amneziawg`,
  `masque`, `vpn://`) берётся из реестра. Свидетель: юнит «`$proto/$name` parses
  + emits + round-trips» по фикстурам всех схем; юнит «контракт 1.1.48/49 —
  `amneziawg` в наборе БЕЗ правки кода». Мутация: схема, объявленная реестром,
  но не принятая диспетчером.
- **P2. Круг ссылка → узел → ссылка → узел не теряет узел.** Свидетель: юнит
  «`$scheme`: тело переживает сборку ссылки и обратный разбор»; юниты «весь
  корпус `<схема>` переживает круг» (vmess, shadowsocks и др.). Мутация: эмит
  ссылки пропускает параметр, который разбор читает.
- **P3. Форма тела опознаётся однозначно.** Каждый документ попадает ровно в
  один вид источника; base64-обёртка снимается не глубже двух слоёв, третий —
  отказ без исключения. Свидетель: юнит «каждый документ опознаётся ОДНОЗНАЧНО
  (победитель по priority один)»; юнит «3× — тихий отказ, узлов нет, без
  исключения». Мутация: две ветки вида источника с равным приоритетом
  совпадают на одном тексте.
- **P4. Битая запись не роняет соседей.** Свидетель: юниты «битая форма
  outbound не роняет соседей», «валидные соседи выживают рядом с мусором»,
  «искажённые ссылки никогда не бросают исключение» (malformed URIs). Мутация: исключение разбора одной
  записи прерывает цикл по телу.
- **P5. Потеря названа.** Незнакомая схема — `scheme_unsupported` со схемой,
  незнакомый тип записи — `protocol_unsupported`, непрочитанная оболочка —
  `form_unrecognized`, слишком длинная ссылка — `uri_too_long`, нераспознанное
  тело — `core_rejected` с причиной декодера. Исключение: строка вовсе без
  `://` отбрасывается молча. Свидетель: юниты группы «§506 п.2 — причина вместо
  молчания». Мутация: ветка отказа возвращает «нет узла» без кода.
- **P6.** перенесено в [025-CONTRACT_REGISTRY · P2](../025-CONTRACT_REGISTRY/FEATURE.ru.md#обещания).
- **P7.** перенесено в [025-CONTRACT_REGISTRY · P3](../025-CONTRACT_REGISTRY/FEATURE.ru.md#обещания).
- **P8. Повтор внутри одного тела схлопывается, между источниками — нет.**
  Ключ — содержимое узла без тега и `detour` плюс путь дозвона. Свидетель: юнит
  «`amneziawg://` и `vpn://` одного узла — один узел и `duplicate`»; юнит «дедуп
  не пересекает границы подписок»; юнит «D-086: разный SNI → ДВА узла». Мутация:
  ключ дедупа по четвёрке «схема+хост+порт+учётка».
- **P9. Порядок и имена многоузловых конфигов — авторские.** Узлы идут в порядке
  файла; имя сервера достаётся одиночному элементу, а не пулу. Свидетель: юниты
  «порядок списка — авторский, не отсортированный», «пул первым в файле
  остаётся первым в списке, имена от одиночных». Мутация: сортировка элементов
  по числу узлов остаётся в выдаче.
- **P10. Смена разборщика не меняет идентичность узлов.** Хеш, тег и тело
  каждого кейса корпуса совпадают со снимком до переезда на движок реестра.
  Свидетель: юнит «`$scheme`: хеш, тег и тело каждого кейса на месте»; юнит
  «wireguard: INI-кейсы дают прежние хеш, тег и тело». Мутация: изменён фолбэк
  тега безымянной ссылки.
- **P11.** перенесено в [025-CONTRACT_REGISTRY · P4](../025-CONTRACT_REGISTRY/FEATURE.ru.md#обещания).
- **P12.** перенесено в [025-CONTRACT_REGISTRY · P5](../025-CONTRACT_REGISTRY/FEATURE.ru.md#обещания).
- **P13. Ссылка с приватным ключом копируется только после подтверждения.**
  Свидетель: виджет-тест «роль private_key» и группа `copyNodeUri` (диалог
  «Link contains a private key», отмена не трогает буфер). Мутация: признак
  приватного ключа по классу узла, а не по роли поля в реестре.
- **P14. AmneziaWG получает потолок MTU 1280.** Ссылка/INI без MTU → 1280, выше
  → 1280 с кодом `awg_mtu_clamped`; обычный WireGuard не трогается; авторское
  тело sing-box сохраняет значение с info-кодом. Свидетель: юниты «AWG
  mtu=1420 → кламп до 1280», «plain WG не трогаем», «тело sing-box с mtu=1420:
  значение цело, код info». Мутация: кламп по протоколу `wireguard` без
  признака AWG.
- **P15. Баннер провайдера узлом не становится.** Ссылка на `0.0.0.0`,
  loopback или `localhost` отбрасывается кодом `provider_banner_link`, ремарка
  после `#` едет сообщением. Свидетель: юниты «баннер ЕДИНСТВЕННОЙ записью
  тела: узлов нет, причина названа», «ПОРТ признаком НЕ является». Мутация:
  проверка по порту `1`.
- **P16. Профиль OpenVPN `.ovpn` принимается.** `без свидетеля` — формат не
  реализован (решение владельца: отложено); принимается только готовое тело
  ядра `openvpn-client` (см. функцию sing-box JSON).

## Контролируемые параметры

Пользовательских настроек у фичи нет: поведение задают реестр контракта и
лимиты.

| Параметр | Значение | Источник |
|----------|----------|----------|
| Версия реестра контракта | `1.1.99`, едет в сборке приложения | [025-CONTRACT_REGISTRY](../025-CONTRACT_REGISTRY/FEATURE.ru.md) |
| Длина одной ссылки | ≤ 65536 символов, иначе `uri_too_long` | лимит реестра |
| Длина ссылки `vpn://` | ≤ 524288 символов | лимит реестра |
| Распаковка профиля Amnezia | ≤ 4 МиБ (анти-бомба) | лимит реестра |
| Глубина снятия base64-обёрток | 2 | `max_unwrap_depth` видов источника |
| Длина цепочки `detour` при импорте | ≤ 8 звеньев, дальше обрезается с кодом | лимит реестра |
| Потолок MTU AmneziaWG | 1280 | правило реестра `wireguard.mtu` |
| Комментарии в списке ссылок | строки с `#`, `//`, `;` | `line_comment_prefixes` |
| Цели-баннеры | `0.0.0.0`, `127.0.0.1`, `::`, `::1`, `localhost` | `banner_targets` |
| Служебные схемы | `incy`, `happ` с путём `routing/…` → info-код | `service_schemes` |

Ключи ядра, которые фича отдаёт: тело узла `outbounds[]` (типы `vless`,
`vmess`, `trojan`, `shadowsocks`, `hysteria2`, `tuic`, `anytls`, `socks`,
`http`, `ssh`, `naive`, `masque`, группы `selector`/`urltest`) и `endpoints[]`
(`wireguard` с полями AmneziaWG, `tailscale`, `openvpn-client`); поля
`tls`, `transport` (`ws`, `grpc`, `http`, `httpupgrade`, `xhttp`),
`multiplex`, `detour`, dial-поля TCP keep-alive — по схеме тела реестра.

## Входы / Выходы

**Входы:** текст одной ссылки; тело подписки или файла (список ссылок, base64
от него, JSON Xray/sing-box в любой из форм, `.conf`); ссылка-профиль
`vpn://`; подсказка имени (имя файла `.conf`); признак «свой источник»
(свой сервер или член папки — от этого зависит, авторское ли тело).

**Выходы:** список узлов — у каждого тело в форме ядра, имя (тег), исходный
текст, предупреждения `{code, path, value}`; список отбраковки `dropped[]` —
записи, не ставшие узлами, с кодом и владельцем (тег записи, строка ссылки
или номер контейнера); share-ссылка узла по запросу.

## Data flow

```
текст ─► опознание вида источника (реестр, до 2 слоёв base64)
          │
          ├─ список ссылок ─► по строке: диспетчер схем ─► маппер ссылки ─┐
          ├─ vpn:// ─► распаковка профиля ─► INI на контейнер ─► маппер conf ─┤
          ├─ .conf ─► маппер conf ──────────────────────────────────────────┤
          └─ JSON ─► обход элементов по пути реестра ─► маппер xray/singbox ─┤
                                                                            ▼
                               сырая карта в форме ядра ─► санитайзер по схеме тела
                                                            │ (снять узел / снять поле / код)
                                                            ▼
                                                 типизированная модель узла
                                                            ▼
             отбраковка по вердикту ─► дедуп внутри тела ─► коды по итоговому телу
                                                            ▼
                                              узлы + dropped[]
узел ─► эмит по секции emit реестра ─► share-ссылка (или отказ)
```

## Правила и гарантии

- Реестр — единственный источник схем, полей и текстов. Реестр не загружен —
  ссылки не разбираются вовсе (опознание формы тела работает и без него,
  запасным порядком). Тихого отката на рукописные правила нет.
- Санитайзер — единственный судья значений; модель кормится уже чистой картой.
- Имя узла: ремарка `#…` / `remarks` / `tag` / комментарий под `[Peer]` / имя
  файла; нет ничего — `<тип>-<хост>-<порт>`. Имя — это и идентичность узла.
- Исходный текст узла хранится как пришёл: ссылка байт в байт, объект
  outbound'а, INI-текст. Модель и предупреждения восстанавливаются из него.
- Авторское тело (свой сервер/член папки, вид `singbox_outbound`): реестр
  только сообщает, значения не меняет.
- Служебные outbound'ы (`direct`, `block`, `dns`, `freedom`, `blackhole`)
  узлами не становятся. Из целого конфига берутся только узлы и группы;
  `route`, `dns`, `inbounds` отбрасываются.

## Особенности сопровождения

- **Схема = данные.** Новая схема или алиас приезжает синком реестра; правка
  кода разбора под схему — признак ошибки (страж запрещает имена схем в движке).
- **Идентичность = тег.** Любая правка фолбэка имени или нормализации метки
  (например, флаг `🇪🇳` → `🇬🇧`) меняет идентичность живых узлов: сбрасывает
  выбор, выключение и правила. Снимок корпуса ловит это первым.
- **Дедуп по содержимому, не по адресу.** Один сервер под двумя SNI или прямой
  и через релей — разные узлы; огрубление ключа молча съедает записи.
- **Два прохода санитайзера.** По дословной карте (видит мусор провайдера) и
  по итоговому телу (видит поставленные разбором значения). Порядок значим:
  при совпадении `(code, path)` остаётся дословный.
- **Заметки реестра о Dart устаревают.** `emit.note` описывает поведение обеих
  сторон текстом и не проверяется тестами — верить тестам, а не заметке.
