# Импорт sing-box JSON

| Поле | Значение |
|------|----------|
| Фича | [002-NODE_IMPORT](../FEATURE.ru.md) |
| Обещания | P4 P8 P9 P16 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Переносит узлы из JSON в форме ядра: одиночный outbound, массив outbound'ов,
полный конфиг, массив конфигов. Пользователь sing-box вставляет свой конфиг
и получает те же узлы, группы и цепочки.

## Параметры

| Тип записи | Результат |
|------------|-----------|
| `vless`, `vmess`, `trojan`, `anytls`, `shadowsocks`, `hysteria2`, `naive`, `tuic`, `ssh`, `socks`, `http`, `masque` | узел с моделью |
| `wireguard`, `tailscale` (в `outbounds[]` или `endpoints[]`) | endpoint-узел |
| `openvpn-client` | узел, тело как написано, без проверок и предупреждений |
| тип вне реестра | из своего источника — узел с предупреждением `unknown_node_type`; из подписки — отбраковка `protocol_unsupported` |
| `urltest`, `selector` | группа того же рода; `selector` сохраняет `default` |
| `direct`, `block`, `dns` | не узлы |

## Входы / Выходы

**Вход:** JSON, опознанный как sing-box ([опознание тела](body-recognition.ru.md));
признак «свой источник». **Выход:** узлы (источник — сам outbound дословно,
расширенный источник — конфиг целиком), группы после своих членов,
отбраковка с тегом записи.

## Правила и инварианты

- **Имя** — `tag` записи; пустой — `<тип>-<хост>-<порт>`; повтор тега в
  конфиге — индексный суффикс.
- **Два прохода и дедуп** — как у Xray: имя от одиночного конфига, порядок
  файла, один сервер в двух конфигах под разными тегами — один узел.
- **`detour`.** Цель цепочки узлом не дублируется, а становится звеном
  владельца; одна цель у двух владельцев — копия каждому. Цепочки любой
  длины разворачиваются, звеном может быть любой тип; глубже 8 —
  обрезка с кодом `detour_chain_too_deep`. Цикл рвётся с кодом
  `detour_cycle_broken`, узлы не исчезают. Висячая ссылка —
  `detour_target_missing`; `detour` на группу — `detour_to_group`;
  `detour: direct` молча игнорируется.
- **Группы.** Состав — точные ссылки на разобранные узлы (не regex); состав
  на тегах соседнего конфига резолвится через синонимы; дубли схлопываются;
  вложенная группа выпадает из состава с кодом; пустой состав — группы нет.
  Отсутствующие параметры `urltest` получают дефолты приложения.
- **Из конфига берутся только узлы и группы**: `route`, `dns`, `inbounds`,
  `log`, `experimental`, секции узла — отбрасываются.
- **Битая запись** (мусорный тип поля) → `form_unrecognized` в отбраковке,
  соседи живут. Известный тип с негодной формой (нет `server`) отбрасывается,
  а не становится «чужим» узлом.
- **Авторское тело** (свой сервер или член папки, одиночный outbound):
  реестр ставит коды, но значения не меняет — тело уходит в ядро как написано.
  Тело из подписки чистится санитайзером.
- Тело `tailscale` отдаётся как есть; выход через узел — по признаку реестра.

## Границы

- Куда кладётся результат (один узел → свой сервер, больше → файловая
  подписка) — [001-SUBSCRIPTIONS](../../001-SUBSCRIPTIONS/FEATURE.ru.md).
- Проверка тела `openvpn-client` и чужих типов — ядро на старте; гейт тега
  сборки `with_openvpn` — [003-CONFIG_BUILD](../../003-CONFIG_BUILD/FEATURE.ru.md).
- **OpenVPN-профиль `.ovpn` не разбирается**: текст профиля уходит в ветку
  списка ссылок и даёт ноль узлов. Принимается только готовое тело
  `openvpn-client`.
