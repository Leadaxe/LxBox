# Запись и буфер — журнал сетевых событий по явной команде

Запись стартует только по START, живёт в фоне, держит журнал в выбранном
окне и под потолком и стирается перезапуском приложения.

| Поле | Значение |
|------|----------|
| Фича | [028-TRAFFIC_PROFILER](../FEATURE.ru.md) |
| Обещания | P1, P2, P3, P4, P5, P6 |
| Состояние | ✅ написана по коду, 2026-09-29 |

## Что делает

Вкладка Profiler экрана Statistics: по START подписывается на канал
профайлера ядра и превращает снимки соединений и DNS-события в журнал:
открытие и закрытие TCP/UDP-соединений, резолвы и сбои DNS. Журнал — окно во
времени с потолком; перезапуск приложения его стирает. Экспорт «сохраняет»
только вручную.

## Параметры

| Ручка | Значения | Дефолт |
|-------|----------|--------|
| Запись | START / STOP | остановлена |
| Окно хранения («Keep …») | 1m / 10m / 1h | 10m; сохраняется, входит в резервную копию |
| Отображение | Pause / Resume (замораживает список, запись идёт) | живое |

Фиксировано: потолок 20 000 событий; чистка по окну раз в 15 с; кольцо
событий без владельца — 50; «вероятный RST» — меньше 1 с и 0 байт.

## Входы / Выходы

**Входы:** START/STOP из заголовка вкладки или Debug API; снимки соединений
(`CommandConnections`) и DNS-события (`CommandDNS`) канала профайлера, только
пока идёт запись.

**Выходы:** события `tcpOpen` / `tcpClose` / `udpOpen` / `dnsResolve` /
`dnsFail`: время, приложение, домен, IP, порт, сеть, правило, цепочка групп,
detour-хвост, тип выхода, ↑/↓, длительность (у закрытия), признаки проблем;
заголовок «Recording system-wide events · время · N events» / «Not recording»
с подсказкой «Tap START to begin capture. Recording continues when you leave
this tab.»; чип `Live` на главном экране.

## Правила и инварианты

- **Запись явная и долгая.** Стартует только по START; повторный START —
  ничего. Продолжается при уходе с вкладки и сворачивании приложения
  ([012-LIVE_STATE · P3](../../012-LIVE_STATE/FEATURE.ru.md#обещания));
  STOP снимает подписку и замораживает журнал до следующего START, который
  очищает журнал и кольцо потеряшек.
- **Режимы Live / Aggregated** — способы показа одного журнала: поток
  событий (новые сверху) или своды по домену / IP
  ([filters-and-views](filters-and-views.ru.md)). Pause замораживает снимок
  потока; переход в свод снимает паузу.
- **Окно и потолок.** События старше окна вычищаются раз в 15 с; сверх 20 000
  — вытесняются старейшие. Смена окна действует на следующей чистке. Чистка,
  что-то убравшая, пересчитывает баннеры.
- **Две фазы соединения.** Новое соединение в снимке даёт событие открытия;
  исчезнувшее из снимка или помеченное ядром закрытым — событие закрытия.
  Байты открытого соединения обновляются без событий. Короткое соединение,
  открывшееся и закрывшееся между снимками, даёт обе фазы; повтор уже
  закрытого в следующих снимках дублей не даёт (память о закрытых — 5 мин).
- **Часы ядра.** Начало и конец берутся из меток ядра; метка меньше
  2000-01-01 — «нет данных», тогда время прихода. Отрицательная длительность
  из расхождения часов не показывается и на «вероятный RST» не судится.
- **Вероятный RST.** TCP, закрывшееся быстрее 1 с без единого байта, помечено
  ⚠ «Connection closed within 1s without bytes (likely RST / blocked)» —
  эвристика, ложные срабатывания возможны.
- Ошибка потока канала запись не роняет: следующий снимок придёт следующим
  тиком.
- Всё в памяти: перезапуск приложения стирает журнал.

## Границы

- Запись, начатая при опущенном туннеле или пережившая его перезапуск,
  получает канал обратно на следующем старте туннеля
  ([605](../../../tasks/605-service-live-automation-workspaces-bugs.md)). Возврат после смахивания из недавних останавливает
  осиротевший канал, буфер теряется ([591](../../../tasks/591-spec-kit-revision-audit.md)).
- Атрибуция владельца и маршрута — [attribution](attribution.ru.md);
  DNS-часть событий — [dns-trace](dns-trace.ru.md).
- Сохранённых сессий нет; экспорт — [filters-and-views](filters-and-views.ru.md).
