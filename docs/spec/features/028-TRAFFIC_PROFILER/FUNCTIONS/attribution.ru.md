# Атрибуция — какому приложению, правилу и маршруту принадлежит событие

Владельца, правило и путь пакета называет ядро; клиент показывает уровень
уверенности и не прячет события без владельца.

| Поле | Значение |
|------|----------|
| Фича | [028-TRAFFIC_PROFILER](../FEATURE.ru.md) |
| Обещания | P7, P8, P9 |
| Состояние | ✅ написана по коду, 2026-09-29 |

## Что делает

Каждое событие журнала отвечает на три вопроса: чьё оно (пакет приложения),
как роутер решил (правило и цепочка групп) и куда физически ушёл пакет
(detour, узел, цель). Все три ответа приходят из ядра вместе с соединением
или DNS-запросом; клиент ничего не сшивает по журналу ядра и не угадывает по
IP. Когда владельца нет, событие остаётся в журнале с пометкой.

## Параметры

Своих настроек нет. Фиксировано: тревога потеряшек — больше 5 сбойных
событий без владельца за 30 с; кольцо событий без владельца — 50.

## Входы / Выходы

**Входы:** из снимка соединения — пакет владельца или путь процесса, правило,
цепочка `chain` (узел и селекторы), хвост `detour`, тип выхода, домен и
адрес; из DNS-события — пакет владельца и канал сервера.

**Выходы:** в строке события — приложение (иконка и имя) или «(no owner)»,
красный бейдж `?` у события без владельца с подсказкой «confidence /
matched via / shown because»; в деталях — раздел «App» (приложение, уровень
уверенности, «Matched via», «Shown because») и раздел «Routing» (маршрутная
строка, правило, цепочка, detour, выход и его тип — те же строки, что у
живого соединения); баннер «N unattributed events / 30s — sing-box could not
detect the owner package for some DNS/TCP traffic» и ⚠ в названии вкладки.

## Правила и инварианты

- **Владелец из ядра.** У соединения — пакет, иначе путь процесса; у
  DNS-запроса — пакет. Строка берётся как есть: суффикс UID вида `(10999)`
  и список «пакет, пакет» атрибуцию не ломают.
- **Уровни уверенности.** `verified` — ядро назвало владельца, маркера нет;
  `unattributed` — владельца нет, бейдж `?` и «Shown because: system-wide DNS
  failure (no owner package detected)» у провала DNS. Уровни `secondary` и
  `inferred` спящие: в текущем коде не выставляются, значения оставлены,
  чтобы читать старые экспорты.
- **Тревога потеряшек.** В кольцо без владельца попадает каждое событие
  `unattributed`, но тревогой считаются только сбои: провал DNS и TCP/UDP без
  владельца. Больше 5 таких за 30 с — баннер и ⚠ на вкладке; успешный DNS без
  владельца — норма. Кольцо чистится по окну хранения, тревога гаснет сама.
- **Маршрутная строка.** `процесс ⇒ [сеть] правило ⇒ селекторы сверху вниз :
  detour → … → селектор (выбор) → цель · длительность`. Слева от `:` — ось
  решения, справа — физический путь; пустое правило — `final`; без домена —
  адрес; в потоке — компактная форма без префикса процесса. Цепочка групп и
  detour хранятся раздельно, строка совпадает 1:1 со строкой живого
  соединения ([012-LIVE_STATE](../../012-LIVE_STATE/FUNCTIONS/live-connections.ru.md)).
- Правило — строка ядра, не имя из справочника; фильтр по правилу и выходу
  — [filters-and-views](filters-and-views.ru.md).
- События без владельца видны в потоке и ловятся фильтром «Unattributed», но
  в своды по домену и IP не входят.

## Границы

- Владелец определяется ядром; ОС может не назвать его для части трафика
  (короткие соединения, системные процессы, WebView под другим UID) —
  деградация точности, не поломка. Зависит от возможностей ОС.
- Дополнительных пакетов (WebView) и вывода владельца по недавнему DNS-адресу
  больше нет (§044, §288).
- Атрибуция от «Forward sing-box logs» не зависит: после §180 владелец
  приходит структурным потоком; прежняя подсказка «DNS / router events off»
  удалена ([605](../../../tasks/605-service-live-automation-workspaces-bugs.md)).
