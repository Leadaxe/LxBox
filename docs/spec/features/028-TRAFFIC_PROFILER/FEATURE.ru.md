# Профайлер трафика — журнал соединений по приложениям, атрибуция и трасса DNS

LxBox записывает сетевые события всех приложений устройства — TCP/UDP-соединения
и DNS-запросы — с приложением-владельцем, правилом маршрутизации и узлом ядра
sing-box. Журнал живёт во вкладке Profiler экрана Statistics: фильтр по
приложению, правилу и выходу, группировка по домену или IP, экспорт в JSON и те
же данные через Debug API.

| Поле | Значение |
|------|----------|
| Фича | 028-TRAFFIC_PROFILER |
| Тип | Продуктовая фича |
| Поглотила | `§044F` |
| Состояние | ✅ написана по коду, 2026-09-29 |

## Назначение

Пользователь спрашивает «куда ходит это приложение и как оно роутится», «какое
приложение виновато» и «почему не резолвится». Фича отвечает без захвата
пакетов и root: по явной команде START записывает журнал всех сетевых событий
устройства, каждое — с владельцем, правилом, цепочкой групп и физическим путём
пакета, а DNS-запросы — с цепочкой CNAME, сервером и причиной сбоя.

Фича держит четыре принципа:

- **Запись явная.** Без START ничего не копится и подписки на ядро нет;
  начатая запись живёт, пока её не остановят или процесс не умрёт.
- **Владелец — из ядра.** Приложение соединения и DNS-запроса называет ядро;
  клиент ничего не угадывает. Событие без владельца видно и помечено, а не
  спрятано.
- **Наблюдатель включающий.** Событие с неизвестным владельцем или редким
  типом записи не отбрасывается — попадает в журнал с уровнем уверенности.
- **Всё в памяти.** Журнал — окно 1 мин / 10 мин / 1 ч с потолком 20 000
  событий; перезапуск приложения его стирает.

## Обещания

- **P1. Запись — только по явному START.** Без записи события не копятся.
  Свидетель: юнит «recording off → events ignored». Мутация: автостарт записи.
- **P2. START очищает прошлый журнал, STOP замораживает.** После STOP список
  остаётся до следующего START, который начинает с нуля. `без свидетеля`.
- **P3. Окно хранения выбирается и помнится.** 1 мин / 10 мин / 1 ч, дефолт
  10 мин, переживает перезапуск. Свидетель: юнит «profiler retention —
  default + round-trip + персист». Мутация: окно зашито константой.
- **P4. Квоты буфера.** События старше окна вычищаются раз в 15 с; сверх
  20 000 вытесняются старейшие; кольцо событий без владельца — 50.
  `без свидетеля`.
- **P5. Короткое соединение видно целиком и один раз.** Соединение, открытое и
  закрытое между тиками, даёт обе фазы; закрытое, приходящее в снапшотах ещё
  5 мин, закрывается ровно один раз. Свидетель: юниты «короткий conn сразу
  closedAt>0 → обе фазы», «тот же closed conn 2 тика → ОДИН close». Мутация:
  потребитель получает только живые соединения.
- **P6. Время соединения — по часам ядра.** Длительность считается от меток
  ядра, сентинел не превращается в 1970 год; «вероятный RST» — закрытие
  меньше чем за 1 с без байт. Свидетель: юниты «kernel-метки: duration от
  createdAt/closedAt», «сентинел closedAt=1 не превращается в 1970 год»,
  «TCP RST early flagged on close». Мутация: длительность от момента прихода
  снапшота.
- **P7. Владелец — из ядра, без владельца — видно.** Пакет приложения берётся
  из данных ядра как есть (суффикс UID и список из нескольких пакетов
  атрибуцию не ломают); событие без владельца помечено `unattributed` и
  «no owner». Свидетель:
  юниты «UID-suffixed package name → verified», «multi-package UID →
  verified», «tcp conn without owner → unattributed», «DNS fail with HTTPS
  record type — unattributed if no owner». Мутация: событие без владельца
  отбрасывается.
- **P8. Тревога потеряшек — только по сбоям.** Больше 5 сбойных событий без
  владельца (провал DNS, TCP/UDP без владельца) за 30 с зажигают баннер;
  успешный DNS без владельца — норма. Свидетель: юниты «unattributedBannerActive
  flips when many unattributed events arrive», «successful unattributed DNS
  resolves do NOT light the banner». Мутация: успешный DNS без владельца
  считается тревогой.
- **P9. Маршрутная строка одна для соединений и профайлера.** Слева — как
  выбирал роутер (`rule ⇒ группы`), справа от `:` — физический путь пакета;
  пустое правило — `final`; цепочка групп и detour несутся раздельно.
  Свидетель: юниты «§204 routingLineOf 1:1 Conn ↔ Event», «chains и detours
  несутся РАЗДЕЛЬНО», «routingLine: полная трассировка». Мутация: detour
  вклеен в цепочку групп.
- **P10. Оси фильтра независимы.** Внутри оси — ИЛИ, между осями — И; Protocol
  ловит семейство (DNS — резолв и сбой, TCP — открытие и закрытие);
  «Unattributed» — ИЛИ с выбранными пакетами; пустое правило ловится как
  `final`; Outbound — любое звено цепочки или detour. Свидетель: юниты
  «kind-ось по семейству: DNS ловит resolve+fail», «потеряшки — OR с
  выбранными app», «rule-ось: пустой rule ловится как final», «outbound-ось:
  ловит detour-звено», «rule + outbound ортогональны». Мутация: оси
  объединены через ИЛИ.
- **P11. Фильтр живёт всю сессию приложения.** Переключение вкладок и уход со
  статистики фильтр не сбрасывают; сброс — «Reset all» или перезапуск.
  Свидетель: юниты «фильтр переживает unmount/remount», «clearAll сбрасывает
  session-фильтр». Мутация: фильтр — поле экрана.
- **P12. Агрегаты честные, экспорт полный.** События без владельца в своды по
  домену и IP не входят; экспорт содержит список событий и пересчитанные
  своды. Свидетель: юниты «сериализует список + пересчитанные агрегаты»,
  «unattributed события не пачкают агрегаты». Мутация: потеряшки
  подмешиваются в свод.
- **P13. DNS приписан тому, что спросили.** Событие несёт исходный домен,
  цепочку CNAME отдельно и первый адрес ответа как IP; ответ ядра — полная
  строка записи, берётся значение. Свидетель: юниты «DNS chain attribution:
  CNAME-hops в answers, ip = финальный A», «rdata ПОЛНОЙ RR-строкой → берём
  значение». Мутация: домен события = финальная цель CNAME.
- **P14. Провал DNS — событие с причиной, редкий тип — не потеря.** Решает
  признак сбоя ядра, а не код ответа; неизвестный тип записи даёт `TYPE<N>`.
  Свидетель: юниты «DNS fail produces dnsTimeout issue», «HTTPS record DNS
  resolve is parsed with record_type=HTTPS», «SOA record (NXDOMAIN) is parsed
  without IP». Мутация: сбой по коду ответа.
- **P15. Трасса DNS-группы — только у групповых запросов.** Путь групп, пробы,
  веер и режим выживания видны в деталях; у обычных запросов этих полей нет;
  на провале трасса тоже есть. Свидетель: юниты «веер: путь, пробы и флаг
  fanned», «НЕ групповой запрос → ключей трассы нет», «dnsFail тоже несёт
  трассу». Мутация: пустые поля трассы на каждом событии.
- **P16. Деградация DNS распознаётся при живой связи.** Баннер — при доле
  сбоев ≥ 20 %, не меньше 3 сбоев за 30 с и только если за то же окно были
  соединения. Свидетель: юниты «3 fail из 10 + активность → unhealthy»,
  «5 fail 100%, но НЕТ conn-активности → healthy», «старые fail (>30с назад)
  не учитываются». Мутация: гейт активности убран.
- **P17. Debug API видит то же, что экран.** Маршруты `/profiler/live*`
  читают тот же журнал, стартуют и останавливают ту же запись, событие в JSON
  несёт сервер, источник и трассу группы. `без свидетеля`.

## Контролируемые параметры

| Настройка | Значения | Дефолт | Где |
|-----------|----------|--------|-----|
| Запись | START / STOP | остановлена | заголовок вкладки Profiler; `/profiler/live/start` · `stop` |
| Окно хранения («Keep …») | 1m / 10m / 1h | 10m | кнопка `⏱` в строке управления; входит в резервную копию |
| Отображение | Pause / Resume | живое | строка управления, только в режиме потока |
| Группировка («Grouping») | Event stream / Group by Domain / Group by IP | поток | строка управления |
| Фильтр («Filter») | оси Protocol, App, Rule, Outbound + поиск | пусто | окно «Filter events»; вся сессия приложения |

Фиксированные величины: потолок журнала 20 000 событий; кольцо событий без
владельца — 50; чистка по окну раз в 15 с; порог тревоги потеряшек — больше
5 за 30 с; детектор DNS — окно 30 с, доля ≥ 20 %, минимум 3 сбоя; «вероятный
RST» — меньше 1 с и 0 байт; перерисовка списка не чаще 0,7 с; снимок Debug API
— 1…600 с, по умолчанию 60.

**Контракт с ядром.** Ключей конфига фича не отдаёт. Потребляет канал
профайлера ядра ([012-LIVE_STATE](../012-LIVE_STATE/FEATURE.ru.md)):
`CommandConnections` (дельты; `chain`, хвост `detour`, тип выхода, владелец,
`createdAt`/`closedAt`) и `CommandDNS` (домен, тип, rcode, источник ответа,
признак и причина сбоя, владелец, сервер и его тип, канал, ответы, путь групп,
пробы, веер, выживание).

## Входы / Выходы

**Входы:** START/STOP (вкладка или Debug API); снимки соединений и DNS-события
канала профайлера, только пока идёт запись; жесты — пауза, окно хранения,
группировка, фильтр, поиск из деталей, экспорт.

**Выходы:** события `tcpOpen` / `tcpClose` / `udpOpen` / `dnsResolve` /
`dnsFail`; заголовок «Recording system-wide events · время · N events» /
«Not recording»; чип `Live` на главном экране и ⚠ на вкладке при тревоге;
листы деталей события и агрегата; баннеры «N unattributed events / 30s» и
«N% of DNS queries failing…» с листом «DNS queries are failing»; экспорт
«Share N events (JSON)» / «Copy JSON to clipboard»; ответы `/profiler/live*`.

## Data flow

```
START ──► подписка на канал профайлера (не спит в фоне)
ядро ──CommandConnections (дельты)──► диф снимков ──► open/close-события
     ──CommandDNS──► resolve/fail-события (+ трасса группы)
события ──► журнал (окно · 20 000) ──► поток / своды по домену и IP ──► экран
        ├─► кольцо без владельца (50) ──► тревога потеряшек ──► баннер, ⚠
        ├─► детектор здоровья DNS (30 с) ──► баннер ──► лист решений → 005-DNS
        └─► SSE ──► /profiler/live/stream; снимок ──► /profiler/live
STOP ──► отписка; журнал заморожен до следующего START
```

## Правила и гарантии

- Канал профайлера не засыпает при сворачивании приложения: начатая запись
  продолжается в фоне ([012-LIVE_STATE · P3](../012-LIVE_STATE/FEATURE.ru.md#обещания)).
- Каждое событие несёт уровень уверенности владельца: `verified` (ядро назвало
  пакет) или `unattributed`; уровни `secondary` и `inferred` спящие — в
  текущем коде не выставляются, оставлены ради чтения старых экспортов.
- Пауза замораживает только отображение; запись и журнал идут дальше.
- Своды считаются из полного журнала; поиск применяется к строкам свода.
- Перерисовка отстаёт от потока не больше чем на 0,7 с; события не теряются.
- Остановка туннеля фильтр и журнал не трогает.

## Границы

- Каналы данных, их энергомодель и переподключение — 012-LIVE_STATE. Канал
  профайлера сам не переподключается: запись, начатая при опущенном туннеле
  или пережившая его перезапуск, событий не получает, хотя чип `Live` горит
  (кандидат в задачу, [591](../../tasks/591-spec-kit-revision-audit.md)).
- Живые соединения, статистика, статус — 012-LIVE_STATE. Правило в журнале —
  строка ядра, а не имя из справочника 004-ROUTING; пустое — `final`.
- Настройки DNS, группы, FakeIP — 005-DNS; лист «DNS queries are failing»
  лишь ведёт туда.
- Транспорт, токен и справочник Debug API — 027-DEBUG_API; здесь только
  маршруты `/profiler/*`.
- Per-app-сессии, вкладка App и сохранённые сессии удалены (§288); разбор
  одного приложения — фильтром по App.
- Только L4: домен, IP, порт; заголовков HTTP, URL и задержек по доменам нет.
- Режима «запись только пока открыта вкладка» нет и не планируется
  (решение владельца 2026-09-29, аудит [591](../../tasks/591-spec-kit-revision-audit.md)): запись идёт от START до STOP.
- Зависит от возможностей ОС: владелец трафика; ОС может не назвать его для
  части соединений.

## Особенности сопровождения

- Ядро держит закрытые соединения 5 мин и шлёт их каждый тик: потребитель,
  не помнящий, что уже закрыл, плодит дубли (§176).
- `rdata` ответа DNS — полная строка записи, а не значение (§180).
- Метки ядра меньше 2000-01-01 — сентинелы «нет данных», не даты (§353).
- `extra` события обязано сериализоваться в JSON, иначе Debug API теряет
  сервер, источник и трассу группы, которые видит экран (§315).
- Плашка «DNS / router events off» над журналом осталась от разбора
  лога ядра; после §180 DNS идёт структурным потоком и от «Forward sing-box
  logs» не зависит (кандидат в задачу,  591).
- Экспорт выгружает весь журнал, а не отфильтрованный список, хотя
  сериализатор рассчитан на отфильтрованный (кандидат в задачу,  591).
