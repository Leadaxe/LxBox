# Статус и полоса трафика — состояние туннеля и счётчики на главном экране

Главный экран показывает рядом фазу туннеля от VPN-сервиса и цифры трафика от
ядра.

| Поле | Значение |
|------|----------|
| Фича | [012-LIVE_STATE](../FEATURE.ru.md) |
| Обещания | P1, P4 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Показывает, подключён ли туннель и что через него идёт, прямо на главном
экране: полоса под статусом несёт переданный объём, число соединений,
индикатор записи профайлера и время подключения. Тап по полосе открывает
Statistics.

## Параметры

Своих настроек нет.

## Входы / Выходы

**Входы:** статус службы туннеля (`connecting`, `connected`, `stopping`,
`disconnected`, `revoked` + причина); тики `CommandStatus` — `uplinkTotal` /
`downlinkTotal`, `memory`, `connectionsIn`, `connectionsOut`; время работы
туннеля, известное службе; признак записи профайлера; признак «обход VPN
разрешён в этой сессии».

**Выходы:**

| Элемент | Что показывает |
|---------|----------------|
| ↑ / ↓ | накопленный объём за сессию ядра |
| 🔗 N | `connectionsIn` — соединения приложений (= список на Stats) |
| 🗄 M | `connectionsOut` — соединения к серверам (узлам) |
| `Live` | идёт запись профайлера |
| время | сколько поднят туннель |
| ⚠ в заголовке Statistics | в этой сессии разрешён обход VPN — часть трафика может идти мимо |

Счётчики соединений показываются только при ненулевой сумме; долгое нажатие
даёт подсказку «App connections» / «Outbound connections to servers».

## Правила и инварианты

- **Два мира статуса.** Фаза туннеля приходит только от службы; каналы
  данных ядра (раздел [data-channels](data-channels.ru.md)) дают лишь цифры. Их
  подключение/отключение не отображается как статус туннеля. Поэтому сон
  каналов в фоне не слепит приложение к выключению туннеля.
- Повторный или запоздалый терминальный статус («Stopped» поверх уже
  остановленного) не рвёт живое состояние новой сессии.
- При возврате из фона статус службы перечитывается разово; расхождение с
  показанным прогоняется как обычное событие статуса.
- Тики статуса вне поднятого туннеля игнорируются.
- Счётчики на главном перерисовываются не чаще раза в секунду, даже если тики
  идут чаще.
- Числа согласованы: 🔗 главного ≈ «Connections» на Stats ≈ «active» во
  вкладке Conns; 🗄 — другая величина (физические соединения ядра наружу).
  Раньше показывалась сумма, не совпадавшая ни с одним экраном.
- Время подключения после смахивания из недавних и повторного открытия
  продолжает отсчёт от реального старта туннеля, а не от момента открытия
  (свежий старт — без коррекции, порог 2 с).
- Предупреждение об обходе отражает фактическое состояние текущей сессии,
  а не сохранённую настройку.

## Границы

- Сами переходы статуса, их сроки, «Connection lost» по тишине статуса —
  010-VPN_SERVICE.
- Скорость (байт/с) на главном не показывается — только накопленный объём.
- Зависит от возможностей ОС: доставка статуса службы при свёрнутом
  приложении, событие возврата из фона.
