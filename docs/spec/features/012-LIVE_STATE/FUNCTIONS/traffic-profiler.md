# Профайлер трафика (по приложениям)

| Поле | Значение |
|------|----------|
| Фича | [012-LIVE_STATE](../FEATURE.md) |
| Обещания | P9, P10, P11, P12, P13, P14 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Вкладка Profiler экрана Statistics: по явной команде записывает журнал всех
сетевых событий устройства — открытие и закрытие TCP/UDP-соединений,
DNS-резолвы и их сбои — с приложением-владельцем, правилом и маршрутом.
Отвечает на «куда ходит это приложение и как оно роутится» и «что вообще
происходит в сети» без выбора приложения заранее.

## Параметры

| Ручка | Значения | Дефолт |
|-------|----------|--------|
| Запись | START / STOP | остановлена |
| Окно хранения («Keep …») | 1m / 10m / 1h | 10m; сохраняется, входит в резервную копию |
| Отображение | Pause / Resume (замораживает список, запись идёт) | живое |
| Grouping | поток / by Domain / by IP | поток |
| Filter | Protocol: DNS, TCP, UDP · App: замеченные пакеты, «Unattributed (no owner)», «Add app from full list» · Rule · Outbound · поиск по домену/IP/приложению | пусто |

## Входы / Выходы

**Входы:** снимки соединений и DNS-события канала профайлера (см.
[data-channels](data-channels.md)), только пока идёт запись.

**Выходы:**
- события `tcpOpen` / `tcpClose` / `udpOpen` / `dnsResolve` / `dnsFail`: время,
  приложение, домен, IP, порт, сеть, правило, цепочка групп, detour-хвост,
  тип выхода, ↑/↓, длительность (у закрытия), признаки проблем;
- заголовок «Recording system-wide events · время · N events» / «Not
  recording»; чип `Live` на главном; ⚠ в названии вкладки при тревоге
  потеряшек;
- лист события (маршрутная строка, приложение с иконкой и именем, поля
  копируются, домен/IP/пакет — в поиск); лист агрегата (свод + все
  соединения по ключу);
- экспорт «Share N events (JSON)» / «Copy JSON to clipboard».

## Правила и инварианты

- **Запись явная и долгая.** Стартует только по START; продолжается при уходе
  с вкладки и сворачивании приложения; STOP замораживает журнал до
  следующего START, который его очищает. Без записи события не копятся.
- **Окно и потолок.** События старше окна вычищаются раз в 15 с; сверх
  20 000 — вытесняются старейшие. Смена окна действует сразу.
- **Две фазы соединения.** Новое соединение даёт событие открытия, исчезнувшее
  или помеченное ядром закрытым — событие закрытия. Короткое соединение,
  открывшееся и закрывшееся между снимками, даёт обе фазы; повтор уже
  закрытого соединения в следующих снимках дублей не даёт.
- **Часы ядра.** Начало и конец берутся из меток ядра (значения меньше
  2000-01-01 — «нет данных», тогда время прихода); отрицательная
  длительность не показывается.
- **Вероятный RST.** TCP, закрывшееся быстрее 1 с без единого байта,
  помечается ⚠ «likely RST / blocked» — эвристика, ложные срабатывания
  возможны.
- **Атрибуция.** Владелец — пакет из данных ядра, иначе путь процесса;
  суффикс вида `(10364)` снимается. Нет владельца — событие «no owner», оно
  видно в журнале и учитывается фильтром «Unattributed».
- **Тревога потеряшек.** Больше 5 сбойных событий без владельца (провал DNS,
  TCP/UDP без владельца) за 30 с → баннер «N unattributed events / 30s» и ⚠
  на вкладке. Успешный DNS без владельца — норма, не тревога.
- **Группировка.** По домену / по IP — счётчики, порты, объём; события без
  владельца в агрегаты не входят.
- **Фильтр.** Внутри оси — ИЛИ, между осями — И; «Unattributed» — ИЛИ с
  выбранными пакетами; Protocol ловит семейство (DNS — и резолвы, и сбои;
  TCP — открытие и закрытие); Outbound — любое звено цепочки или detour.
  Счётчик активных — «Filter (N)». Фильтр живёт всю сессию приложения,
  не сбрасывается остановкой туннеля; сброс — «Reset all».
- **Экспорт** — весь журнал текущего снимка с пересчитанными агрегатами.
- Всё в памяти: перезапуск приложения стирает журнал.
- Перерисовка — не чаще 0,7 с; события при этом не теряются.

## Границы

- Per-app-сессии, вкладка App и сохранённые сессии удалены: только общий
  журнал с фильтром по приложению.
- DNS-часть событий — [dns-trace](dns-trace.md).
- Выдача журнала через Debug API — 013-DIAGNOSTICS.
- Владелец определяется ядром; ОС может не дать его для части трафика.
