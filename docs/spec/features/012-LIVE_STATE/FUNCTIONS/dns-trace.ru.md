# Трасса DNS-запросов — кто спросил, что ответили и почему не разрешилось

Трасса — часть журнала профайлера и пишется только во время записи.

| Поле | Значение |
|------|----------|
| Фича | [012-LIVE_STATE](../FEATURE.ru.md) |
| Обещания | P15, P16, P17, P18 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Во время записи профайлера показывает каждый DNS-запрос устройства: кто
спросил, что спросил, что ответили (с цепочкой CNAME), какой сервер и через
какой канал ответил, из кэша ли ответ, а для DNS-групп — кого опрашивали и
чем кончилось. Замечает, когда DNS массово не резолвится при живой связи, и
подсказывает, что делать.

## Параметры

Своих настроек нет; работает, пока идёт запись профайлера
([traffic-profiler](traffic-profiler.ru.md)).

## Входы / Выходы

**Входы:** поток `CommandDNS` ядра — домен, тип запроса, rcode, TTL, источник
ответа (`exchanged` / `cached` / `optimistic` / `refreshed` / `rejected` /
`failed`), признак сбоя и причина, владелец, DNS-сервер и его тип, канал
сервера, ответы, путь групп, пробы (`answered` / `timeout` / `network_error`
/ `servfail` + RTT), признаки веера и выживания.

**Выходы:** события `dnsResolve` / `dnsFail` в журнале; в деталях — сервер,
тип сервера, источник, ответ, путь групп, пробы, веер, выживание; бейдж
`cached` в строке; баннер «N% of DNS queries failing while the connection is
alive — tap to fix» и лист «DNS queries are failing» с кнопками «Open DNS
settings», «Enable FakeIP», «Close».

## Правила и инварианты

- Домен события — тот, что спросило приложение; цели CNAME — отдельной
  цепочкой; IP — первый адрес A/AAAA ответа; у неадресных ответов значение
  идёт в «answer». Ответ ядра приходит полной строкой записи — берётся
  значение.
- Тип запроса — имя записи (A, AAAA, CNAME, HTTPS, SVCB, SOA…); неизвестный
  код — `TYPE<N>`; события не теряются из-за редкого типа.
- Сбой определяется признаком сбоя ядра: часть сбоев приходит с настоящим
  кодом ответа. Причина — текст ядра, иначе «no response» (rcode `-1` —
  ответа не было вовсе), иначе «rcode N». Событие сбоя несёт ⚠ «DNS exchange
  failed: …» и трассу группы.
- Канал сервера — выбранный узел (селектор развёрнут ядром); пусто —
  напрямую или ответ из кэша.
- Владелец — из ядра; нет владельца — «no owner», тревогой считается только
  сбой (см. [traffic-profiler](traffic-profiler.ru.md)).
- Трасса группы пишется только для запросов через DNS-группу, флаги веера и
  выживания — только когда истинны; на попадании в кэш проб нет; опоздавшие
  ответы веера в трассу не входят.
- **Здоровье DNS.** Скользящее окно 30 с по журналу: «деградация», если сбоев
  ≥ 3, их доля ≥ 20 % и за окно были соединения. Без соединений (простой) —
  молчание. Сбои старше окна не считаются.

## Границы

- Перехваченные ядром DNS-запросы в соединения не попадают — только сюда.
- Без записи профайлера DNS-события не собираются и детектор молчит.
- Состояние DNS-групп целиком, настройки DNS и FakeIP — 005-DNS; лист лишь
  ведёт туда.
- История не хранится ядром: поток — с момента подписки.
