# Живые соединения

| Поле | Значение |
|------|----------|
| Фича | [012-LIVE_STATE](../FEATURE.md) |
| Обещания | P7, P8, P22 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Вкладка Conns экрана Statistics: список соединений ядра в реальном времени
(новые сверху) с приложением-владельцем, маршрутом и трафиком; детали по
тапу; закрытие одного или всех. Показывает, через какое правило, группы,
узел и detour-хвост ушло соединение, и подсвечивает зависшие.

## Параметры

| Ручка | Значения | Дефолт |
|-------|----------|--------|
| Хранение закрытых | «Closed kept 30s» / «Keeping all closed» | 30 с; не сохраняется |
| Interrupt connections on switch (010) | вкл/выкл | выкл |

## Входы / Выходы

**Входы:** снимок соединений (живые и закрытые); справочник правил; жесты —
тап, ×, «Close all».
**Выходы:** строка соединения; лист деталей; вызовы `closeConnection`,
`closeConnections`; заголовок «N active / M total».

Строка: иконка приложения (или стрелка TCP/UDP, у закрытых — галочка),
`host:port`, ↑/↓, ×; вторая строка — маршрутная строка и справа возраст
или «closed». Лист деталей — непустые поля группами (адреса, маршрут,
трафик, время, приложение), тап копирует значение, «Copy JSON», «Close».

## Маршрутная строка (восстановление цепочки)

`rule ⇒ группы : detour-вход → … → выход (селектор (выбор)) → цель`

- Слева от `:` — ось решения: правило (имя из справочника, пусто — `final`),
  затем группы-селекторы сверху вниз.
- Справа — физический путь пакета: detour-хвост узла развёрнут так, что
  ближайший к телефону транспорт первым; выход — узел, завёрнутый в свои
  селекторы; последним — домен или хост назначения.
- Цепочка групп (`chain`) и detour-хвост (`detour`) приходят из ядра
  раздельно и не склеиваются. Пустая цепочка — берётся выбранный узел.
- Пара «селектор + его выбор» схлопывается в `селектор (выбор)`.
- Та же строка — в журнале профайлера ([traffic-profiler](traffic-profiler.md)).

## Правила и инварианты

- «Однобокое» соединение (розовый фон, бейдж «One-way» и пояснение в
  деталях): TCP, прожившее ≥ 3 с, трафик строго в одну сторону. UDP, свежие,
  закрытые, без времени старта и нулевые — не помечаются.
- Закрытым соединение считается по метке ядра или по исчезновению из снимка.
  Закрытые остаются серыми 30 с либо до выключения режима «все».
- «Close all» сразу помечает живые закрытыми, не дожидаясь ядра; snackbar —
  «Closed N connections» / «No active connections to close» / «Failed to
  close connections (tunnel down?)».
- Обрыв при смене узла: после успешного выбора узла, при включённой
  настройке, закрываются живые соединения, в цепочке которых есть
  переключаемая группа (не дольше 5 с, ошибки отдельных закрытий
  игнорируются). Выбор уже активного узла ничего не рвёт.
- Перерисовка списка — не чаще 0,7 с; учёт закрытий — на каждом снимке.

## Границы

- Экран живёт внутри Statistics; отдельного экрана нет.
- История дольше окна ядра (5 мин) не хранится; накопление «все» — только
  пока открыт экран.
- Настройка обрыва и сам выбор узла — 010-VPN_SERVICE / 007-NODE_LIST.
