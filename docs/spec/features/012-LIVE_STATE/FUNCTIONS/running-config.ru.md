# Работающий конфиг и вердикт свежести

| Поле | Значение |
|------|----------|
| Фича | [012-LIVE_STATE](../FEATURE.ru.md) |
| Обещания | P20, P21 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Держит снимок конфига, из которого реально построено работающее ядро, и
отвечает на вопрос «отличается ли сохранённый конфиг от работающего». Пока
туннель поднят, всё, что показывается про узлы (список, тип, путь), берётся
из работающего конфига, а не из файла, который мог уже уйти вперёд.

## Параметры

Своих настроек нет.

## Входы / Выходы

**Входы:** `GetRunningConfig` (канонический JSON работающего ядра, с
наложенными стартовыми переопределениями); сохранённый конфиг;
`FormatConfig` ядра; стартовые переопределения туннеля (`auto_redirect`,
дописанный свой пакет в `include_package`).

**Выходы:** снимок работающего конфига на сессию; модель узлов для экранов;
вердикт `fresh` / `stale` / `unknown`.

## Правила и инварианты

- **Когда снимается.** На переходе туннеля в «подключён» и после
  перезагрузки ядра; не побочным эффектом прихода групп.
- **Принадлежность сессии.** Каждое обнуление снимка открывает новую сессию;
  ответ, пришедший от прежней, отбрасывается. Одновременно идёт не больше
  одного захвата.
- **Ретраи.** До 12 попыток с шагом 0,4 с (ядро ещё не запущено — ответа
  нет). После перезагрузки первый запрос — через 1,2 с, и ответ, равный
  прежнему снимку, считается «ядро ещё старое»; если ядро все попытки
  стабильно отдаёт то же — это идентичный конфиг, он принимается.
  Исчерпали попытки без ответа — снимка нет до конца сессии.
- **Какая модель показывается.** Туннель поднят и снимок есть — работающий;
  туннель опущен или снимка нет (старое ядро, гонка) — сохранённый.
- **Вердикт.** Сохранённый конфиг приводится к канону ядра (`FormatConfig`)
  после наложения тех же переопределений, что делает ядро: только первый
  tun-вход; `auto_redirect` присваивается (и `false` перетирает профиль);
  свой пакет дописывается в конец `include_package` без сортировки и
  дедупликации, только в режиме «только выбранные»; нет tun-входа — ничего.
  Затем строки сравниваются: равны — `fresh`, нет — `stale`.
- Нет снимка, нет канона, не удалось узнать переопределения — `unknown`.
  `unknown` плашку не гасит: лишняя плашка лучше пропущенного изменения.
- Вердикт вызывается только чтобы погасить ложную плашку при поднятом
  туннеле; поднять её он не может.

## Границы

- Когда показывать плашку «нужен перезапуск» и что её поднимает —
  003-CONFIG_BUILD.
- Просмотр итогового конфига — 019-CONFIG_EDITOR.
- На ядре без `GetRunningConfig` снимка нет, всё работает по сохранённому.
