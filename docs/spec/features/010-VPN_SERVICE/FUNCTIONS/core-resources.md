# Ресурсы ядра: сон WireGuard-туннелей и лимит памяти

| Поле | Значение |
|------|----------|
| Фича | [010-VPN_SERVICE](../FEATURE.md) |
| Обещания | P17, P18 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Держит память и батарею под контролем при многих WireGuard/AmneziaWG-узлах:
усыпляет простаивающие туннели (они просыпаются сами при первом обращении),
собирает туннель только при первом использовании и ограничивает число
собранных одновременно. Отдельно — задаёт потолок памяти ядра.

## Параметры

| Настройка (Настройки VPN → System) | Значения | Дефолт | Ключ ядра |
|-----------------------------------|----------|--------|-----------|
| Suspend idle tunnels | Off / 30 s / 2 min / 5 min | 30 s | `lx.wg.idle_suspend` |
| Suspend active-route tunnels | Off / 5 / 15 / 30 min / 1 h | 5 min | `lx.wg.idle_suspend_reachable` |
| Lazy tunnel build | вкл/выкл | вкл | `lx.wg.lazy_build` |
| Built tunnels limit | 0 (без потолка) / 3 / 5 / 8 / 12 | 5 | `lx.wg.build_max` |
| Memory limit (Optimization) | Auto / Off / 200 / 384 / 512 / 768 MB | Auto | параметр запуска ядра `oomMemoryLimit` |

Все пять входят в резервную копию.

## Входы / Выходы

**Вход:** выбор пользователя.
**Выход:** блок `lx.wg` в конфиге ядра; потолок памяти в параметрах ядра.

## Правила и инварианты

- «Suspend idle tunnels» усыпляет туннели, которые не лежат на активном
  маршруте и простаивают дольше порога. Off — блок `lx` не пишется вовсе
  (ядро не запускает счётчик простоя).
- «Suspend active-route tunnels» — второе, длинное окно для туннелей активного
  маршрута (выбранный узел, члены пула); первое соединение после сна дольше на
  ~1 RTT. Пишется только вместе с первым порогом; без него строка
  затемнена и недоступна (ядро отвергает окно без порога).
- «Lazy tunnel build» и «Built tunnels limit» пишутся только вместе с порогом
  сна; при выключенной ленивой сборке не пишутся ни `lazy_build`, ни
  `build_max`. `0` пишется как есть — без потолка.
- Устаревший `route.lx_idle_suspend` не пишется никогда: ядро выдаёт
  предупреждение на каждый такой ключ.
- Изменение любого из четырёх WG-параметров — «Applies on next connect.» и
  пометка «нужен перезапуск».
- Лимит памяти: Auto подбирает потолок по объёму памяти устройства (до
  3,5 ГиБ — 200 МБ, до 7 ГиБ — 384 МБ, больше — 512 МБ); Off снимает потолок,
  но наблюдение за нехваткой памяти в системе остаётся; неизвестное значение
  (например, из чужой версии) ведёт себя как Auto. Потолок сборщика мусора
  применяется к работающему ядру сразу («Applied.», без перезапуска); порог
  аварийной выгрузки по памяти — со следующего подключения.
- Слишком низкий лимит держит процессор в сборке мусора и греет телефон —
  поэтому потолок настраиваемый, а не жёсткие 200 МБ.

## Границы

- Выключение/включение отдельного WG/AWG-узла на лету и его состояние
  (спит/собран) — 012-LIVE_STATE / 008-NODE_EDITOR.
- Пассивная проверка здоровья и интервалы URLTest — 009-NODE_HEALTH.
- Сон туннеля целиком — [tunnel-sleep](tunnel-sleep.md).
- Зависит от возможностей ОС: объём памяти устройства, политика выгрузки
  процессов при нехватке памяти.
