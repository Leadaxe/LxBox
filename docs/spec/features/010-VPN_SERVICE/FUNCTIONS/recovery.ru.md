# Восстановление туннеля — подъём после гибели процесса и падения ядра

Туннель поднимается снова после гибели процесса приложения, следующий старт
после падения ядра чистит кэши, а приложение перестаёт показывать
«Connected», когда ядро не отвечает.

| Поле | Значение |
|------|----------|
| Фича | [010-VPN_SERVICE](../FEATURE.ru.md) |
| Обещания | P12, P13, P14 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Три пассивных механизма, каждый против своей беды: туннель поднимается сам
после гибели процесса приложения; после аварийного падения ядра следующий
запуск чистит кэши, которые могли его уронить; открытое приложение замечает,
что ядро перестало отвечать, и не показывает «Connected» над мёртвым туннелем.
Активного сторожа с пробами и автоматическим сбросом сети нет — от него
отказались ради батареи.

## Параметры

Своих настроек нет. Фиксированные значения:

| Что | Значение |
|-----|----------|
| Худшее время автоподнятия после гибели процесса | ~3,5 мин (раньше — при пробуждении экрана) |
| Лимит автоподнятий | 2 в окне 5 мин; третье не выполняется |
| Проверка живости ядра (приложение на экране) | каждые 5 с, «тишина» > 8 с, 2 подряд → потеря |

## Входы / Выходы

**Входы:** гибель процесса при поднятом туннеле; непустой отчёт о падении ядра
с прошлого запуска; поток статуса ядра.
**Выходы:** автоматический старт туннеля; уведомление «VPN stopped — VPN was
restarted too many times after the app was killed. Start it manually.»;
очищенные кэши ядра; статус «Connection lost — VPN tunnel is not responding».

## Правила и инварианты

- Туннель считается «желаемым» с момента подтверждённого старта до любой
  подтверждённой остановки (ручной стоп, стоп по ошибке, перехват слота).
  Автоподнятие работает только для желаемого туннеля — ручной стоп не
  воскрешается.
- Живая служба регулярно откладывает страховочный будильник, поэтому в
  здоровом состоянии лишних пробуждений нет. Будильник не будит спящее
  устройство — срабатывает при первом пробуждении.
- Успешный старт обнуляет счётчик автоподнятий. При исчерпании лимита
  «желание» снимается, показывается уведомление, туннель остаётся выключенным.
- Если в шторке осталось уведомление от погибшей службы, открытие приложения
  его убирает.
- Падение ядра на прошлом запуске → до старта ядра удаляются кэш ядра
  (FakeIP-адреса, DNS-кэш, выбор в группах) и временные файлы. Конфиг, гео-базы,
  rule-set, отчёты о падении и пользовательские данные не трогаются. Срабатывает
  один раз на одно падение.
- Проверка живости работает, только пока приложение на экране; в фоне она
  выключена, а о гибели туннеля сообщает событие службы. Первая проверка после
  возврата из фона не штрафуется; одна вибрация на серию сбоев.
- Потеря живости: пробы узлов останавливаются, данные сессии очищаются,
  выполняется попытка штатной остановки. Это не считается перехватом слота.

## Границы

- Активный сторож по URL-тестам и отсутствию трафика (§042F) — отказ,
  won't-fix; эскалирующее «лечение после сна» (§088) — отложено.
- Баннер «ядро падало» и отчёт о падении — [013-DIAGNOSTICS](../../013-DIAGNOSTICS/FEATURE.ru.md).
- Зависит от возможностей ОС: перезапуск службы системой, доставка
  отложенного будильника, агрессивная чистка фона прошивкой.
