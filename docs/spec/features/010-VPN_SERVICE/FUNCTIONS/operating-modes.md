# Режимы работы: VPN / Proxy / VPN+Proxy

| Поле | Значение |
|------|----------|
| Фича | [010-VPN_SERVICE](../FEATURE.md) |
| Обещания | P5, P6 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Выбирает, как ядро принимает трафик: системный туннель для всего устройства,
локальный прокси-порт, в который приложения ходят по явной настройке, или оба
сразу. Для порта задаёт протокол, адрес, номер и авторизацию. Для туннеля —
разрешение приложениям обходить его.

## Параметры

| Настройка | Значения | Дефолт |
|-----------|----------|--------|
| VPN mode | `vpn` — системный туннель; `proxy` — только порт; `vpn_proxy` — оба | `vpn` |
| Local proxy protocol | `mixed` (HTTP+SOCKS5 на одном порту), `http`, `socks` | `mixed` |
| Listen address | любой IPv4; в списке `127.0.0.1` (только это устройство), `0.0.0.0` (LAN) | `127.0.0.1` |
| Listen port | 1024..65535 | 2080 |
| Require authentication | вкл/выкл; вне `127.x` — принудительно вкл | вкл |
| Username / Password | строка / пароль с кнопками «Show», «Regenerate» | `user` / генерация 32 hex |
| Allow VPN bypass | вкл — приложения могут явно выйти мимо туннеля | выкл |

Порт-настройки видны только в режимах с портом; «Keep VPN on exit» и «Allow VPN
bypass» — только в режимах с туннелем.

## Входы / Выходы

**Вход:** выбор пользователя (экран режима, Debug API).
**Выход в конфиг ядра:** `inbounds[]` —
`{type: tun, tag: tun-in, …}` в `vpn`/`vpn_proxy`;
`{type: mixed|http|socks, tag: mixed-in, listen, listen_port, users?}` в
`proxy`/`vpn_proxy`. Тег `mixed-in` не зависит от протокола. `users` пишется
только при действующей авторизации и непустом пароле. `route.final` от режима
не зависит.

## Правила и инварианты

- Режим `vpn` даёт тот же конфиг, что и до появления режимов; отсутствующая
  настройка = `vpn`.
- Правила разбора трафика (resolve, sniff) действуют на вход порта так же, как
  на туннельный: в `proxy` они переезжают на порт, в `vpn_proxy` действуют на
  оба; отключённый sniff не появляется ни на одном. Перехват DNS действует на
  все входы.
- Адрес не из `127.x` делает авторизацию обязательной, тумблер залочен;
  включение авторизации, выбор такого адреса или режима с портом при пустом
  пароле генерирует пароль. Один и тот же инвариант держат экран и Debug API.
- Неверный порт (вне 1024..65535) или неверный IPv4 — ошибка под полем, значение
  не сохраняется. Debug API отвергает неверный порт и протокол.
- Цифровой пароль остаётся строкой в конфиге (без приведения к числу).
- Смена режима выставляет признак «есть туннель», который решает, нужен ли
  запрос системного VPN-разрешения (см. [foreign-vpn](foreign-vpn.md)).
- Любая смена режима или порт-настроек помечает «нужен перезапуск».
- «Allow VPN bypass» действует с ближайшего поднятия туннеля; значение,
  применённое в текущей сессии, отдаётся отдельно от сохранённого.

## Границы

- Регистрация порта как системного прокси — не делается.
- Два протокола на двух портах одновременно — не делается.
- Адрес, MTU, стек, IPv6 туннельного интерфейса — переменные шаблона,
  003-CONFIG_BUILD.
- Какие приложения идут через туннель — 011-SPLIT_TUNNELING.
- Зависит от возможностей ОС: единственный системный VPN-слот, механизм обхода
  туннеля приложениями.
