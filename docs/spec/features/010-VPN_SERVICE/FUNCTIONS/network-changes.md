# Реакция на смену сети и смену узла

| Поле | Значение |
|------|----------|
| Фича | [010-VPN_SERVICE](../FEATURE.md) |
| Обещания | P15, P19 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Не даёт приложениям висеть на соединениях, которые умерли вместе со старой
сетью или со старым узлом: при реальной смене сети сбрасывает соединения
ядра, при включении экрана просит ядро перепривязать стухшие WireGuard-сессии,
при смене узла (по желанию) рвёт соединения переключаемой группы.

## Параметры

| Настройка | Где | Значения | Дефолт |
|-----------|-----|----------|--------|
| Interrupt connections on switch | Настройки VPN → System | вкл/выкл | выкл |

Фиксированные значения: тишина перед сбросом при смене сети — 1,5 с; бюджет
обрыва соединений при смене узла — 5 с.

## Входы / Выходы

**Входы:** смена, потеря и появление сети по умолчанию (всегда физической, не
собственного туннеля); включение экрана; выбор другого узла в группе.
**Выходы:** вызовы ядра `resetNetwork` (закрыть соединения, сбросить DNS-кэш,
перепривязать исходящие), `rebindStaleEndpoints`, `closeConnection` по каждому
соединению группы; сообщение ядру о текущем интерфейсе или его отсутствии.

## Правила и инварианты

- Сброс соединений — только на реальную смену интерфейса: прежний и новый
  интерфейсы известны и различаются. Первое подключение, обновление свойств
  той же сети и потеря сети сброса не дают; пачка событий схлопывается в один
  сброс.
- Потеря сети: ядру сообщается «интерфейса нет», сброса нет (переподключаться
  некуда). Прежний интерфейс помнится, поэтому переход «Wi-Fi → нет сети → LTE»
  всё равно даёт сброс.
- Сеть по умолчанию для ядра и для локального DNS-разрешения — всегда
  физическая сеть, никогда собственный туннель (иначе DNS уходит по кругу).
  Пока физической сети нет, локальное DNS-разрешение сразу отвечает ошибкой, а
  не ждёт.
- Включение экрана в любом режиме сна просит ядро перепривязать только
  доказуемо стухшие WG/AWG-сессии; решение и дебаунс — на стороне ядра, вызов
  не блокирует.
- Обрыв при смене узла: выполняется только если включён тумблер и выбор узла
  ядро приняло; рвутся только живые соединения, в цепочке которых есть
  переключаемая группа; ошибки отдельных соединений игнорируются, общий
  бюджет 5 с. Выбор уже активного узла — ничего не делает и ничего не рвёт.
- Ручной сброс сети есть только в Debug API: при подключённом туннеле, не чаще
  раза в 3 с.

## Границы

- Разрыв соединений самим ядром при смене выбора группы (опция Направления
  `interrupt_exist_connections`) — 006-DETOUR_AND_BALANCE / 007-NODE_LIST.
- Глубокий сон устройства как повод для паузы — [tunnel-sleep](tunnel-sleep.md).
- Условия правил по сети Wi-Fi — 004-ROUTING.
- Зависит от возможностей ОС: события сети по умолчанию, их порядок и
  задержка появления интерфейса, событие включения экрана.
