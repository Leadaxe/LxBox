# Управление туннелем

| Поле | Значение |
|------|----------|
| Фича | [010-VPN_SERVICE](../FEATURE.md) |
| Обещания | P1, P2, P3, P4, P20 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Старт, стоп, перезагрузка ядра и переподключение туннеля — из приложения и из
уведомления службы. Держит честный статус: у каждой переходной фазы есть срок,
по истечении которого зависшее ядро гасится принудительно, а пользователь
получает причину.

## Параметры

Своих настроек нет. Фиксированные сроки:

| Срок | Значение |
|------|----------|
| Ожидание подтверждённой остановки службой | 9 с |
| Ожидание ответа на «Стоп» в приложении | 10 с |
| Аварийная остановка из фазы Stopping | 12 с |
| Аварийная остановка из фазы Connecting | 15 с + 10 с × число WG/AWG-узлов, потолок 4 мин |
| Пауза между перезагрузками ядра | 3 с |
| Подпись узла в уведомлении, если приложение не открывалось | через ~3 с после старта |

## Входы / Выходы

**Входы:** кнопки Старт / Стоп / Перезагрузка в приложении; Stop / Reconnect
в уведомлении; сохранённый конфиг ядра.
**Выходы:** статус туннеля и причина остановки; постоянное уведомление
«L×Box [final = <route.final>]» с подписью «<группа>: <узел>» (или статусом
«Connected», если узел неизвестен) и кнопками Stop / Reconnect.

## Правила и инварианты

- «Стоп» возвращает успех только после подтверждения «Stopped». Не уложилась
  служба в 9 с — «Stop timed out»; ядро при этом добивается аварийной
  остановкой на 12 с, которая сразу переводит UI в «Disconnected».
- Аварийная остановка не ждёт ядро: интерфейс гасится сразу, а закрытие
  ресурсов ядра идёт с ограничением 2 с на шаг, чтобы следующий старт не упёрся
  в занятый порт.
- Истечение фазы Connecting даёт причину с порогом и числом узлов; оно же
  считается вердиктом старта для страховки узлов (009-NODE_HEALTH).
- Переподключение = подтверждённый стоп → старт; стоп не подтвердился —
  старт отменяется («Stop timed out — reconnect aborted»). Reconnect из
  уведомления работает так же, но без приложения; повторный тап во время
  переподключения игнорируется.
- Старт, отменённый остановкой во время ожидания ядра, не может позже
  объявить себя «Started» (запоздалый старт отбрасывается).
- Перезагрузка ядра — только при подключённом туннеле, не чаще раза в 3 с,
  без остановки службы; успешная снимает пометку «нужен перезапуск»; ошибка
  показывается и сразу разрешает повтор.
- Старт ждёт готовности ядра; пустой конфиг, неготовое ядро, отказ ядра →
  остановка с текстом причины. Правила с Wi-Fi-условиями без разрешения на
  местоположение → диалог с переходом в настройки.
- Подпись уведомления обновляется при смене узла и при смене языка без
  переподключения.

## Границы

- Что именно перечитывается при автоприменении настроек — 003-CONFIG_BUILD.
- Отображение времени подключения и скорости — 012-LIVE_STATE.
- Старт без экрана (плитка, Intent API) — 014-AUTOMATION.
- Зависит от возможностей ОС: постоянное уведомление и кнопки в нём.
