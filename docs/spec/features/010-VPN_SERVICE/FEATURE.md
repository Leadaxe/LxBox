# FEATURE 010 — VPN_SERVICE — туннель как поведение

| Поле | Значение |
|------|----------|
| Тип | Продуктовая фича |
| Поглотила | `§012F` `§042F` `§119F` `§124F` `§128F` |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Назначение

Туннель — то, ради чего приложение существует: пользователь нажимает «Старт»,
и трафик идёт через выбранный узел; нажимает «Стоп» — перестаёт. Всё остальное
в этой фиче — о том, чтобы это простое обещание держалось в реальной жизни
телефона: при перезагрузке, при закрытии приложения, при гибели процесса, при
смене Wi-Fi на мобильную сеть, во сне экрана, при чужом VPN, который хочет
забрать тот же системный слот, и при нехватке памяти.

Фича защищает три принципа:

- **Честный статус.** «Остановлен» говорится только когда туннель реально
  остановлен; «подключён» — только когда ядро подтвердило старт. Зависание
  не прячется за вечным «Подключение…» — у каждой переходной фазы есть срок.
- **Явная воля пользователя главнее автоматики.** Ручной «Стоп» никакой
  сторож не отменяет; автоподнятие работает только пока туннель «желателен».
- **Экономия — опция, надёжность — дефолт.** Сон туннеля по умолчанию
  выключен; усыпление простаивающих WireGuard-туннелей не трогает активный
  маршрут, пока пользователь этого не разрешил.

## Обещания

- **P1. Стоп подтверждается, а не предполагается.** «Стоп» завершается успехом
  только после фактической остановки; медленная, но успешная остановка (до ~9 с
  на тяжёлом туннеле) ошибкой не считается; неподтверждённая — даёт «Stop timed
  out». Свидетель: юниты «медленный, но успешный стоп — без ошибки», «провал
  штатного стопа даёт stopTimedOut». Мутация: бюджет ожидания со стороны UI
  меньше бюджета ожидания службы.
- **P2. Принудительная остановка — только после штатной.** Лестница бюджетов
  строго растёт: ожидание службы 9 с < ожидание UI 10 с < аварийная остановка
  12 с. Свидетель: юнит «эскалация stopping-таймаута больше бюджета остановки в UI».
  Мутация: порог аварийной остановки 3 с.
- **P3. Зависший старт не висит вечно.** Фаза подключения ограничена 15 с плюс
  10 с на каждый WireGuard/AmneziaWG-узел конфига, но не более 4 мин; по
  истечении туннель принудительно гасится, а причина называет порог и число
  узлов. Свидетель: юниты «порог растёт линейно», «ограничен потолком»,
  «таймаут connecting оставляет причину». Мутация: порог без потолка.
- **P4. Переподключение не стартует поверх неостановленного.** Если остановка
  не подтвердилась, старт отменяется с сообщением «reconnect aborted».
  `без свидетеля`.
- **P5. Режим определяет входы ядра.** VPN — только системный туннель; Proxy —
  только локальный порт, системный туннель не поднимается; VPN+Proxy — оба;
  правила маршрутизации и DNS действуют на трафик локального порта так же, как
  на туннельный. Свидетель: юниты «mode=proxy → tun удалён, mixed добавлен»,
  «нет dangling tun-in в rules», «mode=vpn_proxy → оба inbound». Мутация:
  правило, привязанное только к туннельному входу, в режиме Proxy.
- **P6. Порт, видимый вне устройства, закрыт паролем.** Адрес прослушивания не
  из `127.x` форсирует авторизацию, снять её нельзя; при включении авторизации
  с пустым паролем пароль генерируется. Свидетель: юниты «listen 0.0.0.0 →
  effectiveAuth форсится», «произвольный LAN-IP форсит auth», «non-loopback
  listen форсит effectiveAuth → пароль генерится». Мутация: авторизация
  читается из тумблера без учёта адреса.
- **P7. Режим Proxy не трогает чужой VPN.** Без системного туннеля приложение
  не запрашивает VPN-разрешение и не показывает вопрос про чужой VPN.
  Свидетель: виджет-тест «proxy + активен чужой VPN → ни опроса, ни диалога»;
  юнит «mode → proxy зеркалит has_tun=false». Мутация: запрос разрешения
  независимо от режима.
- **P8. Перехват чужого VPN — только с согласия.** Перед ручным стартом в
  режиме с туннелем при активном чужом VPN — диалог «Switch / Cancel / VPN
  settings». Свидетель: виджет-тесты «vpn + активен чужой VPN → диалог»,
  «Cancel отменяет старт». Мутация: старт без опроса.
- **P9. Потеря слота отличима от остановки и переживает фон.** Если слот забрал
  другой VPN, пользователь видит это, а не нейтральное «Disconnected», в том
  числе вернувшись в приложение позже. Свидетель: юниты «Stopped + revoked →
  revoked», «map со Stopped + revoked → revoked (перехват пережил фон)».
  Мутация: признак перехвата не отдаётся при запросе статуса.
- **P10. Автозапуск — только если включён.** После загрузки устройства туннель
  поднимается сам, если включено «Auto-start on boot» (по умолчанию выключено).
  Свидетель: ручная проверка — включить, перезагрузить, туннель поднят.
  Мутация: автозапуск без проверки настройки.
- **P11. Закрытие приложения не рвёт туннель по умолчанию.** При включённом
  «Keep VPN on exit» (по умолчанию) смахивание из недавних туннель не
  останавливает; при выключенном — останавливает. Свидетель: ручная проверка.
  Мутация: остановка при смахивании без учёта настройки.
- **P12. Гибель процесса не оставляет без туннеля навсегда.** Если туннель был
  поднят и не остановлен явно, он поднимается сам (в худшем случае за ~3,5 мин,
  быстрее при пробуждении экрана); третья автоматическая попытка за 5 минут не
  выполняется — туннель остаётся выключенным с уведомлением. Явный «Стоп» не
  воскрешается. Свидетель: ручная проверка (убить процесс при поднятом
  туннеле — туннель вернулся; §428 device-verified). Мутация: сторож не
  снимается явной остановкой.
- **P13. Падение ядра лечит кэши при следующем запуске.** После аварийного
  завершения ядра кэш ядра и временные файлы очищаются до старта; конфиг,
  гео-базы и rule-set не трогаются. `без свидетеля` (DEVICE-PENDING).
- **P14. Молчащее ядро распознаётся.** При открытом приложении две подряд
  проверки без статуса ядра дольше 8 с переводят туннель в «Connection lost —
  VPN tunnel is not responding» с попыткой штатной остановки; первая проверка
  после возврата из фона не штрафуется. `без свидетеля`.
- **P15. Смена сети сбрасывает зависшие соединения один раз.** Реальная смена
  интерфейса (Wi-Fi ↔ мобильная) после 1,5 с тишины даёт один
  `resetNetwork`; первое подключение, обновление свойств той же сети и потеря
  сети сброса не дают. Свидетель: ручная проверка (переключить Wi-Fi → LTE,
  в журнале одна запись сброса). Мутация: сброс на каждое обновление свойств
  сети.
- **P16. Сон туннеля не открывает утечку.** В режимах сна туннельный интерфейс
  остаётся поднятым: на паузе трафик не идёт мимо туннеля, а дропается.
  `без свидетеля`.
- **P17. Усыпление WG/AWG — контракт с ядром через `lx.wg`.** Порог сна пишется
  в `lx.wg.idle_suspend`; пусто — блока `lx` нет; окно для активного маршрута и
  ленивая сборка пишутся только вместе с порогом. Свидетель: юниты
  «idleSuspend="30s" → lx.wg.idle_suspend, route чист», «reachable пишется
  только при включённом idleSuspend», «lazy_build выключен → нет lazy_build и
  нет build_max». Мутация: запись устаревшего `route.lx_idle_suspend`.
- **P18. Лимит памяти ядра применяется без переподключения.** Значения Auto /
  Off / 200 / 384 / 512 / 768 МБ, мусор → Auto. Свидетель: юниты «мусор / null /
  пустая строка → auto», «write-through: JSON-истина + зеркало в native»;
  немедленность — ручная проверка. Мутация: неизвестное значение становится
  действующим лимитом.
- **P19. Переключение на уже активный узел ничего не рвёт.** Свидетель: юнит
  «switchNode на уже активную ноду — no-op». Мутация: обрыв соединений до
  сравнения с активным узлом.
- **P20. Уведомление службы управляет туннелем без приложения.** Пока туннель
  поднят, в шторке висит уведомление с активным узлом и кнопками Stop /
  Reconnect, работающими при закрытом приложении. Свидетель: ручная проверка
  (§182 device-verified). Мутация: Reconnect через UI-процесс.

## Контролируемые параметры

| Настройка | Значения | Дефолт | Когда действует |
|-----------|----------|--------|-----------------|
| VPN mode | `vpn` / `proxy` / `vpn_proxy` | `vpn` | перезапуск туннеля |
| Local proxy protocol | `mixed` (HTTP+SOCKS5) / `http` / `socks` | `mixed` | перезапуск |
| Listen address | любой IPv4; `127.0.0.1` / `0.0.0.0` в списке | `127.0.0.1` | перезапуск |
| Listen port | 1024..65535 | 2080 | перезапуск |
| Require authentication | вкл/выкл (вне `127.x` — всегда вкл) | вкл | перезапуск |
| Proxy username / password | строка / 32 hex-символа, генерируется | `user` / генерация | перезапуск |
| Keep VPN on exit | вкл/выкл (виден только с туннелем) | вкл | сразу |
| Allow VPN bypass | вкл/выкл (виден только с туннелем) | выкл | следующий старт |
| Auto-start on boot | вкл/выкл | выкл | следующая загрузка |
| Interrupt connections on switch | вкл/выкл | выкл | сразу |
| Tunnel sleep mode | `never` / `lazy` / `always` | `never` | следующий старт |
| Suspend idle tunnels | Off / 30 s / 2 min / 5 min | 30 s | следующий старт |
| Suspend active-route tunnels | Off / 5 / 15 / 30 min / 1 h (только при сне выше) | 5 min | следующий старт |
| Lazy tunnel build | вкл/выкл (только при сне) | вкл | следующий старт |
| Built tunnels limit | 0 (без потолка) / 3 / 5 / 8 / 12 | 5 | следующий старт |
| Memory limit | Auto / Off / 200 / 384 / 512 / 768 MB | Auto | сразу |

Ключи конфига ядра, которые отдаёт фича (контракт):

| Ключ | Когда |
|------|-------|
| `inbounds[]` `type: tun`, `tag: tun-in` | режимы `vpn`, `vpn_proxy` |
| `inbounds[]` `type: mixed\|http\|socks`, `tag: mixed-in`, `listen`, `listen_port`, `users[{username,password}]` | режимы `proxy`, `vpn_proxy`; `users` — только при действующей авторизации и непустом пароле |
| `lx.wg.idle_suspend` | порог сна непуст |
| `lx.wg.idle_suspend_reachable` | вместе с порогом сна, если окно непусто |
| `lx.wg.lazy_build: true`, `lx.wg.build_max` | вместе с порогом сна, если ленивая сборка включена |

Вызовы ядра, видимые как контракт: `resetNetwork` (смена сети), `pause` /
`wake` (сон туннеля), `rebindStaleEndpoints` (включение экрана),
`closeConnection` (обрыв при смене узла), лимит памяти — через
`oomMemoryLimit` параметров запуска ядра.

## Входы / Выходы

**Входы:** жесты пользователя (Старт, Стоп, Перезагрузка ядра, Reconnect и Stop
в уведомлении); собранный конфиг ядра; события ОС — загрузка устройства,
смахивание приложения, гибель процесса, смена/потеря сети по умолчанию,
включение/выключение экрана, глубокий сон устройства, перехват VPN-слота
другим приложением; ответы ядра — статус старта/остановки, текст ошибки,
поток статуса.

**Выходы:** системный туннель и/или локальный прокси-порт; статус туннеля
(`disconnected`, `connecting`, `connected`, `stopping`, `revoked`) и причина
остановки; постоянное уведомление службы; разовые уведомления об остановке по
ошибке и о прекращении автоподнятия; вызовы ядра из списка выше.

## Data flow

```
жест / событие ОС
  → проверка режима (нужен ли системный туннель) → вопрос про чужой VPN
  → запуск службы (уведомление «Starting») → ожидание готовности ядра
  → старт ядра с конфигом → проверка разрешений (Wi-Fi-условия в правилах)
  → Started: сторож взведён, уведомление с узлом, поток статуса
  ↻ жизнь: смена сети → сброс соединений; экран вкл → ребинд стухших WG;
    сон (по режиму) → pause/wake; молчание ядра → «Connection lost»
  → Стоп: Stopping → закрытие туннеля, сетевого наблюдателя, ядра
  → Stopped (подтверждение) → сторож снят, уведомление убрано
```

## Правила и гарантии

- Статусов службы ровно четыре (Starting/Started/Stopping/Stopped); перехват
  слота — признак поверх Stopped, а не пятый статус.
- Повтор того же статуса без ошибки не рассылается; поздний «Started» после
  начавшейся остановки отбрасывается.
- Старт при неостановленной службе молча игнорируется службой, поэтому любое
  переподключение — «дождаться Stopped, потом старт».
- Перезагрузка ядра доступна только при подключённом туннеле, не чаще раза в 3 с;
  пересоздаёт ядро без остановки службы, туннель пропадает на ~3 с.
- Изменения режима, адреса, порта, авторизации, сна и порогов усыпления
  помечают конфиг «нужен перезапуск»; лимит памяти и тумблеры keep/interrupt —
  нет.
- Правила с Wi-Fi-условиями без выданного разрешения на местоположение
  останавливают старт с диалогом «Open Settings», а не падением.
- Пустой конфиг, неготовое ядро или отказ ядра — остановка с текстом причины,
  который видит приложение (сырой текст ядра едет рядом для разбора).

## Границы

- Живой статус, скорость, соединения, время подключения — 012-LIVE_STATE.
- Какие приложения идут через туннель — 011-SPLIT_TUNNELING.
- Плитка быстрых настроек, ярлыки, Intent API, автоматизаторы — 014-AUTOMATION.
- Автоприменение изменений настроек к живому туннелю и баннер «нужен
  перезапуск» — 003-CONFIG_BUILD; параметры интерфейса туннеля (адрес, MTU,
  стек, IPv6) — там же как переменные шаблона.
- Журналы, Debug API, отчёт о падении ядра — 013-DIAGNOSTICS.
- Активный health-watchdog с пробами и эскалацией (§042F, §088) — не
  реализован намеренно (батарея).
- Зависит от возможностей ОС: автозапуск после загрузки, выживание в фоне и
  после гибели процесса, момент глубокого сна, получение событий сети и экрана,
  показ уведомлений, единственность системного VPN-слота. Прошивки с агрессивной
  чисткой фона могут ломать P10–P12; обходного пути, кроме исключения из
  оптимизации батареи, нет.

## Особенности сопровождения

- Бюджеты остановки связаны лестницей (9 < 10 < 12 с). Меняешь одну ступень —
  проверь все три, иначе вернётся ложное «Stop timed out» (§415).
- `pause` ядра закрывает все соединения: режим `always` рвёт push-каналы при
  каждом гашении экрана — поэтому дефолт `never`.
- Ключи сна WG/AWG живут в `lx.wg`; старое `route.lx_idle_suspend` ядро
  принимает с предупреждением, а одновременная запись в оба места с разными
  значениями не даёт ядру стартовать.
- Сброс соединений на каждое обновление свойств сети — известная регрессия
  класса sing-box #3400; сброс только на смену имени интерфейса.
- Автоподнятие после гибели процесса держится на признаке «туннель желателен»:
  любой новый путь остановки обязан его снимать, иначе сторож воскресит
  остановленный туннель.
