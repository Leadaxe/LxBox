# Контракт хранения

## Что делает

Задаёт, что приложение хранит и в какой форме. Настройки пользователя живут
одним документом, записи которого — те же, что в LX Backup 1.0: одна форма
для диска, полной копии, переноса и Debug API. Ссылки на узлы хранятся
адресом узла, а не строкой финального тега, и следуют за узлом при
переименовании и переносе.

## Параметры

**Наборы данных** (что хранится где):

| Набор | Что в нём | В полной копии | В слоте набора |
|-------|-----------|----------------|----------------|
| Документ настроек | всё, что настроил пользователь; тумблеры VPN — зеркалом | да (по категориям) | да |
| Предыдущая копия документа | прошлое целое состояние для восстановления | нет | нет |
| Исходник старой формы | байты документа до миграции 2.23.2 | только Debug API `from=v0_bak` | нет |
| Кэш тел подписок | скачанные узлы подписок | нет (перекачиваются) | да |
| Кэш наборов правил | скачанные rule-set | нет | да |
| Собранный конфиг | итог сборки | нет | нет |
| База кэша ядра, журналы, отчёты о сбоях | служебное | нет | нет |
| Состояние узлов Tailscale | личности узлов | нет | по слотам ([018](../../018-WORKSPACES/FEATURE.ru.md)) |
| Свойства устройства вне документа | тема оформления; рабочая копия тумблеров VPN у ОС | нет | нет |

**Документ настроек, верхний уровень:** `storage_version: 1` (признак
формы), `vars`, `sources[]`, `rules[]`, `dns{servers[], rules[]}`,
`directions[]`, `directions_migrated`, `route_final`, `ping_options`,
`warp_account`, `masque_account`, `tun_apps`, `vpn_mode`, пороги
idle-suspend, бюджет сборки WG, пассивная проверка, сортировка и ручной
порядок узлов, служебные отметки. Закрытый список — он же допуск импорта.

**Записи `sources[]`** (порядок записей нормативен):

| `kind` | Суть |
|--------|------|
| `subscription` | `id`, `name`, `enabled`, `url`, `tag_policy{prefix}`, `identity`, `update{interval_hours}`, `disabled{узел: unix-секунды}` + поля LxBox |
| `server` | `id`, `tag`, `enabled`, `origin{kind: uri\|wg_ini\|json, raw}`, `detour` (адрес узла) + поля LxBox; прежнее поле `sections` читается и снимается с отметкой |
| `folder` | `id`, `name`, `enabled`, `tag_policy`, `nodes[]` (`server` / `unsupported` с `reason` / `auto`) |
| `chain` | `tag`, `enabled`, `label`, `body{type: chain, …}`, `hops[]` (адреса узлов) |

Правила — `rules[]` с `kind: inline|srs|preset`, матчеры в `body` ключами
sing-box; DNS-серверы — `user|preset|template`.

**Адрес узла (NodeLink):** `{folder_id?, tag}` — пара «контейнер + сырой
тег» для узла папки или подписки, корневой `{tag}` для одиночного сервера,
Направления, `direct-out`, цепочки.

## Входы / Выходы

**Входы:** правки экранов; переименование, перенос и удаление узлов.

**Выходы:** документ на диске; переписанные ссылки; уведомление о
погашенных ссылках с названием задетых (detour, члены групп, позиции
цепочек).

## Правила и инварианты

- **Ссылка не переуказывается на другой узел.** Какие адреса сменились —
  решается по самим узлам, а не по похожим тегам (P17).
- Переименование узла (правка тела) и перенос между папками переписывают
  все носители ссылки: detour источника, detour члена папки, позиции
  цепочек, состав групп автовыбора.
- Удаление узла или источника гасит ссылки: detour снимается, позиция
  уходит из цепочки, задетые называются порознь.
- Смена префикса или имени контейнера адрес не меняет — ссылки не трогаются;
  финальный тег считает сборка.
- Поля LxBox живут рядом с полями контракта в той же записи; неизвестный
  ключ на входе отбрасывается допуском, уже лежащий на диске мусор
  безвреден.
- Документ без признака формы — форма 2.23.2
  ([миграция](storage-migration.ru.md)); новая установка сразу пишет признак.

## Границы

  ([006-DETOUR_AND_BALANCE](../../006-DETOUR_AND_BALANCE/FEATURE.ru.md) для

  [004-ROUTING](../../004-ROUTING/FEATURE.ru.md), [005-DNS](../../005-DNS/FEATURE.ru.md)).
- Нормы формы — контракт с лаунчером (`docs/contract/`), 1.0.x.
- Шифрования хранения нет.
