# Миграция хранения

| Поле | Значение |
|------|----------|
| Фича | [017-BACKUP_AND_STORAGE](../FEATURE.ru.md) |
| Обещания | P18–P20 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

При первом запуске версии с контрактом хранения 1.0 (v2.24.0+) документ
настроек старой формы 2.23.2 разово переводится в форму 1.0 — так, что
собранный конфиг до и после совпадает. Пользователь ничего не делает и
ничего не замечает; исходник сохраняется копией. Та же миграция применяется
ко всем входам старой формы: к документу на диске, к слоту набора
настроек, к блоку `storage` полной копии и к телу Debug API импорта.

## Параметры

| Что | Значение |
|-----|----------|
| Признак формы | `storage_version`; нет — форма 2.23.2; не число — форма 2.23.2 с предупреждением |
| Известная форма | `1`; документ с версией выше читается как текущий и не переписывается |
| Копия исходника | байты документа до миграции, пишется один раз и хранится всё время установки |

Пользовательских ручек нет.

## Входы / Выходы

**Входы:** документ старой формы (подписки, серверы, папки, цепочки,
правила, DNS старыми ключами); тела подписок из кэша — для перевода ссылок
на их узлы; пресеты шаблона — для ссылок preset-серверов DNS.

**Выходы:** документ формы 1.0; копия исходника; одна строка в журнале с
итогом и счётчиками; потери — предупреждением с именами записей.

## Правила и инварианты

- **Порядок:** прочитать → мигрировать в памяти → копия исходника (если её
  ещё нет) → атомарная запись нового документа. Отметки «мигрировано» нет:
  признак — сама форма документа. Убийство между шагами — старый файл на
  месте, следующий старт мигрирует заново (P19).
- **Идемпотентна:** документ текущей формы возвращается как есть, без
  записи; результат, поданный снова, не меняется (P18).
- **Ключи:** старые ключи источников, цепочек, правил и DNS переходят в
  `sources[]`, `rules[]`, `dns{}`; цепочки встают хвостом `sources[]` по
  старому порядку; легаси-пара Направлений `channels` переименовывается в
  `directions`; ключи без читателей удаляются и перечисляются в журнале.
- **Ссылки на узлы** (detour источника и члена папки, позиции цепочек)
  переводятся по состоянию до миграции: узел папки или подписки — пара
  `{id контейнера, сырой тег}`, в том числе выключенный; одиночный сервер,
  Направление, `direct-out`, цепочка — корневой `{tag}`; не нашлось или
  неоднозначно — корнем с предупреждением, сборка разберёт ссылку
  fail-closed; самоссылки, которые 2.23.2 не эмитила, снимаются (P20).
- **Группы папок** старого текстового вида становятся узлами автовыбора;
  неразрешимые члены снимаются с предупреждением.
- JSON-правило-массив делится на записи по объекту; нечитаемый текст
  сохраняется дословно с предупреждением.
- Версия и легаси-ключи вместе — легаси отбрасываются с предупреждением.
- Битый основной файл и предыдущая копия старой формы: восстановление
  мигрирует и сразу пишет.
- Параллельные первые чтения ждут одну миграцию; признак «конфиг устарел»
  миграцией не поднимается.
- Сбой самой миграции — ошибка в журнал, документ как был, без записи:
  лучше старая форма в памяти, чем стёртые настройки.

## Границы

- Откат на 2.23.2 поверх не поддержан ОС (младшая версия не ставится);
  исходник доступен только стендам через Debug API `from=v0_bak`.
- Прочие одноразовые миграции прошлых лет удалены (§159, §229): мусор
  старых ключей безвреден и уходит при первом импорте копии.
- Удаление этой миграции и копии исходника — техдолг (§440).
