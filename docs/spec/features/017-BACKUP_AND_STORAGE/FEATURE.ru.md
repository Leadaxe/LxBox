# Резервная копия и хранение — полный бэкап настроек, перенос на десктоп и надёжное хранение

LxBox сохраняет настройки VPN — подписки, серверы, правила маршрутизации, DNS,
split tunneling — в JSON-файл и восстанавливает их слиянием или заменой.
Отдельный файл LX Backup 1.0 переносит общую часть настроек на десктопный
лаунчер и обратно. Под этим — хранение настроек одним документом с атомарной
записью, восстановлением повреждённого файла и разовой миграцией из формы
хранения 2.23.2.

| Поле | Значение |
|------|----------|
| Фича | 017-BACKUP_AND_STORAGE |
| Тип | Продуктовая фича |
| Поглотила | `§040F` `§439F` |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Назначение

Всё, что пользователь настроил, должно пережить убийство процесса,
обновление приложения и смену телефона. Фича даёт три вещи:

- **Полная резервная копия** той же установки: снимок настроек в JSON по
  категориям и восстановление слиянием или заменой — в том числе одним тапом
  с пустого главного экрана.
- **Перенос на десктоп** — обмен общей частью настроек с десктопным
  лаунчером в формате LX Backup (контракт 1.0): чему у другой стороны нет
  места, то отбрасывается и называется.
- **Надёжное хранение**: одна форма записей (та же, что в LX Backup 1.0),
  атомарная запись, восстановление битого файла, разовая миграция старой
  формы, отложенная запись правок, защита от записи «из прошлого».

Принципы: **файл — сериализация состояния** (импорт своего экспорта
возвращает то же состояние, полей «на провоз» нет); **нет молчаливых
потерь** (неприменённое названо кодом, счётчиком, журналом); **вход —
default-deny**; **сбой не стирает настройки** (прежнее или новое целое).

## Обещания

- **P1. Секрет не уезжает случайно.** «Debug API config» на экспорте выключена
  по умолчанию; без неё ключи Debug API в файл не пишутся. Закрепление конфига
  (`config_locked_for_debug`, §037) — в этой же категории: восстановление App
  settings не привозит замок без Debug API (§607). Свидетель: юниты
  «без Debug API config ключи Debug API сняты с переменных», «только Debug API
  config — только ключи Debug API». Мутация: Debug-ключи едут с «App settings».
- **P2. Экспорт выгружает всё, что принимает импорт.** Свидетель: юниты
  «допуск ⊆ экспорт (все категории)», «Направления и их отметка миграции
  экспортируются в Routing». Мутация: ключ добавлен в допуск, но не в категорию.
- **P3. Круг полной копии без потерь.** Экспорт всех категорий → сброс →
  импорт = исходное хранение. Свидетель: юнит «круг: экспорт → сброс → импорт
  → побайтно равно». Мутация: ключ вне категорий.
- **P4. Чужой файл отвергается до применения.** Не JSON, нет маркеров
  `app: lxbox` / `kind: backup`, нет блока `storage` (формат до v1.7.3) —
  «Invalid backup» с причиной, ничего не записано. Свидетель: юниты «не JSON —
  отказ», «нет маркеров app/kind — отказ», «старый формат без storage —
  отказ». Мутация: частичный разбор.
- **P5. Вход default-deny.** Неизвестные ключи верхнего уровня и переменных
  отбрасываются в обоих режимах и считаются («N unknown keys skipped»).
  Флаги «уже спрашивали» стартовых вопросов (`wizard_*`,
  `notif_perm_prompted_v1`) — известные-игнорируемые: едут в экспорт, импорт
  их не применяет и неизвестными не считает (§600). Свидетель: юниты «чужой
  ключ отброшен», «чужая переменная отброшена, известные остались», «слияние
  тоже фильтрует», «§600 — флаги не в droppedKeys, чужой ключ рядом
  отброшен». Мутация: фильтр только в режиме замены.
- **P6. Слияние ничего не удаляет.** Источники дописываются по `id`,
  переменные — по ключу, отсутствующее в файле остаётся. Свидетель: юниты
  «слияние сохраняет незатронутые ключи», «источники дописываются по id».
  Мутация: слияние источников заменой списка.
- **P7. Замена заменяет выбранные категории; невыбранные сохраняют значения
  получателя.** Выбранная категория заменяется содержимым файла целиком: ключ
  категории, которого в файле нет, удаляется. Невыбранная категория не
  трогается. Выбраны все категории — заменяется весь документ. Свидетель:
  юниты «замена только Routing: правила и DNS из файла, источники и цепочки
  получателя на месте», «только Server lists: sources[] из файла, правила
  получателя на месте», «все категории: тот же документ, что полная замена»
  (§599). Мутация: замена всего документа.
- **P8. Свойства устройства переживают замену.** Если файл молчит о Debug API
  и о флагах «уже спрашивали» стартовых вопросов, текущие значения остаются;
  ключ Debug API из файла побеждает; флаги стартовых вопросов (все четыре,
  включая `notif_perm_prompted_v1`) из файла не принимаются вовсе и в
  неизвестные не попадают (§600). Зеркало тумблеров VPN (`native_prefs`) из
  документа настроек не берётся, замена оставляет зеркало получателя;
  тумблеры восстанавливает только блок VPN (§607).
  Свидетель: юниты «замена сохраняет Debug API, которого нет в снимке»,
  «ключи из снимка побеждают», «замена сохраняет флаги стартовых вопросов»,
  «замена сохраняет native_prefs получателя, из снимка не берёт» (§607).
  Мутация: замена переменных целиком.
- **P9. Старая копия восстанавливается.** Блок формы 2.23.2 мигрирует до
  фильтра категорий; превью считает мигрированное; конфиг ядра = эталон.
  Свидетель: юниты «блок мигрирует: превью считает по виду записей», «бэкап
  2.23.2 → замена всех категорий → конфиг = эталон». Мутация: фильтр по
  легаси-ключам.
- **P10. LX Backup: пишется 1.0, читаются 1.0 и 0.x, новее — отказ целиком.**
  Свидетель: юниты «пишем 2, читаем 2 и legacy 1», «больше читаемого и вне
  {1, 2} — отказ». Мутация: частичный разбор новой версии.
- **P11. Перенос — сериализация состояния.** Экспорт → импорт в пустое =
  исходное; повторный импорт ничего не добавляет. Свидетель: юниты «круг:
  экспорт → импорт в пустое = исходное», «две тёзки файла — две папки;
  повторный импорт не растёт». Мутация: дедуп узлов по имени, не по телу.
- **P12. Потери переноса названы.** Незнакомое поле, поле чужого типа, ключ
  вне таблицы среза, настройка LxBox без места в 1.0 — код предупреждения на
  импорте и экспорте. Свидетель: юниты «неизвестное поле записи названо, а
  не съедено», «ключ записи вне таблицы срезается с названием», «потеря без
  дома в 1.0 названа». Мутация: тихий срез поля.
- **P13. Перенос не перетирает своё.** Занятый тег Направления или цепочки —
  приехавшее не применяется и названо; отметки «выключено» объединяются.
  Свидетель: юниты «занятый тег не применяется и назван», «отметки из файла
  доливаются». Живая регистрация WARP не перезаписывается —
  `без свидетеля`. Мутация: «последний пишет».
- **P14. Правило не уезжает в никуда.** Правило с неизвестной приёмнику целью
  приезжает выключенным; `route.final` в никуда не применяется; приехавшее
  Направление делает правило рабочим. Свидетель: юниты «несуществующий
  outbound выключает правило», «приехавшая цель делает правило рабочим».
  Мутация: сверка целей до слияния источников.
- **P15. Переносятся только переносимые переменные** — список совпадает с
  реестром контракта, прочие — `backup_var_skipped`. Свидетель: юниты
  «совпадает с реестром», «непереносимая переменная пропускается с
  предупреждением». Мутация: перенос путей и интерфейсов машины.
- **P16. Вердикт ядра не переносится**, выключение узла — переносится.
  Свидетель: юниты «страховка: после импорта узел выключен, вердикта нет»,
  «файл с вердиктом: запись снята, узел остаётся выключенным». Мутация:
  вердикт едет в файле.
- **P17. Ссылка на узел следует за узлом.** Адрес `{folder_id?, tag}`;
  переименование и перенос переписывают все ссылки, удаление гасит и называет
  задетых, смена префикса папки ссылок не трогает. Свидетель: юниты
  «переименование члена папки переписывает все носители», «перенос между
  папками переписывает folder_id», «удаление гасит ссылки и называет
  задетых», «смена tag_policy ссылок не трогает». Мутация: сопоставление по
  похожему тегу.
- **P18. Миграция хранения разовая и безвредная.** Идемпотентна; исходник
  копируется один раз; конфиг до и после совпадает; документ новее известной
  формы читается и не переписывается. Свидетель: юниты «идемпотентна»,
  «копия исходника пишется один раз», «конфиг совпадает с эталоном», «версия
  выше известной не переписывается». Мутация: миграция на каждом старте.
- **P19. Прерванная миграция повторяется.** Свидетель: юниты «сбой между
  записью копии и записью документа: старый файл + копия → миграция заново»,
  «битый основной файл, предыдущая копия старой формы: восстановление
  мигрирует и пишет». Мутация: отметка «мигрировано» до записи.
- **P20. Позиции цепочек и detour указывают на узел.** После миграции ссылка
  на узел подписки или папки — пара `{id контейнера, сырой тег}`, в том числе
  на выключенные цели; ненайденное — корневой `{tag}` с предупреждением.
  Свидетель: юниты «узел подписки из кэша тел — пара {id подписки, сырой
  тег}», «позиции цепочки: выключенный сервер — корень, узел выключенной
  папки — пара», «неоднозначная строка — корень с предупреждением». Мутация:
  перевод ссылок без тел подписок.
- **P21. Запись атомарна.** Убийство в любой момент оставляет прежний или
  новый целый файл; битый основной восстанавливается из предыдущей копии;
  осиротевшие временные файлы убираются; параллельные записи не мешают.
  Свидетель: юниты «битый основной, валидная копия → восстановление», «копия
  только из валидного основного», «осиротевший временный файл удаляется»,
  «конкурентные записи не оставляют сирот». Мутация: запись поверх основного.
- **P22. Битый файл без копии не затирается** до первой правки; настройки —
  по умолчанию. Свидетель: юниты «битый основной, копии нет → пусто, признак
  повреждения», «после сброса и правки — основной перезаписан, признак снят».
  Мутация: немедленная запись пустого документа.
- **P23. Правка видна сразу, на диск — при уходе.** Правки редакторов видны
  пересборке и старту до записи; на диск — одной записью при уходе с экрана
  или сворачивании. Свидетель: юнит «отложенные правила видны читателю до
  дисковой записи»; виджет-тесты «запись при уходе с экрана, если есть
  несохранённое», «запись при сворачивании». Мутация: запись в память только
  при уходе.
- **P24. Запись «из прошлого» не проходит.** Контроллер, переживший смену
  набора настроек, в новый набор не пишет; остановленный проход обновления не
  продолжается. Свидетель: юниты «отложенный фетч старого контроллера не
  трогает новый слот», «остановка прерывает проход между подписками».
  Мутация: запись без сверки поколения.
- **P25. Перенос пишется по свежему состоянию:** план LX-импорта
  пересчитывается в момент подтверждения, а не берётся из превью.
  `без свидетеля`.

## Контролируемые параметры

| Настройка | Где | Значения | Дефолт |
|-----------|-----|----------|--------|
| Server lists / Routing / App settings / VPN system toggles | Backup & restore → Export | вкл/выкл | вкл |
| Debug API config | там же, с предупреждением | вкл/выкл | **выкл** |
| Категории импорта | превью импорта | те, что есть в файле | все, что есть в файле |
| Mode | превью импорта | Merge with existing / Replace all | Merge |
| Способ сохранения | лист экспорта | в файл / в Загрузки / поделиться | выбор пользователя |

Фиксировано: имя полной копии `lxbox-backup-v<версия>-<ГГГГММДД-ЧЧММ>.json`
(не зависит от языка); файл переноса `lx-backup.json`, `lx_backup: 2`
(контракт 1.0), читается `1` и `2`; признак формы `storage_version: 1`.
Ключей конфига ядра фича не отдаёт
([003-CONFIG_BUILD](../003-CONFIG_BUILD/FEATURE.ru.md)).

## Входы / Выходы

**Входы:** категории и режим; JSON-файл; Debug API `GET /backup/export`,
`POST /backup/import`; документ настроек с диска; правки экранов.

**Выходы:** полная копия `{app: "lxbox", kind: "backup", created_at,
source_app_version, storage{…}, vpn_settings{…}}`; LX Backup 1.0
(`lx_backup`, `exported_by`, `exported_at`, `sources`, `directions`, `rules`,
`dns`, `vars`, `route`, `warp`); применённые настройки; итоги; коды `backup_*`.

## Data flow

```
Полная копия:  настройки → категории → конверт + блок VPN → файл
Восстановление: файл → маркеры → миграция старого блока → превью (категории,
   счётчики, режим) → merge: источники по id + upsert | replace: документ целиком
   (+ Debug API и флаги вопросов устройства) → допуск default-deny → атомарная
   запись → досев Направлений → блок VPN → итог + «Restart now»
Перенос: настройки → срез записей + тонкий слой → LX Backup 1.0;
   файл → декодер 1.0 | 0.x → план по свежему приёмнику → превью → запись → итог
Хранение: правка → память (сразу) → одна атомарная запись (уход/сворачивание)
Старт: документ → старая форма? → миграция → копия исходника → запись
```

## Правила и гарантии

- Полная копия и перенос — разные форматы; каждый вход отвергает чужой.
- Категории полной копии (кроме блока VPN) режут один документ настроек;
  признак формы едет при любом наборе. Цепочки — с «Server lists».
- Превью до записи; замена — отдельное подтверждение «Replace all data?».
  Восстановление с пустого главного экрана: без превью, замена, все категории.
- Одна форма записей для диска, полной копии, LX Backup и Debug API; одна
  миграция старой формы для всех входов.

## Границы

- Наборы настроек — [018-WORKSPACES](../018-WORKSPACES/FEATURE.ru.md); здесь —
  какие наборы данных они переносят и защита записи от устаревших контроллеров.
- Смысл самих настроек — в их фичах; файл правил —
  [004-ROUTING](../004-ROUTING/FUNCTIONS/rule-transfer.ru.md).
- Не входят ни в копию, ни в перенос: кэш ядра, журналы, отчёты о сбоях, кэш
  наборов правил, тела подписок, итоговый конфиг, состояние Tailscale, слоты,
  тема ([020-APP_SHELL](../020-APP_SHELL/FEATURE.ru.md)).
- Шифрования, облачного автобэкапа, выбора отдельных подписок — нет.
- Зависит от возможностей ОС: выбор и сохранение файла (на ТВ — подсказка),
  «Поделиться», Загрузки, сворачивание; младшая версия поверх не ставится.

## Особенности сопровождения

- Новый ключ настроек вносится и в допуск импорта, и в категорию экспорта:
  асимметрия уже теряла Направления (§221), автопинг (§349), MASQUE (§219).
  Страж — P2. Обратная асимметрия тестом не ловится. Флаги стартовых
  вопросов едут в копию намеренно и при импорте пропускаются молча (§600).
- После восстановления из «Backup & restore» экраны держат старый снимок до
  перезапуска — отсюда «Restart now»; с главного экрана источники
  перечитываются сами.
- Новый набор данных обязан быть классифицирован: в документ (и в
  категорию) либо явно «свойство устройства».
- Миграция формы 2.23.2 — техдолг на удаление (§440, backlog); пока она жива,
  исходная копия файла хранится всё время установки.
