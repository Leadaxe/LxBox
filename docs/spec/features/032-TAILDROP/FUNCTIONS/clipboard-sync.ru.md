# Синхронизация буфера — буфер обмена телефона и десктопный лаунчер

Буфер обмена ходит между LxBox и десктопным лаунчером (singbox-launcher)
через Taildrop. Телефон → ПК: плитка быстрых настроек «Send clipboard». ПК →
телефон: текст буфера с устройства, которому пользователь разрешил, сам
попадает в буфер телефона.

| Поле | Значение |
|------|----------|
| Фича | [032-TAILDROP](../FEATURE.ru.md) |
| Обещания | P9–P12 |
| Состояние | ✍ Черновик, 2026-11-01 — не реализована |

## Что делает

**Телефон → ПК.** Пользователь добавляет плитку «Send clipboard» в быстрые
настройки. Нажатие на долю секунды открывает прозрачное окно: Android 10 и
новее дают приложению читать буфер только из окна на переднем плане. Окно
читает буфер, проверяет его, отправляет на устройство-цель файлом буфера и
закрывается; уведомление говорит «Sent to <PC>». Устройство-цель выбирается
один раз в настройках.

**ПК → телефон.** Файл Taildrop, в имени которого префикс буфера, с
устройства, для которого пользователь включил «Accept clipboard from
<device>», во входящие не кладётся: его содержимое уходит в буфер телефона
(запись в буфер из фона разрешена), а файл удаляется. От любого другого
отправителя или при выключенной галке тот же файл — обычный файл во
входящих.

## Параметры

| Что | Значение |
|-----|----------|
| Плитка | «Send clipboard», отдельная от плитки туннеля |
| Устройство-цель | одно своё устройство одного узла Tailscale; выбирается один раз; место настройки на экране — открытый вопрос |
| «Accept clipboard from <device>» | переключатель на каждое своё устройство, у получателя; по умолчанию выключен |
| Транспорт | файл Taildrop, имя которого начинается с префикса буфера (текущее значение `lxclip-`) |
| Лимит размера | текущее значение 64 KiB |
| Кодировка | валидный UTF-8 без BOM; переводы строк не нормализуются |
| Свежесть (TTL) | текущее значение 2 минуты, по часам получателя от момента, когда файл обнаружен |
| Подтверждение | уведомление «Sent to <PC>» |

Префикс, лимит, TTL и кодировка — константы контракта с лаунчером
(`docs/contract` и реестр; версию контракта заводит лаунчер). Значения выше —
текущие; источник — контракт.

## Входы / Выходы

**Входы:** нажатие плитки; буфер в этот момент; входящие файлы буфера и их
отправитель Taildrop; выбранная цель; переключатели «Accept clipboard from
<device>».

**Выходы:** файл буфера на устройство-цель; уведомление «Sent to <PC>» или
уведомление об отказе с причиной; буфер телефона, заполненный из входящего
файла; предупреждение в логе приложения о невалидном входящем клипе.

## Правила и инварианты

- **Отправка.** Буфер читается только по нажатию плитки; при копировании
  ничего не отправляется. Плитка не отправляет и показывает причину, когда
  клип пустой, больше лимита, не валидный UTF-8 или помечен Android как
  чувствительный (пароли, P11); а также когда цель не выбрана, цель не в
  сети, VPN выключен или узел не работает.
- **Приём** (P12). Файл буфера применяется, только если для его отправителя
  включено «Accept clipboard from <device>»; по умолчанию переключатель
  выключен. Отправитель — это отправитель Taildrop; в имени файла маркера
  источника нет. Без галки или от неразрешённого отправителя файл попадает во
  входящие обычным файлом (окончательно это фиксирует контракт).
- **Свежесть.** Клип старше TTL на момент, когда получатель его обнаружил,
  удаляется без применения.
- **Серии.** Из нескольких клипов, пришедших подряд, применяется последний по
  времени приёма; остальные удаляются.
- **Валидность.** Входящий клип больше лимита или не валидный UTF-8 (или с
  BOM) удаляется с предупреждением в логе приложения и не применяется.
- **Содержимое как есть.** Переводы строк не нормализуются ни в одну сторону.
- **Без обратной петли.** Полученный клип никогда не отправляется обратно
  автоматически.
- Применённый файл буфера никогда не показывается во входящих и удаляется,
  как только его содержимое в буфере (P10).
- Текст буфера не пишется в лог приложения, дамп для поддержки и Debug API.

## Границы

- Только в паре с лаунчером. Официальные клиенты Tailscale получают файл
  буфера как обычный файл с префиксом в имени; в свой буфер они его не
  кладут.
- Нет чтения буфера из фона и автоматической отправки при копировании.
- Только текст; картинки и другие типы клипов не отправляются.
- Сторона лаунчера — его собственная спека: буфер на macOS, Windows и
  удалённых lxd (через gRPC), на Linux classic и Windows 386 буфера нет;
  отправка с ПК — пункт трея «Send clipboard to <phone>», без глобальной
  горячей клавиши.
- Открыто: входят ли в бэкап цель и переключатели «Accept clipboard from
  <device>».
- На устройстве не проверено.
