# Служебные файлы — буфер обмена и ссылки между телефоном и лаунчером

Файл Taildrop особого вида несёт команды. LxBox или десктопный лаунчер
(singbox-launcher), получив его с разрешённого устройства, выполняет команды
и удаляет файл; во входящие и в Downloads такой файл не попадает. Команд
две: положить текст в буфер обмена и открыть ссылку. Телефон → ПК: окно
Send clipboard — из кнопки «📋 Send clipboard» в уведомлении VPN, из
«Поделиться» текстом или из пункта «Send to device» меню выделения текста.
ПК → телефон: буфер и ссылки с разрешённого устройства.

| Поле | Значение |
|------|----------|
| Фича | [032-TAILDROP](../FEATURE.ru.md) |
| Обещания | P9–P12 |
| Состояние | ✅ реализована, 2026-11-03 — приём (задача 707, итерация 4: команды выполняются, файл удаляется, разрешения по устройству), разрешения на странице устройства (итерация 6), отправка из окна Send clipboard (итерация 7); окно на устройстве не проверено. Контракт 1.1.148–1.1.150 |

## Что делает

**Телефон → ПК: окно Send clipboard.** В уведомлении VPN есть кнопка
«📋 Send clipboard». Она открывает поверх текущего приложения окно «типа
чата» (нижняя половина экрана, своя задача: главное окно LxBox не
поднимается). Android 10 и новее дают приложению читать буфер только из окна
на переднем плане, поэтому окно читает его, получив фокус, и кладёт текст в
поле; пустой буфер или не текст — поле пустое.

```
📋  To: LexRouter ▾          ⋮    ✕
                  https://ya.ru      отправлено · 12:40 ✓
ssh root@10.0.0.5                    с LexRouter · 12:42
[ текст из буфера, правится ]       [➤]
[ Open on LexRouter ]   ← только для одной ссылки
```

- **Получатель** `To: … ▾` — свои устройства, принимающие файлы, со всех
  работающих узлов Tailscale с Allow Taildrop; при нескольких узлах
  устройство показано с узлом. Выбор запоминается и возвращается в следующий
  раз; запомненного нет в списке — берётся первое.
- **➤** отправляет поле служебным файлом с командой `clipboard`; поле
  очищается, окно остаётся открытым.
- **Open on <device>** появляется под полем, только если текст целиком одна
  ссылка `http(s)` (после обрезки пробелов по краям, без пробелов внутри), и
  отправляет `open_url`.
- **Лента** — переписка с выбранным устройством: отправленное справа со
  временем, ✓ при успехе или текстом ошибки под сообщением; пришедшее с
  этого устройства и выполненное по разрешению (`clipboard`, `open_url`) —
  слева. Нажатие на сообщение копирует его текст, «Copied». `⋮ → Clear`
  чистит ленту с этим устройством.
- Окно закрывается ✕, «назад» или нажатием вне окна.

**Телефон → ПК: текст из «Поделиться» и выделенный.** «Поделиться» текстом
(без файлов) открывает то же окно с этим текстом в поле вместо буфера
([поделиться текстом](share-text.ru.md)). Текст, выделенный в любом
приложении и отправленный пунктом «Send to device» меню выделения, делает то
же; текст в исходном приложении не меняется.

**ПК → телефон.** Пришёл файл, имя которого подходит под формат служебного,
и тело разбирается. Каждая команда выполняется, если у получателя для этого
вида и этого отправителя стоит разрешение. Потом файл удаляется, что бы ни
случилось с командами. Если имя подходит, а тело не разбирается или версия
неизвестна, файл остаётся обычным файлом во входящих.

## Формат

**Имя:** `lx-<время>-<метка>.json`
- `<время>` — UTC отправителя, `YYYYMMDDTHHMMSSZ`;
- `<метка>` — 5 случайных символов `[a-z0-9]`;
- ядро при совпадении имён может переименовать файл; получатель узнаёт
  служебный файл по префиксу `lx-` и суффиксу `.json`.

Хеш содержимого в имени не проверяется: без общего секрета он ничего не
защищает (решение владельца 2026-11-02 — без спаривания).

**Тело:** JSON в UTF-8 без BOM, не больше 64 KiB.

```json
{"lx": 1, "commands": [
  {"kind": "clipboard", "text": "…"},
  {"kind": "open_url", "url": "https://…"}
]}
```

- `lx` — версия формата; неизвестная версия означает обычный файл.
- `commands` — по порядку; неизвестный `kind` пропускается, остальные
  выполняются.

## Команды

| `kind` | Поле | Что делает получатель-телефон | Ограничения |
|--------|------|-------------------------------|-------------|
| `clipboard` | `text` | кладёт текст в буфер | не пустой; переводы строк как есть; из нескольких подряд — последний по времени приёма |
| `open_url` | `url` | уведомление «Link from <device>: <url>», тап открывает ссылку в браузере | только `http`/`https`; другая схема — команда пропускается |

`open_url` на телефоне идёт через уведомление: Android не даёт фоновому
сервису открывать окна. Тап по уведомлению и есть подтверждение. На
десктопе лаунчер решает сам.

## Параметры

| Что | Значение |
|-----|----------|
| Кнопка уведомления | «📋 Send clipboard» рядом со Stop; плитки быстрых настроек нет (решение владельца 2026-11-03) |
| Когда есть окно и его входы | «📋 Send clipboard», «Send to device» и LxBox в «Поделиться» — только пока VPN поднят и в работающем конфиге есть узел Tailscale с Allow Taildrop |
| Получатель | `To: … ▾` в окне: свои устройства, принимающие файлы, со всех таких узлов; запоминается на этом телефоне |
| Лента | только в памяти, пока работает VPN; не больше 50 сообщений на устройство (узел + устройство); `⋮ → Clear` |
| Разрешения | у получателя, на каждое своё устройство и каждый вид: «Clipboard from this device», «Links from this device»; по умолчанию выключены; в блоке Taildrop страницы устройства на вкладке Network узла |
| Свежесть (TTL) | 2 минуты по часам получателя от момента приёма; старше — удаляется без выполнения |
| Размер | не больше 64 KiB |
| Бэкап | запомненный получатель и разрешения в бэкап не входят (решение владельца 2026-11-02) |
| Подтверждение отправки | ✓ или текст ошибки под сообщением в ленте; отдельного уведомления нет |

Префикс, суффикс, лимит, TTL и версия формата — константы контракта с
лаунчером (`docs/contract` и реестр). Формат заменяет протокол `lxclip-*`
контракта 1.1.146: его не реализовала ни одна сторона.

## Входы / Выходы

**Входы:** нажатие «📋 Send clipboard» и буфер в момент, когда окно получило
фокус; «Поделиться» текстом; «Send to device» с выделенным текстом; ➤ и
«Open on <device>»; входящие служебные файлы и их отправитель Taildrop;
выбранный получатель; разрешения.

**Выходы:** служебный файл выбранному устройству; ✓ или ошибка в ленте либо
причина отказа над полем; буфер телефона; уведомление со ссылкой;
выполненные входящие команды — в ленте их отправителя; предупреждение в
логе приложения о битом служебном файле.

## Правила и инварианты

- **Отправка.** Буфер читается только когда окно получает фокус; при
  копировании ничего не отправляется, без ➤ или «Open on <device>» ничего не
  уходит (P11). Клип, который Android пометил как чувствительный (пароль),
  показывается в поле как любой другой: перед отправкой видно всё (решение
  владельца 2026-11-03; правило контракта «не отправлять чувствительный
  клип» — про отправку без показа).
- **Отказы.** ➤ и «Open on» неактивны, причина стоит над полем, первая
  подходящая: VPN выключен или ни один узел Tailscale не работает — `Start
  VPN to send`; ни у одного узла нет Allow Taildrop — `Taildrop is off for
  this node.`; ни одно устройство не принимает файлы — `No devices accept
  files`; получатель не в сети — `Device is offline.`; текст больше лимита —
  `Too large to send`. Пустое поле гасит кнопки без причины. Ошибка ядра при
  отправке — под сообщением в ленте.
- **Лента.** Только в памяти: остановка VPN и гибель процесса её стирают,
  файла нет. Текст буфера и ссылки из неё не попадают в лог приложения и
  Debug API; Debug API показывает только запомненного получателя (имя — с
  `reveal`) и число сообщений в лентах.
- **Приём** (P12). Команда выполняется, только если для её вида и её
  отправителя стоит разрешение. Отправитель — это отправитель Taildrop.
- **Перехват.** Служебный файл разбирается раньше автосохранения и
  уведомления «принят» ([входящие](inbox.ru.md)): разобранный не попадает
  ни в Downloads, ни во входящие (P10).
- **Удаление.** После разбора файл удаляется всегда, даже если ни одна
  команда не выполнена (нет разрешения, просрочен).
- **Свежесть.** Файл старше TTL на момент, когда получатель его обнаружил,
  удаляется без выполнения.
- **Серии.** Из нескольких команд `clipboard`, пришедших подряд, применяется
  последняя по времени приёма.
- **Безопасность.** Отправителя подтверждает Tailscale: файлы принимаются
  только от своих устройств (или по праву из ACL). Внутри разрешённого
  устройства любая программа может прислать служебный файл — поэтому
  команды только безобидные. Никаких произвольных команд, скриптов, путей и
  intent'ов в теле.
- **Без обратной петли.** Полученная команда никогда не отправляется
  дальше сама.
- Текст буфера и ссылки не пишутся в лог приложения, дамп для поддержки и
  Debug API.

## Границы

- Только между LxBox и лаунчером. Официальный клиент Tailscale показывает
  служебный файл как обычный `.json`.
- Нет чтения буфера из фона и автоматической отправки при копировании; нет
  плитки быстрых настроек для буфера.
- Только текст; картинки и другие типы клипов не отправляются.
- Управление VPN и добавление подписок — не в этой версии.
- Сторона лаунчера — его собственная спека: буфер на macOS, Windows и
  удалённых lxd (через gRPC), на Linux classic и Windows 386 буфера нет;
  отправка с ПК — пункт трея «Send clipboard to <phone>», без глобальной
  горячей клавиши.
- На устройстве не проверено: окно, чтение буфера по фокусу, пункт меню
  выделения, включение и выключение входов, кнопка уведомления. Логика окна
  покрыта JVM-тестами (задача 707, итерация 7).
