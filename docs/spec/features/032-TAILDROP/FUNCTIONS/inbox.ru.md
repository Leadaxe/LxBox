# Входящие — файлы со своих устройств, у каждого узла Tailscale свои

Файлы, присланные на телефон со своих устройств tailnet, принимаются без
запроса во входящие того узла, через который пришли, объявляются
уведомлением и лежат на вкладке Network этого узла, пока пользователь их не
сохранит или не удалит.

| Поле | Значение |
|------|----------|
| Фича | [032-TAILDROP](../FEATURE.ru.md) |
| Обещания | P4–P7 |
| Состояние | ✍ Черновик, 2026-11-01 — не реализована |

## Что делает

Пока файл идёт, уведомление «receiving from X» показывает прогресс и
предлагает Cancel. Когда файл принят, уведомление становится «file from X» с
Save и Delete. На вкладке Network узла под Devices есть блок входящих: каждый
принятый файл с Save и Delete. Save кладёт файл в Downloads; Delete удаляет
его. Тап по любому из уведомлений открывает вкладку Network узла, принявшего
файл.

## Параметры

| Что | Значение |
|-----|----------|
| От кого принимается | свои устройства tailnet узла; без шага согласия |
| Куда попадает | во входящие узла, хранятся в `<state_directory узла>/taildrop` (по умолчанию у ядра одна папка `Taildrop` на все узлы, сборка подставляет свою) |
| Уведомление во время приёма | «receiving from X», Cancel |
| Уведомление по завершении | «file from X», Save, Delete |
| Блок входящих | вкладка Network узла, под Devices; у каждого файла Save, Delete |
| Куда сохраняет Save | Downloads |
| Тап по уведомлению | вкладка Network узла-получателя |

## Входы / Выходы

**Входы:** входящие файлы Taildrop со своих устройств; нажатия Cancel, Save,
Delete и тап по уведомлению; удаление узла.

**Выходы:** файлы во входящих узла; файл в Downloads; уведомления; блок
входящих на вкладке Network.

## Правила и инварианты

- У каждого узла Tailscale свои входящие; файлы никогда не показываются под
  другим узлом.
- Cancel останавливает передачу и не оставляет во входящих частичного файла.
- Принятый файл лежит во входящих через перезапуски приложения и VPN, пока
  его не сохранят или не удалят (P6). Удаление узла удаляет его входящие
  вместе с его состоянием.
- Сохранённый файл уходит из входящих; копия, которую пользователь оставляет
  себе, — в Downloads.
- При выключенном VPN или неработающем узле ничего не принимается (P7); блок
  входящих по-прежнему показывает принятое раньше.
- Файл с префиксом буфера от отправителя, у которого включено «Accept
  clipboard from <device>», — не файл входящих, см.
  [синхронизацию буфера](clipboard-sync.ru.md); от любого другого отправителя
  это обычный файл во входящих.
- Имена файлов и устройств не пишутся в лог приложения, дамп для поддержки и
  Debug API.

## Границы

- Нет запроса «принять/отклонить» и списка разрешённых устройств: Tailscale
  доставляет только со своих устройств, это и есть граница доверия.
- Нет предпросмотра и открытия файла внутри LxBox; пользователь сохраняет его
  и открывает другим приложением.
- Входящие не входят в бэкап.
- Приём требует включённого в админке tailnet Taildrop (возможность file
  sharing у этого узла); без него блок входящих показывает причину.
- Уже сегодня ядро молча принимает файлы в свою папку по умолчанию, вне
  всякого интерфейса; оставшиеся там до фичи файлы один раз переносятся во
  входящие первого узла Tailscale ([особенности сопровождения](../FEATURE.ru.md#особенности-сопровождения)).
  Работа приёма в userspace-стеке подтверждена по коду, не на устройстве.
- На устройстве не проверено.
