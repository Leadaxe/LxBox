# Регистрация в один тап

| Поле | Значение |
|------|----------|
| Фича | [015-WARP](../FEATURE.md) |
| Обещания | P1, P2, P3, P4, P16, P17 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

По кнопке «Register» в мастере «Get WARP» регистрирует устройство в
Cloudflare WARP напрямую через API Cloudflare, без сторонних генераторов.
Ключ туннеля создаётся на телефоне; в Cloudflare уходит только публичная
часть. Регистрация кэшируется и переиспользуется всеми следующими узлами того
же транспорта, пока пользователь не попросит новую.

## Параметры

| Параметр | Значение |
|----------|----------|
| Хосты API | `api.hosts` пула; по умолчанию `https://api.devices.cloudflare.com`, затем `https://api.cloudflareclient.com` |
| Путь / версия клиента | `v0a2158` · `CF-Client-Version: a-7.21-0721` · `User-Agent: okhttp/3.12.1` |
| Таймаут | 5 с на один запрос к одному хосту |
| WARP+ license key | пусто — free; только транспорт WireGuard |
| Re-register (force new account) | выкл |

## Входы / Выходы

**Входы:** выбранный транспорт, лицензия, флаг Re-register; ответы
`POST /reg`, `PATCH /reg/{id}/account` (лицензия), `PATCH /reg/{id}`
(MASQUE enroll).

**Выходы:** регистрация WG (ключ, ключ пира, адреса v4/v6, `client_id`,
устройство, токен, лицензия, признак WARP+) или MASQUE (ECDSA-ключ в SEC1
DER, ключ сервера в PKIX DER, адреса, сервер и порт data-plane); кэш
регистрации; строка журнала с маской секретов.

## Правила и инварианты

- **WireGuard.** X25519-пара на устройстве → `POST /reg` с публичным ключом.
  При лицензии — `PATCH …/account` тем же токеном на тот же хост; любой отказ
  (сеть, 4xx, нет токена) — остаётся free-аккаунт, узел всё равно
  добавляется, снек «Added WARP node» вместо «Added WARP+ node».
- **MASQUE — два шага.** `POST /reg` с одноразовым настоящим X25519-ключом
  (случайные 32 байта ловили 401 «Invalid public key»), затем
  `PATCH /reg/{id}` c публичным ECDSA P-256 (`key_type: secp256r1`,
  `tunnel_type: masque`). Ключ сервера из ответа, пришедший PEM, приводится к
  чистому base64(DER); порт `0` → 443; `:0` в адресе снимается.
- **Перебор хостов.** Исключение клиента или таймаут — следующий хост; любой
  HTTP-ответ — итог. Все хосты глухи — ошибка «network error:» с перечнем.
  Ответивший хост обслуживает весь поток (enroll, лицензия); между
  регистрациями победитель не запоминается.
- **Ошибки ответа** видит пользователь снеком: «registration failed (HTTP N).
  API version may have changed», «bad response: not JSON / missing config /
  missing peer public_key / missing interface address», для MASQUE —
  «MASQUE enroll failed (HTTP N)». Узел не добавляется, кэш не трогается.
- **Кэш.** Без Re-register берётся кэш своего транспорта (WG и MASQUE
  раздельно). Re-register — новая регистрация, кэш перезаписывается. Кэш WG
  без WARP+ при введённой лицензии не используется: регистрация новая.
- **Секреты.** Приватный ключ, токен и лицензия в журнал не пишутся —
  только маска `<redacted>`.
- **Резервная копия.** Регистрации уезжают записями `warp[]`
  (`type: wg|masque`, канонические имена полей); запись без приватного ключа
  или ключа пира при импорте отбрасывается; запись без `type` — предупреждение,
  а не молчаливая потеря.

## Границы

- Регистрация — прямой запрос приложения; выбрать узел или detour для неё
  нельзя.
- WARP+ для MASQUE не поддержан.
- Удаления устройства в Cloudflare нет: Re-register оставляет старое
  устройство в аккаунте Cloudflare.
- Регистрация без интерфейса (`POST /warp`, только WireGuard) —
  013-DIAGNOSTICS, Debug API.
