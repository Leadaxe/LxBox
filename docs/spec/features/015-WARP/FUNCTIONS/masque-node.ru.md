# MASQUE-узел WARP — WARP поверх HTTP/3 или HTTP/2

MASQUE-узлу нужна собственная MASQUE-регистрация, отдельная от WireGuard.

| Поле | Значение |
|------|----------|
| Фича | [015-WARP](../FEATURE.ru.md) |
| Обещания | P9, P10, P11, P12 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Переключатель Transport = MASQUE даёт тот же WARP другим транспортом:
IP-пакеты внутри HTTP/3 (QUIC) или HTTP/2 (TCP) к Cloudflare — снаружи это
обычный HTTPS на 443 и соседних портах, а выход часто в другой стране.
Узел — outbound `masque` ядра sing-box-lx с профилем `cloudflare`.

## Параметры

| Параметр | Ключ ядра | Значения | Дефолт |
|----------|-----------|----------|--------|
| Transport | `vhttp` | Auto (h3 → h2) · HTTP/3 (QUIC) · HTTP/2 (TCP) | Auto |
| Endpoint IP | `server` | IP; пресеты по транспорту; 🎲 | пусто = сервер регистрации (виден подсказкой) |
| Port | `server_port` | набор портов транспорта + ввод | первый порт набора |
| SNI | `tls.server_name` | домен; SNI-пул MASQUE; 🎲 | случайный из пула |
| Idle timeout (min) | `idle_timeout` | минуты → `Nm`; пусто/0 — не писать | пусто |
| Keep-alive (sec) | `keep_alive_period` | секунды → `Ns`; недоступно при HTTP/2 | пусто |
| Фиксировано | `profile: cloudflare`, `mtu: 1280`, `ip`/`ipv6` из регистрации | — | — |

## Входы / Выходы

**Входы:** MASQUE-регистрация (кэш или свежая), ввод мастера, MASQUE-секция
пула.

**Выходы:** одиночный сервер со ссылкой `masque://<ключ>@<server>:<port>?
publickey=…&address=…&profile=cloudflare&vhttp=…&mtu=1280[&sni=…]
[&idle_timeout=…][&keep_alive=…]#…`; в конфиге — outbound `masque` новой
схемы. Тег `🔥🎭 WARP (MASQUE)`, занятый — суффикс ` 2`…; снек «Added MASQUE
node»; при сбое сборки — «Invalid MASQUE config».

## Правила и инварианты

- **Схема ядра.** В конфиг пишутся только `vhttp` и вложенный `tls{}`;
  старые `network`/`sni` в корне не пишутся никогда (старое и новое имя с
  разными значениями — отказ ядра). Пустой SNI — блока `tls` нет, решает
  ядро. `tls.disable_sni` мастер не выставляет.
- **Старые ссылки.** Параметр `network=` в `masque://` не читается (контракт
  0.8.0): такая ссылка разбирается, но версия HTTP берётся по умолчанию —
  `h3`. Ссылка без `vhttp` — явный `h3`, не `auto`; мусорное значение →
  `h3` с предупреждением реестра.
- **Версия HTTP — у узла.** В кэш регистрации не пишется; одна регистрация
  порождает узлы любой версии, identity WARP-узла от версии не зависит.
- **IP:порт.** Заданный IP или порт идёт только в узел, кэш хранит сервер
  регистрации. При смене транспорта порт вне набора нового транспорта
  сбрасывается на первый; пресет-хост, которого у нового транспорта нет
  (h3-only при переходе на h2), очищается; ручной IP не трогается.
- **Хосты по транспорту.** h3 — общие + h3-only хосты; h2 и Auto — только
  общие. 🎲: h3 — из h3-хостов, h2/Auto — случайный адрес блока кроме
  исключений; порт — случайный из набора транспорта.
- **SNI, таймауты** применяются к кэшу без новой регистрации.
- **Фрагментация TLS** (глобальная настройка) доходит до узла при `h2` и
  `auto`, не под detour; при `h3` — молча нет.

## Границы

- WARP+ и обфускация AWG для MASQUE не предусмотрены.
- Автопадение `auto` с h3 на h2, запоминание победителя, умолчания таймаутов
  — поведение ядра (FEATURE 009-MASQUE_WARP ядра).
- Профиль `standard`, импорт чужих MASQUE-конфигов — вне фичи (разбор —
  002-NODE_IMPORT).
