# FEATURE 015 — WARP — Cloudflare WARP глазами пользователя

| Поле | Значение |
|------|----------|
| Тип | Продуктовая фича |
| Поглотила | `§025F` `§130F` |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Назначение

Пользователь хочет бесплатный рабочий туннель без чужих конфигов и сайтов-
генераторов. Фича регистрирует устройство в Cloudflare WARP одним нажатием
«Register» в мастере «Get WARP» (меню экрана Servers) и сразу кладёт готовый
узел в список: WireGuard-узел (при желании — с обфускацией AmneziaWG) или
MASQUE-узел (CONNECT-IP поверх HTTP/3 или HTTP/2). Отдельно — «Make
experiment»: папка случайных WARP-узлов по пулу известных адресов, чтобы
найти, что пролезает в конкретной сети.

Фича защищает пять принципов:

- **Ключ туннеля рождается и остаётся на устройстве.** Никаких сторонних
  генераторов конфигов: их владелец знает приватный ключ каждого. В Cloudflare
  уходит только публичная часть.
- **Одна регистрация — много узлов.** Регистрация кэшируется и
  переиспользуется; параметры узла (endpoint, обфускация, версия HTTP, SNI)
  меняются без новой регистрации. Новая — только по явному «Re-register».
- **Выбор пользователя сильнее умолчаний.** Вписанный вручную endpoint не
  затирается ни ответом Cloudflare, ни кэшем, ни рандомом.
- **Данные пулов — не код.** Адреса, порты, SNI, хосты API и региональные
  поправки живут в одном файле пула и правятся без смены логики.
- **К ядру — только его текущая схема.** MASQUE уходит в конфиг ключами
  `vhttp` и `tls{}`; обфускация — ключами ядра `id`/`ip`/`ib`, служебный
  пакет `i1` строит ядро, а не приложение.

## Обещания

- **P1. Приватный ключ не покидает устройство.** WireGuard: в запрос
  регистрации уходит публичный X25519-ключ. MASQUE: первый запрос несёт
  одноразовый публичный X25519-ключ, второй — публичный ECDSA P-256 в DER.
  Свидетель: юниты «register: в /reg уходит pub, не priv», «registerMasque:
  … в POST — 32-байтный ключ», «PKIX public key: SPKI-структура». Мутация:
  в тело запроса попадает приватник.
- **P2. Глухой хост API не ломает регистрацию.** Хосты перебираются по
  порядку; сетевая ошибка или таймаут (5 с на запрос) — следующий хост; любой
  HTTP-ответ, включая 4xx/5xx, — итог; все хосты глухи — ошибка с перечнем
  хостов. Последующие запросы потока идут на ответивший хост. Свидетель: юниты
  «первый хост недоступен → регистрация через второй; license туда же»,
  «таймаут первого хоста → второй», «HTTP-ошибка первого хоста — итог»,
  «все хосты недоступны → WarpException с перечнем хостов», «registerMasque:
  PATCH туда же». Мутация: 4xx переключает хост; PATCH идёт на первый хост.
- **P3. Негодная лицензия WARP+ не мешает получить узел.** Отказ привязки
  лицензии оставляет free-аккаунт, узел добавляется. Свидетель: юнит
  «license: PATCH 4xx → free-аккаунт сохраняется». Мутация: ошибка лицензии
  роняет регистрацию.
- **P4. Повторный «Register» не регистрирует заново.** Без «Re-register»
  берётся кэш регистрации своего транспорта; с «Re-register» — новая
  регистрация, кэш заменяется. Кэш free-аккаунта при введённой лицензии не
  используется — регистрация новая. Свидетель: ручная проверка — дважды
  Register без галки: в журнале одна строка `WARP registered`, у обоих узлов
  один адрес интерфейса. Мутация: кэш игнорируется.
- **P5. Каждый «Register» добавляет новый узел.** Прежние WARP-узлы не
  удаляются; занятый тег получает суффикс ` 2`, ` 3`… Тег по виду:
  `🔥☁️ WARP`, `🔥⛈️ WARP (AWG 1.5)`, `🔥🎭 WARP (MASQUE)`, `+` для WARP+.
  Свидетель: юнит «§137 nodeTag: облако/гроза, +, AWG-суффикс»; накопление —
  ручная проверка. Мутация: новый узел заменяет прежний.
- **P6. Свой endpoint WireGuard не затирается.** Не-дефолтный endpoint
  попадает в узел и при свежей регистрации (ответ Cloudflare игнорируется), и
  при кэше; дефолтный — заменяется хостом из ответа. Свидетель: юниты «§135
  register: кастомный endpoint НЕ затирается», «§135 дефолтный endpoint →
  fallback на host из ответа», «§138 copyWith(endpoint)». Мутация: endpoint
  из кэша побеждает ввод.
- **P7. Plain-узел WARP несёт привязку к устройству.** `reserved` из
  `client_id` (3 байта), MTU 1280, весь трафик в `allowed_ips`, keepalive 25 с
  по умолчанию; при обфускации `reserved` по умолчанию не пишется; keepalive
  0 — не пишется. Свидетель: юниты «toWireguardUri несёт reserved и
  парсится», «keepalive=25 → query keepalive», «keepalive=0 → не пишется»,
  «§142 includeReserved=false → НЕТ Reserved». Мутация: узел без `reserved`
  при выключенной обфускации.
- **P8. Обфускация не ломает рукопожатие WARP.** Пресет: `s1=s2=0`,
  `h1..h4=1,2,3,4`, `jc/jmin/jmax` (по умолчанию 4/40/70) плюс ключи
  маскировки `ip`/`id`/`ib` (`ib` — только при `ip=quic`); `i1` приложение
  не пишет. Свидетель: юниты «preset: s1=s2=0, h1..h4=1,2,3,4», «§143
  buildAmneziaAwg(quic): id/ip/ib, БЕЗ i1», «buildAmneziaAwg(dns): ib НЕ
  пишется», «§143 obfuscated: AWG + id/ip/ib + reserved доходят до spec».
  Мутация: `i1` рядом с `id`/`ip`/`ib` (ядро отвергает оба).
- **P9. MASQUE уходит в конфиг только новой схемой.** Outbound `masque`:
  `vhttp`, SNI и отказ от SNI — во вложенном `tls{}`; ключей `network`/`sni`
  в корне нет; пустой SNI — нет блока `tls`. Свидетель: юниты «emitMasque даёт
  Outbound со схемой ядра», «SNI и disable_sni уезжают во вложенный tls{}»,
  «пустой SNI не создаёт пустой tls{}». Мутация: запись старого и нового имени
  рядом (ядро падает на расхождении).
- **P10. Версия HTTP — свойство узла, не регистрации.** Одна MASQUE-
  регистрация даёт узлы `h3`, `h2`, `auto`; identity WARP-узла не сдвигается
  ни на одной версии. Свидетель: юниты «§393 — версия HTTP задаётся при сборке
  URI, а не хранится в аккаунте», «узел фабрики WARP не сдвинулся ни на одной
  версии HTTP». Мутация: версия HTTP в кэше регистрации.
- **P11. Ручной IP:порт MASQUE — только в узел.** Кэш держит сервер из
  регистрации; пустое поле IP — сервер регистрации. Свидетель: без
  свидетеля. Мутация: override пишется в кэш и уезжает во все будущие узлы.
- **P12. h3 не предлагается там, где он мёртв.** Рандом и список хостов для
  `h3` — только h3-хосты пула; для `h2`/`auto` — общие хосты и блок минус
  исключения. Свидетель: юниты «§420 randomMasqueIp: h3 — только из
  h3-хостов; h2 — блок минус exclude», «§420 masqueHostsFor: h3 — общие +
  h3-only; h2 и auto — только общие». Мутация: h3-рандом по всему блоку.
- **P13. Регион правит пул, а не логику.** Секция `loc.<страна>` пула
  накладывается на корень: объекты сливаются, списки заменяются целиком,
  `alias` — один переход; неизвестный регион — корень. Свидетель: юниты
  «override по ключу; … список целиком», «alias — один переход»,
  «пустой/неизвестный/битый регион = корень», «кэш пикера привязан к
  региону». Мутация: списки региона дописываются к корню.
- **P14. Пометка «(recommended)» не утекает в значение.** Свидетель: юнит
  «§424 label = чистое значение». Мутация: суффикс пресета в endpoint.
- **P15. Эксперимент не привилегирует протокол.** Кандидаты равновероятно
  AWG / MASQUE h3 / MASQUE h2 среди доступных по пулу; порт — из набора своего
  транспорта; протокол без источника не сеется. Свидетель: юниты «покрывает
  все три протокола при полном пуле», «§305 — порт согласован с протоколом»,
  «wg-диапазон, но БЕЗ wg-портов → только masque, без краша». Мутация: AWG
  при пустом наборе портов.
- **P16. Секреты регистрации не пишутся в журнал.** В журнал идёт
  представление с маской приватника, токена и лицензии. Свидетель: юниты
  «WarpAccount.redacted маскирует priv_key/token/license», «redacted маскирует
  приватник и токен». Мутация: полная регистрация в строке журнала.
- **P17. Регистрации переживают резервную копию.** Свидетель: юниты «warp:
  круг сохраняет регистрацию и мобильные добавки», «§219 — warp_account/
  masque_account переживают restore». Мутация: восстановление без регистраций
  — новый «Register» плодит устройство.

Мастер «Get WARP»:

| Bind to this device (reserved) | вкл/выкл | = не обфускация | WG |

| Masquerade domain (`id`) | домен, пул, 🎲 | случайный из пула | WG+обфускация |
| Browser (`ib`) | Chrome · Firefox · cURL | Chrome | при `ip=quic` |
| Jc / Jmin / Jmax | числа | 4 / 40 / 70 | WG+обфускация |
| Transport (версия HTTP) | Auto (h3 → h2) · HTTP/3 · HTTP/2 | Auto | MASQUE |
| Endpoint IP / Port | IP, пресеты по транспорту, 🎲; порт из набора | пусто = из регистрации; первый порт набора | MASQUE |
| SNI | домен, пул, 🎲 | случайный из пула | MASQUE |

| Re-register (force new account) | вкл/выкл | выкл | оба |

«Make experiment»: Number of nodes 1–200 (дефолт 20), JSON пула (дефолт —
встроенный пул). Общая настройка «Usage region» (Auto · Not set · код
страны) выбирает секцию `loc.<cc>` пула.

Ключи конфига ядра, которые отдаёт фича:

- endpoint `wireguard`: `address`, `private_key`, `mtu`, `peers[].address`/
  `port`/`public_key`/`reserved`/`allowed_ips`/`persistent_keepalive_interval`;
  при обфускации в корне — `jc`, `jmin`, `jmax`, `s1`, `s2`, `h1`–`h4`, `ip`,
  `id`, `ib`;
- outbound `masque`: `server`, `server_port`, `profile: cloudflare`, `vhttp`,
  `private_key`, `public_key`, `ip`, `ipv6`, `mtu: 1280`, `tls.server_name`,
  `tls.disable_sni`, `idle_timeout`, `keep_alive_period`.

## Входы / Выходы

**Входы:** нажатия мастера; ответы API регистрации Cloudflare (`/reg`,
`/reg/{id}`, `/reg/{id}/account`); файл пула (`api`, `wireguard`, `masque`,
`loc`); настройка региона; системный флаг IPv6 (разрешает v6-адреса WG).

**Выходы:** узел в списке Servers (одиночный сервер со ссылкой
`wireguard://…` или `masque://…`); папка «WARP GENERATOR»; кэш регистраций
WG и MASQUE; записи `warp[]` в резервной копии; снек «Added WARP node» /
«Added WARP+ node» / «Added MASQUE node» или текст ошибки.

## Data flow

```
мастер → [кэш регистрации транспорта?] ─ да ─┐
            │ нет / Re-register              │
            ▼                                │
   ключ на устройстве → POST /reg (перебор хостов API)
            │ WG: (+PATCH лицензии)   MASQUE: PATCH enroll ECDSA
            ▼                                │
   регистрация → кэш ◄───────────────────────┘
            ▼
   параметры узла (endpoint, обфускация, vhttp, SNI, IP:порт)
            ▼
   ссылка узла → общий разбор → новый одиночный сервер с тегом WARP
            ▼
   сборка конфига → endpoint `wireguard` / outbound `masque`
```

Эксперимент: пул (+регион, +правка JSON) → кэш или регистрация обоих
транспортов → N случайных кандидатов → ссылки → папка «WARP GENERATOR».

## Правила и гарантии

- Регистрация без сети/с ошибкой — узел не добавляется, кэш не меняется.
- Ответ без ключа пира или без адреса интерфейса — ошибка «bad response»,
  узла нет. MASQUE-ответ сервера в PEM приводится к base64(DER).
- Обфускация клиентская: включение/выключение на кэше не требует новой
  регистрации. Включение подставляет случайный `ip:port` из блоков WG, если
  endpoint не вписан руками; выключение возвращает поля к умолчаниям.
- v6-адреса WG подставляются только при включённом IPv6 в системе.
- Кэши регистраций WG и MASQUE раздельны и в конфиг не идут — только узлы:
  WG — endpoint, MASQUE — outbound; оба работают как обычные узлы.
- Глобальная фрагментация TLS касается MASQUE-узла только при `h2`/`auto`
  (есть TCP-плечо) и не под detour; `h3` пропускается молча.

## Границы

- Разбор ссылок `wireguard://` / `masque://` / WG INI — 002-NODE_IMPORT;
  фича только порождает ссылки.
- Правка готового узла — 008-NODE_EDITOR; пинг и проверка папки
  «WARP GENERATOR» — 009-NODE_HEALTH (эксперимент сам не пробует и мёртвые
  не удаляет).
- Регистрация идёт прямым запросом приложения: выбрать для неё узел или
  detour нельзя; при глухих хостах подсказки «зарегистрируй через прокси» нет.
- WARP+ для MASQUE не поддержан (поле лицензии в режиме MASQUE скрыто).
- Проверка формата `host:port` endpoint'а перед регистрацией не делается.
- `tls.disable_sni` в мастере не выставляется — только через ссылку/импорт.
- Автоопределение страны зависит от возможностей ОС (сеть оператора → локаль).
- Секреты в Debug API не маскируются намеренно (root-доступ by design,
  013-DIAGNOSTICS); регистрация без интерфейса — `POST /warp` там же.

## Особенности сопровождения

- **Версия API подвижна.** Путь `v0a2158` и заголовок клиента `a-7.21-0721`
  Cloudflare периодически меняет; 4xx на `/reg` — первым делом сверять с
  актуальным `wgcf`/`warp-cli`.
- **`api.cloudflareclient.com` из РФ молчит на TCP.** Поэтому первым идёт
  `api.devices.cloudflare.com`; встроенный запасной список обязан совпадать
  с `api.hosts` пула.
- **h3 живёт на единицах адресов.** В `162.159.198.0/24` и `.199.0/24`:
  `.1` — только h3, `.2` — оба, остальные — только h2. Рандом h3 по блоку
  даёт ~1% живых.
- **Наивная проба врёт про QUIC.** Живость MASQUE мерить через боевое ядро
  (переподключение + URLTest), а не пробой при выключенном VPN.
- **Без keepalive WG-узел WARP «гниёт»**: NAT закрывается за 30–120 с.
