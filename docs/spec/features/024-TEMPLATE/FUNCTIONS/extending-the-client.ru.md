# Развитие клиента — новая возможность через шаблон

Новый пресет, DNS-сервер, переменная или rule set добавляются в LxBox правкой поставляемого
шаблона; код пишется только когда самому языку шаблона нужна новая конструкция или экрану — новый
вид поля.

| Поле | Значение |
|------|----------|
| Фича | [024-TEMPLATE](../FEATURE.ru.md) |
| Обещания | — (процесс; поведение, на которое он опирается, обещают другие функции) |
| Состояние | ✅ написана по коду, 2026-09-29 |

## Что делает

Закрепляет процедуру «новая возможность через шаблон»: что добавляется без
кода, что требует кода, в каком порядке идёт работа и какие документы
меняются. Текст шаблона общий с десктопным лаунчером, поэтому у процедуры
две стороны: репозиторий приложения и контракт лаунчера.

## Параметры

**Добавляется без кода** (только правка шаблона, тесты и локализация):

| Возможность | Что попадает в шаблон | Реальный пример |
|---|---|---|
| Пресет | запись `selectable_rules[]`: `preset_id`, `ui`, `vars`, `rule`/`rules`, `rule_set`, DNS-части | [371](../../../tasks/371-vowifi-direct.md) VoWiFi — «код не трогается»; [364](../../../tasks/364-fcm-push-bypass-preset.md) Google push (FCM) — шаблон, ru-оверлей, три теста разворота |
| Rule set внутри пресета с галкой | запись `rule_set[]` с `#enable: ["@флаг"]`, переменная `bool`, правило со ссылкой на набор | [531](../../../tasks/531-ru-app-list-ruleset-in-ru-preset.md) Russian apps by package в Ru internet segment |
| Сервер каталога DNS | запись `dns_options.servers[]` с телом `server` и необязательными `vars` | [527](../../../tasks/527-dns-shield-yandex-dot-base.md) `yandex_dot` базовой записью |
| Переменная с полем на типовом экране | запись `sections[].vars[]` с `wizard_ui: edit` и `@var` или `#if` в каркасе или пресете | переменные `tun_*`, `log_level` |
| Ref-переменная в пресете | `{"ref": "<глобальная>"}` в `vars[]` пресета; глобальная существует (секция `internal`, если её не надо показывать) | [264](../../../tasks/264-traffic-processing-preset.md) `resolve_strategy` в Traffic Processing |
| Реакция `on_change` | `#on_change: {#set: {...}}` на переменной или на псевдопеременных пресета `rule_enable` / `dns_enable` | `ipv6_enabled` → стратегии; FakeIP → `resolve_enabled` |
| Пресет на каждый узел | `for_each{node_type, as, filter}`, `@node`, `#tpl` в теле | пресет `tailscale` ([578](../../../tasks/578-tailscale-preset-template-for-each.md)) |
| Смена умолчания или текста | `default_value`, `title`, `tooltip`, `ui.label`; ключи оверлея следуют за английским текстом | — |

**Требует кода** (правка шаблона — только часть изменения):

| Нужда | Почему код | Реальный пример |
|---|---|---|
| Новая конструкция языка | движок, валидатор на загрузке, модель, корпус, норматив лаунчера | [578](../../../tasks/578-tailscale-preset-template-for-each.md) `for_each`/`@node`/`#tpl`; [265](../../../tasks/265-ref-vars.md) `ref`; [264](../../../tasks/264-traffic-processing-preset.md) объект `ui`, locked/pinned |
| Переменная на своём экране или с границами | `wizard_ui: fix` рисует тот экран; границы `int` не в шаблоне | [580](../../../tasks/580-dns-cache-settings.md) переменные кэша DNS на вкладке DNS, 1024..65535 |
| Переменная нового `type` | рендер на экране настроек, приведение | — |
| Новый верхний ключ шаблона | читатель в сборке | — |
| Переменная, которая должна помечать конфиг устаревшим | список имён конфиг-переменных зашит в коде (аудит 588: 18 переменных в нём отсутствуют) | — |
| Пресет, который должен дойти до пользователей с сохранённым состоянием | список поздних дефолтов | [578](../../../tasks/578-tailscale-preset-template-for-each.md) `tailscale` |
| Новое поле записи (поле узла, которое читает пресет) | хранение, бэкап, Debug API, перенос | `skip_presets` ([578](../../../tasks/578-tailscale-preset-template-for-each.md)) |
| Ключ конфига ядра | установленное ядро обязано его принимать; сверяется по исходникам ядра или реестру контракта | [580](../../../tasks/580-dns-cache-settings.md) `dns.cache_capacity`, `dns.optimistic`, `store_dns` |

## Входы / Выходы

**Входы:** решение владельца в задаче; текущий шаблон; норматив и реестр
лаунчера; текущие файлы оверлеев.
**Выходы:** правленый шаблон обеих сторон; бамп контракта (норматив, реестр,
корпус), когда меняется язык или общий текст пресета; обновлённые оверлеи,
тесты, golden-эталоны и документы.

## Правила и инварианты

Чеклист, по порядку:

1. **Сначала задача.** Решение владельца записано в `tasks/NNN-…` с
   выписанным фрагментом шаблона; текст пресета одинаков на обеих сторонах.
2. **Правка шаблона** в `wizard_template.json` по стилю оформления из
   `docs/TEMPLATE.md`; отображаемые тексты по-английски; каждая новая условная
   конструкция ссылается только на объявленные переменные, иначе поставляемый
   шаблон отвергается на загрузке ([P4](../FEATURE.ru.md#обещания)).
3. **Контракт, если менялся общий текст или язык:** запрос в лаунчер (раздел
   `TEMPLATE_LANG.md` для конструкции, `registry/vars.json` с `portable` для
   переменной, которая едет в переносе, случай корпуса для поведения движка);
   затем `app/tool/sync_contract.sh` бампает копию и lock. Конструкция без
   фикстуры не считается сделанной ([021-CORE_CONTRACT](../../021-CORE_CONTRACT/FEATURE.ru.md)).
4. **Локализация:** новые или переименованные отображаемые тексты получают
   ключи в `assets/l10n/<tag>/template.json` для каждого поставляемого языка;
   ключ — сам английский текст, поэтому изменённый текст — новый ключ.
5. **Тесты:** поставляемый шаблон проходит валидацию на загрузке; тест
   разворота пресета; golden-эталоны хранения и конфига, когда меняется
   эмитируемый конфиг; тесты `on_change` и засева, когда они затронуты.
6. **Существующие пользователи:** решить засев (поздние дефолты для нового
   дефолтного пресета; несортируемый пресет досевается сам), перенос значений
   (не нужен — хранение ключуется именем), allowlist бэкапа (переменные
   шаблона принимаются автоматически; новый верхний ключ надо добавить в
   allowlist и категорию бэкапа) и классификацию для слота Workspaces
   ([жизненный цикл шаблона](template-lifecycle.ru.md)).
7. **Документы:** `docs/TEMPLATE.md` (всегда: раздел, полевая матрица,
   таблица переменных); `TEMPLATE_LANG.md` в лаунчере, когда меняется язык;
   `docs/STORAGE.md`, когда добавляется поле записи; ревизии
   фичи-владельца (эта фича — для языка и каталога, 004/005/006 — для
   поведения); `F`-спека помечается superseded, когда изменение её заменяет;
   `CHANGELOG.md` Unreleased.
8. **Проверка:** эмитируемое правило декодируется ядром; поведение на
   трафике проверяется на устройстве там, где эмулятор его не показывает
   (пуши FCM, звонки VoWiFi остаются pending до этого).

Инварианты:

- Псевдопеременная пресета с `#on_change` несёт `default_value` и
  `required: false`; без них пресет молча ничего не эмитит.
- Цель ref-переменной обязана существовать в какой-то секции; переменная,
  которую не надо показывать, живёт в `internal`.
- `reject` как цель пресета пишется в шаблоне как `outbound: "reject"` и
  становится `action: reject` в сборке; других псевдоцелей нет.
- Второй `#if` на объекте, где один уже есть, пишется с суффиксом (`#if1`,
  `#if tun-only`).

## Границы

- Поведение добавленного — фичи-владельцы (004, 005, 006, 016).
- Лаунчерская сторона контракта правится в репозитории лаунчера; здесь
  описаны только запрос и синк.
- Пользователь шаблон не расширяет: ни пользовательского шаблона, ни своих
  пресетов.

## Документация

- [`docs/TEMPLATE.md`](../../../../TEMPLATE.md) — «что ломается, когда» и стиль

  лаунчера — норматив языка и фикстуры (копия приезжает через

- [021-CORE_CONTRACT](../../021-CORE_CONTRACT/FEATURE.ru.md) — как контракт
  версионируется и синхронизируется.
