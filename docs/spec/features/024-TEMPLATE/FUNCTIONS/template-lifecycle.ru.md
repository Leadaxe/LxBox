# Жизненный цикл шаблона — что новый шаблон делает с сохранёнными настройками

Обновление приложения приносит новый шаблон поверх сохранённого состояния пользователя; LxBox
засевает новое, держит переопределения пользователя по имени и не хранит ничего, что равно
умолчанию шаблона, поэтому шаблон и переопределения снова встречаются на каждой сборке.

| Поле | Значение |
|------|----------|
| Фича | [024-TEMPLATE](../FEATURE.ru.md) |
| Обещания | P10 P11 P13 |
| Состояние | ✅ написана по коду, 2026-09-29 |

## Что делает

Держит поставляемый шаблон и сохранённые переопределения пользователя
согласованными между обновлениями приложения. У шаблона нет собственной
версии: какой шаблон несёт установленная сборка, тот и текущий. Хранение
никогда не держит копию шаблона — только отклонения пользователя от него,
по именам шаблона (имена переменных, `preset_id`, теги DNS-серверов). При
каждом чтении и сборке к этим отклонениям применяется текущий шаблон.

## Параметры

| Метка в документе настроек | Смысл |
|---|---|
| `presets_migrated` | «дефолтные пресеты засеяны один раз» (чистая установка) |
| `late_presets_seeded[]` | id пресетов, ставших дефолтными после появления состояния у пользователей и предложенных один раз |
| `directions_migrated` | дефолтные Направления засеяны из шаблона один раз |
| `storage_version` | форма самого документа — [017-BACKUP_AND_STORAGE](../../017-BACKUP_AND_STORAGE/FEATURE.ru.md) |

`parser_config.version` (5) внутри шаблона читается в модель, но ничего на
него не завязано. Пользовательских ручек нет.

## Входы / Выходы

**Входы:** шаблон установленной сборки; документ настроек (`vars`, `rules[]`,
`dns{}`, `directions[]`, метки выше); резервная копия или слот Workspaces с
тем же документом.
**Выходы:** тот же документ с засеянными записями и вычищенными
переопределениями; строки журнала «default preset X added once»; счётчики
отброшенных ключей на импорте.

## Правила и инварианты

**Где живут переопределения.**

| Что изменил пользователь | Где хранится | Что по-прежнему даёт шаблон |
|---|---|---|
| Переменная секции (VPN Settings, Routing, DNS) | `vars.<имя>` — только значение | тип, умолчание, варианты, границы, экран, тексты |
| Пресет: включён, позиция, переменные, цель | запись `rules[]` `kind: preset` с `ref = preset_id`, `num`, `vars` (только неумолчательные значения; цель — `vars.outbound`) | тело, rule set, DNS-части, тексты `ui` |
| Шаблонный DNS-сервер: вкл/выкл, переменные | запись `dns.servers[]` `kind: template` с `tag`, `enabled`, `vars` | тело сервера |
| DNS-сервер пресета: вкл/выкл | запись `dns.servers[]` `kind: preset` с `ref = <preset_id>:<tag>`, `enabled` | тело сервера |
| Направление | `directions[]` — полная запись | только первый засев и шаблоны групп |

**Чистая установка.** Пресеты с `ui.default: true` добавляются один раз
(метка `presets_migrated`), дефолтные Направления из `default_directions` —
один раз (`directions_migrated`), DNS Final/Resolver/Strategy начинают с
`default_value` шаблона ([005-DNS · P8](../../005-DNS/FEATURE.ru.md#обещания)).

**Обновление с новым шаблоном поверх сохранённого состояния.**

- Новая переменная: сохранённого значения нет, действует умолчание; ничего
  не переносится (§580).
- Изменённое умолчание: все, кто значение не менял, следуют новому
  умолчанию, потому что равное значение никогда не хранилось; иное значение
  пользователя остаётся (P11). Закрепить текущее умолчание против его
  будущей смены нельзя по замыслу (§441).
- Переменная, переехавшая между секцией и пресетом (через `ref`), сохраняет
  значение пользователя: хранение ключуется именем, а не местом (§264).
- Удалённая переменная: сохранённое значение безвредно лежит до следующего
  импорта бэкапа, где его снимает allowlist (§159); разовых чисток на старте
  нет.
- Новый дефолтный пресет одним `default: true` до сохранённого состояния не
  доходит: первый засев прошёл один раз. Он добавляется один раз через список
  поздних дефолтов (сегодня: `tailscale`), включённым, на `num` шаблона;
  удаливший его пользователь обратно его не получает (P10). Несортируемый
  пресет (Traffic Processing) досевается на каждой сборке, если его нет.
- Переименованный или удалённый `preset_id`: запись остаётся, в списке
  «Preset not found — tap to fix»; старый разовый ремап id снят (§229),
  пропустивший v2.10.0..v2.17.x видит это на трёх старых id.
- Новый шаблонный DNS-сервер появляется с `enabled` шаблона; запись, чей
  шаблонный или пресетный сервер исчез, удаляется; пользовательские серверы
  не трогаются никогда ([005-DNS](../../005-DNS/FUNCTIONS/dns-servers.ru.md)).
- Теги пресета: тег конфига — `<preset_id>:<tag>`; документ формы 2.23.2,
  слот или старый бэкап с голым тегом читаются в то же пространство
  миграцией хранения (P12).
- Копии одного пресета (старый импорт правил) схлопываются при загрузке,
  остаётся последняя.

**Бэкап, перенос и слоты.**

- Бэкап несёт документ, а не шаблон. На импорте ключи `vars` принимаются
  только по именам, которые объявляет шаблон импортирующей сборки, плюс
  флаги приложения; неизвестные отбрасываются и считаются (P13,
  [017 · P5](../../017-BACKUP_AND_STORAGE/FEATURE.ru.md#обещания)). Поэтому
  бэкап из более новой сборки теряет переменные, которых старый шаблон не
  знает, — видимо.
- Метки засева едут в категории «App settings», так что восстановленная
  установка дефолты заново не засевает.
- LX-перенос на десктоп берёт только переменные, помеченные `portable` в
  реестре контракта; остальные пропускаются с `backup_var_skipped`
  ([017 · P15](../../017-BACKUP_AND_STORAGE/FEATURE.ru.md#обещания)).
- Слот Workspaces — копия документа; шаблон общий для всех слотов, слот
  старой формы мигрирует при загрузке ([018-WORKSPACES · P13](../../018-WORKSPACES/FEATURE.ru.md#обещания)).

## Границы

- Форма документа хранения, его миграция с 2.23.2 и атомарная запись —
  [017-BACKUP_AND_STORAGE](../../017-BACKUP_AND_STORAGE/FEATURE.ru.md).
- Засев Направлений и шаблоны групп — [006-DETOUR_AND_BALANCE](../../006-DETOUR_AND_BALANCE/FEATURE.ru.md).
- Откат приложения на более старый шаблон ОС не поддерживает; документ,
  записанный более новой сборкой, читается как текущий.
- Версии шаблона и таблицы миграций по шаблону нет: ломающее изменение формы
  шаблона — это изменение формы хранения.
