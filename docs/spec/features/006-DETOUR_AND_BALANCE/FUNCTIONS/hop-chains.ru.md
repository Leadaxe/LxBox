# Цепочки хопов — многохоповые маршруты, собираемые ядром

Цепочка хопов ведёт трафик через несколько серверов в заданном порядке, а
для остального приложения выглядит обычным узлом.

| Поле | Значение |
|------|----------|
| Фича | [006-DETOUR_AND_BALANCE](../FEATURE.ru.md) |
| Обещания | P7 P8 P9 P10 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Цепочка — третий вид источника рядом с подпиской, сервером и папкой:
строка «`tag · N hops`» в общем списке Servers («Add hop chain…»),
перетаскивается наравне с остальными. Это **маршрут**
`клиент → позиция 1 → … → позиция N → цель`, собранный ядром в рантайме
(outbound `chain` ядра sing-box-lx, фича ядра 015-CHAIN). Для остального
приложения цепочка — узел: её отбирают фильтры Направлений, её можно
выбрать на главном экране.

## Параметры

| Поле | Значения | Умолчание | Ключ ядра |
|---|---|---|---|
| Tag | `chain-N` (первый свободный) или свой; неизменяем | `chain-N` | `tag` |
| Enabled | вкл/выкл | вкл | выключенная не эмитится |
| Positions | ≥2, в порядке пакета; позиция — узел, группа подписки, Направление, `direct-out`, цепочка выше по списку (только первой) | — | `outbounds` |
| Idle timeout | длительность, `0s` = жить до остановки | пусто = умолчание ядра 5m | `idle_timeout` |
| Strip evasion tricks from links | вкл/выкл/не тронуто | не тронуто = ядро (вкл) | `strip_evasion` (только если задано) |
| Per-key overrides | ключи каталога реестра: не тронуто / снять / оставить | не тронуто | `strip` |
| rewrite | merge-patch по типу узла | `{}` | `rewrite` |

## Входы / Выходы

**Входы:** список цепочек в порядке объявления; финальные теги узлов,
Направлений, служебных outbound'ов, вышестоящих цепочек; тела узлов на
позициях (для правил каталога `strip`); версия ядра.
**Выходы:** outbound `{"type":"chain","outbounds":[…], …}` перед группами
Направлений; тег цепочки в пуле Направлений; предупреждения с кодами
`chain_unsupported_by_core`, `chain_invalid`, `chain_hop_missing`,
`chain_nested_position`, `chain_cycle_through_direction`.

## Правила и инварианты

- Порядок позиций уходит дословно — это порядок пакета (P7).
- Деградация — целиком, остальной конфиг собирается (P8), в этом порядке:
  1. ядро старше `1.14.0-lx.27-rc.5` — «Hop chain … was skipped» (кривая
     строка версии — цепочка эмитится);
  2. инварианты ядра: <2 позиций, пустая позиция, самоссылка, повтор,
     неизвестный ключ `strip`, пустое имя типа в `rewrite`;
  3. тег занят узлом, Направлением или другой цепочкой;
  4. позиция не разрешилась — «A route without a hop is a different
     route, so the whole chain is skipped.»; сюда же ссылка на цепочку
     ниже по списку (циклы между цепочками исключены порядком);
  5. вложенная цепочка не на первой позиции.
- Звено требует снимаемый путь (например `tls.utls` у REALITY на
  позиции ≥2): ключ снимается с патча, цепочка собирается, код — в
  предупреждение. Позиция 1 не судится.
- Направление не берёт цепочку, идущую через него, в т.ч. транзитивно
  (P9): «Hop chain "…" runs through direction "…" and was left out of
  it…». Вычет не считается виной фильтра Направления.
- Сборка дополнительно дропает цепочку, чья позиция опустела каскадом, и
  убирает цепочки из листьев групп, стоящих позицией ≥2.
- Лечение (P10): удаление сервера, члена папки, подписки, папки с
  серверами, Направления, другой цепочки снимает соответствующие
  **позиции**; счётчик «N chain position(s) removed». Цепочка с <2
  позициями остаётся видимой и не собирается. Роспуск папки с
  сохранением серверов и обновление подписки позиции не трогают.
- Хранение — записи `kind: chain` в общем списке источников; порядок
  записи = порядок объявления. Бэкап — в категории серверов.

## Границы

- Выключение позиции в рантайме, состояние звеньев, MTU и сон
  WireGuard-звеньев — стороной ядра, приложение их не показывает.
- Группа на позиции ранжирует свои узлы прямыми замерами, не «через
  нижние хопы» — поведение ядра.
- Цепочка не предлагается целью detour и позицией в пикере (см.
  [chain-editor.md](chain-editor.ru.md)); существующие такие позиции валидны.
