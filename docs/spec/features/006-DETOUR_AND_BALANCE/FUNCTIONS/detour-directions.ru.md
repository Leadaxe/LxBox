# Направление как detour-прослойка — смена upstream у многих узлов сразу

Направление с галкой «Use as detour» становится общим upstream: смена его
узла на главном экране переводит все серверы, идущие через него.

| Поле | Значение |
|------|----------|
| Фича | [006-DETOUR_AND_BALANCE](../FEATURE.ru.md) |
| Обещания | P3 P4 P5 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Делает Направление (`vpn-2`, своё) переключаемой прослойкой: галка
**Use as detour** в редакторе Направления разрешает выбирать его целью
detour у серверов, членов папок, папок и подписок. Переключил узел в
Направлении на главном экране — весь флот, идущий через него, переехал
на другой upstream без правки узлов. С автовыбором прослойка
самонаводящаяся.

## Параметры

| Ручка | Значения | Умолчание | Эффект |
|---|---|---|---|
| Use as detour («can be picked as a detour target for servers and folders») | вкл/выкл | выкл | Направление в секции Directions пикера detour |

У `vpn-1` галки нет. Остальные ручки Направления (состав, фильтр,
`include_block`, автовыбор) — общие с обычным Направлением,
[004-ROUTING](../../004-ROUTING/FUNCTIONS/directions.ru.md).

## Входы / Выходы

**Входы:** флаг, состояние Направления (вкл/выкл, существует), ссылки
на него в detour-полях источников.
**Выходы:** `detour: "<tag>"` у узлов, ходящих через прослойку
(сам селектор эмитится как у любого Направления); имя с маркером `⚙ `
везде, где Направление показано (пикеры, главный экран, пикер целей
правил); уведомление о сброшенных ссылках; в Debug API — `detour` и
счётчики `healed`.

## Правила и инварианты

- Разрешение, не роль (P3): Направление с флагом остаётся целью правил,
  `route.final`, пресетов и DNS; `include_block` с флагом совместим.
- `vpn-1` detour-Направлением не бывает: флаг коэрсится при чтении
  (правленый бэкап, ручной файл), Debug API отвечает 409 «…is the primary
  direction and cannot be a detour direction».
- Маркер ⚙ хранится в имени (P5): включение флага переименовывает
  в `⚙ <имя>`, выключение снимает префикс; стёртый руками маркер
  возвращается; пустое имя не трогается (показывается `⚙ <tag>`).
- Пикер показывает только включённые Направления с флагом; текущий
  выбор селектора — в скобках, когда туннель поднят.
- Лечение (P4), по ссылке на тег или `<tag>-auto`, только корневые
  ссылки (адрес члена папки Направлением не бывает):

| Событие | detour-ссылки (override источника, личный detour члена) |
|---|---|
| флаг вкл | ничего |
| флаг выкл | → None |
| выключение | → None |
| удаление | → None; позиции цепочек на него тоже снимаются |

- Лечение необратимо: повторное включение ссылки не возвращает. Итог —
  одно уведомление «Direction "…" …» со счётчиками «N detour
  reference(s) reset to None», «N chain position(s) removed» и др.
- Лечение хранения и списка источников в памяти — одна операция; иначе
  ближайшее сохранение воскресило бы ссылку.
- Пустое Направление (фильтр ничего не поймал) у прослойки ведёт себя как
  у любого: состав `[block, direct-out]`, умолчание `block` —
  ходившие через него узлы блокируются, а не идут напрямую, и сборка
  называет их отдельным предупреждением.
- Узел-член прослойки с detour на неё же — кольцо, см.
  [detour-graph.md](detour-graph.ru.md).

## Границы

- Лечение rule-ссылок, `include`, DNS-серверов при удалении/выключении —
  [004-ROUTING](../../004-ROUTING/FUNCTIONS/directions.ru.md), [005-DNS](../../005-DNS/FEATURE.ru.md).
- Совместимость AmneziaWG с WireGuard в составе прослойки не проверяется
  (ни запрета, ни предупреждения).
- Подсветка возможного кольца прямо в пикере не делается.
