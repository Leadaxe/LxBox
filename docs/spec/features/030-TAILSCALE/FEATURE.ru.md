# Tailscale — телефон как узел вашей сети tailnet внутри VPN

LxBox входит в сеть Tailscale изнутри туннеля sing-box: узел Tailscale — это
endpoint ядра `tailscale`, добавленный из мастера «Add server» или вставленный
как sing-box JSON, а приложение даёт ему личность устройства на каждый узел,
сервер MagicDNS и маршруты в tailnet. На главном экране такой узел виден под
NETWORKS с живым состоянием; его вкладка Network показывает устройства сети,
переключает exit node на ходу и проверяет пиров. С `exit_node` узел становится
обычным Направлением и несёт интернет-трафик.

| Поле | Значение |
|------|----------|
| Фича | 030-TAILSCALE |
| Тип | Продуктовая фича |
| Поглотила | `§435` (бывшая фича, отменена §575/§578) · задачи 437, 445, 449, 578, 579, 581 |
| Состояние | ✅ написана по коду, 2026-09-29 |

## Назначение

Пользователь хочет добраться до машин своей tailnet (домашний NAS, сервер в
офисе, роутер с подсетями) через LxBox без второго VPN-приложения, а когда
пир предлагает exit node — отправить через него весь интернет. Клиент
Tailscale (tsnet) в user space запускает ядро; дело приложения — всё вокруг:
узел, который несёт только своё тело, стабильная личность устройства,
переживающая переименования, переносы в папки и переключения Workspaces, DNS и
маршруты tailnet из пресета шаблона, а не из узла, и экран, показывающий, как
tailnet выглядит с телефона.

Принципы: **узел — только тело** — правила маршрута и DNS с ним не ездят,
пресет `tailscale` обслуживает каждый узел Tailscale в конфиге (§575, §578);
**личность выдаётся один раз** — каталог состояния привязан к стабильному
ключу узла, а не к тегу, и переименование не регистрирует новое устройство
(§445); **конфиг не меняется за спиной** — exit node, выбранный на ходу, живёт
в ядре, пока «Save choice» не запишет его в узел.

## Обещания

- **P1. Узел Tailscale — endpoint без адреса.** Читается из sing-box JSON
  (`outbounds[]` или `endpoints[]`) с телом как есть, пустой тег становится
  `tailscale`, эмитируется всегда в `endpoints[]` с `type` и `tag` первыми.
  Свидетель: юниты «разбор: без адреса, тело как есть, kind endpoint», «тег
  пустой → tailscale», «принимается из outbounds[] и endpoints[]», «реестр:
  kind задаёт раздел конфига». Мутация: эмиссия в `outbounds[]`.
- **P2. Узел не несёт связки.** Вставленный конфиг с endpoint'ом `tailscale`
  импортирует только узел; соседние блоки `route`/`dns`, голое тело и член
  папки своих правил не получают. Свидетель: юниты «голое тело → узел без
  секций», «конфиг с одним узлом и route → узел без секций», «папка: голое
  тело членом → секций нет», «многоузловой конфиг со ссылками: связка не
  извлекается». Мутация: правила из вставленного конфига извлечены в узел.
- **P3. Ядро без `with_tailscale` снимает узел, а не конфиг.** Узел исключён
  при сборке с предупреждением `tailscale_core_unsupported` и остаётся в
  хранилище; остальное собирается. Свидетель: юниты «tailscale: без тега —
  отказ с кодом, с тегом и без знания тегов — годен», «гейт ядра по тегу
  сборки: без with_tailscale узел снят с кодом». Мутация: ядро отвергает весь
  конфиг.
- **P4. Без `exit_node` узел не кандидат Направлений.** Решает реестр
  (`exit_capable_when`): с `exit_node` узел — кандидат, как любой другой.
  Свидетель: юниты «контракт 1.1.63: выход — по exit_capable_when реестра»,
  «Tailscale без exit_node входит (в NETWORKS)», «Tailscale с exit_node не
  входит». Мутация: узел без выхода в selector'е.
- **P5. Узлы Tailscale выделяются из многоузловой вставки.** Каждый становится
  своим сервером; остаток идёт прежним путём как текст без `tailscale`-записей,
  и кэш файловой подписки не вернёт узел дублем. Свидетель: юниты «endpoint +
  прокси → два сервера», «endpoint + два прокси → сервер и файловая подписка
  без tailscale в кэше», «endpoint + группа: остаток без узлов — не ошибка».
  Мутация: узел возвращается из кэша подписки на старте.
- **P6. Каталог состояния выдаётся один раз и идёт за узлом.**
  Переименование, смена префикса, правка тега члена, перенос между папками и
  в сервер, перестановка тёзок и выключение сохраняют каталог. Свидетель:
  юниты «переименование одиночного сервера и смена префикса — каталог тот
  же», «смена префикса папки — каталог тот же», «переименование члена — запись
  переходит на новый ключ, каталог тот же», «перенос члена в другую папку»,
  «перенос сервера в папку и вынос обратно», «перестановка тёзок — каталоги
  остаются за своими узлами», «выключение члена, папки и сервера — каталог не
  трогается»; контроллер «правка тега и префикс папки — каталог тот же;
  удаление — каталог удалён». Мутация: каталог по финальному тегу.
- **P7. Путь подставляется только при эмиссии.** `state_directory` пишется в
  запись конфига, когда корень известен и в теле нет своего значения; в
  хранимое тело путь не попадает. Свидетель: юниты «state_directory
  подставляется при известном корне, тело не трогается», «без корня не
  пишется; своё значение не трогается». Мутация: путь сохранён в тело.
- **P8. Удаление узла удаляет личность — при остановленном ядре.** Запись
  снимается сразу; каталог — когда ядро остановлено и на него не ссылается
  ни один Workspace, иначе при ближайшей сборке с остановленным ядром.
  Свидетель: юниты «удаление члена при остановленном ядре — каталог удалён»,
  «удаление под живым ядром: запись снята сразу, каталог — при сборке»,
  «удаление папки и подписки целиком — каталоги удалены», «сирота: снимается
  при остановленном ядре, остаётся при поднятом», «статус ядра не
  запрашивается, когда снимать нечего». Мутация: каталог удалён под живым
  ядром.
- **P9. Каталоги 2.24.0 подхватываются один раз.** На первой сборке слота
  Workspaces каталог, названный по финальному тегу, привязывается к узлу; узел
  с записью старый каталог не забирает. Свидетель: юниты «миграция: каталог
  2.24.0 по финальному тегу подхватывается», «миграция одноразовая: запись
  есть — старый каталог не забирается», «слот без записей держит каталоги
  2.24.0, пока не собран». Мутация: подхват затирает существующую запись.
- **P10. Пока узла Tailscale нет, ничего не пишется.** Ни индекса, ни
  каталога; индекс и каталоги лежат вне файла настроек. Свидетель: юниты «без
  узлов, индекса и каталогов на диск ничего не пишется», «без индекса
  Tailscale операции Workspaces файлов не создают»; отсутствие в бэкапе — `без
  свидетеля` (по построению,
  [017-BACKUP_AND_STORAGE](../017-BACKUP_AND_STORAGE/FEATURE.ru.md)).
  Мутация: индекс создаётся на старте.
- **P11. Hostname по умолчанию — `LxBox-<модель устройства>`.** Модель
  приводится к DNS-метке (латиница и цифры, прочее → `-`, серии схлопнуты, 63
  символа всего); пустая или схлопнувшаяся целиком модель даёт `LxBox`.
  Свидетель: юниты «модель как есть → префикс и нижний регистр через дефисы»,
  «подчёркивания и серии разделителей схлопываются», «края очищаются»,
  «модель без латиницы и цифр → голый префикс», «пустая модель → голый
  префикс», «длинная модель обрезается в DNS-метку без хвостового дефиса»;
  виджет «Hostname с дефолтом LxBox, стирание возвращает пустое тело».
  Мутация: hostname подставляется при сборке.
- **P12. Пресет `tailscale` обслуживает каждый узел Tailscale в конфиге.** На
  узел: правило маршрута `preferred_by: [<узел>] → <узел>`, `resolve` через
  `<узел>-dns` прямо перед ним, DNS-сервер `{type: tailscale, tag: <узел>-dns,
  endpoint: <узел>}` и DNS-правило `preferred_by: [<узел>-dns] → <узел>-dns`,
  в порядке конфига. Свидетель: юниты «два узла: записи из таблицы спеки,
  порядок конфига», «один узел — записи из таблицы спеки», «два узла — повторы
  подряд в порядке узлов, теги без неймспейса». Мутация: `preferred_by`
  DNS-правила называет узел (ядро отказывает `DNS server not found`).
- **P13. Пропущенные, выключенные и снятые гейтом узлы не обслуживаются.**
  Свидетель: юниты «skip_presets и выключенный узел не обслуживаются», «узел
  снят гейтом ядра — пресет его не видит», «filter ложен (skip_presets) — не
  обслуживается», «узел с skip_presets не обслуживается, узлов нет — пусто».
  Мутация: DNS-сервер для снятого узла (висячий `endpoint`).
- **P14. Без узлов Tailscale конфиг байт в байт прежний.** Свидетель: юнит
  «без узлов Tailscale конфиг байт в байт прежний». Мутация: пустой пресет
  эмитирует лишние записи.
- **P15. Переключатель DNS пресета оставляет только правило маршрута.**
  Свидетель: юнит «dns_enable выключен — только правило маршрута». Мутация:
  DNS-сервер эмитируется всегда.
- **P16. Пресет доходит до существующих пользователей один раз.** Установка,
  где дефолты уже засеяны, получает пресет включённым на позиции шаблона;
  удалённый пресет не возвращается; свежая установка не трогается.
  Свидетель: юниты «дефолты засеяны раньше: пресет добавляется один раз»,
  «пресет уже есть — дубля нет», «свежая установка не трогается; первый seed
  закрывает шаг». Мутация: пресет добавлен повторно после удаления.
- **P17. `skip_presets` переживает бэкап.** Хранится только `true`; импорт,
  совпавший по телу, его не сбрасывает. Свидетель: юниты «одиночный узел:
  skip_presets=true своей записи не сбрасывается», «член папки:
  skip_presets=true не сбрасывается при повторном импорте». Мутация:
  отсутствующее поле при импорте сбрасывает флаг.
- **P18. Пикер DNS-сервера `tailscale` предлагает включённые узлы Tailscale
  всех источников** с финальным тегом последней сборки. Свидетель: юниты
  «свой сервер Tailscale — опция; не-Tailscale — нет», «выключенные источник,
  член и папка в перечень не входят», «узел подписки Tailscale — опция»,
  «финальный тег последней сборки побеждает отображаемый», «дубль тега — одна
  опция». Мутация: выключенный узел предложен (сервер выпал бы при сборке).
- **P19. Вкладка Network есть только у узла Tailscale, перед Diagnostics**; из
  строки NETWORKS экран открывается на ней. Свидетель: виджеты «узел
  Tailscale: Network перед Diagnostics», «узел не Tailscale: вкладки Network
  нет», «из NETWORKS: начальная вкладка Network, Save choice есть». Мутация:
  вкладка у узла WireGuard.
- **P20. Вкладка объясняет, почему показывать нечего.** VPN выключен — «Start
  VPN to see the network.»; записи от ядра ещё нет — индикатор ожидания; узла
  нет в работающем конфиге — «The node is not in the running config.»
  Свидетель: виджеты «VPN выключен», «данных от ядра ещё нет — ожидание»,
  «узла нет в работающем конфиге». Мутация: бесконечный индикатор при
  выключенном VPN.
- **P21. Exit node, выбранный на ходу, тело не трогает.** Расхождение
  записанного `exit_node` и действующего выхода показывает знак предупреждения
  и «Save choice»; Save choice пишет адрес Tailscale пира (IPv4 первым) или
  убирает поле; у узла подписки и узла без записи источника Save choice нет.
  Свидетель: юниты «совпадают — знака нет», «в узле нет, на ходу выбран», «в
  узле записан, на ходу снят», «в узле один, на ходу другой», «в тело пишется
  адрес IPv4», «поле появляется / меняется с прежним порядком ключей / None
  убирает»; виджеты «различаются — знак и Save choice, запись адреса», «снят
  на ходу — Save choice пишет пусто», «узел подписки — знак есть, Save choice
  нет», «выбор пункта переключает на ходу, тело не трогает», «записи нет:
  Save choice скрыта». Мутация: Save choice пишет `StableID`.
- **P22. Устройства — сначала в сети, затем по имени, с отметками.**
  Свидетель: юнит «порядок устройств: в сети первыми, внутри по имени»;
  виджет «устройства: порядок и отметки». Мутация: только алфавит.
- **P23. Узел без действующего выхода прячет внешнюю проверку на
  Diagnostics.** При поднятом VPN решает состояние ядра, иначе записанный
  `exit_node`. Свидетель: виджеты «выхода нет — проверка скрыта, строка вместо
  неё», «выход есть — проверка доступна»; юниты «VPN включён — по состоянию
  ядра», «VPN выключен или данных нет — по записанному». Мутация: проверка,
  всегда падающая с «context deadline exceeded».
- **P24. Debug API видит только состояние и число устройств.** Без имён,
  адресов, имени сети, владельцев и ссылки входа. Свидетель: юнит «Debug API:
  состояние и число устройств, без имён и адресов». Мутация: список пиров в
  `GET /state`.

## Контролируемые параметры

| Ручка | Значения | По умолчанию |
|-------|----------|--------------|
| Мастер → Tailscale: Tag, Auth key, Control URL, Hostname, Ephemeral, Accept routes, Exit node | строки, два тумблера; Auth key обязателен, маскирован с Show/Hide | `tailscale` · — · пусто · `LxBox-<модель>` · выкл · выкл · пусто |
| Экран узла → «Skip presets» | вкл/выкл; виден у своего сервера и члена папки, когда в шаблоне есть пресет с `for_each` под тип узла | выкл |
| Пресет «Tailscale networks» (`tailscale`) | вкл/выкл, сортируемый, `num` 945; переменная «DNS» (`dns_enable`) | вкл · DNS вкл |
| DNS-сервер типа `tailscale` | `endpoint` (узел Tailscale, обязателен), `accept_default_resolvers` | — |
| Вкладка Network → Exit node | пир с `ExitNodeOption` или None; «Save choice» | из тела |
| Вкладка Network → Log out | после подтверждения | — |

Ключи конфига ядра, которые фича отдаёт: запись `endpoints[]` `{type:
tailscale, tag, …тело, state_directory}`; от пресета — записи `route.rules` с
`preferred_by`, `action: resolve`, `server`, `outbound`; запись `dns.servers`
`{type: tailscale, tag: <узел>-dns, endpoint: <узел>}`; запись `dns.rules` с
`preferred_by` и `server`. Save choice пишет `exit_node` в тело узла. RPC ядра:
`SubscribeTailscaleStatus`, `SetTailscaleExitNode`, `TailscaleLogout`,
`StartTailscalePing`. Файлы данных: `tailscale/<имя>/` (состояние одного узла у
ядра), `tailscale_state.json` (индекс слот → ключ узла → имя каталога). Код
предупреждения: `tailscale_core_unsupported`. Debug API: поле `tailscale` в
`GET /state`, поле записи `skip_presets` (только чтение).

## Входы / Выходы

**Входы:** форма мастера; вставленный sing-box JSON (одно тело, конфиг, массив
конфигов) или тело подписки; теги сборки ядра; статус туннеля; поток ядра о
состоянии tailnet (`BackendState`, `AuthURL`, свой узел, exit node, пиры по
владельцам); нажатия на вкладке Network; операции Workspaces.

**Выходы:** запись `endpoints[]` с каталогом состояния; записи маршрутов и DNS
от пресета; строка узла (🕸️, чип «Tailscale», «No address», «—» вместо
задержки; в NETWORKS — состояние); вкладка Network; строка на Diagnostics;
строки журнала о сохранённых и удалённых каталогах; уведомление
`tailscale_core_unsupported`; собственное уведомление ядра «войдите по ссылке»
([013-DIAGNOSTICS · P23](../013-DIAGNOSTICS/FEATURE.ru.md#обещания)).

## Data flow

```
Мастер / вставка JSON → тело узла как есть → запись источника (свой сервер, член папки, узел подписки)
Сборка: гейт реестра → гейт ядра (with_tailscale) → endpoints[] {type, tag, тело}
       → state_directory = <files>/tailscale/<имя из индекса; выдаётся один раз на ключ узла>
       → пресет tailscale: for_each по эмитированным узлам Tailscale (skip_presets выкл)
         → route.rules: resolve через <тег>-dns, preferred_by [<тег>] → <тег>   (позиция 945)
         → dns.servers: {tailscale, <тег>-dns, endpoint <тег>} · dns.rules: preferred_by [<тег>-dns] → <тег>-dns
Ядро: tsnet входит в tailnet (auth key или ссылка входа уведомлением)
       → SubscribeTailscaleStatus → состояние строки NETWORKS · вкладка Network · Diagnostics · GET /state
Вкладка Network: выбор выхода → SetTailscaleExitNode (только ядро) → «Save choice» → exit_node в теле → пересборка
       → узел переходит между NETWORKS и списками Направлений
Удаление узла / Delete слота → запись индекса снята → каталог удалён, когда никто не ссылается (ядро остановлено)
```

## Правила и гарантии

- Маршрут в tailnet — живое условие, а не список подсетей: `preferred_by`
  спрашивает endpoint, считает ли он адрес или имя своим (имена машин, адреса
  машин, принятые подсети). Пока tailnet не поднят, правило не совпадает и
  трафик идёт по остальным правилам. Два узла в одной tailnet считают своими
  одни и те же машины — побеждает первый по порядку конфига.
- Тег DNS-сервера узла — `<тег узла>-dns` без пространства пресета, поэтому
  ссылки пользователя на него работают; свой сервер с тем же тегом побеждает
  по общему правилу дедупа тегов DNS с предупреждением.
- DNS-сервер `tailscale` с висячим `endpoint` или второй сервер на тот же узел
  выбрасывается с предупреждением; `detour` у этого типа всегда снимается
  ([005-DNS](../005-DNS/FEATURE.ru.md)).
- Ключ узла в индексе личностей: свой сервер — его id (`#2`, `#3` для
  следующих узлов Tailscale того же сервера); член папки и узел подписки — id
  контейнера плюс сырой тег. Тело со своим `state_directory` записи не
  получает, и его каталог не удаляется.
- Слоты Workspaces делят личности записями, а не копиями файлов: «Save as»
  копирует записи (оба слота — одно устройство tailnet), Rename переносит их,
  Delete снимает и сразу удаляет каталоги без ссылок
  ([018-WORKSPACES · P12](../018-WORKSPACES/FEATURE.ru.md#обещания)).
- Бэкап несёт тело узла (включая `auth_key`) и `skip_presets`, но не личность:
  восстановленный на другом устройстве узел регистрируется заново, а
  потраченный одноразовый ключ даёт `invalid key`. Очистка данных приложения
  действует так же — мастер говорит об этом под Auth key.
- Exit node, выбранный на ходу, живёт в каталоге состояния узла и переживает
  перезапуск, пока в теле нет `exit_node`; с `exit_node` в теле при старте
  побеждает тело. Тексты у знака предупреждения блока Exit node называют три
  случая (не сохранено: трафик в узел не идёт / выхода нет до записи /
  теряется после перезапуска).
- Подписка ядра на состояние держится, пока VPN включён и либо в NETWORKS есть
  узлы, либо открыта вкладка Network; перезагрузка конфига переподнимает её.
  Log out подтверждается текстом о том, что узел с записанным ключом входа
  войдёт снова при следующем запуске.
- Имена устройств, адреса, имя сети, владельцы и ссылка входа не пишутся в
  журнал приложения, дамп поддержки и Debug API.

## Границы

- Узел не пробуется: адреса нет, а проба должна была бы войти в tailnet; в
  строке «—» вместо задержки (`без свидетеля`). Общий замер задержки в
  NETWORKS недоступен.
- Особой реакции на смену сети и на режим Proxy у Tailscale нет: перезапуск
  туннеля при смене сети — дело
  [010-VPN_SERVICE](../010-VPN_SERVICE/FEATURE.ru.md), узел входит снова с
  личностью из каталога состояния; конфиг в обоих режимах собирается
  одинаково (`без свидетеля`).
- В мастере нет полей `exit_node_allow_lan_access`, `advertise_routes`,
  `advertise_exit_node` и SSH; они правятся на вкладке JSON, и их проверяет
  реестр (маршрут по умолчанию в `advertise_routes` снимается с кодом,
  `exit_node` конфликтует с `advertise_exit_node`).
- Подсети за пирами (`accept_routes`) матчатся тем же условием
  `preferred_by`; подсеть, совпавшая с домашней, — решение пользователя
  (позиция 945 стоит раньше «Private IPs» на 950).
- MagicDNS отвечает только на полные имена `*.ts.net`; короткие имена (search
  domain) не разрешаются.
- Правка `auth_key` или `control_url` существующего узла новую личность не
  выдаёт: уже вошедший узел остаётся в прежней tailnet.
- SSH к пиру, Taildrop, сертификаты `*.ts.net`, tailnet только по IPv6 при
  `prefer_ipv6` и трафик по устройствам — вне фичи. Системная резервная копия
  `files/` (`android:allowBackup` не задан) здесь не регулируется.
- Вход по интерактивной ссылке, переключение exit node, Log out и Ping на
  устройстве с живой tailnet не проверены (задачи 445, 449, 578, 579, 581:
  DEVICE-PENDING).

## Особенности сопровождения

- **`preferred_by` DNS-правила называет сервер, а не узел.** Ядро ищет
  `preferred_by` в `dns.rules` среди DNS-серверов; тег узла роняет весь конфиг
  на старте (контракт 1.1.90).
- **Каталог состояния на диске не переименовывать.** Ядро пишет файл состояния
  через временный файл в том же каталоге; каталог, переименованный под живым
  ядром, теряет записи. Индекс переносит ключи, файлы стоят.
- **Каталог удаляется только при остановленном ядре**: ядро работает с
  конфигом, с которым стартовало, а не с последним собранным.
- **DNS-серверу пресета не давать пространство пресета**: запись хранения
  держит `ref` равным тегу; с `preset_id` тег стал бы `tailscale:<тег>-dns`, и
  правила указывали бы в пустоту.
- **Новый дефолтный пресет сам не сеется** на установке с уже засеянными
  дефолтами — нужен список поздних дефолтов, и он только растёт.
- **Файловой подпиской многоузловой вставки становится только текст без
  `tailscale`-записей**; отфильтрованный список узлов воскресил бы узел из
  кэша на старте.
