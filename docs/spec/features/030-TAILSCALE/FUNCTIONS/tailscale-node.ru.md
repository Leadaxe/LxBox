# Узел Tailscale — endpoint tailnet из мастера или sing-box JSON

Узел Tailscale — это endpoint ядра `tailscale`: адреса у него нет, тело
хранится как есть, а в конфиг он попадает только на ядре, собранном с
`with_tailscale`.

| Поле | Значение |
|------|----------|
| Фича | [030-TAILSCALE](../FEATURE.ru.md) |
| Обещания | P1–P5, P11 |
| Состояние | ✅ написана по коду, 2026-09-29 |

## Что делает

Создаёт узел Tailscale из формы «Add server → Tailscale» или из вставленного
sing-box JSON, хранит его как тело с `tag` (ссылки шаринга у этого типа нет),
эмитирует в `endpoints[]`, снимает с кодированным предупреждением, когда ядро
не может его запустить, и решает, может ли он быть Направлением: в интернет
выходит только узел с `exit_node`, поэтому только такой узел предлагается в
списках Направлений.

## Параметры

| Что | Значение |
|-----|----------|
| Поля мастера | Tag (необязателен, пусто → `tailscale`, добавляется эмодзи 🕸️), Auth key (обязателен, маскирован), Control URL, Hostname (заполнен `LxBox-<модель>`), Ephemeral, Accept routes, Exit node |
| Тело от мастера | `auth_key` плюс только заполненные поля; булевы только как `true` |
| Тело из JSON | как есть, минус `type`, `tag`, `detour`; незнакомые ключи сохраняются с кодом `json_field_unknown` |
| Проверки реестра | `exit_node` конфликтует с `advertise_exit_node`; `exit_node_allow_lan_access` требует `exit_node`; маршрут по умолчанию в `advertise_routes` снимается с кодом `tailscale_default_route_advertised` |
| Гейт ядра | тег сборки `with_tailscale`; его нет → узел снят с кодом `tailscale_core_unsupported` |
| Кандидат Направлений | `exit_capable_when: any_set [exit_node]` |

## Входы / Выходы

**Входы:** форма; одно тело, целый конфиг, массив конфигов или массив
outbound'ов; тело подписки; теги сборки ядра.

**Выходы:** свой сервер (или член папки, узел подписки) с тегом в заголовке;
запись `endpoints[]`; кодированное предупреждение на узле, когда у ядра нет
тега; подсказки мастера под Auth key («одноразовый ключ расходуется при первом
входе…») и под Exit node (выберите узел Направлением, чтобы вести через него
интернет).

## Правила и инварианты

- **Запись tailscale — endpoint, откуда бы ни пришла**: принимаются и
  `outbounds[]`, и `endpoints[]`, а `kind` реестра кладёт узел в `endpoints[]`
  при эмиссии (P1). Форма шаринга узла — компактный JSON тела с `tag`, он
  разбирается обратно как одиночный outbound.
- **С узлом не ездит связка** (P2): мастер пишет голое тело; конфиг,
  вставленный вместе с узлом, теряет блоки `route`/`dns`, как любой конфиг;
  маршрут и DNS tailnet даёт пресет
  ([tailnet-dns-and-routes.ru.md](tailnet-dns-and-routes.ru.md)).
- **Многоузловая вставка разделяется** (P5): каждая запись Tailscale
  становится своим сервером; остаток текста с вырезанными записями Tailscale
  идёт прежним путём — один узел → сервер, несколько → файловая подписка.
  Остаток из одних групп — не ошибка, когда узлы Tailscale добавлены. Пустой
  `endpoints`, оставшийся после вырезания, снимается.
- **Гейт ядра снимает узел, а не конфиг** (P3): узел остаётся в хранилище и
  возвращается после обновления ядра; предупреждение показывается на узле с
  причиной и способом исправить.
- **Без `exit_node` узел не кандидат Направлений** при любой политике
  детуров (P4); он остаётся законной целью `detour`, звеном цепочки и целью
  правила и виден на главном экране под NETWORKS
  ([012-LIVE_STATE](../../012-LIVE_STATE/FEATURE.ru.md)).
- **Hostname по умолчанию** `LxBox-<модель>` — только начальное значение
  поля формы (P11): пользователь правит или стирает его; стёртое поле
  `hostname` не пишет, и ядро берёт имя хоста системы. Уникальность не
  проверяется — второе устройство той же модели получит от Tailscale суффикс
  `-1`. У уже вошедшего устройства имя правкой тела не меняется: личность
  лежит в каталоге состояния.
- Строки узлов и пикеры показывают только тип, без `:0`; экран узла пишет
  «No address (Tailscale)»; узел не пробуется, в строке «—».
- При включённом VPN строка узла с exit node пишет `tailscale·via <устройство>`.
  Если это устройство офлайн, на месте состояния endpoint'а — `exit offline`
  оранжевым; выключенный вручную узел остаётся `off`. Direct или relay не
  показывается: в статусе ядра пути нет, его знает только проверка устройства
  во вкладке Network.
- Меньше чем за 7 суток до истечения ключа устройства строка предупреждает
  `key expires Nd` / `key expires <1d` / `key expired` оранжевым: у узла с
  exit — на месте состояния endpoint'а, ниже по важности, чем `exit offline`;
  в строке NETWORKS — только вместо `running`. `keyExpiry == 0` (истечение
  отключено в админке) — метки нет.
- Узел подписки не правится; узел Tailscale внутри URL-подписки обслуживается
  пресетом, как любой другой.

## Границы

- Разбор четырёх форм sing-box JSON и проверки полей по реестру —
  [002-NODE_IMPORT](../../002-NODE_IMPORT/FEATURE.ru.md); сам мастер —
  [008-NODE_EDITOR](../../008-NODE_EDITOR/FEATURE.ru.md).

  [013-DIAGNOSTICS](../../013-DIAGNOSTICS/FEATURE.ru.md).
