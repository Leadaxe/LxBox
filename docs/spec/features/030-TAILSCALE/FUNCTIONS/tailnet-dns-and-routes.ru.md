# DNS и маршруты tailnet — пресет `tailscale` и сервер MagicDNS на узел

Пресет «Tailscale networks» повторяет свои записи для каждого узла Tailscale в
конфиге: маршрут в tailnet узла по `preferred_by`, сервер MagicDNS,
привязанный к узлу, и DNS-правило для него; узел отказывается через «Skip
presets».

| Поле | Значение |
|------|----------|
| Фича | [030-TAILSCALE](../FEATURE.ru.md) |
| Обещания | P12–P18 |
| Состояние | ✅ написана по коду, 2026-09-29 |

## Что делает

Даёт узлу Tailscale записи, без которых он бесполезен, — маршрут в его tailnet
и резолвер имён tailnet — из пресета шаблона, а не из узла. Пресет включён по
умолчанию, доходит до существующих пользователей один раз, обслуживает и узлы
подписок, а его DNS-половина — переключатель. Форма DNS-сервера также
предлагает тип `tailscale` для сервера MagicDNS, сделанного руками и
привязанного к узлу.

## Параметры

| Что | Значение |
|-----|----------|
| Пресет `tailscale` («Tailscale networks») | включён по умолчанию, `num` 945, сортируемый; `for_each` по `node_type: tailscale` с `filter: not skip_presets`; переменная «DNS» (`dns_enable`, вкл) |
| Записи на узел | `route.rules`: `{preferred_by: [<узел>], action: resolve, server: <узел>-dns}`, затем `{preferred_by: [<узел>], outbound: <узел>}`; `dns.servers`: `{type: tailscale, tag: <узел>-dns, endpoint: <узел>, description: "MagicDNS of the tailnet"}`; `dns.rules`: `{preferred_by: [<узел>-dns], server: <узел>-dns}` |
| `dns_enable` выкл | только правило маршрута |
| Поле записи `skip_presets` | свой сервер и член папки; хранится только `true`; узел подписки обслуживается всегда |
| Переключатель «Skip presets» | на экране узла; виден, когда в шаблоне есть пресет с `for_each` под тип узла |
| Тип DNS-сервера `tailscale` | `endpoint` — узел Tailscale (обязателен), `accept_default_resolvers`; без адреса, без `detour` |
| Позднее сеяние | список поздних дефолтных пресетов (`tailscale`); уже засеянные id запоминаются |

## Входы / Выходы

**Входы:** пресет шаблона; эмитированные узлы Tailscale после всех гейтов в
порядке конфига; `skip_presets` записей; значения переменных пресета;
источники для экранов (маршруты, DNS, форма DNS-сервера).

**Выходы:** правила маршрута на позиции 945, DNS-серверы и правила; подпись
строки пресета на экранах маршрутов и DNS — теги обслуживаемых узлов или «No
matching nodes»; серверы пресета на экране DNS; опции пикера `endpoint`.

## Правила и инварианты

- **`for_each` раскрывается, когда состав узлов окончателен** (P12, P13):
  узел выключенный, снятый гейтом реестра, гейтом ядра или деградацией не
  обслуживается; порядок повторов — порядок конфига; узлов нет — пресет ничего
  не выдаёт, и конфиг байт в байт прежний (P14). Проба пресеты не раскрывает.
- **DNS-правило называет сервер**, а не узел: в `dns.rules` ядро ищет
  `preferred_by` среди DNS-серверов, в `route.rules` — среди outbound'ов.
- **Теги без пространства пресета**: сервер остаётся `<узел>-dns`; запись
  хранения такого сервера держит `ref` равным тегу. Свой сервер с тем же тегом
  — первый побеждает, предупреждение.
- **`resolve` перед правилом маршрута** закрывает FakeIP: без него у
  UDP-потока к endpoint'у нет адресов, и ядро отказывается его вести.
- **Позднее сеяние** (P16): на установке с засеянными дефолтами пресет
  добавляется один раз, включённым, на позиции шаблона — перед чтением правил
  в сборке и на экране маршрутов; удалённый пресет не возвращается; свежая
  установка сеет его вместе с остальными дефолтами.
- **`skip_presets`** (P17): пишется только как `true`; едет в бэкапе, и
  импорт, совпавший по телу, его не сбрасывает; Debug API показывает его
  только для чтения. Переключатель помечает конфиг грязным.
- **Список узлов для экранов** строится тем же отбором, что сборка, минус
  гейты (включённые источники, члены и узлы подписок; `skip_presets`), с
  финальным тегом последней сборки, если узел в ней был, иначе с
  отображаемым; до сборки подпись может назвать узел, который сборка снимет.
- **Пикер `endpoint`** (P18) перечисляет включённые узлы Tailscale всех
  источников, одна опция на тег; значение вне списка (вкладка JSON, удалённый
  узел) показывается первым. Сохранение сервера `tailscale` без узла —
  «Tailscale node is required», записи нет. Висячий `endpoint` или второй
  сервер на тот же узел снимается при сборке с предупреждением; `detour`
  убирается ([005-DNS](../../005-DNS/FEATURE.ru.md)).

## Границы

- Язык шаблона (`for_each`, `@node`, `#tpl`) и неполный `for_each`, снимающий
  только свой пресет — [003-CONFIG_BUILD](../../003-CONFIG_BUILD/FEATURE.ru.md);
  правка пресетов, позиции и сеяние вообще —
  [004-ROUTING](../../004-ROUTING/FEATURE.ru.md).
- В пресете нет постоянных подсетей (`100.64.0.0/10`,
  `fd7a:115c:a1e0::/48`) и суффикса `.ts.net`: маршрут — живое условие
  `preferred_by` (решение лаунчера D-120). Пока tailnet не поднят, правило не
  совпадает.
- Два узла в одной tailnet: побеждает первый по порядку конфига.
- Связка, правленная руками в бывших секциях узла, потеряна вместе с §575.
- Такого же пресета для WireGuard нет.
