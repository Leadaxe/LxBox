# Личность устройства и состояние — каталог состояния на узел, переживающий переименования

У каждого узла Tailscale свой каталог состояния, где ядро держит ключи машины
и вход; приложение привязывает его к стабильному ключу узла, и устройство в
tailnet остаётся тем же после переименования, переноса или переключения
Workspaces.

| Поле | Значение |
|------|----------|
| Фича | [030-TAILSCALE](../FEATURE.ru.md) |
| Обещания | P6–P10 |
| Состояние | ✅ написана по коду, 2026-09-29 |

## Что делает

Выдаёт узлу имя каталога, когда он впервые попадает в сборку, пишет его в
конфиг как `state_directory`, сохраняет запись при операциях над узлом,
удаляет каталог вместе с узлом (когда ядро остановлено), подхватывает каталоги
от 2.24.0 и даёт каждому слоту Workspaces свой набор записей. Пользователь
видит в tailnet одно устройство на узел, а не новое после каждого
переименования.

## Параметры

| Что | Значение |
|-----|----------|
| Каталог | `tailscale/<имя>/` в каталоге файлов приложения; имя — финальный тег, приведённый к `[A-Za-z0-9._-]`, затем `-1`, `-2`… при занятости |
| Индекс | `tailscale_state.json`: `slots` (слот → ключ узла → имя каталога), `legacy` (каталоги, найденные при создании индекса) |
| Ключ узла | свой сервер: id сервера, `#2`, `#3` для следующих узлов Tailscale того же сервера; член папки и узел подписки: id контейнера + сырой тег, `#2` у тёзок |
| Свой `state_directory` в теле | записи нет, каталог не трогается |
| «Ядро остановлено» | статус туннеля `disconnected` или `revoked`; ошибка канала считается работой |

## Входы / Выходы

**Входы:** хранимые источники до и после операции; сборка; справочник
Workspaces (имена слотов, текущий); статус туннеля.

**Выходы:** `state_directory` у записи конфига; индекс; строки журнала
«Tailscale state of node … kept», «Tailscale state of a removed node deleted»,
предупреждения о нечитаемом индексе и о занятом целевом ключе.

## Правила и инварианты

- **Имя выдаётся один раз** и не меняется (P6): переименование, смена
  префикса, правка тега члена, переносы между папками и в сервер и обратно,
  перестановка тёзок переписывают ключ записи; файлы стоят. Выключение узла,
  члена, папки или источника запись сохраняет — ключи считаются по всем
  хранимым узлам.
- **Путь пишется только при эмиссии** (P7): при известном корне запись
  получает `<корень>/tailscale/<имя>`; хранимое тело пути не несёт. Без
  индекса имя берётся по финальному тегу с предупреждением.
- **Удаление** (P8): запись снимается сразу, чтобы тёзка, добавленный следом,
  не унаследовал личность; каталог удаляется, когда на него никто не ссылается
  и ядро остановлено — при самой операции или при ближайшей сборке с
  остановленным ядром. Слоты-призраки (которых нет в справочнике Workspaces)
  и их каталоги снимаются так же. Узел, пропавший из тела подписки, при
  сборке считается удалённым.
- **Неразобранные контейнеры сохраняют записи**: подписка без тела в кэше,
  сервер с нечитаемым телом, член с битым текстом.
- **Подхват** (P9): на первой сборке слота каталог, названный так, как называла
  2.24.0 (финальная форма, затем `-1`, `-2`… в порядке узлов), который есть в
  `legacy` и не занят другим слотом, привязывается к узлу. Узел с записью
  старый каталог не забирает. Пока у какого-то слота справочника нет записей,
  каталоги `legacy` не удаляются; `legacy` очищается, когда каждый слот собран
  или удалён.
- **Занятый целевой ключ** (устаревшая запись на ключе, куда переходит узел):
  побеждает переходящий узел, в журнал — предупреждение, каталог устаревшей
  записи становится сиротой.
- **Workspaces**: Save as копирует записи текущего слота в целевой (копия в
  обоих слотах — одно устройство tailnet; одноразовый ключ тратится один
  раз), Rename переносит набор, Delete снимает его и сразу удаляет каталоги
  без ссылок, Load ничего не трогает. Файлы не копирует ни одна операция.
- **Без узлов на диске ничего нет** (P10): индекс создаётся на первой сборке,
  где есть узел Tailscale или найдены каталоги; нечитаемый индекс считается
  пустым, и слот проходит подхват заново. Операции индекса идут по одной;
  сбой индекса не останавливает ни сборку, ни операцию Workspaces.
- **Бэкап и переустановка:** индекс и каталоги лежат вне файла настроек и
  вне копии слота, поэтому бэкап восстанавливает тело узла без личности. На
  том же устройстве восстановленные источники сохраняют id и находят свои
  записи; на другом устройстве или после очистки данных узел регистрируется
  новым устройством и требует свежий ключ.

## Границы

- Само обещание Workspaces —
  [018-WORKSPACES · P12](../../018-WORKSPACES/FEATURE.ru.md#обещания); строка
  контракта хранения — [017-BACKUP_AND_STORAGE](../../017-BACKUP_AND_STORAGE/FEATURE.ru.md).
- Каталог, чьё имя 2.24.0 уникализировала иначе, чем даёт порядок хранимых
  узлов, не подхватывается (выключенный тёзка в середине списка сдвинул
  суффиксы); такой узел входит новым устройством.
- Правка `auth_key` или `control_url` новый каталог не выдаёт: узел с
  сохранённым входом новый ключ не читает.
- Системная резервная копия Android каталога `files/` не исключена
  (`android:allowBackup` не задан).
- Подтверждение удаления узла Tailscale или слота о потере входа в tailnet не
  говорит.
