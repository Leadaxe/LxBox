# FEATURE 004 — ROUTING — правила маршрутизации, пресеты, кэш rule-set, Направления

| Поле | Значение |
|------|----------|
| Тип | Продуктовая фича |
| Поглотила | `§011F` (локальный кэш rule-set), `§030F` (единые пользовательские правила), `§033F` (пресеты-бандлы), `§393F` (Направления) |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Назначение

Решает, куда пойдёт каждое соединение: в туннель через одно из Направлений,
напрямую, в блокировку — и по какому признаку (домен, IP, порт, протокол,
приложение, сеть Wi-Fi, внешний список). Всё это — один упорядоченный список
правил на экране Routing: свои правила трёх видов (поля, внешний `.srs`,
сырой JSON) вперемешку с пресетами из шаблона. Порядок списка — порядок
матчинга в ядре, первое совпадение побеждает.

Принципы, которые фича защищает:

- **Список правил на экране и `route.rules` — одно и то же**, в одном
  порядке; выключенное правило не оставляет в конфиге ничего.
- **Правило не может уронить конфиг.** Висячая цель, битый JSON, нескачанный
  список, пресет, которого нет в шаблоне, — правило деградирует или
  пропускается с предупреждением, остальной конфиг собирается.
- **Ядро ничего не качает само.** Внешние списки приходят в конфиг только
  локальными файлами; в сеть за ними ходит приложение — по тапу или по
  устареванию кэша.

Из коробки: весь трафик — в `vpn-1`; включены пресеты Traffic Processing,
Ru internet segment, BitTorrent, VoWiFi, Tailscale networks.

## Обещания

- **P1. Порядок списка = порядок `route.rules`** для всех видов; пресет
  может дать несколько правил подряд. Свидетель: юниты «storage [preset,
  inline, preset] → config rules в том же order», «storage [preset, srs,
  preset] → srs middle». Мутация: сборка группами по виду.
- **P2. Traffic Processing — всегда первый и неустраним:** засевается,
  если потерян; не двигается, не выключается, не удаляется. Свидетель:
  юниты «шапку нельзя утащить вниз никаким drag-ом», «шапка засевается,
  даже если storage её потерял», «правило, бросённое в самое начало, встаёт
  ПОД шапку». Мутация: drag головы — `sniff` не первый.
- **P3. Ось порядка стабильна:** своё новое — в конец зоны 1000–1100,
  пресет — на номер шаблона; drag сдвигает лишь сплошной занятый блок.
  Свидетель: юниты «50 случайных drag-ов — якоря шаблона не дрейфуют»,
  «пресет из каталога садится на шаблонный num даже среди пользовательских»,
  «каскад останавливается на первой дырке». Мутация: перенумерация всех
  правил на каждом drag.
- **P4. Выключенное правило не порождает ничего** (ни route, ни rule_set,
  ни DNS). Свидетель: юниты «disabled → skipped», «§121 routing = король:
  route disabled подавляет DNS-аспект целиком». Мутация: выключение только
  в UI.
- **P5. Условия inline:** в категории ИЛИ, между категориями И;
  `protocol`, `network`, `ip_is_private`, `source_ip_is_private`, `inbound`
  — на уровне правила маршрута; правило без условий не эмитится.
  Свидетель: юниты «protocols идут на routing-rule level», «§240
  network-only (match пуст) → routing rule без rule_set», «inline
  source_ip_is_private → routing-rule level», «no match fields → skipped».
  Мутация: `protocol` в headless — ядро отвергает конфиг.
- **P6. Reject — действие, не цель:** всегда `action: reject`, никогда
  `outbound: "reject"`, включая умолчание шаблона. Свидетель: юниты
  «reject + protocol → action:reject», «outbound override == reject», «§162
  default_value == reject». Мутация: без нормализации — fatal.
- **P7. Resolve перед маршрутом.** «Resolve first» — пара `resolve` →
  `route` с одним матчем; «Resolve only» — одно нетерминальное; у inline без
  доменов resolve не эмитится. Свидетель: юниты «inline + resolve (route
  mode) → ДВА правила», «inline + resolve only → ОДНО нетерминальное»,
  «inline БЕЗ доменных полей + resolve → resolve НЕ эмитится». Мутация:
  resolve после route.
- **P8. Внешний список — только из локального кэша:** `type: local`, без URL
  и `update_interval`. Своё правило без файла хоть одного набора —
  пропуск с предупреждением; у пресета выпадает только нескачанный набор.
  Свидетель: юниты «srs без cached path → skip + warning», «remote rule_set
  + cached path → type: local», «§045 geoip on + .srs НЕ cached → даунгрейд
  до single ru-domains». Мутация: `type: remote` в конфиге.
- **P9. Сбой загрузки не отнимает рабочий файл;** `304` продлевает
  свежесть без перезаписи. Свидетель: юниты «404 не удаляет уже скачанный
  файл», «304 — файл не переписан, но lastUpdated сдвинут». Мутация:
  удалять файл перед скачиванием.
- **P10. Автообновление по устареванию:** файлы включённых правил старше
  TTL, «Never» не трогается, условный GET; раз в сессию, через 30 с после
  старта приложения или подъёма туннеля, только на переднем плане.
  Свидетель: юниты «TTL 0 = Never», «свежий кэш в пределах TTL →
  пропускаем», «If-None-Match уходит в запрос»; расписание — `без
  свидетеля`. Мутация: фоновый таймер.
- **P11. Правило без файла видно выключенным.** Открытие Routing выключает
  такое правило; свич в списке сначала качает и включает при полном успехе.
  Свидетель: ручная проверка — «Clear cached files», открыть Routing: OFF
  с ☁; свич → загрузка → ON. Мутация: свич «вкл», правило пропущено.
- **P12. Сырой JSON не роняет сборку:** битое/пустое тело — пропуск с
  предупреждением, ключи `//…` снимаются; редактор не сохраняет невалидное и
  массив. Свидетель: юниты «битый JSON → skip + warning», «§350: //-ключи
  вычищаются рекурсивно», виджет «Save в AppBar заблокирован, текст на
  месте». Мутация: `//` в конфиге — ядро отвергает.
- **P13. Пресет — ссылка на шаблон:** разворачивается на каждой сборке;
  умолчания переменных не хранятся; цель пользователя заменяет решение
  шаблона целиком, промежуточные `resolve`/`sniff` не трогает. Свидетель:
  юниты «outbound override == vpn-tag», «override vpn-1 → #if-гейт роняет
  resolve; route получает override», «все пресеты шаблона: умолчания в vars
  ≡ пустые vars». Мутация: копия тела пресета в правиле.
- **P14. Битый пресет не ломает сборку:** нет в шаблоне — пропуск и «Preset
  not found — tap to fix»; правило без полей-условий выпадает. Свидетель:
  юниты «broken preset (presetId не найден) → warning + skip», «§571:
  правило без полей-условий реестра выпадает с кодом». Мутация: правило
  без условий матчит весь трафик.
- **P15. Цели правил — только живые:** `direct`, включённые Направления
  (`vpn-1` всегда), `block`, Reject. Удаление/выключение Направления
  переводит правила, переопределения пресетов и Default traffic на `vpn-1`
  в хранении; повторное включение не воскрешает. Свидетель: юниты
  «выключенное Направление скрыто, vpn-1 присутствует всегда», «disable
  Направления (§202): route_final + rule outbound → vpn-1», «повторное
  включение НЕ воскрешает старую ссылку». Мутация: висячая цель — fatal.
- **P16. Default traffic на исчезнувшую цель → `vpn-1`** с предупреждением.
  Свидетель: юнит «route_final на удалённое Направление → vpn-1».
- **P17. Пустое Направление не роняет конфиг:** фильтр отсёк всё →
  `[block, direct-out]`, умолчание `block`, предупреждение; битый regex →
  все узлы. Свидетель: юниты «regex без совпадений → fallback [block,
  direct-out] default block», «невалидный regex → fallback на все ноды».
- **P18. Тег Направления неизменяем и не конфликтует:** первый свободный
  `vpn-N` без потолка или свой; запрещены пустой, служебные, дубль,
  коллизия с `<tag>-auto`. Свидетель: юниты «первый свободный, а не
  максимум + 1», «служебные теги конфига и псевдо-цели правил → reserved».
- **P19. Импорт правил безопасен:** пресеты вне обмена; новый id и номер в
  своей зоне; `.srs` выключен; висячая цель → `vpn-1` + выключено; висячий
  DNS-сервер → опция выключена; занятое имя — отказ; формат новее 2 —
  отказ. Свидетель: юниты «§398 — любой preset неимпортируем», «висячий тег
  → vpn-1 + выключение + warning», «parse отвергает format из будущего».
- **P20. Wi-Fi-условия:** без условий — любая сеть; BSSID в нижнем
  регистре; чтение текущей сети называет причину отказа. Свидетель: юниты
  «inline wifi-only → headless rule_set с wifi_ssid», «inline: BSSID
  lower-case на read-side», «fine_location_missing carries the missing list
  in order».

## Контролируемые параметры

| Настройка (экран Routing) | Значения | Умолчание | Ключ конфига ядра |
|---|---|---|---|
| Список правил: вкл/выкл, порядок, удаление | — | засеянные пресеты | `route.rules[]`, `route.rule_set[]` |
| Вид своего правила | Inline · Remote (.srs) · Raw JSON | Inline | inline/local rule_set или тело как есть |
| Цель правила | `direct` · Направление · `block` · Reject | `direct` | `outbound` / `action: reject` |
| Action & Resolve | Route · Resolve first · Resolve only + опции | Route | `action: resolve`, `strategy`, `server`, … |
| TTL `.srs` | Never · день · неделя · 2 недели · месяц · 6 мес · год | неделя | — (локально) |
| Переменные пресета | по объявлению шаблона | `default_value` | подставляются в тела |
| Default traffic | `direct` · Направление · `block` | `vpn-1` | `route.final` |
| Направления | тег, имя, вкл, состав, фильтр | `vpn-1` вкл, `vpn-2` выкл | `outbounds[type=selector]` |

Пресет Traffic Processing (голова списка): Packet sniffing (вкл) и Sniff
timeout (`100ms`…`3s`, `300ms`) → `action: sniff` на `tun-in`/`mixed-in` по
режиму; Hijack DNS (вкл) → `{protocol: dns, action: hijack-dns}`; Resolve
destination IP (вкл, глобальная переменная) и Resolve strategy (`ipv4_only`)
→ `action: resolve`.

DNS-опция правила («Send DNS to dedicated server», «Force IPv4 (drop
AAAA)») и DNS-части пресетов — только след в `dns.rules`/`dns.servers`,
описан в [005-DNS](../005-DNS/FEATURE.ru.md).

## Входы / Выходы

**Входы:** правила пользователя; каталог пресетов шаблона
(`selectable_rules`: `preset_id`, `ui{label, description, default, locked,
num, isSortable}`, `vars`, `rule`/`rules`, `rule_set`, DNS-части);
Направления; скачанные `.srs` и их метаданные (ETag, время подтверждения);
глобальные переменные (`vpn_mode`, `resolve_enabled`); узлы для пресета с
`for_each`; файл обмена правилами; состояние Wi-Fi от ОС.

**Выходы:** `route.rules`, `route.rule_set`, `route.final`; DNS-зеркала
правил (в 005); предупреждения сборки; fatal проверки перед стартом (висячая
цель); файлы `.srs` в локальном кэше; файл `lxbox-rules-YYYYMMDD-HHMM.json`.

## Data flow

```
список правил ─► НОРМАЛИЗАЦИЯ: засев головы, номера, сортировка, дедуп пресетов
                    ▼
               ОБХОД ПО ПОРЯДКУ (выключенные — пропуск, P4)
   inline → headless rule_set + route (P5, P7)   srs → local rule_set (P8) ◄ кэш .srs
   json   → тело, `//` снят (P12)                preset → разворот шаблона (P13, P14)
                    ▼
               reject → action (P6); DNS-аспекты → сборка DNS (005)
                    ▼
               route.final (P16); селекторы Направлений (P17)
                    ▼
               ПРОВЕРКА ПЕРЕД СТАРТОМ: цель правила существует ── fatal
                    ▼
               конфиг ядра
```

## Правила и гарантии

- Первое совпадение побеждает; порядок — только ось номеров (0 голова,
  945–990 специфичные пресеты, 1000–1100 свои, 1110–1150 широкие
  перехватчики).
- Имя своего правила уникально среди видимых имён (включая названия
  пресетов); имя — тег rule_set в конфиге, коллизия тегов получает суффикс
  ` (2)`.
- Пресет добавляется из каталога один раз; с внешними наборами — выключенным.
- Смена URL или вида правила стирает кэш и выключает правило; `vpn-1` не
  выключается и не удаляется.
- Правка на экране помечает конфиг к пересборке; запись — при уходе.

## Особенности сопровождения

- `sniff` обязан быть первым правилом: любое правило выше Traffic Processing
  матчит без домена. Поэтому голова — единственный несортируемый пресет, и
  её номер лечится при загрузке, сборке и импорте.
- `ip_is_private`, `protocol`, `network`, `inbound` живут на уровне правила
  маршрута, а домены — в headless rule_set: по формуле ядра адресные
  условия объединяются по ИЛИ. Правило «домен + Private IP» матчит и то, и
  другое, а не пересечение.
- Несколько Wi-Fi-пар в правиле дают `wifi_ssid:[A,B] И wifi_bssid:[X,Y]` —
  перекрёстное совпадение возможно; осознанный риск.
- Своё `.srs`-правило требует все файлы, пресет — нет (набор-гейт лишь
  расширяет матч). Но экран выключает пресет целиком, пока нужный набор не
  скачан — у включённого по умолчанию Ru internet segment это гонка с
  первым автообновлением.
