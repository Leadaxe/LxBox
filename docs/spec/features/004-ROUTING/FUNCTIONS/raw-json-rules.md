# Правило сырым JSON

| Поле | Значение |
|------|----------|
| Фича | [004-ROUTING](../FEATURE.md) |
| Обещания | P12 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Даёт написать правило маршрута ядра целиком, как в документации sing-box:
любые условия (включая `invert`, `domain_regex`, логические `and`/`or`) и
любое действие — `hijack-dns`, `sniff`, `resolve`, `route-options`,
`reject` с опциями, `route`. Это выход для всего, что форма Inline не
выражает, без отдельной модели на каждое поле.

## Параметры

| Параметр | Значение |
|---|---|
| Source | **Raw JSON** (переключатель вида в редакторе) |
| Тело | один JSON-объект — одно правило `route.rules` |

Цели, секций условий, Wi-Fi, DNS-опции и Action & Resolve у такого правила
нет: всё внутри тела. Пикер цели в строке списка не показывается.

## Входы / Выходы

**Входы:** текст тела.
**Выходы:** тело кладётся в `route.rules` как есть, на своё место в порядке
списка.

## Правила и инварианты

- **Редактор:** пустое тело («Enter a JSON object.»), невалидный JSON
  («Invalid JSON.»), скаляр и массив не сохраняются; для массива подсказка
  «One rule holds one JSON object. Add each object of the array as a separate
  rule.» Одна проверка у кнопки Save формы, Save в заголовке и Save из
  диалога несохранённых правок; набранный текст остаётся в поле.
- **Сборка:** пустое тело, битый JSON, скаляр — правило пропускается с
  предупреждением, остальной конфиг собирается. Массив объектов (старые
  записи) раскладывается в несколько правил подряд, не-объекты
  отбрасываются.
- Ключи-комментарии `//…` снимаются рекурсивно с предупреждением — ядро
  отвергает неизвестные поля; правило, состоящее только из комментариев,
  не эмитится. Прочие неизвестные поля не трогаются — их отвергнет ядро.
- Цель `outbound` внутри тела проверяется перед стартом, как у всех правил:
  висячая — fatal с причиной.
- Равенство правил — по содержимому JSON; смена только форматирования
  считается правкой в редакторе.
- Выключенное правило не эмитится.

## Границы

- Смысл тела не проверяется клиентом, кроме `//`-ключей и цели; ошибки
  схемы ловит ядро при проверке перед стартом.
- Ссылка тела на rule_set, которого нет в конфиге, клиентом не лечится.
