# Порядок и включение правил — один упорядоченный список, где побеждает первое совпадение

Свои правила и пресеты стоят в одном списке на вкладке Rules; ядро проверяет его сверху вниз,
поэтому перемещение правила меняет то, что оно ловит.

| Поле | Значение |
|------|----------|
| Фича | [004-ROUTING](../FEATURE.ru.md) |
| Обещания | P1 P2 P3 P4 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Держит один список правил на табе **Rules**, где свои правила и пресеты
стоят вперемешку. Пользователь перетаскивает правила за ручку, включает и
выключает свичом, удаляет долгим тапом (с подтверждением) или из
редактора. Ядро проверяет правила сверху вниз, первое совпадение побеждает
— поэтому порядок в списке и есть смысл маршрутизации.

## Параметры

Порядок задаёт разреженная ось номеров, общая для всех правил:

| Зона | Номера | Кто |
|---|---|---|
| Голова | 0 | Traffic Processing (не двигается) |
| Специфичные пресеты | 945–990 | Tailscale, Private IPs, Block Ads, FCM, BitTorrent, VoWiFi |
| Свои правила | 1000–1100 | inline / `.srs` / JSON |
| Широкие перехватчики | 1110–1150 | Russia-only, Ru internet segment, FakeIP, Unknown traffic |

Номер — стартовая позиция: пресет из каталога садится на номер шаблона,
новое своё правило — в конец занятой части зоны 1000–1100.

## Входы / Выходы

**Входы:** жесты пользователя; номера из шаблона; список из хранения.
**Выходы:** отсортированный по номерам список в хранении; в конфиге —
правила в том же порядке.

## Правила и инварианты

- Список всегда отсортирован по номеру; при равных номерах сохраняется
  взаимный порядок.
- **Drag «встать за целевым»:** правилу даётся номер цели + 1; если он
  занят, на +1 сдвигается только сплошной занятый блок до первой дырки.
  Якоря шаблона за дыркой не двигаются; соседи при удалении не
  перенумеровываются.
- Брошенное в самое начало правило встаёт под голову, а не выше.
- Зона своих правил исчерпана — новые получают её верхнюю границу, порядок
  доопределяет позиция в списке.
- Список без номеров (старое хранение) размечается при первой загрузке:
  пресеты — номерами шаблона, остальное — подряд с 1000 в прежнем порядке.
- Голова стоит на номере 0 всегда: сдвинутая импортом возвращается при
  загрузке, сборке и после импорта; потерянная — засевается.
- Выключенное правило остаётся на месте и в конфиг ничего не даёт; его
  DNS-аспект тоже гаснет.
- Удаление правила стирает его файлы внешних наборов.
- Сохранение правила в редакторе не меняет его номер (нет ложного «Save
  changes?» и прыжка вверх).
- Изменения на экране помечают конфиг к пересборке; на диск пишутся при
  уходе с экрана или сворачивании приложения.

## Границы

- Автоматической сортировки «reject выше direct» больше нет — только ось.
- Порядок DNS-правил — [005-DNS](../../005-DNS/FEATURE.ru.md) (зеркала
  маршрутизации идут в порядке этого списка).
- Перемещение через Debug API — [013-DIAGNOSTICS](../../013-DIAGNOSTICS/FEATURE.ru.md).
