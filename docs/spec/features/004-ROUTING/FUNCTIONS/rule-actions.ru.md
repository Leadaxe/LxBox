# Действие правила — направить, заблокировать, отклонить или разрешить домен

Каждое правило отправляет совпавший трафик в Направление или `direct`, блокирует или отклоняет его
либо сначала разрешает домен — например, только в IPv4.

| Поле | Значение |
|------|----------|
| Фича | [004-ROUTING](../FEATURE.ru.md) |
| Обещания | P6 P7 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Определяет, что происходит с совпавшим трафиком: отправить в Направление
или напрямую, заблокировать, либо сначала разрезолвить домен (например,
только в IPv4) и затем отправить. Цель выбирается пикером в строке списка
или в редакторе, режим — в листе **Action & Resolve**.

## Параметры

| Выбор | Что в конфиге |
|---|---|
| `direct` | `outbound: direct-out` |
| Направление (`vpn-1`, …) | `outbound: <тег>` |
| `block` | `outbound: block` (служебный outbound блокировки) |
| Reject | `action: reject` |
| Route to outbound | только правило маршрута (по умолчанию) |
| Resolve first | `{…матч, action: resolve, …}` перед правилом маршрута |
| Resolve only | одно `action: resolve` без маршрута; трафик идёт дальше по списку |

Опции resolve (пусто — ключ не пишется): Strategy (`prefer_ipv4`,
`prefer_ipv6`, `ipv4_only`, `ipv6_only`; пусто — наследует DNS), DNS server
(пусто — «auto», DNS-маршрутизация), Advanced: Disable cache, Disable
optimistic cache, Rewrite TTL (сек), Query timeout (`5s`), Client subnet
(CIDR). Лист показывает превью получающихся `route.rules`.

## Входы / Выходы

**Входы:** выбор цели и режима; список Направлений; DNS-серверы.
**Выходы:** `outbound`/`action` правила маршрута; при resolve — одно или два
правила с тем же матчем (включая `network`, порты, Wi-Fi).

## Правила и инварианты

- `reject` никогда не пишется как цель `outbound` — только как действие;
  это держится и для умолчаний пресетов.
- «Resolve first»: resolve-правило всегда стоит непосредственно перед своим
  правилом маршрута и повторяет его матч целиком.
- «Resolve only»: выбранная цель сохраняется в правиле (смена режима её не
  теряет), но в конфиг не идёт; в списке у правила значок ✳.
- Resolve применим, только если есть что резолвить: у inline — при наличии
  доменных условий (иначе опция скрыта и не эмитится); у `.srs` — всегда.
- DNS-сервер resolve, пропавший из списка серверов, при импорте правила
  сбрасывается в «auto»; в листе показывается как «… (missing)».
- Действия `hijack-dns`, `sniff`, `route-options` и прочие — только через
  [сырой JSON](raw-json-rules.ru.md) или пресет Traffic Processing.
- DNS-опция («Send DNS to dedicated server», «Force IPv4 (drop AAAA)») —
  отдельная секция, недоступна при фильтрах порт/протокол/сеть; её
  действие описано в [005-DNS](../../005-DNS/FEATURE.ru.md).

## Границы

- `block` и Reject различаются для ядра (outbound против действия); в
  интерфейсе оба красные. Выбор между ними — на пользователе.
- Проверить, каким правилом и куда ушло соединение, —
  [012-LIVE_STATE](../../012-LIVE_STATE/FEATURE.ru.md).
