# Внешние rule-set и локальный кэш

| Поле | Значение |
|------|----------|
| Фича | [004-ROUTING](../FEATURE.ru.md) |
| Обещания | P8 P9 P10 P11 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Позволяет маршрутизировать по готовым спискам из сети (geosite, geoip,
реклама, списки приложений) в формате `.srs`. Пользователь заводит правило
вида **Remote (.srs)** с одним или несколькими URL; пресеты шаблона тоже
несут внешние наборы. Приложение скачивает файлы в свой кэш и отдаёт ядру
локальный путь; само ядро в сеть за списками не ходит.

## Параметры

| Параметр | Значения | Умолчание |
|---|---|---|
| URL набора (правило `.srs`) | по одному `http(s)://` на строку, повторы и пустые отбрасываются | — |
| Check for updates (TTL своего правила) | Never · Every day · Every week · Every 2 weeks · Every month · Every 6 months · Every year | Every week (168 ч) |
| TTL пресетного набора | из `update_interval` шаблона (`h`/`d`/`w`, без единицы — часы, `0` — никогда) | неделя |
| Доп. фильтры `.srs`-правила | порты, приложения, протокол, сеть, источник, вход, Wi-Fi | — |

Действия: ☁ в строке правила — скачать/перекачать (✅ — всё в кэше,
спиннер — идёт загрузка); долгий тап по ☁ пресета — «Refresh rule-sets» и
«Clear cached files»; в редакторе — «Update now», «Refresh SRS», «Clear
cached file», «Copy URL», «Paste» и строка «Updated … / ошибка последней
попытки».

## Входы / Выходы

**Входы:** URL наборов; ответы сервера (200 с телом, 304, ошибки); ETag.
**Выходы:** файлы в кэше приложения (по одному на набор, ключ — id правила
или пресет+тег набора) с метаданными (последнее подтверждение, последняя
попытка, ETag, ошибка); в конфиге — `{type: local, format: binary, path}`
на каждый набор и одно правило маршрута со списком тегов.

## Правила и инварианты

- **Скачивание:** до 3 попыток с паузами 1 с и 3 с, повтор только на
  временных сбоях (сеть, таймаут, 5xx, пустое тело); 4xx — сразу отказ.
  Запись атомарная: файл заменяется только целиком.
- **Сбой не удаляет файл:** устаревший рабочий список лучше выключенного
  правила; 304 — успех, файл не переписан, свежесть продлена, конфиг не
  помечается изменённым.
- **Своё `.srs`-правило** требует файлы всех наборов; хоть одного нет —
  правило пропускается сборкой с предупреждением «skipped: no cached file
  (Download first)». Первый набор даёт тег = имя правила, следующие —
  `<имя>-2`, `<имя>-3`…
- **Пресетный набор** без файла выпадает сам, остальное правило пресета
  живёт; набор, выключенный переменной пресета (например GeoIP-слой), не
  требуется, но его файл хранится — вернут галку, качать заново не нужно.
- **Экран Routing при открытии** выключает правило, у которого нет нужных
  файлов; свич в списке у такого правила сначала качает, включает только при
  полном успехе. В редакторе свич `.srs`-правила недоступен до загрузки.
- Правило, добавленное из каталога с внешними наборами, приходит
  выключенным: «Added … — tap ☁ to download, then enable».
- Смена URL или вида правила стирает старые файлы и выключает правило;
  удаление правила стирает его файлы; при открытии экрана удаляются файлы,
  которым не соответствует ни одно правило.
- **Автообновление:** кандидаты — наборы включённых правил старше TTL
  (или без метаданных); «Never» не обновляется. Проход — через 30 с после
  старта приложения и через 30 с после подъёма туннеля, только на переднем
  плане, условным GET, с паузой между наборами; неудача — один повтор через
  20 с; успешный проход — до перезапуска процесса больше не проверяем.
  Изменившийся файл поднимает пересборку конфига. Ручное «Update now»
  перекачивает безусловно.
- DNS-опция у `.srs`-правила работает, только если в наборе есть домены.

## Границы

- Содержимое `.srs` не разбирается и не показывается.
- Кэш не входит в резервную копию; после восстановления наборы качаются
  заново.
- Фонового обновления по таймеру нет и не будет (батарея).
