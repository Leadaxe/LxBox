# JSON и схема протокола

| Поле | Значение |
|------|----------|
| Фича | [008-NODE_EDITOR](../FEATURE.ru.md) |
| Обещания | P6 P8 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Показывает тело узла в форме sing-box и даёт писать его руками. Знание о
полях протокола (какие есть, какого типа, что допустимо) живёт в реестре
контракта с ядром; сегодня редактор этим знанием **не пользуется** — только
подсвечивает синтаксис JSON. Проверка написанного — ядро при сохранении
([source-editing.md](source-editing.ru.md)) и предупреждения разбора (002).

## Параметры

| Место | Что есть |
|---|---|
| Узел → JSON | тело только для чтения, подсветка JSON, Copy JSON, Edit JSON |
| Узел подписки → JSON / Source | только чтение, подсветка; Source — Compact/Extended |
| Мастер → Paste JSON | редактируемое поле с подсветкой JSON |
| Узел → Source | редактируемое моноширинное поле **без** подсветки |

Своих настроек у функции нет.

## Входы / Выходы

**Вход:** тело узла (своё — дословно из источника, иначе — тело модели).
**Выход:** текст для просмотра и копирования; правка — только через Source.

## Правила и инварианты

- Вкладка JSON своего узла показывает то, что получит ядро: у sing-box-
  источника — его объект дословно, у ссылки, INI и Xray-объекта — тело
  модели. Без префикса тегов, detour и шагов сборки.
- Поля, которых нет в модели приложения, в своём JSON-теле сохраняются и
  уходят в ядро (P8).
- **TLS/SNI правятся только текстом.** Отдельной формы TLS у узла нет, поэтому
  объект `tls` своего узла меняется ровно так, как его написал человек.
  Мастер HTTP при включённом HTTPS пишет `tls: {enabled: true, server_name:
  <Host>}`; ALPN, `insecure`, сертификаты и прочее — правкой тела.
- **Ловушка «замена объекта `tls` целиком».** Форма, которая выставляет одно
  поле из `tls` (SNI) и при его правке собирает `tls` заново из двух ключей,
  молча теряет остальные (`alpn`, `certificate`, …). Так работает форма
  DNS-сервера (известное ограничение, задача 530, фича
  [005-DNS](../../005-DNS/FEATURE.ru.md)). Любая будущая форма узла по схеме
  обязана сливать поле в существующий `tls`, а не заменять объект.
- Узел из ссылки, пересобранный моделью, TLS-поля, которых модель не
  рассуждает, переносит как есть (разбор — 002).

## Что не сделано (направление §554F)

Принятое направление — JSON-редактор, осведомлённый о схеме реестра; форма по
схеме отложена. Из фазы 1 сделана только подсветка синтаксиса. Нет:

- подчёркивания ошибок по кодам санитайзера с путями до полей;
- нижнего листа с описанием поля (`desc_ru`/`desc_en`, тип, `required`,
  `default`, `values`, `format`) под курсором;
- автодополнения ключей и значений по схеме;
- подсветки на вкладке Source, где правка и происходит;
- формы по схеме (скрытие полей по `conflicts`/`requires`/`when`, маскировка
  `secret`).

Место редактора по схеме в навигации не решено.
