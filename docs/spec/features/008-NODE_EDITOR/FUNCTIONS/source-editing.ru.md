# Правка источника — ссылка, WireGuard INI или sing-box JSON за узлом

Свой узел правится через текст источника, и в ядро уходит ровно то, что
сохранено; JSON-тело сначала проверяет ядро.

| Поле | Значение |
|------|----------|
| Фича | [008-NODE_EDITOR](../FEATURE.ru.md) |
| Обещания | P5 P6 P7 P8 P9 P10 P12 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Даёт изменить сам текст, из которого получается свой узел, — ссылку,
WireGuard INI или тело sing-box — и сохранить его так, чтобы в конфиг ушло
именно написанное. Истина узла — источник; тело, которое видит ядро,
выводится из него и не хранится.

## Параметры

| Вид источника (по тексту) | Подпись на вкладке Source | Что делает Save |
|---|---|---|
| JSON (начинается с `{` или `[`) | «sing-box JSON: sent to the core as is. The core checks it on save.» | только тело узла, тег из Tag в `tag`, проверка ядром, запись |
| ссылка (одна строка с `://`) | «Link: the tag goes into its fragment on save.» | тег во фрагмент `#…`, запись |
| WireGuard INI | «WireGuard config: saved as is. The tag is stored separately.» | текст как есть, тег — полем записи |

Кнопка **Edit JSON** на вкладке JSON.

## Входы / Выходы

**Вход:** текст вкладки Source, поле Tag, ответ ядра `CheckConfig`.
**Выход:** новый источник записи, перечитанный узел, сообщение.

| Ситуация | Сообщение |
|---|---|
| пусто | «Source is empty» |
| невалидный JSON | «Invalid JSON: …» |
| объект без `type`, без `outbounds`/`endpoints` | «JSON must be an outbound object with "type" or a document with "endpoints"/"outbounds"» |
| в документе нет узла | «The document has no node to save.» |
| ядро отвергло | «The core rejected the node: <текст ядра>» |
| во входе было лишнее | «Only the node is saved. The rest of the input is not kept.» |
| были комментарии | «Comments were removed.» |
| член папки или одиночный сервер, текст не дал узла | «Could not parse server config — keeping current» |
| успех | «Saved» |

## Правила и инварианты

- **Только тело узла.** Документ (`endpoints`/`outbounds` в корне) — форма
  ввода, не хранения: берётся первый элемент, не служебный (`direct`,
  `block`, `dns`) и не группа (`selector`, `urltest`), сначала из
  `endpoints`, потом из `outbounds`. Массив — первый элемент. `dns`, `route`
  и прочее из документа не сохраняются (P5).
- **Байт в байт.** Голое тело при неизменном теге пишется как набрано;
  извлечённое из документа или массива — JSON с отступом 2 пробела (P6).
- **Проверка ядром** — только у JSON: ядру отдаётся конфиг из одного узла без
  `detour` (ссылка на чужой тег ядру неизвестна), WireGuard — под
  `endpoints`, прочее — под `outbounds`. Проверяется ровно то, что уйдёт в
  конфиг: у sing-box-тела — оно само, у Xray-объекта — тело модели. Мост к
  ядру недоступен — сохранение не блокируется (P7).
- **Дословность.** Своё sing-box-тело (свой сервер или член папки) уходит в
  конфиг как написано: ключи вне модели живы, гейты приложения тело не
  правят, реестр только сообщает; `detour` тела снимается — detour решает
  запись (P8). Правила сборки — [003-CONFIG_BUILD](../../003-CONFIG_BUILD/FEATURE.ru.md).
- **Edit JSON.** У JSON-источника — переход на Source. У ссылки и INI —
  предупреждение «Edit JSON?» (приложение перестаёт проверять узел, проверяет
  только ядро на Save, «There is no way back to a link»); Continue заменяет
  источник телом модели и уводит на Source («Source replaced with JSON»).
- **Вердикт ядра** снимается, только если тело узла действительно
  изменилось; узел при этом включается. Правка имени и пробелов вердикт не
  трогает. Выключенный человеком узел правкой не включается (P9).
- **Член папки и одиночный сервер** — транзакционно: текст без узла не
  записывается, запись остаётся прежней (P10).
- **Комментарии** `//` и `/* */` снимаются до разбора; незнакомый приложению
  тип своего тела принимается с предупреждением; тело без `type` — отказ (P12).
- После записи экран перечитывает узел: Source — записанный текст, JSON —
  новое тело, уведомления — свежие.
