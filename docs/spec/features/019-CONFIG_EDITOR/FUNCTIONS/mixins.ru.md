# Миксины — хранимые правки итогового конфига, которые переживают пересборку

Миксин — хранимая операция над собранным конфигом sing-box: путь к цели,
действие и JSON-значение. Добавляет то, чего шаблон не даёт (лишний inbound,
правило, поле у группы outbound'ов), без закрепления конфига.

| Поле | Значение |
|------|----------|
| Фича | [019-CONFIG_EDITOR](../FEATURE.ru.md) |
| Обещания | P12 |
| Состояние | ✅ написана по коду, 2026-11-01 |

## Что делает

- **Где.** Экран Config (≡ → Config Editor), вкладка **Mixins** рядом с
  **Config**. Вкладка Config показывает конфиг с уже применёнными миксинами.
- **Когда.** Последний шаг каждой сборки: после пресетов, после гардов и
  автоснятия битых узлов, перед итоговой проверкой. Включённые миксины
  применяются сверху вниз; каждый видит результат тех, что выше.
- **Сколько живут.** Миксины — часть настроек: пересборка применяет их
  заново, они сохраняются в LX Backup (секция `mixins`) и доступны через
  Debug API по `/mixins`.

## Список миксинов

Строка: ручка перетаскивания (порядок = порядок применения), имя, под ним
`target → action`, тумблер справа. Если последняя сборка упала из-за
миксина, под его строкой — `⚠ <причина>`. Долгий тап — Duplicate, Delete.
Кнопка (+) открывает пустую форму. Тумблер, порядок и удаление сохраняются
сразу и запускают пересборку.

## Запись миксина

| Поле формы | Ключ записи | Смысл |
|------------|-------------|-------|
| Name | `name` | Свободный текст, может быть пустым; пустое имя показывается как `target → action` |
| — (тумблер в списке) | `enabled` | Выключенный миксин сборка пропускает |
| Target | `target` | Путь в конфиге, см. «Язык пути» |
| Action | `op` | `append`, `prepend`, `before`, `after`, `set`, `merge`, `remove` |
| Value | `value` | Любой JSON; в форме принимается JSON5 (комментарии, висячие запятые). У `remove` — `true` или список ключей |

В Debug API и в LX Backup миксин — объект
`{"target": "...", "op": "...", "value": <json>, "name": "...", "enabled": true}`.
Импорт из бэкапа добавляет в конец списка; миксин с теми же `target` + `op` +
`value` пропускается, дубля не будет.

## Язык пути

Собственный синтаксис приложения, не JSONPath.

```
путь      = "" | сегмент ("." сегмент)*
сегмент   = имя | имя "[" N "]" | имя "[" условия "]"
условия   = условие ("," условие)*
условие   = поле "=" значение
поле      = имя ("." имя)*
```

- Сегменты соединяются через `.`: `route.rules`, `dns.servers`, `log.level`.
- Пустой путь — корень конфига.
- `name[0]` — элемент списка по индексу. `name.0` означает то же.
- `name[k=v]` — все элементы списка `name`, у которых поле `k` равно `v`.
  Несколько условий — через запятую, верны должны быть все:
  `route.rules[action=resolve,strategy=prefer_ipv4]`.
- Поле в условии может уходить вглубь элемента: `outbounds[tls.enabled=true]`.
- Сравнение: число с числом, `true`/`false` с bool, остальное — как строки с
  учётом регистра. Если поле элемента — список, `=` означает «содержит»:
  `route.rules[rule_set=Ads]` совпадает с правилом
  `"rule_set": ["Ads", "Trackers"]`.
- Значение — всё до `,` или `]`; пробелы внутри допустимы:
  `outbounds[tag=S2 Fastest]`. Запятой и `]` в значении быть не может.
- Регулярок, `!=` и `or` нет. Путь, начинающийся с `$`, зарезервирован и
  считается синтаксической ошибкой.

Путь обозначает набор узлов: `outbounds[type=vless]` — все VLESS-outbound'ы, а
не первый.

## Действия

| Действие | Цель | Что делает |
|----------|------|------------|
| `append` | один список | Значение в конец; если значение — список, каждый его элемент по очереди |
| `prepend` | один список | То же в начало; порядок значения сохраняется |
| `before` | элементы списка | Значение (или каждый элемент значения-списка, по порядку) на тот же уровень перед **первым** совпавшим |
| `after` | элементы списка | То же после **последнего** совпавшего |
| `set` | любой узел | Заменяет узел целиком: скаляр, список или объект. В корне — только объект |
| `merge` | объект(ы) | Слияние вглубь: ключи значения дописываются или заменяют свои, остальные ключи не трогаются; объект в объект — рекурсивно; список внутри значения заменяет список цели целиком. Значение — только объект |
| `remove`, значение `true` | любой узел | Удаляет узел: элемент списка выбывает, ключ объекта исчезает. Корень удалить нельзя |
| `remove`, значение `["key", "a.b"]` | объект(ы) | Удаляет только названные ключи; ключ через точку — вглубь элемента; отсутствующий ключ — не ошибка |

По числу совпадений:

| Действие | 0 | 1 | несколько |
|----------|---|---|-----------|
| `set`, `merge`, `remove` | ошибка | применяется | к каждому, одно и то же значение |
| `before` | ошибка | перед ним | перед первым |
| `after` | ошибка | после него | после последнего |
| `append`, `prepend` | ошибка | в этот список | ошибка |

## Форма

- **Target** — текстовое поле с подсказками по позиции курсора: в начале и
  после `.` — ключи объекта; после `[` — поля и индексы; после `=` — значения
  поля; после `,` — ещё не использованные поля; после `]` — `.`. Значок
  лампочки в поле (подсказка Suggestions) включает и выключает подсказки;
  выбор запоминается между открытиями и пересборку не запускает. Под полем —
  живой статус: `✓ 1 match`, `✓ N matches → before first` / `→ after last`,
  `✗ no match`, `✗ syntax: <сообщение>`, `✗ needs a single list`,
  `✗ not a list element`.
- **Action** — семь действий. У `remove` — переключатель Whole node / Keys;
  при Keys вместо поля Value — список ключей через запятую.
- **Value** — JSON-редактор с Format.
- **Preview** — родитель цели после применения: одна строка на элемент,
  `+` вставлен, `~` изменён, `-` удалён; тап по строке — полный JSON
  элемента. Для цели-скаляра — одна строка `было → стало`.

Подсказки, статус и предпросмотр берутся из текущего собранного конфига в
том виде, каким он был до этого миксина, с применёнными включёнными миксинами
выше него. Save неактивна, пока статус показывает ✗ или Value не разбирается.

## Примеры

DNS-слушатель для другого приложения (Rethink и подобных) — два миксина в
таком порядке:

```json
{"name": "DNS listener", "target": "inbounds", "op": "append",
 "value": {"type": "direct", "tag": "dns-in", "listen": "127.0.0.1",
           "listen_port": 5354, "override_address": "1.1.1.1", "override_port": 53}}
{"name": "Hijack DNS from dns-in", "target": "route.rules[action=hijack-dns]", "op": "before",
 "value": {"inbound": ["dns-in"], "action": "hijack-dns"}}
```

Порт 5353 на Android может держать системный mDNS, поэтому в примере 5354;
подойдёт любой свободный порт.

Другие действия:

```json
{"target": "route.rules[action=resolve,strategy=prefer_ipv4]", "op": "after",
 "value": {"domain_suffix": [".nas.home"], "outbound": "direct-out"}}
{"target": "outbounds[type=vless]", "op": "merge", "value": {"tcp_fast_open": true}}
{"target": "outbounds[tag=PR DE-1]", "op": "remove", "value": ["tcp_fast_open", "tls.utls"]}
{"target": "route.rules[rule_set=Ads]", "op": "remove", "value": true}
{"target": "log.level", "op": "set", "value": "warn"}
{"target": "", "op": "merge", "value": {"services": []}}
```

## Ошибки

Миксин, который нельзя применить, останавливает сборку: конфиг не
собирается, ошибка показывается как фатальная ошибка сборки, под строкой
миксина в списке — `⚠`. Текст ошибки:

- `Mixin "<name>": <target>: no match`
- `Mixin "<name>": <target>: needs a single list` — `append`/`prepend` на
  не-списке или на нескольких совпадениях;
- `Mixin "<name>": <target>: not a list element` — `before`/`after` на ключе
  объекта (`inbounds`, `log.level`);
- `Mixin "<name>": <target>: not an object` — `merge` или `remove` с ключами
  на не-объекте; `merge needs an object value` — значение не объект;
- `Mixin "<name>": duplicate tag "x" in outbounds` — после всех миксинов
  теги проверяются на уникальность в `inbounds`, в `outbounds` + `endpoints`
  (одно пространство имён) и в `dns.servers`.

Пустой путь в тексте — `(root)`. Миксин остаётся включённым: его правят или
выключают.

## Правила и инварианты

- Миксины работают по сырому конфигу: автоснятие битых узлов и санитайзер
  outbound'ов их не видят. Значение, которое ядро отвергает (неизвестное
  поле, неверный тип), ядро и сообщит на старте; у элемента с тегом ошибка
  привязывается к тегу, у правила — только к индексу.
- `prepend` на `route.rules` ставит правило перед Traffic Processing (sniff,
  hijack-dns). Это допустимо: цель выбирает пользователь.
- `merge` дописывает новые ключи в конец объекта; порядок ключей ядру
  безразличен.
- Ручная правка на вкладке Config и миксины независимы: следующая пересборка
  ручную правку отбрасывает и применяет миксины заново.
- Lock config останавливает пересборки целиком; миксины пересборки
  сохраняют и меняют только свои узлы.

## Границы

- После перезапуска приложения и до первой сборки форма пишет под Target
  `No config built yet`: нет числа совпадений, подсказок и предпросмотра.
  Save проверяет только синтаксис пути и Value; совпадения проверит
  следующая сборка.
- Группировки миксинов и общего тумблера нет.
- Схема бэкапа лаунчера секцию `mixins` пока не объявляет; при импорте
  такого бэкапа лаунчер предупреждает о неизвестном поле.
- Эндпоинты Debug API (список, создание, `PATCH`, удаление, порядок,
  предпросмотр одного миксина) — [справочник Debug API](../../../../api/debug-api-reference.md#mixins-crud--mixins).
