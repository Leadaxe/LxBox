## 1. Зачем

Санитайзер уже устроен правильно: один движок (`body_sanitizer.dart`) исполняет
атрибуты `body.fields` реестра и не знает ни одного протокола. Новое правило
значения — правка JSON у лаунчера и синк, а не код в двух приложениях.

Слой перед ним устроен наоборот. 13 рукописных мапперов ссылок
(`app/lib/services/parser/mappers/*_mapper.dart`), маппер Xray, маппер INI,
рукописное опознание формата документа (`isDirectLink`, развилки
base64 / список ссылок / JSON / INI) и рукописная сборка ссылки
(`node_spec_emit.dart`, `toUri*`). Секции `uri`, `mapper`, `emit` в реестре
есть, но их читает только генератор документации. Каждое расхождение
Go ↔ Dart в этом слое — отдельная находка и отдельная заплата с двух сторон.

Маппер по сложности не выше санитайзера: таблица «откуда взять → куда
положить» плюс конечный набор структурных примитивов. Объём работы — не в
движке, а в доказательстве, что ни один живой узел не изменился.

## 2. Решения (приняты)

1. **Реестр управляет превращением ВСЕХ источников в узел.** У протокола —
   раздельные секции-мапперы по виду источника: ссылка, Xray-JSON,
   sing-box-JSON, `.conf`/INI. Примитивы и движок общие.
2. **sing-box-JSON — не «как есть», а маппер с диалектами форков**: опознание
   диалекта по признакам тела, алиасы и пути по диалекту, перенос
   outbound ↔ endpoint, `peers[]` ↔ плоские поля; неизвестный ключ — info-код.
   Xray-JSON — тоже диалекты. *Граница:* хранение не меняется — дословный
   `rawSource` (§454–§456) остаётся источником; маппер работает только на пути
   в модель.
3. **Декларативное опознание, два уровня.** Реестр видов документа
   (base64-подписка, список ссылок, конфиг xray, конфиг sing-box, ini, …) и
   `detect` у каждой секции-маппера (regex и/или json/ini-схема). Рукописных
   снифферов формата в коде не остаётся. Линтер: каждый кейс корпуса
   опознаётся ровно одной секцией.
4. **Сборка ссылки — от той же таблицы, в этом релизе**, последней волной
   после доказанного разбора.
5. **Декодирование.** Percent-декод query — один раз. «+» в query — пробел
   (норма form-encoding не отменяется); у полей base64-формата (ключи
   WG/AWG/masque, `pbk`, `header_protection_key`) «+» читается буквально —
   свойство формата поля в реестре, заплат в коде нет. `alpn` — повторный
   percent-декод до стабилизации, не более 16 проходов; `path` — 2 прохода,
   повторный — только percent. На выходе пробел — `%20`.
6. **Имена параметров — регистронезависимо**; при двух написаниях побеждает
   точное совпадение с каноном, иначе первое по порядку.
7. **Неизвестный параметр источника — `uri_param_unknown` (info).**
   «Объявленными» считаются и параметры общих файлов (tls, transports,
   dialer); содержимое `extra` у xhttp — не параметры ссылки.
8. **Тег безымянного узла — по типу узла** (`hy2://` → `hysteria2-…`,
   `ss://` → `shadowsocks-…`), правило в реестре. У нас так сейчас —
   identity не двигается. Xray-вход держит историческое написание — в секции
   xray.
9. **Authority разбирает лексер движка**, не `Uri.parse`: платформенный
   парсер отказывает на `host:443,20000-30000`.
10. **Дельты поведения — только явным списком** (`DELTAS.md` у лаунчера,
    «было → стало» для обоих приложений), отдельный коммит с правкой
    ожиданий на каждую. Критерий отбора (владелец доверил решать
    исполнителю): тело РАБОЧЕГО узла и identity не меняются; чинится сегодня
    сломанное или молча теряемое; общепринятая норма не отменяется;
    исключения — атрибутом реестра. Позиция LxBox: регистр имён — да;
    `pinSHA256` списком по запятой — да; пароль trojan по «:» не резать;
    открытый userinfo SS2022 читать; эвристику SNI у trojan не включать
    (если лаунчер оставит её как `default_from` — решить по фикстурам);
    9 написаний `insecure` — да; vmess legacy с IPv6 в скобках — починить.

## 5. Критерии приёмки

1. Identity-фикстуры `app/test/fixtures/<схема>/pipeline_identity_before.json`
   всех схем и входов — без единого изменения, кроме кейсов из `DELTAS.md`;
   каждая дельта — свой коммит с «было → стало».
2. Круг `parse(emit(node))` даёт то же тело на всех фикстурах; ссылки,
   сохранённые прежними версиями (`rawSource` ручных узлов), читаются в то же
   тело. Тег не двигается ни у одного узла.
3. Греп-страж: в пакете маппера нет имён схем и нет схемных функций;
   `*_mapper.dart` удалены.
4. Линтер: каждый кейс корпуса опознаётся ровно одной секцией; рукописных
   снифферов формата нет.
5. Корпус контракта зелёный без новых per-app override'ов.
6. Перф: полная воронка 2000 узлов — не дороже ×1,5 к замеру до фичи
   («лучший из трёх»).
7. Без реестра (на CI каталога `app/contract` нет) тесты грузят зеркало
   `app/assets/contract`; движок без реестра не работает вовсе — рукописного
   запасного пути не остаётся, отсутствие реестра в сборке — ошибка сборки
   (страж `check_contract_lock`).

## 7. Что вышло: W1

Движок и пилот trojan влиты в `develop`. Устройство пакета — записка
`ENGINE_NOTES.md` (написана для сведения с Go-движком лаунчера, который
ждёт её в приложение «Dart» своего `MAPPER_ENGINE.md`).

**Пакет `app/lib/services/parser/engine/`** — пять частей и ни одного имени
схемы (греп-страж `engine_no_scheme_names_test.dart` ловит слово даже в
комментарии):

| Файл | Что делает |
|---|---|
| `lexer.dart` | текст → пространство источников без `Uri.parse`: переживает `host:443,20000-30000`, IPv6 в скобках, сырой userinfo; query — список пар, потому что при двух написаниях имени норма требует «первое по порядку» |
| `decoders.dart` | две семантики percent-декода (`query` с `+`→пробел, `path` с литеральным `+`) и N проходов либо до стабилизации; какую применить — решает запись, а не код |
| `source_space.dart` | плоское пространство имён: `query.*`, `userinfo*`, `host`, `port_raw`, `path`, `fragment` плюс `json.*`/`ini.*` под волну W5 |
| `section.dart` | модель FROZEN-грамматики; DRAFT-имена (§0.7) изолированы в `DraftNames` |
| `interpreter.dart` | исполнение: `scheme_sets` → `defaults` → userinfo → селекторы → зависимые → `default_from`/`materialize_default` → метка → `unknown_key` |
| `section_loader.dart` | секция из реестра, если исполняемая, иначе из черновика; `include` разворачивает блоки по диалектам |

Данные — `app/assets/contract_draft/uri/`: копии ИСПОЛНЯЕМЫХ секций
лаунчера (контракт 1.1.13, `8cc6ac69`), а не наше сочинение. Черновик
временный: как только секция приедет синком контракта, загрузчик возьмёт
её оттуда без правки кода.

**Расширения грамматики.** Заводить своих имён не пришлось: G1–G8 вошли в
FROZEN-таблицу лаунчера (`PRIMITIVES.md` §0, `4a3dbf3f`) до начала работы.
Сверх неё понадобилось четыре ЗАПИСИ (не примитива) и одно уточнение нормы
— всё передано лаунчеру списком:

| Что | Зачем |
|---|---|
| `transports#uri.ws.ed` / `.eh` | плоская форма `?ed=N&eh=` параметрами ссылки: у лаунчера объявлен только хвост пути, и узел молча терял `max_early_data` |
| `tls#uri.ech` | `maps_to: null` + `on_present` — ECH объявленно никуда не едет; без записи параметр уехал бы в `uri_param_unknown` |
| блок `dialer#uri` | §453 keep-alive тремя плоскими записями; у лаунчера блока нет |
| сила `defaults` секции | грамматика молчит, кто побеждает: дефолтный порт или явный. У нас дефолт слабее любой записи — иначе `443` перебивал бы порт из ссылки |

Отступление от секции лаунчера одно: `pbk`/`sid`/`key_share` сужены
условием по типу тела. Общий `tls#uri` отдал бы REALITY и trojan, то есть
ДОБАВИЛ бы блок телу рабочего узла, а дельты на это нет ни в `DELTAS.md`,
ни в ТЗ волны. Снятие сужения — отдельной дельтой.

**Дельты (5 кейсов из 35).** Каждая помечена в фикстуре полем `_delta480`,
прежние значения лежат рядом в `_before480`, и тест проверяет оба
направления — тело обязано совпасть с новым ожиданием И отличаться от
прежнего:

| Кейсы | Было | Стало |
|---|---|---|
| `upper_type_ws`, `upper_alpn`, `upper_fp` | `Type=`, `ALPN=`, `Fp=` не читались — транспорт, ALPN и отпечаток терялись молча | читаются (норма §0.6: имена регистронезависимо) |
| `path_raw_plus`, `path_encoded_slash_raw_plus` | `/a b` — путь декодировался query-семантикой, сервер отвечал 404 | `/a+b` — path-семантика на обоих проходах (D133-14, чинится у обеих сторон) |

`upper_security` и `upper_sni` дельтами НЕ помечены: тело у них не
меняется. `Security=tls` совпадает с дефолтом схемы, `SNI=` — с
`default_from: host`, то есть непрочитанный параметр давал тот же ответ
случайно, и пометка прикрывала бы будущую регрессию.

**Перф** (2000 ссылок trojan, лучший из трёх, разнородный набор из пяти
форм): слой маппера 18 → 75 мс (×4,06), полная воронка +28%. Критерий
спеки — ×1,5 на воронке — выдержан: маппер это 37% воронки, остальное
санитайзер и постройка модели. Четырёхкратность слоя снимается
предкомпиляцией плана (`_orderedParams` и разбор строк-источников идут на
каждом узле); делать её стоит на волне, где движок понесёт 13 схем.

## 7a. Что вышло: W5–W6 (входы-документы и опознание)

Три блока в `develop`: Xray-JSON на движке, опознание вида документа от
реестра, секции вида источника `singbox`.

### Xray-JSON

`mappers/xray_mapper.dart` **удалён**; `json_parsers.dart` зовёт движок.
Второй вход движка — `runSectionOnJson`: пространство строится не лексером
из текста, а из уже разобранной карты (норма §1 — «JSON элемента
разбирается один раз на элемент»; просить движок разбирать текст заново
значило бы разбирать подписку из 2000 узлов дважды). `$base` подставляется
якорем формы, и одна таблица обслуживает `settings.vnext.0`,
`settings.servers.0` и плоскую форму.

**Диспетчера по имени протокола не осталось.** Секцию выбирает `detect`
самой секции (`MapperSections.matchJson`): прежний `switch (protocol)` и
был опознанием элемента, просто в коде.

Сверка — `engine_xray_pilot_test.dart`: 45 входов снимка
`xray/pipeline_identity_before.json` сходятся **байт в байт** (identity,
тег, имя, `rawSource`, тело), плюс линтер «ровно одна секция на элемент».
**Дельт нет ни одной**: два расхождения со снимком (`vless_ws_path_junk`,
`vless_encryption_junk`) объявлены раньше, шагом 8 фичи 472.

Отступления от секций реестра оформлены **оверлеями**, каждое — красный
кейс, переданный лаунчеру:

| Отступление | Было → стало без него |
|---|---|
| `tls#xray.alpn` → `maps_to: null` | запись реестра ДОБАВЛЯЕТ `tls.alpn` телу; с этого входа ALPN у нас не ехал никогда (`vless_alpn_tls`). D133-C9 у лаунчера помечен КАНДИДАТОМ, а запись уже боевая |
| `include` + `dialer#xray` | в `include` реестра блока нет — keep-alive из `sockopt` (§453) терялся (`vless_sockopt_keepalive`) |
| `defaults.server_port: 443` | у реестра `port` `required` без дефолта: элемент без порта давал НОЛЬ узлов (`vless_default_port`) |
| `forms[].detect.type_of` вместо `default: true` | из мусорного `streamSettings: "none"` собирался рабочий узел без транспорта и TLS, а сосед по элементу задваивался (`malformed_stream`) |
| `$sni_from_server`, `when: {tls.enabled}` у `fp`/`insecure`/`pbk` | имя сервера не заполнялось адресом узла; блоки TLS появлялись при `security: none` |

### Опознание вида документа

Реестр `assets/contract_draft/documents.json` плюс движок
`engine/document.dart`. **Язык предикатов один на оба уровня** (§2 НОРМЫ):
`detect` вида документа и `detect` секции-маппера читаются одними
функциями — второго, «документного» языка норма не допускает, с ним
сниффер вернулся бы в код под другим именем.

Снято рукописного:

- порядок веток `body_decoder` (`vpn://` → эвристика base64 → `{`/`[` →
  `[Interface]` → строки) и `_detectFlavor` с `_looksLikeSingboxOutbounds`
  — уехали в данные буква в букву;
- `isDirectLink` больше не держит **вторую копию списка схем**: читает
  `kPipelineSchemes`. Копия успела разъехаться — `naive+quic://` конвейер
  разбирал, а классификатор ввода не знал, и вставка такой ссылки падала на
  «not a subscription URL, proxy link, or JSON». Тем же дефектом раньше
  были `socks4://` (§475) и `naive+https://`/`masque://` (§268), и каждый
  чинился правкой этой копии — по одной схеме за находку;
- `isWireGuardConfig` и `isAmneziaVpnLink` спрашивают реестр.

Оболочки остались КОДОМ (`qCompress`+zlib предикатами не выражаются), но
вызываются по ИМЕНИ из `unwrap` — так же у лаунчера. Вложенная оболочка
снимается с потолком `max_unwrap_depth: 2`.

Линтер `document_registry_test.dart`: каждый документ опознаётся
однозначно (победитель по `priority` один) и реестр даёт **ту же форму**,
что прежний порядок — ответ старого пути снимается до загрузки реестра,
то есть тем же кодом.

### Секции `singbox`

13 секций **порождены механически** (норма `MAPPER_ENGINE.md` §8a, ответ
лаунчера на находку 7: «да, генерируйте»); `trojan` и `vless` приехали
реестром 1.1.15. Пустая `params` — нормальное конечное состояние, а не
заготовка: вход уже в каноне ядра, переводить нечего. Диалект уровней у
`wireguard`/`tailscale` — форма `endpoint` (по `peers[]`) объявлена ПЕРЕД
веткой `default`, иначе `default` перехватил бы элемент.

Одна правка в коде: секция под FROZEN-ключом `mappers.<вид>` исполняема
**по определению**. Прежняя проверка «есть `params` с `source`» считала
пустую `singbox`-секцию отсутствующей, и элемент не достался бы никому.

**ГРАНИЦА соблюдена:** `parseSingboxEntry` и форма хранения `rawSource`
(§454–§456) не тронуты ни строкой — секция `singbox` работает ПЕРЕД
санитайзером, как нормализатор диалекта.

### Примитивы, добавленные волной

Все — общие, ни одного имени схемы в пакете движка.

| Примитив | Зачем |
|---|---|
| `json.type_of: {<путь>: object\|array\|string\|number}` | ФОРМА значения по пути: мусорный ТИП поля делает элемент нечитаемым целиком, и это не «поля нет» |
| `json.array_elem_any_keys` с несколькими `[]` | «хотя бы у одного элемента» по вложенным массивам: `[].outbounds[].protocol`. Рукописный сниффер смотрел ПЕРВЫЙ элемент и решал за весь массив |
| `json.any` / `all` / `not` | комбинаторы, которых у объектного предиката не было; у текстового они уже есть — выражение обязано читаться одинаково на обоих уровнях |
| `text.prefix_trim`, `text.min_len` | `{`/`[` после отступа; порог длины отсекает случайный текст, проходящий алфавит base64 |
| `ini.first_section_fold` | имя первой НЕ-КОММЕНТАРНОЙ секции INI (комментарий над `[Interface]` законен и несёт имя узла, G7) |
| `when: {lt, gt}` | числовое сравнение: диалект, где ЗНАК несёт смысл («любое отрицательное = выключено совсем»), набором значений не выразить |
| `type: duration_seconds` | длительность целыми секундами числом → строка с единицей |
| `default_from: "body.<путь>"` | дефолт из УЖЕ ПОСТРОЕННОГО тела: у объектного входа адрес лежит под якорем формы, и общий блок его пути не знает |
| `on_len_gt: {n, action, code}` | у источника-МАССИВА больше `n` элементов; сегодня лишние теряются молча (Q133-18) |
| `on_no_match: {action: drop_node}` | значение не попало ни в один ключ `sets` — у селектора рода узла это «узла нет» |
| `unknown_key.ignore` | ключи УРОВНЯ ДОКУМЕНТА, полем узла не являющиеся (`protocol`, `tag`, `remarks`) |
| `label.fallback.scheme` | историческое написание тега-фолбэка объявлено ДАННЫМИ, а не остаётся свойством кода (тег и есть identity) |
| `default_when: {absent: true}` у селектора | «не сказано» ЕСТЬ значение, и запись исполняется как обычная |

Две правки формы, сделанные по ходу: ключи общего блока в плоском наборе
получили ИМЯ БЛОКА (`tls.security`) — иначе одноимённая запись схемы
затирала селектор блока и TLS-блок у такой схемы не появлялся вовсе;
переопределением при этом считается совпадение имени **и источника**, а
одно имя над разными источниками — две разные записи.

### Что осталось

- **Диалекты форков в `params` секций `singbox`** (`$masque_flat`,
  `obfs` с `coerce.object_to_scalar`, `xmux.*` тремя написаниями,
  `$addressless`, `$credential` — список `SCHEMES.md` §13.3). Сегодня их
  исполняет `parseSingboxEntry`, и перенос обязан идти вместе со снятием
  соответствующих веток оттуда, а это правка ЧИТАТЕЛЯ ТЕЛА — за границей
  волны.
- **`elements`/`element_kind` реестра видов документа читает только
  линтер**: разбор элементов по-прежнему ведёт `parse_all` своим
  `switch (flavor)`. Опознание ДОКУМЕНТА объявлено, обход его элементов —
  ещё нет.
- **Трасса** (`MAPPER_ENGINE` приложение «Трасса») на объектном входе не
  снимается.

## 8. Риски

- **Секция реестра пишется у лаунчера по Go-поведению.** Там, где Dart
  сегодня ведёт себя иначе, выбирает `DELTAS.md`, а не молчаливый перенос.
  Фикстуры W0 — единственное, что отличает «починили» от «сломали».
- **`toUri()` — форма хранения ручного узла.** Смена вида ссылки перезапишет
  `rawSource` при пересохранении. Identity (тег) не двигается; критерий 5.2
  обязателен до W7.
- **Реестр становится обязательным в рантайме разбора.** Сегодня часть путей
  работает и без него (`kAwgMtuFallback`); после W8 — нет.

## 8. Дельты волны W4 (hysteria2 / tuic / masque / wireguard + INI)

Оформление — пометка `delta480` у кейса фикстуры, «было → стало» ниже.
Всё, что в этот список не попало, — не дельта, а баг секции.

| # | Схема | Кейс фикстуры | Было → стало | Основание |
|---|---|---|---|---|
| delta480-1 | hysteria2 | `b480:pinsha256_pair` | `pinSHA256=a,b` давал ПУСТО (значение с запятой не читалось) → список `["a","b"]` | D133-11 |
| delta480-2 | masque | `b480:publickey_raw_plus` | сырой `+` в `publickey` становился пробелом и ключ терял первый символ → `+` читается буквально | D133-7 |
| delta480-3 | wireguard | `b480:publickey_raw_plus`, `b480:privatekey_raw_plus_query`, `b480:presharedkey_raw_plus` | сырой `+` в ключе ронял УЗЕЛ целиком (`body: null`) → узел живёт, ключ читается буквально | D133-7 |
| delta480-4 | wireguard INI | `ini:b480_preshared_key_snake` | `preshared_key` в `[Peer]` молча терялся (читался только `PresharedKey`) → алиас читается | «чиним молча теряемое» |
| delta480-5 | все четыре | имена параметров | `SNI=`, `AllowInsecure=` и прочий регистр не читались → общий fold-case | D133-9 |
| delta480-6 | hysteria2/tuic/masque | `insecure` | 4 написания → 9 из `tls.json` | D133-10 |

**Не дельты, воспроизводится как есть:**

- INI `Endpoint = 2001:db8::1:51820` — голый IPv6 берётся адресом ЦЕЛИКОМ,
  порт по умолчанию 51820 (§219: отличить порт от адреса нечем). Кейс
  `ini:b480_endpoint_bare_ipv6`; в `DELTAS.md` лаунчера этого нет, значит
  чинить не наша волна.
- INI: читается только ПЕРВАЯ `[Peer]`, прочие отбрасываются
  (`repeat: "first_only"`); код `wgconf_extra_peer_dropped` объявлен в
  секции, но сегодняшнюю тишину не отменяет.
- `Interface.DNS` — лоссы by design, получает info-код `wgconf_dns_ignored`.
