## 1. Зачем

Санитайзер уже устроен правильно: один движок (`body_sanitizer.dart`) исполняет
атрибуты `body.fields` реестра и не знает ни одного протокола. Новое правило
значения — правка JSON у лаунчера и синк, а не код в двух приложениях.

Слой перед ним устроен наоборот. 13 рукописных мапперов ссылок
(`app/lib/services/parser/mappers/*_mapper.dart`), маппер Xray, маппер INI,
рукописное опознание формата документа (`isDirectLink`, развилки
base64 / список ссылок / JSON / INI) и рукописная сборка ссылки
(`node_spec_emit.dart`, `toUri*`). Секции `uri`, `mapper`, `emit` в реестре
есть, но их читает только генератор документации. Каждое расхождение
Go ↔ Dart в этом слое — отдельная находка и отдельная заплата с двух сторон.

Маппер по сложности не выше санитайзера: таблица «откуда взять → куда
положить» плюс конечный набор структурных примитивов. Объём работы — не в
движке, а в доказательстве, что ни один живой узел не изменился.

## 2. Решения (приняты)

1. **Реестр управляет превращением ВСЕХ источников в узел.** У протокола —
   раздельные секции-мапперы по виду источника: ссылка, Xray-JSON,
   sing-box-JSON, `.conf`/INI. Примитивы и движок общие.
2. **sing-box-JSON — не «как есть», а маппер с диалектами форков**: опознание
   диалекта по признакам тела, алиасы и пути по диалекту, перенос
   outbound ↔ endpoint, `peers[]` ↔ плоские поля; неизвестный ключ — info-код.
   Xray-JSON — тоже диалекты. *Граница:* хранение не меняется — дословный
   `rawSource` (§454–§456) остаётся источником; маппер работает только на пути
   в модель.
3. **Декларативное опознание, два уровня.** Реестр видов документа
   (base64-подписка, список ссылок, конфиг xray, конфиг sing-box, ini, …) и
   `detect` у каждой секции-маппера (regex и/или json/ini-схема). Рукописных
   снифферов формата в коде не остаётся. Линтер: каждый кейс корпуса
   опознаётся ровно одной секцией.
4. **Сборка ссылки — от той же таблицы, в этом релизе**, последней волной
   после доказанного разбора.
5. **Декодирование.** Percent-декод query — один раз. «+» в query — пробел
   (норма form-encoding не отменяется); у полей base64-формата (ключи
   WG/AWG/masque, `pbk`, `header_protection_key`) «+» читается буквально —
   свойство формата поля в реестре, заплат в коде нет. `alpn` — повторный
   percent-декод до стабилизации, не более 16 проходов; `path` — 2 прохода,
   повторный — только percent. На выходе пробел — `%20`.
6. **Имена параметров — регистронезависимо**; при двух написаниях побеждает
   точное совпадение с каноном, иначе первое по порядку.
7. **Неизвестный параметр источника — `uri_param_unknown` (info).**
   «Объявленными» считаются и параметры общих файлов (tls, transports,
   dialer); содержимое `extra` у xhttp — не параметры ссылки.
8. **Тег безымянного узла — по типу узла** (`hy2://` → `hysteria2-…`,
   `ss://` → `shadowsocks-…`), правило в реестре. У нас так сейчас —
   identity не двигается. Xray-вход держит историческое написание — в секции
   xray.
9. **Authority разбирает лексер движка**, не `Uri.parse`: платформенный
   парсер отказывает на `host:443,20000-30000`.
10. **Дельты поведения — только явным списком** (`DELTAS.md` у лаунчера,
    «было → стало» для обоих приложений), отдельный коммит с правкой
    ожиданий на каждую. Критерий отбора (владелец доверил решать
    исполнителю): тело РАБОЧЕГО узла и identity не меняются; чинится сегодня
    сломанное или молча теряемое; общепринятая норма не отменяется;
    исключения — атрибутом реестра. Позиция LxBox: регистр имён — да;
    `pinSHA256` списком по запятой — да; пароль trojan по «:» не резать;
    открытый userinfo SS2022 читать; эвристику SNI у trojan не включать
    (если лаунчер оставит её как `default_from` — решить по фикстурам);
    9 написаний `insecure` — да; vmess legacy с IPv6 в скобках — починить.

## 5. Критерии приёмки

1. Identity-фикстуры `app/test/fixtures/<схема>/pipeline_identity_before.json`
   всех схем и входов — без единого изменения, кроме кейсов из `DELTAS.md`;
   каждая дельта — свой коммит с «было → стало».
2. Круг `parse(emit(node))` даёт то же тело на всех фикстурах; ссылки,
   сохранённые прежними версиями (`rawSource` ручных узлов), читаются в то же
   тело. Тег не двигается ни у одного узла.
3. Греп-страж: в пакете маппера нет имён схем и нет схемных функций;
   `*_mapper.dart` удалены.
4. Линтер: каждый кейс корпуса опознаётся ровно одной секцией; рукописных
   снифферов формата нет.
5. Корпус контракта зелёный без новых per-app override'ов.
6. Перф: полная воронка 2000 узлов — не дороже ×1,5 к замеру до фичи
   («лучший из трёх»).
7. Без реестра (на CI каталога `app/contract` нет) тесты грузят зеркало
   `app/assets/contract`; движок без реестра не работает вовсе — рукописного
   запасного пути не остаётся, отсутствие реестра в сборке — ошибка сборки
   (страж `check_contract_lock`).

## 7. Что вышло: W1

Движок и пилот trojan влиты в `develop`. Устройство пакета — записка
`ENGINE_NOTES.md` (написана для сведения с Go-движком лаунчера, который
ждёт её в приложение «Dart» своего `MAPPER_ENGINE.md`).

**Пакет `app/lib/services/parser/engine/`** — пять частей и ни одного имени
схемы (греп-страж `engine_no_scheme_names_test.dart` ловит слово даже в
комментарии):

| Файл | Что делает |
|---|---|
| `lexer.dart` | текст → пространство источников без `Uri.parse`: переживает `host:443,20000-30000`, IPv6 в скобках, сырой userinfo; query — список пар, потому что при двух написаниях имени норма требует «первое по порядку» |
| `decoders.dart` | две семантики percent-декода (`query` с `+`→пробел, `path` с литеральным `+`) и N проходов либо до стабилизации; какую применить — решает запись, а не код |
| `source_space.dart` | плоское пространство имён: `query.*`, `userinfo*`, `host`, `port_raw`, `path`, `fragment` плюс `json.*`/`ini.*` под волну W5 |
| `section.dart` | модель FROZEN-грамматики; DRAFT-имена (§0.7) изолированы в `DraftNames` |
| `interpreter.dart` | исполнение: `scheme_sets` → `defaults` → userinfo → селекторы → зависимые → `default_from`/`materialize_default` → метка → `unknown_key` |
| `section_loader.dart` | секция из реестра, если исполняемая, иначе из черновика; `include` разворачивает блоки по диалектам |

Данные — `app/assets/contract_draft/uri/`: копии ИСПОЛНЯЕМЫХ секций
лаунчера (контракт 1.1.13, `8cc6ac69`), а не наше сочинение. Черновик
временный: как только секция приедет синком контракта, загрузчик возьмёт
её оттуда без правки кода.

**Расширения грамматики.** Заводить своих имён не пришлось: G1–G8 вошли в
FROZEN-таблицу лаунчера (`PRIMITIVES.md` §0, `4a3dbf3f`) до начала работы.
Сверх неё понадобилось четыре ЗАПИСИ (не примитива) и одно уточнение нормы
— всё передано лаунчеру списком:

| Что | Зачем |
|---|---|
| `transports#uri.ws.ed` / `.eh` | плоская форма `?ed=N&eh=` параметрами ссылки: у лаунчера объявлен только хвост пути, и узел молча терял `max_early_data` |
| `tls#uri.ech` | `maps_to: null` + `on_present` — ECH объявленно никуда не едет; без записи параметр уехал бы в `uri_param_unknown` |
| блок `dialer#uri` | §453 keep-alive тремя плоскими записями; у лаунчера блока нет |
| сила `defaults` секции | грамматика молчит, кто побеждает: дефолтный порт или явный. У нас дефолт слабее любой записи — иначе `443` перебивал бы порт из ссылки |

Отступление от секции лаунчера одно: `pbk`/`sid`/`key_share` сужены
условием по типу тела. Общий `tls#uri` отдал бы REALITY и trojan, то есть
ДОБАВИЛ бы блок телу рабочего узла, а дельты на это нет ни в `DELTAS.md`,
ни в ТЗ волны. Снятие сужения — отдельной дельтой.

**Дельты (5 кейсов из 35).** Каждая помечена в фикстуре полем `_delta480`,
прежние значения лежат рядом в `_before480`, и тест проверяет оба
направления — тело обязано совпасть с новым ожиданием И отличаться от
прежнего:

| Кейсы | Было | Стало |
|---|---|---|
| `upper_type_ws`, `upper_alpn`, `upper_fp` | `Type=`, `ALPN=`, `Fp=` не читались — транспорт, ALPN и отпечаток терялись молча | читаются (норма §0.6: имена регистронезависимо) |
| `path_raw_plus`, `path_encoded_slash_raw_plus` | `/a b` — путь декодировался query-семантикой, сервер отвечал 404 | `/a+b` — path-семантика на обоих проходах (D133-14, чинится у обеих сторон) |

`upper_security` и `upper_sni` дельтами НЕ помечены: тело у них не
меняется. `Security=tls` совпадает с дефолтом схемы, `SNI=` — с
`default_from: host`, то есть непрочитанный параметр давал тот же ответ
случайно, и пометка прикрывала бы будущую регрессию.

**Перф** (2000 ссылок trojan, лучший из трёх, разнородный набор из пяти
форм): слой маппера 18 → 75 мс (×4,06), полная воронка +28%. Критерий
спеки — ×1,5 на воронке — выдержан: маппер это 37% воронки, остальное
санитайзер и постройка модели. Четырёхкратность слоя снимается
предкомпиляцией плана (`_orderedParams` и разбор строк-источников идут на
каждом узле); делать её стоит на волне, где движок понесёт 13 схем.

## 7c. Что вышло: W2 (vless, контракт 1.1.16, предкомпиляция)

**Синк на 1.1.16** (`64377c76`) закрыл четыре из шести отступлений, которые
W1 держала оверлеями. Закрыл их лаунчер, а не мы: каждое было отправлено ему
красным кейсом, и ответ пришёл правкой реестра.

| Отступление W1 | Чем закрыто в 1.1.16 |
|---|---|
| `tls#uri.pbk` сужен по типу тела | `pbk` вынесен в отдельный блок `tls#uri_reality`; подключают его только vless и anytls, и trojan REALITY больше не получает |
| `ws.path` без кода `ws_early_data_converted` | код объявлен атрибутом `code` у ГРУППЫ `extract.into` — не у записи целиком: хвост разложился по двум полям, и сказать об этом может только тот член, который его поймал |
| `httpupgrade.host` с откатом на `sni` | откат снят, цепочки больше нет |
| `uri_param_unknown` у trojan снят целиком | §3B.2: записи-`null` и `overlay` считаются объявленными, и код перестал красить корпус |

Осталось одно отступление W1 и появилось одно новое — оба ниже, в «Оверлеях».

**vless на движке.** 99 кейсов снимка, **6 дельт, и все шесть уже приняты**
на trojan и W4 — своих у vless не появилось:

| Кейсы | Было → стало | Основание |
|---|---|---|
| `upper_type_ws`, `upper_alpn`, `upper_fp` | `Type=`, `ALPN=`, `Fp=` не читались | §0.6 FROZEN, регистр имён |
| `path_raw_plus`, `path_encoded_slash_raw_plus` | `/a b` вместо `/a+b` | D133-14 |
| `pbk_raw_plus` | `+` становился пробелом, ключ не проходил санитайзер и блок `reality` пропадал ЦЕЛИКОМ | D133-7 |

Последняя дельта чинит больше прежних: у trojan тот же дефект отнимал одно
поле, здесь — весь блок REALITY у рабочего узла.

**Сверка научилась проверять дельты двусторонне.** Раньше это умели только
пилот и W4-тест, а `engine_w4_reconcile_test` (он идёт по ВСЕМ кейсам файла)
сравнивал тело с ожиданием и на пометку не смотрел. Односторонняя пометка

### Новые атрибуты грамматики в движке (1.1.16)

Своих имён не заводилось — все из FROZEN-таблицы лаунчера:
`on_when_false`, `on_implies_written`, `value_map_case: sensitive`,
`userinfo.required`, работающий `on_invalid: keep`, `code` у члена
`extract.into`, `forms[].decode` с областью (`scope: userinfo|authority`).

Два решения реализации, которые стоит знать второй стороне:

- **`on_when_false` спрашивает источник, НЕ отмечая его прочитанным**
  (`_valueOfBare`, норма §10.2). Иначе подавленный условием параметр переставал
  бы давать `uri_param_unknown` — код замолкал бы там, где он единственный
  признак непонятого входа.
- **`on_implies_written` смотрит на тело ДО и ПОСЛЕ**, а не на факт вызова:
  при занятом пути присваивание проигрывает владельцу, и сообщать не о чем.
- **`scope`-декодер пересобирает ссылку и зовёт лексер второй раз**, а не
  правит поля пространства: декодированный authority приносит СВОЮ структуру
  (`base64(method:password@host:port)` — это и userinfo, и хост, и порт
  разом), и разбирать её обязан тот же лексер, а не второе место с теми же
  правилами.

Все — общие, ни одного имени схемы в пакете движка.

| Примитив | Зачем |
|---|---|
| `json.type_of: {<путь>: object\|array\|string\|number}` | ФОРМА значения по пути: мусорный ТИП поля делает элемент нечитаемым целиком, и это не «поля нет» |
| `json.array_elem_any_keys` с несколькими `[]` | «хотя бы у одного элемента» по вложенным массивам: `[].outbounds[].protocol`. Рукописный сниффер смотрел ПЕРВЫЙ элемент и решал за весь массив |

### Круг и чтение старых ссылок

Два стража, оба по фикстурам всех схем:

- **круг** `parse(emit(body))` — тело БАЙТ В БАЙТ, включая порядок ключей,

  не тело исходного узла: между ними лежит потеря рукописного эмита, и
  требовать от новой волны восстановить то, чего в тексте ссылки нет, значило
  бы требовать невозможного.

**Починены потери, которых раньше не замечали:** весь корпус hysteria2 теперь
переживает круг (прежде семь кейсов из 23 исключались — `mport` и `pinSHA256`

### Расширения грамматики эмита — СВЕДЕНЫ (GRAMMAR_SYNC «Сведение №2», §5)

Заводились по правилу «сперва ищи аналог»: всё, что выражалось существующим
примитивом, новым именем не называлось. Имена читаются в ОДНОМ месте —
`EmitNames` в `engine/emitter.dart`, по образцу `DraftNames`. Расчёт оправдался:
по итогам сведения префикс снят у четырёх имён правкой одной строки каждое.

К правилам выбора имени лаунчер добавил **пятое, специфичное для эмита**:
*ссылка, которую мы пишем сегодня, не меняется без строки в `DELTAS.md`* —
`rawSource` ручного узла перезаписывается при пересохранении, и смена написания
молча переписывает то, что человек когда-то вставил сам. Единственное принятое
исключение — `%20` вместо `+`.

| Имя (итоговое) | Зачем | Итог сведения |
|---|---|---|
| `round_trip: false` + `round_trip_why` | объявленный отказ от обратного хода. Без него потеря на круге молчалива; объявленная — видна линтеру и отчёту, а не телу узла пользователя | **принято как есть** |
| `emit_as` (`join` / `bool01` / `json` / `raw`) | как сериализуется значение, когда тело хранит его не строкой. `alpn` в теле список, в ссылке строка через запятую; `insecure` в теле булев, в ссылке `1`. Угадывать по типу нельзя: булев, писанный `true`, и булев, писанный `1`, — разные ссылки у живых панелей | **принято как есть**; префикс `emit_` у атрибутов ЗАПИСИ сохраняется — он отличает атрибут выхода от атрибута входа в одном словаре |
| `compose` строкой ЛИБО `{template, from, omit_when_empty}` | обращение `extract`: один параметр из нескольких путей тела. Регуляркой обратный ход не выражается — шаблон объявляет его прямо | **сведено к FROZEN-имени**: `compose` в схеме уже был строкой, добавлена объектная форма (расширение значений, не новое имя) |
| `emit.omit_port` | порт, опускаемый в ссылке. Обращать `defaults.server_port` напрямую нельзя: у схемы бывает дефолт РАЗБОРА без права опускать порт на выходе — иначе ссылка перестала бы читаться клиентами, которые дефолта не знают | **принято, префикс снят** (внутри `emit` он называл бы `emit` дважды). У нас выставлен, у лаунчера объявлен и не выставлен: его `hostPort` пишет порт всегда — расхождение объявлено, выравнивание отдельной дельтой |
| `emit.userinfo`: строка либо `{form, padding}` | выходная форма userinfo. `userinfo.decode` разбора — конвейер ПОПЫТОК (`percent`, `base64?`), и обратить его нельзя: `base64?` значит «может быть, а может и нет» | **принято, префикс снят**; паддинг вынесен третьим ключом — наш base64 без `=`, у лаунчера с `=`, обе стороны читают обе формы, и ни одна не меняет свою молча |
| `emit.json_map` + `emit.json_always` | форма, собирающая не query-ссылку, а base64(JSON) | **принято, префикс снят.** У нас `json_map` вдобавок НЕ ОБЪЯВЛЯЕТСЯ, а выводится из источников записей той же формы: объявленная отдельно, она была бы вторым источником правды |
| ~~`emit_name`~~ | написание имени в ссылке, не равное канону разбора | **ОТКЛОНЕНО.** Норма: каноническое имя на выходе — первое в `aliases`, без исключений; расхождение чинится перестановкой `aliases` плюс строкой в `DELTAS.md`. Отдельный атрибут позволял бы входу и выходу разъехаться молча |

**Перестановок `aliases` нам не потребовалось ни одной**: у записей,
где выход исторически расходился с каноном, ключ реестра уже совпадает с тем,
что мы пишем.

## 7c. Что вышло: W8 (вид ссылки = де-факто формат схемы)

Вид ссылки волна W7 меняла намеренно, и таблица выше это фиксировала. Ревизия
показала, что часть отличий **ломает совместимость**, а не только написание:
`toUri()` у нас одновременно форма хранения ручного узла (`rawSource`) и то,
что уезжает по кнопке **Copy link** в v2rayN, v2rayNG, NekoBox, Hiddify и
Shadowrocket. Круг у чужого клиента свой. Опущенный `security=tls` круг
проходит — наш разбор поднимет TLS умолчанием, — а у Xray-клиентов умолчание
`security` для vless равно `none`, и тот же узел встаёт у соседа БЕЗ
шифрования. Написание `insecure` вместо `allowInsecure` читают не все.

Отсюда уточнение нормы, принятое владельцем и лаунчером: **вид ссылки = де-факто
формат схемы**, а не канон нашей таблицы. Из него следует отмена решения
W7 по `emit_name`.

### `emit.names` — принято вместо отклонённого `emit_name`

Отклонение держалось на доводе «выход и вход разъедутся молча». Довод снимается
ограничением набора, а не отказом от имени: **выходное написание выбирается ИЗ
написаний самой записи** (имя, алиасы, query-источники), и это судит линтер
секций — запись, которая пишет то, чего не читает, отдаёт ссылку, которую мы
сами не разберём. Имя читается в `EmitNames`, набор написаний даёт общая
`readableNames` — одно правило, одно место, общее у эмиттера и линтера.

Объявляется оно **у СХЕМЫ**, а не перестановкой `aliases` общего блока, и это
существо решения. Признак «не проверять сертификат» читается всеми написаниями
сразу, но ПИШЕТСЯ у каждой схемы своим — тем, которое читают её клиенты:
`allowInsecure` у vless/trojan/anytls/http, `allow_insecure` у tuic, `insecure`
у hysteria2 (официальная спека). Перестановка `aliases` блока `tls#uri`
навязала бы одно написание всем схемам разом.

### Страж вида ссылки

`engine_emit_shape_test.dart`: **ссылка = снимок `emit_before480.json` байт в
байт**, по всем 13 схемам, кроме ЗАКРЫТОГО поимённого списка отличий с
причиной. Классом («у vless теперь иначе») отличие не объявляется — классом
прикрывается и то, чего не заметили. Список судится в обе стороны: разрешённый
кейс, у которого отличия больше нет, тоже валит тест, иначе строка прикрывала бы
будущую поломку.

Осталось разрешённых отличий девять кейсов плюс один класс, и все они —
**починки потерь**: поле, которое тело несёт, а рукописный эмит не писал
(`transport.path` и `transport.mode` у vless, `transport.host` у контейнера
vmess, `disable_sni` с `sni` у tuic), либо написание схемы `awg://` у узла с
AWG-полями (обращение `kind_when`, объявлено разделом 7b).

### Данные, которыми секции сведены к снимку

| Схема | Что объявлено | Почему |
|---|---|---|
| vless | `names: insecure→allowInsecure`; `security` вычеркнут из `omit_default`, объявлен `emit_when: always` | умолчание `security` у Xray-клиентов — `none`: ссылка без параметра читается как узел без TLS |
| trojan | то же, `omit_default` пуст | так писал рукописный эмит |
| anytls | то же; ветки `sets` записи `security` переставлены, ветка `reality` возвращена | запись перекрывает одноимённую из `tls#uri` целиком и вместе с ненужной ей веткой `none` теряла нужную `reality`; порядок объявления и есть выбор между ветками, которые тело подтверждает одинаково |
| tuic | `names: insecure→allow_insecure` | де-факто написание диалекта |
| http | `names: insecure→allowInsecure`; черновик стал оверлеем | полная копия секции устарела с приходом зеркала и всё равно проигрывала реестру — её правки не исполнялись вовсе |
| hysteria2 | `userinfo.empty_separator: true` | `@` у узла без пароля — часть сегодняшнего вида ссылки; из разбора флаг не выводится (пустой и отсутствующий userinfo неразличимы) |
| vmess | `param_order` перечнем (порядок ключей контейнера); `json_always` картой; `names: serviceName→path` | контейнер читается частью клиентов позиционно; `aid` пустой строкой читается хуже нуля, `type: none` и `net: tcp` — значения, а не пустота; имя gRPC-канала v2rayN кладёт в `path` |
| transports (xhttp) | `emit_as: raw` у трёх булевых | написание булева (`true` против `1`) — свойство параметра, а не типа значения |

### Правки движка

Четыре, все — правила, а не случаи:

1. **`emit.names`** плюс `readableNames`: выбор написания из тех, что запись
   читает.
2. **`emit_when: always` сильнее ветки умолчания.** Прежде умолчание
   побеждало равную по весу ветку и возвращало `null` до проверки
   `emit_when` — «разбор восстановит сам» верно для НАШЕГО разбора, и у
   чужого клиента умолчание бывает другим.
3. **Запись-селектор с явным `maps_to: null` остаётся селектором.** Её
   обратный ход — ветка `sets`, а не `maps_to`; так написан отказ от общей
   записи блока, и вырезать её значило потерять параметр, который тело
   несёт ветками.
4. **Ветка `sets` не пишется, когда все её пути принадлежат ДРУГИМ записям
   напрямую.** У такого пути есть хозяин — запись с `maps_to` в него, — и на
   чтении побеждает он (priority). Обратный ход повторяет тот же выбор:
   иначе составное имя ветки уезжало вместо прямого параметра, и клиент читал
   поле, которого автор не писал.

`param_order` теперь задаёт порядок и у формы-контейнера: правило одно, форм
две. `json_always` принимает карту «ключ → заполнитель» вдобавок к перечню.

### Нормы, исполненные как написаны

- **порядок параметров** — алфавитный;
- **пробел на выходе** — `%20`, не `+`;
- **литеральный `+` в значении** — `%2B`: чтение декодирует `+` как пробел
  (form-encoding), и без этого base64-ключ вернулся бы с пробелом — тот самый
  класс дефектов, который W4 чинила на входе (D133-7);
- **каноническое имя параметра** — первое в `aliases` (§0.6);
- **IPv6** — в скобках.

### Обращение `value_map`

Канон написания объявлен ПОРЯДКОМ — тем же правилом, что и каноническое имя
параметра:

- **неинъективная таблица — норма, а не ошибка.** В одно значение тела ведут
  несколько написаний (`on`, `true`, `1` — всё это «включено»); обратный ход
  берёт ПЕРВОЕ ОБЪЯВЛЕННОЕ. Прежняя редакция этого раздела требовала
  инъективности и отказывала — отказ ронял вид ссылки AWG3;
- ветка со значением `null` (`fp: {random: null}`) из обращения выпадает: она
  означает «поле не ставится», а не «значение такое»;
- **канон, которого таблица не переводит, не подменяется.** Таблица переводит
  алиасы в канон и тождественной пары не содержит: канон стоит справа, слева
  его нет. Обрати её вслепую — канон уехал бы под именем алиаса, а когда алиас
  вдобавок нагружен своим `sets`, узел на обратном чтении получил бы поле,
  которого у него не было.

### Ещё три обращения, которых потребовали схемы волны

- **`form_from: {any_set: …}`** — обращение `kind_when`. Род узла у части схем
  объявлен НАБОРОМ полей, а не значением одного пути, и написание схемы обязано
  его нести: узел с AWG-полями, уехавший как `wireguard://`, теряет род,
  который вход объявил схемой. Имя предиката взято у `kind_when` разбора —
  тот же предикат в ту же сторону, второго словаря не заводится.
- **умолчание побеждает равную по весу ветку `sets`.** Тело, одинаково
  объяснимое и умолчанием, и явным значением, писать явным не нужно: разбор
  восстановит его сам. Этим снят лишний `security=tls` у схем, где шифрование
  несёт само написание.
- **userinfo, названный ПЕРВЫМ источником обычной записи.** У туннельных схем
  блок `userinfo` секции пуст, а канон объявлен порядком источников записи
  (`["userinfo", "query.<имя>"]`): не напиши мы канон, ключ уезжал бы
  параметром — ссылка осталась бы читаемой, но сменила бы вид у всех живых
  узлов схемы.

### Что осталось нерешённым: род узла без единого своего поля

Узел, у которого вход просил AmneziaWG, но НИ ОДНО поле не уцелело (`jc=abc`
вместе с одиноким `jmin`), от обычного WireGuard неотличим: рода нет ни в
каноническом теле, ни в модели `NodeSpec` — он восстанавливается перепарсом
`rawSource`. Эмиттер такой узел отдаёт написанием `wireguard://`.

Сегодня это безвредно и проверено кругом: потолок MTU уже применён и уезжает в
ссылку числом (`mtu=1280`), identity и тег не двигаются. Станет вредно, когда
правило реестра перейдёт с `any_set` по телу на `when.source_kind` — тогда роду
нужно место в модели (поле рода у `WireguardSpec` либо признак в
`extensionFields`). **Это решение по МОДЕЛИ, а не по грамматике эмита**, и
принимается оно владельцем вместе с переходом правила.

## 7c. Сведение грамматики (GRAMMAR_SYNC 5d8adc80)

Лаунчер свёл грамматику двух сторон по каждому примитиву, который эта фича
завела: `SPECS/133-F-N-REGISTRY_DRIVEN_LINK_MAPPER/GRAMMAR_SYNC.md`, норма —
`PRIMITIVES.md` §0.11, ответ нам — `contract/TASKS_LXBOX.md` §24.27. Правило
выбора имени: аналога у них нет — берут наше; аналог есть под их FROZEN-именем
и исполняется — остаётся их; новый примитив дублирует существующий — сводится
к существующему. Переименований FROZEN-атрибутов нет ни у одной стороны.

**Шесть наших имён приняты добавлением** (`text.prefix_trim`, `text.min_len`,
`ini.first_section_fold`, вложенные `[]` у `json.array_elem_any_keys`,
`when{lt,gt}`, `unknown_key.ignore`), **шесть совпали независимо**
(`json.type_of`, `on_len_gt`, `on_no_match`+`drop_node`,
`default_when{absent}`, `$host`, `on_item_invalid`), **четыре сведены к
именам лаунчера** — их и правит эта волна:

| Было у нас | Стало | Причина отклонения |
|---|---|---|
| `json.any/all/not` внутри `json` | композиция уровня `detect` | дубль: иначе `json`/`ini`/`text` заводят по своей копии трёх операторов |
| `type: duration_seconds` | `normalize: duration_bare_seconds` | дубль: разница только в месте объявления, а две дороги к одному результату расходятся на первой же схеме |
| `label.fallback.scheme` | `label.fallback.scheme_source` | дубль: «объявить написание данными» и есть `scheme_source: as_written` |
| неявное «одинокий userinfo → первое имя `into`» | явный `single_into` | неявность даёт неверный ответ там, где конвенция другая: у `naive` одиночный userinfo — ПАРОЛЬ, то есть второе имя |

Уровень документа (`documents.json`) лаунчер **принял за основу** и вернул
шесть правок: имена на FROZEN (`id`→`kind`, `has_key`→`required_keys`,
`reunwrap`→`redetect`, `element_kind`→`mapper`, `yields`→`elements`,
`amnezia_vpn_link`→`amnezia_vpn`), `json.not` → композиция `detect`, снятие
`contains "[Peer]"` у `wireguard_conf` (**правда наша**: у заготовки без пира
`[Peer]` отсутствует законно), удаление ветки `clash_yaml`, `desc_en`/`desc_ru`
всем веткам.

### Что удержано оверлеем, а не переименовано

- **`defaults.server_port` у xray-секций — расхождение сторон, не дефект.**
  У лаунчера дефолта нет и элемент без порта отбраковывается целиком; у нас
  даёт узел, как было. Это состав подписки, а не грамматика, и молча принять
  чужое поведение не может ни одна сторона. Оверлей помечен полем
  `_divergence` со ссылкой на §24.27 и снимается только решением владельца.
- **Умолчание «первое имя `into`» в движке СНЯТО БЫТЬ НЕ МОГЛО.** Черновики
  волны объявляют `single_into` явно, но живой реестр (`assets/contract`,
  зеркало лаунчера) проставляет его только там, где поле не первое, — у
  четырёх секций (`shadowsocks`, `socks`, `ssh`, `vmess`) двухимённый `into`
  полагается ровно на это умолчание. Снятие обнулило бы их первое поле,
  то есть identity живых узлов, правкой в чужом зеркале. Умолчание уходит
  вместе с синком реестра, где `single_into` проставлен всем; судья —
  `before_480_identity_snapshot_test.dart`, который этот откат и поймал.
- **`alpn` с Xray-входа** остаётся `maps_to: null` у обеих сторон: лаунчер
  подтвердил, что ALPN оттуда не читается ни общей веткой TLS, ни REALITY
  (исключение — hysteria, где чтение уже есть). Включение — отдельной дельтой.
- **Ветка `clash_yaml` убрана из реестра, но форма ответа сохранена.**
  У лаунчера её заменяет `on_unrecognized`, который наш движок ещё не
  исполняет; чтобы «ноль узлов» не подменился на «список ссылок из одной
  строки JSON», опознаваемый JSON без своей ветки разбирается прежним
  рукописным порядком. Ветка вернётся снятием заплаты, когда
  `on_unrecognized` заработает.

### Сведение №2 (GRAMMAR_SYNC 8602a857, §5–§9 и PRIMITIVES §0.13)

Вторая волна свела примитивы нашей W4. Норма §6.0 («маппер переносит,
санитайзер судит; исключение — структурный отказ») принята: проверка при
заведении правила — «если это убрать, тело построится?». Построится —
правило принадлежит `body.fields`.

- **`range_order` в маппере — отклонён как дубль, и это верно.** Правило
  судит ЗНАЧЕНИЕ, тело строится и без него, а у нас `normalize: range_order`
  уже живёт в `body.fields` реестра. Снятие из секций — за агентом
  wireguard/INI, чей файл это (`uri/wireguard.json`, 10 записей
  `range_order:swap|strict`); судья — его же кейсы W4.
- **`cidr_prefix` и `base64_std` остаются пока в маппере** с пометкой
  `_awaitingContractSync`: лаунчер переносит их в `body.fields` отдельным
  контрактом, и до его прихода снятие оставило бы поля без нормализации
  вовсе. У `base64_std` перенос вдобавок двигает identity живых узлов
  (канонизация ключа меняет тело) — обязательна строка `DELTAS.md`.
- **`prepend_group` — живой случай у нас ЕСТЬ**, имя закрепляет не
  частность: секция `uri/hysteria2.json`, запись `$multiport`, член
  `into.spec` (`prepend_group: "first"`). Одно значение источника
  (`port_raw`) читается ДВАЖДЫ в разной нарезке: первый порт едет числом в
  `server_port`, а вся спецификация вместе с ним — списком диапазонов в
  `server_ports`. Пример-ссылка — фикстура
  `hysteria2/mport_authority_comma_recovery`:
  `hysteria2://pass123@example-1.com:443,20000-30000/?insecure=1#hop`.
  `merge: prepend` его не заменяет: тот работает на одном пути, а здесь
  склеиваются две группы ОДНОЙ регулярки до записи в тело.

#### Несогласие: `kind_when` к `when` + `sets` не сводится

Лаунчер отклонил `kind_when` как третью дорогу к результату, который даёт
присваивание селектора. **У нас это не так, и кейсы корпуса это показывают.**

`sets` пишет ПУТИ ТЕЛА (`_applySets` → `_write`). `kind_when` не пишет тело
вовсе: он отвечает именем РОДА, которое читается снаружи маппера
(`uri_pipeline.dart:368`) и включает потолок MTU с кодом
`awg_mtu_clamped` из реестра. Ни рода, ни кода `sets` произвести не может.

Подменить его правилом реестра тоже нельзя, и по той же причине, по которой
`kind_when` заведён: `body.fields.mtu.max_when.when.any_set` судит ТЕЛО, а
у двух кейсов корпуса в теле не осталось ни одного AWG-поля —
`awg_bad_numeric_skipped` (`jc=not-a-number` + одинокий `jmin`) и
`awg_jc_invalid_dropped` (`jc=abc` + `jmin=50`). Оба значения негодны и
сняты общим правилом поля, тело такого узла от обычного WireGuard
неотличимо, и снимок ждёт у обоих `mtu: 1280`. Условие обязано смотреть на
ВХОД (`query.jc`), а не на тело: узел ПОПРОСИЛ AmneziaWG, и потолок — это
свойство запрошенного протокола, без которого туннель поднимается, но
данные по нему не идут.

Вывод для сведения: `kind_when` и `when`+`sets` отвечают на разные вопросы —
«каким родом объявил себя ВХОД» против «что записать в тело». Сводить их
можно будет, когда у присваиваний появится адресат вне тела; сегодня
отклонение снесло бы два зелёных кейса снимка. Переформулировка не сделана
намеренно — отчёт с фактами ушёл лаунчеру.

## 7d. Что вышло: INI и обход элементов

Два блока в `develop`: вход `.conf` на движке и обход элементов документа
от реестра. Оба закрывают долги раздела «Что осталось» волны W5–W6.

### INI/`.conf` на движке

**Третий вход движка** рядом с лексером ссылки и объектным входом:
`engine/ini_space.dart` раскладывает текст в пространство `ini.<Section>.<Key>`
по диалекту, который объявила САМА СЕКЦИЯ (`ini_dialect`, §0.11 DRAFT), а не
по правилам, зашитым в адаптер. «Как принято в wg-quick» — это один диалект
из нескольких возможных, и второй (панельный `.ini`, `.ovpn`) потребовал бы
ветки в коде, будь первый умолчанием движка.

`mappers/wireguard_mapper.dart` **удалён целиком**: `mapWireguardIni`,
`_splitEndpoint`, `_mapWireguardParams`, `_cidrList`, `_reserved`. Из
`ini_parser.dart` снят `peerCommentName` — цепочка имени (комментарий под
`[Peer]` → подсказка вызывающего → `WireGuard`) объявлена `label.source`
секции. Тег И ЕСТЬ identity, и порядок звеньев обязан быть данными.

Примитивы — все общие, ни одного имени схемы в пакете движка:

| Примитив | Зачем |
|---|---|
| `detect.ini` (`sections` / `keys_any` / `keys_all`) | опознание формы по РАЗОБРАННОМУ пространству; тот же язык предикатов, что у текста и объекта (§2 НОРМЫ) |
| `on_no_match: {action: take_all, into, defaults}` у `extract` | регулярка не разложила значение, и объявленный ответ «взять целиком», а не потерять. G7: голый IPv6 в `Endpoint` (§219) |
| источник `hint` | имя, предложенное вызывающим: в документе его нет, но МЕСТО в цепочке метки остаётся данными |
| `ini_dialect` | `line_comment_prefixes` по GRAMMAR_SYNC §0.11; прежнее `comment_prefixes` читается тоже — секция приедет реестром с новым именем, а черновик несёт старое, и разъехаться они не должны молча |

Две правки формы по ходу: звено цепочки метки считается ответившим по
ПОСЛЕ-нормализационному значению (пробельная подсказка больше не занимает
место в цепочке и не глушит следующие звенья); `withParams` перестал терять
`kind_when` при вмонтировании `include` — до правки род узла, объявленный
входом, пропадал у любой секции с `include`.

**Дельт нет.** 27 INI-кейсов снимка `wireguard/pipeline_identity_before.json`
сходятся байт в байт, включая голый IPv6 адресом целиком, чтение только
первой `[Peer]` и тишину `Interface.DNS`.

Коды `wgconf_dns_ignored` и `wgconf_extra_peer_dropped` объявлены секцией
ВПЕРЁД своего текста: в `warnings.json` контракта их нет. Ставить их значило
бы показать человеку предупреждение с ПУСТЫМ текстом там, где сегодня
законная тишина, а дельты на это нет. Имена лежат под `$code_pending` —
вернуть их будет правкой одного ключа, когда текст приедет синком. Сами
записи при этом обязаны остаться: без записи `dns` уехал бы в
`uri_param_unknown`.

### Обход элементов документа

`elements` реестра читал только линтер: опознание ДОКУМЕНТА было объявлено
данными волной W6, а путь к его ЭЛЕМЕНТАМ оставался `switch (flavor)` в
`parse_all` — второй копией того же знания. Теперь путь исполняет движок
(`DocumentRegistry.groupsFor`), а ветка документа едет в `JsonConfig.source`
целиком.

Снято рукописного: четыре ветки `switch (j.flavor)` для sing-box — «массив
конфигов», «массив outbound'ов», «одиночный», «полный конфиг». Это были
четыре способа добраться до элементов ОДНОГО диалекта, и все четыре
выражаются строкой `elements`. Сборка документа Xray (порядок §321, дедуп
§404, владение именем §342) вынесена в `_parseXrayDocument` без правок:
способ ДОБРАТЬСЯ до элементов называет реестр, а что с ними делать
дальше — принадлежит сборке документа и остаётся кодом.

Результат обхода — ГРУППЫ, а не плоский список: границы конфига несут смысл
для дедупа и владения именем, и схлопни обход их в один список, узлы разных
конфигов начали бы вытеснять друг друга.

**`JsonFlavor` НЕ снят намеренно.** Его читают превью вставки из буфера
(`clipboard_analysis.dart`) и контроллер подписок, то есть UI, а UI эта
задача не трогает. Он остался публичной формой и запасным путём для
документа, опознанного БЕЗ реестра: опознание документа, в отличие от
разбора узла, обязано работать и без реестра — на нём стоит вся вставка из
буфера, и молчаливый отказ выглядел бы как «подписка пустая».

### Трасса на объектном и текстовом входе

Первая строка трассы (`elem_detect` — какая секция и какая форма взяли
элемент) пишется в `execute()`, то есть в ОДНОМ месте на все три входа:
ссылка, объект и текст INI сходятся там, и строка «что опознано» обязана
быть у всех трёх одинаковой — иначе механическая сверка Go↔Dart ловила бы
ложное расхождение на самом первом событии. Прежде трасса снималась только
на ссылке, и вход, который её не пишет, из сверки просто выпадал.

### Что осталось после блока

- **Строка `elements` разбирается по форме, а не по полному пути.**
  `[].outbounds[]` и `outbounds[]+endpoints[]` дают одинаковые группы:
  ХВОСТ пути проходит сборка документа (`parseSingboxConfigs` сама читает
  `outbounds` и `endpoints`). Пока обе стороны пишут ровно эти две формы,
  разницы нет; третья форма пути потребует разбора хвоста движком.
- **Диалекты форков в `params` секций `singbox`** — как было, за границей
  волны (правка читателя тела).

## 8. Риски

- **Секция реестра пишется у лаунчера по Go-поведению.** Там, где Dart
  сегодня ведёт себя иначе, выбирает `DELTAS.md`, а не молчаливый перенос.
  Фикстуры W0 — единственное, что отличает «починили» от «сломали».
- **`toUri()` — форма хранения ручного узла.** Смена вида ссылки перезапишет
  `rawSource` при пересохранении. Identity (тег) не двигается; критерий 5.2
  обязателен до W7.
- **Реестр становится обязательным в рантайме разбора.** Сегодня часть путей
  работает и без него (`kAwgMtuFallback`); после W8 — нет.

### Новое в движке (примитивы контракта)

- **`scheme_sets` с ключом `"*"`** — присваивания, общие для всех написаний
  схемы. У QUIC-схем TLS включён всегда, параметра `security` в ссылке нет, и
  выразить это записью нечем. Общий набор кладётся ПЕРВЫМ, конкретное
  написание вправе его переопределить.
- **`params.<ключ>: null`** — ключ объявлен, но телом не становится. При
  `unknown_key.action: keep` отсутствующая запись дала бы повод коду
  `uri_param_unknown`, объявленная — нет: потеря осознанная.
- **Область `authority` раскрывается ДО лексера.** base64 законно несёт `?`

  оболочка накрывает весь пэйлоад, теряла все параметры.
- **`when.source_kind`** в `max_when`/`min_when`/`default_when`, оператором
  рядом с `any_set`. Операторы соединяются **ИЛИ**: `source_kind` знает род от
  входа и работает там, где в теле не осталось ни одного опорного ключа;
  `any_set` судит тело и остаётся навсегда, потому что у входа в собственной
  форме ядра рода от входа нет вовсе.
- **`body.relations` kind `cooccurrence`** с оператором `$range_width` —
  цена СОЧЕТАНИЯ настроек, ни одна из которых не битая. Дедуп по `code`+путь.

## 10. Что вышло: синк 1.1.26

Источник — `develop` лаунчера `a0c403ab` («dialer#uri у vless/trojan +
duration_bare_seconds переехал в тело»), зеркало реестра 1.1.22 → **1.1.26**.

### wireguard переехал на секцию реестра

Секции `mappers.uri` и `mappers.conf` приехали реестром ИСПОЛНЯЕМЫМИ и стали
основой. Наши полные черновики заменены **оверлеями** (`_overlay: true`) с
`_why` у каждого ключа.

Грабля, которую этот переезд вскрыл: черновик БЕЗ `_overlay` замещает
реестровую секцию ЦЕЛИКОМ. Секция реестра объявляет `emit: null` (обратного
хода у лаунчера нет вовсе — share-URI собирает только LxBox), и после синка
`toUri()` у wireguard падал `StateError` на каждом узле. Полная копия секции
при исполняемой реестровой запрещена не из чистоплотности: она молча
проигрывает реестру и перестаёт исполняться.

| Секция | Отличие | Почему |
|---|---|---|
| `uri` | `emit` целиком наш | реестр несёт `emit: null` |
| `conf` | `ini_dialect` | секция реестра диалект INI НЕ объявляет: у Go правила чтения зашиты в ридер. Передано лаунчеру — диалект свойство ФОРМАТА, а не реализации; держится под `_awaitingContractSync` |
| `conf` | `label.fallback` — литерал `WireGuard` | реестр уводит фолбэк в шаблон `{scheme}-{server}-{server_port}`. Цепочка ЗВЕНЬЕВ при этом реестровая буква в букву, включая `hint` (у нас он живой — `nameHint`) и хост `peers[].address` |
| `conf` | `unknown_key: drop` | тело собирается для ЯДРА: незнакомый ключ роняет запуск целиком, а `.conf` человек приносит руками из чужой панели |
| `conf` | `defaults.peers[].port` | `.conf` законно несёт `Endpoint` без порта; у лаунчера такой элемент отбраковывается |

Снято: оверлей `include` у `uri/trojan` и `uri/vless` — контракт 1.1.26 сам
подключил им `dialer#uri` (D133-26), дельта закрыта В НАШУ СТОРОНУ.

### Дефекты, найденные переездом

- **`format: base64_32` и `normalize: base64_std` судили ключ СТРОГИМ
  декодером.** Ядро (Go `encoding/base64`) принимает неканоническую последнюю
  группу: `…ccC=` и `…ccA=` — одни и те же 32 байта (D-030). Законный ключ
  падал с `wg_key_invalid`, и корпус `uri_psk_keepalive` (ключи в query)
  переставал разбираться ЦЕЛИКОМ. Оба выражения переведены на ленивый декодер,
  которым ключ судил парсер ссылки; у декодера появилось публичное имя.
- **Границы `min`/`max` у `int_array` не проверялись вовсе** — ветка списка
  смотрела только `len` и возвращалась. `reserved=1,2,999` уезжал в ядро.
  Границы относятся к ЭЛЕМЕНТУ: длину задаёт `len`, второго смысла у них нет.
- **Служебный `_why` ВНУТРИ `defaults`** доезжал до узла полем (`unknown_key`
  с путём `_why`): у этого ключа каждый ключ — путь тела. Причина выносится
  отдельным ключом секции (`_why_defaults`).

### Снято с нашей стороны

- умолчание **«одинокий userinfo → первое имя `into`»**: контракт 1.1.25
  проставил `single_into` всем 14 секциям с `userinfo`, включая те, где оно
  совпадает с `into[0]`, и завёл линтер. Догадка стирала разницу между
  «совпало» и «никто не смотрел»;
- `$code_pending` у **`wgconf_dns_ignored`**: корпус этой версии кода ЖДЁТ
  (`wgconf/ini_basic.expected.json` несёт его единственным warning).
  `wgconf_extra_peer_dropped` остаётся отложенным — корпусного кейса у него
  по-прежнему нет вовсе.

### Эмит AWG

Написание схемы возвращено к сегодняшнему виду: узел С awg-полями уезжает
`wireguard://…?jc=…`, как ждёт `emit_before480.json` (все 65 кейсов, включая
24 awg-именованных). Исключение вида ссылки из стража снято.

Написание `awg://` остаётся за узлом «род awg, ни одного awg-поля в теле», и
выразить его сегодня НЕЧЕМ: рода в каноническом теле нет, а вход эмита —
тело. Обе ветки `any_set` дают одно написание намеренно, чтобы перечень
awg-путей остался на виду.

### Тесты, которые шли БЕЗ реестра

`amnezia_link_test`, `wireguard_edge_test` грузили только черновики. Пока
черновик был полной копией секции, это работало; с оверлеем накладывать
стало не на что, и продакшен-путь `vpn://` → wireguard не давал НИ ОДНОГО
узла. Добавлена загрузка реестра рядом с черновиками.

Golden-судьи хранения: `*.config.json` совпадают БАЙТ В БАЙТ — тела и
identity сохранённых узлов не сдвинулись. Разошёлся только список
предупреждений, где прибавилась одна строка про DNS из `.conf`.

## 11. Что вышло: синк 1.1.28, корпус

Источник — `develop` лаунчера `b57625ea` («снят рукописный конвертер Xray»),
зеркало реестра 1.1.26 → **1.1.28**. Главное этого синка не в новых полях, а
в том, что корпус контракта впервые прогнан ЦЕЛИКОМ: в чистом worktree
`app/contract/` нет (каталог gitignored), и 130 тестов корпуса молча
скипались. После синка их 1165, и красное в них — не регрессия синка, а
то, чего раньше никто не смотрел.

### Носитель наложенного слоя не считался объявленным

Настоящая регрессия движка, найденная корпусом. `overlays[]` называет
параметр-НОСИТЕЛЬ своим `source` (`query.extra`), а записи читают слой под
его именем (`extra.mode`). Набор «объявленных» собирался только из `source`
записей, и плоского `query.extra` там не было ни у кого: носитель уезжал в
`uri_param_unknown`. Шесть кейсов `vless/xhttp_extra_*`, включая тот, где
слой битый и записей не даёт вовсе — там код был единственным содержимым
конверта.

### Q133-54: зеркальные записи оверлеев

Норма MAPPER_ENGINE §7.1: запись БЛОКА изымается из плана только когда
одноимённая запись секции несёт ТОТ ЖЕ полный набор `source`. Наши оверлеи
держали копии реестровых записей, и этому условию они не отвечали —
вставали РЯДОМ с реестровой и решали спор за путь своим `priority`.

| Запись | Было | Чем кончилось |
|---|---|---|
| `ws.ed` | `priority: -1` против реестровых 5 | плоская пара `?ed=` била хвост пути |
| `ws.eh` | `priority: 0` против 30 | то же |
| `xhttp.path` | без `extract` | терялось срезание `?`-хвоста (SPEC 002 §4.1) |
| `$selector`, `httpupgrade`, `grpc`, весь `xhttp` вида xray | своё написание `source` | состав полей выходил смешанный — 16 кейсов `xhttp_test` |

Сняты все, кроме `ws.ed`: у неё есть НАСТОЯЩЕЕ отличие — реестр подставляет
`Sec-WebSocket-Protocol` через `implies`, мы нет (D-008, зафиксировано парой
override'ов корпуса). Запись приведена к реестровым `priority` и набору
`source`, то есть теперь переопределяет по норме, а не спорит.

### Снято с нашей стороны

- `xray/hysteria2` черновик ЦЕЛИКОМ: контракт привёз ДВЕ секции со
  взаимоисключающими `detect` по версии (TASKS_LXBOX §26), обе исполняемы.
  Наш черновик ронял версию 1 кодом `protocol_unsupported`, у реестра она
  становится живым узлом рода `hysteria` — дельта односторонняя, принята
  лаунчером. Полная копия при исполняемой секции реестра молча ей
  проигрывает и перестаёт исполняться (та же грабля, что у wireguard в
  1.1.26).
- ожидание «hysteria2 из Xray не получает `tls_not_applicable_quic`»:
  правило реестра (`tls.json`, `body.fields.utls.forbidden_for`) снимает
  блок САНИТАЙЗЕРОМ и одинаково на трёх входах. Прежняя рукописная ветка
  молчала не по правилу, а потому что эмитить отпечаток было некому.

### Дефект, найденный переездом и НЕ закрытый

Обратный ход выводит ключ контейнера v2rayN из таблицы и берёт ПЕРВЫЙ
источник записи. У записи с ФОЛБЭКОМ источников канон и написание
контейнера расходятся: `grpc.serviceName` читает `serviceName` ∥
`service_name` ∥ `path`, каноном зовётся по первому, а контейнер знает
только `path`. Пока ключ `path` держала наша зеркальная запись `http.path`,
это не стреляло; с её снятием grpc-узел уезжает в ссылку ключом, которого
чужой клиент не читает, и теряет `service_name` на круге
(`vmess_pipeline_invariants`, кейс «VMess gRPC»).

Оверлеем это НЕ лечится: перестановка цепочки в нашей записи набор `source`
меняет, и по §7.1 реестровая запись не изымается — обе остаются в плане.
Лечение — выбирать написание ПО ФОРМЕ: у формы-контейнера и формы-ссылки
написания законно разные, и сегодня ни таблица, ни движок этого различия не
выражают. Вопрос о норме вывода ключа передаётся лаунчеру; до ответа кейс
держится красным, а не заклеивается.

### Красное, что осталось корпусу

`direction_corpus` чинился не секцией, а загрузкой: раннер строит узлы кейса
`parseUri`-ссылкой, а схема на движке без реестра не разбирается вовсе — 19
кейсов падали пустым составом группы, то есть жаловались на модель
Направления, к которой отношения не имели.

Остальное — РАСХОЖДЕНИЯ СТОРОН, поведение по ним не менялось. Общая их
черта: per-app override корпуса завести с нашей стороны НЕЛЬЗЯ, потому что
`<case>.expected.lxbox.json` лежит в корпусе ЛАУНЧЕРА и приезжает синком, а
`app/contract/` у нас gitignored. Заводить их обязана вторая сторона, и
список передаётся ей:

| Кейс | Расхождение |
|---|---|
| `naive/unknown_query_ignored` | у нас `uri_param_unknown` на КАЖДЫЙ ключ с путём, у лаунчера один код без пути |
| `trojan/echfq_not_read`, `vless/reality_tcp_no_flow` | тот же код на `echfq`/`spx`; у лаунчера `unknown_key` на JSON-входе не исполняется вовсе (§25 п. 6) |
| `naive/empty_host_rejected` | `parse_error` против `emit_error`+`field_missing` |
| `wireguard/reserved_*` | в `value` у нас негодный ЭЛЕМЕНТ (`999`), у лаунчера вся тройка (`[1 2 999]`) |
| `wireguard/amnezia_vpn_awg*` | порядок `warnings[]`: наш `wgconf_dns_ignored` несёт `path: dns`, чужой — без пути, и `body.order` разводит их по-разному |
| `hysteria/*` (8) | схема объявлена расширением чужой стороны, каталог скипается целиком |

Три кейса `contract_24_2_rules` (`hellorandom*` → `randomized` вместо
`random`, пустой пароль tuic, алиас `splithttp`) тем же синком стали ВИДНЫ:
тест гейтится наличием `contract/registry`, то есть до появления корпуса
скипался целиком. Разбираться с ними отдельно — они не о 1.1.28.
