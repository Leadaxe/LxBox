## Назначение

От DNS-секции конфига зависят приватность (видит ли провайдер запросы),
доступность (жив ли сервер) и правильность маршрута (на какой IP уйдёт
российский сайт). Фича даёт управлять ею без ручного JSON: каталог серверов
с выбором канала, свои серверы любых типов ядра, DNS-правила, стратегия,
группы с резервированием, FakeIP, кэш.

Принцип, который фича защищает: **конфиг, собранный из DNS-настроек, либо
принимается ядром, либо не собирается вовсе — с понятной причиной.**
Второй — **fail-closed**: сервер выпал из-за канала — его домены получают
отказ, а не утекают в прямой резолвер.

Из коробки DNS работает без настройки: `dns.final` и резолвер ядра —
группа `dns_shield` (гонка шифрованных провайдеров), российские домены
(при включённом по умолчанию пресете `ru-direct`) — своя группа `dns_ru`.

## Обещания

- **P1. Шаблонный сервер резолвится с переменными; прямой канал — без `detour`.**
  Значение пользователя из записи сервера, иначе `default_value`; пустое —
  ключ выпадает. `detour` = `direct-out` или пусто → ключ не пишется.
  Свидетель: юнит «kind:template → server.tag, дефолты vars, direct-out стёрт».
  Мутация: `detour: "direct-out"` попадает в конфиг.
- **P2. Fail-closed по каналу.** Сервер, чей `detour` указывает на тег,
  которого нет в конфиге, не эмитится; DNS-правила на него становятся
  `action: reject`; `dns.final` на него снимается и последним правилом
  встаёт `{"action":"reject"}`; резолверы (`route.default_domain_resolver`,
  `domain_resolver` узлов и серверов) переключаются на умолчание шаблона.
  Выбор пользователя в хранении не трогается. Свидетель: юниты «detour на
  исчезнувшее Направление → сервер не эмитится, warning», «правила → reject,
  final снят + заглушка reject, резолверы — умолчание шаблона». Мутация:
  снять только ключ `detour`, оставив сервер (запросы пойдут напрямую).
- **P3. Сервер, на который опирается активный пресет или правило, не
  выключается.** Он попадает в `dns.servers` при любом положении
  переключателя; в UI переключатель заблокирован во «вкл», удаление скрыто,
  видна пометка «used by …». Свидетель: юниты «lifecycle (locked №7):
  выключенный сервер, реферимый правилом — force-include в dns.servers»,
  «locked (used by preset): editor видит lock и label». Мутация: фильтр
  по `enabled` без исключения для ссылаемых.
- **P4. Выключенный пресет не оставляет DNS-хвостов.** Пресет с выключенной
  маршрутизацией не даёт ни серверов, ни DNS-правил, ни замков. Свидетель:
  юнит «§121 routing = король: route disabled подавляет DNS-аспект целиком».
  Мутация: DNS-аспект пресета читается независимо от его включения.
- **P5. Недоступный член группы выпадает с предупреждением, пустая группа
  блокирует сборку.** Выключенный / неизвестный / сам себя / повтор —
  выкидывается из эмиссии со своей причиной, хранение не меняется.
  Пустая после фильтра группа не чинится молча → fatal до старта ядра;
  исключение — группа, опустевшая из-за P2, выпадает сама (и лечится как
  сервер). Свидетель: юниты «disabled-член выкидывается с warning»,
  «пустая группа → EmptyDnsGroup (fatal)», «группа, опустевшая от висячего
  detour, выпадает вместе с объемлющей». Мутация: пустую группу выбрасывать
  молча.
- **P6. Запреты ядра ловятся до старта.** `fakeip`/`hosts` под `dns.final`,
  `route.default_domain_resolver` или членом группы; цикл групп — fatal
  сборки. `detour` у группы и у `tailscale` снимается при сборке. Свидетель:
  юниты «dns.final = fakeip → fatal», «член fakeip/hosts →
  BadDnsGroupMember», «цикл групп → DnsGroupCycle, один на кольцо», «§319
  detour у группы вычищается из эмиссии». Мутация: пропустить `detour` у
  группы — ядро падает на лишнем ключе.
- **P7. Исчезнувший резолвер лечится сборкой.** `dns.final` /
  `route.default_domain_resolver` на сервер, которого нет в собранном
  списке, заменяются умолчанием шаблона (или первым пригодным не
  `fakeip`/`hosts`) и замена сохраняется. Свидетель: юнит «битые обе ссылки
  → дефолты шаблона, var-имена для персиста». Мутация: оставить битую
  ссылку — вечная плашка «Settings changed» с fatal.
- **P8. Умолчания — из шаблона, одно место.** На чистой установке экран и
  сборка показывают/собирают одно и то же: Final и Default Domain Resolver
  — `dns_shield`, Strategy — `ipv4_only`. Свидетель: юнит «чистая установка —
  Final/Resolver/Strategy = default_value шаблона». Мутация: литерал-дефолт
  на экране, отличный от шаблона.
- **P9. Порядок DNS-правил — порядок пользователя; зеркала правил
  маршрутизации — атомарная группа.** Итоговый `dns.rules` повторяет
  порядок списка; DNS-зеркала пресетов и правил идут одной группой в
  порядке маршрутизации; зеркало на пропавший сервер тихо не эмитится.
  Свидетель: юниты «linear order: storage порядок == финальный dns.rules
  порядок», «порядок группы = порядок routing-правил (preset + rule)»,
  «пропавший сервер → DNS-rule тихо не эмитится (решение №3)». Мутация:
  сортировка правил по виду.
- **P10. Переименование сервера не рвёт ссылки.** Новый тег каскадно
  переписывается в `domain_resolver` других серверов, переменных-серверах,
  DNS-правилах, `dns.final`, резолвере и DNS-опциях правил маршрутизации.
  Свидетель: юнит «каскад: domain_resolver, dns_servers-vars, §061-правила,
  resolvers». Мутация: rename без каскада.
- **P11. Устаревший `strategy` в DNS-правилах не роняет старт.** Если в
  конфиге есть `query_type` или `ip_version` (FakeIP, Force IPv4),
  `strategy` снимается со всех DNS-правил. Свидетель: юнит «strategy +
  query_type в конфиге (FakeIP) → strategy снят». Мутация: не снимать —
  fatal ядра 1.14.
- **P12. FakeIP выключает резолв назначения.** Включение пресета FakeIP с
  включённым DNS ставит `resolve_enabled=false`; выключение — возвращает.
  Свидетель: юниты «FakeIP enabled + dns_enable(default true) →
  resolve_enabled=false», «FakeIP disabled → resolve_enabled=true».
  Мутация: FakeIP с реальным резолвом назначения.
- **P13. Кэш: вне границ не сохраняется.** Размер кэша 1024..65535; ввод
  вне границ показывает ошибку и не попадает ни в хранение, ни в конфиг
  (действует 4000). Свидетель: юнит «вне границ ($bad) не попадает в конфиг
  — действует 4000», виджет-тест «размер: в границах сохраняется, вне
  границ — нет». Мутация: сохранение любого числа.
- **P14. Сброс кэша DNS.** «Clear DNS cache» удаляет `cache.db` целиком
  (FakeIP-выдачи, записи DNS); при поднятом туннеле ядро перезагружается.
  Свидетель: ручная проверка — туннель поднят, Clear → снекбар «DNS cache
  cleared — reloading», FakeIP-адреса выдаются заново. Автотеста нет, на
  устройстве не подтверждено (§263). Мутация: удалять только FakeIP-часть.
- **P15. Живое состояние групп — снимок на открытии экрана.** При поднятом
  туннеле под группой видна текущая цель и по членам ✓/✗, RTT, ошибки;
  ядро без метода или туннель вниз — строки нет, экран не ломается.
  Свидетель: юнит «пустой/битый map не роняет» (маппинг); отображение —
  ручная проверка. Мутация: таймерный опрос.
- **P16. `dns_shield` — только шифрованные члены, все объявлены** в базовом
  списке серверов. Свидетель: юниты «§527 каждый член dns_shield объявлен
  в БАЗОВЫХ dns_options.servers», «в группе fastest пресета dns_shield нет
  открытых udp-серверов». Мутация: член группы, которого нет в списке.
- **P17. Российские домены — через группу из трёх независимых путей.**
  `ru-direct` даёт `dns_ru` (`fastest`) над UDP через канал пресета, DoT
  через `vpn-1` и DoH напрямую; при Force IPv4 AAAA для ru-доменов
  глушится. Свидетель: юниты «ru-direct (дефолты) → dns_ru + три члена по
  разным путям», «ru-direct: force_ipv4=false → route без resolve, DNS без
  AAAA-гейта». Мутация: один сервер через канал пресета.

## Контролируемые параметры

| Настройка (экран DNS) | Значения | Умолчание | Ключ конфига ядра |
|---|---|---|---|
| Серверы: вкл/выкл, свои, переопределения | список | каталог шаблона (см. [серверы](FUNCTIONS/dns-servers.md)) | `dns.servers[]` |
| Strategy | `prefer_ipv4` · `prefer_ipv6` · `ipv4_only` · `ipv6_only` | `ipv4_only` | `dns.strategy` |
| DNS Final | тег включённого сервера, не `fakeip`/`hosts` | `dns_shield` | `dns.final` |
| Default Domain Resolver | то же | `dns_shield` | `route.default_domain_resolver` |
| DNS-правила | свои / шаблонные / пресетные / по rule-set | зеркала пресетов | `dns.rules[]` |
| DNS cache size | 1024..65535 | 4000 | `dns.cache_capacity` |
| Serve stale answers | вкл/выкл | вкл | `dns.optimistic` |
| Keep DNS cache after restart | вкл/выкл | вкл | `experimental.cache_file.store_dns` |
| Clear DNS cache | действие | — | удаляет `cache.db` |

Смежные ручки чужих фич: «Hijack DNS», «Resolve destination IP» (пресет
Traffic Processing, [004-ROUTING](../004-ROUTING/FEATURE.md)), DNS у
пресета (`dns_enable`) и у правила, тумблер IPv6 (переставляет Strategy).

Ключи серверов, которые фича отдаёт ядру: `type` (`local`, `udp`, `tcp`,
`tls`, `https`, `quic`, `h3`, `fakeip`, `group`, `tailscale`, …), `tag`,
`server`, `server_port`, `path`, `tls{server_name}`, `detour`,
`domain_resolver`; у группы — `servers`, `mode`
(`stable`/`fastest`/`parallel`), `error_ttl`, `win_ttl`; у FakeIP —
`inet4_range`, `inet6_range`; `experimental.cache_file.store_fakeip: true`.

## Входы / Выходы

**Входы:** DNS-секция шаблона (серверы-обёртки с переменными, пресеты с
`dns_servers`/`dns_rules`); записи пользователя (серверы по видам, правила,
переменные); правила маршрутизации с DNS-опцией; список активных
Направлений и узлов (для `detour`, `endpoint` Tailscale); снимок групп от
ядра (`getDNSGroups`).

**Выходы:** ключи из таблицы выше; предупреждения сборки (снекбар и
журнал); fatal-причины проверки перед стартом; живые строки групп на экране.

## Data flow

```
шаблон (серверы, пресеты)   записи пользователя   правила маршрутизации
          │                        │                       │
          ▼                        ▼                       ▼
  ДОСБОР СПИСКОВ: новые серверы/правила шаблона и активных пресетов
  дописываются, сироты (исчезнувший пресет/шаблон) убираются, своё — цело
          ▼
  ТЕЛА СЕРВЕРОВ: подстановка переменных → снятие служебных полей →
  фильтр выключенных (кроме ссылаемых, P3) → detour: direct-out снят,
  висячий → сервер выпал (P2) → Tailscale без endpoint выпал →
  фильтр членов групп по эмитированным (P5)
          ▼
  ПРАВИЛА: список пользователя по порядку, зеркала — атомарной группой (P9);
  srs-правило без скачанного файла — пропуск
          ▼
  ЛЕЧЕНИЕ: правила/final/резолверы на выпавшие → reject/замена (P2);
  битые резолверы → умолчание шаблона (P7); legacy strategy (P11)
          ▼
  ПРОВЕРКА ПЕРЕД СТАРТОМ: висячие final/resolver, fakeip/hosts,
  пустые группы, циклы (P5, P6) ── fatal → конфиг не собран
          ▼
  конфиг ядра  ──►  ядро  ──►  getDNSGroups (снимок на экране, P15)
```

## Правила и гарантии

- Виды сервера: **шаблонный** (из каталога, правятся только переменные и
  описание), **пресетный** (из активного пресета, только чтение, параметры —
  в правиле пресета), **свой** (любое тело). Свой с тегом шаблонного или
  пресетного — **переопределение** («Overridden»), его можно сбросить к
  исходному.
- Тег — единственный идентификатор сервера (повтор — побеждает первый);
  теги серверов пресета — в его пространстве (`ru-direct:dns_ru`).
- `detour` — только из активных Направлений; пропавший канал в хранении
  остаётся (вернётся канал — вернётся сервер).
- Пикеры Final/Resolver не предлагают `fakeip`/`hosts`; члены группы — тоже.
- DNS-опция правила ссылается на сервер по тегу; правило его detour не
  трогает.
- Изменения на экране помечают конфиг к пересборке; запись на диск —
  отложенная, при уходе с экрана.

## Границы

- Общая сборка конфига, язык шаблона, переменные и плашка «Settings
  changed» — [003-CONFIG_BUILD](../003-CONFIG_BUILD/FEATURE.md).
- Правила маршрутизации, пресеты как таковые, Hijack DNS, «Resolve
  destination IP», DNS-опция в редакторе правила —
  [004-ROUTING](../004-ROUTING/FEATURE.md); здесь — только их DNS-след.
- Поток DNS-запросов ядра (`subscribeDNSQueries`), трасса групп в
  профайлере, детектор «DNS массово падает при живой связи» —
  [012-LIVE_STATE](../012-LIVE_STATE/FEATURE.md) и
  [013-DIAGNOSTICS](../013-DIAGNOSTICS/FEATURE.md); Debug API
  `/settings/dns_options/*` — там же.
- Перенос DNS-записей в резервной копии и слияние — [017-BACKUP_AND_STORAGE](../017-BACKUP_AND_STORAGE/FEATURE.md).
- Узлы Tailscale и их пресет — не здесь; фича лишь даёт тип сервера
  `tailscale` в форме.
- Региональных DNS-наборов нет: `ru-direct` включён по умолчанию для всех,
  регион использования на DNS не влияет.
- Разовой кнопки «протестировать DNS-серверы» нет и не будет (§365).
- Удаление `cache.db` и перезагрузка ядра зависят от возможностей ОС.

## Особенности сопровождения

- Тег шаблонного сервера живёт внутри `server.tag` обёртки; поменять формат
  обёртки без сборки — все шаблонные серверы молча пропадут (§117 задача 1).
- Пустую группу нельзя «лечить» выбросом — пользователь не увидит, что
  выбор умер; выбрасывается только опустевшая из-за канала (P2).
- `detour` у группы и `tailscale` ядро считает лишним ключом и падает;
  чистится на сборке, а не только в форме, потому что старые записи его
  уже несут (§319).
- Правка SNI в форме заменяет весь `tls` (дефект §530); ссылка своего
  DNS-правила на удалённый сервер клиентом не проверяется.
