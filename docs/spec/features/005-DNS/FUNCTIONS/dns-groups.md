# DNS-группы

| Поле | Значение |
|------|----------|
| Фича | [005-DNS](../FEATURE.md) |
| Обещания | P5 P6 P15 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Объединяет несколько DNS-серверов под одним тегом, чтобы сбой одного не
ронял резолв. Группа ставится везде, где ждут тег сервера: в `dns.final`,
в резолвер ядра, в DNS-правило, в другую группу. Ядро само выбирает цель
по режиму; клиент собирает группу, отсекает недоступных членов и
показывает, кого ядро сейчас выбрало.

## Параметры

| Поле формы | Ключ ядра | Значения | Умолчание |
|---|---|---|---|
| Members | `servers` | теги серверов, ≥1, порядок не значим | — |
| Selection mode | `mode` | `stable` — держаться одного до сбоя · `fastest` — гонка, затем держаться победителя · `parallel` — гонка на каждый запрос | `stable` (ключ не пишется) |
| Error TTL | `error_ttl` | длительность `NNh NNm NNs` | ядра (`2m`), ключ не пишется |
| Win TTL (только при `fastest`) | `win_ttl` | то же | ядра (`5m`) |

Больше ключей у группы нет: `detour`, адрес, порт, `tls` форма снимает при
переходе в режим группы, сборка снимает `detour` в любом случае.

## Входы / Выходы

**Входы:** тело группы (форма или JSON), полный список эмитируемых
серверов, снимок `getDNSGroups` от ядра при открытии экрана.
**Выходы:** `dns.servers[]` с `type: group`; предупреждения о выброшенных
членах; fatal-причины «пустая группа», «недопустимый член», «цикл
групп»; строка живого состояния под группой.

## Правила и инварианты

- Пикер членов предлагает все серверы, кроме самой группы и `fakeip`/`hosts`;
  выключенный член выбирается, но помечен «disabled — will be skipped»;
  член, которого нет в списке, — «unknown server — will be skipped».
- Фильтр членов — после сборки всего списка (член ниже группы доступен).
  Причины выброса в предупреждении: `disabled`, `unknown`, `itself`,
  `duplicate`, `dangling detour`. Хранение не меняется: включил член — он
  вернулся.
- Группа, опустевшая после фильтра, эмитится пустой → fatal до старта ядра.
  Исключение: все живые члены выпали из-за висячего `detour` — группа
  выпадает сама (и объемлющие, опустевшие так же), ссылки на неё лечатся
  политикой отказа.
- Член `fakeip`/`hosts` (например, через JSON) — fatal; цикл групп (в т.ч.
  самовключение мимо формы) — fatal, один на кольцо; вложенная группа без
  кольца допустима.
- Неверная длительность — подсказка под полем, сохранение не блокируется,
  ключ просто не пишется.
- Смена режима не материализует умолчание: `stable` убирает ключ `mode`.
- В списке группа подписана `group · <mode> · <число членов>`.
- Живое состояние: только при поднятом туннеле, один запрос на открытие
  экрана, без таймера. Строка: `→ <текущая цель>`, по члену
  `tag ✓ 12ms` (у `fastest` — `wN` побед) или `tag ✗N (34s)`, `●` у
  текущего. Ядро без метода или ошибка — строки нет.

## Границы

- Поведение выбора цели (TTL-записи, режим выживания, амнистия при смене
  сети) — ядро, [sing-box-lx FEATURE 013-DNS_GROUP](https://github.com/Leadaxe/sing-box-lx/tree/lx/SPECS/FEATURES/013-DNS_GROUP).
- Трасса группового запроса (путь, пробы, веер) — в профайлере,
  [012-LIVE_STATE](../../012-LIVE_STATE/FEATURE.md).
- Отдельного Debug-endpoint'а состояния групп нет.
- Группы шаблона и пресетов (`dns_shield`, `dns_ru`) —
  [встроенные наборы](builtin-dns-sets.md).
