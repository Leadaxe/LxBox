# DNS-правила — какой сервер резолвит какие домены

DNS-правила отправляют отдельные запросы на отдельные серверы раньше `dns.final`; свои, шаблонные и
rule-set правила и зеркала правил маршрутизации образуют один упорядоченный список.

| Поле | Значение |
|------|----------|
| Фича | [005-DNS](../FEATURE.ru.md) |
| Обещания | P4 P9 P11 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Решает, каким сервером резолвить конкретный запрос — до `dns.final`.
Собирает `dns.rules` из четырёх источников в одном упорядоченном списке и
показывает DNS-след правил маршрутизации и пресетов отдельной группой, где
его можно выключить, не трогая маршрут.

## Параметры

| Вид | Откуда | Что можно |
|---|---|---|
| Своё правило | пользователь: имя + тело DNS-правила sing-box (JSON) | добавить, править, вкл/выкл, двигать, удалить (с подтверждением) |
| Шаблонное | `dns_options.rules` шаблона (`name`, `enabled_default`) | вкл/выкл, двигать |
| По rule-set (`.srs`) | запись из импорта / Debug API (UI не создаёт) | вкл/выкл, двигать |
| Зеркало пресета | `dns_rules` активного пресета | переключатель DNS пресета (`dns_enable`) |
| Зеркало правила маршрутизации | DNS-опция правила: сервер и/или Force IPv4 | переключатели DNS и Force IPv4 |

Сейчас шаблон своих DNS-правил не несёт (`rules: []`): всё, что не
сматчилось, уходит в `dns.final`.

## Входы / Выходы

**Входы:** записи правил, правила шаблона, `dns_rules` активных пресетов,
правила маршрутизации с DNS-опцией, пути скачанных `.srs`, список реально
эмитированных серверов.
**Выходы:** `dns.rules[]`; для правил по rule-set — локальные наборы
(`type: local`, `format: binary`) в `route.rule_set`.

## Правила и инварианты

- Порядок `dns.rules` = порядок списка. Новые зеркала пресетов вставляются
  перед блоком шаблонных, новые шаблонные — в конец; сохранённый порядок
  пользователя не меняется.
- Зеркала пресетов и правил — одна атомарная группа («From routing rules ·
  ordered as in Routing») в порядке правил маршрутизации. Свои правила
  ставятся выше или ниже группы целиком, не внутрь. Якорь группы — позиция
  первой записи пресета; без неё — перед шаблонными; иначе — в конец.
- Зеркало правила маршрутизации строится, только если правило включено и
  не содержит портов, протоколов и `network` (их нет в момент DNS-запроса).
  Выбранный сервер задаётся тегом; Force IPv4 даёт отдельное правило
  `{ip_version: 6, action: predefined, rcode: NOERROR}` и идёт первым.
  Для inline-правила матч уезжает в общий headless rule-set, для `.srs` —
  ссылка на тот же набор.
- Зеркало на сервер, которого нет в собранном списке, тихо не эмитится
  (без предупреждения). Сервер, выпавший из-за канала, — наоборот: правило
  на него становится `action: reject`.
- Выключенный пресет (маршрутизация выкл.) не даёт DNS-правил; запись
  пресета в списке остаётся якорем, её собственный `enabled` сборка не
  читает.
- Правило по rule-set без скачанного файла или без `server` пропускается
  молча.
- Своё правило: пустое имя — «Name is required»; тело не JSON-объект —
  «Invalid JSON: …»; содержимое тела клиент не проверяет.
- Если в конфиге есть `query_type` или `ip_version`, устаревший `strategy`
  снимается со всех DNS-правил (P11).
- Сироты (шаблонное без шаблона, пресетное без активного пресета)
  удаляются при загрузке экрана и при сборке.
