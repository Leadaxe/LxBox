# Статус приложения: имя, иконка, «удалено»

| Поле | Значение |
|------|----------|
| Фича | [011-SPLIT_TUNNELING](../FEATURE.ru.md) |
| Обещания | P10 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Показывает в списке вкладки человеческое имя и иконку приложения вместо
голого пакета и честно помечает пакеты, которых на устройстве нет:
«<пакет> — uninstalled, auto-skipped», с приглушённой иконкой.

## Параметры

Нет.

## Входы / Выходы

**Вход:** пакеты из списка; ответы ОС: «есть, вот имя», «пакета нет» или
отсутствие ответа (таймаут, сбой).

**Выход:** строка списка с именем и иконкой; метка «uninstalled» только для
подтверждённого отсутствия.

## Правила и инварианты

- Три состояния пакета: неизвестно (ещё проверяется или проверка сорвалась),
  установлен, подтверждённо отсутствует. Метка — только для третьего.
- Сорвавшаяся проверка не кэшируется как «нет»: до трёх автоматических
  повторов с задержкой 2, 5, 15 с; после — «неизвестно», новая попытка при
  следующем заходе на вкладку.
- Подтверждённое «нет» повторно не спрашивается до конца сессии; загрузка
  полного списка приложений (пикер) лечит устаревшие записи.
- Имя появляется сразу, иконка догружается отдельно; пока её нет —
  нейтральная заглушка.
- Пакет без имени (ещё не проверен) показывается идентификатором и сортируется
  по нему.
- Пакет с меткой из списка не удаляется автоматически: переустановленное
  приложение снова работает без повторного выбора.

## Границы

- Метка — диагностика для пользователя; реальное решение «пропустить пакет»
  принимает ОС при создании туннеля и о нём пишет подробный журнал ядра
  (см. [mode-and-list](mode-and-list.ru.md)).
- Зависит от возможностей ОС: ответ на запрос о пакете и его скорость.
