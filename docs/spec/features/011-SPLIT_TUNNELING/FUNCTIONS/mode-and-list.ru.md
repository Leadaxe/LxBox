# Режим и список приложений

| Поле | Значение |
|------|----------|
| Фича | [011-SPLIT_TUNNELING](../FEATURE.ru.md) |
| Обещания | P1–P6, P11 |
| Состояние | ✅ написана по коду, 2026-09-28 |

## Что делает

Хранит выбор пользователя — режим и список пакетов — и превращает его в поле
туннельного входа конфига ядра, откуда ОС при создании туннеля узнаёт, какие
приложения пускать в туннель, а какие вести мимо.

| Режим | Подпись на экране | В туннеле |
|-------|-------------------|-----------|
| Off | All apps go through VPN (default) | все приложения |
| Allow-list | Only selected apps go through VPN. Others bypass via cellular/wifi | только выбранные |
| Deny-list | Selected apps bypass VPN. Others go through | все, кроме выбранных |

## Параметры

| Настройка | Значения | Дефолт |
|-----------|----------|--------|
| Mode | `off` / `allow` / `deny` | `off` |
| Список | идентификаторы пакетов | пусто |

Список показан только в Allow/Deny: счётчик «Apps in this list (N)», кнопка
«Add app» (пикер), у строки — кнопка удаления. Меню вкладки: «VPN settings
(System)» (переход к системным настройкам туннеля), «Clear all» (с
подтверждением, режим сохраняется), «Help».

## Входы / Выходы

**Входы:** выбор на вкладке, результат пикера (заменяет список целиком),
`PUT /settings/tun_apps`, восстановление бэкапа.

**Выходы:** `{mode, packages}` в настройках; `include_package` (allow) или
`exclude_package` (deny) у первого `inbounds[type=tun]`; признак «нужна
пересборка»; `GET /settings/tun_apps` отдаёт текущую пару.

## Правила и инварианты

- Неизвестный режим при чтении — Off с пустым списком; при записи — отказ
  (экран его не допускает, Debug API отвечает 400).
- Запись нормализует список: обрезка пробелов, без пустых, без дублей, по
  алфавиту. На экране строки упорядочены по имени приложения.
- Смена режима список не трогает; Off только перестаёт его применять.
- Пустой список в Allow/Deny — конфиг не меняется (все в туннеле).
- Нет туннельного входа (режим Proxy) — шаг ничего не делает, ошибки нет.
- Шаг — последний правщик туннельного входа при сборке конфига.
- Правка применяется к живому туннелю только его новым поднятием: плашка
  «restart» или автоперезапуск — [003-CONFIG_BUILD](../../003-CONFIG_BUILD/FUNCTIONS/apply-to-running-tunnel.ru.md).
  Правки копятся в памяти и пишутся на диск при уходе с экрана или уходе
  приложения в фон.
- Debug API: имя пакета — латинская буква, затем буквы/цифры/`_`, сегменты
  через точку; иначе 400. Пустые строки отбрасываются.
- Пакет, которого нет на устройстве, при поднятии туннеля пропускается.
- В режиме подробного журнала ядра на каждом поднятии туннеля пишется строка
  `per-app: mode=… allow_bypass=… applied=N […] not_installed=M […]`;
  в обычном режиме — ничего.

## Границы

- Proxy-режим: список не действует; вкладка этого не показывает.
- Split по доменам и адресам — правила ядра, 004-ROUTING.
- Зависит от возможностей ОС: механизм разрешённых/запрещённых приложений,
  применение только при создании туннеля.
