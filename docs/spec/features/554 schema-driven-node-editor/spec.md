## 1. Зачем

Сегодня узел добавляется мастером и правится в настройках с фиксированным набором
полей. Знание «какие поля есть у протокола и что с ними можно» живёт в реестре, а
экраны его не читают. Каждый новый протокол или правило требует правки экранов.

Идея: экран не знает протоколов. Он берёт схему тела из реестра и строит форму по
ней. Поменялся реестр — поменялась форма. Проверка ввода — тот же санитайзер, что
судит разбор и сборку, поэтому редактор не может разойтись с ними.

## 2. Что даёт схема (уже есть, после §553 без обёрток)

- порядок и тип полей → набор и вид виджетов, вложенные секции для объектов;
- `required` → обязательность;
- `values`, `format`, `default` → списки допустимых значений, проверка на лету, подсказка;
- `desc_en` / `desc_ru` → подпись и помощь на обоих языках;
- варианты транспорта по типу → форма меняется от выбора;
- связи (`conflicts`, `requires`, `when`) → скрытие или блокировка полей, которые в текущем сочетании не имеют смысла;
- `secret` → скрытый ввод;
- пометка происхождения из общей суб-схемы → группировка полей («Соединение», «TLS»).

## 3. Контур решения (без деталей)

1. Форма читает тело узла в формате sing-box и пишет обратно такое же тело: один и тот же
   редактор для узла из ссылки, из JSON и созданного вручную.
2. Проверка ввода — прогон тела через санитайзер реестра. Он возвращает коды с путями до
   поля; форма подсвечивает поле и показывает текст кода (реестр их уже отдаёт, экран
   уведомлений узла ими пользуется). Второй валидации в UI нет.
3. Дословный исходник `rawSource` после правки теряется, узел считается отредактированным —
   как сейчас при правке в настройках.
4. Правила версии ядра (`min_when` и т.п.) форма не отражает: их судит санитайзер при
   сохранении.

## 4. Открытые вопросы (решить до плана)

- Полная форма по схеме или «несколько главных полей + сырой JSON с проверкой
  санитайзером»? Второе в разы дешевле и даёт ту же защиту.
- Как показывать поля, снятые санитайзером молча (`default_when`, нормализация), чтобы
  пользователь не думал, что ввод пропал.
- Место в навигации: замена настроек узла или отдельный «расширенный» режим.
- Что делать с полями, которых нет в схеме (чужие ключи): показывать как есть или скрывать.
- Нужна ли форма для узлов из подписки (правка перетирается при обновлении) или только
  для UserServer и папок.

## 5. Не входит

Изменения реестра, парсера, сборки. Новых примитивов схемы не требуется: всё, что нужно
форме, уже есть в поле схемы.
