# §422 — Support-лента: сеть только с согласия на проверку обновлений; единственный источник `app/assets/support.json`

**Тип:** таска (поверх §356/§357)
**Статус:** реализовано, юниты зелёные (support_message_test: 4 кейса fetch); device-verify не требуется — ветвление чисто в сервисе, UI не менялся
**Связано:** §356 (лента), §362 (донат: asset+кэш, но БЕЗ гейта и с отдельной копией), §379/F-Droid (онбординг-вопрос `auto_check_updates`, issue #61)

---

## Проблема

Ревьюер F-Droid (duckniii, #61, 30.08.2026) увидел запрос на
`raw.githubusercontent.com` при выключенной проверке обновлений. Это
`support.json` — лента §356. До этой таски она ходила в сеть при каждом
запуске процесса с поднятым туннелем, независимо от онбординг-ответа и даже
когда все сообщения прочитаны; кэш `cache_json` был только офлайн-фолбэком.
Отключить это пользователь не мог.

## Решение (владелец, 05.09.2026)

**1. Гейт.** Один тумблер на всё «в сеть за нашими файлами» — уже существующий
`auto_check_updates` (вопрос первого запуска «Check for updates?»):

| Согласие | Порядок источников ленты |
|---|---|
| `auto_check_updates = true` | сеть → кэш → bundled → null |
| `auto_check_updates = false` | кэш → bundled → null; **ни одного запроса** |

**2. Единственный источник — `app/assets/support.json`.** Он бандлится в APK
(лента работает у ответивших «Skip» с первого запуска: очередь, пороги,
тексты — на момент сборки) и он же раздаётся с GitHub по
`raw.githubusercontent.com/Leadaxe/LxBox/main/app/assets/support.json`.
Промежуточный вариант «копия `docs/support.json` → `app/assets/` + тест
паритета» отброшен: копирование пришлось бы повторять в CI, в локальном
скрипте и в fdroiddata (`prebuild`), а один файл не расходится по определению.

**Языки не затронуты:** файл изначально один на все локали — блок `i18n`
(`en` обязателен, `ru` и прочие опциональны) у каждого сообщения, выбор в
момент показа (§356). Словари `assets/l10n/` к ленте отношения не имеют.

**Bundled-копия не пишется в `cache_json`:** как только согласие появится,
придёт свежая лента, а не переписанный из asset снимок.

**Старые версии.** ≤ 2.22.0 читают `docs/support.json`; файл удалён → 404 →
они живут на своём кэше, а свежая установка старой версии ленту не увидит.
Принято владельцем: пользователи ставят актуальную версию.

Отдельного тумблера «не показывать ленту» не делаем: кнопки «Later» (снуз
10 ч наработки) и «Got it» остаются как были; вопрос ревьюера был про сеть.

## Код

| Файл | Изменение |
|---|---|
| `app/assets/support.json` | `git mv` из `docs/support.json` — единственный источник |
| `app/assets/support.test.json` | `git mv` из `docs/` — тестовая кампания, `LXBOX_SUPPORT_URL` |
| `app/pubspec.yaml` | asset зарегистрирован |
| `app/lib/services/support/support_message.dart` | `_url` → `main/app/assets/support.json`; `fetchOrCached`: гейт `SettingsStorage.getAutoCheckUpdates()` перед `_fetch()`; после кэша — `rootBundle.loadString('assets/support.json')`; общий `_parse` |
| `app/lib/screens/home_screen.dart` | docstring `_maybeShowSupport`: гейт внутри сервиса, экран не ветвится |
| `app/test/services/support_message_test.dart` | setUp даёт согласие; «ни сети, ни кэша» → asset; +2 кейса: без согласия клиент не вызывается (кэш / asset), asset не попадает в кэш |

Гейт живёт **в сервисе**, а не в `home_screen`: Debug API `/support/preview` и
любой будущий вызов получают то же поведение автоматически.

## Что НЕ изменилось

- `LXBOX_SUPPORT_URL` (dart-define для тестовой кампании) работает только при
  согласии — тестовый APK включает проверку обновлений.
- Ретрай 30 с в `_maybeShowSupport` при закрытой сети не срабатывает: сервис
  отвечает мгновенно из кэша/asset.
- Остальные три запроса на `raw.githubusercontent.com` без гейта, как были:
  `docs/latest.json` (сам под флагом), `app/assets/donate.json` (только при
  открытии About; переехал тем же способом в §423), `public-servers-manifest.json`
  (только экран публичных тест-серверов). Все три — по явному действию
  пользователя, не фоновые.
