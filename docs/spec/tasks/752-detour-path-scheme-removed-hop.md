## Problem

С §739 недоступный detour (Направление выключено, цель удалена, пропала из
подписки, член папки выключен) не убирает сервер: сборка снимает `detour`,
сервер подключается напрямую, у источника, строки члена папки и на карточке
появляется ⚠ «Hop … unavailable: hop removed» (код `detour_unavailable`).

Схема пути под строкой **Detour server** при этом рисует выбранный detour:
«Phone → ⚡ J730 → ⚡ T731 → Internet». На одном экране ⚠ «hop removed» и путь
через этот хоп — как будто он действует.

## Diagnosis

Схема строится из выбора (`_detour` → `detourPathHops`) и об итоге сборки не
знает. Итог сборки по узлу уже есть: `SubscriptionController.
lastBuildWarningsByTag[config-тег]` содержит `detour_unavailable`, если detour
этого узла снят. Код ставится носителю, чья собственная ссылка не разрешилась
(`resolveDeferredDetours` п. 1/4, правило 1 граф-санитайзера).

Та же схема есть у detour источника на вкладке Settings подписки и папки
(«Phone → X → Nodes → Internet»): detour подписки снимается у каждого её узла,
и каждый получает тот же код.

## Solution

1. Виджет `DetourPathLine` (`lib/widgets/detour_path_line.dart`) и функция
   `detourRemovedWarning(warnings)` — код `detour_unavailable` среди
   предупреждений узла. Без кода — путь как раньше (тот же стиль). С кодом —
   путь перечёркнут (приглушённый цвет), под ним строка со значком и цветом
   уровня кода (`warningSeverityStyle`, как ⚠ строки члена папки):
   - карточка сервера / члена папки: «Not applied: the detour is unavailable,
     traffic goes directly to this server.»;
   - Settings подписки / папки: «Not applied: the detour is unavailable,
     nodes connect directly.».
   Новых цветов нет; выбор detour не меняется и не сбрасывается.
2. Карточка сервера (`node_settings_screen.dart`): предупреждения сборки по
   config-тегу узла — из обратной карты `lastEmittedTagMap` по самому узлу,
   иначе display-тег с префиксом (как у ⚠ строки члена папки, §739 итер. 3).
   Строка обёрнута в `ListenableBuilder` контроллера: после пересборки вид
   меняется без перезахода.
3. Settings подписки / папки (`SubscriptionSettingsTab`): два необязательных
   параметра — `buildResults` (контроллер) и `overrideDetourRemoved`.
   Подписка: detour снят, если код есть у любого её узла. Папка: у любого
   члена, который наследует detour папки — без личного detour, а при Replace
   (§237) — любого.
4. До первой сборки (`lastBuildWarningsByTag` пуст) — вид прежний.

Сборка, контракт, цепочки (chain) и пикер detour не меняются.

## Risks and edge cases

- Многохоповый путь «Phone → A → B → узел»: если снят detour у промежуточного
  B (код у B, не у узла), путь узла не перечёркивается — код адресован B. Узел
  при этом действительно идёт через B, неточна только часть пути до B. Не
  делаем: хопы схемы — подписи, обратного сопоставления с config-тегами нет.
- Папка: личный detour члена недоступен, detour папки задан — строка папки
  не перечёркивается (член с личным detour папочный без Replace не
  наследует).
- Подпись TLS «Not applied: traffic goes through a detour first» на той же
  карточке при снятом detour не меняется — вне задачи.
