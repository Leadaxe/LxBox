## 1. Проблема

`.srs` скачивался ровно один раз — тапом по ☁. Дальше файл лежал в
`$docs/rule_sets/<id>.srs` бессрочно: ядро в сеть за рулсетами не ходит
(в конфиг попадает `{type: "local", path: …}`), приложение само не
перекачивало. Списки блокировок и geosite обновляются на стороне
издателей, локальная копия тихо устаревала, и пользователь не мог даже
узнать, насколько — в UI не было ни даты, ни кнопки обновления.

## 2. Решение и отвергнутые варианты

**Что сделано:** проверка устаревания на двух триггерах — старт
приложения и подъём VPN, — с per-rule TTL, условным GET по ETag и
видимым временем последнего обновления.

| Вариант | Решение |
|---|---|
| Фоновый таймер (`Timer.periodic`, WorkManager) | **Нет.** Рулсеты живут неделями; ежечасный будильник стоит батареи каждый день ради события раз в неделю |
| Кнопка «Update all» (просили в issue) | **Нет** — решение пользователя. Ручное обновление одного правила уже есть; массовая кнопка не решает корневую проблему, о ней всё равно надо вспомнить |
| `type: remote` — пусть качает ядро | **Нет.** Ломает намеренную модель: в сеть за рулсетами ходит только приложение и только явно |
| Глобальный интервал в настройках | **Нет** — решение пользователя. TTL задаётся на правило |

## 3. Триггеры

| Триггер | Когда | Задержка |
|---|---|---|
| `appStart` | запуск приложения | 30 с |
| `vpnConnected` | туннель поднялся | 30 с |
| `retry` | предыдущий проход дал хоть одну неудачу | 20 с, **один раз за триггер** |

Инварианты:

- **Один успешный проход за сессию.** Проход, завершившийся без единой
  неудачи (в том числе «обновлять нечего»), выставляет `_sessionDone` —
  дальше все триггеры no-op до перезапуска процесса.
- **Только на переднем плане.** Уход в фон отменяет запланированную
  попытку (`onAppPaused`); проверка `_foreground` повторяется в момент
  срабатывания таймера и на каждой итерации цикла — свернули посреди
  прохода, останавливаемся, и проход НЕ считается успешным.
- При неудаче старый `.srs` **не удаляется** и правило **не выключается** —
  даже на 404. Устаревший рабочий список лучше выключенного правила.

Файл: [`app/lib/services/rule_set_auto_updater.dart`](../../../app/lib/services/rule_set_auto_updater.dart).
Подключение — `home_screen.dart` (создание, `start()`, lifecycle),
`home_controller.dart` (`onVpnConnected` на transition → connected).

## 4. TTL — per-rule

Вшитый набор (часы), свободного ввода нет:

| Часы | Подпись |
|---|---|
| 0 | Never |
| 24 | Every day |
| **168** | **Every week (дефолт)** |
| 336 | Every 2 weeks |
| 720 | Every month |
| 4320 | Every 6 months |
| 8760 | Every year |

- **Свои SRS-правила** — `CustomRuleSrs.updateIntervalHours`, выпадающий
  список в редакторе правила. Дефолт в JSON не пишется: старые правила
  без ключа читаются как неделя.
- **Пресеты** — поле `update_interval` в `rule_set` шаблона (формат
  sing-box: `"168h"`, `"7d"`). Пользователем не редактируется.
  Парсер — `parseUpdateIntervalHours`; единицы меньше часа округляются
  **вверх** (иначе `"30m"` молча означал бы «никогда»).

Поле `update_interval` в шаблоне существовало и раньше (у `geoip-ru`), но
было мёртвым: `preset_expand.dart` вырезает его при сборке конфига, и
правильно — при `type: local` sing-box такого поля не знает. §366 читает
его до вырезания, на стороне приложения.

`kDefaultSrsTtlHours` / `kSrsTtlChoicesHours` — в
[`models/custom_rule.dart`](../../../app/lib/models/custom_rule.dart).

## 5. Метаданные и условный GET

Внутри `.srs` данных о свежести нет: формат — `SRS` + байт версии формата
+ zlib-поток правил (`common/srs/binary.go`), ни даты сборки, ни версии
контента. Зато HTTP отдаёт `ETag` (проверено на
`raw.githubusercontent.com/SagerNet/sing-geosite`), поэтому еженедельная
проверка стоит одного `304` без тела.

Метаданные — sidecar `$docs/rule_sets/<id>.meta.json`:

```json
{ "lastUpdated": "…", "lastAttempt": "…", "etag": "…", "lastError": "HTTP 404" }
```

Почему sidecar, а не поля модели:

1. preset-рулсеты (`preset__<presetId>__<tag>`) своей записи в
   `custom_rules` не имеют — класть метаданные некуда;
2. кэш и так вне бэкапа, метаданные о нём симметрично не должны попадать
   в `custom_rules`;
3. `delete(id)` сносит файл и метаданные одним вызовом.

**Почему не хватило mtime файла** (прежний источник «времени обновления»,
`RuleSetDownloader.lastUpdated`): при `304` файл не переписывается, mtime
остаётся старым — каждая следующая проверка снова считала бы кэш
протухшим. Нужен явный «когда последний раз подтвердили актуальность».

Контракт [`RuleSetDownloader`](../../../app/lib/services/rule_set_downloader.dart):

- `fetch(id, url, {conditional})` → `DownloadResult{outcome, path}`,
  `outcome ∈ {downloaded, notModified, failed}`. `304` — **успех** (двигает
  `lastUpdated`), но `changed == false`: пересборку конфига не вызывает.
- `download()` сохранён обратно-совместимым (`String?`) — старые
  вызовы и тесты не тронуты.
- `conditional: true` только у авто-обновления. Ручной ⟳ шлёт безусловный
  GET: «обновить» должно перекачивать, даже если сервер считает копию
  свежей.
- `If-None-Match` не отправляется, если файла нет — иначе сервер ответил
  бы `304` на пустой кэш.
- `pruneOrphans` чистит и осиротевшие `.meta.json`.

## 6. UI

- **Тайл правила** ([`custom_rule_tile.dart`](../../../app/lib/screens/routing_screen/widgets/custom_rule_tile.dart)) —
  строка «Updated 3d ago» под subtitle; при неудачной последней попытке —
  «Update failed — using cached copy» цветом ошибки. У пресета
  агрегируется по всем его rule_set'ам: время — самое старое, ошибка —
  любая.
- **Кнопка ⟳** ([`srs_status_button.dart`](../../../app/lib/screens/routing_screen/widgets/srs_status_button.dart)) —
  рядом с ☁, только когда файл уже скачан. ☁ остаётся индикатором
  «скачано / не скачано». У пресетов дублирует пункт long-press меню
  видимой кнопкой — меню не находят.
- **Редактор правила** ([`srs_section.dart`](../../../app/lib/screens/custom_rule_edit/sections/srs_section.dart)) —
  выпадающий список TTL и строка времени последнего обновления.

## 7. Архитектурная правка попутно

`PresetRemoteRuleSet`, `remoteRuleSetsOf` и `isRuleSetEnabled` переехали
из `screens/routing_screen/routing_screen_helpers.dart` в
[`models/preset_rule_set.dart`](../../../app/lib/models/preset_rule_set.dart):
это чистые функции без зависимости от UI, а headless-сервису
авто-обновления они нужны — иначе `services/` импортировал бы `screens/`.
В хелперах остались делегаты и `export`, вызовы на экранах не менялись.
