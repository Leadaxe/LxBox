## Часть F. Экран общего конфига: нельзя выделить кусок текста

### Проблема

Пользователи: «долгий тап показывает меню, выделение слетает; строку ещё можно
копирнуть». На экране общего конфига (`config_screen.dart:217`) и в мастере
добавления сервера (`add_server_wizard_screen.dart:688,715`) выделить фрагмент
и скопировать его было невозможно — в буфер уезжало не то, что выделил человек.

### Диагностика

`app/lib/widgets/lx_code_editor.dart:79` (до правки) показывал контекстное меню
через `showMenu<void>(...)`. Это `Navigator.push` модального `PopupRoute`:

1. Маршрут забирает фокус у редактора и ставит поверх барьер, перехватывающий
   указатель.
2. У re_editor выделение живёт на `CodeLineEditingController` вместе с фокусом
   и снимается на любом тапе вне текста — `re_editor-0.10.0`,
   `lib/src/_code_selection.dart:172-176` (`_onMobileTapDown` → `_selectPosition`
   + `hideHandle()` + `hideToolbar()`) и `:188-192` (та же ветка в
   `_onMobileTapUp`).
3. У `PopupMenuItem` колбэк `onTap` вызывается **после** закрытия маршрута —
   `controller.copy` доходил до контроллера с уже схлопнутым выделением.

Отсюда и второе наблюдение пользователей: одиночная строка попадала под
схлопнутое выделение, поэтому «строку ещё можно копирнуть».

Дополнительно `hide(BuildContext)` имел пустое тело (`:67`) — снимать было
нечего, потому что маршрут закрывал себя сам.

Контракт пакета предполагает **оверлей, а не маршрут**: `show(...)` получает
`layerLink` и `visibility` (`lib/src/code_toolbar.dart:13-20`) — оба параметра
раньше не использовались.

### Решение

`app/lib/widgets/lx_code_editor.dart` — `_LxSelectionToolbarController`
заменён на публичный `LxSelectionToolbarController`:

- меню живёт в `OverlayEntry` + `CompositedTransformFollower(link: layerLink)`;
- обёртка — `CodeEditorTapRegion` (`groupId: CodeEditor`, публичный класс
  пакета): тап по кнопке меню **не** считается тапом вне текста, поэтому
  выделение не снимается;
- видимость привязана к переданному `ValueNotifier<bool> visibility`;
- `hide()` действительно снимает `OverlayEntry`; `show()` начинается с `hide()`
  — второй показ не плодит оверлеи;
- порядок в обработчике кнопки: сначала действие над живым выделением, только
  потом снятие меню.

**Почему не штатный `MobileSelectionToolbarController`.** Пакет даёт готовую
фабрику (`code_toolbar.dart:26-32`), и механика у неё ровно та же — оверлей с
`CodeEditorTapRegion`. Но её реализация делает
`offset: -renderRect!.topLeft` (`_code_selection.dart:1134`), а `renderRect`
не-null только на мобильной ветке: `_DesktopSelectionOverlayController.showToolbar`
(`:454-461`) передаёт `null`, и штатный контроллер на desktop/в тестах падает.
Свой класс переживает обе ветки (`renderRect?.topLeft ?? Offset.zero`).

### Риски и edge cases

- Внешний вид меню сменился с `PopupMenu` на горизонтальный ряд кнопок в
  `Material`. Пункты и их порядок те же (Cut / Copy / Paste / Select all),
  новых видимых строк нет — ключи уже были в словарях.
- Позиционирование меню при выделении у самого края редактора оверлей не
  клампит — как и раньше у `showMenu` через `RelativeRect`. Если всплывёт,
  отдельной задачей.
- Меню не закрывается по тапу в пустоту вне редактора: его снимает штатный
  путь re_editor (`hideToolbar` на скролле и на тапе по тексту), как и
  задумано контрактом пакета.

### Верификация

`app/test/widgets/lx_code_editor_toolbar_test.dart` — 7 виджет-тестов через
**штатный** путь (долгий тап по тексту, как на устройстве), без
`pumpAndSettle` (у редактора бесконечная анимация каретки — settle не
сойдётся), только `pump(Duration)`:

- меню показано, `selection` не схлопнулось, `selectedText == 'alpha'`;
- Copy кладёт в буфер **выделенный** фрагмент (мок `SystemChannels.platform`);
- Cut забирает выделенное и вырезает его из текста;
- Select all выделяет весь текст; Paste заменяет выделение;
- `hide` снимает оверлей (скролл — штатный триггер);
- повторный показ не плодит оверлеи.

Контрольная проверка: на прежней реализации из `origin/develop` файл падает
4 тестами из 7, и Copy кладёт в буфер пустую строку — тест не вакуумный.

Дёргать `toolbarController.show` напрямую бессмысленно: без связанного с
редактором `layerLink` follower садится в начало координат поверх самого
редактора, и тап по «кнопке» уходит в текст. Это зафиксировано в докблоке
теста, чтобы следующий не переписал его на «прямой» вызов.

## Часть G. DNS-пресет `dns_shield`: открытый UDP в группе `fastest`

### Проблема

`app/assets/wizard_template.json` — группа `dns_shield` держала четыре
открытых udp-сервера рядом с DoH/DoT:

```json
{ "type": "group", "tag": "dns_shield",
  "servers": ["google_udp", "cloudflare_udp", "opendns_udp",
              "google_doh", "google_dot", "cloudflare_dot",
              "quad9_doh", "yandex_udp", "yandex_dot"],
  "mode": "fastest", "error_ttl": "5m", "win_ttl": "5m" }
```

`mode: "fastest"` шлёт запрос **всем** членам сразу и берёт первый ответ.
Открытый UDP по порту 53 без TLS-рукопожатия почти всегда выигрывает гонку у
DoH/DoT — значит в группе с именем «shield» победителем регулярно оказывался
открытый резолвер. Хуже: даже когда побеждал шифрованный член, запрос по UDP
уже **был отправлен** и виден наблюдателю независимо от того, чей ответ
приняли. Имя пресета обещало противоположное тому, что он делал.

### Решение

**Было → стало** в группе `dns_shield`:

| Снято из группы | Чем закрыт тот же провайдер |
|---|---|
| `google_udp` (8.8.8.8:53) | `google_doh` + `google_dot` — уже были в группе |
| `cloudflare_udp` (1.1.1.1:53) | `cloudflare_dot` — уже был в группе |
| `opendns_udp` (208.67.222.222:53) | `opendns_doh` — **добавлен** (DoT у OpenDNS публично нет) |
| `yandex_udp` | `yandex_dot` — уже был в группе |

Итоговый состав: `google_doh`, `google_dot`, `cloudflare_dot`, `opendns_doh`,
`quad9_doh`, `yandex_dot` — только `https`/`tls`.

Новая запись `opendns_doh` по форме соседних DoH (`cloudflare_doh`/`google_doh`):
`type: https`, `server_port: 443`, `server: 208.67.222.222`,
`path: /dns-query`, `tls.server_name: dns.opendns.com`.

**Сами записи `*_udp` в `dns_options.servers` оставлены.** На них ссылаются
`default_value` резолверов и подсказки (`dns_default_domain_resolver`,
`dns_final`) — удаление определений сломало бы ссылки. Снят только их
членский состав в группе.

Подсказки резолверов в трёх местах говорили «races 9 providers»: после правки
это 6 и все шифрованные, поэтому текст поправлен на
«races 6 encrypted providers» в `wizard_template.json`,
`app/lib/screens/dns_settings_screen.dart` и в overlay-словарях ru/zh
(`template.json`, `ui.json`) — иначе `template_check`/`ui_check --strict`
уронили бы CI на orphan-ключах.

### Побочное из разбора — НЕ меняли

`quad9_doh` — единственный член группы с `detour: vpn-1`. При `mode: fastest`
это значит, что члены идут разными путями и состав победителей зависит от
того, поднят ли `vpn-1`. Решение «ставить детур всем членам единообразно или
никому» — за владельцем, в объём §517 сознательно не входит. Текущее
состояние зафиксировано стражем, чтобы правка не прошла молча.

### Риски и edge cases

- **Существующие конфиги не мигрируются.** Пресет применяется к новым
  установкам и при (пере)выборе пресета; у кого `dns_shield` уже лежит в
  хранении (`kind: "template"`, состав группы берётся из шаблона при сборке) —
  состав подтянется при следующей сборке конфига; у кого группа сохранена
  как `inline` — останется как была. Автоматической миграции пользовательских
  конфигов нет и не добавляли.
- Резолв через «щит» станет медленнее на величину TLS-рукопожатия. Это и есть
  цена шифрования, ради которой пресет существует.
- `yandex_udp`/`yandex_dot` объявлены не в базе, а в пресете `ru-direct`
  (`selectable_rules[].dns_servers`), хотя базовая группа `dns_shield` на них
  ссылается. Так было и до §517: при выключенном пресете §121 уносит его
  серверы, а битых членов группы подчищает сборка с предупреждением
  `DNS group 'dns_shield': member 'yandex_dot' dropped (unknown)`. Не
  трогали — отдельная тема.

### Верификация

- `app/test/services/wizard_template_dns_shield_test.dart` — 5 новых тестов:
  в группе `fastest` нет открытых udp-членов (тип каждого члена ищется по
  объединению базы и серверов пресетов); группа покрывает шесть шифрованных
  тегов; `opendns_doh` — корректная DoH-запись; записи `*_udp` остались
  объявлены; `quad9_doh` сохраняет `detour: vpn-1`.
- Страж `golden_config` (§439) поймал правку — эталоны перегенерированы
  `UPDATE_GOLDEN=1`. Диффы содержат ровно ожидаемое: из `dns_shield` ушли
  udp-члены, появился `opendns_doh` (и как член, и как запись в
  `dns.servers`), из `*.config_warnings.json` исчезли строки
  `member 'cloudflare_udp' dropped (disabled)` и
  `member 'yandex_udp' dropped (unknown)`. Постороннего в диффах нет.
- Четыре l10n-чекера (`ui_check`, `template_check`, `hardcoded_check`,
  `kotlin_check`) — `--strict`, 0 failures / 0 warnings. Для новой записи
  добавлен ключ `"OpenDNS DoH"` в ru/zh `template.json` (название продукта +
  аббревиатура протокола — одинаково во всех языках).
