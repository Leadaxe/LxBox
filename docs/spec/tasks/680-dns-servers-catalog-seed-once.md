## Проблема

Пользователи просят удалять DNS-серверы из стартового списка. Сейчас в нём
12 серверов шаблона (11 включены), плюс до четырёх от пресета ru-direct.
Удалить можно только свои inline-серверы: у шаблонных в редакторе нет Delete
(`dns_server_edit_screen.dart:239`, условие `isUserOnly`), а если бы и было,
шаг 3 `resolveDnsServersList` (`post_steps/dns_servers.dart:141-149`) досеял
бы отсутствующий тег при следующей сборке или открытии вкладки. Единственный
способ убрать сервер из глаз — выключить тумблер; строка остаётся.

## Решение (владелец, 23.10.2026)

Секция `dns_options.servers` шаблона становится **каталогом**, как
`selectable_rules`: шаблон описывает, что бывает, список пользователя — что
включено. Третье такое место после Направлений (§125) и пресетов (§010):
посев один раз, дальше список принадлежит пользователю. «Работаем с тем, что
есть»: состав списка приложение само не меняет, новые серверы шаблона
появляются только в каталоге.

### 1. Посев один раз, без флага

- Признак «список создан» — наличие ключа `dns.servers` в хранилище
  (`kDnsKey`/`kDnsServersKey`). Отдельного флага нет (решение владельца
  23.10.2026: «стейдж создан — значит создан»). Новый аксессор
  `SettingsStorage.hasDnsServersList()` = ключ присутствует; сегодняшний
  `getDnsServers()` отдаёт `[]` и для отсутствующего ключа, и для пустого
  списка, поэтому различать по нему нельзя.
- Шаг 3 `resolveDnsServersList` (досев шаблонных серверов) выполняется только
  когда ключа нет; результат пишется шагом 4, после чего ключ есть и досев
  больше не повторяется. `enabled` берётся из обёртки шаблона, как сейчас.
- Пустой сохранённый список — выбор пользователя, не признак «не засеяно».
  Через UI он недостижим: значения `dns_final` и `default_domain_resolver`
  держат хотя бы один сервер залоченным (п. 3). Достижим через Debug API
  `PUT /settings/dns_options/servers` с `[]` и через бэкап — и тогда
  остаётся пустым.
- Существующие установки: ключ уже есть → шаг 3 не выполняется, состав не
  меняется. Миграции нет.
- Шаг 1 (orphan-cleanup: тег исчез из шаблона → запись уходит) и шаг 2
  (досев серверов активного пресета) — без изменений. Серверы пресета
  обязаны появляться при включении пресета и уходить при выключении.
- **Тело** шаблонного сервера по-прежнему ссылка: запись `kind: template`
  хранит тег, `enabled`, `vars`; тело берётся из шаблона на каждой сборке.
  Правка адреса в шаблоне доезжает до всех, как у пресетов.

### 2. Удаление шаблонного сервера

- `canDelete` в редакторе: `!isNew && !locked` для inline и template;
  preset — по-прежнему нельзя (живёт с пресетом). Override (inline поверх
  template) удаляется как template: запись уходит целиком, не откатывается
  к канону — для отката есть Reset.
- Long-press на тайле сервера → контекстное меню «Delete», как у правил на
  вкладке Rules (`routing_screen.dart:1310`). У locked и preset — пункт
  неактивен.
- Диалог подтверждения `showDeleteConfirmDialog`: для template — «Remove
  "Google DoH" from the list? You can add it back from the catalog.»;
  для inline — текущий текст про необратимость.
- Удаление ставит dirty по общей воронке вкладки (§655/§667), как правка.

### 3. Локи: что нельзя удалить и выключить

Расширение правила №7 §117 «сервер, на который ссылаются, управляемый».
К существующим источникам (активный пресет, DNS-опция правила) добавляются:

| Источник ссылки | Подпись «used by» | Где считать |
|---|---|---|
| член группы (`type: group`, `servers[]`) — для каждой группы в списке | `used by Shield DNS` (description группы, иначе тег) | `resolved_server.dart` по телам групп из списка |
| значение `dns_final` | `used by DNS Final` | `DnsController` отдаёт теги final/default resolver |
| значение `dns_default_domain_resolver` | `used by Default Domain Resolver` | там же |
| `domain_resolver` другого сервера в списке (var `dom_resolver` у `safe_dns_dot` → `google_udp`, inline-`domain_resolver`) | `used by Safe DNS (DoT)` | по телам серверов из списка (resolved, с подстановкой vars) |

Несколько источников — подпись через запятую, первые два, дальше «+N».
Как и сейчас: тумблер у locked заблокирован во включённом положении,
Delete недоступен. Снятие ссылки (удалили группу, сменили final) освобождает
сервер. Лок только по ссылкам из **списка**: группа, которой в списке нет,
никого не держит.

Удаление группы разрешено, если на неё саму нет ссылок (final/default
resolver). После удаления её члены свободны.

### 4. Каталог по (+)

Кнопка (+) в заголовке секции «DNS Servers» (`dns_settings_tab.dart:688-695`)
вместо прямого открытия inline-редактора открывает полноэкранную страницу
«Add DNS server» (паттерн §117 решение №8: экраны, не шиты):

- первая строка **Custom server** → текущий inline-редактор
  (`_addServer`, `DnsServerInline(tag: 'dns_new', …)`), без изменений;
- ниже подзаголовок «From template» и каталог: по строке на каждый сервер
  `dns_options.servers` шаблона в порядке шаблона; справа `[+ Add]`, у
  уже присутствующих в списке — `[✓ Added]` неактивная (образец
  `preset_catalog_tile.dart:32-45`);
- `Add` добавляет `DnsServerTemplate(enabled: <из обёртки шаблона>, tag)`
  в конец списка (порядок отображения всё равно template → preset →
  inline), SnackBar «Added "Google DoH"», страница остаётся открытой для
  следующих добавлений;
- меню ⋮ страницы: **Add all defaults** — досев всех отсутствующих, как
  шаг 3; сообщение «Added N servers» или «All defaults are already in the
  list»;
- новые серверы будущих версий шаблона попадают сюда сами: каталог — это
  разность «теги шаблона минус теги списка», версия шаблона не хранится.

Источник каталога — `TemplateLoader.load().dnsOptions.servers` (как у
Presets — `template.selectableRules`).

### 5. Сопутствующие дыры, которые открывает удаляемость

- **Пикер DNS-сервера в редакторе правила** (`custom_rule_edit/edit_controller.dart:329-339`)
  сейчас объединяет теги хранения со всеми тегами шаблона. После 680 выбор
  сервера не из списка дал бы висящую ссылку (mirror тихо не эмитится,
  `dns_rules.dart:175`). Источник пикера — только список. То же для
  авто-`domain_resolver` при вводе hostname (`edit_controller.dart:586-590`)
  и дефолта DNS-опции правила (`custom_rule_edit/edit_controller.dart:604-607`):
  `google_udp` берётся, если он в списке, иначе первый пригодный сервер
  списка (не fakeip/hosts), иначе пусто.
- **`domain_resolver` DNS-сервера на сборке**: гарда нет
  (`resolveTemplateDnsServerBody`, `dns_servers.dart:49-83`, существование
  тега не проверяется). Лок закрывает пользовательское удаление; на случай
  расхождения шаблона (новая версия сменила дефолт var) — post-step: ключ
  `domain_resolver`, указывающий на неэмитированный тег, снимается с
  предупреждением сборки `DNS server '<tag>': domain_resolver '<ref>' dropped
  (not in list)`. Ядро тогда берёт `route.default_domain_resolver`.
- **Член группы, которого нет в списке** (шаблон обновился, группа получила
  нового члена): уже сегодня снимается с предупреждением
  (`dnsGroupMemberDropReason`, :303-321), группа живёт на остальных. Без
  изменений. Пустая группа → fatal `EmptyDnsGroup`, без изменений: до неё
  не дойти, пока члены залочены.
- **`dns_final` / `default_domain_resolver`** — `healDanglingDnsResolvers`
  уже лечит, без изменений.

### 6. Бэкап и перенос

- **Файл правил** (`rule_transfer`, format 2): аддитивный импорт, без
  изменений. Шаблонный сервер из файла, которого нет у получателя, добавится
  (как «Add» из каталога).
- **Полный LX-бэкап и перенос телефон→TV (§622)** — решение владельца
  23.10.2026: для записей `kind: template` файл — **полный список**.
  `applyDnsBackup` (`dns/dns_backup.dart:217`) при импорте секции DNS
  снимает у получателя шаблонные записи, тегов которых нет в файле; inline
  и preset-записи — слияние как сейчас (локальная сильнее, отсутствующая
  дописывается). Файл без секции DNS список не трогает. Старые бэкапы
  (до 680) содержат все шаблонные серверы, поэтому ничего не теряют.
  Норма действует **только для файла LxBox** (`exported_by.app == "lxbox"`):
  так её принял лаунчер в контракт 1.1.134 (BACKUP.md §9 п. 5, D-138 —
  при выпуске стояло D-133, номер был занят, лаунчер перенумеровал;
  TASKS_LXBOX §131). Каталог шаблона у лаунчера другой (нет `opendns_doh`,
  `yandex_dot`), записей `kind: template` в его файле может не быть вовсе —
  бэкап с десктопа снял бы на телефоне серверы, которых пользователь не
  удалял. Файл лаунчера и файл без `exported_by` — слияние, как до 680.
  **Заменено [681](681-dns-servers-uniform-backup-catalog.md)** (контракт
  1.1.135, D-139): файл несёт `dns.template_catalog`, правило снятия одно
  для обоих приложений (тег в каталоге файла, нет записи в файле, нет
  удерживающей ссылки); проверка приложения осталась только в переходной
  ветке для файлов без каталога.
- Debug API `PUT /settings/dns_options/servers` пишет список как есть;
  досева после него больше не будет — поведение становится честным.

### 7. Документация

- `docs/TEMPLATE.md`: секция `dns_options.servers` — «catalog, seeded once»;
  `enabled` в обёртке = состояние при посеве и при добавлении из каталога.
- `docs/USER_GUIDE.md` (EN+RU) и `docs/features/…dns`: удаление серверов,
  каталог, «Add all defaults», подписи «used by».
- `docs/STORAGE.md`: ключ `dns.servers` — признак посева; отсутствие ключа = первый запуск.
- `CHANGELOG.md`: EN+RU, с пометкой, что новые серверы шаблона теперь
  появляются в каталоге, а не в списке.

## Проверка

- Свежая установка: список = 12 серверов шаблона, `safe_dns_dot` выключен,
  ключ `dns.servers` записан. Удалил `opendns_udp` → пересборка, открытие вкладки, рестарт:
  записи нет. (+) → каталог показывает его с `[+ Add]`, Add возвращает.
- Существующая установка (ключ есть, список полный): после обновления
  состав не изменился.
- Debug API `PUT /settings/dns_options/servers` с `[]` → после сборки и
  открытия вкладки список пуст, досева нет.
- Лок: у `google_doh` подпись «used by Shield DNS», тумблер и Delete
  недоступны; удалил `dns_shield` (сменив final/default resolver на другой
  сервер) → `google_doh` свободен.
- `safe_dns_dot` в списке → `google_udp` залочен подписью «used by Safe DNS
  (DoT)»; удалил `safe_dns_dot` → свободен.
- Пикер DNS-сервера в редакторе правила не предлагает удалённые серверы.
- Включение пресета ru-direct после удаления `yandex_dot` из списка:
  сервер появляется как preset-ref (шаг 2), после выключения пресета уходит.
- Unit: `dns_servers_resolver_test.dart` — шаг 3 только при отсутствующем
  ключе, пустой список не досевается;
  новые кейсы локов в `resolved_server`; post-step `domain_resolver`.
- Debug API: `PUT /settings/dns_options/servers` с укороченным списком →
  `GET /config` после сборки содержит ровно его.
- Бэкап: экспорт после удаления `opendns_udp`, импорт на устройстве с полным
  списком → `opendns_udp` снят; импорт старого бэкапа (все 12) → список полный;
  импорт бэкапа лаунчера → шаблонные записи не снимаются.

## Реализация

- Посев: `SettingsStorage.hasDnsServersList()`, шаг 3 `resolveDnsServersList`
  под `!seeded`. Эталоны `test/fixtures/storage/golden/{rich,avd}_v0.config*`
  перезаписаны: снимки v0 не содержат `opendns_doh`/`yandex_dot`, досева
  больше нет, группа `dns_shield` теряет их с предупреждением (п. 5, без
  изменений).
- Локи: `ResolvedServer.usedByList` (`dnsServerListRefs`), `forceIncluded` =
  прежний лок сборки (пресет, правило). Лок по ссылке из списка сборку не
  форсирует: включённый сервер держится включённым; выключенный (состояние
  до 680, например член группы) показывается выключенным и включается, но не
  удаляется. `enabledServerTags` — по `forceIncluded`, как раньше.
- Бэкап: снятие шаблонных записей вне файла — только если в секции файла
  есть серверы (`incoming.servers` не пуст); секция с одними скалярами список
  не трогает, и только у файла с `exported_by.app == "lxbox"` (параметр
  `exportedByApp` у `applyDnsBackup`, из `lx_backup_import.dart` —
  `file.exportedByApp`). Контракт 1.1.134 (синк на лаунчер a05ab921) норму
  принял с этим сужением; тесты — `dns_backup_merge_test.dart`, группа §680
  (файл лаунчера с неполным списком и файл без `exported_by` — записи
  остаются).
- Post-step `healDanglingDnsServerResolvers`
  (`post_steps/heal_dangling_dns_server_resolver.dart`), перед
  `healDanglingDnsResolvers`.
