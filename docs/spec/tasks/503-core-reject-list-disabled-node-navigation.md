# §503 — лист страховки: переход к выключенному узлу вне сборки

| | |
|---|---|
| **Статус** | **Released в v2.25.0** (20.09.2026, ядро `v1.14.1-lx.8`). Реализовано |
| **Дата** | 2026-09-19 |
| **Источник** | дефект §498: одиночный сервер (UserServer), выключенный страховкой, в листе «1 server disabled» — серая неактивная строка без перехода |
| **Связанные** | §498, §501, фича 478 |

## Что было

§498 добавил переход из листа «N servers disabled» в детали узла на вкладке
Diagnostics. Поиск узла шёл по `lastEmittedTagMap` — обратной карте **текущей**
сборки конфига. Выключенный страховкой узел из следующей сборки исключается,
его тег из карты пропадает. Для одиночного сервера (UserServer), добавленного
вставкой sing-box JSON, строка листа становилась серой и неактивной — хотя
узел есть в хранилище с вердиктом `core_rejected`. То же затрагивало узлы
подписки, папки и хопы цепочки после пересборки без тега в карте.

## Что сделано

1. **Идентичность в вердикте.** При `applyVerdict` в `params` вердикта
   сохраняются `source_id` (`ServerList.id`) и `node_key` (идентичность узла
   подписки, bare-тег одиночного сервера, у члена папки — сырой тег,
   уникализированный по папке: `X`, `X-2`, как адрес NODE_LINK §2.2; §510
   M3). Тот же ref пишется в `DisabledNode` прогона. Ключ уникален внутри
   источника — иначе тап по второму тёзке открывал первого.
2. **Поиск узла.** `resolveCoreRejectNode` / `resolveCoreRejectNavigation`:
   сначала ref из `DisabledNode` или из params вердикта в хранилище (по
   тексту причины — только если он однозначен: одна причина бывает у пачки
   узлов, §510 M3); затем
   карта текущей сборки; для старых вердиктов без ref — по emitted-тегу среди
   выключенных узлов всех источников. Хоп цепочки ведёт к владельцу.
3. **Лист.** Строка активна, пока узел найден в хранилище; справа шеврон «›»;
   тап закрывает лист и открывает детали на Diagnostics (§501). Неактивна
   только если узла больше нет (подписка обновилась и узел исчез).
4. Тесты: виджет-тест листа для одиночного сервера, подписки, папки, удалённого
   узла; юнит `core_reject_resolve_test.dart`.

## Критерии приёмки

- Одиночный сервер, выключенный страховкой: строка листа активна, тап →
  `NodeSettingsScreen` на Diagnostics с секцией уведомлений.
- Узел подписки / член папки / хоп цепочки — то же при пустой `lastEmittedTagMap`.
- Удалённый узел — серая строка, без шеврона, тап не работает.
- Старый вердикт без `source_id`/`node_key` — переход по тегу среди
  выключенных.
- `flutter analyze` без новых issues; тесты `core_reject*`, `screens/`,
  `bottom_inset_contract_test.dart`.
