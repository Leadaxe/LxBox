# §658 — «Send HWID» включён по умолчанию

| Поле | Значение |
|------|----------|
| Тип | U (смена дефолта) |
| Статус | I (implemented) |
| Фича | [001-SUBSCRIPTIONS](../features/001-SUBSCRIPTIONS/FUNCTIONS/fetch-identity.md) |
| Дата | 2026-10-17 |
| Связанные | 118F (идентичность фетча; решение №3 «HWID выкл» этой задачей отменено), §289 (свой режим подписки) |

## Проблема

Проверено на подписке Remnawave-провайдера 17.10.2026:

- запрос без `x-hwid` панель всё равно обслуживает, но заводит устройство
  сама, без имени: в боте оно выглядит как «Unknown | Устройство»;
- ключ такого устройства зависит от запроса, а в User-Agent есть версия
  приложения. После обновления LxBox панель видит новое устройство и
  тратит ещё один слот лимита. Об этом пишут пользователи;
- с `x-hwid` и заголовками устройства запись стабильна, получает имя и ОС
  (`SM-S918B | Android`) и обновляется на каждом запросе.

При выключенном по умолчанию HWID обычный пользователь попадает в первый
случай.

## Решение (владелец, 17.10.2026)

1. «Send HWID» в глобальной идентичности включён по умолчанию.
   - Переменная `subscription_send_hwid` отсутствует → включено.
   - Явное `'false'` → выключено. Кто выключил вручную, у того так и остаётся.
2. При старте, если HWID включён, а `subscription_hwid` пуст, заводится
   UUIDv4 и сохраняется. Без этого гейт «HWID непуст» молча снимал бы
   заголовки.
3. Свой режим подписки (§289) не меняется: там действует слепок, и его
   `send_hwid` хранится явно.
4. Подпись тумблера: «On by default.» вместо «Off by default.», переводы
   ru/zh.

Обновлённые установки, где тумблер не трогали, начинают слать HWID со
следующего обновления подписки. Панель с лимитом увидит их как одно новое
устройство (с именем). Безымянное старое устройство пользователь удаляет
в панели сам.
