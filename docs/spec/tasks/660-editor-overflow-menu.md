# §660 — Меню ⋮ редактора JSON: Format, лупа; кнопка переноса не жмётся во время раскладки

| Поле | Значение |
|------|----------|
| Тип | Доработка фичи [019-CONFIG_EDITOR](../features/019-CONFIG_EDITOR/FEATURE.ru.md), согласовано владельцем 17.10.2026 |
| Статус | I (implemented) |
| Дата | 2026-10-17 |
| Связанные | §624 (нативный sora-editor), §649 (кнопка переноса, лупа из редактора, полоса раскладки) |

## Проблема

Владелец, 17.10.2026:

1. Кнопка переноса строк на больших текстах отрабатывает 3–5 с. Полоса
   раскладки (§649) есть, но кнопку можно жать снова, и нажатия копятся.
2. Подписки часто приходят сжатым JSON в одну строку. В просмотрщиках
   (вкладка Source подписки и другие `LxJsonView`) кнопки Format нет: она
   есть только в редактируемых полях.
3. Лупу выделения sora нельзя выключить.
4. Решение владельца: справа вверху редактора меню «три точки», в нём
   Format и настройка лупы; настройка лупы сохраняется.

## Решение

### 1. Кнопка переноса во время раскладки

- После нажатия кнопка переноса недоступна (`onPressed: null`), пока натив
  не закончит раскладку: от нажатия до `layoutBusy(false)` после этого
  переключения. Вместо иконки — маленький `CircularProgressIndicator`
  (тот же размер 18) — сразу, без задержки 300 мс.
- Если натив раскладку не начал (короткий текст, `layoutBusy(true)` не
  пришёл), кнопка снова доступна, как только вернулся вызов `setWordWrap`.
  Исполнитель проверяет по `SoraEditorPlatformView.kt`, в каком порядке
  приходят `setWordWrap`-ответ и `layoutBusy`, и выбирает признак конца так,
  чтобы кнопка не залипла навсегда (страховка — таймаут 30 с).
- `_setWordWrap` сам игнорирует вызов, пока переключение не закончено
  (на случай D-pad/клавиатуры, повторного события до перерисовки).
- Полоса раскладки §649 остаётся как есть.

### 2. Меню ⋮

- В строке кнопок над рамкой, **последней справа** (после `actions`
  экрана), — `PopupMenuButton` с иконкой `Icons.more_vert`, размер 18,
  `VisualDensity.compact`, tooltip `More options`.
- Есть у **всех** `LxCodeEditor` / `LxJsonView` / `LxTextCodeField`, где
  есть хоть один пункт (лупа — пункт всегда, значит меню всегда). Там, где
  строки кнопок раньше не было (нет подписи, кнопок, actions), она
  появляется ради меню — это решение, не побочный эффект.
- Прячется вместе с остальными кнопками на время панели поиска.
- Кнопки Find и перенос остаются кнопками в строке. Кнопка Format из
  строки **убирается** — переезжает в меню.

Пункты, по порядку:

**Format** — виден, когда текст в поле сейчас JSON
(`detectCodeLanguage(...) == json`).
- Редактируемое поле: поведение текущей кнопки Format без изменений
  (`_format()`: JSON5 → JSON с отступом 2, диалог про комментарии, правка в
  undo, снек при битом тексте). Условие `widget.format` сохраняется: где
  `format: false`, пункта нет.
- Только чтение (`LxJsonView`, `readOnly`): форматирует **показ**, хранимое
  тело не трогает. Текст в редакторе заменяется отформатированным; пункт
  становится **Show original** и возвращает исходный текст. Выбор живёт в
  `State`, не сохраняется. Если сверху пришёл новый `text` — показ
  сбрасывается на исходный. Для readOnly Format всегда есть (параметр
  `format` не нужен), когда текст — JSON.
- Комментарии JSON5 в readOnly теряются без диалога (исходник не меняется,
  Show original возвращает всё).
- Большие тела (вкладка Source подписки — мегабайты): разбор и
  форматирование вне главного изолята (`Isolate.run`/`compute`) при длине
  больше 64 КБ.
- **Прелоадер Format такой же, как у переноса** (решение владельца
  17.10.2026): от выбора пункта до конца раскладки нового текста кнопка ⋮
  недоступна и вместо её иконки — тот же `CircularProgressIndicator`
  размера 18, сразу, без задержки; полоса раскладки §649 — как у переноса.
  Признак конца — тот же, что у переноса (п. 1), включая страховку 30 с.
  Повторный Format и перенос, пока идёт одно из двух, не запускаются: одно
  общее состояние «занят» на редактор, его видят обе кнопки. Битый JSON — снек `Failed to parse JSON: %s`, как сейчас.
- После форматирования в просмотрщике с липкими заголовками перенос можно
  оставить как был — многострочный JSON с ними читается и без переноса.

**Magnifier** — `CheckedPopupMenuItem`, лупа выделения sora вкл/выкл.
- Настройка одна на всё приложение, сохраняется в `SettingsStorage`
  (ключ `editor_magnifier`, по умолчанию `true` — как сейчас). Не
  config-significant, без `markConfigDirty`.
- Переключение применяется сразу в текущем редакторе (метод канала
  `setMagnifier {enabled}`) и во всех редакторах, открытых после; уже
  открытые на других экранах подхватывают значение не позже следующего
  пересоздания platform view (держать живой список не требуется).
- Натив: creation param `magnifier` и метод `setMagnifier` —
  `editor.getComponent(Magnifier::class.java).isEnabled = value`.
  `isWithinEditorForcibly = true` (§649) не трогать.
- Значение читается при создании редактора; до чтения — `true`. Чтобы не
  ждать хранилище в `build`, допустим статический кэш в виджете,
  прогреваемый при первом чтении.

### 3. Кэш: Format и перенос не пересчитываются после гашения экрана

Владелец, 17.10.2026: читаешь большое тело, экран гаснет, включаешь —
редактор заново форматирует и раскладывает строки (3–5 с).

**Диагностика (исполнитель, до правки).** На эмуляторе (`-no-window`,
гашение — `adb shell input keyevent 26` дважды) с временным логом выяснить,
что именно происходит при гашении/включении: пересоздаётся ли platform view
(`create`/`dispose` в `SoraEditorPlatformView.kt`), пересоздаётся ли
`State` виджета, меняется ли размер вью (`onSizeChanged`, в том числе
транзитный 0×0), какие `setLayoutBusy` приходят. Итог диагностики — в
раздел «Итог» спеки. Временный лог перед коммитом убрать.

**Решение по итогам диагностики** — по ветке, которая подтвердится:

- **Пересчёт раскладки в нативе при том же тексте и ширине** (транзитный
  размер, повторный `setText`, повторный `isWordwrap`): не запускать
  раскладку, если текст, ширина и режим переноса не изменились; транзитный
  нулевой размер игнорировать.
- **Пересоздаётся `State` / platform view** (Flutter выкинул вью или экран
  перестроился): выбор пользователя и результат форматирования
  восстанавливаются из кэша процесса, а не считаются заново:
  - кэш Format — статический в `lx_code_editor.dart`, ключ — хеш исходного
    текста (+ длина), значение — отформатированный текст; LRU на 4 записи,
    суммарно не больше 16 МБ строк (решение владельца 17.10.2026); новая
    запись вытесняет самые старые, пока сумма не влезет в 16 МБ — одно
    тело до 16 МБ кэшируется, даже если останется в кэше одно; тело больше
    16 МБ не кэшируется — Format для него считается заново; живёт до смерти процесса, на диск не пишется;
  - выбор в просмотрщике (Format/Show original и перенос вкл/выкл) — тот же
    кэш по хешу исходного текста: открыли то же тело снова в этом процессе —
    показ как был. Это уточняет §649 («перенос не хранится»): по-прежнему не
    на диск, но в памяти процесса для того же текста — да.
- Если пересоздаётся и вью, и натив неизбежно раскладывает заново (новый
  `CodeEditor`) — раскладка остаётся, но без повторного Format (из кэша) и
  с той же позицией прокрутки, если её можно вернуть дёшево; в «Итог»
  записать, что именно осталось и почему.

Редактируемые поля: правка пользователя не должна теряться — это уже
обеспечено текстом в контроллере; кэш Format для них не нужен (Format там
одноразовая правка).

### Строки

`More options`, `Format`, `Show original`, `Magnifier` — EN в коде,
переводы ru/zh в `assets/l10n/*/ui.json` (что уже есть — не дублировать).

### Не на Android

Заглушка редактора (не Android) — меню тоже есть; пункт Magnifier ничего не
делает, кроме сохранения настройки.

## Итог

### Сделано

- **Меню ⋮** (`PopupMenuButton`, последним справа в строке кнопок, у всех
  `LxCodeEditor` / `LxJsonView` / `LxTextCodeField`): Format (или Show
  original в просмотрщике) и `CheckedPopupMenuItem` Magnifier. Строка кнопок
  теперь есть всегда. Кнопка Format из строки убрана.
- **Format в просмотрщике** меняет только показ: отформатированный текст
  уходит в натив `setText`, контроллер не трогается (`flush()` при этом
  ничего не забирает); новый текст в контроллере сбрасывает показ. Больше
  64 КБ — `compute(formatJson5)`.
- **Общее «занят»** (`_busy`) на перенос и Format: обе кнопки
  `onPressed: null` / `enabled: false`, вместо иконок
  `CircularProgressIndicator` 18 сразу. `_setWordWrap` при «занят»
  игнорируется.
- **Признак конца раскладки.** В нативе ответ `setWordWrap` уходил раньше,
  чем `layoutBusy(true)`: `setLayoutBusy(true)` sora зовёт из фоновой задачи
  раскладки (`WordwrapAnalyzeTask.compute`, `LineBreakLayout$1.compute`), а
  `false` — на главном потоке после неё. Поэтому натив держит ответ
  `setWordWrap` (и `setText` с `waitLayout: true` — Format / Show original
  просмотрщика) до первого `layoutBusy(false)` после вызова; обе раскладки
  sora всегда ставят хотя бы одну задачу, так что ответ приходит и на
  коротком тексте. Перенос в то же значение отвечает сразу. `dispose`
  отвечает ждущим. Dart ждёт ответ не дольше 30 с. Format редактируемого
  поля (`replaceAll`) раскладывается синхронно — «занят» до ответа на
  `replaceAll`; диалог про комментарии в «занят» не входит.
- **Лупа:** ключ `editor_magnifier` (по умолчанию `true`) в
  `SettingsStorage`, allowlist и бэкап (настройки приложения), STORAGE.md;
  creation param `magnifier`, метод `setMagnifier`. Статический кэш в
  `LxCodeEditorState`, прогрев первым редактором на Android.

### Диагностика гашения экрана (раздел 3)

Эмулятор, release-сборка с временным логом (create/dispose view,
initState/dispose/attach `State`, смена размера вью, каждый
`setLayoutBusy`, `setText` из контроллера). Сценарии: экран Config и
вкладка Source подписки (сжатый JSON 65 КБ, Format + перенос включены);
гашение и включение (`keyevent 26` дважды) с паузой 4 с и 40 с; Home и
возврат в приложение.

- Во всех сценариях после гашения/включения — **ни одной строки лога**:
  platform view и `State` не пересоздаются, размер вью не меняется
  (транзитного 0×0 нет), `setLayoutBusy` не приходит, `setText` не
  уходит. Отформатированный показ и перенос после включения экрана на
  месте, без раскладки.
- Ни одна ветка решения не подтвердилась, поэтому кэш Format и защита от
  пересчёта **не сделаны**: без воспроизведения это был бы код под
  догадку.
- На телефоне владельца причина другая, чем на эмуляторе. Кандидаты:
  смерть процесса за время сна (тогда кэш процесса не поможет), выброс
  поверхности hybrid composition прошивкой. Чтобы различить, нужен logcat
  с телефона за гашение/включение: постоянный лог `SoraEditor`
  (`created id=…`, `setText N chars in X ms`) показывает, создавался ли редактор
  заново, а смена PID в logcat — перезапуск процесса.

### Проверено на эмуляторе

Format / повторный Format в просмотрщике Source подписки, перенос на нём;
лупа выключена — после force-stop и перезапуска пункт без галки, в
`lxbox_settings.json` `editor_magnifier: false` (после проверки включена
обратно). Не проверено: что повторные нажатия переноса не проходят на теле
в мегабайты (на 65 КБ раскладка ~80 мс) и отсутствие лупы при
перетаскивании ручек.
