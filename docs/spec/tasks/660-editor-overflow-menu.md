# §660 — Меню ⋮ редактора JSON: Format, лупа; кнопка переноса не жмётся во время раскладки

| Поле | Значение |
|------|----------|
| Тип | Доработка фичи [019-CONFIG_EDITOR](../features/019-CONFIG_EDITOR/FEATURE.ru.md), согласовано владельцем 17.10.2026 |
| Статус | S (spec) |
| Дата | 2026-10-17 |
| Связанные | §624 (нативный sora-editor), §649 (кнопка переноса, лупа из редактора, полоса раскладки) |

## Проблема

Владелец, 17.10.2026:

1. Кнопка переноса строк на больших текстах отрабатывает 3–5 с. Полоса
   раскладки (§649) есть, но кнопку можно жать снова, и нажатия копятся.
2. Подписки часто приходят сжатым JSON в одну строку. В просмотрщиках
   (вкладка Source подписки и другие `LxJsonView`) кнопки Format нет: она
   есть только в редактируемых полях.
3. Лупу выделения sora нельзя выключить.
4. Решение владельца: справа вверху редактора меню «три точки», в нём
   Format и настройка лупы; настройка лупы сохраняется.

## Решение

### 1. Кнопка переноса во время раскладки

- После нажатия кнопка переноса недоступна (`onPressed: null`), пока натив
  не закончит раскладку: от нажатия до `layoutBusy(false)` после этого
  переключения. Вместо иконки — маленький `CircularProgressIndicator`
  (тот же размер 18) — сразу, без задержки 300 мс.
- Если натив раскладку не начал (короткий текст, `layoutBusy(true)` не
  пришёл), кнопка снова доступна, как только вернулся вызов `setWordWrap`.
  Исполнитель проверяет по `SoraEditorPlatformView.kt`, в каком порядке
  приходят `setWordWrap`-ответ и `layoutBusy`, и выбирает признак конца так,
  чтобы кнопка не залипла навсегда (страховка — таймаут 30 с).
- `_setWordWrap` сам игнорирует вызов, пока переключение не закончено
  (на случай D-pad/клавиатуры, повторного события до перерисовки).
- Полоса раскладки §649 остаётся как есть.

### 2. Меню ⋮

- В строке кнопок над рамкой, **последней справа** (после `actions`
  экрана), — `PopupMenuButton` с иконкой `Icons.more_vert`, размер 18,
  `VisualDensity.compact`, tooltip `More options`.
- Есть у **всех** `LxCodeEditor` / `LxJsonView` / `LxTextCodeField`, где
  есть хоть один пункт (лупа — пункт всегда, значит меню всегда). Там, где
  строки кнопок раньше не было (нет подписи, кнопок, actions), она
  появляется ради меню — это решение, не побочный эффект.
- Прячется вместе с остальными кнопками на время панели поиска.
- Кнопки Find и перенос остаются кнопками в строке. Кнопка Format из
  строки **убирается** — переезжает в меню.

Пункты, по порядку:

**Format** — виден, когда текст в поле сейчас JSON
(`detectCodeLanguage(...) == json`).
- Редактируемое поле: поведение текущей кнопки Format без изменений
  (`_format()`: JSON5 → JSON с отступом 2, диалог про комментарии, правка в
  undo, снек при битом тексте). Условие `widget.format` сохраняется: где
  `format: false`, пункта нет.
- Только чтение (`LxJsonView`, `readOnly`): форматирует **показ**, хранимое
  тело не трогает. Текст в редакторе заменяется отформатированным; пункт
  становится **Show original** и возвращает исходный текст. Выбор живёт в
  `State`, не сохраняется. Если сверху пришёл новый `text` — показ
  сбрасывается на исходный. Для readOnly Format всегда есть (параметр
  `format` не нужен), когда текст — JSON.
- Комментарии JSON5 в readOnly теряются без диалога (исходник не меняется,
  Show original возвращает всё).
- Большие тела (вкладка Source подписки — мегабайты): разбор и
  форматирование вне главного изолята (`Isolate.run`/`compute`) при длине
  больше 64 КБ; на это время пункт недоступен, показывается полоса
  раскладки. Битый JSON — снек `Failed to parse JSON: %s`, как сейчас.
- После форматирования в просмотрщике с липкими заголовками перенос можно
  оставить как был — многострочный JSON с ними читается и без переноса.

**Magnifier** — `CheckedPopupMenuItem`, лупа выделения sora вкл/выкл.
- Настройка одна на всё приложение, сохраняется в `SettingsStorage`
  (ключ `editor_magnifier`, по умолчанию `true` — как сейчас). Не
  config-significant, без `markConfigDirty`.
- Переключение применяется сразу в текущем редакторе (метод канала
  `setMagnifier {enabled}`) и во всех редакторах, открытых после; уже
  открытые на других экранах подхватывают значение не позже следующего
  пересоздания platform view (держать живой список не требуется).
- Натив: creation param `magnifier` и метод `setMagnifier` —
  `editor.getComponent(Magnifier::class.java).isEnabled = value`.
  `isWithinEditorForcibly = true` (§649) не трогать.
- Значение читается при создании редактора; до чтения — `true`. Чтобы не
  ждать хранилище в `build`, допустим статический кэш в виджете,
  прогреваемый при первом чтении.

### Строки

`More options`, `Format`, `Show original`, `Magnifier` — EN в коде,
переводы ru/zh в `assets/l10n/*/ui.json` (что уже есть — не дублировать).

### Не на Android

Заглушка редактора (не Android) — меню тоже есть; пункт Magnifier ничего не
делает, кроме сохранения настройки.

## Проверка

- Тесты виджета (один затронутый файл, например
  `app/test/widgets/lx_code_editor_find_fold_test.dart` или новый
  `lx_code_editor_menu_test.dart`): меню есть; Format в редактируемом поле
  меняет текст; в readOnly Format ↔ Show original; Magnifier пишет
  настройку; кнопка переноса недоступна, пока не пришёл конец раскладки.
- Эмулятор (по разрешению владельца): вкладка Source подписки со сжатым
  JSON — Format/Show original; перенос на большом теле — повторные
  нажатия не проходят; лупа выкл — при перетаскивании ручек лупы нет,
  после перезапуска приложения всё ещё выкл.
