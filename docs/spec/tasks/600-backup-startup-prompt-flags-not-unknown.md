# §600 — Флаги стартовых запросов в бэкапе не считаются «неизвестными ключами»

| Поле | Значение |
|------|----------|
| Тип | B (баг) |
| Статус | N (new) |
| Фича | [017-BACKUP_AND_STORAGE](../features/017-BACKUP_AND_STORAGE/FEATURE.md) |
| Дата | 2026-09-30 |
| Связанные | аудит §591 (017, пункт «Флаги `wizard_*` уезжают в копию…»), §447, §349, §599 |

## Проблема

Флаги «уже спрашивали» стартовых запросов лежат в `vars`
(`SettingsStorage.startupPromptVarKeys`: `wizard_battery_v1`,
`wizard_addtile_v1`, `wizard_update_check_v1`, `notif_perm_prompted_v1`,
`app/lib/services/settings_storage.dart` ~стр. 1030). Экспорт кладёт их в
бэкап вместе с прочими переменными. Импорт их намеренно не применяет (свойство
устройства, §447), но из-за отсутствия в allowlist считает «неизвестными» и
показывает «N unknown keys skipped» почти на любом собственном бэкапе. Пользователь
видит ошибку там, где её нет.

## Решение (владелец, 2026-09-30)

- Экспорт не меняется: флаги остаются в файле (полезны для диагностики).
- Импорт (merge и replace, UI и Debug API `POST /backup/import`) распознаёт эти
  ключи как известные-игнорируемые: не применяет их из файла (как сейчас) и **не
  включает** в список/счётчик отброшенных неизвестных ключей. Никаких
  предупреждений и строк в итоге восстановления из-за них.
- Список берётся из `startupPromptVarKeys` (одно место), без дублирования имён.
- Проверить, что все четыре флага действительно пишутся в экспорт и все четыре
  одинаково обрабатываются импортом (аудит говорил про `wizard_*`; у
  `notif_perm_prompted_v1` другой префикс — убедиться, что он не выпадает).

Документация: в `docs/spec/features/017-BACKUP_AND_STORAGE/FEATURE.md` (и `.ru.md`,
если есть) у P5 (default-deny) и P8 (свойства устройства) дописать, что флаги
стартовых запросов едут в экспорт, при импорте игнорируются и не считаются
неизвестными; в `FUNCTIONS/full-backup-restore.md` — то же и строку §600 в таблицу
задач; в аудите §591 у пункта про `wizard_*` дописать `→ 600`.

## Критерии приёмки

1. Юнит-тест: экспорт → импорт (replace и merge) своего снимка с четырьмя
   флагами → список отброшенных ключей пуст, флаги на получателе равны его
   прежним значениям (из файла не взяты).
2. Юнит-тест: настоящий чужой ключ в том же файле по-прежнему попадает в
   отброшенные (default-deny не ослаблен).
3. Тесты §447 зелёные.
4. `flutter analyze` по проекту чистый.

## Проверка

Затронутые тестовые файлы — по одному. Остальное — CI.
