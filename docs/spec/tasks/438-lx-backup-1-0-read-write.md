## Что и почему

Контракт 1.0 снял маппер между файлом и состоянием лаунчера: запись файла —
запись состояния («метаданные + `body`»). Четыре секции 0.12
(`subscriptions[]`/`servers[]`/`chains[]` + `folder`) свернулись в одну
`sources[]` с `kind`, у папки появилась своя запись с `id`, правило и
DNS-запись несут тело sing-box в `body`, у узла есть `sections`, ссылки на узел
(`hops[]`, `detour`) — объекты `{folder_id?, tag}`.

Шаг 1 — чтение 1.0 вместе с legacy 0.x: каждый вход превращает файл в одни и те
же промежуточные записи, дальше один код слияния (норма §9: второй набор правил
под второй формат дал бы на одном файле два разных состояния). Шаг 2 — запись
1.0 вместо 0.12: лаунчер 1.6.0 читает оба формата и сам пишет только 1.0.

## Что LxBox в 1.0 не выражает и как решено

| Данные LxBox | Решение |
|---|---|
| `import_rules`, `import_rules_enabled`, `on_update_action` подписки | дома в 1.0 нет — `backup_local_only_dropped` (реестр: `side: both`, у LxBox — import-rules и настройки папки), одним предупреждением на подписку |
| `detour_policy` подписки и папки (включая `overrideDetour` источника) | `detour` источника — поле лаунчера, флаги политики шире ссылки — `backup_local_only_dropped` |
| флаги `detour_policy` одиночного узла кроме `overrideDetour`; `tag_prefix` одиночного узла | `overrideDetour` едет `detour` узла; прочее — `backup_local_only_dropped` |
| `ping_url`, `ping_timeout_ms` папки | `backup_local_only_dropped` |
| имя цепочки (`label`) | у записи `chain` 1.0 поля нет — `backup_local_only_dropped` |
| правило вида `json` (§225) | `inline` с телом как есть; массив тел — несколько записей; текст, не разбирающийся в тело, — `backup_local_only_dropped` |
| `srs`-правила DNS; `varValues` и `description` DNS-сервера | `backup_local_only_dropped` одной строкой на секцию |
| DNS-правила вида `template` | не пишутся: это ссылки на правила шаблона, которые сторона заводит сама по своему шаблону, пользовательской настройки в них нет |
| `origin` одиночного узла (`paste`/`manual`, write-only диагностика §219) | не пишется; импорт ставит `manual` |
| исходник члена папки, который не разобрался | `kind: unsupported` с `origin.raw` (импорт возвращает его нечитаемым членом) |

BACKUP.md говорит, что писатель 1.0 `backup_local_only_dropped` не эмитит: у
лаунчера полей без дома не осталось. У LxBox они есть, и реестр после синка
1.0.0 это прямо называет (`side: both`, «у LxBox — import_rules, свои
настройки папки, политика detour источника»), поэтому код остался в писателе.

## Ось правил

Норма (§9 п. 7) — относительный порядок сохраняется, абсолютные номера у
сторон свои. Лаунчер перенумеровывает подряд от 1000. Шаг 1 (86803db6) сделал
так же, и у LxBox это ухудшало то, что идёт ПОСЛЕ импорта. Раскладка шаблона
LxBox: `traffic-processing` 0, `private-ip` 950, `block-ads` 960, `fcm-push`
970, `bittorrent` 980, `vowifi` 990, пользовательская зона 1000–1100,
`ru-inside` 1110, `ru-direct` 1120, `fakeip` 1130, `unknown-traffic` 1150.

Пример — файл LxBox `[tp 0, private-ip 950, block-ads 960, A 1000, B 1001, ru-inside 1110, ru-direct 1120]`:

| | v2.23.2 | шаг 1 (1000+позиция) | сейчас |
|---|---|---|---|
| номера после импорта | 0, 950, 960, 1000, 1001, 1110, 1120 | 1000–1006 | 0, 950, 960, 1000, 1001, 1110, 1120 |
| новое правило из UI (`nextUserRuleNum`) | 1002 — перед `ru-inside` | 1007 — после `ru-direct` | 1002 — перед `ru-inside` |
| включённый позже `fcm-push` (970) | между 960 и 980 | перед `traffic-processing` (1000): `sniff` не первый | между 960 и 980 |

Решение: номер из файла сохраняется (при равных — корневое раньше узлового, как
у сборки), неразмеченные корневые встают в хвост оси, правило секции без номера
остаётся без него (сборка ставит 945). Досев шаблона на загрузке ставит свой
номер только отсутствующему несортируемому `traffic-processing` (0 — голова), и
среди пользовательских правил он не встаёт. Корпус сверяет порядок, а не
номера, — `order_renumbered_preserving_sequence` и `v10_node_sections` зелёные.

## Что не применяется на импорте

По норме BACKUP.md §1 объявленное поле чужой стороны игнорируется молча:
`tag_policy.postfix`, `fold`/`fold_tag`, `detour` источника,
`relays_in_directions`, `skip`, `max_nodes`, `update.auto_refresh`; у узла —
`group`, `service`, `reason` (кроме члена `unsupported`). `folder_id` ссылки у
LxBox не хранится: позиция цепочки и detour — теги конфига, префикс
подставляется в момент импорта; ссылка без контейнера ввозится сырым тегом, и
папка, приехавшая следующим файлом, её уже не подхватит. Исходник `uri` едет как
есть: если имя в ссылке разошлось с `tag`, у члена папки имя будет из ссылки.
Прежняя граница, импортом 1.0 не затронутая: тег нового корневого узла не
уникализируется суффиксом `-2` (§9 п. 2).
