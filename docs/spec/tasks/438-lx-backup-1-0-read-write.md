## Что и почему

Контракт 1.0 снял маппер между файлом и состоянием лаунчера: запись файла —
запись состояния («метаданные + `body`»). Четыре секции 0.12
(`subscriptions[]`/`servers[]`/`chains[]` + `folder`) свернулись в одну
`sources[]` с `kind`, у папки появилась своя запись с `id`, правило и
DNS-запись несут тело sing-box в `body`, у узла есть `sections`. Лаунчер пишет
1.0 чекбоксом в диалоге экспорта и переключит дефолт, когда LxBox выпустит
чтение. Запись 1.0 у LxBox — после миграции хранения (волна 4), экспорт
остаётся 0.12.

Норма §9 требует одно слияние на оба формата: каждый вход превращает файл в
записи, дальше работает общий код. Второй набор правил под второй формат дал
бы на одном файле два разных состояния.

## Отклонения от базового ожидания корпуса

`v10_sources_union` у LxBox расходится с базой в трёх местах, все — граница
модели (класс B по `docs/IDENTITY.md` §4a, поле/вид записи, которого у стороны
нет):

- член папки `de-via-nl` вида `chain` — у LxBox цепочка только корневой
  источник; запись отброшена с `backup_source_kind_unsupported`, состав
  `Europe` = `[local-fr, de-1]`;
- `postfix` подписки — у LxBox поля нет (тег источника — префикс);
- `replace_tags` — свёртки источника в группу у LxBox нет (как в
  `replace_tag_index.expected.lxbox.json`); раннер этот ключ не сверяет.

Override в корпусе заводит его владелец, поэтому ожидание стороны лежит в
`app/test/contract/backup_pending_overrides/v10_sources_union.expected.lxbox.json`,
раннер читает его, пока в корпусе нет своего. Остальные ключи кейса
(`folder_ids`, `chains[].hops`, подписка, корневые узлы) сверяются в полном
объёме.

## Что не применяется и почему

По норме BACKUP.md §1 объявленное поле чужой стороны игнорируется молча:

- `tag_policy.postfix`, `fold`/`fold_tag`, `detour`, `relays_in_directions`,
  `skip`, `max_nodes`, `update.auto_refresh` у подписки и папки; `detour`,
  `group`, `service`, `reason` у узла. `fold_tag` модельного поля не имеет —
  свёртки у LxBox нет;
- `folder_id` ссылки хопа у LxBox не хранится: позиция цепочки — тег конфига.
  Префикс подставляется в момент импорта по папке, найденной в файле или на
  устройстве; ссылка без контейнера ввозится сырым тегом, и папка, приехавшая
  следующим файлом, её уже не подхватит;
- исходник `uri` едет как есть: если имя узла в ссылке разошлось с его `tag`,
  у члена папки LxBox имя будет из ссылки (у корневого узла имя записи — `tag`).

Прежние границы, импортом 1.0 не затронутые: тег нового корневого узла не
уникализируется суффиксом `-2` против занятых имён (§9 п. 2); у подписки
0.x/1.0 не применяются `max_nodes` и `update.auto`.

## Тесты

- корпус `backup/*` (23 кейса): все 0.12-кейсы зелёные без изменения ожиданий;
  `v10_dns_body`, `v10_node_sections`, `v10_rules_body_action` — по базе
  корпуса; `v10_sources_union` — по ожиданию стороны (выше). Сверки проверены
  порчей кода: без перевода `folder_id` по карте падает `chains[].hops`, с
  причиной `kind` вместо `rule_set` падает `warning_reasons`;
- `test/contract/lx_backup_v10_test.dart` (18): версии чтения/записи и отказы;
  ключи 0.12 в файле 1.0; две папки-тёзки файла в пустое состояние и повторный
  импорт; настройки совпавшей папки; папка 0.x не трогает настройки; хоп в папку
  файла, в корень и в отсутствующую папку; секции совпавшего узла (замещение,
  сохранение, снятие) и `@self` по B5; `sections` у подписки, члены папки
  `chain`/`auto`/`unsupported`, корневой `auto`; ось правил (узловое без `num`
  между корневыми, неразмеченное в хвост, 0.x); `method: drop` и `action: sniff`
  видом json; отброс `rule_set`/`srs`/`json`; цель вне известных, preset без
  имени; три preset-сервера DNS и два правила с одним `domain_suffix`,
  повторный импорт без дублей; кодек (`action`, preset `ref`); канон WG-INI;
  причины B3 у секций.

Не проверялось на устройстве: импорт файла 1.0 из диалога экрана бэкапа
(перестановка шагов применения покрыта теми же чистыми функциями, что раннер).

## Вопросы лаунчеру

1. Завести в корпусе `v10_sources_union.expected.lxbox.json` (готовое ожидание —
   в `app/test/contract/backup_pending_overrides/`): член папки `chain`,
   `postfix`, `replace_tags`.
2. `backup_source_kind_unsupported`: в реестре `side: export`, а BACKUP.md §2
   велит читателю отвергать тем же кодом — поправить `side` на `both`; и
   подтвердить этот код для членов папки `chain`/`auto` у стороны, чья модель
   их не держит.
3. Причина отбраковки записи секции, отброшенной строгостью LxBox по
   незнакомому ключу тела (не `rule_set`): сейчас `kind` — нужен ли в перечне
   отдельный `reason`?
4. `ref` preset-сервера DNS у лаунчера формы `<preset_id>:<tag>`, у LxBox
   ссылка — тег сервера пресета: LxBox хранит `ref` как есть (у чужого пресета
   запись станет сиротой) — договориться о форме или оставить.
5. `detour` в BACKUP.md §2 помечен «launcher», а у LxBox есть detour узла и
   источника: переводить в «обе» и применять?
6. Перенумерация оси от 1000 кладёт бывшие широкие перехватчики шаблона
   (1110+) в пользовательскую зону: у LxBox новое правило из UI после такого
   импорта встаёт за ними. Норма это называет — подтвердить, что так и
   остаётся.
