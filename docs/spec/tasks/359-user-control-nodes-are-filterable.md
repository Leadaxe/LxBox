# §359 — Авто-узлы подписок фильтруются как обычные узлы

**Статус:** РЕАЛИЗОВАНО + **DEVICE-VERIFIED** (03.08.2026, эмулятор).
Тесты зелёные (2771 + 16 новых), analyze чист, 4 l10n-чекера 0 failures.

> **Проверка на эмуляторе** (`emulator-5554`, sdk_gphone64_arm64, канал VPN ①,
> 76 узлов, туннель up). Фикстура: 4 авто-группы подписки, все с `balancer{}`
> ⇒ round_robin (`🇵🇱 Польша | Авто⚡`, `🇪🇺 Europe | Auto⚡`,
> `🇪🇺 Europe | Hysteria | Auto⚡`, `🇪🇺 Europe | Game | Auto⚡🕹️`) + шасси
> `vpn-1` / `vpn-1-auto` / `direct-out` / `block`.
>
> 1. **Сам баг** — чип-фильтр `🇫🇮`: все четыре авто-группы ушли из списка
>    (до фикса висели в нём, игнорируя regex). Остались только финские узлы.
> 2. **Шасси** — «Напрямую», «Авто», «Блокировка» остались на месте при
>    активном `🇫🇮`, как и задумано.
> 3. **Чип протокола `Auto`** — появился в ряду рядом с Hy2/MASQUE/Trojan/VLESS;
>    отбирает ровно четыре авто-группы, обычные узлы уходят в non-matching.
> 4. **Чип транспорта `Pool`** — присутствует, `Auto`+`Pool` вместе дают те же
>    четыре группы. `Fastest` в ряду НЕ появился — корректно: чипы собираются
>    из реально присутствующих значений, а least_test-групп в этом конфиге нет.
>
> Ретест least_test-ветки (чип `Fastest`) остаётся на конфиг, где есть
> авто-группа без `balancer{}`.

## Проблема

Фильтр списка узлов пропускает мимо себя ЛЮБОЙ control-узел, включая
пользовательские `urltest`-группы из подписок и папок (§322). Юзер вводит в
поиск `🇫🇮`, а в списке остаются `🇪🇺 Europe | Auto`, `Europe | Game | Auto`,
`Europe | Hysteria | Auto` и «Блокировка» — ни одно из имён под фильтр не
подходит.

Причина — короткое замыкание в `node_list_presenter.dart`:

```dart
if (state.isControlTag(tag) || f.passes(tag)) {
  matching.add(tag);
```

`isControlTag` (`home_state.dart`) — чисто **типовой** признак:
`selector || urltest || ConfigNode.isControl`. Он не различает происхождение
узла, поэтому авто-группа подписки попадает в `matching` мимо regex, чипов
протокола/транспорта/подписки и фильтра по пингу.

Те же три места короткозамыкают и pool-фильтр (detour).

## Модель: три класса узлов в списке

Различение системного и пользовательского в проекте УЖЕ зафиксировано —
pin-логика `_computePinned` пинит не любой `urltest`, а только
`channelAutoTags.contains(n)` (§322, `home_state.dart`), с комментарием
«у узла автовыбора подписки/папки тип тоже `urltest`, но он обычная нода
списка и своего места не покидает». До фильтра этот инвариант не доехал.

| | Селектор канала + его auto | Авто-узел подписки/папки | Обычный узел |
|---|---|---|---|
| regex по имени | не применять | **применять** | применять |
| чип подписки/папки | не применять | **применять** | применять |
| чип протокола/транспорта | не применять | **применять** (`urltest` × mode) | применять |
| фильтр по пингу | не применять | **применять** | применять |
| detour-pool | не применять | **применять** | применять |
| `direct` / `block` / `dns` | всегда видимы | — | — |

**Селектор канала** (`vpn-1`, `vpn-2`) и его auto-двойник (`vpn-1-auto`,
`Channel.autoTag`) — шасси приложения, а не контент. Строка в списке для них =
точка управления каналом; отфильтровав её имя, юзер потерял бы доступ к каналу.
Видимы всегда.

**Авто-узел подписки/папки** (§322) — контент внешнего источника. Живёт в общем
списке наравне с обычными узлами, принадлежит источнику по тому же
prefix-механизму (`sourcesOfTag`), скрывается без потери управляемости. Значит,
чип подписки обязан на него действовать: снял чип источника — его авто-узел
уходит вместе с его узлами.

У авто-узла подписки есть **свой** протокол и транспорт, а не наследованные от
выбранного члена:

- **протокол = `urltest`** — тип группы как он есть в конфиге;
- **транспорт = режим** — `least_test` («быстрейший») либо `round_robin`
  («пул»), см. `UrltestMode` (`channel.dart`) и §344, где режим показан на
  экране деталей именно как параметр узла.

Поэтому чипы протокола и транспорта на него действуют наравне с обычными
узлами, и список от переключения члена группы не «прыгает» — оба свойства
принадлежат самой группе и от выбора члена не зависят.

Наследование протокола выбранного члена (`protocolOfTag` → `urltestNowOf`)
остаётся для СЕЛЕКТОРОВ каналов и не участвует в фильтрации авто-групп: там
протокол действительно менялся бы под юзером при каждом переключении.

## Решение

Новый предикат в `HomeState` — рядом с `isControlTag`, не вместо него:

```dart
/// §359 — control-узел, созданный ПРИЛОЖЕНИЕМ (шасси), а не пришедший
/// контентом из подписки/папки. Фильтр списка короткозамыкает только такие:
/// авто-узел подписки (§322) — обычная нода и фильтруется наравне со всеми.
bool isSystemControlTag(String tag) {
  if (groupLabels.containsKey(tag)) return true;   // селектор канала (vpn-N)
  if (channelAutoTags.contains(tag)) return true;  // его auto-двойник
  // direct/block/dns — по ТИПУ, не по тегу: подписка не может прислать узел
  // такого типа, а теги расходятся ('block' в magic_nodes vs 'block-out'
  // в аллокаторе build_config) — литерал здесь был бы ловушкой.
  final t = activeModel[tag]?.type;
  return t == 'direct' || t == 'block' || t == 'dns';
}
```

Источники обеих величин уже в `HomeState`, проброс не нужен:
`groupLabels` — tag→label каналов из storage `channels[]` (§125);
`channelAutoTags` — `vpn-N-auto` (§322).

`isControlTag` остаётся как есть — он про тип и используется по смыслу типа.

### Протокол и транспорт авто-группы

Сейчас `protocolOfTag` для группы отдаёт протокол ВЫБРАННОГО ЧЛЕНА
(`urltestNowOf`-fallback), а `variantsOfTag` целенаправленно отбрасывает
control-узел (`n.isControl → null`). Для авто-групп это надо развернуть:

- `protocolOfTag(tag)` → `'urltest'`, если узел — авто-группа подписки/папки;
- `variantsOfTag(tag)` → `{'least_test'}` либо `{'round_robin'}` по
  `raw['balancer']` (наличие `balancer{}` ⇒ round_robin — тот же критерий, что
  у `autoGroupLabel` в презентере и у билдера: `balancer` эмитится только под
  round_robin, см. §208).

Fallback «протокол выбранного члена» сохраняется для селекторов каналов.

Следствие: в чипах фильтра появляются опция протокола `urltest` и опции
транспорта `least_test`/`round_robin` — `availableProtocols`/
`availableVariants` в `computeListData` собираются из pool'а тем же кодом,
отдельной правки не требуют. Нужны человекочитаемые лейблы: `protoLabel`
дополнить `'urltest' => 'Auto'`, для режимов — лейблы в духе §344
(«Fastest» / «Pool»), строки по-английски (правило проекта).

## Тесты

`app/test/screens/home/node_list_presenter_test.dart`:

- авто-узел подписки НЕ проходит regex, не совпавший с его именем;
- он же проходит regex, совпавший с именем;
- снятый чип подписки убирает её авто-узел вместе с её узлами;
- чип протокола `urltest` оставляет авто-узел подписки, чип `vless` — убирает;
- чип транспорта `round_robin` оставляет пул-группу и убирает least_test-группу;
- `protocolOfTag` для авто-группы = `urltest` (НЕ протокол выбранного члена);
- `protocolOfTag` для селектора канала по-прежнему = протокол выбранного члена;
- селектор канала и `vpn-N-auto` видимы при любом фильтре;
- `direct`/`block` видимы при любом фильтре;
- фильтр по пингу применяется к авто-узлу подписки.

## Совместимость

Поведение меняется: узлы, которые раньше игнорировали фильтр, теперь ему
подчиняются. Это и есть цель. Персиста/схемы storage не касается.
