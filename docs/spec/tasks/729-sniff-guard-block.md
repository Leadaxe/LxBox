## Problem

Ядро lx.34 меняет две вещи, и обе касаются конфига, который пишет LxBox.

- `lx.quic_sniff_decoy` — ошибка загрузки при любом значении. LxBox пишет этот
  ключ, когда пользователь включил «Anti-sniff decoy».
- Разрез TLS ClientHello на записи для узла с `detour` ядро больше не включает
  само. Конфиг без `lx.sniff_guard` загружается, но TLS-узлы за релеем, который
  перенаправляет по SNI (Xray `sniffing.destOverride` без `routeOnly`),
  перестают подниматься. Ошибки нет, узел выглядит мёртвым.

Обратная сторона старого поведения — issue #215: MASQUE h2 с `detour` в группу,
где выбран `direct`, получал разрез и не поднимался, потому что сеть репортёра
дропает ClientHello, разрезанный на записи. В lx.34 такой путь считается прямым
и стартует без разреза.

## Solution

Решения владельца 14.11.2026; норма общая с лаунчером (контракт 1.1.170).

### Блок по умолчанию

```json
"lx": {
  "sniff_guard": {
    "nodes": { "sni_mismatch": true },
    "tls":   { "method": "record_fragment" },
    "quic":  { "method": "decoy_first_byte",
               "detour_type": { "socks": "never" } }
  }
}
```

- Общая карта `detour_type` и `override` не пишутся — действуют умолчания
  ядра: `direct`, `ssh`, `socks` стартуют без защиты, остальные релеи с
  защитой; узловые ключи сильнее блока.
- `nodes.sni_mismatch: true` — защищаются только узлы, у которых SNI не
  совпадает с адресом сервера. Ключ пишется всегда, значением настройки: ядро
  с lx.34 без ключа считает фильтр включённым, поэтому выключение — только
  явный `false`.
- QUIC через зашифрованные релеи стартует сразу с байтом. Вариант «только по
  доказанной паре» (`"*": "clean"`) отклонён: AmneziaWG путь не учит и остался
  бы без защиты.
- `"socks": "never"` у `quic` — полевой отчёт 06.11.2026: через `socks` с
  UDP-over-TCP байт сам ломал туннель.
- `persist` по умолчанию не пишется (`false` ядра): метки путей живут до
  перезапуска ядра. Включается настройкой; `experimental.cache_file.enabled` в
  шаблоне стоит всегда, поэтому `persist: true` загрузку не роняет.

### Переменные шаблона

Секция **Sniff guard** (chapter `core`, после «TLS Fragmentation»):

| Переменная | Значения | Умолчание |
|---|---|---|
| `sniff_guard_tls` | `record_fragment` / `fragment` / `delay` / `off` | `record_fragment` |
| `sniff_guard_quic` | `decoy_first_byte` / `delay` / `off` | `decoy_first_byte` |
| `sniff_guard_sni_mismatch` | bool | `true` |
| `sniff_guard_persist` | bool, одна на обе секции | `false` |

Секция `tls` / `quic` пишется, только если метод не `off`; при обоих `off`
блока нет, а две bool-настройки неактивны (`#enable`). `nodes.sni_mismatch`
пишется всегда значением `sniff_guard_sni_mismatch`, `persist: true` в обеих секциях — при
`sniff_guard_persist = true`. Пауза метода `delay` — умолчание ядра 300 мс,
переменной нет. `override`, общая карта и `quic.detour_type` — константы
шаблона.

Сняты `quic_sniff_decoy`, `quic_sniff_decoy_send`, `quic_sniff_decoy_outbounds`,
`quic_sniff_decoy_detours`.

### Миграция

Старые значения не переносятся: сохранённые в хранилище или бэкапе значения
снятых переменных сборка не читает (как было с `awg_masquerade`). Включённая и
выключенная приманка дают один результат — новое умолчание
`decoy_first_byte`. Точного соответствия `mode` / `send` / списков типов новой
карте нет.

### Гейт по версии ядра

`app/lib/services/builder/sniff_guard.dart`:

- `applySniffGuardGate` — шаг сборки после шаблона: на ядре ниже
  `1.14.4-lx.34` блок снимается (неизвестный ключ `lx` валит загрузку; разрез
  под `detour` там делает само ядро). Неизвестная версия (пустая строка) — гейт
  не применяется.
- `lx.quic_sniff_decoy` не пишется ни на каком ядре.
- Пре-релиз `lx.34-rc.N` младше `lx.34`: если пин встанет на rc, границу
  `kSniffGuardMinCore` двигать на `rc.1`.

Так `develop` работает на пине lx.33, а бамп пина — отдельный последний шаг.

### Probe-конфиг

Проверка узлов идёт отдельным экземпляром ядра, конфиг собирает
`probe_config.dart` мимо шаблона. Он получает тот же блок из тех же переменных
(`probeSniffGuard`, с фильтром `nodes`), но без `persist` при любом значении
настройки: у probe нет `cache_file`, а
`persist: true` без него — ошибка загрузки. Без блока проба показала бы узел
за сниффящим релеем мёртвым при живом туннеле.

### Что не меняется

- Глобальная секция «TLS Fragmentation» и TLS-политика узла / папки: это
  узловые ключи первого хопа, ядро исполняет их как раньше.
- Сборка по-прежнему не пишет флаги TLS узлу с `detour` и снимает явный
  `tls.fragment` под `detour` (`yieldToBuildDetour`): при `override: false`
  явный ключ узла выключил бы для него блок.
- Пометка в Node Settings под `detour` дополнена: там решает sniff guard.
