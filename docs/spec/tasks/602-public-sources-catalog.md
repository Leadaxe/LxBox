## Задача (владелец, 30.09.2026)

«Сделать страницу-рубрикатор публичных источников подписок, завести в него
все работающие источники с GitHub; в главном README сверху поставить ссылку
(типа „реестр публичных серверов“). В рубрикаторе указать, что он служит для
целей индивидуального тестирования. Про каждый источник — пару слов. Всё на
английском и русском.»

Плюс: добавить в корпус §525 источник
`https://raw.githubusercontent.com/arshiacomplus/v2rayExtractor/refs/heads/main/mix/sub.html`.

## Что сделать

1. **Корпус.** Дописать URL выше в `app/test/fixtures/public_subscriptions/urls.txt`,
   `dart run tool/public_subs/fetch.dart` из корня (доберёт только новый),
   прогон с `LX_CORPUS_PUBLIC=1 LX_CORPUS_REPORT=1 LX_CORPUS_UPDATE_EXPECTED=1`,
   отдельный коммит (как в `docs/testing/PUBLIC_SUBSCRIPTIONS_CORPUS.md` §7).
2. **Рубрикатор** — `docs/PUBLIC_SOURCES.md` (EN) и `docs/PUBLIC_SOURCES.ru.md`
   (RU), ссылки друг на друга в шапке. Содержание одинаковое.
3. **README.** В `README.md` и `README.ru.md` в строку ссылок под бейджами
   (`Download latest release | … | Support the project`) добавить
   `Public servers registry` → `docs/PUBLIC_SOURCES.md` и
   `Реестр публичных серверов` → `docs/PUBLIC_SOURCES.ru.md`.

## Какие источники заводить

Только источники на GitHub (`raw.githubusercontent.com`,
`github.com`) — из корпуса `urls.txt` плюс arshiacomplus.

«Работающий» = на дату проверки все три условия:

- URL отвечает `200` и тело не пустое;
- разбор приложения даёт ≥ 1 узел (число берётся из свежего прогона корпуса,
  `report.json`);
- репозиторий обновлялся не позже 14 дней назад (`pushedAt` или последний
  коммит файла, через `gh api`).

Не прошедшие — в рубрикатор не попадают (отдельного раздела «мёртвые» нет).
Соединение с узлами не проверяется — это запрещено методикой корпуса и в
рубрикаторе прямо сказано, что живость узлов не гарантирована.

## Состав страницы

- **Шапка-оговорка** (первым абзацем, не мелким шрифтом): список собран для
  индивидуального тестирования клиента L×Box — разбора подписок, протоколов и
  транспортов; узлы принадлежат третьим лицам, проект их не держит, не
  проверяет и не рекомендует; доступность, скорость и безопасность не
  гарантируются; использовать только в соответствии с законом страны
  пользователя (как в разделе README «Purpose and terms of use»). Дата
  проверки.
- **Таблица-сводка:** репозиторий (ссылка на `github.com/<owner>/<repo>`),
  файлы-подписки (прямые raw-ссылки, можно несколько на строку), протоколы,
  узлов на дату проверки, как часто обновляется.
- **По разделу на репозиторий:** 1–2 предложения — что это (сборщик из
  Telegram, проверенные списки, белые списки для мобильного интернета РФ,
  зеркало и т. п.), чем выделяется, на что обратить внимание (например,
  Cloudflare Workers, только reality). Брать из README репозитория и из
  содержимого тела, без домыслов.
- **Как добавить подписку в L×Box** — одна строка со ссылкой на User Guide.
- **Благодарность авторам** — одна строка.

## Стиль

Сухо, фактами, без рекламы и оценочных слов («лучший», «надёжный»), без
эмодзи и ИИ-штампов. Русский текст — не подстрочник английского. Номера задач
(§NNN) в тексте страниц не упоминать.

## Критерии приёмки

1. В корпусе есть `arshiacomplus` (`urls.txt`, `index.json`, тело, эталон).
2. Обе страницы существуют, содержание совпадает, в каждой оговорка и дата
   проверки; каждый репозиторий проходит три условия «работающего».
3. Ссылка из обоих README видна в строке ссылок под бейджами.
4. Все ссылки в страницах открываются (проверка `curl -I`).
