## Проблема

`Share dump` писал в корень пака `'app': 'lxbox'` — и всё. Ни версии
приложения, ни версии ядра.

Версия ядра приезжала **случайно**: полем `core_version` внутри элементов
`oom_reports` и `crash_archive`, потому что их туда кладёт само ядро. Нет ни
одного снимка — нет и версии. Версии приложения не было ни при каких условиях.

Практический эффект виден на дампе 4PDA (2026-08-04, разбор в §376): версию
ядра (`1.14.0-lx.17-rc.3`) удалось прочитать только потому, что в паке случайно
оказались пять OOM-снимков. Какая версия APK стоит у пользователя — по дампу
неизвестно вообще, а это первый вопрос при разборе любого репорта: воспроизводить
на текущей сборке или на той, где баг ещё жил.

## Решение

Три поля в корень дампа —
[`dump_builder.dart`](../../../app/lib/services/dump_builder.dart):

| Поле | Источник | Когда null |
|---|---|---|
| `app_version` | `VersionInfo.I.version` — versionName `X.Y.Z` | никогда (fallback `0.0.0` в самом `VersionInfo`) |
| `app_build` | `VersionInfo.I.buildNumber` — versionCode | никогда (fallback `0`) |
| `core_version` | `BoxVpnClient().getCoreVersion()` → `Libbox.version()` | канал не ответил / timeout |

`VersionInfo` инициализируется один раз в `main()` до `runApp`, доступ
синхронный — дополнительного await в сборке пака не появилось.

`getCoreVersion` — статический Go-side метод, **живой туннель для него не
нужен**: версия ядра есть в дампе и при выключенном VPN. Этим он отличается от
`goroutines_stack`, который осознанно снимается только при поднятом туннеле
(§207).

`app_build` берётся не для красоты: при `--split-per-abi` versionCode кодирует
ABI (`ABI×1000 + code`, см. [FDROID.md](../../FDROID.md)), то есть отвечает ещё
и на вопрос «какой именно APK из релиза стоит».

## Область эффекта

Только формат дампа — расширение, не ломающее чтение старых паков. Схема
`Share dump` нигде не зафиксирована как контракт (ни тестов, ни парсера на
стороне разработчика), поэтому добавление ключей ничего не ломает.

Старые паки версией приложения не обзаведутся задним числом — при разборе
архивных дампов версию по-прежнему придётся спрашивать у пользователя. Отмечено
в DIAGNOSTICS.

сделано.
