## Проблема

Ссылка `vpn://` — JSON-профиль клиента Amnezia: в корне `dns1`/`dns2`,
в `containers[]` под-объект протокола с `last_config` (строка JSON:
`mtu` и `config` — текст INI с плейсхолдерами `$PRIMARY_DNS, $SECONDARY_DNS`).
Сегодня и LxBox, и лаунчер хранят в origin узла **производное** — вынутый
INI (`kind: wg_ini`); LxBox ещё и правит его (`_withLastConfigMtu`, замена
DNS). Это нарушает §454: origin не истина, Regen из него не может применить
правила реестра `context.container.mtu` / `context.profile.dns*` (1.1.63),
пользователь в «исходном тексте» видит не то, что импортировал.

**Решение владельца 26.09.2026:** origin узла из Amnezia — сама ссылка
`vpn://` байт в байт, `kind: amnezia_link` (вид уже есть в
`registry/source_kinds.json`). Тело строится распаковщиком с контекстом
контейнера и профиля по правилам реестра; Regen перераспаковывает.
Многоузловой контейнер: общий `raw` + указатель, какой контейнер этого узла.
Уже сохранённые узлы с `wg_ini`-origin не мигрируются (истина потеряна).

## Диагностика

- Декодер: `app/lib/services/parser/amnezia_link.dart` — распаковывает и
  сразу дописывает MTU/DNS в текст INI (~:206–240).
- Вид origin: `app/lib/models/codec/source_record.dart` `originKindOf` (~:175)
  знает `uri | wg_ini | json`; `sourceKindOf` уже отдаёт `amnezia_link`.
- Маппер wireguard `conf`: `mtu_container` (`context.container.mtu`),
  `dns.substitute` (`context.profile.dns1/dns2`) — реестр 1.1.63, движок
  маппера в LxBox читает `context.*` после §556 (волна 2).
- Где Regen/пересборка тела из origin — grep `origin` в
  `app/lib/services/subscription`, `node_document`/`engine`.

## Решение

1. Импорт `vpn://` (вставка, подписка, QR): узел получает
   `origin {kind: amnezia_link, raw: <ссылка как есть>, container: <индекс или
   имя контейнера>}`; форма поля-указателя — согласовать с нормой лаунчера,
   до её выхода — индекс в `containers[]`.
2. Разбор тела из такого origin: распаковщик отдаёт движку маппера INI **как
   в контейнере** плюс `context.container` (объект `last_config` без
   `config`) и `context.profile` (корень без `containers`). Правки текста INI
   в декодере снимаются вместе с их тестами (`_withLastConfigMtu`, подмена DNS).
3. Regen / «исходный текст» узла показывают и перечитывают ссылку.
4. Экспорт/бэкап: origin едет как есть (`BACKUP.md`), читатель со старым
   `wg_ini` продолжает работать.
5. Старые узлы `wg_ini` не трогать; тест на то, что они читаются прежним путём.
6. Документация: параграф в `docs/spec/features/110…` (или где описан §110),
   `CHANGELOG.md` Unreleased.

Правило кампании: имена полей контейнера (`mtu`, `dns1`) в Dart не
появляются — их знает реестр (`context.*`); Dart только отдаёт контекст.

## Риски и edge cases

- Ссылка `vpn://` может быть очень длинной (лимит в декодере) — хранится в
  origin целиком; проверить размер записи и бэкапа.
- Контейнер с несколькими протоколами (awg + wireguard) — по одному узлу на
  под-объект, общий `raw`.
- Голый `vpn://` без JSON-обёртки (`_decodeBareIni`) — контекста нет,
  `container` пуст, правила `context.*` дают «значения нет» без кода.
- identity узла (тег) не должен измениться от смены формы origin — тело то же.

## Верификация

По одному файлу: тесты декодера Amnezia, `source_record`-тесты,
`body_contract_test` (кейсы amnezia в корпусе), `backup_corpus_test`,

то же тело.
