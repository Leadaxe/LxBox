# §477 — vless `encryption`: проверка грамматики ядра, негодное значение отбраковывает узел

## Проблема

`encryption` у vless в ядре — закрытая грамматика, а не свободная строка.
Значение, которое грамматике не соответствует, роняет старт **всего
конфига**: одна негодная строка в одном узле подписки — и VPN не поднимается
ни на одном узле. Приложение сегодня значение не проверяет вовсе.

## Решение — ревизия 1 (действующая)

Владелец: «делаем минимальную проверку просто по форме». Дублировать
разборщик ядра не будем — копия расходится с ядром на бампе и тогда
отбраковывает годные узлы.

Правило реестра для `vless.body.fields.encryption`: значение не пустое и не
точное `none` ⇒ не меньше **четырёх непустых сегментов через «.»**, без
пробельных символов. Иначе — `on_invalid: drop_node`, код
`vless_encryption_invalid` (error, `params: path + value`). Перечисления
метода/вида/RTT, padding, длины и коэффициенты ключей НЕ проверяются.

Правило ловит случай #147 (`got N segments`) и `None`/`NONE`/` none`, которые
ядро принимает за значение и роняет конфиг. Как правило выражено в реестре
(формат или общий атрибут) — решает лаунчер; исполняет санитайзер по телу,
одна запись на ссылку, JSON и Xray. Критерии приёмки ниже действуют в объёме
этой ревизии (юниты — на форму, без веток полной грамматики); строка в
KERNEL.md «сверить при бампе» не нужна — форма с ядром разойтись не может.

## Решение — исходная редакция (не реализуется, справка)

1. Правило живёт в реестре контракта: `format: vless_encryption` у
   `vless.body.fields.encryption`, `on_invalid: drop_node`, код
   `vless_encryption_invalid` (error, `params: path + value`). Пустое
   значение и `none` — как сейчас: поле в тело не кладётся.
   **Узел отбраковывается, поле не снимается:** узел без `encryption` к
   серверу, который его требует, всё равно не подключится, а молча снять
   слой шифрования — тихое понижение защиты.
2. Исполняет санитайзер по ТЕЛУ — одна запись закрывает ссылку,
   JSON-вкладку и (после шага 8 фичи 472) Xray-JSON. Параметр ссылки
   percent-декодирует маппер до проверки.
3. Грамматика — по исходникам ядра (`protocol/vless/lx_encryption.go`,
   `encryption/common.go`), подтверждённая сессией ядра; нормативный текст —
   описание формата в реестре, Dart-реализация совпадает с Go побайтно:

   `mlkem768x25519plus.<native|xorpub|random>.<0rtt|1rtt>[.<padding>…].<key>[.<key>…]`

   - сегментов не меньше 4, пустых нет;
   - padding (0..N до первого ключа): сегмент короче 20 символов, форма
     `int-int-int`; у первого блока ≥100-≥35-≥35; сумма максимумов блоков на
     чётных позициях ≤ 65553;
   - ключей не меньше одного: base64url без `=`, после декода ровно 32 или
     1184 байта;
   - ключ 1184 байта: каждый 12-битный коэффициент первых 1152 байт < 3329
     (то, что в Go делает `mlkem.NewEncapsulationKey768`) — ручной
     распаковкой, без криптобиблиотеки.

   Уточнения ядра (граница padding/ключ, индексация «чётных позиций»,
   регистр, пробелы) вносятся сюда до начала работы.
4. Правило нормативно для пина ядра **lx.8**. В `docs/KERNEL.md` — строка в
   список «сверить при бампе»: `protocol/vless/lx_encryption.go`. Новый метод
   или вид в ядре без правки реестра = годные узлы отбраковываются, поэтому
   сверка обязательна.
5. Синк на коммит лаунчера с форматом (контракт 1.1.9); кейсы корпуса — по
   одному на каждую строку отказа ядра плюс годные (ключ 32, ключ 1184, с
   padding и без, percent-кодированное значение в ссылке).

## Уточнения ядра (сверка по исходникам v1.14.1-lx.8, 18.09.2026)

Источники: `protocol/vless/outbound.go:107`, `lx_encryption.go`
(`parseClientEncryption`), `encryption/common.go` (`ParsePadding`),
`encryption/client.go` (`Init`). Между lx.4 и lx.8 в `protocol/vless/`
коммитов нет. Нормативен текст формата в реестре; здесь — порядок разбора,
который реализация обязана повторить.

0. Точное сравнение ДО trim: `""` и `none` — слой не создаётся. `None`,
   `NONE`, ` none` идут в разбор и отвергаются («1 segments»). Строка из
   пробелов — `empty encryption string`.
1. Вся строка — trim, затем split по `.`; сегментов < 4 — отказ.
2. Сегменты 0–2 НЕ тримятся, сравнение точное, с учётом регистра. Пустой
   сегмент здесь даёт ошибку метода/вида/RTT, не `empty segment`.
3. Сегменты с 4-го — каждый тримится; пустой — `empty segment`.
4. **Padding или ключ — только по длине:** пока не встретился первый ключ и
   длина сегмента (в байтах, после trim) < 20 — это padding, что бы в нём ни
   было; иначе — ключ (base64url без `=`, 32 или 1184 байта = 43 или 1579
   символов), и фаза padding закрыта навсегда. Padding длиной ≥ 20 и короткий
   сегмент после ключа — ветка ключа, отказ по base64/длине. Смешение ключей
   32 и 1184 разрешено; лимитов на длину и число блоков нет.
5. Padding-блок: split по `-`, частей НЕ МЕНЬШЕ трёх (лишние игнорируются),
   первые три непустые, каждая — целое (`Atoi`: ведущий `+` допустим).
6. Первый блок: ≥100, ≥35, ≥35.
7. Блоки с чётным индексом С НУЛЯ (0, 2, 4…) — длины, с нечётным — паузы.
   Сумма `max(y1, y2)` по блокам-длинам ≤ 65553. У пауз — только форма.
8. Ключ 32 байта — любой. Ключ 1184: **768** коэффициентов по 12 бит
   (FIPS 203 ByteDecode₁₂) из первых 1152 байт, каждый < 3329; на 3 байта
   `b0,b1,b2` два значения: `c0 = b0 | (b1 & 0x0F) << 8`,
   `c1 = b1 >> 4 | b2 << 4`. Последние 32 байта не проверяются.
9. Go `RawURLEncoding` молча пропускает `\r`/`\n` внутри сегмента и не
   требует каноничных хвостовых битов. Клиент может быть строже ядра —
   как решит лаунчер в описании формата, так и делаем.

Снаружи отказ выглядит как `initialize outbound[i] vless[tag]: parse
encryption: …` либо `…: initialize encryption: …` — обе роняют старт целиком.

## Критерии приёмки

- корпус зелёный без override;
- юниты на каждую ветку грамматики, включая коэффициент ≥ 3329 и границы
  padding; годные значения из живых подписок (фикстуры app/test с
  `encryption`) проходят — identity-фикстура vless без расхождений;
- узел с негодным `encryption`: отбракован, в списке отбракованных виден код
  с исходным значением; остальные узлы подписки живы;
- узел `origin.kind: json` (дословный, §455): гард сборки тоже не пускает
  негодное значение в ядро — закрыть тестом;
- тесты только затронутых каталогов + прогон без `app/contract`; CI зелёный;
- CHANGELOG (Fixed, со ссылкой на #147), GUARDS.md, PROTOCOLS.md (VLESS —
  encryption), KERNEL.md.
