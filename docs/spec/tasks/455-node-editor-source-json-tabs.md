## Проблема

Вкладка «JSON» экрана узла показывает не источник, а `emit()` модели — копию,
которую модель собрала из `origin.raw`. Пользователь правит копию, Save кладёт
её в `origin.raw` поверх оригинала. Всё, чего модель не знала, пропадает на
этом шаге (issue #140 до §454). После §454 модель знает столько же, сколько
ядро, но принцип остаётся: правится копия, а не источник, и в конфиг ничего
сверх модели попасть не может.

## Решение

### 1. Термины

- **`origin`** — источник узла, `origin.raw` записи или члена папки. Истина.
  Всегда есть, меняется только правкой на вкладке Source.
- **`body`** — кеш: outbound в форме sing-box, как его получит ядро. Выводится
  из источника и не хранится. У узла с `origin.kind: json` кеш равен источнику.
- **`origin.kind`** — выводится из текста (`originKindOf`, правило экспорта
  438): JSON-объект → `json`, WG-INI → `wg_ini`, прочее → `uri`. Единственное,
  от чего зависит поведение; флага режима нет.

### 2. Правило сборки: `json` → дословно

Как у лаунчера (ручной объект `config_json` allowlist не проходит — уходит как
есть). Для записи `server` и члена папки с `origin.kind == json` в конфиг
уходит **объект источника** (`jsonDecode(node.rawSource)` — по §454 это
оригинальный outbound, и для голого тела, и для документа с `sections`, и для
целого конфига с одним узлом), а не `emit()` модели:

| Что | Откуда |
|---|---|
| тело узла | объект источника, ключи как есть — в том числе те, которых модель не знает |
| `tag` | из тела; нет — тег модели. Дальше как у всех: префикс контейнера, `allocateTag` |
| `detour` | ключ тела снимается; detour решает сборка (политика, личный detour члена, родная цепочка) — как у модельного узла |
| звенья родной цепочки (`chained`, целый конфиг с `detour` внутри) | через модель, как раньше |
| подстановка переменных, пост-шаги (fragment, mixed-case SNI, heal fp) | применяются к карте — уровень конфига, не узла |

Гейты модели (§169/§281/§282/§343, naive-фильтр) на таком узле **не работают**:
человек сам написал sing-box-объект. Страховка — ядро: `CheckConfig` при
сохранении (§4). Модель по-прежнему разбирает источник для формы, списка,
identity (§283: тег), предупреждений и диагностики.

Узлы подписок и файловых подписок (`sub_cache/`) — через модель, как раньше:
текст чужой, гейты нужны.

Код: `app/lib/services/builder/verbatim_body.dart` (`verbatimBodyOf(containerRaw, node)`),
вызов в `server_list_build.dart` перед `getEntries`: карта `main` замещается
телом источника. `FolderServers.memberRaws` — raw членов, выровненный с
`nodes` (тот же фильтр, что `memberDetours`).

### 3. Экран узла (`node_settings_screen.dart`)

Вкладки: **Settings · Source · JSON · Diagnostics**. Save в AppBar сохраняет
Source.

**Source** — `origin.raw` как есть, редактируется всегда.

| `origin.kind` | Save |
|---|---|
| `uri` | тег из поля Tag — во фрагмент (`rawWithName`), текст → контроллер, узел перечитывается через модель |
| `wg_ini` | текст как есть (многострочный; тег в INI не подмешивается) |
| `json` | `prepareNodeDocumentForSave` (тег в тело, §435) → **`CheckConfig`** → контроллер. Отказ ядра — снекбар со словами ядра, запись не меняется |

`updateConnectionAt` / `updateMemberAt` принимают любой текст; вид записи
после Save выводится из текста, отдельно не хранится.

**JSON** — только чтение: то, что уйдёт в ядро (без префикса, detour и
пост-шагов сборки — как раньше). У `uri`/`wg_ini` это `emit()` модели, у
`json` — объект источника. Кнопки: Copy; **Edit**:

- `uri`/`wg_ini`: диалог-предупреждение → согласие → `origin.raw` :=
  этот JSON (тег внутри), запись сохраняется через контроллер, вид становится
  `json`, экран переключается на Source. Текст предупреждения: источник
  заменится этим JSON; проверки приложения на узле выключатся, ошибки поймает
  только ядро при сохранении; обратно в ссылку узел не превратится;
  рекомендуем править Source.
- `json`: без предупреждения — просто переход на Source, менять нечего.

Экран узла подписки (`node_inspect_screen`, §302) не меняется: обе его вкладки
только чтение, истина там файл выдачи.

### 4. Проверка ядром — `CheckConfig`

Мост: Kotlin `VpnPlugin` метод `checkConfig` (по образцу `formatConfig`:
статический Go-метод, `Dispatchers.IO`, живой сервис не нужен) →
`{"ok": bool, "error": String?}`; Dart `BoxVpnClient.checkConfig(text)` →
`CoreCheck?` (`null` = мост недоступен: юнит-тест, старый native — сохранение
не блокируется).

Полезная нагрузка — минимальный конфиг из одного узла: тело источника без
`detour` (ссылка на чужой тег ядру неизвестна) под ключом `outbounds` или
`endpoints` по типу узла. `box.New` без inbound'ов законен; проверяет декод
(unknown field, типы), создание outbound'а (отвергнутые naive-опции, битый
REALITY-ключ, неизвестный uTLS-отпечаток). Переменные шаблона (`@vpn_mode` и
т.п.) в теле проверке неизвестны — тело с ними может быть отвергнуто на Save;
известное ограничение, подстановка идёт на сборке.

На сборке повторной проверки нет: Save — единственные ворота. Если ядро
отвергнет тело позже (бамп ядра снял поле), сработает существующий путь
фатала старта с текстом ошибки ядра, где назван outbound.

### 5. Хранение и контракт

Ничего нового: `origin{kind, raw}` как было, `body` не пишется. Импорт бэкапа
лаунчера: его `body` игнорируется, узел перечитывается из `origin.raw` (как
велит BACKUP §9 п.2). Экспорт LxBox: `origin.raw` = JSON — лаунчер такой
объект тоже отдаёт как есть. Паритет семантики без нового поля.

### 6. Что не делается

- Список «что отброшено» под JSON: у `json` отброшенного нет по построению, у
  `uri` сравнивать нечего. Не нужен.
- Кнопка Regen (§439 В1): тело всегда выводится из источника, пересобирать
  отдельно нечего.
- Форма (Settings) для новых полей — нет.

  тело узла из `rawSource`, секции инжектятся.

  голое тело → `{"outbounds":[тело без detour]}`; wireguard → `endpoints`;
