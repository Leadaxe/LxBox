## Проблема

1. В каталоге `dns_options.servers` (`app/assets/wizard_template.json`) записи
   двух поколений. У семи есть vars и поля в редакторе; у четырёх
   (OpenDNS UDP, OpenDNS DoH, Quad9 DoH, Yandex DoT) тело зашито, и в
   редакторе только тумблер и описание: ни Направления, ни адреса не выбрать.
2. Шаблонную запись нельзя взять за основу своей: у `kind: template` в
   редакторе нет поля Tag, JSON-вкладка — превью. Чтобы получить «такой же,
   но свой», пользователь переписывает тело руками в Custom server.

## Ограничение, от которого зависит всё остальное

**Теги каталога заморожены.** Шаг 1 `resolveDnsServersList`
(`post_steps/dns_servers.dart`) снимает запись `kind: template`, тега которой
нет в шаблоне. Переименовать или убрать тег в шаблоне = молча удалить сервер у
всех, у кого он в списке, вместе с выбором vars; плюс `template_catalog` в
чужих бэкапах (§681) начнёт расходиться. Поэтому ревизия только **добавляет**:
vars к существующим записям и новые записи с новыми тегами.

Второе ограничение: значение var по умолчанию = нынешнее тело байт в байт.
Тогда у всех существующих установок конфиг не меняется, появляются только поля.

## 2. Копия из каталога

### 2.1. Сейчас

- `kind: template` — ссылка: тег, `enabled`, `vars`, своё описание. Тело
  приходит из шаблона на каждой сборке. Поля Tag в редакторе нет.
- `kind: preset` — то же для серверов пресета; тег в пространстве пресета
  (`ru-direct:yandex_dot`).
- `kind: inline` — свой сервер, тело в записи; Tag правится, rename
  каскадит по ссылкам (§117 4b).
- Override — inline-запись с тегом шаблонной; в редакторе бейдж и Reset.
  Из UI сейчас не создаётся, приходит из бэкапа/Debug API.

### 2.2. Предложение

Шаблонная и пресетная запись остаются ссылками: правка тела не встраивается
в них. Всё, что выходит за vars, делается в **копии**: новая inline-запись,
тело которой — текущее разрешённое тело оригинала.

**Действие «Duplicate»** (⋮ редактора шаблонного/пресетного сервера и
long-press на тайле, рядом с Delete):

- тело = разрешённое тело оригинала с подставленными vars и
  нормализованным `detour`, как в превью JSON;
- тег = `<тег>_copy`, при занятости `_copy2`, …; у пресетного — без
  пространства пресета (`yandex_dot_copy`);
- описание = `<описание> (copy)`;
- открывается inline-редактор в режиме нового сервера: до Save в список
  ничего не пишется;
- оригинал не трогается: его локи (группа, `dns_final`, правила) остаются
  на нём.

**Поле Tag у шаблонной записи** (пример владельца): поле показывается, но
правка тега не переименовывает ссылку, а переводит Save в «копию»:

- под полем подпись: «Changing the tag creates a custom copy. The template
  server stays in the list.»;
- кнопка Save → «Save as copy»; сохраняется inline с новым тегом, текущими
  описанием и телом (с выбранными сейчас vars), оригинал остаётся как был;
- вернуть исходный тег — Save снова обычный.

Каскада ссылок на копию нет: группа `dns_shield`, `dns_final`, правила
продолжают указывать на оригинал. Переключить их пользователь может сам.

Override-запись UI по-прежнему не создаёт, Reset у полученных из бэкапа
работает как сейчас.

## 3. Предупреждение у Default Domain Resolver

Default Domain Resolver (`dns_default_domain_resolver`, пикер на вкладке
DNS, `dns_settings_tab.dart` ~853) резолвит адреса узлов при установке
соединения, когда туннеля ещё нет. Резолвер через `vpn-1` = круг: адрес
сервера туннеля нужен, чтобы поднять туннель, а запрос за ним ждёт туннеля.

**Условие показа** (по разрешённым телам из списка, с vars):

- выбран одиночный сервер, у которого после нормализации есть `detour`
  (то есть не `direct-out`);
- выбрана группа (`type: group`), у которой **все** эмитируемые члены имеют
  `detour`. Хотя бы один прямой член — предупреждения нет (Shield по
  умолчанию его не показывает: в группе прямые OpenDNS DoH, Yandex DoT,
  Google DoH).

У DNS Final предупреждения нет: его запросы идут при поднятом туннеле.

**Вид** (правка владельца 23.10.2026 после эмулятора): оранжевый ⚠ в строке
заголовка у правого края (над пикером, ширину пикера не меняет), ℹ у
заголовка остаётся (цвет `bannerIconColor(warning)`, как у
предупреждения про `local_dns_resolver`); тап — диалог без значка: заголовок
«Resolver goes through a tunnel» размером основного текста, оранжевым, текст
ниже, кнопка OK. Сборку не блокирует,
выбор не меняет. Текст:

> This resolver sends queries through %s. It is used to look up server
> addresses while the connection is being set up, before the tunnel exists,
> so lookups can fail and the VPN may not connect. A direct resolver is the
> safest choice; for privacy pick a DoT or DoH server.

`%s` — тег Направления (для группы — первое из Направлений членов).
Строка — в l10n по правилам `docs/l10n.md`.

### 2.3. Что не меняется

- Хранение и контракт: копия — обычный `kind: inline`, бэкап и лаунчер её
  уже знают. Синк контракта не нужен.
- Сборка, локи, каталог по (+).

## Решения владельца (23.10.2026)

1. Состав п. 1.1 принят: Outbound у всех серверов, где есть путь (кроме
   System DNS и групп), четырём зашитым — плюс выбор адреса.
2. Дефолты Направлений не трогать: разнобой намеренный — «хоть один да
   сработает» в группе Shield.
3. Расширение каталога — не в этой задаче.
4. Смена тега: оригинал остаётся, рядом появляется копия.
5. Duplicate есть и у пресетных серверов.

## Проверка (после решений)

- Валидатор шаблона зелёный; конфиг сборки с дефолтами для четырёх записей
  совпадает с сегодняшним байт в байт (тест на разрешённое тело каждой).
- Редактор: у четырёх записей появились Outbound и IP; смена значения
  меняет тело в превью JSON.
- Duplicate и смена тега: оригинал на месте с локами, копия inline с
  ожидаемым тегом и телом; эмулятор.
