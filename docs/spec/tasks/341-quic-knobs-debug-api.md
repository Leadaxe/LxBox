## Проблема

На реальных устройствах с вендорским ядром (репро: OnePlus Nord CE 2 / MTK /
Android 15) все quic-go-протоколы (hysteria2, tuic, masque-h3) мертвы внутри
VPN-процесса: каждый dial виснет до `context deadline exceeded`, тест пинга
вечно `-1`. TCP-протоколы, WARP AWG и MASQUE h2 живы. Эмулятор с generic-ядром
не воспроизводит — поэтому вся эмуляторная лестница (v2.19.0 release, dev.9)
была зелёной, и баг долго выглядел «средовым у репортёра».

Корень оказался **в среде сборки AAR ядра**: libbox, собранный Go 1.24.x (так
делал CI), даёт этот дефект; тот же исходник на Go 1.25.x — работает. Разбор,
матрица и фикс CI — в SPEC 044 ядра. Приложение и его конфиг-пайплайн чисты
(эмиссия hy2-аутбаунда сверена байт-в-байт, минимальный конфиг и socks-путь
мертвы одинаково — исключили tun/правила/шаблон).

## Что сделано в LxBox

Диагностическая ручка Debug API, которой закрывали offload-гипотезы (GSO/ECN)
прямо на устройстве без пересборок — и которая остаётся для будущих полевых
диагнозов этого класса:

- `POST /action/quic-knobs?gso=on|off[&ecn=on|off]` — [`action.dart`](../../../app/lib/services/debug/handlers/action.dart):
  `off` = принудительно выключить (env `QUIC_GO_DISABLE_*=true`), `on` =
  вернуть авто-детект (env снят). Меняет только НОВЫЕ QUIC-сокеты — после
  переключения нужен `reload-vpn`/`reset-network`. `native_ok=false` = AAR
  старее SPEC 044 (нет экспорта).
- Мост: `BoxVpnClient.setQuicKnob()` → MethodChannel `setQuicKnob` →
  [`VpnPlugin.kt`](../../../app/android/app/src/main/kotlin/com/leadaxe/lxbox/vpn/VpnPlugin.kt)
  → статические `Libbox.setQuicGSODisabled/-ECNDisabled` (Go-side `os.Setenv`;
  сервис не нужен, вызов безопасен в любой момент).
- `/help` дополнен.

### Решения по месту

| вопрос | решение |
|---|---|
| Почему env-ручки, а не пересборки | quic-go читает `QUIC_GO_DISABLE_GSO/ECN` на каждом новом сокете → A/B переключается двумя HTTP-вызовами на одной установке; цикл проверки — минута вместо получаса |
| Почему static Libbox, а не CommandServer RPC | ручка нужна и без поднятого туннеля; `os.Setenv` не трогает рантайм — RPC-механика избыточна |
| `on` = unset, не `false` | «нетронутое» состояние библиотеки — авто-детект; явный `false` семантически то же, но unset честнее в `/state`-археологии |

## Ход расследования (сжатая хроника, полные логи — сессия 2026-08-02)

1. Десктоп (ядро HEAD и точное lx.17-rc.5) + эмулятор (голый бинарь, v2.19.0
   release APK, dev.9 APK) — hy2-сервер репортёра работает везде → «не
   воспроизводится».
2. CPH2411 проснулся → **воспроизвелось в приложении**: все Hysteria + MASQUE
   h3 = −1 при живых TCP/AWG. Голый android-бинарь ядра с того же телефона без
   VPN — работает.
3. Исключены: конфиг (минимальный PUT /config мёртв так же), tun (socks-in
   мёртв так же), сотовая (off — без изменений), bind_interface.
4. Локальный AAR (go1.25.5) → узел ожил; контрольный откат на dev.9 (CI AAR) →
   снова −1×3; локальный AAR на go1.24.7 (тот же исходник/NDK/машина) → −1×3.
   **Единственная переменная — Go-тулчейн.**
5. На воспроизводящей go1.24-сборке ручками: gso=off → мёртв; ecn=off → мёртв;
   оба off → мёртв. Offload-гипотезы закрыты.
6. Финал: AAR go1.25.5 + ручки (dev.10) — 124/208/159 ms тремя прогонами.

## Верификация

- `/action/quic-knobs?gso=off` на AAR без экспорта → `native_ok:false`, канал
  не падает (ветка старого AAR проверена на dev.9).
- На go1.24-AAR ручки применяются (`native_ok:true`) и реально меняют
  поведение сокетов — подтверждено самим ходом A/B (§выше).
- Регрессий нет: TCP/AWG/MASQUE h2 узлы живы до и после, `dart analyze` чист.

## Остаток

- Бамп пина ядра на релиз с SPEC 044 (lx.19-rc.2+) — тогда фикс приедет всем
  пользователям штатно; ручки станут чисто диагностическими.
- Мёртвые hy2-узлы **подписки** (11 шт.) и MASQUE h3 к этому багу не относятся
  (проверено после фикса: личный сервер жив, они — нет; их реестр — в памяти
  проекта).
