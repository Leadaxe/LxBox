## Проблема

sing-box strict-decode на unknown-field роняет ВЕСЬ конфиг на старте, а
`//`-ключ — распространённая конвенция комментариев в JSON-примерах: юзер
копирует правило из примера с комментариями → приложение не стартует. Два
пути доставки:

1. **Raw-JSON правило** (§225): `_applyJsonSingle` клал тело в
   `route.rules` как есть — `{"//": "…"}` доезжал до ядра.
2. **§302 Replace**: `writeJsonPath` с `target_path` вида `//note` (или с
   таким сегментом в середине) создавал ключ-комментарий в emit-JSON узла.

Ни `validateConfig` (проверяет только ссылки/циклы), ни heal-шаги это не
ловили.

## Решение

По философии §172/§281/§343 — деградация, не fatal:

- **`_stripCommentKeys`** (custom_rules.dart): рекурсивный съём ключей,
  начинающихся с `//`, из тела raw-JSON правила + warning с количеством.
  Правило, ставшее пустым (целиком из комментариев), пропускается — пустой
  объект в `route.rules` ядру тоже не нужен. Рекурсия по всему телу
  безопасна: в `route.rules` нет free-form map'ов (все поля типизированы,
  вложенность — только logical-`rules`).
- **`writeJsonPath`** (import_rule.dart): сегмент `//…` → `false`
  (вызывающий ничего не меняет — существующий контракт функции).

**Прочие unknown-поля не трогаем**: их набор билдеру неизвестен, резать
вслепую опаснее, чем отдать декодеру ядра.

## Тесты

- `test/builder/custom_rules_test.dart`: рекурсивная вычистка + warning;
  правило целиком из комментариев → skip; комментарий-элемент массива
  выпадает, соседи живут.
- `test/subscription/import_rules_test.dart`: `//`-сегмент в начале/середине
  пути отвергается, мапа не мутируется.
