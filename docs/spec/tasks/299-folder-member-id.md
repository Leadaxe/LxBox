# §299 — FolderMember стабильный id вместо позиционных индексов (DEFER, RISKY)

**Тип:** structural refactor (фича [§291](../features/291%20layered-architecture-facades/spec.md)) · **Статус:** spec — **отложено** · **Размер:** L · **Риск:** высокий blast-radius

`FolderMember` не имеет id — каждый мутатор контроллера принимает `int index`,
экраны пересчитывают `entries.indexOf()` перед каждым вызовом, индексы съезжают
под callers. Запатчено ref-снапшотами и orphan-pop-слушателями (§278) вместо
id-based дизайна.

## Проблема

Позиционная адресация — источник целого класса багов (индекс съехал → правка не
той ноды). Лечится симптоматически (ref-снапшоты), не структурно.

## Решение (когда/если)

Стабильный `id` на `FolderMember`; мутаторы адресуют по id, не индексу. Трогает
контроллер + экраны + Debug + Automation (`/folders` адресует по позиции — см.
`folders.dart` шапка). **Deep** — брать только если index-баги повторятся.

## Приёмка (когда возьмём)

- `FolderMember.id` стабилен через remove/reorder/refresh.
- Мутаторы по id; нет `indexOf()` перед вызовом.
- Debug `/folders` адресация по id (breaking для API — согласовать).

Пока: **defer.** Отмечено в §291 как RISKY. Связано: §278 orphan-pop (симптом-фикс).
