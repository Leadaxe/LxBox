## Проблема

Пользователь 4PDA (Android TV, 7.1.1 / API 25):

> в подписках — прокси работают те которые не требуют сертификации
>
> нужно чтобы сертификация была настраиваемой
>
> в NekoBox + есть возможность выбора сертификата chrome firefox система
> система+личный — загрузить скачать сертификаты с гугл

В логе у него — `TLS certification is disabled`, то есть работают только
узлы с `insecure`.

**Причина — протухший trust store прошивки.** Набор корневых CA вшит в
образ Android и на 7.1.1 не обновлялся с 2016 года. Сертификаты, выданные
удостоверяющими центрами более позднего происхождения, в нём
отсутствуют — в первую очередь Let's Encrypt: корень **ISRG Root X1**
старые прошивки не знают, а кросс-подпись через **DST Root CA X3**
истекла 30.09.2021. Итог: TLS-рукопожатие с большинством современных
серверов не проходит проверку цепочки, и узел «не работает» — при том что
сам сервер исправен.

User-impact: на старых Android (5.0–7.1) неработоспособна бо́льшая часть
узлов с настоящим TLS. Обходной путь, к которому пользователь пришёл сам —
`insecure` — **снимает проверку подлинности сервера целиком** и как
рекомендация неприемлем.

## Ключевая находка: в ядре это уже есть

Реализовывать бандлы и «таскать с собой сертификаты» **не нужно** —
sing-box несёт их в себе. `sing-box-lx/option/certificate.go`:

```go
type _CertificateOptions struct {
    Store                    string                     `json:"store,omitempty" enum:"system,mozilla,chrome,none"`
    Certificate              badoption.Listable[string] `json:"certificate,omitempty"`
    CertificatePath          badoption.Listable[string] `json:"certificate_path,omitempty"`
    CertificateDirectoryPath badoption.Listable[string] `json:"certificate_directory_path,omitempty"`
}
```

Это **глобальная** секция конфига (`certificate` верхнего уровня), а не
пер-нодовая — одна настройка чинит все узлы разом.

Проверено по исходникам ядра:

| Факт | Где |
|---|---|
| Бандлы вшиты в исходники ядра | `common/certificate/mozilla.pem` (258 КБ), `chrome.pem` (161 КБ) |
| Генерируются самим ядром | `make update_certificates`, шапка `// Code generated … DO NOT EDIT.` |
| Компилируются **безусловно** | `mozilla.go` / `chrome.go` без build-тегов ⇒ уже внутри нашего APK |
| Системный стор на Android читается через JNI | `common/certificate/system_android.go` (`//go:build android`) |
| `store: system` — дефолт | `UnmarshalJSON`: пустая строка нормализуется в `system` |

То есть достаточно **прокинуть в конфиг одно поле** — код и данные в
ядре уже собраны.

## F-Droid: рисков нет

Опасение «сломать сборку F-Droid своими бандлами» не подтверждается:

- бандлы **не добавляются нами** — они уже часть исходников ядра, которое
  F-Droid и так собирает из исходников (см. [FDROID.md](../../FDROID.md));
- содержимое — публичные корневые сертификаты (Mozilla NSS / Chrome Root
  Store), это открытые данные, а не проприетарные блобы;
- размер APK **не растёт**: `.pem` компилируются в ядро независимо от этой
  таски, наличие или отсутствие UI на это не влияет;
- новых зависимостей и загрузок из сети не появляется.

Формулировку про источник данных стоит вынести в текст-подсказку в UI,
а лицензионную сноску — в `FDROID.md`, если ревьюер F-Droid спросит.

**Что делать НЕ надо:** «скачать сертификаты с гугл», как предлагает
пользователь по аналогии с NekoBox. Загрузка trust store из сети — это и
есть тот случай, который у F-Droid вызовет вопросы (недетерминированный
внешний источник), и он не нужен: актуальный набор уже вшит.

## Решение

Настройка целиком декларативная — **новый Dart-код не нужен**. VPN Settings
(`settings_screen.dart`, вкладка **Core**) рендерит поля прямо из
`wizard_template.json` через `TemplateVarListView`, где `type: enum` уже
даёт выпадающий список (`template_var_list.dart:185`).

### A. Переменная в шаблоне

В `app/assets/wizard_template.json`, секция `general` (`chapter: "core"`) —
рядом с `log_level`. Перевод title/tooltip — в
`app/assets/l10n/ru/template.json` (без него `template_check --strict`
падает предупреждением о непереведённых ключах):

```json
{ "name": "certificate_store", "type": "enum", "wizard_ui": "edit",
  "title": "Certificate store",
  "tooltip": "Root certificates used to verify TLS servers. On old Android (7.x and earlier) the system store is outdated — Let's Encrypt and other modern authorities are missing, so TLS nodes fail to connect. Switch to Mozilla or Chrome to use an up-to-date bundle shipped with the app.",
  "default_value": "system",
  "options": ["system", "mozilla", "chrome"]
}
```

### B. Эмит в конфиг

Секция `certificate` верхнего уровня — рядом с `log` / `dns` / `route` в
корне `"config"` того же файла (строка ~331):

```json
"certificate": {"store": "@certificate_store"}
```

**Реализовано безусловным эмитом** — ключ пишется всегда, включая
`store: "system"`.

Рассматривался условный `#if` (не эмитить дефолт, чтобы не трогать конфиг
у тех, кому фича не нужна), но выбран простой вариант. Размен осознанный:

- для ядра `store: "system"` и отсутствие секции **эквивалентны**
  (`UnmarshalJSON` нормализует пустое значение в `system`) — поведение не
  меняется ни у кого;
- цена — разовый «config changed» при первой пересборке конфига после
  обновления: диффом добавится одна строка. Плашка снимается обычным
  рестартом, данные не теряются;
- выигрыш — нет ветвления в шаблоне и нет зависимости от того, умеет ли
  движок подстановки сравнение с константой.

Если разовый diff окажется нежелательным (например, перед релизом с
большим числом обновляющихся пользователей) — вернуться к `#if`.

### C. `none` — намеренно вне выбора

Ядро поддерживает `store: none` (отключить встроенные корни целиком), но в
UI его **нет**: без своих сертификатов он делает неработоспособными все
TLS-узлы, а пользы обычному пользователю не несёт. Кому действительно
нужно — доступен через Config Editor правкой JSON.

Побочный выигрыш: не нужен ни предупреждающий значок, ни гейт «не
выбирать без загруженных сертификатов» — опасного варианта в списке
просто нет.

### D. Пользовательские сертификаты — отдельно и позже

Импорт своего PEM (`certificate` / `certificate_path`) в этот заход **не
входит**: это второй UI (список, добавление, удаление, файловый пик) при
том что основную боль — протухший системный стор — закрывает уже выбор
бандла. Если понадобится, делать через `pickFileSafely` (§383), а не голый
`FilePicker`, и хранить PEM-строками (см. Риски).

### E. Storage

Значение переменной шаблона персистится существующим механизмом
template-vars — **отдельный ключ в `lxbox_settings.json` не заводится**.
Проверить на реализации, что vars уже покрыты allowlist/export бэкапа
(§221); если нет — довести, иначе настройка потеряется при восстановлении.

### F. Диагностика

Ошибку проверки цепочки ядро отдаёт текстом рукопожатия. Стоит распознавать
характерный случай (`certificate signed by unknown authority` / `x509: …`)
и подсказывать про эту настройку в Debug/варнинге узла — иначе пользователь
снова придёт к `insecure`. Отдельная таска, если разбор окажется объёмным.

## Риски и edge cases

- **`none` вне UI** (см. Решение C) — снимает целый класс рисков: нельзя
  случайно обезоружить проверку и получить «всё сломалось без объяснений».
- **Хранилище своих сертификатов** (когда дойдёт до D): `certificate`
  (PEM-строки прямо в конфиге) проще — не зависит от файловой системы,
  переживает бэкап. `certificate_path` требует живого файла при каждом
  старте ядра и ломается ровно на тех устройствах, где нет нормального
  доступа к файлам (§383). **Предпочесть PEM-строки.**
- **Условный эмит `system`** — главный технический риск таски: если
  движок подстановки не умеет сравнение с константой, `#if` придётся
  обойти (см. Решение B). Проверять дифференциально: с `system`
  сгенерированный конфиг обязан совпасть с текущим.
- **REALITY не затрагивается** — там своя схема проверки, не X.509-цепочка.
- **Проверять на живом старом Android.** На современном API системный стор
  свежий, и разница `system` ↔ `mozilla` не проявится: успешная проверка
  на API 34 **ничего не доказывает** про 7.1.1.
- **Не путать с `insecure`.** Настройка чинит проверку, а не отключает её.
  В UI это должно быть очевидно, иначе пользователи будут выбирать
  «покрепче» наугад.

## Нерешённое / follow-up

- **Импорт своих сертификатов** (Решение D) — отдельной таской, если
  выбора бандла окажется мало. Там же проверить, что `store` + непустой
  `certificate` дают объединение, а не замену: тогда «система + личные»
  получается само, без отдельного значения enum.
- **Распознавание x509-ошибок** с подсказкой на эту настройку (Решение F).
- **`none` через Config Editor** — убедиться, что правка JSON руками не
  затирается пересборкой конфига из шаблона; если затирается, это общий
  вопрос к template-движку, не к этой таске.
