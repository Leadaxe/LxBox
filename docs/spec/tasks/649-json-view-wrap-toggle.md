## Проблема

Просмотрщики JSON с липкими заголовками (`LxJsonView` с `stickyHeaders: true`
и языком JSON) показывают текст без переноса строк: sora-editor 0.23.6
липкие заголовки при переносе не рисует, и §624 отдал приоритет заголовкам.
Компактный JSON в одну строку (вкладка Source подписки, тело Liberty VPN)
уходит вправо, читать его можно только прокруткой вбок.

## Решение

В строке кнопок над рамкой редактора — кнопка переключения переноса строк.

### Где показывается

Только там, где перенос по умолчанию выключен, то есть в `LxJsonView` при
`stickyHeaders: true` и языке JSON (вкладка Source подписки, JSON узла,
инспектор узла, outbound, правило, DNS-сервер — где эти условия выполняются).
Плюс редактор экрана Config (`LxCodeEditor` с `wrapToggle: true`): там тоже
липкие заголовки и перенос выключен (§624, решение 11.10). Дополнение по
жалобе с форума 13.10 («галочку wrap text»), согласовано владельцем
14.10.2026. В остальных редактируемых полях и в просмотрщиках с переносом по
умолчанию кнопки нет.

### Поведение

- Иконка `Icons.wrap_text`, размер 18, `VisualDensity.compact` — как у лупы.
  Порядок: лупа, перенос, затем `actions` экрана.
- Подсказка (tooltip): `Wrap lines` (выключено) / `Unwrap lines` (включено);
  либо одна `Wrap lines` с выделенным состоянием кнопки (`isSelected`) —
  исполнитель выбирает один вариант, переводы ru/zh в `assets/l10n/*/ui.json`.
- По умолчанию перенос выключен (как сейчас). Нажатие включает перенос,
  повторное выключает.
- При включённом переносе липких заголовков нет (ограничение sora), подсветка
  текущей строки выключена — то же, что сейчас делает натив при
  `wordWrap: true`. При выключении возвращается исходный режим: липкие
  заголовки и подсветка текущей строки.
- Переключение на лету, без пересоздания platform view и без потери позиции
  прокрутки сверх того, что делает сама sora при смене раскладки.
- Состояние нигде не хранится: открыли экран заново — перенос выключен.
  Пока виджет жив, выбор держится в его `State`: если platform view
  пересоздаётся (смена темы), текущее значение уходит в creation params.
- На время панели поиска кнопка прячется вместе с остальными (как сейчас).

### Натив

`SoraEditorPlatformView.kt`: метод канала `setWordWrap(bool)` — выставляет
`isWordwrap` и `isHighlightCurrentLine = !wordWrap` (как при создании).
Липкие заголовки (`stickyHeaders`) не трогать: sora сама их не рисует при
переносе.

### Не на Android

Заглушка на `TextField` (тесты, desktop) — кнопка есть, переключает перенос
заглушки, если это дёшево; иначе только состояние кнопки. Виджет-тест:
кнопка есть у `LxJsonView` со sticky JSON, нет у редактируемого поля;
нажатие меняет состояние.

## Дополнение 14.10.2026: жесты и лупа

Согласовано владельцем 14.10.2026 (жалобы с форума 13.10 и владельца).

### Проблема: свайп вбок уводит вкладку

Экран подписки, вкладка Source (и вкладка JSON узла): длинная строка без
переноса не прокручивается пальцем вбок — едет `TabBarView`. После того как
поставишь курсор в строку, начинает работать.

Причина (§628): касание целиком забирает редактор, только если
`_scrollable || _selected`, где `_scrollable` — текст не помещается **по
вертикали**. Горизонтальный выход за поле не учитывается; горизонтальный
распознаватель редактора разыгрывается на равных со свайпом вкладок и
проигрывает.

### Решение: кому жест — по направлению на пороге сдвига

Вместо `_GatedEagerGestureRecognizer` (решение при касании) — распознаватель,
который решает, когда палец сдвинулся на порог (`kTouchSlop`), по направлению
движения:

| Ситуация в момент сдвига | Кому жест |
|---|---|
| В редакторе есть выделение (`_selected`) | редактору целиком — **при касании**, как сейчас (ручки тянут в любую сторону) |
| Горизонтальное движение (\|dx\| > \|dy\|), есть куда вбок (`scrollMaxX > 0`) | редактору целиком |
| Горизонтальное, вбок некуда | вкладкам / странице, как сейчас |
| Вертикальное, в эту сторону есть куда мотать | редактору целиком |
| Вертикальное, редактор в эту сторону у края или текст помещается по высоте | странице |

- Решение — на жест: внутри одного жеста передать остаток странице нельзя
  (жест уже у native view). Довёл текст до края, отпустил — следующий свайп
  в ту же сторону листает страницу.
- Направление «есть куда мотать»: палец вниз (dy > 0) — текст к началу,
  нужно `не у верхнего края`; палец вверх — `не у нижнего края`.
- Принятие редактором на пороге должно случаться не позже, чем вкладки и
  страница примут свой drag (тот же или меньший порог), иначе ничья
  разыгрывается как сейчас.
- Долгий тап (выделение) — как сейчас.
- Набор распознавателей остаётся постоянным (§628: `PlatformViewLink`
  кэширует его), условия читаются на каждом касании из `State`.

### Натив: состояние прокрутки

Кроме `rows`/`rowHeight` натив сообщает в Dart:
- `canScrollX` — `editor.scrollMaxX > 0`;
- `atTop` / `atBottom` прокрутки — `offsetY <= 0` / `offsetY >= scrollMaxY`
  (не путать с существующими `atTop`/`atBottom` события `cursor` — это
  каретка в первой/последней строке; новые поля назвать иначе, например
  `scrollTop` / `scrollBottom`).

Шлёт при изменении (прокрутка — `ScrollEvent` sora, смена раскладки, текста,
переноса), только когда значения поменялись — без потока событий на каждый
пиксель.

### Лупа

Лупа выделения sora на API 26+ копирует кусок окна (`PixelCopy`) по
`getLocationInWindow()` редактора. Под hybrid composition координаты
неверны: в Config после прокрутки лупа белая, в JSON узла после сдвига
страницы показывает строки не из-под пальца. Решение:
`Magnifier.isWithinEditorForcibly = true` — лупа рисуется из самого
редактора. Если на эмуляторе не поможет — лупу выключить
(`Magnifier.isEnabled = false`).

### Индикатор раскладки

Перенос большого тела (одна длинная строка, Source Liberty VPN) натив
считает долго (`WordwrapLayout` в фоне), и всё это время поле выглядит так,
будто кнопка не сработала. Натив шлёт `layoutBusy` {busy} на начало и конец
фоновой раскладки (`setLayoutBusy`), только при смене значения. Flutter
показывает тонкую полосу прогресса у верхнего края рамки поверх текста,
если раскладка не готова за 300 мс; быстрые пересчёты (ввод, смена ширины)
полосой не мигают. Касается всех полей на нативе.

### Кнопка переноса: состояние

Включённый перенос — кнопка на тональной подложке (как
`IconButton.filledTonal`: фон `secondaryContainer`, иконка
`onSecondaryContainer`); выключенный — обычная кнопка.

### Реализация дополнения

- Натив шлёт `scrollState` {canScrollX, scrollTop, scrollBottom} при смене
  значений: на `ScrollEvent` (по конечной точке прокрутки), после `changed`
  (текст, перенос, ширина), смене высоты поля и переключении переноса.
- Распознаватель `LxEditorDragRecognizer`: при выделении (и в поле во всю
  высоту — экран Config, страницы вокруг нет) принимает касание сразу; иначе
  ждёт сдвига больше порога по любой оси и решает по таблице
  (`lxEditorOwnsDrag`). Порог — `min(kTouchSlop,
  MediaQuery.gestureSettings.touchSlop)`: `Scrollable` вкладок и страницы
  берёт порог из `gestureSettings` (на Android меньше `kTouchSlop`).
  Распознаватель platform view стоит первым в маршруте указателя и решает на
  том же событии раньше их. Принятие отдаёт native view всю
  последовательность, включая события до решения (буфер
  `_PlatformViewGestureRecognizer`).
- Отдельный `HorizontalDragGestureRecognizer` из набора убран: вбок, когда
  некуда, жест уходит вкладкам. Жест, который никто не взял (поле без
  страницы вокруг), уходит view по отпусканию пальца, как раньше тап.

### Проверка дополнения (эмулятор)

- Source Liberty VPN (одна длинная строка): свайп вбок по полю прокручивает
  текст, вкладка стоит; свайп вбок вне поля — вкладка.
- Короткий текст без выхода вбок: свайп вбок — вкладка (как сейчас).
- Длинный текст в поле фиксированной высоты: вертикальный свайп листает
  текст; у края следующий свайп в ту же сторону листает страницу.
- Выделение: ручки тянутся в любую сторону, вкладка и страница стоят (§628).
- Config: прокрутка, выделение и лупа после прокрутки вниз — лупа
  показывает текст под пальцем.
- JSON узла: сдвиг страницы, выделение — лупа показывает текст под пальцем.
- Source Liberty VPN: кнопка переноса — пока натив считает раскладку, над
  текстом идёт полоса прогресса; включённая кнопка на тональной подложке.
