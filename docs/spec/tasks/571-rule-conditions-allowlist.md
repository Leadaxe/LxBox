## Проблема

Правило пресета, у которого после подстановки переменных и Dropped-каскада
не осталось ни одного условия, матчит весь трафик (DNS-правило — все
запросы). У LxBox гейт был узким: выпадало только правило, у которого не
осталось `rule_set`. Правило из одного `action` или с выпавшими
`domain_suffix`/`port` уходило в конфиг. Реестр поля-условия не размечал,
общий гейт без списка в коде не выражался (§570, «Нерешённое»).

## Диагностика

Контракт 1.1.81 (§78) объявил списки в `registry/allowlists.json`:
`route_rule_conditions` (поля `RawDefaultRule` ядра без `invert`, плюс `rules`)
и `dns_rule_conditions` (поля `RawDefaultDNSRule` без `invert` и
модификаторов, плюс `rules` и `outbound`). `action` условием не считается.
Go (`core/build/preset_expand.go:hasRuleCondition`) проверяет наличие ключа;
reason у обоих гейтов — `rule_set` (единственное значение reason для этого
случая в описании кода `template_fragment_dropped`).

## Решение

- `app/lib/services/contract/registry.dart`: `allowlists.json` грузится как
  общий файл без `ref`; `allowlistValues(name)` отдаёт значения списка.
- `app/lib/services/builder/preset_expand.dart`: `hasRuleCondition` — в
  правиле есть поле из списка своего вида. Значение `null` и пустой список
  условием не считаются; список объектов (под-правила логического правила)
  считается, если условие есть хоть у одного под-правила. Гейт стоит после
  чистки `rule_set` у route- и dns-правил; при срабатывании —
  `template_fragment_dropped {owner, kind, reason: rule_set}`. Реестр не
  загружен — гейт не срабатывает (как у Go). Имён полей в коде нет.
- Гейты «без outbound/action» и «без server/action» и выпадение по висячему
  `rule_set` не менялись.

## Риски и edge cases

- Строже Go в двух местах: пустой список (`domain_suffix: []`, `rules: []`)
  условием не считается — у Go ключ считается по наличию. Ядро пустой список
  условием тоже не считает, так что LxBox не выпускает правило, которое
  матчило бы всё.
- Висячий `rule_set` у LxBox по-прежнему снимает правило целиком; Go снимает
  только ключ, и правило с другими условиями живёт. Расхождение старое (§555).

## Верификация

- Новый тест в `app/test/services/builder/preset_expand_test.dart`: правило
  из одного `action` выпадает, с `domain_suffix` живёт, логическое с пустыми
  под-правилами выпадает, DNS-правило `predefined` без условий выпадает.
  Тест §219 для DNS получил условие (`query_type`): без него правило теперь
  выпадает по новому гейту.
- По одному файлу: `preset_expand_test` 68/0, `template_contract_test` 118/0,
  `direction_corpus_test` 29/0, `body_contract_test` 169/0,
  `registry_load_test` 12/0.
- Пресеты `app/assets/wizard_template.json` (28 правил) сверены скриптом со
  списками реестра: у каждого правила после раскрытия `#if` есть условие;
  решение ни по одному не изменилось.
