| Связанные spec'ы | контракт 1.1.81/1.1.82 (гейт «правило без условий», TEMPLATE_LANG §5.1) |

## Проблема

1. Гейт «правило без условий» (1.1.81/1.1.82) снимает правило пресета, в
   котором после подстановки не осталось полей-условий. Под него попадает и
   правило, которое автор так и написал: голый `{"action": "sniff"}`, тестовое
   правило на весь трафик. Решение владельца 29.09: такое правило идёт в
   конфиг, снимается только правило, чьи условия убрал сбой.
2. Своё DNS-правило (`DnsRuleInline`, `post_steps/dns_rules.dart`) уходит в
   конфиг как есть, даже если все его ссылки `rule_set` указывают на теги,
   которых нет в `route.rule_set`. `{"rule_set": "x", "server": "y"}` без
   набора `x` либо ломает конфиг, либо (после чистки) превращается в «весь
   DNS на y». Правила пресетов этот паритет уже держат (`preset_expand.dart`).

## Решение

### A. Движок и гейт пресета (§97)

Правило `rules` / `dns_rule` / `dns_rules` пресета, в котором после
подстановки нет ни одного поля из `route_rule_conditions` /
`dns_rule_conditions` (нулевое значение условием не считается):

1. **Условия снял сбой → выпадает с `template_fragment_dropped`**, как
   раньше. Сбой — это: все ссылки `rule_set` висячие, **или** хоть одна
   ссылка на переменную в теле правила дала Dropped либо нулевое значение
   JSON (`null`, `""`, `[]`, `{}`, `false`, `0`). Ссылка — `"@имя"` в
   позиции значения (включая элемент массива и сплайс `text_list`) и вставка
   `@{имя}` в `#tpl`. Признак ставится на всё правило, а не на ключ. Не
   считаются: имена в предикатах `#if`/`#enable`; невыбранные ветки `#if`
   (не обходятся). Необъявленное имя (`"@имя"` или `@{имя}` в `#tpl`) —
   тоже сбой (контракт 1.1.103, `TASKS_LXBOX.md` §100): правило без условий
   выпадает с `template_fragment_dropped` рядом с `template_var_undeclared
   {name}`; вне правил плейсхолдер остаётся как есть.
2. **Иначе → правило идёт в конфиг как есть + код
   `template_rule_unconditional`** (warning, params `owner` — id пресета,
   `kind` — `route.rules` / `dns.rules`). Сюда попадают: правило без условий
   в теле, литерал без значения (`"domain_suffix": []` — ключ остаётся как
   написан), условия только в ложных ветках `#if`.

Порядок гейтов прежний: правило, снятое ложным `#if`/`#enable`, кода не
даёт; «нет `outbound`/`action`» и «нет `server`/`action`» проверяются
раньше и дают `template_fragment_dropped`.

Где: признак «ссылка без значения» — в контексте `if_engine.dart` (где
рождается Dropped у объявленного имени без значения и при подстановке
нулевого значения), наружу — флаг результата подстановки; гейты rule /
dns_rule — `preset_expand.dart`. Новый код показывается в отчёте сборки как
остальные `template_*` (текст — из реестра).

### B. Своё DNS-правило с висячим `rule_set` (§98)

1. Все ссылки `rule_set` своего DNS-правила указывают на теги, которых нет в
   итоговом `route.rule_set` (набор выключен, не скачан, нет в конфиге) →
   правило не эмитится, в отчёт сборки — `template_fragment_dropped`
   (`owner` — имя правила, если есть, иначе `dns_options`; `kind`
   `dns.rules`; `reason` `rule_set`).
2. Висячее имя рядом с живыми — убрать из списка, правило остаётся.
3. Правило не сохранять «по `server`», сняв ссылку.
4. `DnsRuleSrs` без кэша — сейчас пропускается молча; привести к тому же
   исходу (выпадение + код), если это тот же случай «набор не попал в
   конфиг».
5. У `template_fragment_dropped` в реестре дополнены `cause`/`fix` (набор не
   скачан → скачать и пересобрать) — UI берёт тексты из `warnings.json`,
   захардкоженных не заводить.

**Умолчание `required` (решение владельца 29.09.2026).** У переменной
пресета без ключа `required` умолчание — `false`, как у лаунчера
(`WizardVar.fromJson`); обход в раннере корпуса снят. Встроенным переменным
шаблона, которым обязательность нужна (глобали с непустым умолчанием, кроме
`secret`; не-bool переменные пресетов и DNS-серверов), `required: true`
дописан явно; у переключателя пометка «(optional)» не показывается.

## Верификация

- Корпус: `corpus/template/for_each/` — `rule_unconditional_kept`,
  `rule_unconditional_dns_kept`, `rule_conditions_lost_var_dropped`,
  `rule_conditions_lost_rule_set_dropped` зелёные в раннере шаблонов.
- Юнит на B: своё DNS-правило `{"rule_set": "x", "server": "y"}` без набора
  `x` — в `dns.rules` его нет, код есть; `{"rule_set": ["x","z"], …}` при
  живом `z` — правило с `["z"]`.
- Вручную (эмулятор): пресет с `{"action": "sniff"}` → правило в
  `route.rules`, одно предупреждение `template_rule_unconditional`; пресет
  `games` при нескачанном `.srs` → в `route.rules` нет
  `{"network": ["tcp","udp"], "outbound": …}`, `template_fragment_dropped`
  от `games`.

## Дополнение: логическое правило (контракт 1.1.107, 29.09.2026)

Признак сбоя (ссылка без значения) по-прежнему на всё правило; гейт «без
условий» заходит в под-правила `type: logical` на любой глубине — одно
под-правило без условий + сбой → всё правило выпадает с
`template_fragment_dropped`, без сбоя → `template_rule_unconditional`.
Висячие ссылки `rule_set` под-правил чистятся тем же `cleanRuleSetRefsDeep`
при раскрытии пресета (набор не объявлен / `.srs` не скачан) и у
пользовательских DNS-правил (`cleanDanglingDnsRuleSet`); префикс пресета
(`namespacePresetTags`) получают и ссылки под-правил. Кейс
`template/for_each/logical_sub_rule_conditions_lost_dropped`.
