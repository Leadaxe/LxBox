# §251 — Схлопывание «селектор (выбор)» в routing-строках и пикере detour

> **СТАТУС: РЕАЛИЗОВАНО** (06.07.2026). Фидбэк владельца после device-теста
> §248: в Route/Detour-строках detour-канал и выбранный им сервер рендерятся
> как ДВА последовательных хопа (`vpn-4 → 🇳🇱 Нидерланды`), хотя это одна
> точка пути — «канал и кого он сейчас выбрал». Читается как «трафик идёт
> через vpn-4 после Нидерландов» — бред.

## Проблема

Ядро отдаёт цепочки плоскими списками строк без ролей:

```
outbound_chain = ["WARP out", "vpn-1"]           // [node, …селекторы]
detour_chain   = ["vpn-4", "🇳🇱 Нидерланды", "WARP in"]  // селектор, его выбор, транспорт
```

В `detour_chain` элемент-селектор всегда идёт НЕПОСРЕДСТВЕННО перед своим
выбором. UI (§181-нотация) склеивает список через `→` — пара рассыпается в
два «хопа». Перестановка местами не лечит (всё равно два элемента) —
лечит только схлопывание в один: `vpn-4 (🇳🇱 Нидерланды)`.

## Решение (согласовано с владельцем)

**Правило:** элемент цепочки, являющийся известным селектором, схлопывается
со СЛЕДУЮЩИМ элементом в `селектор (выбор)`. Фолд идёт справа налево:
выбор селектора может сам быть селектором (канал в режиме AUTO → его
urltest-двойник → узел) — пары вкладываются:
`vpn-4 (vpn-4-auto (узел))`, реальный узел не остаётся «лишним хопом».
Две независимые пары в цепочке → два схлопывания. Селектор без следующего
элемента — не трогается.

**Признак «селектор»** — НЕ regex, а живые данные приложения (они уже есть
на главном экране): теги групп от ядра (`ccGroups`: tag + selected) с
fallback'ом на каналы из storage (`vpn-N` + `vpn-N-auto`), когда туннель
не поднят. Держатель — синглтон `SelectorInfo.I` (паттерн
`RuleNameResolver.I`): пассивные данные, обновляется из HomeController.
Осознанное исключение из принципа «модель vpn не знает про резолвер»:
продевать набор селекторов параметром через 6 call-site'ов + argless-getter
`routingLine` (dump-writer) хуже, чем пассивный держатель без зависимостей.

**Нотация §181 (`⇒` решение / `:` выход / `→` снаружи) НЕ меняется.**
Порядок хопов НЕ меняется. Единственное изменение — схлопывание пар.

Эталон (реальное соединение, WARP-MASQUE через detour-канал vpn-4):

| Поле | Было | Стало |
|---|---|---|
| Route | `[udp] final ⇒ vpn-1 : WARP out → vpn-4 → 🇳🇱 → WARP in → 142.250.150.132` | `[udp] final ⇒ vpn-1 : WARP out → vpn-4 (🇳🇱) → WARP in → 142.250.150.132` |
| Chain | `WARP out / vpn-1` | без изменений (пар «селектор→выбор» нет: там выбор ПЕРЕД селектором) |
| Detour | `vpn-4 → 🇳🇱 → WARP in` | `vpn-4 (🇳🇱) → WARP in` |
| Rule / Outbound / Outbound type | — | без изменений |

**Область:** везде, где рендерятся цепочки, — фолд в общей модели:
- `TrafficEvent.routingLineOf` (профайлер: detail-карточка, Live-список,
  per-app trace, dump);
- `CcConnection.routingLineOf` (Conns: ряд + detail);
- строка Detour в `routingRows` (§204 — общая секция Routing обоих
  detail-sheet'ов).

**Плюс пикер detour в серверах** (задача — сделать понятным, куда сейчас
поедет трафик):
- запись канала в секции Channels: `⚙ <label> (<selected>)`, когда выбор
  известен (туннель up, есть данные групп); иначе `⚙ <label>` как раньше;
- рендер сохранённого значения (`detourChannelDisplay`) — так же.

## Семантика SelectorInfo

Два раздельных набора тегов с **replace-семантикой** (накопление тегов
прошлых конфигов давало бы ложный фолд ноды-омонима удалённого канала):
`_kernelTags` (замещается каждым push'ем групп — авторитетный снапшот
эмитированного конфига) и `_fallbackTags` (замещается каждым
`refreshChannelLabels` — актуальные каналы storage). `isSelector` = union.

| Событие | Действие |
|---|---|
| push групп от ядра (`_applyGroups`) | `setGroups({tag: selected})` — kernel-теги + выборы, замещение целиком |
| туннель down — ВСЕ ТРИ пути: disconnected-ветка `_handleStatusEvent`, heartbeat-смерть (`_onTunnelDead`), transient-timeout (`_armTransientTimeout`) | `clearSelected()` — выборы протухли, теги остаются (история профайлера продолжает фолдиться). Синтезированные пути обязаны чистить сами: последующий настоящий Stopped проглатывается stale-terminal guard'ом |
| `refreshChannelLabels` (storage) | `setFallbackTags(vpn-N + vpn-N-auto)` — фолд работает и до первого подключения; удалённый канал уходит сразу |

`foldSelectorPairs(chain)` — pure-функция рядом с держателем; списки от
ядра не мутирует (возвращает новый).

## Что НЕ делаем

- Не меняем нотацию §181 и порядок хопов (обсуждался «физический поток» —
  владелец оставил нотацию).
- Не фолдим Chain/outbound_chain (там выбор перед селектором — пары нет).
- Не трогаем сырые данные ядра/Debug API (`/profiler/*` отдаёт списки как
  есть — фолд только в отображении).
