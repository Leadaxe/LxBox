## TL;DR

> **Итог одной строкой: кнопка «протестировать DNS» не реализуется. Задача
> закрыта как Won't-fix.** Документ объясняет _почему_, чтобы её не подняли
> повторно. Разобранная ниже конструкция `TestDNSServer(tag, domain)` —
> **отклонённый** вариант, а не план работ.

## 1. Запрос

Пользователь ([issue #50](https://github.com/Leadaxe/LxBox/issues/50)) попросил
на экране DNS кнопку разового замера латентности всех серверов, чтобы выбирать
лучшую конфигурацию.

## 2. Что уже есть — и чего нет

**Группы.** `getDnsGroups` (kernel SPEC 033/035) отдаёт по каждому члену
`lastRttMs`, `liveErrors`, `lastErrorAgeMs`, `liveWins`; экран DNS рисует их
строкой `google ✓ 12ms ● / quad9 ✗2 (34s)`
([merged_server_tile.dart](../../../app/lib/screens/dns_settings_screen/widgets/merged_server_tile.dart)).
Снапшот берётся **один раз при открытии экрана**, без таймера (решение §312 №2).

**Важно про семантику этих цифр:** ядро **не делает синтетических проб**. Это
статистика по боевым запросам — групповая машина выбора обязана её вести для
своей работы (`fastest` считает победы веера, `stable` уходит с цели по
ошибкам), а наружу она отдаётся как побочный продукт. `lastRttMs` — RTT
последнего реального резолва, на том домене, который в тот момент спросило
приложение.

**Не-группы.** Одиночный `udp://1.1.1.1` в `getDnsGroups` не представлен вовсе:
в ядре нет места, где его RTT хранился бы, — некому и незачем писать.

## 3. Что потребовалось бы

Ядровой `TestDNSServer(tag, domain)` — по тегу **любого** сервера, группа как
частный случай (поштучный обход членов, ср. [§336](336-probe-skips-group-nodes.md)
для узлов-групп). Не
`TestDNSGroup(tag)`: тот повторяет исходную ошибку — привязку измерителя к
групповой машине.

Обязательно **через боевое ядро**, не через probe-сессию: в probe-сессии нет ни
настоящих outbound'ов, ни цепочек детуров (§236), а замер вне живого туннеля
физически не может пройти по `proxy-a`.

## 4. Решение — не делаем

**4.1. Замер по «своему» detour'у — единственно осмысленный, и это снимает
половину задачи.** У каждого DNS-сервера свой `detour`
([dns_servers.dart](../../../app/lib/services/builder/post_steps/dns_servers.dart)),
и это **часть настройки, а не переменная**: сервер, ходящий через `proxy-a`,
ходит через `proxy-a`, другого его состояния не существует. Поэтому исходная
формулировка из issue — «сравнить прямое подключение и через прокси» — некорректна:
она предлагает мерить конфигурацию, которой нет. Одно число на сервер, по его
собственному маршруту. (У групп `detour` запрещён ядром вовсе — §319.)

**4.2. Синтетика меряет не тот домен — и это уже не чинится.** Тест обязан
выбрать один домен и спросить его у всех серверов. Но латентность DNS сильно
зависит от имени: закешированный популярный домен и холодный дают от одного и
того же сервера разные числа, и оба честные. Любой выбранный домен оказывается
тем единственным, который пользователю не важен, тогда как важные — те, что
реально резолвят его приложения, — остаются неизмеренными. Настраиваемый домен
проблему не решает, а перекладывает: у нас DNS часто настраивают доменно-специфично
(§253, §312), и «средний по больнице» замер вводит в заблуждение ровно там, где
конфигурация тоньше всего.

**4.3. Профайлер уже пишет то, что нужно, — и по всем серверам.** `CcDnsQuery`
([cc_channel.dart](../../../app/lib/vpn/cc_channel.dart)) несёт `dnsServer`,
`dnsServerType`, `outbound` (развёрнутая цепочка) и `attempts` с пер-попыточным
RTT — **на всех путях, а не только групповых**. В UI: **Stats → Live**, тап по
DNS-событию → строки `DNS server` и `Attempts`
([traffic_event_detail_sheet.dart](../../../app/lib/screens/stats_screen/traffic_event_detail_sheet.dart)).
Это измеренная латентность по собственному detour'у сервера, на настоящих
доменах, без единого нажатия. Дыра «для не-групп данных нет» существует только в
`getDnsGroups`; в потоке событий её нет.

**4.4. Автовыбор лучшего уже решён.** Группа в режиме `fastest`/`stable` сама
маршрутизирует на лучшего члена и уходит с деградировавших — а это и есть цель,
стоящая за желанием сравнивать латентности руками.

## 5. Отклонено заодно

**Кнопка refresh live-статуса** (перечитать `getDnsGroups` + показать возраст
снапшота). Рассматривалась как дешёвая половина: чисто клиентская, ~20 строк,
без ядра. Отклонена вместе с основной задачей — как подпорка к retest'у она
теряет смысл, а сама по себе, при живом профайлере, добавляет кнопку ради
кнопки. Если протухание цифр на экране DNS когда-нибудь начнёт мешать
самостоятельно — поднимать отдельно и по своим основаниям.
