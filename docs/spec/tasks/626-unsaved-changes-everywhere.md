# §626 — Диалог «Unsaved changes» на всех экранах с явным Save

| Поле | Значение |
|------|----------|
| Тип | Доработка UI (несколько фич: 008-NODE_EDITOR, 019-CONFIG_EDITOR, подписки, DNS) |
| Статус | D (done), выпущено в v2.25.12 |
| Дата | 2026-10-11 |
| Связанные | §219 (общий `showUnsavedChangesDialog`), §624 (диалог на Config, доработка после rc.2) |

## Проблема

Владелец, rc.2: «если что-то наменял, при выходе не спрашивает, сохранить
или нет». Диалог `showUnsavedChangesDialog` (`app/lib/services/ui_helpers.dart`,
Discard / Keep / Save) есть только на части экранов: Direction, правило
маршрута, DNS-сервер, цепочка, автогруппа и (с §624) Config. На остальных
экранах с явной кнопкой Save Back молча теряет правки. Самый заметный —
настройки узла (`node_settings_screen.dart`): вкладки Settings и Source.

## Решение (владелец, 11.10.2026)

Правило для всего приложения: **экран или шторка с явной кнопкой Save и
локальными несохранёнными правками спрашивает при выходе** тем же общим
диалогом и с той же механикой, что соседние экраны (`PopScope` +
`_handleBack`, как в `custom_rule_edit_screen.dart`).

- **Save** — тот же путь, что кнопка Save экрана; при ошибке валидации экран
  не закрывается, ошибка показывается как при обычном Save.
- **Discard** — выйти без сохранения. **Keep** / dismiss — остаться.
- «Есть правки» = текущее состояние формы/текста отличается от того, с чем
  экран открылся или что сохранено последним Save. Вернул как было — диалога
  нет. Текст редактора сравнивается после `flush()` (§624).
- Выход без диалога: правок нет; режим только чтения; идёт загрузка или
  сохранение.
- Все пути выхода: системный Back, жест, стрелка AppBar. Шторка — также
  смахивание вниз и тап по фону (если шторка закрывается так).

## Обязательные места

| Экран | Что считается правкой |
|---|---|
| `node_settings_screen.dart` — настройки узла | поля вкладки Settings (имя, detour, Masquerade и т.д.), текст Source |
| `subscription_detail_screen.dart` — настройки подписки | поля и фильтры, если у экрана явный Save |
| `source_replace_screen.dart` | новый текст источника |
| `dns_settings_screen/user_rule_editor_sheet.dart` — шторка DNS-правила | поля и JSON шторки |
| Edit server в папке (`folder_detail_screen.dart`, диалог) | текст поля |

Исполнитель проходит все экраны с явным Save (`grep -rl 'Icons.save\|"Save"'
app/lib/screens`) и для каждого фиксирует в отчёте: добавлен диалог / уже был
/ не нужен (автосохранение, Save — не выход из экрана, нечего терять) с
причиной. Экраны с автосохранением (настройки приложения и т.п.) не трогать.

## Не делать

- Не менять сам диалог, его строки и стиль (§219).
- Не вводить автосохранение вместо диалога.

## Проверка

Виджет-тест на каждый изменённый экран: правка → Back → диалог; Discard →
закрыт; Keep → остался, правка на месте; Save → сохранено и закрыто; без
правок → без диалога. На эмуляторе: настройки узла — правка имени и правка
Source, Back → диалог; шторка DNS-правила — смахивание с правкой → диалог.

## Ревизия 2 — без редакторов в шторках (владелец, 12.10.2026)

Шторка с правками и своей обработкой смахивания (`unsaved_changes_sheet.dart`)
— обход, а не решение: в других местах редакторы — полноэкранные окна. Решение:

1. **DNS-правило — полноэкранный редактор** вместо шторки
   `dns_settings_screen/user_rule_editor_sheet.dart`, по образцу
   `dns_server_edit_screen.dart` (и `custom_rule_edit_screen.dart`): AppBar с
   заголовком и Save, поле имени, JSON-поле (`LxTextCodeField`) на всю
   оставшуюся высоту с кнопками над рамкой (поиск, Format), диалог «Unsaved
   changes» на Back через `PopScope` + `_handleBack`, как на соседях. Те же
   данные, валидация и путь записи, что у шторки; создание нового правила и
   правка существующего — тем же экраном. Открывается push-маршрутом с
   экрана DNS-правил вместо `showAppBottomSheet`.
2. **Ping Settings — как в rc.2, не трогать** (владелец: «меня полностью
   устраивало как было»). В обязательный список §626 она не входила;
   диалог добавлен исполнителем по своей инициативе и откатывается: Save,
   Reset, вкладки «все»/направление, стандартная шторка со стандартным
   смахиванием, без диалога.
3. **`app/lib/widgets/unsaved_changes_sheet.dart` удаляется** вместе с
   тестами и обращением к защищённому `route.controller`. Других шторок с
   несохраняемыми правками в приложении не остаётся; правило §626 теперь:
   «редактор с явным Save — экран», исключение — короткие шторки настроек вроде Ping Settings, где диалог не нужен.

**Проверка.** Виджет-тесты: экран DNS-правила (создать, править, Save,
битый JSON → ошибка, Back с правкой → диалог, без правки → без диалога);
Ping Settings — тесты §626 сняты, поведение rc.2. Эмулятор: оба места.

## Реализация (11.10.2026)

Механика везде одна: `PopScope(canPop: false)` + `_handleBack` → общий
`showUnsavedChangesDialog`. Шторки открываются с `enableDrag: false` и
оборачиваются в `UnsavedChangesSheet` (`app/lib/widgets/unsaved_changes_sheet.dart`):
штатное смахивание `BottomSheet` (Flutter 3.47) закрывает через
`Navigator.pop` мимо `PopScope`, поэтому жест ведёт обёртка. Она двигает тот
же контроллер анимации маршрута шторки, что и штатный жест (с поправкой на
кривую появления), — шторка и затемнение едут за пальцем. Пороги штатные:
рывок вниз быстрее 700 px/s или шторка видна меньше чем наполовину. Ниже
порога без правок — `Navigator.pop`, маршрут доигрывает закрытие с текущего
места; с правками — контроллер возвращает шторку на место и показывается
диалог. Выше порога — шторка возвращается. Тап по фону идёт через
`maybePop` штатно. (Первая версия закрывала по рывку или трети высоты без
движения шторки за пальцем — заменено 12.10.2026 по замечанию владельца.)
Текст полей формы `flush()` не требует: задержка натива — только у текста
длиннее 256 КБ, а ключа к состоянию редактора у `LxTextCodeField` нет.
