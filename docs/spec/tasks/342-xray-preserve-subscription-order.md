# §342 — Xray-подписка: сохранять авторский порядок узлов

| | |
|---|---|
| Статус | Реализовано, тесты зелёные (2666); девайс-проверка не требуется (чистый парсинг) |
| Дата | 2026-08-02 |
| Связанные | [§321](321-xray-json-parsing/spec.md) (P2 «от одиночных к многоузловым», P4 дедуп, P6 синонимы), [§310](310-xray-element-multi-node.md), [§322](322-xray-auto-select.md) |
| Триггер | Владелец: «мы вольно меняем порядок узлов в подписке, а авторы часто выставляют их специально — надо по возможности сохранять» |

## Проблема

Парсер Xray-массива сортировал элементы по числу серверов
(`_payloadCount`, «сначала одиночные, потом пулы») — и это был единственный
проход, поэтому сортировка определяла и порядок готового списка узлов.

Замер на боевой подписке (37 элементов, тело от `connliberty.com`):
**сместились все 37 позиций**, элемент `🇪🇺 🚀Авто | Лучший сервер ⚡⚡`
уезжал с первого места в конец, а первым в списке оказывалась случайная
`🇨🇭⚡Швейцария`. Между тем порядок в подписке осмыслен: автор ставит
рекомендуемый узел первым, дальше группирует по регионам. В LxBox есть режим
сортировки «как в подписке» — он показывал не авторский порядок, а результат
нашей внутренней сортировки.

## Почему сортировка вообще появилась (и почему её нельзя просто убрать)

§321 P2 решал **задачу имён**, а не порядка. Один сервер обычно встречается
дважды: внутри пула (технический тег `proxy-154-222-9-195-direct`) и отдельным
элементом (`🇩🇪⚡Германия`). Дедуп P4 оставляет первого увидевшего, поэтому
без сортировки узел назывался бы мусорной строкой из пула. Убрать сортировку
«в лоб» = вернуть плохие имена.

## Решение — два прохода

Разводим две задачи, которые раньше решались одной сортировкой:

1. **Черновой проход** (`priming`, результат выбрасывается) — элементы
   отсортированы как раньше, от одиночных к многоузловым. Заполняет `seen`
   (§321 P4) и `synonyms` (§321 P6) и попутно фиксирует **владельца** каждой
   идентичности: `owner[identity] = element`. Право назвать сервер получает
   элемент с осмысленным `remarks`, как и до §342.
2. **Боевой проход** — элементы **строго в порядке файла**. Каждый элемент
   выпускает только те серверы, что закреплены за ним в проходе 1
   (новый параметр `parseXrayElement(ownedBy:)`); чужие пропускаются до
   дедупа. Имена прежние, позиции — авторские.

Ключевая тонкость: боевой проход получает **свой пустой** `seen`. Общий
накопитель к этому моменту полон, и дедуп-`continue` съел бы вообще все узлы —
подписка приехала бы пустой. Ownership передаётся отдельным колбэком.

## Проверка

- Боевое тело подписки до и после: **42 узла в обоих случаях**, имена
  посимвольно совпадают, порядок стал файловым (`🚀Авто | Лучший сервер`
  первым, как в источнике).
- Регресс-тесты §342: пул первым в файле остаётся первым; одиночный после
  пула не всплывает наверх; приоритет имён при этом соблюдён.
- `flutter test` целиком — 2666 зелёных.

## Границы

- Порядок **внутри** элемента (`main` первым: dialerProxy → тег `proxy` →
  первый) не менялся — это контракт §310.
- Узел автовыбора (§322) по-прежнему добавляется ПОСЛЕ своих членов.
- URI-подписки (не JSON) порядок и раньше сохраняли — их путь не затронут.
- Цена: элементы парсятся дважды. На боевой подписке (37 элементов, 42 узла)
  разница незаметна; парсинг идёт вне UI-потока при обновлении подписки.
