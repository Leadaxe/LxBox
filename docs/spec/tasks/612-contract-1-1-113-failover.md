`app/contract/TASKS_LXBOX.md` §106–§110 (после синка). Коротко:

## Решения (Fable, автономно, 08.10.2026)

1. **Синк контракта** ровно на коммит лаунчера `a85af771` (контракт 1.1.113;
   HEAD лаунчера `7c34a986` контракт не меняет):
   `bash app/tool/sync_contract.sh --to a85af771`, затем сверить
   `app/contract/VERSION` = `1.1.113` и `app/contract.lock` (`source_sha`).
   Зеркала `app/assets/contract/` и `docs/contract/` — тем же скриптом, как
   он делает всегда. Только `git archive`, никогда из рабочего дерева лаунчера.
2. **`required_unless`** — примитив санитайзера на уровне обхода полей реестра:
   обязательность отсутствующего поля снимается, если задан путь из `set`
   (от корня тела) **или** в том же объекте не задан сосед из `absent`;
   при снятии, если есть `code`, — info-код без изменения тела. Семантика
   точно по PARSING_PRINCIPLES §6.3 синкнутого контракта; при расхождении
   текста принципов и корпуса истина — корпус.
3. **Авторские тела**: info-код, у которого значение по пути одинаково в сыром
   и чистом теле, идёт без `applied: false` (§6.3).
4. **`failover`**: `enum UrltestMode` + третье значение; кодеки
   `auto_group_record.dart`, `source_replace_record.dart`, `direction`;
   `lx_backup_slice.dart`; формы — `direction_edit_screen.dart`,
   `auto_group_edit_screen.dart`, `source_replace_screen.dart`:
   третий пункт с подписью **«Hold until failure»** (EN, UI только английский),
   при нём ряд Tolerance скрывается. Подзаголовок группы в списке, если он
   показывает режим, — показывает и этот.
   Эмит двойника: `mode: failover`, ключи `tolerance` и `balancer` не пишутся,
   даже если заданы у Направления или подставлены умолчанием.
5. **Миграция от `passive_check` (§611)**: один раз при первом запуске после
   обновления, до первой сборки конфига. Условие — читать сырой ключ
   `urltest_passive_check` из хранилища настроек:
   - ключ `true` **или отсутствует** (прежнее умолчание было true) → все
     авто-группы и Направления с `mode == least_test` переводятся в `failover`;
   - ключ `false` → ничего не менять;
   - группы с `round_robin` не трогаются ни при каком значении;
   - после миграции ключ `urltest_passive_check` удаляется из хранилища, а
     `@Deprecated`-геттер из §611 — из кода.
   Умолчание режима для **новых** авто-групп и Направлений — `failover`.
   Основание: релиз ядра lx.12 называет `failover` явной заменой того, что
   `passive_check` делал неявно; энергетический эффект §272/§273 сохраняется
   (одна проба в `interval` вместо N).
   **Подтверждено владельцем 08.10.2026:** умолчание `failover` оставить,
   хотя это не эквивалент `passive_check` (перевыбор самого быстрого в простое
   не происходит). Довод: пользователь может переключить узел руками или
   запустить ручной тест группы.
6. **Коды отчёта сборки** `group_default_dropped` и `node_detour_through_group`
   — через реестр предупреждений (`registryCause`/`registryFix`), в
   `lastBuildWarningsByTag` и карточку уведомлений узла/источника. Для
   `node_detour_through_group` адресат — источник (подписка) узла, одна
   запись на пару (источник, группа).
7. Проверка §105 (1.1.108): эмит MASQUE не пишет `idle_timeout: 0` там, где
   ключа у узла нет. Если пишет — починить здесь же.

## Порядок и ограничения

- Сначала синк (п. 1) отдельным коммитом, потом код. Корпус после синка
  обязан быть зелёным целиком **к моменту push** — промежуточные красные
  коммиты в develop не пушить.
- `app/contract/**` после синка — read-only: код подгоняется под фикстуры, не
  наоборот. Если кейс корпуса противоречит постановке — доложить, не править.
- Перед push убедиться, что `origin/develop` уже содержит §611
  (`app/android/libbox.version` = `v1.14.2-lx.12`): `failover` знает только
  ядро lx.12. Если §611 ещё не влит — не пушить, доложить.
- `backup-0.12.schema.json` заморожена, не правится.

## Итог

1. Синк ровно на `a85af771`: `VERSION` 1.1.113, `contract.lock`
   `source_sha` = `a85af771…`, зеркала `app/assets/contract/` и
   `docs/contract/` — тем же скриптом, отдельным коммитом.
2. `required_unless` — примитив санитайзера (`_requiredLifted` в
   `body_sanitizer.dart`, геттер `FieldSchema.requiredUnless`): `set` — по
   снимку санитайзера, у не обойдённого — по исходному телу (§6.2); `absent`
   — сосед по чистой карте объекта или по исходной. `field_missing` теперь
   несёт `path` (как Go `requiredFailed`); пир без обязательного поля снимает
   узел ЯВНО (`explicitDropNode`) — подписка роняет его при разборе
   (`dropped[]`). Разбор sing-box-JSON больше не отбрасывает пир без адреса
   кодом `protocol_unsupported`; эмит не пишет пустые `address`/`port` пира;
   ссылка с пустым хостом не строится (эмиттер движка: объявлен источник
   `host`, а он пуст → пустая строка, «This node cannot be shared as a link»).
3. Авторское тело: info-код без правки идёт без `applied: false`
   (`body_edit.dart`, `_infoWithoutEdit`). Исключение — `max_when.note_code`
   (`awg_mtu_high`): правка была, её отменило `except_sources`, корпус ждёт
   `applied: false`.
4. `UrltestMode.failover`; кодеки — через `fromWire`/`wire`; эмит двойника,
   свёртки и узла автовыбора — `mode: failover` без `tolerance` и
   `balancer`. Формы: третий пункт «Hold until failure» (у узла автовыбора —
   рядом с Manual), Tolerance скрыт; подзаголовок группы `📌 [N]`, чип
   фильтра `Hold`. Новый автовыбор формы — `kNewAutoMode` (= failover);
   запись без `mode` читается `least_test` (умолчание схемы).
5. Миграция `SettingsStorage.migrateUrltestModeIfNeeded` в `main.dart` после
   seed Направлений и до первого билда; маркер `urltest_mode_migrated`
   (allowlist + экспорт с Routing, как `directions_migrated`). Геттер
   `getPassiveCheck` удалён.
6. `group_default_dropped` — запись на группу (ручной род в
   `server_list_build.dart` и правило 3 граф-санитайзера),
   `node_detour_through_group` — запись на пару (источник, группа) из пар
   правила 4. Строка отчёта — заголовок реестра + `[code]`, запись — в
   `BuildResult.buildCodes` и в `lastBuildWarningsByTag` адресата.
   Граф-санитайзер без колбэков пишет прежние строки (его юнит-тесты не
   менялись). Эталон `rich_v0.config_warnings.json` перезаписан.
7. MASQUE: эмит пишет `idle_timeout` только при непустом значении узла;
   разбор JSON и ссылки без ключа дают пустое; мастер WARP переводит `≤0` в
   «нет ключа». Правки не потребовалось.

## Нерешённое / хвосты

- Адресат `node_detour_through_group` — источник, но отдельного канала
  предупреждений источника в UI нет: запись ложится на карточку каждого
  выброшенного узла (по его config-тегу) и в отчёт сборки; значок строки
  источника её не учитывает.
- Группы urltest из тела подписки режим по-прежнему не переносят
  (`singbox_config.dart`, «режим — наше расширение»): `mode: failover` от
  провайдера читается `least_test`. Миграция их не касается — они не
  хранятся.
- Бэкап, сделанный до §612, восстанавливается без маркера: при следующем
  старте его группы `least_test` мигрируют (значение `passive_check` из
  такого бэкапа не берётся — §611).
- Для лаунчера: `authored/soft_awg_mtu_high_kept` ждёт `applied: false` у
  info-кода, хотя значение по пути в сыром и чистом теле одинаково (1420);
  у Go это даёт `reflect.DeepEqual(float64, int)` в `samePathValue`, а не
  правило §6.3. У нас — явное исключение `max_when.note_code`; стоит
  записать его в §6.3.
- Исключение `awg_mtu_high` снято после контракта 1.1.114 (9cc7d144):
  лаунчер исправил сравнение (числа по величине), кейс ждёт код без
  `applied: false`; в Dart сравнение по пути — `sameJsonValue` в
  `body_edit.dart`, задача 616.

- Исправлено (эмуляторный прогон): `POST /directions` с `auto` без `mode`
  создавал Направление `least_test` — обработчик брал базу `DirectionAuto()`
  с умолчанием кодека. Теперь при отсутствующем `auto` у Направления (POST
  или первый PATCH с `auto`) база — `kNewAutoMode`; запись с уже
  сохранённым `auto` мержится как раньше, кодек чтения не менялся.
