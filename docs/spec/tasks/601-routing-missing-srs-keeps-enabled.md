# §601 — Экран Routing не выключает правило из-за нескачанного набора

| Поле | Значение |
|------|----------|
| Тип | B (баг) |
| Статус | N (new) |
| Фича | [004-ROUTING](../features/004-ROUTING/FEATURE.md) |
| Дата | 2026-09-30 |
| Связанные | аудит §591 (004, «экран Routing при открытии выключает пресет…»), task 011, §045, §107, §534 |

## Проблема

`_refreshSrsCache` (`app/lib/screens/routing_screen/routing_srs_cache.dart`,
~стр. 128–185) при каждом открытии экрана Routing записывает `enabled=false`
правилу (`CustomRuleSrs` и `CustomRulePreset`), у которого нет скачанного
`.srs` (обоснование task 011: «свич вкл., а ничего не матчит»).
`RuleSetAutoUpdater` (`app/lib/services/rule_set_auto_updater.dart:223`)
выключенные правила пропускает, первый его проход — через 30 с после старта.

Итог на чистой установке: пользователь открывает Routing в первые 30 с →
дефолтный `ru-direct` выключается в хранилище → автообновление его не качает →
правило выключено навсегда, хотя пользователь его не выключал. То же после
очистки кэша наборов, при сбое сети на первом скачивании и т. п.

Корень: временное состояние «файла нет» записывается в поле намерения
пользователя `enabled`.

## Решение

`enabled` — только намерение пользователя. Экран и любые другие места больше не
пишут `enabled=false` из-за отсутствия файла. Наличие файла — отдельное
вычисляемое состояние, как и сейчас (`_srsCached`).

Состояния строки правила с удалёнными наборами (набор включён гейтом §534):

| # | `enabled` | файл | свич | иконка / подпись | в конфиге |
|---|---|---|---|---|---|
| 1 | true | есть | вкл., обычный | ✅ | да |
| 2 | true | нет | вкл., приглушённый | ☁, подпись `Waiting for download`; во время скачивания — индикатор | нет |
| 3 | false | нет | выкл. | ☁ | нет |
| 4 | false | есть | выкл. | ✅ | нет |

Переходы:

- 2 → 1 само: автообновление (или тап по ☁) скачало файл; экран, если открыт,
  обновляет строку.
- 2, тап по свичу → 3 (пользователь выключил).
- 3, тап по свичу → скачивание, затем `enabled=true` (как сейчас,
  `_enableAfterDownload`); ошибка → остаётся 3 + снэкбар (как сейчас).
- 2, ошибка скачивания → остаётся 2 (не выключается); автообновление повторит
  по своему расписанию.
- 1 ↔ 4 — обычный тап, как сейчас.

Сборка конфига: правило в состоянии 2 в конфиг не попадает — проверить, что
билдер (`preset_expand.dart` и путь `CustomRuleSrs`) действительно пропускает
правило без файла без ошибки сборки; если нет — сделать так. Когда файл
появился (2 → 1), конфиг должен считаться устаревшим (баннер «Config changed»),
как при любом скачивании набора автообновлением сейчас; проверить.

`RuleSetAutoUpdater` качает включённые правила — после правки он скачает и
правила в состоянии 2. Ничего в нём менять не нужно, кроме случая, если он
тоже где-то выключает правило при ошибке — тогда убрать.

Миграции нет: уже выключенное этим багом правило неотличимо от выключенного
пользователем — остаётся как есть.

Строки UI — только английские, новые ключи добавить в l10n (`ru`, `zh`) по
правилам проекта. Если в проекте уже есть подходящая подпись для «ожидает
скачивания» — использовать её.

Документация: `docs/spec/features/004-ROUTING/` — описать таблицу состояний
(обещание: «Routing screen never turns a rule off by itself»), свидетель —
тест ниже; в таблицу задач фичи — строку §601; в аудите §591 у пункта 004 —
`→ 601`.

## Критерии приёмки

1. Тест: включённое правило без файла → `_refreshSrsCache` (или вынесенная
   чистая функция) не меняет `enabled`; сохранённые правила не переписываются.
2. Тест: автообновление берёт правило в состоянии 2 в работу (включённое без
   файла).
3. Тест/проверка: сборка конфига с правилом в состоянии 2 успешна, правила и
   его rule_set в конфиге нет.
4. Если свич строки вынесен в виджет — виджет-тест на вид состояния 2
   (вкл., приглушённый, ☁); иначе — по месту, без обязательного виджет-теста.
5. `flutter analyze` по проекту чистый.

## Проверка

Затронутые тестовые файлы — по одному. Остальное — CI.
