Контракт со стороны лаунчера — 0.12.6, D-096: поля объявлены в
`schema/direction.schema.json` и `schema/backup.schema.json`, кейс корпуса —
`corpus/backup/directions_ping_roundtrip`.

## Факты

`ping_options.groups[<тег Направления>] = {url?, timeout_ms?}` — per-Направление
override бюджета ручного и массового теста узлов (§040). Resolve chain в
`HomeController`: override Направления → глобальное значение секции → дефолт
шаблона (`pingUrlFor` / `pingTimeoutFor`). Ключи карты — только живые теги
Направлений; инвариант держит heal §408.

**Это не параметры ядра.** `auto.url` и `auto.idle_timeout` записи
`directions[]` настраивают urltest-двойника `<tag>-auto` ВНУТРИ ядра: по ним
ядро само переключает узел. `ping_url` / `ping_timeout_ms` — чем ПРИЛОЖЕНИЕ
меряет узлы Направления в списке, по кнопке. Адресаты разные, и слить их
значило бы менять поведение ядра правкой кнопки «Ping».

## Что было

LX-бэкап переносил запись Направления целиком, кроме бюджета теста: секции
`ping_options` в переносимой схеме нет вовсе, а места внутри `directions[]`
полям не было. Пользователь, задавший своему Направлению отдельный URL замера
и таймаут, на новой машине получал его на глобальном умолчании — молча, без
предупреждения: экспорт о потере не знал, потому что не смотрел в
`ping_options` вовсе.

Внутренний бэкап (§221) переносил их всё это время: `ping_options` в
allowlist'е и восстанавливается секцией целиком. Расходились ровно два
формата, и переносимый был беднее.

## Что стало

**Поля записи Направления, а не своя секция.** Бюджет адресуется тегом
Направления, и корневая секция `ping_options` в файле означала бы второй
список тегов рядом с `directions[]` — с собственными сиротами, собственным
порядком применения и вопросом «что делать с записью, чьё Направление не
приехало». Внутри записи вопроса нет: приехало Направление — приехал бюджет.

### Форма

| Поле | Тип | Поддержка | Смысл |
|---|---|---|---|
| `directions[].ping_url` | string, непустой | LxBox | URL замера узлов Направления в приложении |
| `directions[].ping_timeout_ms` | integer > 0 | LxBox | таймаут одного замера, мс |

Отсутствие ключа = override нет. Поля объявлены в схеме, применяет их только
LxBox (колонка «Поддержка» `docs/BACKUP.md` §2); лаунчер игнорирует молча и
провозит — правило §1 контракта.

### Экспорт

`buildLxBackup` принимает `directionPing: Map<тег, LxDirectionPing>`;
`_directionToJson` подмешивает половины, которые заданы. Форму storage в
переносимую переводит чистая `lxDirectionPingFromStorage`
(`app/lib/services/lx_backup.dart`), зовёт её `backup_screen.dart` — парсер
`SettingsStorage` не видит и видеть не должен.

Читается ТОЛЬКО подкарта `groups`. Глобальные `url` / `timeout_ms` — настройка
приложения, а не Направления; их дом — `vars`, и выписывать их в запись
Направления значило бы превратить умолчание в зафиксированную настройку на
принимающей стороне.

Экспорт остаётся чистой функцией состояния (§401 П1): порядок ключей задан
литералом записи, карта бюджетов читается по тегу, два прогона одного
состояния дают идентичные `directions[]`.

### Импорт

**Бюджет применяется только у СОЗДАННЫХ Направлений.** Запись с занятым тегом
по норме §9 BACKUP.md пропускается целиком (`backup_direction_exists`) — под
этим именем у пользователя своё Направление со своими настройками. Бюджет
уходит вместе с записью: файл не вправе менять настройку Направлению, которого
сам не создавал. Объединения половинок, как у подписок, здесь нет и быть не
может — сливать нечего, приехавшая запись не применена.

Парсер по той же причине не кладёт занятые теги в `LxBackupFile.directionPing`:
карта заполняется в том же цикле, после `continue` по занятому тегу.
Направление, приехавшее без полей, локальный override не трогает — писать
нечего.

Применение — `backup_screen.dart`, штатным `SettingsStorage.setGroupPing` и
ПОСЛЕ `DirectionMutations.bulkReplace`: ключ `ping_options.groups` адресуется
тегом Направления, и запись, легшая раньше своего Направления, была бы
сиротой, которую §408 всё равно вычистит.

### Валидация

Та же, что делает диалог §040 при сохранении, и та же, что требует схема
(`minLength: 1`, `minimum: 1`):

| Приехало | Итог |
|---|---|
| непустая строка / целое > 0 | применяется |
| `""`, `"   "`, `0`, отрицательное | отбрасывается молча, Направление применяется |
| строка вместо числа, число вместо строки | отбрасывается, `backup_field_type_mismatch` |

Различие намеренное. Тип верный, значение вне диапазона — это ровно то, что на
этой стороне означает «override сброшен», и шуметь не о чем. Разошедшийся ТИП
знакомого ключа — случай `subscriptions[].skip` (§401): пользователю важно
отличать «такого поля тут нет» от «поле есть, но значение записано
по-другому». Файл при этом читается дальше: терять всё прочее из-за одного
поля запрещает П6.

Нормализация живёт в конструкторе `LxDirectionPing`, а не у каждого
вызывающего: в него сходятся и storage, и разбор файла, и пропуск проверки на
новом пути записи дал бы файл, не проходящий схему.

### Корпус

Раннер `app/test/contract/backup_corpus_test.dart` сверяет `ping_url` /
`ping_timeout_ms` УКАЗАТЕЛЬНО, как `label` (§405): базовый golden пишет
ожидания принимающей стороны лаунчера, который поля не применяет, и отсутствие
ключа там значит «сторона не применяет», а не «override обязан отсутствовать».
Кейс `directions_ping_roundtrip` кладёт оба ключа своим
`.expected.lxbox.json`.

## Тесты

`app/test/contract/lx_backup_test.dart`, группа «бюджет теста узла у
Направления (§409)»: экспорт только заданных половин; Направление без override
без ключей; пустое значение в файл не едет; `lxDirectionPingFromStorage`
читает только `groups`; круг экспорт→импорт у нового Направления; занятый тег
бюджет не получает; невалидное значение отбрасывается молча; чужой тип даёт
`backup_field_type_mismatch`; свой же экспорт не даёт ложный
`backup_unknown_field`; детерминизм экспорта.

`app/test/contract/backup_corpus_test.dart` — кейс `directions_ping_roundtrip`
проходит по override без подгонки раннера.
