| | |
|---|---|
| **Статус** | Реализовано, тесты зелёные (5022) |
| **Дата** | 2026-09-18 |
| **Источник** | ядро SPEC 093 (`v1.14.1-lx.8`, singbox-launcher#130); решение владельца 18.09.2026, переданное сессией лаунчера: нормализация снимается целиком |
| **Связанные** | §464 (ввёл `normalize: grpc_service_name`), §467, §462 (прошлый бамп), `docs/KERNEL.md` |

## Проблема

Xray пишет gRPC-путь как `/<service>/Tun`, а custom path — любым путём с
ведущим `/`. До lx.8 ядро экранировало такое значение целиком
(`/%2Fa%2Fb%2FTun/Tun` → 404), поэтому §464 по правилу реестра переводил
`/<service>/Tun` → `<service>`. На многосегментном пути (`/a/b/Tun`) и на
нестандартном имени стрима перевод даёт неверный результат.

lx.8 понимает ведущий `/` сам: посегментный PathEscape, последний сегмент —
имя стрима, хвост `|…` отбрасывается. Без ведущего `/` — байт в байт как было.

## Решение

1. Пин `app/android/libbox.version` → `v1.14.1-lx.8`. javap-дифф
   Java-поверхности AAR против lx.7 (одной командой, из релизных AAR, не из
   `libs/classes.jar`) — в спеку. Версию в собранном APK не проверяем (APK не
   собирается в этой задаче).
2. Синк контракта на коммит лаунчера, где `normalize: grpc_service_name`
   снят у `transport.grpc.service_name` и удалён из схемы. Способ — только
   `git archive <sha>`.
3. Санитайзер: вид нормализации `grpc_service_name` удалить (код, тесты
   §464). Неизвестный вид нормализации по-прежнему логируется один раз.
4. URI-парсеры и JSON-импорт: `serviceName` хранится и эмитится как пришёл,
   включая ведущий `/`. Проверить `transport.dart` (§464 завёл там ту же
   нормализацию на URI-пути) — снять.
5. Правило нормативно только для пина lx.8+. Откат ядра ниже lx.8 ⇒ вернуть
   перевод односегментной формы. Записать в `docs/KERNEL.md` рядом с
   остальными «нормативно для пина».
6. Тем же синком приедет контракт 1.1.2: `reality_fp_not_chrome` —
   `warning` → `info` (решение владельца). Проверить, что серьёзность у нас
   читается из реестра, а не зашита; если зашита — привести.

## Критерии приёмки

- `/a/b/Tun`, `/svc/Tun`, `/a/Stream`, `svc`, `a/b` — в теле узла байт в байт
  как во входе, на URI- и JSON-пути; warnings пусты;
- корпус зелёный без новых override;
- javap-дифф приложен; `flutter analyze` всего проекта, «All tests passed»;
- KERNEL.md, PROTOCOLS.md (gRPC), GUARDS.md, CHANGELOG, спека 464 (пометка
  об отмене нормализации) обновлены.

## Как сделано

### Пин ядра

`app/android/libbox.version`: `v1.14.1-lx.7` → `v1.14.1-lx.8`. Больше менять
нечего: `scripts/fetch-libbox.sh` берёт версию из этого файла, качает
`libbox-<ver>.aar` вместе с `SHA256SUMS` того же релиза и сверяет хеш на
месте — контрольных сумм ядра в репозитории не записано, и обновлять их
негде. Тот же пин читают локальная сборка и CI.

**javap-дифф lx.7 → lx.8 — пуст.** Оба AAR взяты из релизов форка (не из
`app/android/**/libs/classes.jar` — он протухший), из каждого распакован
`classes.jar`, javap прогнан одной командой по всем классам:

- списки классов совпадают, по 253 в каждом;
- сигнатур 3493 строки, `diff` пуст.

Обвязку Kotlin задача не трогает.

### Контракт 1.1.1 → 1.1.3

Синк строго снимком: `git archive 3dacd68e contract` из репозитория лаунчера
во временный каталог, оттуда `LX_CONTRACT_SRC=… app/tool/sync_contract.sh`.
Рабочее дерево лаунчера в копию не попало, в его репозитории ничего не
менялось. Хеш дерева в `app/contract.lock` —
`c7a820187790a3c9152d43a3a3906606fc5502e0a01bb375cbbfa928b000913e`.

Изменились три файла реестра:

- `transports.json` — у `grpc.service_name` снято `normalize`, переписаны
  `desc_en`/`desc_ru`/`impl` под разбор ведущего «/» ядром (§24.12);
- `warnings.json` — `reality_fp_not_chrome`: `warning` → `info` (§24.11);
- `protocols/ssh.json` — тексты `impl`/`note` про inline `private_key`:
  эмит сведён, обе стороны пишут ключ в query после подтверждения
  пользователя (§24.10, наша §466).

Значение `grpc_service_name` пропало и из enum `normalize` в
`schema/registry_body.schema.json` — сверено, наш линтер схемы на него
больше не смотрит.

### Снятие нормализации

| Где | Было | Стало |
|---|---|---|
| `body_sanitizer.dart` | `case 'grpc_service_name'` в `_normalizeString` + публичная `normalizeGrpcServiceName` | обе вырезаны; неизвестный вид нормализации по-прежнему логируется один раз и значение не трогает |
| `parser/transport.dart` | `GrpcTransport(serviceName: normalizeGrpcServiceName(sn))` | `serviceName: sn`, импорт снят |
| `parser/json_parsers.dart` | то же правило на ветке Xray-JSON | значение как есть, импорт снят |
| `contract/registry.dart` | `grpc_service_name` в перечне видов в док-комментарии | убран |

Тесты §464 переписаны на «как есть»: один кейс на семь форм
(`abcde`, `/abcde`, `/abcde/Tun`, `/a/b/Tun`, `/a/Stream`,
`/abcde/Tun|multi`, `a/b`) — значение не меняется, `warnings` пусты.

### Серьёзность `reality_fp_not_chrome`

Была **зашита в рукописном классе**: `RealityFingerprintWarning.severity`
возвращал константу `WarningSeverity.warning`, хотя severity кода — данные
контракта (24.1.5). Приведено к реестру: класс зовёт
`registrySeverity('reality_fp_not_chrome')` — та же функция, которой уже
пользуется `RegistryWarning`. Правка мелкая и снимает расхождение навсегда,
а не до следующего решения владельца.

Фолбэк `registrySeverity` (реестр не загружен → `warning`) остаётся: незнакомый
код глушить нельзя. `node_warning_test` работает без реестра и теперь проверяет
именно фолбэк; `info` из реестра проверяется там, где реестр загружен
(`registry_load_test`).

**Что меняется на экране.** Узел, у которого `reality_fp_not_chrome` —
единственное предупреждение:

- значок и цвет строки: оранжевый `warning_amber` → приглушённый
  `info_outline` цветом `onSurfaceVariant`;
- шапка списка подписки: такой узел выпадает из счётчика «узлов с
  предупреждениями» (`actionableCount` считает всё, кроме `info`), и оранжевая
  полоса над списком не появляется вовсе, если других предупреждений в
  подписке нет;
- порядок в строке узла: при нескольких кодах показывается старший, так что
  рядом с любым `warning`/`error` этот код со строки уходит.

Текст, сам код и тело узла не меняются. Рекомендация лаунчера из §24.11
(развести три уровня по разным местам строки: значок info у имени узла,
тултип, группа «К сведению» в карточке) — вопрос отдельной задачи, UI здесь
не перестраивался.

### Корпус

Зелёный без единого нового override. Перенормированы три кейса
(`uri/trojan/grpc_service_name_leading_slash`,
`uri/vless/grpc_service_name_leading_slash`,
`body/xray/grpc_service_name_leading_slash`) и добавлены четыре
(`uri/vless/grpc_service_name_custom_path_one_segment`,
`…_custom_path_two_segments`, `…_custom_path_other_stream`,
`…_plain_multi_segment`).
