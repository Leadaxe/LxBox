## Проблема

`app/lib/services/debug/serializers/subs.dart`, `serializeEntryWarnings` —
карта `warnings` ключевалась **сырым** `NodeSpec.tag`:

```dart
for (final n in e.list.nodes) {
  byTag[n.tag] = [for (final w in n.warnings) serializeNodeWarning(w)];
}
```

Сырой тег узла-тёзку не различает, а `Map` — last-write-wins. Тёзки в выдаче
провайдера норма, а не экзотика:

- §310 — панель зовёт **все** узлы `proxy`;
- дубль `vpn://`↔`amneziawg://` под одним именем: один и тот же сервер
  отдаётся двумя схемами, имя одно.

Итог: предупреждения всех дублей, кроме последнего, молча пропадали. На
входе демо D `nodes_count` отдавал верные **12**, а `warnings` — **8**
записей. Счётчик расходился со списком, причём комментарий на `:150` прямо
обещал «все узлы присутствуют», и снаружи потеря выглядела как «у этих узлов
предупреждений нет».

Это именно дефект ответа, а не разбора: предупреждения у узлов есть
(`NodeSpec.warnings` заполнен), теряет их сериализатор.

## Выбор ключа — почему `containerRawTags`

Кандидатов было два, и они дают разные суффиксы.

| Источник | Суффиксы | Область | Знает `tag_prefix` |
|---|---|---|---|
| `build_config.dart` `allocateTag` (`:941`) | `X-1`, `X-2` | весь конфиг | да |
| `node_hash.dart` `_uniquifyAgainstCounts` (`:113`), через `containerRawTags` | `X-2`, `X-3` | один источник | нет |

Взят **`containerRawTags`** (`app/lib/services/node_link_address.dart:35`,
NODE_LINK §2.2) — для подписки это `sourceNodeRawTags` → тот же
уникализатор, что у `sourceNodeIdentities`.

Обоснование:

1. **Совпадает с тем, чем узел адресуют снаружи.** `containerRawTags` — уже
   объявленный «один модуль на сборку, реестр ссылок, пикеры, миграцию и
   импорт»; им ключуются `nodeWarnings` в хранении, экран деталей записи
   (`subscription_detail_screen.dart:138`), `entry_warnings.dart`, probe и
   ссылки `{folder_id?, tag}`. Ключ ответа обязан совпадать с адресом, по
   которому проверяющий позовёт `GET /nodes/link?tag=` и
   `POST /action/switch-node?tag=`, иначе ключ не адрес, а украшение.
2. **Адрес сборки для этого ответа не годится.** `allocateTag` живёт внутри
   конфига: он клеит `tag_prefix` и зависит от состава **остальных**
   источников — включили соседнюю подписку, и ключ узла в этом ответе
   поехал бы, хотя сам узел не менялся. Ответ про запись не должен зависеть
   от того, что рядом.
3. **Обратная совместимость по форме соблюдена.** Тот же JSON-объект
   «тег → список». У записи без тёзок каждый ключ **дословно** равен
   прежнему `n.tag` (проверено тестом) — двигаются только тёзки.

### Состав узлов оставлен прежним

Итерируется `e.list.nodes`, а не `containerNodes(list)`. У папки
`containerNodes` включает **выключенных** членов, которых `nodes` (фильтр
`enabled && parsed`) не видит, и ответ стал бы шире `nodes_count` — ровно та
расходимость, которую эта таска закрывает. Карта адресов ключуется по ссылке
узла (`Map.identity`), поэтому шире своего входа она безвредна.

### Коллизия у папки и безымянный узел

`containerRawTags` уникализирует только у подписки. У **члена папки** адрес —
тег как есть (NODE_LINK §2.2: у ссылки побеждает первый), схлопывать ключ
нельзя — это та же потеря. Поэтому суффикс ставится **только на фактической
коллизии**, и это **индекс узла** в списке (`X`, `X#1`, `X#3`), а не
порядковый номер тёзки: индекс — тот же адрес, которым член папки адресуется
в `/folders/*` (`serializeFolderMember` отдаёт его полем `index`), так что по
такому ключу узел ещё и находится. Безымянный узел адреса не имеет вовсе —
ему выдаётся `#<index>`. Разделитель `#` выбран один на оба случая: он не
встречается в уникализации источника (`-2`/`-3`), так что ключ-адрес и
ключ-заплатка снаружи отличимы — узел в ответе присутствует, но ключ не
притворяется тегом, по которому его можно позвать в `switch-node`.

Инвариант, который теперь держится: **`warnings.length == nodes_count`**.

## Тесты

`app/test/services/debug/nodes_link_and_subs_warnings_test.dart`, группа
«тёзки не затирают друг друга (§520)»:

1. **3 узла с одним сырым тегом** (`proxy` ×3, разные предупреждения) → 3
   ключа `proxy` / `proxy-2` / `proxy-3`, у каждого **своё** предупреждение.
   До правки был один ключ с предупреждением последнего узла.
2. **`nodes_count == warnings.length`** на входе с 2 тёзками (синтетика по
   мотивам входа D: 4 узла, двое зовутся `Tokyo`) — 4 ключа, узлы без
   предупреждений на месте пустым списком, оба тёзки сохранили свои коды.
3. **Запись без тёзок** — ключи дословно равны сырым тегам (пин обратной
   совместимости, включая тег с эмодзи).

Синтетика, а не URI-конвейер: через какой ввод разбор выдаст именно трёх
тёзок с разными кодами — вопрос конвейера, а пинится здесь ключевание
ответа. Прогон: `flutter test test/services/debug/` — 244 passed,
`flutter analyze` чистый.
