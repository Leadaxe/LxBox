## Problem

Issue #191 (lolpoi, v2.25.19-rc.2), Направление в режиме Load balance с
`pool = 1`:

1. Карточка «✨ Auto» вместо имени узла показывает протокол: `SOCKS`,
   `WG·awg1.5`. Причина — стык двух правил §322: у группы с `balancer`
   стрелка «→ узел» снимается (одного выбранного у round_robin нет), а метка
   режима `🔀 [N/M]` двойнику Направления не выдаётся (имя уже подменено на
   «Auto»). В остатке срабатывает запасной вариант §048: протокол с текущего
   выбора ядра. Узел автовыбора в папке в том же режиме рисует
   `🔀 [N/M] 🇩🇪, 🇳🇱[2]`, но у узлов без флага в имени значков не выходит и
   метка остаётся голой.
2. Автор просит видеть в списке узлов результаты URL-теста ядра, как в окне
   View pool. Класть их в основной бейдж нельзя: замер приложения идёт на
   цель из Ping Settings, замер ядра — на `url` группы через туннель; это два
   разных измерения. Решение владельца: класть их в слот «чужих» замеров
   §325 (приглушённый бейдж с `~`).

Пункты 1 и 3 issue (мёртвый узел заменяется только по health-check, подпись
«висит» на старом узле) — поведение ядра: в `round_robin` ошибка дозвона пул
не меняет, мёртвый слот держится до найденной замены
(`sing-box-lx/docs/configuration/outbound/urltest.md`). Для «один узел,
реакция на падение» есть режим Hold until failure (`failover`). Не меняется.

## Solution

### A. Метка пула: значки, иначе имена слотов

Одна функция `poolLabelSuffix(slots, badge)` для двойника Направления и узла
автовыбора: значки по регулярке `badge` (как было); если ни один слот значка
не дал — имена слотов через запятую в порядке пула. Пула нет (туннель не
поднят, ответ ещё не пришёл) — только база `🔀 [N/M]`. Стрелки «→» нет.

Двойник Направления с `balancer` получает ту же метку (`autoGroupLabel`), и
протокол из подписи уходит, как у узла автовыбора. Двойник в Fastest /
Hold until failure — как был: стрелка на выбранный узел.

```
│ ✨ Auto                           57 ms │
│    ACTIVE  🔀 [10/3] 🇩🇪, 🇳🇱[2]        │   флаги нашлись
│    ACTIVE  🔀 [2/1] s-wawg-903          │   флагов нет → имена слотов
│    🔀 [10/3]                            │   туннель не поднят
```

### B. Замеры ядра — псевдо-Направление `coreDirection`

- `HomeState.coreDirection` — отдельный ключ в `delayByDirection`
  (как `scratchDirection`).
- `_refreshEndpointStates` (heartbeat, 5 с, уже тянет `getOutbounds`)
  собирает карту `tag → urlTestDelay` для узлов с `urlTestTime > 0`
  (`urlTestDelay == 0` при ненулевом времени → `-1`, ошибка) и кладёт её под
  `coreDirection`; при равной карте emit не делается.
- `delayOf`: свой замер → замер другого Направления → замер ядра. Замер
  ядра всегда «чужой» (`delayIsForeign`), рисуется с `~` и приглушённо.
- Туннель опустился → ключ `coreDirection` остаётся (как любой чужой замер
  §325) и перезаписывается первым heartbeat'ом следующего сеанса.
- Mass ping и одиночный пинг пишут в своё Направление и ключ ядра не трогают;
  свой замер перекрывает замер ядра в показе.
- §355: мёртвый по ядру узел (`-1`) без своих замеров считается мёртвым —
  провал health-check ядра через туннель и есть подтверждённая смерть.
