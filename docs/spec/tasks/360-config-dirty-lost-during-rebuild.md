# §360 — Мутация во время пересборки теряет `configDirty`

| | |
|---|---|
| Тип | bugfix (потеря пользовательского изменения) |
| Статус | ✅ DEVICE-VERIFIED (эмулятор) — тесты зелёные |
| Дата | 2026-08-03 |
| Связанные | [`331`](331-blue-banner-and-manual-refresh-reaction.md) (`keepDirtyFlag`, `_compositionKey`), [`107`](107-lazy-persist-stale-read-race.md) (lazy rebuild на возврат в home), [`338`](338-auto-reload-on-settings-change.md) (галка автоперезапуска) |

## Проблема

Юзер включает подписку на экране Servers, возвращается на home — нового
набора нод нет. Галка «пересобрать конфиг и перезапустить» не помогает:
она отрабатывает по `configDirty`, а флага нет.

Два места сговорились терять изменение.

**1. Гейт в `_persist`** — `if (!_busy && !keepDirtyFlag) configDirty = true`.
Флаг `_busy` поднимает не только пересборка, но и `addUserServer`,
`addFromInput`, fetch подписки, `addMembersToFolder`. Любая мутация, попавшая
в чужое busy-окно, молча не поднимала `configDirty`.

**2. Безусловное гашение в `generateConfig`** — `configDirty = false` в конце.
`_generate` читает `_entries` в начале, а флаг гасит в конце: мутация,
прилетевшая в середине, в собранный конфиг не попала, но флаг за неё уже сняли.

Сцепка на реальном пути: возврат на home запускает `_onReturnToHome` →
пересборку (§107). Тап по галке подписки попадает в её окно — изменение
применяется в `_entries`, но конфиг остаётся старым и «грязным» его никто не
считает. Новый состав доезжал только при следующей случайной мутации.

Гейт `!_busy` появился в `2454f8af` («don't set configDirty during rebuild»)
и целился в самозагрязнение пересборки. С §331 её внутренние записи помечены
явным `keepDirtyFlag: true`, так что широкий гейт остался только вредить.

## Решение

| место | было | стало |
|---|---|---|
| `_persist` | гейт по `_busy` | гейт по новому `_generating` — глушится только сама пересборка |
| `generateConfig` | `configDirty = false` безусловно | гасит, только если состав `_entries` не изменился под ней; иначе флаг остаётся + лог |

Отпечаток состава — новый `_compositionSignature()`: `id` + `enabled` + хеши
узлов по всем entries, порядок значим.

Решения по месту:

| вопрос | решение |
|---|---|
| Почему не переиспользовать §331 `_compositionKey`? | Тот отвечает на другой вопрос («фетч принёс новое?») и считается по одной подписке. Здесь нужен состав всех entries, и в него входит `enabled`: выключенная подписка отдаёт билдеру пустой набор узлов, так что сам флаг — часть состава |
| Не проще ли снять гейт целиком? | Нет: 7 голых `_persist()` живут внутри чужих `_busy`-окон. Но все они — добавление серверов, обязанное быть dirty; глушил их именно широкий гейт |
| Порядок entries в отпечатке | Значим — от него зависят суффиксы `allocateTag` и порядок внутри пулов, ровно как в §331 |

## Тесты

`test/subscription/toggle_during_rebuild_test.dart` — группа §360:

- toggle подписки в окне летящего `generateConfig` → `configDirty` остаётся
  (на старом коде падал);
- пересборка без параллельных мутаций → флаг честно снимается (нет ложного
  вечного dirty — та регрессия, от которой защищал `2454f8af`);
- `addUserServer` → флаг поднят, свой `_busy` его не глушит.

Полный прогон: 2807 passed, `flutter analyze` по проекту — No issues.

## Device-verify

Эмулятор (`emulator-5554`), сборка из этой ветки. Сценарий: подписка выключена
и конфиг чист → включить галку на Servers → сразу вернуться на home.

Ожидание: пересборка подхватывает включённую подписку, ноды видны без
дополнительных действий; при включённой §338-галке и живом туннеле —
автоперезапуск.
