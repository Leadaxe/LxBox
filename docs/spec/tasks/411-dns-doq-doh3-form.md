4PDA #1767…#1770 (curse127, ark.sergo): «нет типа DNS DoQ». Ядро
(sing-box 1.14, `constant/dns.go`) знает `quic` (DNS-over-QUIC) и `h3`
(DNS-over-HTTP/3) давно; в приложении их не давала выбрать форма редактора:
`kDnsServerModes` содержал только `udp`/`tls`/`https`/`group`, а сервер с
другим `type` открывался как «нестандартный, правьте JSON».

## Что стало

| Режим | `type` | Порт по умолчанию | Path | TLS SNI |
|---|---|---|---|---|
| UDP | `udp` | 53 | — | — |
| DoT | `tls` | 853 | — | да |
| DoH | `https` | 443 | да | да |
| **DoQ** | `quic` | 853 | — | да |
| **DoH3** | `h3` | 443 | да | да |
| Group | `group` | — | — | — |

- `kDnsServerModes` + `defaultDnsPort` расширены; набор режимов с path вынесен
  в `kDnsPathModes` (`https`, `h3`) — все места формы, где раньше стояло
  `mode == 'https'`, читают его.
- Смена режима сохраняет прежнюю семантику: стандартный порт старого режима
  снимается, нестандартный живёт; path чистится при уходе из DoH/DoH3; tls —
  при уходе в UDP.
- URL-вставка `https://host/path` в адрес: из DoH3 режим не сбивается на DoH.
- Сегментов стало шесть — порог переключения на дропдаун поднят с 340 до
  520dp: на телефоне всегда дропдаун, сегменты остаются планшету.
- Подсказки под селектором: «DNS-over-QUIC · port 853»,
  «DNS-over-HTTP/3 · port 443» (+ ru).

Билдер и валидатор тип сервера не гейтят (проверяют только `group`) — правок
там нет; DoQ через JSON-вкладку работал и раньше.

## Тесты

`test/screens/dns_server_edit/edit_controller_test.dart`: режимы quic/h3
распознаются, порты по умолчанию, path у h3 живёт и чистится при уходе,
URL-вставка не сбивает h3.
