# 700 — Дефолт MTU tun-инбаунда 9000 вместо 1492

| Поле | Значение |
|------|----------|
| Статус | In progress (дефолт и подсказка сменены; замер на эмуляторе и проверка UDP через AWG не сделаны) |
| Дата начала | 2026-10-31 |
| Источник | вопрос владельца 31.10.2026 «почему дефолт inbound mtu мелкий, а не 9000» |
| Связанные | §049 F13 (аудит: 1492 против 9000 у sing-box, тип D), §473 (потолок MTU AmneziaWG-узла) |

## Проблема

`tun_mtu` в `wizard_template.json` стоял `1492` с подсказкой «1492 recommended
for mobile/WiFi». Значение пришло с первым шаблоном (с лаунчера) и
сознательно не выбиралось. 1492 — MTU PPPoE, к TUN отношения не имеет: TUN —
виртуальный интерфейс, TCP завершается в стеке ядра и уходит наружу заново по
MTU исходящего соединения. Маленький MTU tun даёт только больше пакетов через
интерфейс и больше работы процессору, сильнее всего на `gvisor`/`mixed`.
Дефолт самого sing-box — 9000. Аудит §049 (F13) это отметил и отложил замер.

## Решение

1. `wizard_template.json`: `tun_mtu.default_value` = `9000`, подсказка —
   «9000 recommended (sing-box default)»; переводы ru/zh под новую строку.
2. Миграции нет и не нужна: экран настроек пишет в хранилище только
   изменённые пользователем vars (§232, `dirtyKeys`). Установка, где MTU не
   трогали, получает 9000 со следующей сборкой конфига; заданное руками
   значение остаётся.
3. USER_GUIDE (EN/RU): строка MTU в таблице VPN Settings.

## Риски

- UDP в узлы с пакетным туннелем (WireGuard 1408, AmneziaWG 1280): датаграмма
  больше MTU узла режется или теряется. Приложения обычно подбирают размер
  сами (QUIC ходит пакетами ~1200–1350), поэтому sing-box и держит 9000, но
  на наших AWG-узлах это не проверено.

## Паритет с лаунчером

В реестре контракта `vars.json` → `tun_mtu.note` записано «дефолт 1492
совпадает». После этой задачи дефолты расходятся (у нас 9000). Реестр правит
только лаунчер; запрос — сменить дефолт у себя или поправить note.
