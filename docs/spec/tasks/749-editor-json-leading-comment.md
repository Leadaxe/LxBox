## Problem

С задачи 741 сервер, вставленный JSON-ом, хранит текст как набран — с
пометками автора. Если первая строка текста — комментарий (`// …`,
`/* … */` или `# …`), на вкладке Source у такого сервера нет подсветки
синтаксиса, а в меню ⋮ — пункта Format (только Magnifier). Тело,
начинающееся с `{` с комментариями внутри, работает.

## Diagnosis

`detectCodeLanguage` (`app/lib/widgets/lx_code_editor.dart`) решает по
первой значащей строке: JSON — только если она начинается с `{` или `[`.
Строка `// …` или `/* …` давала `null`; строка `# …` уходила в ветку INI,
которая ищет `[Секцию]` или `Ключ = значение`, и тоже давала `null`. Язык
определяет и подсветку (параметр `language` у экранов), и пункт Format
(`_computeCanFormat`). Разбор (`uncommentedJson` в
`app/lib/services/parser/json_comments.dart`) ведущие комментарии уже
пропускал — определение языка отстало.

Места вызова: Source узла (`node_settings_screen`), редактор члена папки
(`folder_detail_screen`), поле мастера добавления сервера
(`add_server_wizard_screen`), вкладка Source подписки
(`subscription_source_tab`) и сам редактор — пункт Format, в том числе у
Config и Mixins.

## Solution

- `json_comments.dart`: `jsonLeadChar(text)` — первый значащий символ
  текста; BOM, пробелы и комментарии `//`, `/* */`, `#` пропускает тот же
  сканер `_skipBlank`, что у правки тега (второго сканера нет).
- `detectCodeLanguage`: правила `[Секция]`, `{`/`[` и INI по
  `#`/`;`-комментарию остаются первыми и прежними. Если текст начинается с
  `#`/`;` и INI не подтвердился, а также если первая строка начинается с
  `//` или `/*`, — JSON, когда первым значащим символом после ведущих
  комментариев идёт `{` или `[`; иначе `null`, как раньше.
- Format уже умел такой текст: `formatJson5` снимает `#`, `json5` — `//` и
  `/* */`, `hasJson5Comments` поднимает диалог «Comments will be removed».

## Risks and edge cases

- WG/AWG `.conf` с `#`/`;`-комментариями и `[Interface]` — INI: ветка INI
  проверяется раньше. Тест.
- Подписка, начинающаяся с `# profile-title: …`, за которой ссылки: как
  прежде (строка `vless://…?type=…` подходит под «ключ = значение» → INI);
  JSON не стал.
- Ссылка после комментария (`// c\nvless://…`) — `null`, как прежде.
- Незакрытый `/*` — сканер съедает текст до конца, `null`.
- Текст, где за `#`-комментарием идёт `[a]` (имя без кавычек) — INI, как
  прежде; JSON-массив `["a"]` под регулярку секции не подходит → JSON.
