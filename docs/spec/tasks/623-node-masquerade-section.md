# §623 — Секция Masquerade в настройках узла WireGuard/AmneziaWG

| Поле | Значение |
|------|----------|
| Тип | Доработка фичи [008-NODE_EDITOR](../features/008-NODE_EDITOR/FEATURE.ru.md) |
| Статус | Реализовано (3a824296), ревизия 1 — см. «Реализация» |
| Дата | 2026-10-09 |
| Связанные | §143-warp ([143-warp-masquerade-id-ip-ib.md](143-warp-masquerade-id-ip-ib.md), сахар `ip`/`id`/`ib` и форма в визарде WARP); §581/§613 (поля тела с вкладки Network у Tailscale — прецедент «форма пишет в источник»); §617 (QUIC-приманка несёт целый ClientHello с SNI = `id`); §450 (`awg://` с base64 `.conf`); §455/§456 (источник как есть, INI байт в байт); §421 (`Uri.queryParameters` ест сырой `+`); ядро `sing-box-lx/SPECS/009-F-O-WIRESOCK_MASQUERADE_PROFILES` |

## Проблема

Сахар маскировки `ip`/`id`/`ib` (ядро само строит `i1`) поддержан во всём
тракте: разбор ссылки, INI `[Interface]` и JSON, сборка, реестр контракта
(`protocols/wireguard.json`, поля `body/fields/ip|id|ib`). Форма для него есть
только в визарде WARP (Advanced). Свой узел WireGuard/AmneziaWG из ссылки,
`.conf` или JSON маскировку получает только руками в тексте Source: нужно
знать имена ключей, допустимые значения и то, что `id` при `quic`
обязателен. Ошибка в значении молча снимается разбором (`awg3_field_invalid`),
и узел остаётся без маскировки.

## Решение (владелец, 09.10)

На вкладке **Settings** узла WireGuard/AmneziaWG — секция **Masquerade** с
тремя полями. Значения пишутся **в тело источника** (не в отдельное хранилище
и не в overrides), дальше тем же путём, что Save вкладки Source.

**Явный `i1` приоритетнее.** Если у узла задан `i1`, секция недоступна, и под
заголовком написано почему.

Это узкое исключение из решения 29.09.2026 (аудит §591: «отдельная форма
WireGuard/AmneziaWG не планируется»). Остальные поля WG/AWG (`jc`, `h1`–`h4`,
`i2`–`i5`, AWG 3.x) по-прежнему правятся только текстом.

## Поведение

### Где видна

- Вкладка Settings, отдельный блок под строками Protocol / Server.
- Только у узла `WireguardSpec` — у обычного WireGuard и у AmneziaWG
  одинаково. Обычный WG-сервер пакеты-приманки перед рукопожатием
  отбрасывает (WARP — обычный WG, §143 проверено на устройстве), поэтому
  ограничивать секцию узлами с AWG-полями незачем.
- Узел подписки (P14 фичи 008): секция видна с текущими значениями, все
  поля выключены, кнопки Save нет.

### Поля

| Поле | Ключ | Значения | Видно |
|---|---|---|---|
| Protocol | `ip` | `Off` · `quic` · `dns` · `stun` · `sip` | всегда |
| Domain | `id` | LDH-имя, ≤ 253 байт, шаблон реестра `body/fields/id.pattern`; рядом кубик — случайный домен из пула визарда (`ScanPool.wgSniPool`) | при `quic`, `dns`, `sip` |
| Browser | `ib` | `chrome` · `firefox` · `curl` | только при `quic` |

Подсказка под Protocol — по выбранному протоколу:

| `ip` | Что значит домен | Обязателен |
|---|---|---|
| `quic` | SNI в ClientHello первого QUIC Initial (§617) | да (`requires` у `ip`, контракт 1.1.58) |
| `dns` | QNAME запроса, виден на проводе | нет: пусто → ядро придумывает имя |
| `sip` | host SIP-запроса, виден на проводе | нет: пусто → ядро придумывает имя |
| `stun` | не используется, поле скрыто | — |

Начальные значения берутся из модели узла (`awg.fields['ip'|'id'|'ib']`,
уже после нормализации `trim_lower`). Значение, снятое разбором как
негодное, в модели отсутствует: секция показывает `Off`, Save перепишет
мусор в источнике каноническими ключами.

### Save секции

Своя кнопка Save внизу блока, активна при изменённых значениях. Что
пишется в тело:

| Выбор | `ip` | `id` | `ib` |
|---|---|---|---|
| Off | убрать | убрать | убрать |
| `quic` | `quic` | значение (обязательно) | значение или убрать |
| `dns` / `sip` | значение | значение или убрать | убрать |
| `stun` | `stun` | убрать | убрать |

Ключи, которые форма не показывает, при Save убираются: так в теле не
остаётся сочетание, которое ядро или разбор отвергнут (`ib` без `quic`).

Проверки до записи. Пока они не пройдены, Save выключен, у поля текст ошибки:
- `quic` без домена — «Domain is required for QUIC.»
- домен не проходит шаблон или длиннее 253 байт — «Not a valid domain name.»

Дальше текст источника с новыми ключами кладётся в `_sourceCtrl` и уходит
через `_saveSource()`: тег из поля Tag, ворота ядра `CheckConfig` для JSON,
транзакционная запись члена папки (§237) или одиночного сервера (§603),
перечитывание экрана. Сообщения об успехе и отказе — те же, что у Source.

Если на вкладке Source есть несохранённая правка (`_sourceCtrl.text` ≠
сохранённый источник), Save секции выключен, под кнопкой — «Source has
unsaved changes.». Иначе запись секции молча затёрла бы чужую правку или
сохранила бы её без ведома пользователя.

### Явный `i1` — секция недоступна

Условие: в модели узла есть `awg.fields['i1']`. Разбор уже следует тому же
приоритету: мапперы реестра берут `ip`/`id`/`ib` только при отсутствии `i1`
(`mappers/*/params/ip.when: {query.i1/ini.Interface.I1: present false}`).

Что видно:
- все поля секции выключены, Save нет;
- под заголовком текст: «Masquerade is off: the node sets I1 explicitly,
  and I1 takes priority. Without I1 in Source this section becomes
  available.»
- если в источнике рядом с `i1` лежат и `ip`/`id`/`ib`, текст дополняется:
  «The masquerade keys in Source are ignored.» (у ссылки и INI их снимает
  разбор; у sing-box JSON тело идёт дословно, и такое сочетание ядро
  отвергает при Save Source — «masquerade conflicts with an explicit i1»).

### Явный `i2` и `sip`

`ip=sip` занимает `i2` («sip masquerade fills i2», `device_awg.go`). При
заданном `i2` пункт `sip` в списке выключен с подписью «Not available: the
node sets I2 explicitly.». Остальные протоколы `i2` не трогают.

### Источник, в который секция писать не умеет

| Источник | Поведение |
|---|---|
| `awg://` с base64 `.conf` (§450), Amnezia `vpn://` | поля выключены; текст: «This source is a packed link. Masquerade can be changed after Edit JSON turns the node into JSON.» |
| Xray-конфиг (WG-outbound Xray, `sourceKindOf` = `xray_config`) | то же, текст: «Masquerade is not supported for this source format.» |

Открытый вопрос 1 — писать ли в упакованные формы через распаковку.

## Ключевые узлы

### 1. Запись ключей в источник — `lib/services/wireguard/masquerade_source.dart` (новый)

Чистые функции без ввода-вывода:

```dart
/// Маскировка узла: null-поле = ключа нет.
class Masquerade { final String? ip, id, ib; }

/// Можно ли писать в этот источник; если нет — причина для текста секции.
MasqueradeWritability masqueradeWritability(String raw);

/// Текст источника с ключами [m]; прочие байты источника не трогаются.
String withMasquerade(String raw, Masquerade m);
```

Разбор по виду источника (`originKindOf` + `sourceKindOf`, свой сниффер не
заводить — правило §480/§482):

- **`json`** (sing-box endpoint `type: wireguard`) — `withBodyFields(raw,
  {'ip': …, 'id': …, 'ib': …})` из `services/tailscale_network.dart`. Он
  переформатирует JSON с отступом 2 и роняет комментарии — так же, как Save
  Source (P12), отдельного сообщения не нужно.
- **`wg_ini`** — правка только секции `[Interface]`: убрать строки с ключами
  `Ip`/`Id`/`Ib` **без учёта регистра** (и с пробелами вокруг `=`), новые
  дописать после последней непустой строки `[Interface]` в виде `Ip = quic`.
  Остальные строки, комментарии, порядок, переводы строк (`\r\n`) — байт в
  байт (§456). Регистр имён ключей сверить с ридером INI разбора
  (`ini.Interface.Ip`) — если он чувствителен к регистру, писать ровно так.
- **`uri`** (`wireguard://`, `wg://`, `awg://`, `amneziawg://` с query) —
  правка query **на уровне строки**: найти и заменить или удалить пары
  `ip=`/`id=`/`ib=`, новые дописать в конец query, фрагмент `#тег` не
  трогать. `Uri.queryParameters` и пересборку `Uri` не использовать: они
  перекодируют прочие параметры и съедают сырой `+` в ключах (§421).
  Значения кодировать `Uri.encodeQueryComponent` (у LDH-домена и enum
  кодировать нечего, но чужой мусор в старом значении удаляется целиком).

### 2. Виджет секции — `lib/widgets/masquerade_fields.dart` (новый)

Вынести из `warp_wizard_screen.dart` (строки ~880–990) три поля с подсказкой
и кубиком в общий виджет. Визард и экран узла используют один виджет:
подсказки по протоколу и проверка домена не расходятся.

Попутно — исправить подсказку визарда для `quic`: сейчас там «QUIC/STUN
decoy carries no hostname — the domain below is cosmetic», что неверно с
§617 и контракта 1.1.58 (домен = SNI ClientHello, обязателен). Таблица
подсказок выше — одна на оба места.

Виджет получает: начальные значения, флаги `enabled`, `sipBlocked`, текст
причины недоступности; отдаёт `Masquerade` и признак валидности.

### 3. Экран узла — `lib/screens/node_settings_screen.dart`

- В `_buildSettingsTab` — блок секции при `_node is WireguardSpec`.
- Обработчик Save секции по образцу `_saveTailscaleFields`:
  `withMasquerade(_containerRaw, m)` → `_sourceCtrl.text = …` →
  `_saveSource()`. Отличие от Tailscale: источник НЕ переводится в JSON
  (у Tailscale не-JSON источник подменяется `_jsonCtrl.text`), вид
  источника сохраняется.
- Признаки для виджета: `i1`/`i2` из `awg.fields`, `masqueradeWritability`,
  режим «только просмотр» узла подписки, грязный Source.

### 4. Локализация

Новые строки — английские ключи `getLocalText.s(...)` (около десяти:
заголовок, подписи полей, подсказки по протоколу, тексты недоступности,
ошибки домена) во все словари `assets/l10n/ui/<tag>.json`. Названия
протоколов (`quic`, `dns`, `stun`, `sip`) и браузеров — `l10n-exempt`.

## Проверка (критерии приёмки)

Юниты (`test/services/masquerade_source_test.dart`):
- INI: ключи добавляются в `[Interface]`, `[Peer]` и комментарии не
  тронуты; существующие `IP = DNS` в другом регистре заменяются; `Off`
  убирает все три; `\r\n` сохраняется.
- Ссылка: прочие параметры (включая сырой `+` в `h1`–`h4`/`i*`) байт в
  байт; фрагмент сохранён; повторная запись идемпотентна.
- JSON: ключи в корне тела, `null` убирает.
- Круг: `withMasquerade` → разбор → в модели ровно записанные `ip`/`id`/`ib`
  (для всех трёх форм, на образцах корпуса `ini_masquerade_sugar.body` и
  `warp_masquerade_ip_id_ib.uri`).
- `masqueradeWritability`: `awg://` base64 и `vpn://` → недоступно.

Виджеты:
- узел с `i1` → поля выключены, текст причины виден, Save нет;
- `i2` задан → пункт `sip` выключен;
- `quic` с пустым доменом → Save выключен; `stun` → поле домена скрыто;
- узел подписки → Save нет.

На эмуляторе (телефон владельца не трогать):
- свой WG-узел из `.conf` → Settings → Masquerade `quic` + домен → Save →
  в Source появились `Ip`/`Id`/`Ib`, строка узла на главном показывает
  уровень `+`, туннель поднимается;
- WARP-узел из визарда → смена `quic` → `dns` → ссылка в Source изменилась
  только в `ip`/`id`/`ib`;
- узел с явным `I1` → секция недоступна с причиной.

## Открытые вопросы (с рекомендацией)

1. **Упакованные источники (`awg://` base64, `vpn://`).** Можно распаковать
   INI, поправить, упаковать обратно. Рекомендация: в этой задаче не делать,
   секция недоступна с причиной. У `vpn://` упаковка — `qCompress` JSON
   Amnezia со своими полями (§110), обратная сборка — отдельный риск;
   `awg://` base64 редкий.
2. **Секция у узла без AWG-полей.** Включение маскировки делает узел
   AmneziaWG: подпись Protocol и уровень `awg1.5+` в списке. Рекомендация:
   так и оставить, это правда о том, что уйдёт в ядро.

## Не входит

- Форма для прочих полей WG/AWG (`jc`, `jmin`/`jmax`, `s*`, `h*`, `i2`–`i5`,
  AWG 3.x) — решение 29.09 в силе.
- Кнопка «убрать `i1` и включить маскировку» — пользователь правит Source сам.
- Overrides маскировки для узлов подписки (P14).
- Изменения ядра и контракта.

## Реализация (10.10.2026)

Открытые вопросы владелец закрыл по рекомендациям: упакованные `awg://`
base64 и `vpn://` не распаковываются (секция недоступна с причиной); у
обычного WG-узла маскировка делает его AmneziaWG.

- `lib/services/wireguard/masquerade_source.dart` — `Masquerade`,
  `masqueradeWritability`, `withMasquerade`, `masqueradeKeysPresent`,
  `masqueradeDomainError` (шаблон и длина — из реестра `id.pattern`/`id.max`,
  без реестра — копия шаблона).
- `lib/widgets/masquerade_fields.dart` — общее: списки значений, подсказки
  по протоколу, тексты ошибок домена; `MasqueradeFields` — форма визарда
  WARP (три поля с подписью в рамке, без Off); `MasqueradeSection` — строки
  экрана узла (ревизия 1). Браузер у секции имеет пункт Default (`ib` не
  пишется), у визарда — нет.
- Ревизия 1: заголовок — `_sectionHeader` экрана; строки `ListTile`, тап →
  диалог (радио-список протокола/браузера, диалог домена с кубиком и
  подсказками пула), выбор пишется сразу (`_saveMasquerade` →
  `withMasquerade` → `_saveSource`). При отказе Source возвращается к
  сохранённому тексту, иначе он остался бы «грязным» и секция заблокировалась
  бы. Переходы протокола — `Masquerade.withProtocol` (юниты); если на QUIC
  пул пуст, перед записью открывается диалог домена. Грязный Source → snack
  «Source has unsaved changes.», выбор не открывается.
- INI: новые строки встают после последней строки-ключа `[Interface]`, а не
  после последней непустой — комментарий перед `[Peer]` остаётся при `[Peer]`
  (из него берётся имя узла ссылки на конфиг).
- Визард WARP: ошибка домена показывается, но кнопку создания не держит;
  пустой домен у QUIC не ошибка — визард подставляет случайный.

Отклонение: у узла подписки (P14) вкладки Settings нет — его открывает
экран осмотра (`NodeInspectScreen`: JSON / Source / Replacements). Секция
туда не добавлена; режим `readOnly` из первой версии виджета в ревизии 1
убран — у него не было потребителя.

Ревизия 2: `Masquerade.withProtocol(p, randomDomain:)` — случайный домен
передаёт вызывающий (`randomSni()` пула), юниты детерминированы; у `quic`,
`dns`, `sip` пустой домен заменяется им, у `quic` пустой браузер — `chrome`
(`kMasqueradeDefaultBrowser`). Пул пуст — до записи открывается диалог
домена (у `dns`/`sip` в нём можно оставить пусто). Поле домена —
`MasqueradeDomainField`: один `TextField` в рамке с подписью, в `suffixIcon`
кубик и стрелка (`MenuAnchor` со всем пулом); тот же виджет в диалоге
домена и в визарде WARP. Визард по умолчанию уже брал случайный домен пула
и `chrome` — не менялся. Описание секции — «AmneziaWG 1.5 parameters: decoy
packets before the WireGuard handshake.».

Эмулятор исполнителем не гонялся: сценарии раздела «Проверка → На
эмуляторе» — за владельцем.

## Ревизия 1 (10.10.2026, владелец посмотрел на эмуляторе)

Замечания владельца: подписи полей «прыгают» (Protocol и Browser — слева от
поля, Domain — над полем), своя кнопка Save у секции лишняя. Решение
владельца: **«всё как смена detour»**. Поправка перекрывает разделы «Поля»
(в части вида), «Save секции», «Ключевые узлы → 2, 3» и соответствующие
критерии приёмки выше.

**Вид — как блок Detour на этом же экране** (`_buildSettingsTab`, Detour
server):
- `_sectionHeader("Masquerade", "Decoy packets before the WireGuard
  handshake")`;
- строки — `ListTile` с иконкой слева, `title` = имя параметра, `subtitle` =
  текущее значение, `trailing: chevron_right`, тап открывает выбор:

| Строка | subtitle | Тап | Видна |
|---|---|---|---|
| Masquerade protocol | `Off` · `QUIC` · `DNS` · `STUN` · `SIP` | диалог-список с радио; `SIP` выключен с подписью при явном `i2` | всегда |
| Masquerade domain | домен; у `dns`/`sip` пустой — «Generated by the core» | диалог: поле ввода + кубик (`suffixIcon`) + подсказки пула; ошибка домена — `errorText`, OK выключен, пока ошибка | при `quic`, `dns`, `sip` |
| Browser | `Default` · `Chrome` · `Firefox` · `curl` | диалог-список с радио | при `quic` |

- под строками — подсказка по протоколу мелким текстом (`bodySmall`,
  `onSurfaceVariant`), как строка «Traffic goes directly to this server.» под
  Detour;
- секция недоступна (явный `i1`, упакованная ссылка, Xray) — строки
  `enabled: false`, причина — тем же мелким текстом под заголовком.

**Сохранение — сразу по выбору, как `_pickDetour` → `_persistDetour`.**
Кнопки Save у секции нет; дискета в шапке маскировку не касается.
- Выбор в диалоге → `withMasquerade(<сохранённый источник>, m)` → запись тем
  же путём, что Save Source (тег, ворота ядра для JSON, транзакционная запись,
  перечитывание), сообщение «Saved» или отказ ядра snack-ом; при отказе
  значение в строке остаётся прежним.
- Переход протокола: на `QUIC` с пустым доменом — домен подставляется
  случайный из пула (как в визарде), иначе запись невалидна; уход с `QUIC`
  снимает `ib`; `STUN` снимает `id`; `Off` снимает всё.
- Если на вкладке Source есть несохранённая правка — тап по строке не
  открывает выбор, snack «Source has unsaved changes.» (запись в источник
  иначе затёрла бы её).

**Визард WARP.** Поля там остаются формой (визард создаёт узел одной кнопкой),
но вид — единообразный: все три поля с подписью в рамке
(`InputDecoration.labelText` + `OutlineInputBorder`), как прочие поля
визарда; отдельные подписи-строки (`_label`) у этих полей убрать. Общими у
визарда и экрана узла остаются подсказки по протоколу, проверка домена и
список значений — виджет секции экрана узла от формы визарда отделяется.

Критерии приёмки: виджет-тесты — у секции нет кнопки Save; строки и их
видимость по протоколу; `i1` → строки выключены, причина видна; `i2` → `SIP`
в диалоге выключен; диалог домена не пускает OK при ошибке. Переходы
протокола (`QUIC` с пустым доменом → домен подставлен; уход с `QUIC` → без
`ib`; `STUN` → без `id`) — юнитами чистой функции, без поднятия экрана с
`BoxVpnClient`.

## Ревизия 2 (10.10.2026, владелец на эмуляторе)

1. **Умолчания при включении маскировки** (уточнено владельцем: «когда
   ставим режим маскировки — автоматически подстановку домена какого-нибудь
   случайного»). При выборе `QUIC`, `DNS` или `SIP`, если домена нет, —
   случайный домен из пула (`randomSni`); заданный домен сохраняется. У
   `DNS`/`SIP` пустого домена («Generated by the core») при включении больше
   не бывает; стереть его руками в диалоге по-прежнему можно. `STUN` домен
   снимает, как раньше. Browser при `QUIC` — `Chrome` (а не `Default`). Те же
   умолчания — в визарде WARP. Пул пуст — открывается диалог домена до
   записи (как сейчас).
2. **Поле домена — комбобокс с кубиком в одной рамке** (владелец: «надо
   сделать выпадающий список», «комбобокс + кубик надо так оформить»). Одно
   поле `TextField` с `OutlineInputBorder` и подписью в рамке (как Tag); в
   `suffixIcon` — ряд из двух иконок: кубик (случайный домен из пула) и
   стрелка (открывает меню со ВСЕМ пулом независимо от введённого текста,
   `MenuAnchor` или аналог; выбор пункта ставит домен в поле). Свой домен
   вписывается руками. Подсказка протокола — `helperText`, ошибка —
   `errorText`. Кнопок вне рамки нет, отдельного списка под полем нет. Тот же
   виджет поля — в диалоге домена на экране узла и в визарде WARP.
3. **Откуда пул** (вопрос владельца): `assets/warp_endpoints.json`,

4. **Заголовок секции называет уровень AWG** (владелец). Заголовок —
