## Проблема

В редакторе Направления под полем «Node filter (regex)» видна только строка
«matched: N / M nodes». Каких узлов коснулся фильтр, не видно; эмодзи
приходится набирать с клавиатуры. В лаунчере у того же поля есть окно
Emoji picker: regex, сетка эмодзи из имён узлов со счётчиками и полный список
узлов с отметкой ✓/✗.

## Решение

1. Справа от поля Node filter — иконка-кнопка (tooltip «Open picker»).
   Пока пул кандидатов считается, кнопка неактивна.
2. Кнопка открывает полноэкранный экран «Node filter» (Navigator.push):
   - строка как в редакторе: `!`-тогл инверсии + поле regex (с кнопкой
     очистки), ошибка «Invalid regex»;
   - сетка эмодзи из тегов пула: эмодзи + число узлов, где он встречается,
     по убыванию частоты (тот же порядок и то же определение эмодзи, что у
     чипов home, `NodeFilter`); тап — toggle эмодзи в OR-паттерне (`a|b`),
     выбранные подсвечены — поведение чипов home (§048);
   - счётчик «N / M match»;
   - список всех узлов пула: попавшие (с учётом инверсии) — сверху,
     зелёным с ✓, остальные — ниже, приглушённо с ✗; порядок внутри групп —
     порядок пула. Невалидный regex — список без отметок не рисуется, только
     ошибка.
3. Применение — ✓ в AppBar: паттерн и инверсия возвращаются в поля
   редактора (редактор становится dirty, сохраняет Save редактора). Назад без
   изменений — просто закрыть; с изменениями — стандартный диалог
   Save/Keep/Discard (`showUnsavedChangesDialog`), Save = применить.
4. Совпадение — та же логика, что у превью редактора: регистронезависимо
   (§301), пустой паттерн = все узлы, инверсия выбирает не совпавшие.

## Границы

- Поле Default (regex) пикера не получает.
- Пул — тот же `nodePool` редактора (§674), без туннеля работает.
- Новых данных в хранилище нет.
