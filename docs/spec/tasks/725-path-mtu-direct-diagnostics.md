## Problem

Нет способа узнать, какой размер пакета реально проходит через сеть
пользователя. Когда оператор молча роняет пакеты крупнее ~1300 байт,
WireGuard / AWG / MASQUE с дефолтным MTU не работают, а пользователь видит
только «всё висит». Нужен замер и готовая рекомендация, какой MTU ставить узлу.

Попутно: на вкладке Diagnostics узла Endpoint выбирается только из четырёх
готовых чекеров, свой адрес ввести нельзя.

## Решения владельца (не пересматривать)

1. Замер идёт **без ядра**: `ProbeStun` / `ProbeUdpMTU` / `ProbeTcpMTU` в ядро
   не добавляем.
2. Замер работает **при любом состоянии VPN**: небольшой Kotlin-код —
   непривилегированный ICMP-сокет, привязанный к физической сети через
   `Network.bindSocket`, с запретом фрагментации. Системный `/system/bin/ping`
   не используем (при включённом VPN он уходит в tun; `-I` требует
   `CAP_NET_RAW`).
3. Инструмент живёт **у узла direct** (`direct-out`), на его вкладке
   Diagnostics. Отдельной вкладки в общем разделе Diagnostics нет.
4. Вкладка Diagnostics узла — **острова**: остров Check (как сейчас) и под ним
   отдельный остров Path MTU со своей кнопкой и своим результатом. Не
   совмещать в одну секцию.
5. **Цель управляется**: поле Target, дефолт `8.8.8.8`, IP или имя хоста.
6. Верхняя граница поиска — **MTU физического интерфейса** (не константа
   1500; 1500 — запасное значение, когда система MTU не сообщила). MTU
   интерфейса показывается в острове сразу, до запуска.
7. Главный результат — **наибольший размер IP-пакета, который прошёл**
   (пришёл ответ). Именно размер пакета целиком, не нагрузка ping.
8. **Endpoint в острове Check — комбобокс**: готовые чекеры из списка или свой
   URL. Для всех узлов (остров общий).

## Макет

Узел `direct-out`, вкладка Diagnostics:

```
╭──────────────────────────────────────────╮
│ CHECK                                    │
│ Request is sent through this node        │
│ ┌─ Endpoint ─────────────────────────┐   │
│ │ https://1.1.1.1/cdn-cgi/trace    ▾ │   │   ▾ — готовые чекеры по названиям
│ └────────────────────────────────────┘   │
│ [ ▶ Run ]                                │
│ RESPONSE                            ⧉    │
│ …сырой ответ, как сейчас…                │
╰──────────────────────────────────────────╯

╭──────────────────────────────────────────╮
│ PATH MTU                                 │
│ Largest packet that reaches the target   │
│ unfragmented. Probes bypass the tunnel.  │
│                                          │
│ Interface   wlan0 (Wi-Fi) · MTU 1500     │
│ ┌─ Target ───────────────────────────┐   │
│ │ 8.8.8.8                            │   │
│ └────────────────────────────────────┘   │
│ [ ▶ Run ]                                │
│                                          │
│ Path MTU   1340                     ⧉    │
│ Network drops packets above 1340         │
│                                          │
│ Recommended tunnel MTU                   │
│ WireGuard / AWG   ≤ 1280                 │
│ MASQUE            ≤ 1289                 │
│                                          │
│ ▸ Probes (7)                             │
╰──────────────────────────────────────────╯
```

- У остальных узлов острова Path MTU нет (ICMP через прокси не ходит), остров
  Check — тот же, в рамке острова.
- Путь пропускает всё: «Path MTU 1500» + «Nothing is cut on the way».
- Цель не отвечает даже на маленький пакет: «Target does not answer ping», без
  чисел и без рекомендации.
- Нет физической сети: «No network».
- «Probes (N)» свёрнуты; по тапу — список «размер · ok 38 ms / no reply /
  does not fit the interface».
- ⧉ копирует отчёт текстом целиком, включая пробы.
- Во время замера кнопка — «Stop», пробы дописываются по мере прихода.
- Стиль острова — тот же, что уже есть в приложении (найти существующую
  обёртку островов, не рисовать свою).

## Solution

### Kotlin — одна проба (примитив)

Новый файл рядом с сетевым кодом (`android/.../lxbox/vpn/` или соседний
пакет), канал — по образцу существующих `MethodChannel` в приложении. Три
метода, всё вне main-потока:

- `network` → `{iface, transport: wifi|cellular|ethernet|other, mtu}` —
  физическая сеть: `INTERNET`, без `TRANSPORT_VPN`. При поднятом туннеле —
  та, что держит `DefaultNetworkMonitor`; иначе `activeNetwork`, если она не
  VPN; иначе первая подходящая из `allNetworks`. `mtu` — `LinkProperties.mtu`,
  `0` если неизвестен. Нет сети — ошибка `no_network`.
- `resolve(host)` → IP через `Network.getAllByName` той же сети (мимо DNS
  туннеля); IPv4 предпочтительно, иначе IPv6. Литерал IP возвращается как есть.
- `probe(ip, size, timeoutMs, seq)` → `{status: ok|timeout|too_big|error,
  rtt_ms, error}`:
  - `Os.socket(AF_INET, SOCK_DGRAM, IPPROTO_ICMP)` (для IPv6 —
    `AF_INET6` / `IPPROTO_ICMPV6`); ping-сокеты на Android доступны приложениям
    без прав;
  - `network.bindSocket(fd)`; если `VpnService` жив — дополнительно
    `protect(fd)`, как ядро защищает свои сокеты;
  - запрет фрагментации: `setsockoptInt(IPPROTO_IP, IP_MTU_DISCOVER=10,
    IP_PMTUDISC_PROBE=3)` — DF выставлен, кэш PMTU ядра Linux не подменяет
    результат; откат на `IP_PMTUDISC_DO=2`, если PROBE отвергнут. IPv6:
    `IPV6_MTU_DISCOVER=23` → `3`, плюс `IPV6_DONTFRAG=62` → `1`. Констант в
    `OsConstants` нет — числами, с комментарием;
  - эхо-запрос, нагрузка = `size − 28` (IPv4) / `size − 48` (IPv6);
  - `EMSGSIZE` на отправке → `too_big` (не влезает в сам интерфейс);
  - ждать ответ `poll` до `timeoutMs`; годится эхо-ответ с тем же `seq`
    **любой длины** (часть серверов обрезает ответ);
  - сокет закрывается в `finally`.

Поиск, повторы и отмена — в Dart: примитив тестируется подменой канала.

### Dart — поиск

`lib/services/diagnostics/path_mtu.dart` — чистая функция над интерфейсом
пробника (канал подменяется в тестах):

1. `network` → `hi = mtu > 0 ? mtu : 1500`; заголовки по семейству адреса.
2. Достижимость: маленький пакет (84 байта). Две попытки без ответа →
   `unreachable`.
3. Проба `hi`: ответ → `path_mtu = hi`, конец.
4. Бинарный поиск между последним прошедшим и первым непрошедшим до разницы 1.
   Нижний пол: 576 (IPv4) / 1280 (IPv6). Не прошёл и пол → «ниже пола»
   (`path_mtu` = последний прошедший размер, пометка `below_floor`).
5. Каждая проба — до двух попыток, таймаут 1000 мс; `too_big` — без повтора,
   считается непрошедшей.
6. Отмена между пробами.
7. Рекомендация: WireGuard / AWG — `path_mtu − 60` (IPv4-цель) / `− 80`
   (IPv6-цель); MASQUE — `path_mtu − 51`. Число 51 сверить с доками ядра /
   фичей 130 (SPEC 120: внешний `InitialPacketSize = mtu + 51`); разойдётся —
   взять из доков и записать сюда. **Сверено 10.11:** `docs/KERNEL.md`
   — `InitialPacketSize = mtu + 51`, число 51 верно.

## Risks and edge cases

- Замер — путь туда и обратно: ответ того же размера должен вернуться; сервер,
  обрезающий ответ, проверяет только прямой путь. Принято.
- Путь до `8.8.8.8` может отличаться от пути до сервера узла — для этого поле
  Target.
- Always-on VPN с «Block connections without VPN» может запретить обход
  туннеля — тогда пробы не пройдут, результат `unreachable`; отдельно не
  обрабатываем.
- На эмуляторе сеть — slirp: значения MTU не показательны, проверяется только
  сценарий. Настоящая проверка — телефон владельца.
- Замер через прокси-узлы и участки цепочек — не делаем.

## Реализация

- Kotlin: `vpn/PathMtuProbe.kt` (канал `com.leadaxe.lxbox/path_mtu`,
  регистрация в `MainActivity`), `BoxVpnService.live` — ссылка на живой

  (метка ставится сокету, дубликат делит его) — без скрытого API.
- Dart: `services/diagnostics/path_mtu.dart` (поиск, `ChannelPathMtuProber`),
  `widgets/path_mtu_island.dart`, слот `footer` у `NodeDiagnosticsTab`,
  подключение в `outbound_view_screen.dart` по `type == 'direct'`.
- Debug API: `/action/pathmtu` в `handlers/action.dart`, `help.dart`,
  `docs/api/debug-api-reference.md`.

Отступления от текста спеки:

- MTU интерфейса: `LinkProperties.mtu` (API 29+), а если `0` — MTU самого
  интерфейса из `NetworkInterface.getByName(iface)`: `LinkProperties` часто
  пуст, а отправка упирается именно в интерфейс. 1500 — только если неизвестны
  оба.
- Статус `cancelled` добавлен к перечню (Stop в острове; в Debug API —
  страховочная отмена через 25 с, чтобы ответ успел до таймаута запроса 30 с).
- Ниже пола `path_mtu` = последний прошедший размер (84, проба
  достижимости); рекомендация показывается только при `status: ok`.
- Остров Notifications тоже стал островом (вкладка «разложена по островам»).
