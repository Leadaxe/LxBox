## Problem

VPN Settings → Core → WireGuard. При «Suspend idle tunnels» = Off блок `lx.wg`
в конфиг не уходит вовсе: ни ленивая сборка, ни лимит собранных туннелей не
действуют, ядро собирает все WG-туннели при старте. На экране зависимые строки
серые, но показывают сохранённые значения: переключатель «Lazy tunnel build»
в положении «вкл», в «Built tunnels limit» — «12». Читается как «ленивая
сборка включена, лимит 12», и список из 212 узлов в состоянии «up» выглядит
нарушением лимита.

## Diagnosis

`TemplateVarListView._buildVarWidget` (`app/lib/widgets/template_var_list.dart`)
при ложном `#enable` оборачивает ту же строку в `AbsorbPointer` + `Opacity`.
Серый цвет говорит «менять нельзя», но не «не действует»: значение рисуется
из модели как есть.

Гейт объявления и гейт тела шаблона у этих переменных совпадают
(`wizard_template.json`: `#enable` строк и `#if wg` блока — одно условие), то
есть неактивная строка = настройка в конфиг не попадает. То же у двух
переменных Sniff guard с `#enable`.

## Solution

Неактивная строка рисуется в «недействующем» виде, сохранённое значение не
меняется и возвращается на экран, когда условие снова истинно:

- `bool` — переключатель в положении «выкл»;
- список значений (`enum` и `int`/`text` с `options`) — вместо значения
  подпись «Not in effect»;
- прочие виды (текстовые поля) — как раньше, только затемнение.

Правка общая для всех переменных с `#enable`, не только WireGuard. Модель,
сборка конфига, шаблон и контракт не меняются.
