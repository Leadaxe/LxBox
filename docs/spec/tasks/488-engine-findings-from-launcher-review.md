# §488 — дефекты движка с ревью лаунчера

| | |
|---|---|
| **Статус** | Реализовано |
| **Дата** | 2026-09-19 |
| **Источник** | ревью движка лаунчера (Go) на том же реестре; проверка, воспроизводятся ли те же дыры в LxBox |
| **Связанные** | фича 480 (движок-маппер), `registry/source_kinds.json`, `registry/protocols/hysteria2.json` (`merge: append` у `mport`) |

## Проблема

Лаунчер нашёл два дефекта интерпретатора и три мелочи на общем контракте.
Два парсера, разошедшиеся на одной подписке, дают разный набор узлов.
Задача — воспроизвести у нас и починить, если красное.

## Таблица дефектов

| Дефект | Воспроизвёлся? | Фикс |
|---|---|---|
| Два писателя в путь-список (`merge: append`/`prepend`): hysteria2 authority `host:20000-30000` + `?mport=40000-50000` → в `server_ports` оба диапазона | **Нет.** `_write` уже сливал списки; живой вход зелёный без смены тела | Вынесен общий `_mergeInto` (только списки; скаляр не меняет тип пути). Тест на живой ссылке и синтетический append/prepend |
| Двойная base64-обёртка подписки → ссылки; тройная → тихий отказ | **Да, частично.** Список из двух ссылок на 2× уже шёл через промежуточный слой (`redetect` + повторный детект той же обёртки). Одиночная ссылка на 1×/2× оставалась blob'ом: `formMatchesText` судил `contains: "://"` только по пэйлоаду после схемы, а у одной ссылки разделитель в пэйлоад не входит. 3× через запасной `_classifyLegacy` снимал ещё одну оболочку и обходил `max_unwrap_depth` | (1) `contains` сверяется с пэйлоадом **или** целым текстом, как `prefix_fold`. (2) `requires_after_unwrap` провалился, но inner снова совпал с detect обёртки → рекурсия `detect` (`depth+1`). (3) предел глубины: вид оставляем, не снимаем. (4) `mapper == null` + `unwrap` → `DecodeFailure`, без legacy. 3× — пустой набор узлов, без исключения |
| BOM (`U+FEFF`) в начале ломает вид источника | **Да.** Dart `trim` BOM снимает, но `detect` резал только хвост (`trimRight`), и предикаты видели FEFF | `_stripBom` до предиката в `matchAll`/`detect`/`_tryJson` |
| Порядок замен `label.value_map` зависит от объявления | **Да.** Обход `Map.entries` — порядок ключей JSON | Сортировка: длина по убыванию, равные — по алфавиту |
| `on_len_gt` при превышении обрывает разбор остальных записей узла | **Нет как `return` из прохода узла** (`return` был из `_applyParam` служебной записи). Но код ставился после `_valueOf`, а `$extra_*` существует ради массива, на котором обычный lookup молчит | `_applyOnLenGt` до чтения скаляра; по цепочке `source` — `continue`, не `return`; проход по записям узла не обрывается |

Снимки identity/golden/emit не переписывались. Тела существующих корпусных кейсов не менялись.

## Решение

Файлы: `interpreter.dart` (`_mergeInto`, `formMatchesText.contains`, порядок `value_map`, `_applyOnLenGt`), `document.dart` (BOM, глубина unwrap, промежуточный слой), `body_decoder.dart` (исчерпанный unwrap без legacy).

Тесты: `test/parser/engine_launcher_findings_test.dart` (hysteria2 оба диапазона; unwrap 1×/2×/3×, в том числе одиночная ссылка; BOM JSON/base64/ссылки/INI), `engine_primitives_test.dart` (append/prepend, длинный ключ раньше короткого, `on_len_gt` не роняет соседнюю запись), `document_registry_test.dart` (1× и 2× одиночной ссылки до URI).

## Критерии приёмки

- [x] `hysteria2://pw@host:20000-30000?mport=40000-50000&sni=x#n` → `server_ports` = `20000:30000` и `40000:50000`.
- [x] `base64(links)` и `base64(base64(links))` → те же узлы; `base64³` → узлов нет, без исключения. Одиночная ссылка 1×/2× раскрывается.
- [x] BOM не мешает JSON, base64-обёртке, списку ссылок, INI.
- [x] `value_map` `{a→SHORT, ab→LONG}` на метке `ab` даёт `LONG`.
- [x] `on_len_gt` ставит код и оставляет соседнюю запись узла.
- [x] Имена схем в `engine/` не появляются (`engine_no_scheme_names_test`).
- [x] `flutter analyze` без новых issues; точечные тесты зелёные.
