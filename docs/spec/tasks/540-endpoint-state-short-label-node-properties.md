## Зачем

§535 подписывал состояние WG/AWG-endpoint'а в строке списка фразой
(`Node asleep`, `Node not built yet`). Решение владельца 24.09.2026: в строке
списка — одно слово, детали — в свойствах узла.

## Решение

### 1. Строка списка (`NodeRow._endpointStateLabel`)

| Состояние ядра | Подпись |
|---|---|
| `up` | `up` |
| `asleep` | `sleep` |
| `never_built`, `torn_down`, `down` | `down` |
| `building`, не endpoint, неизвестно | пусто |

Слова — обычные строки UI (`getLocalText.s`), в словарях ru/zh значение равно
ключу: владелец хочет коротко и без перевода. Старые ключи `Node asleep` /
`Node not built yet` удалены из кода и словарей.

После §536 (`lazy_build`) все WG-узлы, кроме выбранного, после старта
показывают `down` — принято владельцем: ядро поднимет узел на первом дайле.

### 2. Свойства узла

Экран — `OutboundViewScreen`, пункт **Details** в меню строки узла на главном
(`node_actions.dart`; из трёх экранов узла §392 — этот). На вкладке Overview в
блоке Parameters новая строка **Endpoint state** только для `wireguard`/`awg`:
строка ядра как есть (`never_built` / `building` / `up` / `asleep` /
`torn_down` / `down`, не переводится), для `asleep` с простоем —
`asleep · idle for N s`. Нет состояния в карте — строки нет.

Источник — та же карта `HomeState.endpointStates`, что кормит `NodeRow`.
Простой — новая карта `HomeState.endpointIdleSince` (тег → `idleSinceSeconds`,
только для `asleep`), наполняется тем же pull'ом `_refreshEndpointStates()`
(второго `getOutbounds()` нет); `emit` — только когда изменилась хотя бы одна
из двух карт. Экран читает `homeController.state` при построении, живого
обновления на открытом экране нет.
