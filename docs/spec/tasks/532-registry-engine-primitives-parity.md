## Дефект 1 — `json.key_absent` не исполнялся

Предикат FROZEN (`PRIMITIVES.md` §0.2) в Dart отсутствовал вовсе: ключ
`key_absent` в `detect.json` не читался, а неизвестный ключ движок молча
пропускал, то есть **предикат всегда давал истину**.

Цена — не косметика: `key_absent` это то, чем реестр отличает ВЕРСИИ одной
схемы. Ветка «поля версии нет ни по одному из путей» проходила при ЛЮБОМ
содержимом, и элемент с чужой версией уезжал в секцию старшей версии. Ревизия
называет живой случай: Xray-`hysteria` с `version: 3` давал у нас узел v1,
которого по D133-28 быть не должно.

| | |
|---|---|
| До | `app/lib/services/parser/engine/interpreter.dart:853` — читаются `required_keys`/`has_key`, следующим идёт `array_elem_any_keys`; ветки `key_absent` нет |
| После | `interpreter.dart:872-880` — `key_absent`: ни один путь не существует, иначе предикат не сходится |
| Эталон | `core/config/linkmap/detect.go:293-297` (`for _, p := range j.KeyAbsent { if _, ok := lookupPath(v, p); ok { return false } }`) |

Тем же проходом добавлен **`json.any_keys`** (`interpreter.dart:865-870`) —
дизъюнкция существования, тоже FROZEN и тоже отсутствовавшая. Реестр её несёт
в `source_kinds.json` (ветка «конфиг sing-box»), и без неё вид источника
опознавался не тем предикатом. Пустой список условием не является — как у Go
(`detect.go:283-292`).

## Дефект 2 — `json.type_of` проходил при ОТСУТСТВУЮЩЕМ пути

`type_of` отвечает на вопрос «что это за значение по пути». У отсутствующего
значения ответа нет, и Go так и судит: путь обязан существовать. Dart
отсутствующий путь пропускал (`continue`), и предикат вырождался в «либо нужный
тип, либо ничего».

Почему это ломает именно реестр: различие «объект ИЛИ ключа нет» реестр несёт
СВОИМИ средствами — `any` + `key_absent` (так объявлены формы `xray/vless`,
`xray/trojan`, `xray/vmess`: контейнер `settings` обязан быть объектом всегда, а
`streamSettings` законно отсутствует у plain-TCP). Снисходительный `type_of`
делал вторую ветку МЁРТВОЙ и отнимал у реестра способ выразить это различие.

| | |
|---|---|
| До | `interpreter.dart:874-881` — `if (actual == null) continue;`, в доке: «Отсутствующий путь условию НЕ противоречит» |
| После | `interpreter.dart:885-907` — `if (actual == null) return false;`, дока объясняет, чем различие выражает реестр |
| Эталон | `detect.go:298-303` (`if !ok \|\| jsonTypeOf(got) != want { return false }`) |

Два следствия, без которых строгий `type_of` сам стал бы дефектом:

1. **`$root` как путь** (`interpreter.dart:988-994`, эталон `detect.go:445-451`)
   — «сам документ, а не ключ в нём». Реестр пишет `type_of: {"$root":
   "array"}` в `source_kinds.json` пять раз; Dart этот путь не разбирал и
   возвращал `null`. Прежде такое сходилось СЛУЧАЙНО (null пропускался), со
   строгим предикатом опознание вида источника сломалось бы целиком.
2. **`bool` в наборе имён типов** (`interpreter.dart:918-926`, эталон
   `jsonTypeOf`, `detect.go:495-509`) — у Go он есть, у нас не было, и предикат
   о булевом поле молча не сходился ни с чем.

**Оверлеи `forms` у `contract_draft/xray/trojan.json` и `xray/vless.json`
СНЯТЫ — со строгим `type_of` они не «излишни», а НЕВЕРНЫ.** Их `detect` —
плоское `type_of: {settings: object, streamSettings: object}`, то есть требует
контейнер потока ОБЪЕКТОМ. На снисходительном предикате отсутствующий
`streamSettings` пропускался, и plain-TCP элемент форму проходил; со строгим —
перестал, а оверлей ПЕРЕКРЫВАЕТ реестровую форму, у которой ровно этот случай
выражен как надо (`all`: `settings` объект И (`streamSettings` объект ИЛИ его
нет)) и прямо описан в её `impl`. Итог без снятия — живой узел vless/trojan без
транспорта перестаёт разбираться вовсе.

Поймал это CI, а не локальный прогон: `engine_trace_test` («объектный вход
пишет ту же трассу», `res` стал `null`) в мою локальную выборку гардов не
входил — гардов по движку больше, чем я прогонял, и выборку надо брать
каталогом (`test/parser`), а не списком файлов. Снятие оверлеев — ровно то
условие, которое спека задачи и ставила («снять, если после фикса оверлей
становится излишним»), просто цена ошибки оказалась выше: не лишний параметр, а
потерянный узел.

Отдельно проверено, что снятие не двигает ни тела, ни identity: состав отказов
обоих корпусных раннеров ПОБАЙТНО равен baseline, `before_480_identity_snapshot`
и `engine_xray_pilot` зелены.

## Дефект 3 — коллизия записей блока и секции: **ОТЛОЖЕН, правило не взято**

MAPPER_ENGINE §7.1 говорит: переопределением считается совпадение имени И
полного набора `source`, **а запись под условием (`when`) переопределением НЕ
считается** — условная запись исполняется лишь в части случаев, и изъять за неё
запись блока значит оставить остальные случаи без правила вовсе. Go так и делает
(`core/config/linkmap/plan.go:529-563`, `entryOverrideKey` + пропуск записей с
`len(Param.When) > 0`).

Правило было реализовано и **откачено**: оно меняет ТЕЛО и IDENTITY живого узла.

Ход отказа, воспроизведён:

1. у tuic запись `sni` (`registry/protocols/tuic.json`) условна — гейт
   `when.query.disable_sni.not_in: [1, true, yes]`, и набор `source` у неё тот
   же, что у записи блока `tls#uri` (`["query.sni","query.peer"]` — совпадает и
   как множество, и по порядку);
2. по §7.1 она блочную не изымает → обе живут;
3. запись `disable_sni` (`priority: 100`) снимает `tls.server_name` ветвью
   `sets.true`;
4. стадия дефолтов (`interpreter.dart` `_applyDefaults`) исполняет `default_from:
   host` У КАЖДОЙ записи, в том числе у дожившей блочной `sni`, чей `when`
   (`tls.enabled: true`) держится, — и `tls.server_name` ВОЗВРАЩАЕТСЯ;
5. кейс `b480:disable_sni_with_sni` меняет identity
   (`7e4334b9…` → `87b72b21…`).

Смена identity означает, что у пользователей слетают выбор узла, отключения и
цепочки, а спека прямо запрещает трогать identity в этой задаче. Строгий
ключ-по-полному-набору (как у Go) исход не меняет: наборы `source` у этих двух
записей совпадают и по порядку, проверено.

Правило берётся вместе с **разделением блока на стороне реестра** — лаунчер эту
дыру у себя закрыл именно так (блок `tls#uri_security` вынесен из `tls#uri`;
`tls.json`, `blocks.uri_security`), и `sni` у него должна разъехаться тем же
приёмом. Это задача 533, после синка 1.1.53.

| | |
|---|---|
| Где | `app/lib/services/parser/engine/section_loader.dart:384-396` — расхождение с §7.1 объявлено вслух в доке `_withIncludes`, с воспроизведением и с условием снятия |
| Эталон | `core/config/linkmap/plan.go:512-563` |

**Компенсирующий оверлей `uri/http` `$security_none_https` ОСТАЁТСЯ.** Условие
спеки «снять, если после фикса он даёт двойное применение» не наступило: фикс
откачен, двойного применения нет. Отдельно проверено, что оверлей не является
причиной отказа: при взятом правиле §7.1 и СНЯТОМ оверлее
`engine_emit_shape_test` (http) и `before_480_identity_snapshot` (tuic) падают
ровно так же — дело в записи блока, а не в оверлее.

## Дефект 4 — булев на выходе без `emit_as` писался цифрой

Написание булева в ссылке — свойство ДИАЛЕКТА, а не типа значения, и объявляет
его запись (`emit_as`). Умолчание у Go — СЛОВО; цифру даёт только явный
`emit_as: bool01`. У нас умолчание было обратным: `_emitAs` выводил `bool01` из
`type: "bool"`, а ветка «булев без объявления» писала `1`.

| | |
|---|---|
| До | `app/lib/services/parser/engine/emitter.dart:1299` — `if (p.type == 'bool') return EmitNames.emitAsBool01;`; `emitter.dart:1282-1284` — `return _firstTruthySpelling(p) ?? '1';` |
| После | `emitter.dart:1297-1304` — вывод `bool01` из типа снят, умолчание `raw`; `emitter.dart:1286-1289` — `return _firstTruthySpelling(p) ?? 'true';` |
| Эталон | `core/config/linkmap/emit.go:986-991` (`case bool: if !t { return "", false }; return "true", true`) |

Написание истины по-прежнему берётся у САМОЙ ЗАПИСИ первым ключом её
`value_map`, ведущим в истину (запись с `{"on": "true", …}` пишет `on`) — это
защита сохранённого `rawSource`, и она не менялась. Ложь не пишется вовсе:
«параметра нет» и есть её написание в ссылке.

**Проверка по эталону, а не по прозе.** Снимок `emit_snapshot.json` у лаунчера —
ЗАМОРОЖЕННЫЙ слепок РУКОПИСНЫХ эмиттеров, а не вывод движка, и он показывает
`zero_rtt_handshake=1`. Прогон `go test ./core/config/linkmap -run
TestEngineEmitVsSnapshot -v` на `origin/develop` лаунчера показывает, что
Go-ДВИЖОК на том же теле собирает **`reduce_rtt=true`** (кейс числится у него
разрешённым отличием D133-E6). После правки LxBox выдаёт ту же строку
посимвольно.

Вид трёх ссылок tuic из-за этого сменился (`reduce_rtt=1` → `reduce_rtt=true`);
отличия названы в `allowed` стража вида ссылки с причиной и ссылкой на прогон
эталона. Тел и identity смена не касается.

**Оверлеи `emit_as: raw` у трёх записей xhttp
(`contract_draft/uri/transports.json`) остаются до задачи 533**: `raw` пишет
значение как есть, и с новым умолчанием совпадает — конфликта нет.
