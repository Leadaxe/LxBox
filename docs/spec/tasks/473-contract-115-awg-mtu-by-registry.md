# §473 — контракт 1.1.5: потолок MTU AmneziaWG по реестру, коды `awg_mtu_clamped` / `awg_mtu_high`

| | |
|---|---|
| **Статус** | **Released в v2.25.0** (20.09.2026, ядро `v1.14.1-lx.8`). **Реализовано, тесты зелёные (5101 passed / 15 skipped); долг снят §472 шагом 7 — см. «Что осталось рукописным»** |
| **Дата** | 2026-09-18 |
| **Источник** | лаунчер `7b034569`, `TASKS_LXBOX.md` §24.14; решение владельца 18.09.2026 (передано сессией лаунчера) |
| **Связанные** | §421 (кламп 1280 для AWG, включая AWG 3.x), фича 460, фича 472, §469 |

## Проблема

Для AmneziaWG мы опускаем `mtu` до 1280 (`awgClampMtu` и аналоги, §421) —
молча. Пользователь задал 1420, получил 1280 и не знает об этом. Правило
живёт в коде, у лаунчера было так же.

## Решение

1. Синк контракта на `7b034569` (только `git archive`); `contract.lock`,
   зеркала `assets/contract/` и `docs/contract/` в коммит; версии в тестах
   поднять до 1.1.5.
2. Новые атрибуты поля `wireguard.body.fields.mtu` — чтение в `registry.dart`,
   исполнение в `body_sanitizer.dart`, линтер в `registry_invariant_test`:
   - `max_when {max, code, note_code, except_sources, when.any_set:[…]}`;
   - `default_when` получил условие `when.any_set` (дефолт 1280 без кода).
   `any_set` судит **наличие ключа** (`jc: 0` — законный AWG), в отличие от
   `conflicts`/`requires`, которые судят значение (§467). Два предиката не
   смешивать; назвать их в коде так, чтобы путаница была невозможна.
3. Правило работает **по телу**, не в парсере ссылки. Рукописный кламп
   (`awgClampMtu` и его вызовы в URI/INI/JSON-парсерах и эмиттере) уходит
   туда, где его теперь исполняет санитайзер. Если санитайзер на этом входе
   ещё не стоит в конвейере (фича 472 в пути) — кламп остаётся, но код
   ставится по правилу реестра, а не молча; что осталось рукописным —
   записать в спеку 472 как долг соответствующего шага.
4. Коды: `awg_mtu_clamped` (warning — значение заменено на 1280, `value` —
   исходное) и `awg_mtu_high` (info — значение сохранено).
5. Исключение по входу: для sing-box JSON (`except_sources: ["singbox"]`)
   `mtu > 1280` **не заменяется**, только `awg_mtu_high`. У нас вход — это
   `origin.kind` (`json`); узел хранится источником и разбирается заново при
   каждом старте, поэтому исключение переживает перезапуск по построению —
   закрыть тестом (разбор → сохранение → загрузка → тот же `mtu` и тот же
   код). Проверить соответствие с §455: узел `origin.kind: json` идёт в ядро
   дословно, значит замены там и не было — убедиться, что теперь есть info.
6. Тело узлов из ссылок и INI не меняется (кламп был и раньше) — golden без
   перегенерации. Меняются только предупреждения.

## Критерии приёмки

- корпус зелёный без override: 8 AWG-кейсов с `mtu > 1280` несут код, 2
  новых `body/singbox` кейса проходят;
- AWG из ссылки/INI с `mtu=1420` → тело `1280`, `awg_mtu_clamped` с
  `value=1420`; без `mtu` → `1280`, кодов нет; обычный WG с 1420 → без
  изменений и кодов;
- AWG из sing-box JSON с `mtu=1420` → тело `1420`, `awg_mtu_high`;
  переживает перезагрузку;
- `jc: 0` считается AWG-узлом (`any_set` по наличию);
- `flutter analyze` всего проекта, `flutter test -j 2` — «All tests passed»,
  `check_contract_lock.dart` зелёный;
- CHANGELOG, GUARDS.md, PROTOCOLS.md (WireGuard/AWG — MTU), спека 460
  раздел 7 (`max_when`, `any_set`), спека 472 (долг, если остался).

## Как сделано

### Реестр и санитайзер

`FieldSchema.maxWhen` — новый геттер рядом с `defaultWhen`; оба возвращают
сырую карту реестра, как и прочие атрибуты (копировать 30+ полей в класс
спека 460 отказалась осознанно). Исполнение — `_applyMaxWhen` в
`body_sanitizer.dart`, вызывается в `_sanitizeScalar` ПОСЛЕ `_checkConstraints`
и ДО `advisory`. Место выбрано не случайно: обычный `max` делает значение
негодным (`on_invalid` — поле снимается), а `max_when` оставляет узел жить, и
смешивать эти две ветки нельзя.

Три исхода правила разведены явно:

| Условие `when` | Вход | Тело | Код |
|---|---|---|---|
| не выполнено | любой | не тронуто | нет |
| выполнено | не в `except_sources` | заменено потолком | `code`, warning |
| выполнено | в `except_sources` | **не тронуто** | `note_code`, info |

`default_when` получил ту же проверку условия: без неё дефолт 1280 достался бы
каждому обычному WireGuard-узлу, а он поля `mtu` не получает вовсе (ядро берёт
свой 1408, и наш дефолт ломал бы identity-хеш, PARSING_PRINCIPLES §2.4).

### Два предиката

Спека требовала назвать их так, чтобы путаница была невозможна. Сделано именами
и местом: `_anySetInBody` («ключ присутствует») стоит прямо над `_meaningful`
(«значение задано»), и у обоих в докблоке написано, чем обернётся смешение.

| | `_meaningful` (§467) | `_anySetInBody` (§473) |
|---|---|---|
| Кто читает | `conflicts`, `requires` | `when.any_set` у `max_when`/`default_when` |
| Что судит | значение | наличие ключа |
| `jc: 0` | не задано | **задано** — законный AWG |
| Цена ошибки | снятая рабочая настройка (13 узлов xmux, §467) | снятый потолок MTU: туннель поднимается, данные не идут |

Условие читается по ИСХОДНОМУ телу (`root`), а не по уже очищенному: род узла
задаёт то, что написал автор. Битый `jc`, снятый санитайзером строкой выше,
AmneziaWG-узел AmneziaWG-узлом быть не перестаёт — то же основание, что у
рукописного `isAwg` в §463.

### Источник входа

`BodySource` — перечисление из двух значений (`singbox` / `other`) с полем
`registryName`. Словарь `sources` реестра (`uri`/`singbox`/`xray`/`wgconf`/
`amnezia`) намеренно не повторяется целиком: правило одно, и делит оно ровно
надвое; появится второе с другим делением — перечисление расширится по нему.

Параметр `sanitize(source:)` — явный, без глобального состояния: оно разошлось
бы с телом на первом же параллельном разборе. Дефолт `other` консервативен —
«вход неизвестен» значит «правило работает заменой, как раньше».

Источник доступен на всех трёх путях:

| Путь | Откуда вход | Значение |
|---|---|---|
| `annotateFromRawBody` (§472 шаг 1) | сам проход идёт по карте sing-box | всегда `singbox` |
| `annotateWithRegistry` (`emit()` модели) | `bodySourceOf(node)` — тот же признак, что у прохода выше | по узлу |
| `applyRegistryGate` (сборка) | множество `ctx.verbatimEntries`, которое ведёт `server_list_build` | по записи |

**Оба прохода разбора обязаны видеть ОДИН вход.** Разойдись они, узел из
sing-box-тела получил бы по дословной карте info `awg_mtu_high`, а следом по
`emit()` — warning `awg_mtu_clamped` о том же поле: коды разные, дедуп по паре
`(code, path)` их не схлопывает, и человек прочёл бы два противоположных
сообщения об одном `mtu`. Поэтому `bodySourceOf` опознаёт вход ровно тем
признаком, которым `annotateFromRawBody` опознаёт свою карту (`rawSource` —
JSON-объект с полем `type`): второго ответа на вопрос «чей это вход» в коде
нет.

Вход СТАБИЛЕН и потому переживает перезапуск: `rawSource` — то, что лежит в
хранении (§454–§456), и разбор идёт заново при каждой загрузке. Считай мы вход
из чего-то сессионного (флаг импорта, путь вызова), узел с `mtu: 1420` получил
бы кламп задним числом при следующем старте — настройка человека исчезла бы
молча. Закрыто тестом «исключение по входу ПЕРЕЖИВАЕТ перезапуск»
(разбор → `sourceToRecord` → JSON → `sourceFromRecord` → тот же `mtu` и тот
же код).

### §455 — узел `origin.kind: json` идёт в ядро дословно

Гард сборки — единственный, кто тело ПЕРЕПИСЫВАЕТ, поэтому исключение обязано
соблюдаться именно там; без метки он заклампил бы `mtu: 1420` на сборке, то
есть ровно то, чего §455 не позволяет. Гард работает над `SingboxEntry`, а тот
источника не знает и знать не может — метку ведёт тот, кто тело подставил:
`server_list_build` зовёт `ctx.noteVerbatim(main)` там же, где применяет
`verbatimBodyOf`. Новый метод `EmitContext.noteVerbatim` с пустой реализацией
по умолчанию (пул звеньев тел в конфиг не отдаёт).

Закрыто парой тестов в `registry_gate_test`: то же тело с меткой — `mtu` цел,
info-код; без метки — заменён, warning-код. Пара намеренно рядом: различие
входов НАМЕРЕННОЕ, и держать его надо на виду.

### Что осталось рукописным — СНЯТО §472 шагом 7 (18.09.2026)

> **Долг закрыт.** `awgClampMtu`, `awgMtuByRegistry` и `awgMtuWarnings` сняты
> РАЗОМ вместе со всеми вызовами: потолок и дефолт исполняет санитайзер
> (`body_sanitizer.dart`), по телу, на всех входах. Причина, по которой они
> существовали, отпала вместе с переездом — в конвейере санитайзер тело
> ПЕРЕПИСЫВАЕТ (`parseSingboxEntry` кормится очищенной картой), в отличие от
> проходов-аннотаторов, где очищенная карта выбрасывается. Тела узлов из
> ссылок и INI при этом не изменились ни на один кейс: эталоны корпуса
> сошлись байт в байт, identity — у 100 проверенных входов.
>
> За конвейером остались два случая, до которых санитайзер не достаёт, и оба
> опасны молчанием: вход, который ПРОСИЛ AmneziaWG, но не донёс ни одного
> годного AWG-поля (условие `when.any_set` судит ключи в теле, а их там не
> осталось — §463), и НЕЗАГРУЖЕННЫЙ реестр. Запасное число `kAwgMtuFallback`
> сохранено намеренно — решение «молчание тут не безопасно» в силе; закрыто
> тремя тестами в `awg_test.dart`, файле, который реестр не грузит по
> построению. Подробности — спека 472, раздел 13.4.

Текст ниже сохранён как постановка задачи.

Замену на входах ссылки и INI по-прежнему делает парсер (`awgClampMtu`), и
это не недоделка, а следствие границы: тело узла из ссылки нормировано
корпусом и меняться не должно (эталоны `uri/wireguard/*` сверяются байт в
байт), а санитайзер разбора тело не переписывает (§460 W2a, граница 1).
Число 1280 в Dart при этом НЕ осталось — и потолок, и дефолт читаются из
реестра (`awgMtuByRegistry`), а код о замене ставит `awgMtuWarnings` по тому
же правилу `max_when`. Это тот же приём, которым §469 ставит коды запрещённых
TLS-блоков на QUIC-схемах, и по той же причине: санитайзер до значения не
дотягивается, но второй копии правила в Dart заводить нельзя.

Записано долгом шага 7 фичи 472 — снимать надо разом `awgClampMtu`,
`awgMtuByRegistry`, `awgMtuWarnings` и их вызовы.

### Найденное на тестах

**Реестр может быть не загружен — и это меняло поведение.** Первый полный
прогон дал 7 красных в `awg_test`/`amnezia_link_test`: эти файлы реестр не
грузят, а `awgMtuByRegistry` при отсутствии схемы возвращал значение БЕЗ
потолка. Для дефолта запасное число было, для потолка — нет, и AWG-узел со
ссылочным `mtu: 1420` уехал бы с ним в ядро. Дефект наш, починен: без реестра
работает `kAwgMtuFallback = 1280`. Молчание тут не безопасно, в отличие от
кодов, где выдуманный код хуже его отсутствия.

**Инвариант идемпотентности потребовал уточнения.** Норма 24.1.7 — «значение с
вердиктом B после санитайзера в теле остаться не может», и проверяется она
вторым проходом: он обязан молчать. `awg_mtu_high` молчать не может по
устройству — это info о значении, которое реестр ОСТАВЛЯЕТ, и оно повторяется
на каждом проходе ровно потому, что тело не меняет (так же ведут себя
`advisory`-коды). Проверка сузилась до кодов не-`info`; устойчивость тела
по-прежнему проверяет сравнение `second.body == first.body`.

Заодно инвариант стал брать вход из ПУТИ кейса (`body/singbox/**` →
`singbox`). Без этого `endpoints_awg_mtu_high` был бы зелёным ложно: первый
проход заклампил бы 1420 до 1280, второй промолчал бы, и инвариант
подтвердился бы на теле, которого в приложении не бывает.

**Корпус зелёный без единого override.** Восемь URI-кейсов с `mtu > 1280`
получили код (тела не менялись — кламп отрабатывал и раньше), два новых
`body/singbox` кейса прошли сразу.
