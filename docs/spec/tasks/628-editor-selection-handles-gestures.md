# §628 — Ручки выделения в редакторе JSON уводят вкладку и страницу

| Поле | Значение |
|------|----------|
| Тип | Исправление |
| Статус | I (implemented), ждёт проверки на устройстве |
| Дата | 2026-10-12 |
| Связанные | §624 (sora-editor во всех JSON-полях), issue #167 |

## Проблема

Экран узла, вкладка Source, клавиатура открыта. Выделяешь слово
долгим тапом, тянешь ручку выделения — вместо неё едет вкладка
(TabBarView уходит к JSON) или скроллится страница.

## Диагностика

`LxCodeEditor._buildNative` раздаёт жесты platform view так:

- текст не помещается в поле (`scrollable`) — `EagerGestureRecognizer`,
  все жесты у редактора;
- текст помещается — только `HorizontalDragGestureRecognizer` и
  `LongPressGestureRecognizer`; вертикальный свайп уходит странице.

На Source поле растёт по содержимому (`_Fit.grow`), текст помещается,
работает вторая ветка. Ручку тянут в любом направлении: вертикальная
составляющая достаётся скроллу страницы, горизонтальную выигрывает
свайп TabBarView.

## Решение

Натив в событии `cursor` шлёт `selected` (`Cursor.isSelected`). Пока
выделение есть, обёртка ставит `EagerGestureRecognizer` в обоих режимах.
Без выделения поведение прежнее: вертикальные свайпы по короткому полю
скроллят страницу.

Набор распознавателей меняется со следующего жеста. Выделение появляется
по долгому тапу, ручку тянут уже новым касанием, так что задержки
пользователь не замечает.

## Проверка

- Source, текст помещается: выделить слово, тянуть ручки вверх, вниз,
  вбок — двигается выделение, вкладка и страница стоят.
- Снять выделение тапом — вертикальный свайп по полю снова скроллит
  страницу.
- Длинный текст (поле со скроллом) — как раньше.
