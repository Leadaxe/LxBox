# §633 — Merge при импорте бэкапа — настоящее слияние

| Поле | Значение |
|------|----------|
| Тип | B (баг) |
| Статус | D (done), выпущено в v2.25.13 |
| Фича | [017-BACKUP_AND_STORAGE](../features/017-BACKUP_AND_STORAGE/FEATURE.md) |

| Связанные | §599 (замена по категориям), §524 (цепочки — Server lists), §413/§447 (свойства устройства), §370 (ось `num`) |

## Проблема

Окно импорта обещает для Merge «Adds new items, keeps existing.»
(`app/lib/screens/backup_screen/import_preview_dialog.dart:149`). Сливались на
деле только источники Server lists (дописывались по `id`). Всё остальное шло
upsert'ом верхнего уровня (`app/lib/services/settings_storage/backup_tun.dart:163-177`
до правки): ключ из файла целиком заменял ключ получателя.

- Routing: `rules`, `directions`, `dns` (серверы и правила), `tun_apps`,
  `route_final` — из файла целиком; свои правила, Направления и DNS пропадали.
- App settings, Debug: подключи `vars` — upsert по ключу, значение файла
  побеждало (`backup_tun.dart:170`).
- VPN toggles: все ключи файла применялись (`backup_service.dart:515`).
- Цепочки: архив с цепочками заменял цепочки получателя целиком
  (`backup_service.dart:458`).
- Debug API `POST /backup/import?merge=true` — тот же upsert, источники тоже
  заменялись списком (`debug/handlers/backup.dart:124`).

Решение владельца: если есть выбор «слияние или перезапись», слияние должно быть
слиянием.

## Решение

Одно правило для всех категорий: Merge добавляет то, чего у получателя нет, и не
трогает то, что у него есть. Списки сливаются по идентичности записи, скаляры —
значение получателя, отсутствующий у получателя ключ берётся из файла.

| Категория / ключ | Было | Стало |
|---|---|---|
| Server lists — источники | дописываются по `id` | так же |
| Server lists — цепочки | архив заменял все цепочки | дописываются по тегу; тег, занятый цепочкой или Направлением получателя, пропускается |
| Routing — правила (`rules`) | список файла целиком | пресет — по `ref`; прочие — по `id` или по содержательному отпечатку (JSON с сортировкой ключей, без `id`/`num`/`enabled`); новые — в конец пользовательских правил |
| Routing — пресеты | файл | включён, если включён у кого-либо; параметры (`vars`) — у того, у кого включён; включён у обоих или выключен у обоих — параметры получателя |
| Routing — Направления | список файла | по тегу; существующий тег (в том числе `vpn-1`) — получателя; новый — в конец; тег, занятый цепочкой получателя, пропускается |
| Routing — DNS-серверы | список файла | по `tag` (у preset — `ref`) или отпечатку (без `enabled`); новые в конец |
| Routing — DNS-правила | список файла | preset — по `ref`, template — по `name`, прочие — по `id` или отпечатку; новые в конец |
| Routing — Tunnel apps | файл | пакеты объединяются (без повторов, по алфавиту); режим получателя, если он не Off; Off — режим файла |
| Routing — `route_final`, `vpn_mode`, прочие скаляры | файл | получателя; отсутствующий — из файла |
| App settings — `vars` и ключи верхнего уровня | файл побеждал | получателя; отсутствующий — из файла |
| Debug config — `vars.debug_*` | файл побеждал | получателя; отсутствующий — из файла |
| VPN toggles | все ключи файла | только ключи, которых нет в зеркале `native_prefs` получателя |
| Replace all | — | не менялся |

### Код

- `app/lib/services/backup_merge.dart` — `mergeStorageDoc(current, incoming)`:
  слияние над JSON-документом, итог — `StorageMergeStats` (по группам
  `added` / `kept`, скалярные ключи — списками имён).
- `backup_tun.dart` — `_replaceRaw` разделён: `_filterSnapshot` (миграция +
  allowlist, общий для обоих режимов), `_applyReplace` (прежняя замена §599 без
  изменений), ветка Merge зовёт `mergeStorageDoc`; `_previewMergeRaw` — то же
  слияние на копии без записи.
- `SettingsStorage.replaceRaw(..., onMerged:)` отдаёт итог;
  `SettingsStorage.previewMergeRaw`; `applyNativePrefsBackup(..., onlyMissing:,
  onKept:)`.
- `BackupService.applyImport` — цепочки по тегу, `BackupApplyResult.merged` /
  `mergeKept`, для Merge `*Applied` = добавлено; `previewMerge(contents)` —
  счётчики по категориям для окна; `mergeCountsByCategory` раскладывает итог по
  категориям (`categoryOfTopLevelKey` / `categoryOfVarKey`).
- Окно импорта: под каждой категорией в режиме Merge — «new: N, already here: M»;
  подпись режима — «Adds what you don't have, keeps everything you do.» (8.4:
  чем вариант отличается от соседнего Replace all).
- Итог после импорта в режиме Merge — «Merged: N added, M already here».
- Debug API: `applied.merge` — `StorageMergeStats.toJson()`,
  `applied.vpn_settings_kept`.

### Порядок правил

Новое пользовательское правило получает `num` = максимум занятой части зоны
1000..1100 у получателя + 1, затем по одному (на границе зоны — 1100, порядок
доопределяет позиция в списке, как у `nextUserRuleNum`). Правило файла с номером
вне зоны (перетащенное выше пресета) тоже встаёт в зону: свои правила получателя
выше по приоритету. Новый пресет приезжает со своим номером (номер шаблона).

### Отступления от брифа

- Идентичность правил — `id` **или** отпечаток, а не «`id`, иначе отпечаток»:
  `id` есть у каждого правила, и одно и то же правило, созданное на двух
  устройствах, имеет разные `id`; без отпечатка Merge двух копий дублировал бы
  его. Пресеты сравниваются по `ref`: у одного пресета на разных устройствах
  разные `id`, а повтор пресета по `ref` §398 схлопывает.
- Цепочки в брифе не названы; при Merge они тоже заменялись — переведены на
  слияние по тегу тем же решением владельца.
- Превью — полное (счётчики по категориям), а не минимум.

## Риски и граничные случаи

- **Порядок правил.** Отпечаток различает правила по имени и телу: одно правило
  с переименованием на одной стороне приедет дубликатом. Принято: лишнее правило
  видно и удаляется, пропавшее — нет.
- **Коллизии тегов.** Направление и цепочка с одним тегом сломали бы конфиг —
  такая запись файла пропускается (считается как «already here»). Новое правило
  или DNS-сервер из файла, ссылающиеся на Направление, которого у получателя нет и
  которое не приехало (категория снята), ведут себя как прежде: висячие ссылки
  схлопывает сборка (`directions` в STORAGE.md, «Reference degradation»).
- **Пресет, включённый слиянием,** берёт параметры файла; его DNS-сервер
  `kind: preset` сливается отдельно по `ref` — если у получателя его нет, он
  дописывается.
- **VPN toggles.** Зеркало `native_prefs` засевается всеми ключами при первом
  старте (§189), поэтому на живом устройстве Merge тумблеры не меняет — все
  уходят в «already here». Это и есть «Merge ничего не затирает».
- **Миграции.** Блок файла мигрирует до слияния (§439), слияние идёт над формой
  1.0. `storage_version` получателя не меняется. `migrateDirectionsIfNeeded`
  после слияния — no-op при наличии `directions`.
- **Debug API.** `merge=true` теперь дописывает источники по `id` (цепочки по
  тегу), а не заменяет `sources[]` целиком.
- Merge не удаляет ничего: снять запись получателя может только Replace all.
