**Тип:** таска (меняется поведение экрана)
**Статус:** РЕАЛИЗОВАНО + **DEVICE-VERIFIED** (02.08.2026)

> 2679 тестов зелёные, analyze чист (весь проект), 4 l10n-чекера 0 failures.

> Internet; Members «8 · 2 in pool», галки у живых, задержки цветные.

## 1. Симптом

Скриншот юзера (02.08.2026): экран `View details` узла автовыбора
«🇵🇱 Польша | Авто⚡», режим — round_robin.

```
Parameters
Type      urltest
Members   4

Route
Живой путь в порядке следования пакета.
 📱 Phone
 ❓ (пустая строка)
    not in config · current pick      ← призрак
 🕸 🇵🇱 Польша | Авто⚡
    urltest · this node
 🌐 Internet
```

Две ошибки в одном экране:

1. **Призрачный хоп** — строка без имени с подписью `not in config · current pick`.
2. **Мёртвая цифра** `Members: 4` — состав не посмотреть, хотя ядро его отдаёт.

## 2. Причина

Экран остался на модели §258 «группа = один выбранный узел». §322 этот
инвариант уже отменил для round_robin — таблица §6.3:

> стрелка «→ выбранный» при round_robin — **не рисуется**; одного выбранного
> там нет; вместо неё значки пула

На главном экране правило соблюдено (`🔀 [15/7]` + значки живого пула), до
`OutboundViewScreen` не доехало. Grep по файлу: `mode`, `balancer`,
`getPool` — ноль совпадений.

Механика призрака:

| шаг | файл | что происходит |
|---|---|---|
| 1 | `cc_channel.dart:476` | `selected: m['selected']?.toString() ?? ''` — у round_robin выбора нет, приходит `''` |
| 2 | `home_controller.dart:1064` | `g.tag: g.selected` — пустое кладётся в карту как валидный выбор |
| 3 | `selector_info.dart:62` | контракт «null = выбор неизвестен» нарушён: возвращается непустая `''` |
| 4 | `runtime_chain.dart:93` | проверка `cur != null`; `''` её проходит → хоп `tag: ''`, `type: ''` |
| 5 | `outbound_view_screen.dart:316` | `title: ''` → пустой заголовок, `isUnknown` → `not in config` |

Корень — не пустая строка сама по себе, а то, что для пула вообще спрашивается
«кто выбранный». Гейт на `''` нужен как страховка (шаг 2 + 4), но лечит
симптом; лечение — не рисовать «current pick» там, где его нет по определению.

## 3. Решение

### 3.1 Parameters — режим

Режим определяется готовым `HomeController.isRoundRobinAuto(tag)` (§322 §6.1:
round_robin-каналы **или** наличие `balancer{}` в конфиге). Новых проверок не
заводим — это была бы пятая копия.

| режим | строки |
|---|---|
| least_test | `Mode: Fastest` |
| round_robin | `Mode: Load balance`, `Pool: P`, `Pool tolerance: T ms` (T только при `> 0`) |

`P` / `T` — `balancer.pool` / `balancer.pool_tolerance` из raw-конфига.
Не-группа (`type != urltest/selector`) — блок не рисуется вовсе.

### 3.2 Parameters — разворачиваемый Members

`Members: 4` → `ExpansionTile` со списком. Свёрнут по умолчанию, высота
экрана при большом составе не разъезжается.

**Два источника, не путать (§322 §6.1):**

| режим | содержимое |
|---|---|
| least_test | состав из конфига (`raw['outbounds']`), у текущего выбора — пометка `current pick` |
| round_robin | состав из конфига + отметка «в работе» у тех, кто сейчас в живом пуле (`getPool`) |

В конфиге весь состав (15), в работе `pool` штук (7) — показывать одно вместо
другого было бы враньём, поэтому показываем состав и помечаем работающих.

Строка живого слота — формат `pool_view_dialog.dart`: `slot N · тег · delay`,
пороги цвета 200/500 мс, `delay == 0` → `—`. Рендер переиспользуется, второй
копии не заводим.

`getPool` возвращает `null` при опущенном туннеле (§209) — тогда отметок
«в работе» нет, список остаётся составом из конфига. Пустой `[]` — то же
самое. Запрос уходит один раз при открытии экрана (не на каждый ребилд).

### 3.3 Route — свёрнутый хоп пула

Согласовано с юзером 02.08.2026 (вариант A из двух макетов): пул — **одно
звено** пути с раскрытием, а не ветки.

```
 📱 Phone
 🕸 🇵🇱 Польша | Авто⚡              >
    urltest · load balance · this node
 ⑃  4 узла в пуле                   ⌄
    трафик размазан по слотам
 🌐 Internet
```

Причины (обе — против веток): раздел обещает «живой путь в порядке следования
пакета», а ветвление это обещание ломает — пакет идёт через **один** узел из
пула; и на пулах в 20–30 узлов ветки растянут раздел на несколько экранов,
а большие пулы — целевой сценарий §208.

Раскрытие — те же слоты, что в 3.2. Хоп пула **не кликабелен** целиком
(вести некуда — узлов несколько), кликабельны строки слотов внутри → `openTagOwner`.

При least_test всё остаётся как было: обычный хоп выбранного узла.

### 3.4 Гейт пустого выбора (страховка)

Даже с 3.3 пустое `selected` не должно течь по приложению — `selectedOf` его
отдаёт трём потребителям.

```dart
// home_controller.dart, _applyGroups
SelectorInfo.I.setGroups({
  for (final g in ccGroups)
    if (g.selected.isNotEmpty) g.tag: g.selected,
});
```

Плюс `cur.isEmpty` рядом с `cur != null` в `runtimeChainOf` — `selectedOf`
инъектируется в тестах, контракт держим локально.

## 5. Тесты

- `runtimeChainOf`: пустой выбор → обрыв на группе, призрачного хопа нет.
- `_applyGroups`: **тестом не покрыт** — метод приватный, а поднимать ради
  него `HomeController` с нативным каналом дорого и хрупко. Инвариант
  «пустой выбор не рождает хоп» закрыт тестом `runtimeChainOf` — это
  последняя линия перед UI, гейт в `_applyGroups` лишь не даёт пустоте
  разойтись по трём потребителям `selectedOf`.
- Виджет: round_robin → «Mode: Load balance» + хоп пула; least_test → обычный
  выбранный хоп.
- `getPool == null` (туннель down) → список без отметок «в работе», не пусто.
