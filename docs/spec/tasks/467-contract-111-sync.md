## Проблема

Дефект санитайзера, общий с лаунчером; у лаунчера на реальном state испортил
`xmux` у 13 узлов vless+xhttp.

1. `conflicts` (и родственные `requires`, `forbidden_when`) проверяли
   **наличие ключа**. `xmux.max_concurrency: "16-32"` при
   `max_connections: "0"` считался конфликтом, рабочее значение снималось и
   заменялось на `"1-1"`. Ядро (`xmux.go`) считает конфликтом только оба
   значения > 0.
2. `all_or_nothing` дописывал дефолты в частично заданный объект. Ядро
   оставляет незаданные поля нулями; дописывание меняло поведение узла.

## Решение

1. Предикат «задано» — один на весь санитайзер. **Не задано:** ключ
   отсутствует, `null`, `""`, `0`, `false`, пустой объект, пустой массив,
   строка-число из нулей (`"0"`, `"0-0"` — `XmuxRange` приходит строкой).
   `conflicts`, `requires`, `forbidden_when` судят по нему.
2. `all_or_nothing` — санитайзер ничего не делает; атрибут остаётся
   документацией. Код `partial_object_defaulted` удалён из `warnings.json` —
   убрать из маппинга кодов и отовсюду, где он назван.
3. Синк контракта на `cb555281` (или новее, если сессия лаунчера назовёт)
   способом из памяти проекта: `git -C ~/projects/singbox-launcher archive
   <sha> contract | tar -x -C <tmp>` → `LX_CONTRACT_SRC=<tmp>/contract
   app/tool/sync_contract.sh`. Из рабочего дерева лаунчера не синкать.
4. Исключение `_overrideIgnored` из §465 в `contract_test.dart` убрать —
   override у лаунчера снят (`3fa1cfea`).
5. Формат реестра изменился — проверить каждое чтение в
   `app/lib/services/contract/registry.dart` и тестах:
   - ключ `degrade[]` у протоколов удалён — не читать, не требовать;
   - у кодов появились `cause_en`/`cause_ru` (строка) и `fix_en`/`fix_ru`
     (массив строк) — завести поля в модели кода (нужны W2b, раздел 8 спеки
     460), отсутствие — норма;
   - новая секция `mapper` — загрузчик обязан её не ронять; содержимое пока
     не используется;
   - `registry_invariant_test`/`registry_load_test` — привести к новой схеме.
6. Новый кейс корпуса `body/singbox/vless_xhttp_xmux_zero_neighbours` —
   проходит без изменений тела и без warnings.

## Критерии приёмки

- юнит: `max_concurrency:"16-32"` + `max_connections:"0"` → тело без
  изменений, warnings пусты; оба > 0 → конфликт как раньше;
- юнит на предикат «задано» по всему перечню из п. 1;
- частично заданный `all_or_nothing`-объект проходит байт в байт;
- корпус зелёный целиком, новых override не заводить; если кейс красный по
  причине на стороне лаунчера — не чинить подгонкой, вынести в отчёт;
- `contract.lock` и зеркало `app/assets/contract/` закоммичены;
- `flutter analyze` всего проекта, `flutter test` — «All tests passed»;
- CHANGELOG (Fixed — про xmux), GUARDS.md, спека 460 (раздел 7 — семантика
  conflicts/all_or_nothing) обновлены.

## Что вышло

Синк на `cb555281`, контракт 1.1.1, `contract.lock` sha256
`d23e420678a7639c5b9e1c816584ca268e776f97df272642461fc86cc8a0dd15`.

1. Предикат «задано» — `_meaningful` в `body_sanitizer.dart`, один на
   `conflicts` и `requires`. Добавлены: число `0`, пустые коллекции,
   строка-число из одних нулей (`"0"`, `"0-0"`, `"00"`; `"0-32"` — задано).
2. `all_or_nothing` — весь блок дописывания дефолтов снят,
   `partial_object_defaulted` удалён из кода и из тестов.
3. `WarningText` получил `causeEn`/`causeRu` (строка) и `fixEn`/`fixRu`
   (массив строк, через мягкий `_stringList`); отсутствие — норма.
4. `_overrideIgnored` (§465) снят: лаунчер удалил
   `password_only_userinfo.expected.lxbox.json`, кейс сверяется с общей базой.
5. Версия в `registry_load_test` — `1.1.1`.

### Чего в итоге не потребовалось

- **`forbidden_when`** в теле реестра не встречается: слово есть только прозой
  внутри новой секции `mapper` (`transports.json`), атрибутом поля — нет.
  Реализовывать нечего, предикат покрывает `conflicts`/`requires`.
- **`degrade[]`** Dart не читал никогда — удаление ключа у протоколов ничего
  не сломало.
- **Секция `mapper`** соседствует с `body` в файлах протоколов; загрузчик
  читает `body` по имени и на неё не смотрит, так что «не ронять» вышло само.

### Встречная правка, которой в задаче не было

Корпус 1.1.1 стал ждать `path`/`value` у кода `xhttp_param_reset`
(`vless/xhttp_mode_invalid`, `vless/xhttp_placement_bogus_reset`) — это
продолжение §24.7 (коды с путями), приехавшее вместе с синком. Путь приписан
в раннере по тому же правилу, что и у прочих рукописных классов: поле `field`
класса — это имя ключа, под которым значение уезжает в `transport`, поэтому
путь выводится как `transport.<field>`, а не перечисляется вариантами.
Override не заводился.
