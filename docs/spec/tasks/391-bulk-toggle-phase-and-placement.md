## Проблема A — переключатель в противофазе

Репорт пользователя со скриншотами: мелкий переключатель справа от счётчика
узлов показывает состояние, обратное тогглам строк. Все 38 нод включены —
он серый «выключено»; все 38 выключены («38 выкл.») — он синий «включено».

Причина: иконка выбиралась по **будущему действию**, а не по состоянию
([`subscription_meta.dart`](../../../app/lib/screens/subscription_detail_screen/widgets/subscription_meta.dart)):

```dart
icon: Icon(offCount > 0 ? Icons.toggle_on : Icons.toggle_off_outlined),
onPressed: () => onToggleAll!(offCount > 0),
```

`offCount == 0` (всё включено) → рисуется `toggle_off_outlined`. Логика
кнопки была верна («нажмёшь — включит все»), но `Icons.toggle_*` рядом со
столбцом настоящих `Switch` читается как индикатор состояния, а не как
подпись к действию. Отсюда противофаза.

## Проблема B — место

Переключатель жил в мета-блоке, в одной строке со счётчиком узлов, далеко от
прочих действий над списком. Решение пользователя — перенести в строку
«Test servers», слева от неё.

## Решение

Настоящий `Switch` (тот же виджет, что у строк нод) в начале probe-бара
([`subscription_detail_screen.dart`](../../../app/lib/screens/subscription_detail_screen.dart),
`_buildProbeBar`):

```dart
value: !allOff        // ВСЕ выключены → выключен; иначе включён
onChanged: (v) => _toggleAllNodes(v)
```

`allOff = _disabledNodes.length >= _togglableNodes.length` — оба set'а
пересобирает `_rebuildRowsFromEntry` синхронно со строками (§283), поэтому
фаза переключателя не может разойтись с фазой тогглов под ним.

Семантика значения совпадает с параметром `setAllSubscriptionNodes(enabled:)`
— значение `Switch` передаётся как есть, без инверсии.

В мета-блоке остался только счётчик; параметр `onToggleAll` из
`SubscriptionMeta` удалён (`offCount` сохранён — он рисует «M off»).
Место переключателя занимает `SizedBox(width: 12)`, когда тогглов нет
(UserServer / узлы не загружены) — заголовок не съезжает.

## Проблема C — меню Test actions ждало конца прогона

§389 разблокировал пункты по `_probe.isNotEmpty && !_testing`, то есть на
всё время прогона они снова серые. Пользователь: «⋮ разблокироваться должен
если хоть 1 тест прошёл».

Новый гейт `_hasProbeVerdict` (оба экрана — папка и подписка): есть хотя бы
один результат со статусом, отличным от `pending` и `group` (первый ещё не
тестировался, второй не тестируется вовсе, §336). Действия работают по уже
собранным вердиктам; ноды без вердикта в выборку просто не попадают —
`unreachableIndexes`/`slowerThan` их не матчат.

## Verify

Устройством: подписка с включёнными нодами → переключатель в строке «Тест
серверов» включён; выключить все → выключен, счётчик «N выкл.»; включить
обратно → фаза совпадает со строками. Запустить тест → как только первая
нода отдала вердикт, пункты `⋮` активны (не дожидаясь конца прогона).
