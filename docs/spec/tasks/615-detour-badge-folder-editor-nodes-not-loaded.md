## A. Бейдж подписки для `node_detour_through_group`

**Проблема.** §612 ставит код `node_detour_through_group` (узел не взят в
группу, через которую ведёт его detour) на карточку каждого выброшенного узла
(`lastBuildWarningsByTag`). Счётчик уведомлений на строке подписки в списке
(`screens/subscriptions_screen/entry_warnings.dart`) его не учитывает — о
проблеме узнают, только открыв узел.

**Решение владельца:** «если detour указан у группы, должен быть бейдж к
подписке».

**Что сделать.** Код учитывается в бейдже строки подписки (и в счётчике
Notifications внутри экрана подписки, если он считается отдельно). Одна
запись на пару (подписка, группа), как у лаунчера: в тексте — группа и число
узлов (`params`: `group`, `count`, `tags`). Если бейдж считает только
предупреждения узлов по тегам — добавить агрегацию по источнику без новой
формы хранилища. Тест: сборка с кольцом узел→группа даёт запись у подписки.

## B. Диалог «Edit server» в папке — на `LxCodeEditor`

**Проблема.** §614 перевёл JSON-поля на редактор с подсветкой, но диалог
«Edit server» в `screens/folder_detail_screen.dart` (~925) остался на старом
`TextField`, хотя принимает outbound JSON. В спеке §614 его не было — это
пропуск постановки, не техническое ограничение.

**Что сделать.** Тот же перевод, что в §614 п. 6: обёртка `LxTextCodeField`,
язык JSON при тексте, начинающемся с `{`, поведение контроллера/валидации/
сохранения не менять. Найти grep-ом другие поля, принимающие outbound JSON
или sing-box JSON, и перевести тоже, перечислить в отчёте.

## C. Вкладка Nodes подписки без кэша тела

**Проблема.** Если у подписки нет файла с телом в `files/sub_cache/`
(не переехал при восстановлении слота/бэкапа, подписка выключена и
автообновление её пропускает), после перезапуска `entry.list.nodes` пуст:
`_rehydrateFromCache` (`controllers/subscription_controller.dart` ~306–330)
молча делает `continue`. Вкладка Nodes пишет «No nodes found», а строка в
списке показывает старый `last_node_count` (`subscription_entry.dart:24`).
Читается как «в подписке нет узлов», хотя они просто не загружены.

**Решение владельца (08.10.2026):**
1. На вкладке Nodes в этом состоянии (узлов нет, `last_node_count > 0`,
   тела в кэше нет) — текст **«Nodes are not loaded. Update the subscription
   to see them»** и кнопка **Update** рядом (тот же путь, что ручное
   обновление подписки; для выключенной подписки кнопка тоже работает).
2. В строке списка подписок счётчик узлов в этом состоянии показывается
   серым как устаревший (без изменения формы хранилища, §291).
3. При старте, когда тело в кэше не нашлось, — строка в `AppLog`
   (уровень warning, источник `app`): подписка и ожидаемый путь кэша.
   Сейчас пропуск молчит.

Признак «тела нет» хранить в памяти процесса у записи (например флаг
«восстановление без кэша»), не в хранилище.
