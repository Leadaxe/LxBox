## Problem

Главный экран каждый раз открывается не на том Направлении, с которым человек
работал. Если в Routing → Rules → Default traffic стоит Направление —
открывается оно. Если там не Направление — открывается верхнее в списке; у
автора обращения это группа папки (`Replace with a group`), а не `vpn-1`.
Первым действием приходится переключать список.

## Diagnosis

Выбор в списке Direction жил только в памяти `HomeController`
(`HomeState.selectedGroup`) и на диск не писался. `_applyGroups` выбирал
так: текущее, если оно есть в снимке групп → `route.final`, если это
селектор → первое.

Текущее терялось в трёх случаях:

1. перезапуск приложения;
2. окно закрыто, сервис туннеля жив — интерфейс при открытии поднимается
   заново;
3. перезапуск туннеля: первый снимок групп на старте бывает пустым, выбор
   сбрасывается в `null`, следующий снимок выбирает заново.

Случаи 2 и 3 выведены из кода, на устройстве не воспроизводились.

## Solution

Цепочка выбора из двух шагов, `route.final` из неё убран:

1. текущее Направление, пока оно есть в списке;
2. иначе сохранённое последнее выбранное, если оно есть в списке;
3. иначе первое в списке.

Сохранение:

- Тег пишется в var `home_direction` (`lxbox_settings.json`, строка, по
  умолчанию пусто). Это app-var, не config-var: в конфиг ядра не идёт, dirty не
  поднимает, перезапуск VPN не просит.
- Пишет только явный выбор — `HomeController.setSelectedGroup`: список
  главного экрана и команда automation `set-group`. Подстановка из
  `_applyGroups` (шаги 2–3) ничего не пишет, поэтому запасное «первое в
  списке» само себя не запоминает.
- Псевдо-направление `NETWORKS` (§579) не запоминается: это вид, не
  Направление.
- Читается один раз в `HomeController.init` до подписки на статус туннеля.
- Сохранённого Направления больше нет (удалено, выключено) — шаг 3; запись
  остаётся до следующего явного выбора и сработает, если тег вернётся.
- Var лежит в общем файле настроек, поэтому едет в бэкап вместе с остальными
  app-var; на другом устройстве несуществующий тег даёт шаг 3.

Последствие отказа от `route.final`: первый запуск и новая установка
открываются на первом Направлении списка, а не на Default traffic.

## Verification

Юнит-тесты (`home_direction_remembered_test.dart`):

1. `pickDirection`: текущее в списке — остаётся, даже если сохранено другое.
2. Текущего нет, сохранённое в списке — берётся сохранённое.
3. Ни текущего, ни сохранённого — первое; пустой список — `null`.
4. `setSelectedGroup` пишет `home_direction`; новый контроллер после `init`
   на том же хранилище поднимает сохранённое, а не первое.

На устройстве:

1. Два Направления, выбрать второе, закрыть приложение из списка недавних,
   открыть — показано второе.
2. То же через Stop → Start без закрытия приложения.
3. Удалить сохранённое Направление, перезапустить VPN — показано первое.
