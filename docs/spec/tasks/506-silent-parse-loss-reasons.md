## Проблема

Диагностика четырёх реальных входов пользователей показала: **два входа из
четырёх исчезали полностью, и `dropped[]` при этом был ПУСТ** — пользователь
видел «0 серверов» без единого слова о причине.

1. **`vpn://<base64 голого .conf>` → 0 узлов молча** (вход A).
   `amnezia_link.dart:_inflate` принимал не-zlib payload только если текст
   начинается с `{` (JSON-профиль Amnezia). Голый `.conf` начинается с
   `[Interface]`, поэтому `_decodeAmneziaRoot` возвращал `null` →
   `DecodeFailure` → `parse_all.dart` отдавал `const []`. **Тело при этом
   поддержано ПОЛНОСТЬЮ**: тот же `.conf`, поданный INI-текстом, даёт узел со
   всеми AWG3-полями. Недостижимо оно было только через обёртку `vpn://`.

2. **Незнакомая схема ссылки пропадала без причины** (вход D: 4 строки
   `amneziawg://` из тела подписки). `uri_parsers.dart` в `default`-ветке
   диспетчера делал `return null` без записи в `dropped[]`, а
   `parse_all.dart:_parseUriLines` пишет причину только когда парсер её
   поставил. Доказательство, что виновато ТОЛЬКО имя схемы: переименование в
   `awg://` при том же payload даёт полноценные узлы.

3. **Причины не собирались на прод-пути вовсе.** `parseFromSource`
   (`sources.dart`) звал `parseAll(decoded)` **без аргумента `dropped`** — то
   есть даже заполненные причины видел только конформанс-раннер корпуса, а не
   UI.

4. **Полоса hysteria2 со строковой единицей терялась** (вход C, Happ):
   `"up": "100mbps"` → `type: int` реестра на нечисловой строке даёт
   отсутствие значения, суффикс не срезается. Проверено: с числовыми `up`/`down`
   поля `up_mbps`/`down_mbps` в emit есть.

Общий механизм: `null` от парсера **без** `verdict.reason` терялся бесследно —
и в `default`-ветке диспетчера, и на раннем `return null` по `maxURILength`, и
во всех ветках `DecodeFailure`.

## Что стало

### 1. `vpn://` с голым `.conf` (`amnezia_link.dart`)

Новый `_decodeBareIni`: после base64-декода (паддинг дописывает
`decodeBase64Safe`) первая НЕ-комментарная непустая строка, начинающаяся с
`[`, значит «payload — ini-текст». Признак взаимоисключающий с JSON-профилем
(`{`), поэтому проверяется ДО JSON-ветки. Тело уходит в существующий разбор
wg-quick/AWG тем же путём, что INI-ввод (`parseWireguardIni`), — новой
конвертации не появилось.

Подключено к ОБОИМ входам `vpn://`: тело подписки целиком
(`decodeAmneziaLink` → `AmneziaConfig`) и строка внутри URI-списка
(`parseAmneziaVpnUri`). Второй заодно получил параметр `dropped`, которого у
него не было.

### 2. Причина вместо молчания

| Место | Было | Стало (код реестра) |
|---|---|---|
| `uri_parsers.dart` `default` | `return null` молча | `protocol_unsupported`, схема в `value` и в `params.scheme` |
| `uri_parsers.dart` лимит длины | `return null` молча | `uri_too_long` с `length`/`limit` |
| `uri_parsers.dart` ветка `vpn` | `null` от парсера молча | `protocol_unsupported` (`scheme: vpn`), если причину не поставил разбор INI |
| `parse_all.dart` `DecodeFailure` | `const []` | `core_rejected` с текстом причины декодера в `params.reason` |
| `sources.dart` `parseFromSource` | `parseAll(decoded)` | `parseAll(decoded, dropped:)`, список в `ParseResult.dropped` |
| контроллер, «серверов не найдено» | `ErrMsg` | `ParseInputRejectedMsg` с причинами (шторка §500) |

Все четыре кода — **уже объявленные в реестре**, новых не заводилось.
`core_rejected` взят намеренно: его текст — «техническое сообщение: {reason}»,
то есть ровно форма «причина от нижнего слоя, дословно»; это код уровня
записи, `path` у него нет — здесь записи нет вовсе, тело целиком и есть запись.

**Служебные строки провайдера — ТИХИЙ игнор.** `_kProviderServiceSchemes =
{incy, happ}`: `incy://routing/…` и `happ://routing/onadd/…` узлами не
являются вовсе, и код «схема не поддержана» на них был бы ложной тревогой.
Без этого разделения список причин у обычной подписки Happ заполнялся бы
строками, о которых пользователю решать нечего, и настоящая потеря узла
терялась бы среди них.

**Строка БЕЗ схемы вовсе — тоже молчим.** `scheme` берётся как
`t.split('://').first`, то есть у строки без `://` схемой становится она сама, и
код о протоколе назвал бы мусор именем протокола. Это не «протокол не
поддержан», а «ввод не распознан» — норма §500 («мусорная строка → прежнее
сообщение без причины»), и три её теста в `parse_input_rejected_test.dart`
именно это и стерегут.

**Схему `amneziawg://` в код НЕ добавляли** — её объявит реестр (см. ниже).

### 3. Полоса с единицей (`interpreter.dart`)

Нормализатор **`bandwidth_mbps`** (`normalizeBandwidthMbps`):
`<число><единица?>` → целое в мегабитах. Единицы десятичные, регистр не
значим, пробел допускается; результат округляется ВВЕРХ (ноль значил бы «не
задано», то есть ту же потерю). Не-полоса → значение едет как пришло, годность
судит санитайзер.

Почему нормализатор, а не `extract`-регулярка «ведущие цифры» (как у hysteria
v1): единица **читается**, а не отбрасывается — `1gbps` это 1000 Мбит/с, а не
1, и ведущие цифры дали бы неверное число.

Движок исполняет то, что назовёт `normalize` секции. **Сегодня ни одна секция
его не называет**: в `hysteria2.json` у `up_mbps`/`down_mbps` (и в `uri`, и в
`xray`) стоит только `type: int`, а `extract` есть лишь у hysteria v1. Поэтому
код готов, а включение — за реестром 1.1.48 (ниже, «Долги»).

## Ответ на вопрос: откуда диспетчер берёт список схем

**Из литералов в коде, не из реестра.** `uri_parsers.dart` знает схемы в трёх
местах: `kPipelineSchemes` (`mappers/uri_pipeline.dart`, `const Set<String>` из
~25 имён), `_kWireguardSchemes` и `switch (scheme)` самого диспетчера.

**Стража `engine_no_scheme_names` это НЕ нарушает**, и он тут ни при чём: страж
грепает каталог `lib/services/parser/engine/` — пакет ДВИЖКА, — а диспетчер
лежит уровнем выше (`lib/services/parser/`). Разделение осмысленное: движок
общий для всех схем и правило схемы держит в данных, а перевод написания схемы
в тип тела — работа диспетчера, о чём прямо сказано в комментарии к
`_kSchemeToType`.

Тем не менее реестр имя схемы **уже несёт** — `mappers.uri.detect.scheme_in`
(например `wireguard.json` → `["wireguard", "awg"]`), и `interpreter.dart:575`
/ `emitter.dart:421` его читают. То есть источник истины существует, а
диспетчер дублирует его литералами: **добавление `"amneziawg"` в `scheme_in`
контракта 1.1.48 само по себе схему НЕ включит** — строка по-прежнему упадёт в
`default` (теперь хотя бы с причиной).

Чтобы схема заработала после синка без правок кода, диспетчер должен строить
свой набор из секций реестра (объединение `scheme_in` всех `mappers.uri`) и
падать на литералы только когда реестр не загружен. Это отдельная работа:
`kPipelineSchemes` — `const`, его читает страж покрытия mapper-правил
(`mapper_rules_coverage_test.dart:184`) и `input_helpers.dart:37` (превью
вставки), поэтому замена на рантайм-набор задевает три потребителя и просится
в свою таску. **В этой задаче подготовлено то, что можно без ломки: потеря
перестала быть молчаливой.**

## Факт про пин ядра и mlkem

Пин — **`v1.14.1-lx.8`** (`app/android/libbox.version`, он же назван в
`docs/KERNEL.md:28`). Ветка `v1.14.1` **новее** `v1.14.0-lx.18`, в которой
появился SPEC 032 (`docs/KERNEL.md:888`), то есть **mlkem поддержан**:
`encryption=mlkem768x25519plus…` из входов B и C доезжает до emit дословно и
конфиг ядром не отвергается. Готча «ядро старше lx.18 отвергает конфиг с полем
целиком» (`KERNEL.md:586`) к текущему пину не относится. Ничего не менялось.

## Долги (в эту задачу не входят)

- **Полоса hysteria2 включается реестром 1.1.48**: `normalize:
  ["bandwidth_mbps"]` у `up_mbps`/`down_mbps` в `hysteria2.json` (обе формы,
  `uri` и `xray`). До этого `"up": "100mbps"` по-прежнему теряется — теперь
  это единственное, что осталось от входа C.
- **Salamander-пароль Happ** лежит вне объявленных путей obfs:
  `streamSettings.finalmask.udp[0].settings.password`, а реестр перечисляет
  только `hysteriaSettings.obfs` / `obfsParam` / `obfs_password`. Сам
  `finalmask` объявлен как «чтение без записи», поэтому секрет проглатывается
  без кода. **Последствие для связи:** сервер с salamander-обфускацией отвергнет
  клиента без `obfs` — «узел есть, а соединения нет». Решает реестр 1.1.48.
- **Схема `amneziawg://`** — за реестром (`scheme_in`), плюс таска на
  рантайм-набор схем в диспетчере (см. выше).
- **Протоколы `extension: desktop`** (hysteria v1 из Xray-JSON с `version: 1`
  или без version, ссылки `hysteria://`) сейчас дают 0 узлов; кода «not
  supported in the mobile app» в `warnings.json` зеркала нет — ближайший по
  смыслу `protocol_unsupported` говорит «ядро не поддерживает», что для
  desktop-расширения неточно. Нужен либо свой код в реестре, либо явное
  решение переиспользовать `protocol_unsupported`. Вынесено из объёма.
- **Заголовки провайдера, которые не читает никто**: `Routing:`,
  `Hide-Settings:` (вход D), `x-hwid-active:` (вход C) — правила роутинга
  провайдера до приложения не доходят.
- **`sockopt` / `spiderX`** снимаются без предупреждений (вход B): у sing-box
  соответствия нет, но факт потери пользователю не сообщается.

## Тесты

`app/test/parser/task_506_silent_loss_test.dart` (14 тестов, все зелёные):

- **п.1**: `vpn://` с голым `.conf` даёт 1 узел (было 0) и пустой `dropped[]`;
  все AWG3-поля в emit (`header_protection_key`, `content_padding_addition`,
  диапазоны `rekey*`/`reject*`/`keepalive*`/`max_handshake_attempts`,
  `random_trailers`/`disable_cookies`, `s3`/`s4`, `h1`–`h4`); **identity равна**
  той же у `.conf`, поданного напрямую (сравнение emit по телу); строкой внутри
  URI-списка — тоже узел.
- **п.2**: незнакомая схема → `protocol_unsupported` со схемой в `value`
  (и на прод-пути тела подписки: две строки → две причины); `incy://`/`happ://`
  → `null` **без** причины (тихий игнор, в т.ч. в `dropped[]` подписки);
  ссылка сверх лимита → `uri_too_long`; неразобранное тело → `core_rejected`
  с текстом декодера; `vpn://` без контейнеров WG/AWG → причина, а не пустой
  список.
- **п.2 (граница)**: строка без `://` → `null` **без** причины (`это не
  конфиг`, `hello world`) — норма §500 сохранена, её три теста зелёные.
- **п.3**: `normalizeBandwidthMbps` — голое число, мегабиты во всех
  написаниях, гигабиты множителем 1000 (а не «ведущие цифры»), килобиты/биты с
  округлением вверх, дробные; мусор и ноль → `null`.

Ключи в фикстуре — тестовые, той же ФОРМЫ (32 байта base64), что у настоящего
входа: форму судит санитайзер, и ключ неверной длины снял бы узел по
`wg_key_invalid`.

## Критерии приёмки

  с прямой подачей того же `.conf`.
