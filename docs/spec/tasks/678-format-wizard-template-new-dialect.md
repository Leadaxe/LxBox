## Проблема

`app/scripts/format_wizard_template.py` (раскладка `app/assets/wizard_template.json`
по разделу «Formatting style» в `docs/TEMPLATE.md`) последний раз правился под
§393 (24.08.2026). С тех пор язык шаблона получил конструкции, которых скрипт
не знает, и на боевом шаблоне он падает на первом же inbound с условием:

```
File "format_wizard_template.py", line 124, in format_if_element
KeyError: 'or'
```

Скрипт ждёт условия с ключами `and`/`or`/`value`/`else`, в шаблоне — канонические
`#and`/`#or`/`#not`/`#value`/`#else` (§120, список ключевых слов в TEMPLATE.md),
короткая форма `#if: [cond, V, E]` и `#if` на `#do` (§656), `#tpl`, `#do`,
`#filter`, `for_each_node*` (§578), предикаты `#notEmpty`/`#in`.

Следствие: шаблон лежит в развёрнутом виде (2367 строк, одна секция
`dns_options.servers` занимает 377 строк там, где форматтер даёт 132) — кто-то
из исполнителей сохранил файл обычным `json.dump` с отступами, а прогнать
форматтер уже не смог. На загрузчик и билдер раскладка не влияет; страдает
только читаемость при правках руками.

Состав конструкций в шаблоне на 23.10.2026: `#and` 29, `#not` 2, `#if` списком 9,
`#do` 1, `#tpl` 4, `@node…` 16, `#notEmpty` 5, `#in` 8; `#or`, `#eq`, `for_each` —
0 (но язык их допускает, скрипт должен их принимать).

## Решение

1. **Скрипт.** `format_if_element` и соседи принимают оба написания условий
   (`and`/`#and`, `or`/`#or`, `value`/`#value`, `else`/`#else`) плюс `#not`;
   раскладка по тем же правилам, что в TEMPLATE.md: скалярное `value` — одна
   строка, объектное — условие и `"#value": {` на первой строке, тело ниже,
   закрытие `}}}`. Короткая форма `#if: [cond, V, E]`: `V` скаляр — одна строка;
   `V` объект — `{"#if": [cond, {` на первой строке, тело ниже, закрытие `}]}`
   (с `E` — `}, E]}`). `#tpl` — всегда одна строка (`{"#tpl": "…"}`). `#do`,
   `#filter`, `for_each_node*` — объект с одним-двумя полями на одной строке,
   если нет вложенного объекта с `@`; иначе одно поле на строку. Неизвестная
   `#`-конструкция не роняет скрипт: падение заменяется на `compact()` этого
   узла и предупреждение в stderr с путём до узла.
2. **Инвариант.** Скрипт сам проверяет, что `json.loads(formatted)` равен
   исходным данным (сравнение Python-объектов, порядок ключей словарей
   включительно), и отказывается писать файл при расхождении. Сейчас этой
   проверки в скрипте нет.
3. **Прогон.** Шаблон переформатирован; семантика идентична по п. 2.
4. **TEMPLATE.md.** В разделе «Formatting style» подраздел «The `#if` construct»
   переписан на канонические ключи `#and`/`#value`/`#else`, добавлены строки
   для короткой формы, `#tpl`, `#do`/`#filter`. Примеры с `"and"`/`"value"`
   без решётки заменены.

## Проверка

- `python3 -I app/scripts/format_wizard_template.py` на боевом шаблоне
  завершается с кодом 0, без предупреждений в stderr.
- Повторный прогон на уже отформатированном файле не меняет ни байта
  (идемпотентность).
- `python3 -I -c 'import json; …'` — `json.load` до и после даёт равные объекты.
- Тесты, читающие боевой шаблон (`grep -rl wizard_template.json app/test`),
  проходят: прогнать один файл, самый прямой — валидатор загрузки шаблона
  (§443 `validateTemplateConstructs`).
- Коммит шаблона отдельно от коммита скрипта и доки.
