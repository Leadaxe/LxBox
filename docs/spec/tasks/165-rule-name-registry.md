# 165 — Имя правила на Stats/Conns (справочник c.rule → title + кэш)

| Поле | Значение |
|------|----------|
| Тип | Task (UX + perf: человекочитаемое имя правила в статистике) |
| Статус | Реализовано |
| Связано | §122 (CommandClient connections), §062/§030 (custom_rules), §166 (фриз Stats) |

На вкладках **Stats → Traffic by Rule** и **Conns** для каждого соединения показывать **человекочитаемое имя правила** (`Home wifi`, `Block Ads`, `Warp` — `custom_rules[].name`), а не обрезок сырых условий (`[LexRouteRich2G`).

---

## 1. Корень проблемы

Ядро (sing-box) в `connection.rule` (`getRule()`) отдаёт `rule.String()` = **условия через пробел**, БЕЗ имени правила:
```
wifi_ssid=[LexRouteRich2G LexRouteRich5G] wifi_bssid=[..] rule_set=Home wifi => route(vpn-3)
```
У sing-box **нет поля «имя» в route-rule** (`abstractDefaultRule.String()` = `strings.Join(allItems, " ")`). Менять конфиг бесполезно — имя в строку не попадёт.

**Дополнительно — `rule.String()` ЛОССОВАЯ:**
- списки >3 элементов обрезаются: `domain_suffix=[a b c...]` (`rule_item_domain.go:43`, `rule_item_cidr.go:47`). Полную строку НЕ восстановить.
- `rule_set`-тег есть НЕ всегда (wifi-only/protocol-only правила → tag не создаётся; inline rule_set с пустым `rules` запрещён ядром — `empty inline rule-set`).

Поэтому: парсить условия / искать rule_set-тег / предсказывать строку байт-в-байт — **ненадёжно**.

---

## 2. Решение — справочник на лету (вариант C) + нормализация + indexOf + кэш

**Идея:** Stats строит соответствие «строка правила от ядра → title» **из `custom_rules`** (мы знаем и условия, и `name`), без хранения в конфиге. Матч устойчив к обрезке и форматированию через нормализацию + `indexOf`.

### 2.1 Поток
```
c.rule (ядро, обрезанная)
   │
   ▼
ruleName(c.rule):
   1. кэш-lookup по c.rule → есть? вернуть (включая промахи!)
   2. промах → нормализовать c.rule
   3. для каждого custom_rule: построить ПОЛНУЮ нормализованную строку условий
   4. indexOf: нормализованная-c.rule ⊂ нормализованная-правила → title
   5. не нашлось → fallback (final / сырое имя условия)
   6. КЭШ[c.rule] = результат (и для найденных, и для промахов)
   ▼
title ("Home wifi") → UI
```

### 2.2 Нормализатор `_norm(s)`
- множественные пробелы → один (`\s+` → ` `)
- убрать переносы строк
- trim
- (НЕ трогаем `[`/`]`/`=` — они часть структуры)

Обе стороны (наша предсказанная строка правила И `c.rule`) проходят `_norm` → формат-различия исчезают.

### 2.3 Матч через `indexOf` (устойчив к обрезке)
`c.rule` от ядра обрезана (`[a b c...]`), наша строка — полная (`[a b c d e]`). Ядровая обрезанная строка — **префикс** нашей до точки обрезки. Матч:
- `normRule.indexOf(normCore без хвоста "...")` ≥ 0, ИЛИ
- сравнение по общему префиксу до `...`.

Практически: берём `normCore`, отрезаем `...]` → `[a b c`, ищем эту подстроку в `normRule` правила. Совпало → это правило.

### 2.4 Кэш `c.rule → title` (perf)
- `ruleName` вызывается в цикле по всем conns × 10/сек (FAST). Без кэша — тяжёлый матч каждый тик → фриз (§166).
- Кэш `Map<String, String>`: ключ = сырой `c.rule`, значение = title ИЛИ fallback. **Промахи тоже кэшируются** (строка без правила/`final`/`direct` не пересчитывается).
- **Сброс кэша при stop VPN** (`tunnel != connected`): правила могли смениться, новый конфиг → новые строки. Сброс из `home_controller` на disconnect, или гейт по epoch.

### 2.5 Построение строки правила из custom_rule
Из `getCustomRules()`, для каждого правила — собрать условия в порядке ядра (`DomainItem`: domain → domain_suffix → domain_keyword; затем ip_cidr, port, package_name, protocol, wifi_ssid, wifi_bssid). Формат значений как ядро: `key=val` (1 элемент) / `key=[a b c]` (набор). Это «полная» эталонная строка → `_norm`.

## 4. Критерии приёмки

1. `Home wifi` (5 suffix + 2 wifi) показывается как **`Home wifi`** на Stats/Conns (не `[LexRouteRich2G`), несмотря на обрезку списка ядром.
2. `Block Ads`, `Warp`, `4pda` и пр. — свои `name`.
3. Правило не найдено / `final` / `direct` → разумный fallback (`final`), закэширован.
4. Нормализация: лишние пробелы/переносы не ломают матч.
5. Perf: повторный `c.rule` берётся из кэша (нет тяжёлого матча каждый тик) → Stats не виснет на FAST 0.1с.
6. Кэш сбрасывается при stop VPN (после смены конфига имена корректны).
7. Нет RegExp в hot-path (indexOf).

## 5. Вне скоупа / открытые

- **Правка ядра** (добавить `name`/`label` в `rule.String()`) — отдельный путь (надёжнее, но требует релиза ядра). Пока — справочник на клиенте. Если матч окажется хрупким на практике — завести запрос core-team.
- Обрезка >3: матч по префиксу до `...`. Если у двух правил совпадает первый-3-префикс набора — теоретическая коллизия (берём первое совпавшее по порядку custom_rules). Маловероятно; при репорте — добивать по доп-полям.
