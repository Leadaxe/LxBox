# §599 — Замена при восстановлении бэкапа — по категориям, а не всего документа

| Тип | B (баг) |

| Дата | 2026-09-30 |
| Связанные | аудит §591 (017, пункт «Подпись режима замены…»), §413, §447, §524 |

## Проблема

В превью импорта бэкапа пользователь отмечает категории (`BackupCategory`: Server
lists, Routing, App settings, Debug API config, VPN settings) и выбирает режим.
Экран обещает для «Replace all»: «Wipes existing data in selected categories.» и
в подтверждении — «This will overwrite your current data in the selected
categories.» (`app/lib/screens/backup_screen/import_preview_dialog.dart:152,176`).

Код делает другое: `SettingsStorage.replaceRaw(…, merge: false)` перезаписывает
весь документ настроек снимком, в котором есть только отмеченные категории
файла. Всё, что относится к неотмеченным категориям, стирается. Пример: отметил
только Routing → правила и DNS из файла, а подписки, одиночные серверы и цепочки
(`sources[]`, категория Server lists с §524) на телефоне исчезают. Операция
необратима.

Спека 017 закрепила поведение кода (P7 «Replace replaces the whole settings
document», мутация «replace per category»). Решение владельца 2026-09-30: верно
то, что обещает экран.

## Решение

Замена — по категориям:

- отмеченная категория заменяется целиком содержимым файла: ключи категории,
  которых в файле нет, у получателя удаляются (для `vars` — в пределах
  переменных этой категории);
- неотмеченная категория не трогается вообще — ни ключи верхнего уровня, ни её
  `vars`;
- отмечены все категории — результат совпадает с нынешней полной заменой;
- ключи вне всех категорий (служебные: `storage_version` и т. п.) — как сейчас;
- уцелевающие свойства устройства (Debug API §413, флаги стартовых запросов
  §447, зеркало тумблеров VPN при снятой категории) продолжают работать как
  сейчас; проверить, что их особые ветки не конфликтуют с новой логикой и при
  возможности упростить (часть из них становится частным случаем «неотмеченное
  не трогается»).

Путь один для UI-импорта и Debug API `POST /backup/import` (там категории — те,
что передаёт запрос; если запрос категорий не передаёт — все, как сейчас).
Merge не меняется.

Документация:

- `docs/spec/features/017-BACKUP_AND_STORAGE/FEATURE.md` и `FEATURE.ru.md` (если
  есть) — переписать P7: «Replace replaces the selected categories; unselected
  categories keep the receiver's values», свидетель — новый тест, мутация —
  «replace of the whole document»;
- `FUNCTIONS/full-backup-restore.md` — убрать фразу «In fact the whole settings
  document is replaced…», описать замену по категориям; в таблицу задач —
  строку §599;
- Debug API-справка по `POST /backup/import`, если там описана полная замена;
- `docs/spec/tasks/591-spec-kit-revision-audit.md` — у пункта 017 «Подпись
  режима замены…» дописать `→ 599`.

Подписи в UI не меняются: они уже верные.

## Критерии приёмки

1. Юнит-тест: у получателя есть подписки, цепочка, правила; импорт в режиме
   replace с одной отмеченной категорией Routing → правила и DNS из файла,
   `sources[]` (подписки и цепочка) остались прежними.
2. Юнит-тест: replace с одной отмеченной Server lists → `sources[]` из файла,
   правила получателя на месте.
3. Юнит-тест: replace со всеми категориями даёт тот же документ, что до
   правки (регрессия полной замены).
4. Юнит-тест: в отмеченной категории ключ, которого нет в файле, у получателя
   удалён (замена, а не слияние).
5. Старый тест «replace only Routing: rules and DNS; neither sources nor chains»
   переписан под новое правило, а не удалён молча.
6. Тесты §413/§447 (Debug API и флаги стартовых запросов переживают замену)
   зелёные.
7. `flutter analyze` по проекту чистый.

## Проверка

Затронутые тестовые файлы бэкапа — по одному, не каталогом. Остальное — CI.

## Итог

- `SettingsStorage.replaceRaw` получил `keepTopLevel` / `keepVar` — ключи,
  которые замена оставляет получателю; `BackupService.applyImport` передаёт
  туда ключи неотмеченных категорий (`categoryOfTopLevelKey`,
  `categoryOfVarKey`). Ключи вне категорий (`storage_version`, служебные вне
  allowlist) — как раньше. Переносы §413/§447 оставлены: они покрывают
  отмеченную категорию, в которой файл молчит о ключах устройства.
- Debug API `POST /backup/import` категорий не передаёт — замена всего
  документа, как раньше.
- Восстановление с главного экрана берёт категории, которые есть в файле
  (`availableCategories`): категории, которых в файле нет, теперь у
  получателя остаются, а не стираются.
