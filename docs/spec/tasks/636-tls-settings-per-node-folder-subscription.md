# §636 — Настройки TLS (фрагментация, mixed-case SNI) на узле, папке и подписке

| Поле | Значение |
|------|----------|
| Тип | Фича (ревизия 016-DPI_HARDENING / tls-fragmentation) |
| Статус | D (done), выпущено в v2.25.14 |
| Дата | 2026-10-13 |
| Связанные | §627 (глобальная фрагментация не для REALITY — там же записано «уступит настройке на узле/папке/подписке»), §574 (fragment уступает detour), §606 (fallback delay), §363 (mixed-case и REALITY), §623 (паттерн секции на экране узла), §577 (авторское тело не трогается), §633 (слияние бэкапа) |

## Проблема

Четыре TLS-ручки раздела «TLS Fragmentation» (`tls_fragment`,
`tls_record_fragment`, `tls_fragment_fallback_delay`, `tls_mixed_case_sni`)
существуют только глобально (`assets/wizard_template.json`, секция
`dpi-bypass`) и применяются пост-шагом ко всем first-hop outbound'ам сразу
(`app/lib/services/builder/post_steps/tls_transforms.dart`, вызов из
`build_config.dart:853-854` и `probe/probe_config.dart:407-408`).

Пользователю нужно включать фрагментацию для одной подписки или одного
сервера, а другие не трогать (или наоборот — выключить для одного узла, у
которого сервер не принимает резаный ClientHello, §627). Сегодня это
невозможно: тумблер один на всё.

Решение владельца: настраивать TLS там же и так же, как detour — на узле,
на папке, на подписке.

## Диагностика

- Detour имеет два уровня: личный detour узла (`FolderMember.detour`,
  `UserServer.detourPolicy.overrideDetour`) и политика источника
  (`DetourPolicy` подписки/папки, `server_list.dart:786-841`). Приоритет
  считается в сборке: `FolderPlan.policyFor` (`server_list_build.dart:540-560`).
  Глобального слоя у detour нет.
- У TLS, наоборот, есть только глобальный слой (`vars['tls_*']`), и
  пост-шаг не знает, из какого источника пришёл outbound.
- Узлы подписок личных настроек не имеют (нет ни detour, ни вкладки Settings
  — §623 «Отклонение»). Узловой уровень = одиночный сервер и член папки.
- Хранение источников: кодек `app/lib/models/codec/source_record.dart`
  (`detour` узла/члена пишется только непустым, `detour_policy` — только при
  отличии от умолчаний; допустимые ключи — `_serverKeys/_folderKeys/_memberKeys`
  `:314-335`). Бэкап пользуется тем же кодеком (`lx_backup.dart`), слияние
  при импорте сохраняет локальный detour (`:3636, 3910, 3999`).
- Debug API отдаёт `override_detour` и `detour_policy` в
  `debug/serializers/subs.dart:88-97`, принимает в `PATCH /subs/{id}`
  (`handlers/subs.dart:231-246`), описание — `handlers/help.dart:215-219, 743`.

## Решение

### Модель

Новое значение `TlsPolicy` — четыре необязательных поля:

| Поле | Тип | Ключ ядра |
|---|---|---|
| `fragment` | `bool?` | `tls.fragment` |
| `recordFragment` | `bool?` | `tls.record_fragment` |
| `fallbackDelay` | `String?` (duration ядра) | `tls.fragment_fallback_delay` |
| `mixedCaseSni` | `bool?` | `server_name` в случайном регистре (пост-шаг) |

`null` = «наследовать». Пустая политика (все `null`) = «всё унаследовано».
Тип трёхзначный намеренно: у `NodeLink` «не задано» — пустой тег, у bool
такого места нет.

Где лежит:

| Уровень | Носитель | Кто редактирует |
|---|---|---|
| Узел | `FolderMember.tls` (член папки); у одиночного сервера — `UserServer.tls` (одиночный сервер = свой источник, как у detour) | экран настроек узла |
| Источник | `SubscriptionEntry.tls` (подписка, папка) | вкладка настроек подписки/папки |
| Глобально | прежние `vars` `tls_*` | раздел «TLS Fragmentation» настроек — без изменений |

### Разрешение

Для каждого outbound, который сборка эмитит из источника, по каждому полю
отдельно: **узел → источник → глобально**; первое не-`null` побеждает.
`false` ниже бьёт `true` выше — ради этого всё и делается.

Outbound'ы не из источников (шаблон, Направления, WARP и т. п.) — только
глобальный слой, как сейчас.

Эффективная политика считается в `server_list_build.dart` по образцу
`policyFor` и отдаётся из сборки списком «итоговый тег → `TlsPolicy`»;
`applyTlsFragment` и `applyMixedCaseSni` получают эту карту и глобальные
`vars` как подложку. Проба и пинг (`probe_config.dart`) получают ту же карту
— §606: пинг проверяет путь трафика, а не другой конфиг.

### Правила применения — что остаётся как было

Перечислено явно; всё действует на любом уровне:

1. Флаги пишутся только outbound'ам **без `detour`** (first-hop). Узел с
   detour, назначенным сборкой, настройку не получает — молча, без кода
   сборки (как сейчас у глобальной); на экране узла секция TLS показывает
   подпись «Not applied: traffic goes through a detour first.» (см. UI).
2. Годность поля телу спрашивается у реестра (`fieldAllowedOn`): naive и
   MASQUE `vhttp: h3` фрагментацию не получают; MASQUE h2/auto — получает,
   блок `tls{}` создаётся.
3. `tls.engine` = `apple`/`windows` — флаги снимаются с кодом
   `tls_fragment_system_engine` (§574).
4. Невалидная `fallback_delay` на любом уровне → `500ms` (§606). Пауза
   пишется, если эффективно включён хоть один из `fragment`/`record_fragment`.
5. Флаги, пришедшие **в теле** узла из разбора (Xray `dialerProxy`,
   `finalmask.tcp`, §488/§573) и авторский JSON (§577), настройка не
   трогает ни при `true`, ни при `false`. `false` означает «сюда не
   дописывать», а не «снять». Снятие провайдерских флагов — не эта задача.
6. Mixed-case SNI **никогда** не применяется к REALITY (§363 — промах по
   map сервера, узел не поднимается), ни на каком уровне; `xn--` метки не
   трогаются.

### Правило применения — что меняется: REALITY и фрагментация

§627 запретил глобальной фрагментации трогать REALITY, потому что массовая
настройка не знает, какой сервер её примет. Для уровней:

| Уровень, на котором стоит `fragment`/`record_fragment: true` | REALITY-узел |
|---|---|
| глобально | пропуск (§627, как сейчас) |
| подписка, папка | пропуск — массовая настройка той же природы |
| узел (член папки, одиночный сервер) | **применяется** — пользователь указал на этот самый узел |

Это и есть обещанный в §627 выход для владельцев REALITY-серверов, которые
резаный ClientHello принимают.

### Хранение и бэкап

- Запись источника и запись члена получают ключ `tls` — объект с ключами
  `fragment`, `record_fragment`, `fallback_delay`, `mixed_case_sni`;
  пишутся только не-`null` поля, пустой объект не пишется (норма кодека —
  «только отличия от умолчаний»). Ключ добавить в `_serverKeys`,
  `_folderKeys`, `_memberKeys` (`source_record.dart:314-335`), иначе уйдёт в
  `unknown` и потеряется при перезаписи.
- Чтение терпимо: неизвестные ключи внутри `tls`, не-bool значения —
  игнорируются, запись не ломается.
- Бэкап едет тем же кодеком. Слияние при импорте (§633): локальная
  политика TLS сохраняется так же, как сохраняется локальный detour
  (`lx_backup.dart:3636, 3910, 3999`) — одно правило на оба поля.
- Версию схемы бэкапа не поднимать, если корпус `backup_corpus_test` и
  round-trip не требуют; если потребуют — по действующему регламенту
  (`docs/STORAGE.md`).
- Глобальные `kLxPortableVars` без изменений.

### UI

Текст интерфейса — только английский, строки ниже окончательные (сверить с
`docs/EDITORIAL_POLICY.ru.md` перед коммитом, в частности 8.3 — объект
назван тем, чем он является). `ru`/`zh` словари `assets/l10n/*/ui.json`
дополнить всеми новыми строками.

**Экран настроек узла** (`node_settings_screen.dart`, одиночный сервер и
член папки; у узла автовыбора секции нет — как у Detour). Новая секция
**между Detour и Skip presets**, строго по образцу соседней: `_sectionHeader`
+ строки `ListTile`, тап открывает диалог с радио-списком, выбор пишется
сразу, без Save (`_persistDetour` как образец записи:
`subController.setMemberTls` для члена, `entry.tls = …` + `persistSources`
для одиночного).

| Элемент | Текст |
|---|---|
| Заголовок | **TLS** |
| Описание | «Override the global TLS settings for this server.» |
| Строка | **Split ClientHello into TCP segments** — подпись: `Default (On — global)` / `Default (Off — folder)` / `On` / `Off` |
| Строка | **Split handshake into TLS records** — то же |
| Строка | **Fallback delay** — подпись: `Default (500ms)` / своё значение |
| Строка | **Mixed-case SNI** — то же, что у bool |
| Подпись под заголовком, если у узла есть detour (личный или от источника) | «Not applied: traffic goes through a detour first.» |

Диалог bool-строки — три пункта: `Default`, `On`, `Off`; в подписи `Default`
— откуда наследуется и что получится: «Inherited: On (global)» /
«Inherited: Off (folder)» / «Inherited: On (subscription)». Диалог паузы —
поле ввода с подсказкой `500ms`, пункт «Use default» сбрасывает в `null`;
невалидное значение не принимается с подписью «Enter a duration like 500ms
or 1s» (проверка — `parseCoreDurationNanos`, тот же, что в сборке).

**Вкладка настроек подписки и папки** (`subscription_settings_tab.dart`,
`folderMode` и обычный режим) — та же секция сразу после блока Detour, до
`SubscriptionServers`. Описание: «Override the global TLS settings for all
servers of this subscription.» / «…of this folder.»; `Default` наследует
только из глобального.

**Глобальный раздел «TLS Fragmentation»** (`app/assets/wizard_template.json`,
секция `dpi-bypass`): ручки те же, меняется только `description` секции —
«Splits the TLS handshake so it carries no single-packet signature. Default
for all servers; override per server, folder or subscription.» Перевод — в
`app/assets/l10n/{ru,zh}/template.json` (ключ `TLS Fragmentation`),
`template_check` должен остаться 0/0.

### Debug API

- `serializers/subs.dart`: у записи источника и члена папки — поле `tls`:
  объект с четырьмя ключами, отсутствующие поля = `null`; у источника без
  политики `"tls": {}`.
- `PATCH /subs/{id}` и PATCH члена папки: ключ `tls` — объект; поле, которого
  нет в объекте, не меняется; поле со значением `null` сбрасывается в
  «наследовать». Строка паузы проверяется той же функцией, что в UI,
  негодная → 400 с текстом ошибки.
- `help.dart` (:215-219, :743, :779) и `docs/api/debug-api-reference.md` —
  дополнить.

## Риски и граничные случаи

- Член папки с личным detour на другого члена: TLS к нему не применяется
  (правило 1), но его цель — first-hop — свою настройку получает.
- Папка в режиме Replace all: личный detour перекрыт папочным, узел всё
  равно под detour → правило 1.
- Узел под detour из входного sing-box JSON (не назначенного сборкой) —
  `containsKey('detour')` истинно, пост-шаг его пропускает сегодня; не
  менять.
- Пауза задана на узле, а оба флага эффективно `false` — пауза не пишется
  (правило 4), в UI показывается как есть.
- Переименование/удаление узла и источника: политика хранится в самой
  записи, ссылок нет — реестр `node_link_registry` не трогать.
- Старые бэкапы без ключа `tls` читаются как «всё унаследовано» — поведение
  до задачи сохраняется побитно (гарантия: существующие тесты
  `tls_fragment_*`, `mixed_case_sni_test`, `detour_yields_test` проходят без
  правок ожиданий).

## Нерешённое / к владельцу

Решения ниже приняты в ТЗ как умолчания; каждое отменяется одним словом:

1. REALITY: узловой `fragment: true` применяется, уровни подписки/папки —
   пропускают (таблица выше).
2. `false` на любом уровне не снимает флаги, пришедшие в теле узла из
   разбора (правило 5).
3. Mixed-case SNI включён в набор переопределяемых ручек наравне с
   фрагментацией.

## Отклонения при реализации

- Бэкап: на момент реализации схема контракта поля `tls` не объявляла, и в
  срезе (`lx_backup_slice.dart`) оно было настройкой без дома — экспорт
  называл его `backup_local_only_dropped`, импорт не применял. Закрыто в тот
  же день: контракт **1.1.117** (лаунчер `f148a603`, TASKS_LXBOX §114)
  объявил `$defs/tlsPolicy` и поле `tls` у `sourceSubscription`,
  `sourceFolder`, `sourceServer` и члена папки `node`; у `chain`/`auto`/
  `unsupported` поля нет. Четыре строки среза переведены в `declared: true`,
  политика едет и применяется; корпус — `corpus/backup/v10_lxbox_tls`
  (неизвестный ключ внутри `tls` терпится). Форма ожидания эффективной
  TLS-политики в `expected.json` корпуса не заведена — при надобности
  предложить лаунчеру (1.1.118).
- Узловая политика действует и на звенья родной цепочки узла (хопы из того
  же тела): first-hop цепочки — тот, кто выходит наружу.
- Диагностика одного узла (`NodeDiagnosticsRunner`, вкладка узла) в пробе
  уровни не получает — её вызов не знает источника; массовая проба
  (`ProbeRunner` папки/подписки, Debug API `/folders/{id}/probe`) получает.
