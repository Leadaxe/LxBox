# §637 — Уведомление об ошибке старта не снимается после успешного повтора

| Поле | Значение |
|------|----------|
| Тип | B (баг) |
| Статус | D (done), выпущено в v2.25.14 |
| Фича | [010-VPN_SERVICE](../features/010-VPN_SERVICE/FEATURE.md) |
| Дата | 2026-10-13 |
| Связанные | §605 (п. 1 — ошибка старта отдельным уведомлением id=2), §182 (кнопки постоянного уведомления), §428 |

## Проблема

Найдено на эмуляторе 13.10.2026 при проверке §605. При отказе старта ядра
`BoxService.stopAndAlert` показывает отдельное уведомление id=2
«Error: Failed to start service …». Страховка «core rejected node» отключает
узел и повторяет старт; старт удаётся (`setStatus(Started)`), но id=2 никто
не снимает — ошибка висит рядом с постоянным уведомлением работающего VPN.

## Решение

- `ServiceNotification.cancelAlert(ctx)` — `NotificationManager.cancel` по
  константе `ALERT_NOTIFICATION_ID`.
- `BoxService.startSingbox`: сразу после `setStatus(VpnStatus.Started)` —
  `notification.cancelAlert()`.
- `BoxService.onStartCommand`: при явном старте (intent не `null`, не
  bounce §430) — `notification.cancelAlert()` до показа «Starting»; если и
  этот старт упадёт, `stopAndAlert` покажет новую ошибку.

## Риски и границы

- Постоянное уведомление id=1 не трогается и не пересобирается: `addAction`
  не идемпотентен (§182).
- Sticky-рестарт (intent `null`) id=2 на входе не снимает: алерт шторма §428
  показывается именно на этом пути. Если sticky-рестарт дошёл до `Started`,
  id=2 снимается там.

## Приёмка

1. Отказ старта → в шторке «Error» с текстом; страховка отключает узел,
   повторный старт удаётся → «Error» исчезает, остаётся постоянное.
2. Отказ старта → «Error» висит → Start с плитки/кнопки → «Error» снят в
   момент старта.

## Проверка

Kotlin-юнитов в проекте нет; компиляция — CI (`assemble`). Ручная проверка
по приёмке — на эмуляторе.

## Итог

Правка в `ServiceNotification.kt` и `BoxService.kt`; на эмуляторе не
проверялось.
