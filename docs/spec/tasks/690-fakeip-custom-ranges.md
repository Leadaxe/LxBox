# 690 — FakeIP: свои пулы IPv4 и IPv6

| Поле | Значение |
|------|----------|
| Статус | Done (на устройстве не проверено) |
| Дата начала | 2026-10-29 |
| Источник | владелец: «дать возможность менять пулы ipv4 и ipv6 для fake-ip — задать кастомные пулы адресов, которые не попадут в стандартные диапазоны для исключения из tun» |
| Связанные | пресет `fakeip` в `wizard_template.json`; ядро `dns/transport/fakeip` |

## Проблема

Пул FakeIP зашит в тело сервера пресета: `inet4_range: 198.18.0.0/15`,
`inet6_range: fc00::/18` (дефолты sing-box). Поменять нельзя. Если эти
диапазоны в сети пользователя заняты или попадают в его исключения из TUN,
FakeIP не годится целиком.

## Решение

Две переменные пресета `fakeip`, тип `text`, видимые в его параметрах (третья, тумблер, — доработка 04.11):

| var | Заголовок | Дефолт | Поле сервера |
|---|---|---|---|
| `inet4_range` | IPv4 pool | `198.18.0.0/15` | `inet4_range` |
| `inet6_range` | IPv6 pool | `fc00::/18` | `inet6_range` |
| `inet6_enabled` (bool) | Fake IPv6 addresses | `true` | `inet6_range` есть только при `true` |

Обе необязательные (`required` нет). Поведение по значению:

- дефолт — конфиг байт в байт как раньше;
- свой CIDR — ядро выдаёт fake-адреса из него; смена диапазона сбрасывает
  сохранённые записи FakeIP (ядро сверяет диапазоны с метаданными кэша);
- тумблер `inet6_enabled` (Fake IPv6 addresses) выключен — ключа
  `inet6_range` в теле нет, ядро на AAAA отвечает пустым `NOERROR`, пул IPv4
  работает (доработка 04.11, ниже);
- CIDR с ошибкой — ядро не стартует (ошибка разбора префикса), ошибка
  старта видна как обычно. Проверки CIDR на стороне приложения нет: поле
  для тех, кто знает, зачем его меняет; подсказка говорит формат.

Пересечение пула с адресом TUN, локальной сетью или `100.64.0.0/10`
(Tailscale) не проверяется — это ответственность того, кто меняет пул.

## Файлы

- `app/assets/wizard_template.json` — vars пресета `fakeip`, тело сервера
  `"inet4_range": "@inet4_range"`, `"inet6_range": "@inet6_range"`.
- `app/assets/l10n/{ru,zh}/template.json` — заголовки и подсказки.
- `app/test/services/builder/preset_expand_test.dart` — дефолты, свой пул,
  выключенный IPv6.
- `docs/TEMPLATE.md` — строка пресета `fakeip`.

## Проверка

- Тест: дефолтные vars → тело сервера как раньше; `inet4_range =
  10.233.0.0/16` → он в `inet4_range`; `inet6_enabled = false` → ключа
  `inet6_range` нет.
- Golden-конфиги не меняются.
- Эмулятор: пресет FakeIP, IPv4 pool = `10.233.0.0/16`, URL Check по
  домену — `app_dns A` с `source=local`, адрес из 10.233.x.x.

## Доработка 04.11.2026 (issue #181)

Пустой IPv6-пул не сохранялся: по норме Н3 контракта пустое значение равно
отсутствию ключа, по Н4 умолчание не пишется, поэтому стёртое поле снова
показывало `fc00::/18`. Нормы и код хранения не трогали (общие с лаунчером).
Добавлен тумблер `inet6_enabled` (bool, дефолт `true`) перед `inet6_range`;
в теле сервера ключ `inet6_range` стоит под map-spread
`"#if": ["@inet6_enabled", {"inet6_range": "@inet6_range"}]` — при `false`
ключа нет. Тело по умолчанию — те же поля. Подсказка `inet6_range` больше не
предлагает оставлять поле пустым. Поле `inet6_range` при выключенном
тумблере не гасится: `#enable` у объявлений vars форма параметров пресета не
обрабатывает. Тест: `inet6_enabled = false` → ключа `inet6_range` нет,
`inet4_range` на месте.
