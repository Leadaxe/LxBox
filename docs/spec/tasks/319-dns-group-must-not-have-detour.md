# §319 — У DNS-группы не должно быть detour: старт падает на не-direct канале

**Тип:** таска (bug, P1)
**Статус:** исправлено 27.07.2026 — DEVICE-VERIFIED 30.07.2026 (v2.18.2)

> Проверка на CPH2411 (сборка 2.18.0-dev.6, ядро `lx.17-rc.3`): в конфиге,
> снятом с работающего ядра, у группы `dns_shield` ключа `detour` нет, набор
> полей ровно `tag/type/servers/mode/error_ttl/win_ttl` — как в
> `GroupDNSServerOptions`; туннель на этом конфиге стартует
> (`last_start_error` пуст). Сценарий «выбрать группе прокси-канал в UI»
> вручную не воспроизводился — пикер для групп скрыт, выбирать нечего.

**Затронутые релизы:** v2.18.0, v2.18.1 (с момента §312)
**Связано:** §312 (DNS-группы), §117 (detour-пикер inline-сервера), §317 (соседняя регрессия того же редактора)
**Ядро:** [kernel SPEC 033](../../../../sing-box-lx/SPECS/TASKS/033-DNS_GROUP_SERVER/SPEC.md)

---

## 1. Симптом

Жалоба пользователя (4PDA, 27.07.2026):

> DNS group works only with "direct". Once you switch from "direct" to
> "proxy", clicking "start" on the home page gives an error message.

## 2. Причина

У DNS-группы **нет своего транспорта**: она не ходит в сеть сама, запросы
несут её участники — каждый со своим `detour`. Ядро это и кодирует:

```go
option.GroupDNSServerOptions{Servers, Mode, ErrorTTL, WinTTL}
```

Поля `detour` в структуре нет, а sing-box падает на unknown field — то есть
конфиг с `detour` у `type: group` не стартует вовсе.

При этом форма редактора рисовала пикер **«Outbound (detour)» для любого
inline-сервера**, не различая группу ([params_tab.dart](../../../app/lib/screens/dns_server_edit/tabs/params_tab.dart)).
Пользователь выбирал канал → ключ уходил в `body` → билд его сохранял
(`normalizeDnsDetour` вычищала только `direct-out`, пустую строку и
неизвестные каналы) → ядро отвергало конфиг на старте.

Отсюда и точная форма жалобы: **direct работает**, потому что для него ключ
и так стирается как дефолт; любой другой канал = битый конфиг.

**Урок тот же, что в §317:** редактор DNS-сервера трактует «inline» как
однородный случай, хотя группа — принципиально иная сущность (нет адреса,
нет транспорта). Оба бага — из одного корня.

## 3. Решение

Две половины, обе нужны.

1. **Форма** — пикер detour не рисуется при `c.isGroup` (геттер из §317).
   Пользователь больше не может выставить ключ, которого у сущности нет.
2. **Билд** — `normalizeDnsDetour` снимает `detour` у `type: group`
   безусловно. Только UI недостаточно: **у пострадавших ключ уже лежит в
   storage**, и без чистки на билде их конфиг остался бы битым до ручного
   захода в редактор. Storage при этом не мутируем — как и в §312 для
   недоступных членов.

## 4. Изменения

1. [preset_expand.dart](../../../app/lib/services/builder/preset_expand.dart)
   — ранний выход `normalizeDnsDetour` для `type: group`.
2. [params_tab.dart](../../../app/lib/screens/dns_server_edit/tabs/params_tab.dart)
   — `if (!c.isGroup)` вокруг блока detour-пикера.

## 5. Тесты

`test/builder/dns_group_test.dart`:

- detour у группы вычищается из эмиссии, остальные поля не тронуты;
- у обычного сервера (`type: udp`) detour остаётся — чистка адресная.
