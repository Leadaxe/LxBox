## Проблема

Строка Tailscale-узла с exit node на главном экране выглядит так же, как
строка любого прокси: `tailscale` · состояние endpoint'а · задержка. Из неё
не видно:

1. через какое устройство идёт трафик;
2. что это устройство офлайн. Тогда трафик уходит в никуда, а строка при
   этом зелёная;
3. что ключ устройства скоро истечёт. После истечения узел молча
   отваливается, а дата видна только во вкладке Network.

Все три факта уже приходят в потоке статуса ядра (`CcTailscaleStatus.exitNode`:
`hostName`, `dnsName`, `online`), но главный экран их не использует.

Direct или relay в строку не выводим: пути до пира в потоке статуса нет,
он известен только после явного пинга (issue #155 закрыт как not planned).
Путь выводится с §613 — ядро lx.12 отдаёт его в потоке.

## Диагностика

- Подписка на `SubscribeTailscaleStatus` на главном экране
  (`HomeController._syncTailnetStatus`) живёт, только если в конфиге есть
  узлы NETWORKS, а это Tailscale-узлы **без** возможности exit
  (`networksNodeTags` отбрасывает узлы, для которых выполняется `exitCapableByRegistry`).
  Для конфига, где есть только узел с exit node, подписки нет совсем.
- Фильтр перерисовки в слушателе потока сравнивает `backendState`,
  `stateText` и число пиров. Смену exit node или его `online` он пропустит.
- Строка обычного узла собирает `protocolLabel` как
  `протокол·транспорт·security` (`node_list.dart`, построение строк прокси).

## Решение

**Подписка.** Держится, пока VPN включён и в конфиге есть хотя бы один
Tailscale-endpoint: узел NETWORKS или узел с возможностью exit. Ключ
переподписки прежний: состав тегов и снапшот конфига ядра.

**Фильтр перерисовки.** Кроме текущих полей сравнивает у `exitNode`:
`stableId`, `hostName` и `online`; у `self` — `keyExpiry`.

**Имя exit node в протокольной метке.** Условие: VPN включён, узел — Tailscale,
в записи ядра для его тега `exitNode != null`. Тогда метка —
`tailscale·via <имя>`. Имя берётся первым непустым из списка:
1. `hostName`;
2. первая метка `dnsNameClean` (до первой точки);
3. `firstIp`.

Во всех остальных случаях метка не меняется: VPN выключен, записи ядра нет,
exit node не выбран. Длинное имя обрезается многоточием по правилам метки,
ширина колонки задержки не меняется. Слово `via` проходит через l10n.

**Exit node офлайн.** Условие: выполнено условие из предыдущего пункта и
`exitNode.online == false`. Тогда на месте подписи состояния endpoint'а
(`up` / `sleep` / `down`) выводится `exit offline` цветом предупреждения
(оранжевый, как `sign-in needed`). У выключенного вручную узла (`off`) и во
время сборки подпись не подменяется. Задержку справа не трогаем.

**Срок ключа.** `self.keyExpiry` — секунды Unix; `0` — истечение ключа
отключено в админке, метки нет. Условие метки: VPN включён, узел — Tailscale
(строка NETWORKS или узел с exit), `self != null`, `keyExpiry > 0` и до
истечения меньше 7 суток. Текст:
- осталось ≥ 1 суток: `key expires Nd`, N — целые сутки с округлением вниз;
- осталось меньше суток: `key expires <1d`;
- срок прошёл: `key expired`.

Цвет — предупреждающий (оранжевый). Место:
- строка узла с exit — слот подписи состояния endpoint'а, но `exit offline`
  важнее: при офлайн-выходе показывается он;
- строка NETWORKS — на месте подписи `running`. Прочие состояния
  (`sign-in needed`, `stopped`, `starting`, текст ядра) важнее метки ключа и
  не подменяются.

Строки NETWORKS в остальном не меняются: `via` и `exit offline` к ним не
относятся.

## Риски и граничные случаи

- `exit_node` записан в конфиге, но ядро его не применило (устройство
  исчезло из сети, нет прав): `exitNode == null`, метка без `via`. Это
  расхождение показывает вкладка Network (`exitNodeMismatch`); в строку его
  не выносим, это отдельный пункт.
- Узел переключили на другой exit node из вкладки Network: метка меняется со
  следующим снапшотом потока, это обеспечивает фильтр перерисовки.
- Подписка теперь живёт и без узлов NETWORKS. Поток уже несёт список
  устройств, поэтому нагрузка та же, что при открытой вкладке Network.
- Сон endpoint'а: пока `online == true`, остаётся `sleep`, подмены нет.
- Метка ключа считается от текущего времени при перерисовке строки. Отдельного
  таймера нет: строка перерисовывается с каждым снапшотом потока и с любым
  обновлением главного экрана, точность до суток этого хватает.
- Ядро могло уже перевести узел в `NeedsLogin` после истечения ключа: тогда
  показывается `sign-in needed`, а не `key expired`.

## Проверка

Unit (по одному затронутому файлу, без прогона каталогов):
- функция построения метки: `exitNode == null` → метка без изменений;
  `hostName` пуст → берётся метка DNS; оба пусты → IP;
- функция подписи состояния: `online == false` → `exit offline` с
  предупреждающим цветом; `off` и сборка не подменяются;
- ключ подписки: конфиг только с exit-узлом → подписка есть; конфиг без
  Tailscale → нет;
- функция метки ключа: `0` → нет; 8 суток → нет; 3,5 суток →
  `key expires 3d`; 5 часов → `key expires <1d`; в прошлом → `key expired`;
- приоритет: `exit offline` важнее метки ключа; `sign-in needed` в строке
  NETWORKS важнее метки ключа;
- фильтр перерисовки: смена `exitNode.online` и `self.keyExpiry` вызывает `_emit`.

Эмулятор: узел Tailscale с exit node, VPN включён → `tailscale·via <имя>`;
exit node выключен на стороне tailnet → `exit offline` в течение одного
снапшота потока.
