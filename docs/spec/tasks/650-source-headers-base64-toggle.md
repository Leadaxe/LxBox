# §650 — Source: расшифровка `base64:`-заголовков с переключателем

| Поле | Значение |
|------|----------|
| Тип | F (доработка UI, вид согласован владельцем 14.10.2026) |
| Статус | I (реализовано), device-pending |
| Фича | [001-SUBSCRIPTIONS](../features/001-SUBSCRIPTIONS/FEATURE.md) → `FUNCTIONS/subscription-meta.md` |
| Дата | 2026-10-14 |
| Связанные | §648 (announce) |

## Проблема

Вкладка **Source** экрана подписки, блок **Response headers**, показывает
значения заголовков как они пришли. У провайдеров `profile-title` и `announce`
часто закодированы (`base64:TGliZXJ0eSBWUE4g8J+XvQ==`), и прочитать их
глазами нельзя.

## Решение

Строка заголовка, чьё значение начинается с `base64:` и расшифровывается в
UTF-8 (тем же декодером, что разбор `profile-title`), выглядит так:

```
 announce            ⚡ — Лучшие сервера
 base64              💳 — Зарубежная оплата
 ┄┄┄┄┄┄              🎮 — ПОДХОДЯТ ДЛЯ ИГР
                     📋 — БЕЛЫЕ СПИСКИ В САМОМ НИЗУ
 profile-title       Liberty VPN 🗽
 base64
 ┄┄┄┄┄┄
```

- В левом столбце под именем заголовка мелкой строкой (`bodySmall`, цвет
  `onSurfaceVariant` или `primary`) стоит `base64`, подчёркнутое пунктиром.
  Это переключатель вида значения этой строки.
- По умолчанию значение показывается расшифрованным. Тап по `base64` →
  значение показывается в исходном виде (`base64:…`), повторный тап →
  снова расшифровано. Состояние своё у каждой строки, не сохраняется между
  открытиями экрана.
- Подпись `base64` одинаковая в обоих состояниях; переключатель только меняет
  вид значения.
- Значение без префикса `base64:` и значение с битым base64 / не-UTF-8 —
  показываются как сейчас, без переключателя.
- Правило общее для всех заголовков блока, включая строки под «Show all (N)».
- Кнопка копирования блока копирует заголовки в исходном виде, как сейчас.

`base64` — техническое имя кодировки, не переводится; UI-строку при
необходимости оформить так, как в проекте оформляются непереводимые токены
(проверить, требует ли гард hardcoded-строк записи в l10n).

## Проверка

- Виджет-тест: строка с `base64:`-значением показывает расшифровку и подпись
  `base64`; тап → исходное значение; повторный тап → расшифровка. Строка без
  префикса и строка с битым base64 — без подписи, значение как есть.
