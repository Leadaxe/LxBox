# §273 — энергоаудит клиента: разбор находок и статусы

| Поле | Значение |
|---|---|
| Статус | ЧАСТИЧНО (config-generator ось закрыта; native/dart оси не прогнаны — лимит агентов) |
| Связанные | §272 (реализация энергосвязки), §215, §208; ядро SPEC 019/020 rev. 2026-07-15 |

## Контекст

После энергоревизии ядра (2026-07-15) прогнан multi-agent аудит клиента по 5 осям.
Отработала ось **config-generator** (6 находок ниже); оси native-service,
dart-runtime, command-streams, background-jobs упали по spend-лимиту — их разбор
отложен (см. «Не покрыто»). Беглый ручной проход по самым жирным точкам этих
осей сделан (см. «Ручная выборка»).

## Находки и статусы

1. **P1 §272-опции не прокинуты в прод-путь** (subscription_controller/BuildSettings/UI)
   — **ЗАКРЫТО в §272-реализации** (та же сессия): controller прокидывает
   `idleSuspendReachable`/`passiveCheck`, UI в Settings→Optimization, генератор
   эмитит с гейтом «reachable только при включённом базовом пороге».

2. **P1 дефолты ON при пине libbox lx.3 → мёртвый VPN на старом ядре** —
   **ПРОЦЕССНЫЙ БЛОКЕР, подтверждён**: незнакомое поле роняет конфиг (KERNEL.md
   #2). Правило: релиз этого кода ТОЛЬКО вместе с бампом `libbox.version` на
   релиз ядра ≥ rev. 2026-07-15 (§272 задача 1, блокирующая). Локальные тестовые
   сборки кладут свежий AAR в `libs/` с маркером. Кодового гейта по версии ядра
   сознательно нет (генератор не знает версию AAR на этапе сборки конфига;
   вводить рантайм-запрос версии в билдер — сложность не по цене риска).

3. **P2 MASQUE без idle_timeout + interval 5m == masque idle 5m → туннель не
   спит** — **СМЯГЧЕНО** дефолтом interval 15m (п.4) и `passive_check` (§272):
   пробы при живом трафике не ходят, ночью гаснут по idle_timeout. Явную эмиссию
   `idle_timeout` в masque-ноды из билдера НЕ делаем (молча менять семантику
   узла — хуже); при жалобах на masque-батарею — отдельная таска.

4. **P2 interval-дефолт '5m' в трёх источниках** — **ЗАКРЫТО**: ChannelAuto
   конструктор → '15m' (channel.dart), wizard_template `urltest_interval`
   default_value → '15m' (+опция '15m' в списке, tooltip про батарею), seedAuto
   fallback → '15m'. fromJson-fallback '5m' оставлен намеренно (legacy-записи
   без поля не должны молча менять поведение). Существующие каналы не мигрируются.

5. **P2 K каналов × полный список нод = K probe-свипов** — **ЗАКРЫТО ЯДРОМ**
   (без изменений клиента): новый probe-гейт по достижимости (SPEC 020) молчит
   пробы невыбранного auto-двойника — селектор канала указывает на конкретный
   член (`Now()`), двойник достижим только пока реально выбран. K свипов
   схлопываются в ≤1 (выбранные двойники), плюс interval 15m + passive_check.
   Дедуп одинаковых групп в билдере НЕ делаем (ломает теги/UX селекторов).

6. **P3 `find_process: true` безусловно** — **ПРИНЯТО КАК ЕСТЬ**: process-
   атрибуция питает DNS-стрим (§180/SPEC 018), connections-UI и package-rules —
   выключение рушит фичи; цена per-connection (не per-packet), умеренная.
   Ручку не выносим.

## Ручная выборка по непрогнанным осям

- **Нотификация foreground-сервиса** — НЕ обновляется по трафику (только смена
  label при переключении); классического «notification re-post каждую секунду»
  нет. ✓
- **Dart always-on таймеры** — единственный резидентный: heartbeat 20s
  (home_controller §..., loopback, задокументирован в коде как осознанный
  residual-drain); 1s-тикеры живут только в открытых вкладках Live
  Events/Per-App Trace; auto_updater — периодика обновления подписок. ✓
- **CommandClient-стримы при фоне/выключенном экране, §180 reconnect-петля,
  background-jobs / Doze** — **НЕ ПОКРЫТО**, прогнать оси при следующем окне
  агентов (или вручную): отдельная сессия.
