## Проблема

- XHTTP по умолчанию несёт идентификатор сессии в виде UUID с дефисами. Часть
  CDN режет запросы с таким шаблоном в пути или заголовке.
- Xray лечит это парой настроек: `sessionIDTable` (алфавит или его имя) и
  `sessionIDLength` (длина). Идентификатор становится случайной строкой.
- Ядро умеет то же с lx.28: `session_table` / `session_length`. Задать нужно
  оба, иначе ядро отвергает конфиг.
- Sing-box-тело узла эти поля знает (реестр контракта, парная защита).
- Разбор Xray-JSON и `extra` в ссылках их **не переносит**: узел есть, поля
  молча потеряны, сервер отвечает 403.

## Почему раньше отказались

§508: «`"0"` без таблицы — не задано, одно поле без второго — отказ ядра».
Парная защита в теле с тех пор появилась: поле без пары снимается с
предупреждением и до ядра не доходит. Довод отпал.

## Решение

- Правка делается **в контракте** (репозиторий лаунчера), не оверлеем на нашей
  стороне — решение владельца 12.11.2026.
- Мапперы диалектов `uri` и `xray` получают источники для обоих полей там же,
  где читаются `sessionIDPlacement` / `sessionIDKey`:
  - `uri`: `extra.*`, плоский `query.*`;
  - `xray`: `xhttpSettings.extra.*`, плоские `xhttpSettings.*`, то же для
    `splithttpSettings`.
- Цели: `transport.session_table`, `transport.session_length`.
- Длина приводится к строке ядра (`"10"` или `"min-max"`). `0` и пустое — «не
  задано», в тело не пишутся.
- Одно поле без второго снимает существующая парная защита тела.

## Тесты

- Xray-JSON, оба поля в `extra` → оба в теле.
- Xray-JSON, оба поля плоско в `xhttpSettings` → оба в теле.
- Ссылка `vless` с `extra` → оба в теле.
- Длина числом и диапазоном.
- Одно поле без пары → в теле нет ни одного, у узла предупреждение.
- Нулевая длина → поля не заданы, предупреждения нет.
