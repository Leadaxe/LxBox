## Проблема

У цепочки хопов два имени: `tag` (`chain-1`) и `label` («warp chain-1»).
Фильтр Направления (regex по тегу, `build_config.dart` `nodesFor`,
`screens/home/node_filter.dart`) видит только тег, поэтому цепочка с
подписью «warp chain-1» под фильтр `warp` не попадает. Пользователь видит
одно имя, фильтр ищет по другому. Заголовок редактора — «Hop chain · chain-1»
при поле Title «warp chain-1».

## Решение владельца (30.09.2026)

`label` у **цепочки** упраздняется, остаётся только тег. Довод §405 («chain-2
пользователю ничего не говорит») к цепочке не применим: тег цепочки задаётся
свободно при создании (диалог New chain), осмысленное имя дают сразу.

- **Направления не трогаем** — `Direction.label` живёт как в §405.
- **Переименование тега после создания — вне задачи.** Тег остаётся
  immutable, как сейчас.

## Что сделать

**Модель.** `SourceChain.label` удалить; `displayLabel` удалить, все
вызовы → `tag`. `SourceChainEntry.displayLabel` (`models/source_entry.dart`)
отдаёт `chain.tag`.

**Хранение.** Кодек `models/codec/chain_record.dart`: `label` не пишется;
при чтении ключ `label` молча отбрасывается (старые `lxbox_settings.json`
его содержат). Ключ остаётся в `_chainKeys`, чтобы не порождать
unknown-key. Миграции имени нет: тег остаётся прежним, подпись теряется.
Это осознанная цена — автопереименование тега требует каскада по ссылкам
(§402), которого нет.

**Экраны.**
- `chain_edit_screen.dart`: поле Title убрать, моноширинную строку тега над
  ним убрать; тег — в заголовке («Hop chain · <tag>», как сейчас). Всё, что
  сравнивало `label` в dirty-проверке и `_snapshot`, убрать.
- `chain_edit/new_chain_dialog.dart`: только поле тега; `NewChainRequest`
  без `label`.
- Списки, пикеры, выпадашки целей правил, DNS-опции, экран outbound,
  `chains_section.dart`, `chain_hop_targets.dart`, `rule_transfer_dialogs` —
  показывают тег.

**Storage / API.** `addChain`/`_addChain` без `label`
(`services/settings_storage.dart`, `settings_storage/chains.dart`).
Debug API (`services/debug/handlers/chains.dart`, `serializers/chains.dart`):
поле `label` из ответа убрать; в POST/PATCH `label` обрабатывать так же, как
хендлер обрабатывает любое неизвестное поле. Обновить help/документацию
Debug API (`docs/api/`), если поле там описано.

**Сборка.** Предупреждения `chain_nodes.dart`, `build_config.dart` —
по тегу.

**Бэкап.** `lx_backup.dart`/`lx_backup_slice.dart`: `chains[].label` не
пишется; при чтении игнорируется без warning'а. Схему контракта
(`app/contract`) НЕ трогать — правку `BACKUP.md`/схем делает владелец
через лаунчер.

**l10n.** Строки, ставшие мёртвыми («Title» у цепочки, «optional — defaults
to the tag», если больше нигде), убрать из ARB по правилам `docs/l10n.md`.

## Проверка

- Юнит: кодек читает запись с `label` без ошибок и не пишет его; бэкап со
  `chains[].label` восстанавливается без warning'а.
- Тесты, ссылающиеся на `label` цепочки, поправить. Запускать ТОЛЬКО
  затронутые файлы тестов, по одному; полный прогон — в CI.
- Критерий: у Направления с фильтром `warp` в пуле цепочка с тегом `warp`
  (сегодня фильтр работал по тегу — поведение сборки не меняется, меняется
  то, что пользователь видит только тег).

## Не входит

- Переименование тега цепочки (каскад по ссылкам, §402).
- `label` у Направлений.
- Правка контракта/схем — follow-up владельца в лаунчере.
