## Проблема

Пропинговал один канал — пинги во всех остальных обнулились. Переключился на
другой, пропинговал его — обнулился первый. Ручной пинг после каждого
переключения, каждый раз заново.

Разбор аndrey (#1382) точен буквально:

> нажатие кнопки тест-пинг сбрасывает данные глобально, а вот сам тест идёт
> только для текущего канала. Причём если сервера из текущего канала содержатся
> и в других, то их данные пинга появятся везде.

## Причина

`HomeState.lastDelay` был **одной плоской картой на всё приложение**, ключ =
глобальный config-тег ноды. Mass-ping на старте прогона чистил её **целиком**:

```dart
_emit(_state.copyWith(lastDelay: <String, int>{}, pingBusy: busyMap));
```

А заполнял только тем, что перебирает, — нодами **текущего** канала
(`order ?? _state.nodes`, где `nodes` = состав выбранного селектора). Асимметрия
«чистим всё — пишем часть» и есть баг.

Наблюдение про общие серверы — прямое следствие глобального ключа: у ноды,
входящей в два канала, тег один, поэтому её замер виден в обоих.

Смена канала сама по себе карту не трогала: `setSelectedGroup` бампает только
`pingBatchGen` (инвалидация кэша сортировки, §070). Источник обнуления был ровно
один — mass-ping.

## Решение

Полное разделение замеров по каналам: **изоляция записи + фоллбэк чтения.**

### Форма хранилища

`lastDelay: Map<String, int>` → `delayByChannel: Map<String, Map<String, int>>`
(`канал → тег → ms`), [home_state.dart](../../../app/lib/models/home_state.dart).

Разделение нужно не только ради изоляции сброса. Ping-URL и таймаут резолвятся
**per-group** (§040), поэтому «180мс» из канала с быстрым test-endpoint'ом и из
канала с медленным — разные величины, и складывать их в один ключ некорректно
независимо от того, кто их стирает.

Ключ канала — `selectedGroup`. Замеры вне контекста канала (`selectedGroup ==
null`: папки, проба подписок) живут под `HomeState.scratchChannel` (`' scratch'`)
— отдельный ключ, а не «сложить в текущий», иначе такие замеры присвоил бы себе
случайный канал.

### Чтение: фоллбэк с пометкой

```dart
int? delayOf(String tag)        // свой замер канала → иначе любой другой → null
bool delayIsForeign(String tag) // показанное число пришло из другого канала
```

Строгая изоляция чтения (в канале B нода без своего замера = пусто) была
отвергнута: она чинит #1382 ценой #1290 — после каждого переключения список
пустой, и пинговать надо каждый канал отдельно. Фоллбэк закрывает обе жалобы:
сброс изолирован, а список никогда не пустеет.

Цена фоллбэка — показанное число может быть получено чужим тестом. Поэтому оно
**помечается**, а не выдаётся за своё.

### Пометка в UI

Бейдж пинга — узкий моноширинный текст (`120MS` / `ERR`), справа в строке.
Значок: **префикс `~`** → `~120MS`, `~ERR`
([node_row.dart](../../../app/lib/widgets/node_row.dart)).

Почему так:

- `~` = «приблизительно» — ровно нужный смысл («ориентир, мерили не здесь»),
  читается без легенды;
- **один символ**: emoji или иконка сломали бы выравнивание колонки и ширину
  бейджа (он прижат к правому краю и конкурирует за место с протоколом);
- цвет остаётся по латентности (видно, что «зелёный»), но приглушается до
  `alpha 0.55` — чужой замер не спорит за внимание со своими.

### Запись

`_delaysWith(updates, {channel})`
([ping_orchestration.dart](../../../app/lib/controllers/home_controller/ping_orchestration.dart))
— точечная запись в карту одного канала, остальные не копируются и не трогаются.
`null`-значение = удалить ключ (старт mass-ping: на время прогона место замера
занимает индикатор `pingBusy: '…'`).

**Канал-получатель фиксируется снимком на старте прогона** — тем же, что уже
брался для url/timeout (§040). Пользователь может переключить канал посреди
прогона, и тогда замеры, сделанные URL'ом канала A, не должны осесть в B.

### Сортировка

`_compareLatency` читает `delayOf` — то же число, что видит пользователь,
включая фоллбэк. Иначе нода с показанным «~120MS» уезжала бы в хвост к
неизмеренным.

### Мёртвые ключи

Нода ушла из конфига — замер остаётся в карте своего канала. Безвредно: карта
нигде не итерируется как список, только lookup по живому тегу. Сборка мусора не
нужна.

## Границы

Что задача **не** делает:

1. **Персиста нет.** `delayByChannel` живёт в памяти `HomeController`, на старте
   — пустой `HomeState()`. Перезапуск приложения обнуляет замеры.
2. **Возраст замера не показан.** Часовой выглядит как минутный (пометка `~`
   говорит «из другого канала», а не «давно»).

Из жалоб эти пункты не следуют; при необходимости — отдельная задача (персист +
метка времени замера).

## Диагностика

Debug-дамп ([serializers/home_state.dart](../../../app/lib/services/debug/serializers/home_state.dart)):

- `delay_by_channel` — вся раскладка по каналам (ключ `' scratch'` = вне канала);
- `last_delay` — плоский срез ТЕКУЩЕГО канала с фоллбэком, ровно то, что видно
  в списке (поле сохранено для совместимости разборов).

## Тесты

[`test/controllers/mass_ping_delay_scope_test.dart`](../../../app/test/controllers/mass_ping_delay_scope_test.dart):

- **изоляция записи** — mass-ping в канале A не трогает карту B; в A убраны
  только ноды прогона; переключение канала само по себе замеры не трогает;
- **фоллбэк чтения** — свой замер приоритетнее чужого и не помечается; нода без
  своего замера берёт чужой и помечается; не мерили нигде → `null` без пометки;
  после смены канала прежние замеры видны как чужие;
- **scratch** — при `selectedGroup == null` замеры уходят в `scratchChannel`.

Для засева добавлен опциональный `delayByChannel` в `debugSeedNodeState` (§290).
Тесты сортировки (`home_state_sort_test.dart`) переведены на новую форму.
Набор §286/§307 (`probe_halt_lifecycle_test.dart` — отмена прогона и
поведение при сворачивании) прогнан без изменений.

Полный прогон: `flutter analyze` чист, 2573 теста зелёные, все четыре
l10n-чекера — 0 findings.
