## 1. Подписи копирования узла не локализованы (019/020)

**Проблема.** «Copy server + detour(s)», «Server copied», «Detour copied»,
«Server + N detour(s) copied» — литералы, положенные в переменную и затем в
`Text(...)` (`outbound_view_screen.dart`, `home/node_actions.dart`). Перевода
нет ни в ru, ни в zh.

**Решение.** Обернуть в `getLocalText.s` / `getLocalText.plural`, добавить
переводы ru и zh.

**Приёмка.** Сайты ловит `hardcoded_check` (п. 3); `ui_check --strict` без
missing/orphan.

## 2. Тема, проверка обновлений в About, «Add tile» (020)

**Проблема.** Подписи режима темы `System/Light/Dark`
(`appearance_tab.dart`), результат ручной проверки обновлений на экране About
(`_statusLine` в `about_screen.dart`) и сообщения запроса плитки быстрых
настроек (`app_settings_screen.dart`) — литералы через переменную.

**Решение.** То же, что в п. 1. В About — те же ключи, что у
`update_status_row.dart` («You're up to date», «Check failed: %s»), плюс
«Check skipped: %s».

**Приёмка.** Как в п. 1.

## 3. Дыра в ratchet `hardcoded_check`: литерал через переменную

**Проблема.** Пункты 1–2 прошли CI, потому что скан смотрит только на литерал
прямо в display-позиции. `final label = 'X'; … Text(label)` и
`_line = 'X'; … Text(_line!)` — мимо. Та же дыра прячет ещё ~25 строк в других
экранах (About — версия ядра, пояснение зависшего соединения, секция приложений
правила, пометка «(optional)», меню Connect/Reconnect, события Live-журнала,
меню группировки Stats) и подписи категорий в превью импорта (хелпер
`_previewCheckbox` не зарегистрирован в `l10n_helpers.json`).

**Решение.** Скан прослеживает идентификатор в display-позиции (и `x!`) до его
значений: инициализатор и присваивания локальной переменной в объемлющем теле
функции, для поля — во всём классе; каждое строковое значение — отдельный сайт.
Найденное — перевести; машинное (JSON-заглушка, тег `unnamed` в JSON-превью,
единица `ms`, имя протокола) — `// l10n-exempt`. `_previewCheckbox`
регистрируется в `l10n_helpers.json`.

**Приёмка.** Юнит-тест в `test/tool/hardcoded_scan_test.dart`: литерал через
локальную переменную, через поле с `!`, через присваивание в `switch` — сайты;
переменная с `getLocalText.s(...)` — не сайт. `hardcoded_check --strict` —
0 failures.

## 4. 17 плоских записей в `ru/ui.json` (029)

**Проблема.** Строки DNS-групп («Error TTL», «Win TTL», «Selection mode»,
«Members», «Group», «Server type», «Fastest — …» и др., 17 шт.) записаны
`"key": "перевод"` вместо `{"value": …}`. Движок (`_lookupValue`: не `Map` →
null) печатает английский; `ui_scan` пропускает не-`Map` молча.

**Решение.** Переписать 17 записей в форму `{"value": …}`. `ui_scan`: запись
не-`Map` — находка `shape` (fail всегда).

**Приёмка.** Юнит-тест в `test/tool/ui_check_test.dart`: плоская строка в
словаре — `shape`. `ui_check --strict` — чисто.

## 5. Debug API: текст ошибки `app_language` без `zh` (029)

**Проблема.** `PUT /settings/vars/app_language` принимает `zh`
(`SettingsStorage.appLanguageValues`), но ошибка говорит
`must be "system", "en" or "ru"`.

**Решение.** Текст собирается из `appLanguageValues` — одно место.

**Приёмка.** Юнит-тест обработчика: неверное значение → 400, в тексте есть
каждое из `appLanguageValues`.

## 6. Локаль ядра на старте процесса (029, ЧАСТИЧНО)

**Проблема.** `BoxApplication.onCreate` ставит `Libbox.setLocale` от локали
устройства. Dart-старт затем пере-пушит сохранённый язык, но в headless-старте
(загрузка устройства, QS-плитка, Intent API без UI) Dart не поднимается — ядро
говорит на языке устройства, а не выбранном.

**Решение.** `onCreate` зовёт `L10n.applyLibboxLocale(this)`: та же функция,
что при смене языка, читает сохранённую настройку (`system` → локаль
устройства с тем же откатом на голый язык).

**Приёмка.** Юнит-тестов Kotlin в проекте нет; проверка — сборка CI и
ручная на эмуляторе (язык `ru` на английском устройстве, старт VPN с плитки,
ошибка ядра по-русски). Ручная проверка — за владельцем/стендом.

## 7. Закрепление конфига едет в «App settings» (017)

**Проблема.** `config_locked_for_debug` (§037) — не в
`SettingsStorage.debugApiVarKeys`, поэтому в бэкапе относится к категории App
settings. Восстановление App settings без Debug API config привозит
`locked = true` без включённого Debug API — пересборка конфига заблокирована,
снять замок негде.

**Решение.** Ключ входит в `debugApiVarKeys`: категория Debug API config, при
замене файл без ключа оставляет значение устройства (§413).

**Приёмка.** Юнит-тест: категория ключа — Debug config; импорт только App
settings из файла с `config_locked_for_debug: true` не ставит замок.

## 8. Зеркало тумблеров VPN при замене (017, ЧАСТИЧНО)

**Проблема (что осталось после §599).** `native_prefs` нет в
`allowedTopLevelKeys` и нет ни в одной категории: замена (`replaceRaw`,
`merge=false`) стирает зеркало получателя. Если блок `vpn_settings` не
применялся (категория снята или её нет в файле), экраны до рестарта показывают
тумблеры VPN по умолчанию, а первая же запись одного тумблера создаёт секцию из
одного ключа — остальные при следующем старте уезжают в native дефолтами. Сырой
снимок Debug API с `native_prefs` показывает его «неизвестным ключом».

**Решение.** `native_prefs` — свойство устройства, как флаги §600: из снимка не
применяется, в отброшенные не попадает, замена сохраняет секцию получателя.
Тумблеры восстанавливаются только блоком `vpn_settings` (как сейчас).

**Приёмка.** Юнит-тест: замена снимком без категории VPN сохраняет
`native_prefs` получателя; снимок с `native_prefs` → он не в отброшенных и не
применён.

## 9. Итог восстановления (017)

**Проблема.** Итоговые строки восстановления на экране Backup и с главного
экрана — литералы; путь с главного экрана не применяет привезённый язык
(`LocaleController.reloadFromStorage`) и не показывает число ошибок.

**Решение.** Общая функция итога для обоих путей: локализованные части,
число ошибок, число отброшенных ключей, «fetching subscriptions…» для главного
экрана. Главный экран зовёт `LocaleController.I.reloadFromStorage()` после
применения, как экран Backup.

**Приёмка.** Юнит-тест функции итога: при ошибках в тексте их число; пустой
итог — «ничего не импортировано». Сайты проверяет `hardcoded_check` и
`ui_check`.

## 10. `LxCodeEditor(readOnly: true)`: Cut/Paste правят текст (019)

**Проблема.** Меню выделения (`LxSelectionToolbarController.show`) кладёт
Cut/Paste безусловно; `CodeLineEditingController.cut()/paste()` пакета тоже
безусловны. В read-only редакторе долгий тап → Cut/Paste режут и вставляют.

**Решение.** Контроллер меню знает `readOnly`; в read-only в меню только Copy
и Select all.

**Приёмка.** Виджет-тест `test/widgets/lx_code_editor_readonly_menu_test.dart`:
в read-only нет пунктов Cut/Paste, Copy копирует, текст не меняется; в обычном
режиме Cut/Paste есть.
