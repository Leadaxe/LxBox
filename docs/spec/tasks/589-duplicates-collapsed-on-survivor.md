|------|----------|

| Дата завершения | 2026-09-29 |

| Контракт | 1.1.102 (лаунчер 2c7af64a; `TASKS_LXBOX.md` §99; SPEC 154 лаунчера) |
| Связанные spec'ы | tasks §342 (владение сервером в Xray-массиве) |

## Проблема

Провайдеры кладут один сервер в подписку много раз под разными именами:
живая подписка на 114 записей даёт 5 разных серверов, каждый повторён 18–25
раз под разными странами и брендами. LxBox схлопывает такие записи
(`_dropDuplicates`, `lib/services/parser/parse_all.dart`), но человек видит
только строку «N entries dropped» в сводке подписки. Сравнивает с Happ (110
строк) и считает, что узлы потерялись.

Владелец 29.09: «хотел бы видеть, что куда схлопнулось».

## Решение

### Модель (норма контракта 1.1.102)

Результат схлопывания пишется на ВЫЖИВШИЙ узел кодом реестра
`duplicates_collapsed` (severity `info`, params `count`, `names`):

1. `count` — сколько записей тела схлопнуто в этот узел.
2. `names` — их имена в порядке тела через `", "`: без пустых, без повторов,
   без имени выжившего; не больше 10, дальше `", …"`. Если называть некого
   (все повторы под тем же именем) — имя выжившего.
3. Путь схлопывания любой: дедуп записей тела (`nodeDedupSignature`) и
   владение сервером в Xray-массиве (§342). Члены балансировщика своего
   элемента в `count`/`names` не входят.
4. Место кода — в конце кодов разбора, перед кодами санитайзера.
5. Код — факт об источнике: пересчёт кодов по телу узла (правка тела,
   миграции) его не стирает, как вердикт ядра; свежий разбор подписки
   заменяет.
6. Схлопнутые записи в `dropped[]` не попадают.

Per-app код `duplicate` (`kWarningCodes`, `DuplicateNodeWarning`) убрать
вместе с комментарием «лаунчер схлопывание не делает» (лаунчер схлопывает с
SPEC 112-B).

### UI (что видит человек)

- **На узле** — `info`-пометка по тексту реестра с подстановкой `count` и
  `names`: видно, какие имена слились в этот узел. Там же, где остальные
  предупреждения узла (строка списка + экран узла), тем же механизмом.
- **Сводка подписки** — строка «N entries dropped» больше не считает дубли.
  Вместо неё, если дубли были, отдельная строка вида «M duplicates merged
  into K nodes» (английский, как весь UI). По ней понятно, куда делась
  разница с числом записей в теле; подробности — на узлах.

## Верификация

- Корпус: `body/uri_list/duplicates_collapsed`,
  `body/xray/duplicates_collapsed_owner` — код стоит на тех узлах, что в
  эталоне.
- Юнит: `count`/`names` — порядок тела, без повторов, без имени выжившего,
  обрезка на 10 с `", …"`, случай «все под тем же именем».
- Юнит: пересчёт кодов по телу сохраняет `duplicates_collapsed`.
- Вручную (эмулятор): подписка с повторами — у выжившего узла пометка со
  списком имён, в сводке строка про слияние, дубли не в «dropped».

## Реализация

- `lib/services/parser/parse_all.dart`: `_collapseDuplicates` (бывший
  `_dropDuplicates`) копит имена схлопнутых записей по выжившему и ставит
  код `markDuplicatesCollapsed`; форма `count`/`names` —
  `duplicatesCollapsedWarning`. Позиция кода — конец кодов разбора: длина
  списка кодов каждого узла снимается до прохода санитайзера по дословной
  карте, код вставляется туда.
- Xray-массив (§342) идёт своим путём: `parseXrayElement` сообщает
  `onCollapse` о выпущенном и выброшенном сервере (правило владения и повтор
  внутри элемента); члены балансировщика своего элемента (`selector` первого
  балансировщика, то же правило, что у состава группы) не сообщаются.
  `_parseXrayDocument` ставит код выжившему.
- `DuplicateNodeWarning` и per-app код `duplicate` удалены; строки
  «Duplicate entry…»/«Duplicate of %s» ушли из каталогов ru/zh.
- Сохранение: предупреждения узла подписки в LxBox не хранятся — пересчёт
  узла подписки есть разбор всего тела (регидрация кэша, обновление), и код
  воспроизводится по построению. Штампы вердикта ядра
  (`stampNodeWarnings`, `unstampCoreRejected`) трогают только свой код.
  Повторная постановка заменяет прежний код.
- UI: на узле — `ⓘ` в строке списка и карточка в Notifications по тексту
  реестра (`title`: «Repeats of this server in the subscription: {count}»,
  `text` с `{names}`); в сводке подписки — строка
  «%1$d duplicates merged into %2$d nodes» (`SubscriptionEntry.duplicatesMerged`,
  значок `merge_type`), «entries dropped» дублей больше не считает.

## Итерация 2 (2026-11-16) — строка сводки раскрывает склейки

Владелец 16.11: попапы на странице подписки — отработанный приём; строка
«M duplicates merged into K nodes» тоже должна по тапу показывать, что с чем
склеилось. Новую задачу не заводить — доработать эту.

### Решение

- Строка сводки «M duplicates merged into K nodes» становится кликабельной,
  как «N entries dropped» (§561): шеврон справа, тап открывает ту же шторку
  `showNodeWarningsSheet`.
- В шторке — по одной карточке на выжившего: код `duplicates_collapsed` с
  узла (текст реестра с `{count}` и `{names}`), подпись «Entry: <тег
  выжившего>» (`ownerTag`). Видно, какой узел остался и какие имена в него
  слились.
- Новых данных нет: всё уже лежит в коде на узле. Предел имён остаётся
  нормой контракта (10 и `", …"`), точное число — в `count`. Хранение,
  бэкап, контракт, Debug API не меняются.
- Цвет строки — прежний нейтральный (`info`, не ошибка).
- Папка не трогается: сводной строки дублей у неё нет, между источниками
  папки повторы не схлопываются. Одиночному серверу склеивать нечего.

### Реализация

- `lib/services/parser/parse_all.dart`: `duplicatesCollapsedWarningsOf(nodes)` —
  коды `duplicates_collapsed` с узлов в порядке списка, копией с
  `ownerTag` = тег выжившего.
- `SubscriptionEntry.duplicatesCollapsed` — список для шторки (пусто у
  не-подписки).
- `subscription_meta.dart`: `_MergedRow` — `InkWell` + шеврон, тап —
  `showNodeWarningsSheet`.

### Проверка

- `test/screens/subscription_dropped_summary_test.dart`: строка дублей
  открывает шторку, в ней по карточке на выжившего с тегом в `ownerTag`.

## Итерация 3 (2026-11-16) — карточки склеек не сворачиваются в группу

Эмулятор на 5b5de62d (подписка 3× DE, 2× NL, 1× FI): шторка показала ОДНУ
общую карточку со счётчиком 2, в заголовке «…» вместо числа, в тексте «…»
вместо имён. Причина — группировка §572 (`groupWarningsByCode`,
`node_notifications_view.dart`): записи одного кода сворачиваются в группу,
а расходящиеся подстановки заменяются на `groupDiffersMark` («…»). Для
`duplicates_collapsed` это убивает смысл шторки: у каждого выжившего свои
число и имена. Владелец 16.11: «Да, починить» до релиза v2.25.22.

### Решение

- `kUngroupedWarningCodes = {duplicates_collapsed}` в
  `node_notifications_view.dart`: коды из набора `groupWarningsByCode` не
  сворачивает, каждая запись — своя карточка (как одиночный код).
  Группировка остальных кодов (в том числе кодов сборки источника, §739)
  не меняется.

### Проверка

- `test/screens/subscription_dropped_summary_test.dart` — шторка с двумя
  выжившими: две карточки с «Entry: <тег>», в заголовках «…: 2» и «…: 1»,
  в раскрытых карточках имена слившихся, знака «…» в шторке нет.
- Эмулятор — переснять строку и шторку на сборке с этой правкой.
