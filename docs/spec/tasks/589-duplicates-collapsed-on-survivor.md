# 589 — Схлопнутые дубли видны на выжившем узле (`duplicates_collapsed`)

| Поле | Значение |
|------|----------|
| Статус | In progress |
| Дата старта | 2026-09-29 |
| Контракт | 1.1.102 (лаунчер 2c7af64a; `TASKS_LXBOX.md` §99; SPEC 154 лаунчера) |
| Связанные spec'ы | tasks §342 (владение сервером в Xray-массиве) |

## Проблема

Провайдеры кладут один сервер в подписку много раз под разными именами:
живая подписка на 114 записей даёт 5 разных серверов, каждый повторён 18–25
раз под разными странами и брендами. LxBox схлопывает такие записи
(`_dropDuplicates`, `lib/services/parser/parse_all.dart`), но человек видит
только строку «N entries dropped» в сводке подписки. Сравнивает с Happ (110
строк) и считает, что узлы потерялись.

Владелец 29.09: «хотел бы видеть, что куда схлопнулось».

## Решение

### Модель (норма контракта 1.1.102)

Результат схлопывания пишется на ВЫЖИВШИЙ узел кодом реестра
`duplicates_collapsed` (severity `info`, params `count`, `names`):

1. `count` — сколько записей тела схлопнуто в этот узел.
2. `names` — их имена в порядке тела через `", "`: без пустых, без повторов,
   без имени выжившего; не больше 10, дальше `", …"`. Если называть некого
   (все повторы под тем же именем) — имя выжившего.
3. Путь схлопывания любой: дедуп записей тела (`nodeDedupSignature`) и
   владение сервером в Xray-массиве (§342). Члены балансировщика своего
   элемента в `count`/`names` не входят.
4. Место кода — в конце кодов разбора, перед кодами санитайзера.
5. Код — факт об источнике: пересчёт кодов по телу узла (правка тела,
   миграции) его не стирает, как вердикт ядра; свежий разбор подписки
   заменяет.
6. Схлопнутые записи в `dropped[]` не попадают.

Per-app код `duplicate` (`kWarningCodes`, `DuplicateNodeWarning`) убрать
вместе с комментарием «лаунчер схлопывание не делает» (лаунчер схлопывает с
SPEC 112-B).

### UI (что видит человек)

- **На узле** — `info`-пометка по тексту реестра с подстановкой `count` и
  `names`: видно, какие имена слились в этот узел. Там же, где остальные
  предупреждения узла (строка списка + экран узла), тем же механизмом.
- **Сводка подписки** — строка «N entries dropped» больше не считает дубли.
  Вместо неё, если дубли были, отдельная строка вида «M duplicates merged
  into K nodes» (английский, как весь UI). По ней понятно, куда делась
  разница с числом записей в теле; подробности — на узлах.

## Верификация

- Корпус: `body/uri_list/duplicates_collapsed`,
  `body/xray/duplicates_collapsed_owner` — код стоит на тех узлах, что в
  эталоне.
- Юнит: `count`/`names` — порядок тела, без повторов, без имени выжившего,
  обрезка на 10 с `", …"`, случай «все под тем же именем».
- Юнит: пересчёт кодов по телу сохраняет `duplicates_collapsed`.
- Вручную (эмулятор): подписка с повторами — у выжившего узла пометка со
  списком имён, в сводке строка про слияние, дубли не в «dropped».
