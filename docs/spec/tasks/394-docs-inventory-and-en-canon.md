# §394 — Инвентаризация документации: язык, парность, сверка с кодом

**Тип:** docs / audit · **Статус:** in progress

Ревизия всей документации проекта по трём осям: язык файла, наличие пары
RU/EN и соответствие содержания коду. Повод — решение перевести основные
документы на английский, а русские версии вести как парные файлы `X.ru.md`.

## Решения (зафиксированы с юзером)

| Вопрос | Решение |
|---|---|
| Имя перевода | `X.ru.md` (не `X_RU.md`) |
| Кто парный | Пользовательские доки: README, USER_GUIDE, DONATE, PRIVACY_POLICY, SECURITY, AUTOMATION |
| Кто только EN | Dev-доки: BUILD, FDROID, ARCHITECTURE, STORAGE, TEMPLATE, PROTOCOLS, KERNEL, DIAGNOSTICS, RELEASE_PROCESS, DEVELOPMENT_GUIDE, l10n |
| Что не трогаем | `DEVELOPMENT_REPORT.md` — замороженная хроника до v1.9.0, переводить нечего; помечен шапкой |
| Что с `docs/spec/` | Не трогаем: 455 файлов, рабочий журнал, канон места — не язык |
| Актуализация | Включает сверку логики с кодом, не только ссылки и версии |

Причина деления: dev-доки правятся вместе с кодом почти в каждой задаче.
Русская пара к ним означала бы двойную работу на каждой правке — и, как
показывает опыт §360, вторая сторона отстаёт молча.

## Расхождения с кодом

Найдено сверкой доков против дерева исходников, не чтением одних доков.

### 1. Пин ядра устарел в четырёх местах

Фактический пин — `app/android/libbox.version` = **`v1.14.0-lx.25-rc.5`**.
В доках стоит `v1.14.0-lx.1` — версия, которой не существует в проекте
уже много релизов:

| Файл | Строка |
|---|---|
| `docs/ARCHITECTURE.md` | 1558 |
| `docs/DEVELOPMENT_GUIDE.md` | 322 |
| `docs/RELEASE_PROCESS.md` | 259 |
| `docs/RELEASE_PROCESS.md` | 377 |

Опасность не косметическая: в `RELEASE_PROCESS.md` это **пункт
post-flight-чеклиста** — «версия ядра совпадает с пином (сейчас
`v1.14.0-lx.1`)». Проверяющий по чеклисту сверит APK с несуществующим
числом и либо решит, что релиз сломан, либо перестанет доверять пункту.

`docs/BUILD.md` починен в этом проходе (было два вхождения).

### 2. Debug API: документированы удалённые эндпоинты

`docs/api/debug-api-reference.md` в разделе «Per-app session» описывает
девять роутов, которых нет в коде — их снёс **§288** (фаза 2: сервисный
слой + Debug API):

```
/profiler/start      /profiler/stop       /profiler/active
/profiler/sessions   /profiler/session/{id}
/profiler/stream     /profiler/secondary-packages
```

Живые роуты профайлера — только `/profiler/live*` (шесть штук), они в
доке тоже есть, ниже по тексту. То есть документ описывает обе версии
как действующие, хотя первой не существует.

Для сравнения: `docs/features/per-app-trace.md` и
`docs/api/clash-api-reference.md` **корректно** помечены как исторические
шапкой-предупреждением. Здесь такой пометки нет.

### 3. Debug API: не документированы живые эндпоинты

Есть в коде и в живом `GET /help`, но отсутствуют в справочнике:

| Роут | Что это |
|---|---|
| `/support/state` | §356 — состояние ленты поддержки |
| `/support/preview` | §356 — предпросмотр сообщения |
| `/support/reset` | §356 — сброс baseline |
| `/rules/move` | §370 — зеркало drag-n-drop правил |
| `/files/oom`, `/files/oom/list` | OOM-снапшоты ядра |

Существенно потому, что документ сам заявляет себя зеркалом `GET /help`:
«зеркалит живой `GET /help`» (`docs/README.md`). Сейчас в `/help` 119
описанных роутов против 113 в справочнике.

### 4. Механизм пина Flutter описан неверно

`BUILD.md` утверждал, что Flutter-версия «зафиксирована в workflow» и при
обновлении надо править `ci.yml`. Фактически CI читает её из файла
`app/android/flutter.version` (шаг `Flutter version pin`), и править надо
именно файл. Значение (3.41.6) совпадает. Починено в этом проходе.

### 5. Битая ссылка

`docs/DEVELOPMENT_REPORT.md:510` вёл на `spec/features/024 loadbalance/` —
на диске папка называется `024 load balance`. Починено.

### 6. DEVELOPMENT_GUIDE: числа устарели вдвое

«~1400+ тест-кейсов в 112 файлах» — фактически **3016 в 227**
(прогон `flutter test`). «61 фича» в `spec/features/` — фактически 72.

### 7. DEVELOPMENT_GUIDE: политика версии в pubspec противоречит §379

Документ утверждал, что версия «не правится вручную нигде и не хранится
в git», а `pubspec.yaml` — фиксированный placeholder `0.0.0+1`. С §379
реальная версия **коммитится** при релизе (иначе F-Droid `checkupdates`
не читает её и автообновление в каталоге не работает); в `pubspec.yaml`
сейчас `2.20.8+22008500`. Исправлено со ссылкой на §379.

### 8. DEVELOPMENT_GUIDE: рекомендованный analyze у́же CI-шного

Гейт советовал `flutter analyze lib/ test/`, тогда как CI гоняет
`flutter analyze` без аргумента — по всему проекту. Сужение путями
пропускает файлы вне этих папок. Плюс раздел вовсе не упоминал четыре
l10n-чекера и `parity_check`, которые в CI идут с `--strict` и валят
сборку на warning'ах. Добавлены командами.

### 9а. Переименование пар: две ссылки пропущены в первом проходе

При переезде на `X.ru.md` (`37cffa16`) в `README.ru.md` была исправлена
шапка-переключатель, но не таблица документов внизу файла — две ссылки
продолжали вести на `docs/USER_GUIDE_RU.md` / `docs/DONATE_RU.md`. Работали
они только благодаря заглушкам. Найдено обратным grep'ом по старым именам
уже после коммита; чинить такое надо в момент переименования:

```bash
grep -rn "СТАРОЕ_ИМЯ" --include="*.md" --include="*.dart" . | grep -v app/build
```

`app/build/` в выдаче — артефакты сборки, не репозиторий.

### 9. DEVELOPMENT_GUIDE: правило «English-only до локализации»

Раздел описывал состояние до §279/§285: «локализация появится когда-нибудь,
пока второго языка нет». Локализация давно есть, английский текст = ключ
перевода. Раздел переписан под natural keys со ссылкой на `l10n.md`.

### 10. Живой баг, найденный при сверке RELEASE_PROCESS

Не документация: **в `develop` сейчас `version: 2.20.8+22008500`** вместо
placeholder'а. CI-guard «Pubspec version is a placeholder (develop only)»
(`ci.yml:160`) падает на любом push в `develop`.

Как попало: в merge-back'е v2.20.8 (`7dfdfefb`, 13.08) пропущен шаг §2.6
`git checkout HEAD -- app/pubspec.yaml` до коммита. Было
`2.20.6-dev.7+22006500` → стало `2.20.8+22008500`.

Это повтор: `bc9d934d` (07.08) — «fix(ci): вернуть placeholder версии в
develop», ровно та же ошибка после v2.20.6. Шаг забывают систематически;
сигнал приходит только на следующем push, потому что merge проходит чисто
и сборку это не ломает (обе сборки переписывают версию перед `flutter
build`).

Исправлено коммитом `747c9177`: `version: 2.20.8-dev.11+22008500`.
Логика guard'а прогнана на новом значении вручную, `pub get` и `analyze`
зелёные.

В `RELEASE_PROCESS.md` §2.6 добавлено предупреждение, что шаг пропускают
регулярно, с указанием обоих прецедентов и лечения.

### 11. Размер AAR разъехался в трёх местах

`KERNEL.md` говорил «~97 MB», `BUILD.md` — «~73 MB» (дважды), фактический
файл на диске — **110 MB** (`libbox-1.14.0-lx.25-rc.5.aar`). Ядро росло, а
цифры не обновляли ни разу. Приведены к факту с оговоркой «as of lx.25».

### 12. KERNEL: ложная метка «текущий пин» у rc.3

В таблице истории версий строка `v1.14.0-lx.25-rc.3` была помечена как
«(текущий пин)», хотя в `libbox.version` уже rc.5 — и сам документ выше
это правильно называл. Метка снята: в таблице истории её вообще не должно
быть, актуальный пин живёт в одном месте.

### 13. STORAGE: два ключа allowlist не документированы

`STORAGE.md` заявлял свой список top-level ключей «исчерпывающим», но в нём
не было `route_idle_suspend_reachable` и `urltest_passive_check` — оба §272,
оба в `SettingsStorage.allowedTopLevelKeys`, оба config-significant, один
из них ещё и в `backup_service.dart`.

Класс расхождения опасный: ключ, попавший в allowlist, но не в документацию,
легко пропустить при добавлении в экспорт — и тогда значение переживает
export и молча теряется на restore. Оговорка про «новый ключ — в оба места»
добавлена прямо под таблицу.

### 14. STORAGE: vars-таблица разошлась с `_appFeatureFlagVars`

Документ требует «держать таблицу в синхроне» с
`SettingsStorage._appFeatureFlagVars`, но `auto_ping_on_start` (дефолт
`'true'`, читается в `ping_orchestration.dart`, тумблер в App Settings)
в таблице отсутствовал. Добавлен.

## Что проверено и расхождений не найдено

Чтобы не перепроверять по кругу:

- `minSdk = 24`, `targetSdk` из Flutter — совпадает с `ARCHITECTURE.md`
  (включая обоснование выбора 24 и историю понижения с 26 в §233).
- Flutter 3.41.6, JDK 17 — совпадают.
- Версия приложения: `pubspec.yaml` 2.20.8, последний `docs/releases/`
  тоже v2.20.8 — сходится.
- Путь словаря локализации `assets/l10n/<tag>/ui.json` — совпадает с кодом
  (`locale_controller.dart`, `template_loader.dart`).
- Ссылки верхнего уровня: из 404 битых по всему дереву на верхнем уровне
  была одна настоящая (см. п. 5). Остальные — в исторических спеках и
  релиз-нотах, где ссылки на переехавший код это норма.

     переведены построчно, структура (134 заголовка) не тронута

**Грабля перевода: якоря на русские заголовки.** Ссылки вида
`ARCHITECTURE.md#локализация-l10n-279` живы, пока целевой документ русский,
и молча ломаются в момент его перевода — markdown не проверяет якоря, CI
тоже (`parity_check` ссылки не сверяет by design). Перед переводом каждого
крупного документа собирать входящие ссылки на его якоря:

```bash
grep -rn "ИМЯ\.md#" docs/ README.md --include="*.md"
```

и чинить их в том же коммите. Всего по репозиторию 15 ссылок на
кириллические якоря; на переводимые крупные доки из них ведут четыре
(`ARCHITECTURE.md#локализация-l10n-279` ×3,
`TEMPLATE.md#локализация-display-текста--l10n-overlay-279` ×1).

Шаг 3 отделён намеренно: это правки фактов, они ценны сами по себе и не
должны ждать перевода 500 КБ текста.
