## Проблема

Импорт LX Backup («Transfer to desktop → Import») показывает snackbar
«Imported …», но импортированный сервер не появляется ни на экране Servers,
ни в `GET /subs` Debug API — до перезапуска приложения. Кнопки «Restart now»,
как у обычного restore, нет.

Хуже: если до перезапуска изменить что-нибудь в списке Servers (выключить
тумблер у другого сервера), `SubscriptionController` записывает в хранилище
свой старый список, и импортированное пропадает с диска (`GET /state/storage`).
Пользователь теряет данные молча. Дефект есть в выпущенной v2.25.22.

Тот же эффект у `POST /backup/import` Debug API и у обычного restore с экрана
Backup: там snackbar предлагает «Restart now», но кнопку можно не нажать, а
snackbar исчезает через 6 секунд — дальше та же потеря.

## Диагностика

Импорт и restore пишут хранилище напрямую (`SettingsStorage`), мимо
контроллеров. Контроллеры, которыми владеет `HomeScreen`
(`SubscriptionController`, `HomeController`, `AutoUpdater`,
`RuleSetAutoUpdater`), держат снимок хранилища в памяти, прочитанный при
`init()`. `SubscriptionController._persist()` переписывает весь набор
источников своим составом (§515), поэтому любая следующая мутация контроллера
(тумблер, перетаскивание, фетч подписки, пересчёт бюджета узлов) затирает то,
что импорт положил в хранилище.

Секции бэкапа и их держатели в памяти:

| Секция импорта | Держатель в памяти | Был ли перечитан |
|---|---|---|
| источники, цепочки (`sources[]`) | `SubscriptionController._entries` | нет — потеря при записи |
| Направления, `ping_options.groups` | `HomeController` / `SubscriptionController` (сборка) | нет |
| правила, `route.final`, vars | читаются при сборке и экранами при открытии | частично |
| DNS | экраны читают при открытии | да |
| миксины, WARP | экраны/сборка читают из хранилища | да |
| native prefs (тема, тумблеры) | `ThemeNotifier` слушает `nativePrefsGeneration`; гейты автоматизации | тема — да; автоматизация у LX-импорта — нет |
| язык | `LocaleController` | у LX-импорта — нет |

Вывод: дефект общий для всего, что пишут импорт и restore, а не только для
серверов; главный носитель потери — `SubscriptionController`.

В приложении уже есть путь, который делает ровно «хранилище переписано целиком
— перечитать всё»: загрузка слота Workspaces (§417). Он перечитывает
статические части (`_reloadStateFromDisk`: кэш хранилища, native prefs, язык,
миграция Направлений, автоматизация), поднимает `configDirty` и увеличивает
`WorkspaceController.generation`. `LxBoxApp` держит `HomeScreen` с ключом
`generation`, поэтому `HomeScreen` и все его контроллеры пересоздаются и читают
хранилище заново, а старые контроллеры становятся `stale`, и их `_persist()`
ничего не пишет (барьер §515) — даже асинхронные хвосты (летящий фетч).

Проверено widget-тестом (опыт, не в репозитории): `HomeScreen` под ключом
пересоздаётся и тогда, когда поверх него открыт другой маршрут (экран Backup).

## Решение

Два варианта из постановки:

1. **Принудительный перезапуск**, как предлагает restore («Restart now»).
   Не выбран: у restore кнопка необязательна — snackbar можно пропустить, и
   данные теряются так же. Сделать перезапуск неизбежным (выход без спроса)
   грубо, а для `POST /backup/import` невозможно без убийства процесса посреди
   HTTP-ответа.
2. **Перечитать сцену без перезапуска** — выбран. Импорт и restore
   переписывают хранилище так же, как загрузка слота Workspaces, и
   обрабатываются тем же механизмом: новый
   `WorkspaceController.remountAfterExternalWrite()` = flush хранилища →
   `markConfigDirty()` → `_reloadStateFromDisk()` → `generation++`. Надёжность
   дают два свойства, уже проверенные в §417/§515: новые контроллеры читают
   свежее хранилище, а старые не могут записать ничего, даже из незавершённых
   асинхронных операций.

   В отличие от загрузки слота VPN не останавливается: импорт меняет настройки,
   а не набор слотов. Поднятый `configDirty` заставляет новый `HomeScreen`
   пересобрать конфиг (и применить, если включён §338 «Auto-restart VPN on
   settings change»; иначе — обычная синяя плашка о несохранённых изменениях).

Где вызывается — одинаково для всех путей, которые пишут хранилище мимо
контроллеров `HomeScreen`:

- импорт LX Backup с экрана Backup — после `LxBackupImportService.apply`;
  сервис остаётся чистым (его вызывают раннер корпуса и golden-обвязка), вызов
  делает экран;
- restore с экрана Backup (`restoreFromContents` без `onApplied`);
- `POST /backup/import` Debug API — после записи; для `rebuild=true` сборка
  ждёт новый `SubscriptionController` (регистрируется в `DebugRegistry` при
  `initState` нового `HomeScreen`), старый собрал бы конфиг из устаревшего
  снимка.

**Экраны поверх главного закрываются.** Экран, открытый поверх `HomeScreen`
(Servers, App Settings → Backup), получил контроллер прежнего `HomeScreen`
при открытии. После remount он показывал бы устаревший список, а правка на нём
молча не записалась бы (контроллер `stale`) — найдено на эмуляторе: открытый
Servers после `POST /backup/import` не показывал импортированный сервер.
Поэтому перед `generation++` remount вызывает хук
`WorkspaceController.onExternalRemount`, который ставит `main()`: корневой
навигатор закрывает всё до `HomeScreen`. Пользователь оказывается на главном
экране с итогом импорта в snackbar (корневой `ScaffoldMessenger`, взятый до
записи). У загрузки слота Workspaces хука нет: она идёт с главного экрана и
сама закрывает свой диалог прогресса — общий «закрыть всё по смене
`generation`» закрыл бы этот диалог дважды.

Пути с главного экрана в пустом состоянии (`restoreFromBackup`,
`receiveFromPhone`) уже перечитывают свой `SubscriptionController` через
`init()` и запускают принудительное обновление подписок своим `AutoUpdater`;
их не трогаем (см. «Не делается»).

## Риски и крайние случаи

- **Пересоздание при поднятом VPN.** Новый `HomeScreen` поднимается так же,
  как при пересоздании Activity с работающим сервисом: подписывается на статус
  туннеля. Проверено на эмуляторе (сц. 7).
- **Пользователь оказывается на главном экране** после импорта, где бы он ни
  был: это цена того, что ни один экран не держит устаревший контроллер.
- **Приложение в фоне (Debug API).** Кадров нет — новый `HomeScreen` построится
  при возвращении на передний план. Старые контроллеры уже `stale`, потери нет.
  `rebuild=true` ждёт новый контроллер ограниченное время и честно отвечает
  `rebuilt: false`, если он не появился.
- **Кнопка «Restart now» у restore** остаётся: перезапуск процесса дополнительно
  перечитывает нативную сторону. Комментарий о том, что без неё UI устаревает,
  исправлен.

## Не делается

- `restoreFromBackup` / `receiveFromPhone` на пустом главном экране: перечитывают
  только `SubscriptionController`; перевод на общий remount требует перенести
  принудительное обновление подписок в новый `HomeScreen` — отдельная задача.
- Контракт с лаунчером не затронут: формат бэкапа не менялся.
