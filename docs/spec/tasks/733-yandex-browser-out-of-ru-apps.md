## Problem

Три жалобы одного автора:

1. **#1995** — переименование SOCKS5-узла правкой `tag` в JSON на вкладке
   Source не применяется, пока узел не удалишь и не добавишь заново.
2. **#2004** — GitHub открывается только при выключенном L×Box; в «Статистике»
   соединение идёт `direct`.
3. **#1924** — пресет «Российский сегмент интернета» идёт через vpn-1, явного
   переключателя нет.

## Diagnosis

Проверено по коду и шаблону 15.11.2026 (`develop` 59a022ba).

### 1. Переименование через Source — дефект, уже исправлен

До 2.25.21 Save вкладки Source брал тег из поля Tag вкладки Settings и вписывал
его в тело: тег, исправленный в самом тексте, затирался прежним значением поля.
Исправлено в §722 коммитом 5f19bfc4 (09.11.2026, вошёл в v2.25.21):
«побеждает тот, кого трогали» —
`app/lib/screens/node_settings/node_document.dart:110`,
вызов — `app/lib/screens/node_settings_screen.dart:489`. Покрыто юнит-тестами
`node_document_test.dart`, но не путём экрана целиком.

Пост написан 31.10 — на 2.25.19/2.25.20, то есть до исправления.

### 2. GitHub напрямую — найден механизм, нужны данные

В шаблоне `github.com` / `githubusercontent.com` нет ни в одном direct-списке:
`ru-domains`/`ru-services` — инлайн-суффиксы `.ru` и т. п.; `geoip-ru` —
российские диапазоны (адреса GitHub/Fastly туда не входят). DNS этих доменов
идёт в `dns_shield` (`dns.final`), не в `dns_ru` — правила `dns_ru` только для
`ru-domains`/`ru-services`.

Но правило маршрута ru-direct
(`app/assets/wizard_template.json:754` до правки) включало набор `ru-apps`
(legiz-ru `ru-app-list.srs`, опция «Российские приложения по пакету», дефолт
вкл., `:726`). В этом списке есть **`com.yandex.browser` и
`com.yandex.browser.lite`** (проверено по `ru-app-list.json` legiz-ru
15.11.2026). Правило по пакету матчит всё, что делает приложение, поэтому весь
трафик Яндекс Браузера — любые сайты, GitHub тоже — уходит `direct` по
умолчанию. В «Статистике» такое соединение показано с правилом ru-direct.

Второй механизм — пресет «Неизвестный трафик» (`:997`): соединение, которое
ядро не смогло приписать установленному приложению, уходит `direct`. Отличить
одно от другого можно только по правилу в карточке соединения.

Почему direct не открывает GitHub, хотя без L×Box открывается — по коду не
видно; нужны данные от пользователя.

### 3. ru-direct через vpn-1 — по дизайну в текущей версии

`outbound` пресета — `direct-out` по умолчанию (`wizard_template.json:688`),
во всех релизах с 2.25.16. В 2.25.16 (актуальном на 20.10) DoT-сервер группы
`dns_ru` был жёстко направлен через vpn-1 (`yandex_dot`, «Yandex Safe DoT (via
vpn-1)»), в 2.25.17 UDP Яндекса шёл через `dns_plain_outbound` = vpn-1 — эти
DNS-соединения и видны в статистике как vpn-1. С 29.10 (§684/§697, в 2.25.19+)
UDP Яндекса идёт через выход пресета, DoT/DoH — напрямую (галка «Шифрованный
DNS через Outbound» выкл.). Сохранённые значения старых vars
(`dns_plain_outbound`, `dns_encrypted_outbound`) шаблон больше не читает, так
что старые установки получают новый дефолт. Переключатель есть: Маршрутизация →
Пресеты → «Российский сегмент интернета» → вкладка «Параметры» → «Исходящий
канал».

## Решение владельца (16.11.2026)

Исключение Яндекс Браузера из `ru-apps` **не согласовано**: «яндекс браузер
русское приложение, работает через ру сегмент». Правка шаблона (`49af728c`) и
эталон под неё (`9d92c81d`) откачены до релиза v2.25.22, в релизы не попали.
Весь трафик Яндекс Браузера при включённой опции «Российские приложения по
пакету» по-прежнему идёт `direct` — это проектное поведение, не дефект. Раздел
Solution ниже описывает отклонённый вариант и оставлен как история.

Правка попала в `develop` 15.11 вместе с ветками 731 и 732 по слову «влить все
три»: пометка «подтвердить у владельца» стояла в коммите и в спеке, но при
слиянии владельцу отдельно показана не была.

## Solution

1. **#1995** — кода не меняем; добавлен виджет-тест пути экрана: узел socks и
   http, тег исправлен в тексте Source, Save → узел переименован
   (`test/screens/node_settings_unsaved_changes_test.dart`).
2. **#2004** — **решение по умолчанию, подтвердить у владельца** (меняет
   дефолт для всех пользователей, отдельный коммит, можно отбросить):
   правило маршрута ru-direct разделено на два —
   `{"rule_set": ["ru-domains", "ru-services", "geoip-ru"]}` и logical `and`
   из `{"rule_set": ["ru-apps"]}` и
   `{"package_name": ["com.yandex.browser", "com.yandex.browser.lite"], "invert": true}`.
   Российские сайты в Яндекс Браузере по-прежнему идут напрямую (по доменам и
   geoip), остальные — по общим правилам. Подсказка опции «Российские
   приложения по пакету» говорит об исключении (en/ru/zh). При выключенной
   опции logical-правило снимается целиком (`cleanRuleSetRefsDeep`).
   Альтернативы, которые не взяты: опция-список исключений в пресете (лишний
   UI ради одного случая); оставить как есть и только объяснить.
3. **#1924** — кода не меняем, ответ пользователю.

## Risks and edge cases

- Пользователь, который сознательно гонял Яндекс Браузер мимо VPN целиком,
  после обновления увидит его в туннеле для нероссийских сайтов.
- Список legiz-ru может добавить другие браузеры — исключение статично.
- Ядро: logical-правило с `rule_set` внутри — поддерживается (такая форма уже
  есть у пресета fcm-push).
