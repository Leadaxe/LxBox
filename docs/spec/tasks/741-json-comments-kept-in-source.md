## Problem

Узел, вставленный JSON-ом с комментариями (`//`, `/* */`, `#`), принимается,
но комментарии снимались до записи: на вкладке Source их уже не было, после
вставки и Save приходило «Comments were removed.». Автор #171 держит в
комментариях пометки к серверам и теряет их при первом сохранении.

Ссылка и WG-INI хранятся в исходнике узла текстом как есть (INI — вместе со
своими `#` и `;`). JSON был единственным видом исходника, из которого текст
вычищался.

## Diagnosis

- У узла две части: `body` (разобранные данные, истина узла) и `origin.raw`
  (текст, из которого узел получен; `origin.kind` — его диалект). Вкладка
  Source показывает `origin.raw`.
- `uncommentedJson` (`app/lib/services/parser/json_comments.dart`) звался до
  записи: `SubscriptionController.addFromInput` (вставка), `classifySource`
  (`source_classify.dart`, Save на Source), превью вставки
  (`clipboard_analysis.dart`). Причина в шапке файла: с комментариями `raw`
  не разбирался строгим `jsonDecode`.
- Узлы своего сервера и члена папки перечитываются из `origin.raw` движком
  `decode` (`body_decoder.dart`) — во многих местах (`server_list.dart`,
  `source_record.dart`, `node_document.dart`, контроллер, миграции). Значит,
  снимать комментарии надо в самом `decode`, а не у каждого вызова.
- Прямые `jsonDecode` исходника в обход `decode`: признаки документа и тега
  (`SourceItem.isDocument`, `node_document.dart`), авто-эмодзи (`node_emoji.dart`,
  `_isJsonDocument` / `_documentWithDefaultEmoji` контроллера), канон тела
  бэкапа (`canonicalNodeBody`), голое тело в декодере бэкапа (`decode_10.dart`),
  поля тела (`withBodyFields` — маскировка, exit-узел Tailscale),
  `masqueradeKeysPresent`.
- Найдено попутно: `prependEmojiToRawBody` опознавал JSON по первому символу
  `{`/`[`. Текст, начинающийся с комментария (`// …\n{…}`), уходил в ветку
  ссылки, и `#` комментария принимался за фрагмент имени — источник портился.
- `nodeIdentityKey` / `node_hash` считаются по разобранному `NodeSpec` — от
  текста исходника не зависят.

## Solution

1. **Одна функция «исходник → JSON»** — `jsonSourceText(text)`
   (`json_comments.dart`): текст без комментариев, если они есть и без них
   текст — строгий JSON (`uncommentedJson`); иначе текст как есть (ссылка,
   `.conf`, JSON без комментариев, битый текст). `uncommentedJson` теперь
   принимает текст, начинающийся с комментария (`//`, `/*`, `#` перед `{`),
   и не делает лишнего `jsonDecode` строгого JSON: сканер его проходит,
   ничего не найдя. Дешёвый отсев — первый значащий символ `{ [ / #`.
2. **Чтение.** `decode()` снимает комментарии на входе — через него идут все
   разборы узлов из `origin.raw`. Остальные читатели (п. «прямые `jsonDecode`»
   диагноза) зовут `jsonSourceText`. Гейт предпросмотра JSON
   (`node_settings_screen.dart`, `verbatimBodyOf`) читает `rawSource` узла —
   он строится из разобранного объекта, комментариев в нём нет, правки не
   понадобилось.
3. **Запись** (норма лаунчера §11 п.2): `classifySource` кладёт в элемент
   текст как набран (`trimmed`, с комментариями), когда обрезать нечего —
   голое тело, документ без ключей вне узловых массивов. Обрезанный документ
   и элемент массива пересобираются (`JsonEncoder.withIndent`) — без
   комментариев. Вставка (`addFromInput`) отдаёт текст как есть.
4. **Тег правкой текста** — `withJsonTag(text, tag)`: ключ `tag` верхнего
   уровня есть — меняется только его строковое значение; нет — `"tag": …`
   встаёт первым ключом (с отступом следующей строки). Им пользуются поле
   Tag на Source (`_withTag` для голого тела с комментариями), авто-эмодзи
   при вставке, импорт бэкапа (тег записи в голое тело, см. «Расхождения»).
5. **Бэкап.** `canonicalNodeBody` снимает комментарии до канонизации: тот же
   узел с пометками и без — одна запись. `decode_10`: голое тело с
   комментариями хранится текстом (тег записи — `withJsonTag`), без
   комментариев — объектом, как прежде.
6. **Папка.** Добавление в папку одного голого тела с комментариями пишет
   члену текст как набран (прежде — `rawSource` узла, без комментариев).
7. **Редактор.** Сообщение «Comments were removed.» снято везде (вставка,
   мастер Add server, Save на Source), признаки `commentsRemoved` /
   `lastCommentsRemoved` удалены, ключ словарей ru/zh удалён. Диалог
   «Comments will be removed» в `lx_code_editor.dart` оставлен: он стоит на
   действии **Format** (JSON5 → JSON с отступом), а Format комментарии
   действительно снимает — и на Source, и в Config.

Известные ограничения (комментарии теряются, текст пересобирается):

- обрезанный документ и массив (норма лаунчера);
- переименование узла внутри документа (поле Tag, авто-эмодзи владельцу
  документа без эмодзи — значит, вставленный документ с комментариями обычно
  пересобирается уже при вставке);
- запись полей приложением в JSON-текст: Edit JSON на вкладке JSON, секция
  маскировки, exit-узел Tailscale (`withBodyFields`);
- форма OpenConnect над Source при комментариях выключена («Source is not a
  valid JSON object») — как и раньше, чтобы правка формы не стёрла их.

Вне задачи: комментарии в кэше тела подписки, в редакторе Config и в Mixins.
Побочный эффект п.2: `decode` общий, поэтому подписка (и файловая), чьё тело —
JSON с комментариями, теперь тоже разбирается (раньше — отказ).

## Расхождения с нормой лаунчера

- **Тег голого тела живёт в тексте.** У LxBox имя узла читается из его JSON,
  тег записи и есть идентичность (§439). Импорт бэкапа кладёт тег записи в
  голое тело с комментариями правкой текста (`withJsonTag`): комментарии и
  прочие байты целы, добавлена одна строка `"tag": "…",`. Кейс
  `backup/v10_origin_raw_json_comments` ждёт `origin_raw` байт в байт без
  тега; наш раннер (`backup_corpus_test.dart`, `_checkOriginRaw`) принимает
  ровно эту вставку — по аналогии с прежним правилом раннера «корневой `tag`
  у объекта не сравнивается, его несёт запись». Лаунчеру — для сведения;
  норму это не меняет (текст «как набран» плюс тег записи).
- **Голое тело без комментариев** при импорте бэкапа по-прежнему
  пересобирается компактно с тегом (`configJson`), а не хранится как набрано
  (лаунчер с 1.1.172 хранит как набрано и его). Сравнение корпуса по значению
  это допускает; менять не стали — вне задачи, затронуло бы golden-тесты.

  **Дефект сц. 7.** Шаги: вставить тело, первая строка которого `// …`
  (как в сц. 1) → открыть сервер → Source → ⋮. Ожидалось: пункт Format,
  подсветка JSON. Вышло: только Magnifier, текст без подсветки. Причина:
  `detectCodeLanguage` (`lx_code_editor.dart`) признаёт JSON, только если
  первая значащая строка начинается с `{`/`[`; первая строка `// …` или
  `/* …` даёт `null`, `# …` — тоже `null` (ветка INI ищет `[секцию]` или
  `ключ=значение`). Это то же, что починено в `uncommentedJson`, но не в
  определении языка редактора; той же функцией язык берёт и редактор в
  `folder_detail_screen`. Не чинилось.

  **Найдено вне задачи (LX Backup, не 741).** Импорт «Transfer to desktop →
  Import» (`LxBackupImportService.apply`) пишет только хранилище:
  `SubscriptionController` в памяти остаётся прежним, импортированный узел
  не появляется в Servers и в `GET /subs` до перезапуска приложения, кнопки
  «Restart now», как у обычного restore, нет (08, 15, 16). Хуже: если до
  перезапуска изменить что-то в списке Servers (выключить тумблер у другого
  сервера), контроллер записывает старый список, и импортированный узел
  пропадает из хранилища (17). Шаги: экспорт LX Backup → удалить сервер →
  Import того же файла → snackbar «Imported …» → Servers: сервера нет →
  тумблер у любого другого сервера → `GET /state/storage`: сервера нет.
  Воспроизведено на обоих AVD. Тот же эффект у `POST /backup/import` через
  Debug API отмечался 16.11.2026 (проверка 739).
