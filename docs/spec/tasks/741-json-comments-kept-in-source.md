## Problem

Узел, вставленный JSON-ом с комментариями (`//`, `/* */`, `#`), принимается,
но комментарии снимаются до записи: на вкладке Source их уже нет, редактор
предупреждает «Comments will be removed». Автор #171 держит в комментариях
пометки к серверам и теряет их при первом сохранении.

Ссылка и WG-INI хранятся в исходнике узла текстом как есть (INI — вместе со
своими `#` и `;`). JSON — единственный вид исходника, из которого текст
вычищается.

## Diagnosis

- У узла две части: `body` (разобранные данные, истина узла) и `origin.raw`
  (текст, из которого узел получен; `origin.kind` — его диалект). Вкладка
  Source показывает `origin.raw`.
- `uncommentedJson` (`app/lib/services/parser/json_comments.dart`) зовётся до
  записи: `SubscriptionController` (вставка), `classifySource`
  (`source_classify.dart`, редактор Source). В `origin.raw` уходит текст без
  комментариев. Причина в шапке файла: с комментариями `raw` не разбирается
  строгим `jsonDecode`, и тело не становится авторским (`verbatimBodyOf`).
- Сравнение «тот же ли это узел» (BACKUP.md, идентичность) у JSON-исходника
  идёт по каноническому JSON, а не по тексту — от комментариев не зависит,
  если читатель снимает их перед разбором.
- `origin.raw` едет в бэкапе к лаунчеру. Лаунчер разбирает его при Regen и
  при вычислении идентичности; про комментарии в `raw` контракт молчит.

## Solution

1. **Запись.** В `origin.raw` видов `singbox` / `xray` уходит текст как
   набран, с комментариями. Снятие комментариев переезжает с записи на чтение.
2. **Чтение.** Каждое место, которое разбирает JSON-исходник (`verbatimBodyOf`,
   гейт редактора `node_settings_screen.dart`, декодер бэкапа, идентичность,
   Regen), сначала снимает комментарии тем же `uncommentedJson`. Одна общая
   функция «исходник → JSON», чтобы не размножать вызовы.
3. **Редактор.** Предупреждение «Comments will be removed» и признак
   `commentsRemoved` снимаются там, где текст сохраняется в исходник. Остаются
   там, где текст по-прежнему не хранится (редактор конфига Config, Mixins —
   вне этой задачи).
4. **Контракт.** Норма для обеих сторон: `origin.raw` видов `singbox` / `xray`
   может нести комментарии `//`, `/* */`, `#` (вне строковых литералов);
   читатель снимает их перед разбором; идентичность считается по
   каноническому JSON после снятия. Запрос лаунчеру — TASKS_LXBOX.
5. **Известное ограничение** (как у ссылок): правка узла через форму Settings
   меняет `body`, текст исходника остаётся прежним; комментарии живут, пока
   узел правят текстом на вкладке Source.

Вне задачи: комментарии в кэше тела подписки, в редакторе Config и в Mixins;
перенос комментариев при правке формой.

## Открытые вопросы

- Ответ лаунчера: умеет ли его разбор `origin.raw` снимать комментарии, или
  ему нужна своя правка до того, как мы начнём их писать (иначе бэкап с
  комментариями у него не прочитается).
- Миграции нет: старые исходники без комментариев остаются валидными.

## Проверка

- Тесты: вставка JSON с тремя видами комментариев → `origin.raw` дословно,
  `body` разобран; правка на Source и сохранение — комментарии на месте;
  бэкап туда-обратно; идентичность одинакова с комментариями и без.
- Эмулятор: вставить узел с комментариями, открыть Source, сохранить, собрать
  конфиг, экспорт и импорт бэкапа.
