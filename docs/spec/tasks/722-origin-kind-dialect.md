## Проблема

Симптом (#209): узел из Xray JSON нельзя сохранить на вкладке Source —
любая правка, даже одного тега, отклоняется («JSON must be an outbound
object with "type"…» / «The document has no node to save»).

Причина глубже симптома. Реестр `source_kinds.json` различает 12 видов
источника (`singbox_outbound`, `xray_config`, `uri_lines`,
`wireguard_conf`…), движок определяет вид при каждом разборе, но результат
**не записывается**: в записи остаётся грубое `origin.kind: uri | wg_ini |
json`, где `json` — и sing-box, и Xray. Дальше каждый потребитель угадывает
диалект заново, и не одним способом:

| Где | Как решает диалект |
|---|---|
| движок (`sourceKindOf`, `services/parser/engine/document.dart`) | реестр |
| `verbatim_body.dart` Д-1 | `sourceIsSingbox` → движок (заплатка после того, как Xray уехал в ядро дословно и уронил конфиг) |
| импорт (`subscription_controller.dart` ~1250) | `decoded.source.mapper == 'singbox'` |
| `bareNodeSourceOf` (`source_record.dart`) | три `singbox_*` вида, Xray — мимо |
| Save на Source (`node_document.dart`) | **свой** критерий: ключ `type` → #209 |

§576/§11 («после правки — только sing-box тело») был попыткой убрать
неопределённость, уничтожив второй диалект; выполнен только для sing-box,
Xray сознательно оставлен сырым. Итог: правило декларировано одно,
фактическое поведение — другое, а Xray как форма своего узла — полуживой.

## Решения владельца (08–09.11.2026)

1. **Вид источника — хранимое свойство записи.** `origin.kind` ∈
   `singbox | xray | uri | wg_ini`. Два признака записи — диалект (маппер)
   и форма текста; форма (outbound/конфиг) видна движку за одну проверку и
   не хранится. Массивы (`*_array`) — формы ввода: на входе режутся на
   записи, каждая со своим видом. Восемь JSON-видов реестра для записи не
   нужны — это 2 диалекта × 4 упаковки.
2. **Вид определяется один раз — когда текст приходит снаружи**: вставка,
   импорт файла, ответ провайдера при обновлении подписки, Save на вкладке
   Source. Определяет движок по реестру. Внутри приложения хранимый текст
   заново **не нюхается**: чтение, сборка, Source/JSON, бэкап ветвятся по
   `origin.kind` через реестр.
3. **Подписки — не исключение.** Их источник получает вид по тому же
   правилу при каждом обновлении (новый вход).
4. **§576/§11 отменяется.** Источник хранится в своём диалекте;
   «источник = sing-box» — неверно. Запись выводит из источника все свои
   узлы (владелец + звенья `dialerProxy`/`detour`); релей в конфиге и в
   списке — отдельный узел, как у подписки (фильтр «Hide detour servers»
   работает по факту ссылок, фича 007).
5. **Save на Source — новый вход:** вставлен текст другого диалекта — вид
   записи **меняется**, не отвергается.
6. **Всё, кроме узлов, выкидывается** при сохранении, как раньше (§575):
   из конфига остаются только `outbounds`/`endpoints` (sing-box) или
   `outbounds` (Xray); `route`/`dns`/`routing`/`log`/… — не сохраняются,
   одно сообщение на сохранение («Only the nodes are saved…»).
7. **Миграция `json`:** одноразово при чтении, вид — движком; JSON, который
   не разобрался (`unsupported`) → `singbox` (прежнее поведение `json`).
8. **Совместимости назад не нужно.** Контракт с лаунчером обновляется
   обязательно; у лаунчера — своя сессия на ту же задачу, синхронно.
9. **Запись с несколькими узлами:** карточка сервера показывает состав
   (`tag · N nodes`), Tag — по узлу (переименование переписывает ссылки на
   него в том же тексте), остальное — по записи (см. таблицу).

| Настройка | Уровень | Почему |
|---|---|---|
| Tag | узел | имя у каждого своё; ссылки `detour`/`dialerProxy`/`routing` в тексте переписываются |
| Enabled | запись | звено отдельно не выключить — сломается владелец |
| Detour-политика | запись | ложится на хвост цепочки (как сейчас, §073/§245) |
| TLS-политика | запись | один набор на источник; на какие хопы ложится — уточнить при реализации (§665: физически наружу говорит звено, не владелец) |
| allow_local/lan/gateway, own_routes, Tailscale-поля | запись | свойства записи |

## Решение

### A. Модель и хранение

- `origin.kind` — поле записи своего сервера и члена папки, значения
  `singbox | xray | uri | wg_ini`. Пишется в `_originToRecord` из
  **хранимого** поля записи, не выводится из текста (`originKindOf` →
  только миграция).
- Отображение реестр → запись: `mapper` вида: `singbox` → `singbox`,
  `xray` → `xray`, `uri` → `uri`, `conf` → `wg_ini`; обёртки
  `amnezia_link`/`base64_wrapped` вида не дают — вид у содержимого.
- Чтение (`_serverFromRecord`, `_memberFromRecord`): `kind` читается;
  отсутствует или `json` → миграция п.7 (один раз, записывается обратно).
  `bareNodeSourceOf` и `kLegacyNodeSourceKinds` снимаются; документы
  хранятся как есть (п.4), с обрезкой до узлов (п.6) **при записи**, не
  при чтении.
- `UserServer.nodes` уже список; разбор источника даёт все узлы записи
  (`parseAll(own: true)`), включая звенья как отдельные `NodeSpec`
  (`chained` остаётся транзитом разбора → `NodeEntries.main + detours`).

### B. Вход текста (единая точка)

Одна функция `classifySource(text) → {kind, items[]}`: движок (`decode`
→ `source.kind` → `mapper`), массив → элементы; элемент документа
обрезается до узловых массивов (п.6), флаг `extrasDropped`. Используют:
мастер/буфер/файл (`addConnection`…), Save на Source
(`prepareNodeDocumentForSave` → переписать на `classifySource` +
правило тега вида), обновление подписки (вид в `SubscriptionEntry`,
информативно — на поведение подписки не влияет).

Правило тега по виду (одно место, `node_document.dart`):

| Вид | Куда ставится Tag |
|---|---|
| `singbox` | `tag` узла; в документе — переписать `detour` ссылки на старый тег |
| `xray` | `tag` outbound'а; в документе — переписать `sockopt.dialerProxy`, `routing.rules[].outboundTag`, `balancers[].selector` на старый тег |
| `uri` | фрагмент `#…` (как сейчас, `rawWithName`) |
| `wg_ini` | поле записи `nameHint` (§456) |

### C. Потребители — ветвление по виду, без нюха

- `verbatimBodyOf`: условие `record.kind == singbox` (вместо
  `isAuthoredNodeSource(raw)`); Д-1-комментарий снимается.
- Импорт: ветка `mapper == 'singbox'`/`bareBodyTextOf` снимается, идёт через
  `classifySource`.
- `isJsonSourceText`/`originKindOf` в Save снимаются — Save берёт вид из
  `classifySource` нового текста.
- Бэкап/LX Backup, `restore_backup`, `lx_backup.dart`: `kind` пишется и
  читается как есть; дедуп §9: `singbox`/`xray` — канонический JSON,
  `uri`/`wg_ini` — как сейчас.
- `legacy_form_v0`: `bareNodeSourceOf` → миграция п.7.

### D. UI

- Строка сервера в Servers: `tag · N nodes` при N > 1 — по образцу строки
  цепочки хопов (ближайший аналог, решение владельца).
- Экран узла, вкладка Settings: блок «Nodes in this source» — узлы
  документа **аккордеоном** (свёрнуты, заголовок = тег; раскрытый —
  поле Tag узла); настройки записи ниже. Вкладка JSON — **одна**: при
  N > 1 показывает группу массивом тел (`[ … ]`), при N = 1 — тело, как
  сейчас. Source — текст записи целиком.
- Сообщение при обрезке документа: «Only the nodes are saved. The rest of
  the input is not kept.» (ключ словаря по `docs/l10n.md`).

### E. Контракт (сессия лаунчера, синхронно)

- `BACKUP.md` §2: `origin.kind` ∈ `singbox | xray | uri | wg_ini`
  (было `uri | wg_ini | json`); чтение `json` — как «определить движком,
  не разобралось → singbox»; §9 дедуп — по виду.
- `PARSING_PRINCIPLES.md` §11 — переписать: источник своего узла хранится
  в своём диалекте, вид — поле записи; формы ввода — массивы (режутся) и
  документы (обрезаются до узлов); правило дословного тела (§455) —
  по `kind == singbox`.
- `schema/backup.schema.json`: enum `origin.kind`.
- `GLOSSARY.md` Origin.
- Запрос — `TASKS_LXBOX.md` (следующий §), ответ лаунчера — версия
  1.1.165; синк копии `app/contract` после ответа.

## Риски и границы

- Переименование узла в документе переписывает ссылки только **внутри
  этого текста**; ссылки из других записей (личный detour члена папки) —
  через `NodeLink`, как сейчас.
- Документ sing-box с `endpoints` + `outbounds` — оба массива остаются.
- TLS-политика на цепочке: не меняется этой задачей; уточнение — при
  реализации, отдельным пунктом проверки.
- Старые версии приложения/лаунчера бэкап с новым `kind` читать не
  обязаны (решение п.8).
- Подписки: поведение не меняется, вид — информативное поле.

## Проверка

1. #209: Xray outbound → смена тега на Source → Saved; текст остался Xray,
   `origin.kind: xray`; конфиг собран, ядро приняло.
2. Xray-конфиг с `dialerProxy` → одна запись, два узла (владелец + звено);
   главный экран: звено скрыто фильтром по умолчанию, «Show only detour
   servers» показывает; карточка `tag · 2 nodes`; переименование владельца
   не ломает `dialerProxy`.
3. Xray-конфиг с `routing` → сохраняется без `routing`, одно сообщение.
4. В Source Xray-узла вставлен sing-box outbound → Saved, `kind: singbox`,
   дословное тело в конфиге.
5. Массив из 3 outbound'ов в мастере → 3 записи.
6. Старый бэкап с `json` (sing-box и Xray тела, битый JSON) → после чтения
   `singbox`/`xray`/`singbox`; узлы те же, что до миграции (golden).
7. `verbatim_body`: Xray-запись никогда не уходит дословно.
8. Тесты: `node_document_test`, `source_record` golden, `verbatim_body`,
   backup golden; прогон — CI.
