# 448 — Контракт нижнего отступа: исключение для шторок освобождает файл целиком

| Поле | Значение |
|------|----------|
| Статус | Открыта |
| Дата | 2026-09-15 |
| Норма | [§429](429-bottom-inset-system-navigation.md) — вертикальный скроллер с явным `padding:` обязан прибавлять отступ под системную панель навигации |
| Связанные | `app/test/contract/bottom_inset_contract_test.dart`, `app/lib/widgets/safe_bottom.dart`, `app/lib/widgets/app_bottom_sheet.dart` |
| Причина заведения | Найдено при разборе рекомендации Play «Отображение от края до края» для 2.24.0 (SDK 35+). Живого дефекта нет, закрывается дыра в защите |

## Что не так

`bottom_inset_contract_test.dart` освобождает от проверки содержимое шторок:
оно рендерится внутри `showAppBottomSheet`, который уже оборачивает контент в
`SafeArea(top: false)`, и второй отступ дал бы двойной зазор.

Признак шторки считается один раз на весь файл (строка 28):

```dart
final isSheetFile = lines.any((l) => l.contains('showAppBottomSheet'));
```

и затем гасит проверку для **любого** скроллера этого файла (строка 37).
Достаточно одного упоминания `showAppBottomSheet` где угодно в файле, чтобы
перестали проверяться и те скроллеры, которые к шторке отношения не имеют.

## Кого задевает

Из 24 файлов с `showAppBottomSheet` два содержат и шторку, и полноценный экран
со своим `Scaffold` — их экранные списки не лежат под `SafeArea` шторки и
отступ им нужен, но тест их не смотрит:

| Файл | Экранный скроллер | Отступ сейчас |
|---|---|---|
| `lib/screens/chain_edit_screen.dart` | `ListView` :374 | `MediaQuery.of(context).padding.bottom + 32` :376 — верно, руками |
| `lib/screens/folder_detail_screen.dart` | `ListView.builder` :1188, `ReorderableListView.builder` :1199 | `MediaQuery.of(context).padding.bottom + 24` :1191, :1202 — верно, руками |

`ReorderableListView.builder` в `chain_edit_screen.dart` :497 — `shrinkWrap`
внутри внешнего скроллера, нижний край не его, отступ не нужен.

То есть на 15.09.2026 оба файла написаны правильно, но правильность эту ничто
не стережёт: новый список с литеральным `padding:` без отступа пройдёт тест
молча. Это ровно тот дефект, ради которого §429 и делалась (жалоба с 4PDA про
уехавшую под панель кнопку Save).

## Что сделать

Считать признак шторки не на файл, а на конкретный скроллер — освобождать
только те, что лежат внутри builder'а шторки. После правки оба файла выше
должны проходить (отступ у них уже есть), остальные 22 — не начать падать.

## Проверка

- `flutter test test/contract/bottom_inset_contract_test.dart` — зелёный на
  текущем дереве (правка не должна ловить ложных нарушителей).
- Временно убрать `.withSafeBottom` / `padding.bottom` у экранного скроллера в
  `chain_edit_screen.dart` — тест обязан упасть. Вернуть.
- Содержимое любой шторки отступа по-прежнему не требует — двойного зазора нет.

Рекомендация Play неактуальна: у приложения `targetSdk = 36`, edge-to-edge
принудительно включён и обработан §429. Проверено на AVD `LxBox_A15` (API 35,
