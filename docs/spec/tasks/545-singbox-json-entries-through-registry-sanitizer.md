## Проблема

Узел из sing-box JSON строится `parseSingboxEntry` прямо по сырой карте,
мимо санитайзера реестра (`RegistrySanitizer`). Ссылки идут через
санитайзер (`mappers/uri_pipeline.dart`), JSON нет. Поэтому модель
JSON-узла может нести комбинацию полей, которую реестр запрещает, и
связи полей судил не только реестр: в `emitVless`
(`app/lib/models/node_spec_emit.dart`) жила рукописная «страховочная
сетка» §115/§544 — `flow` при транспорте гасится, кроме узлов с VLESS
Encryption. Это копия правила `vless.flow.conflicts` с
`unless_set: [encryption]` (контракт 1.1.55). Копии расходятся: до §544
сетка снимала Vision и у узлов с encryption.

## Диагностика

Боевых вызовов `parseSingboxEntry` мимо санитайзера два, оба в
`app/lib/services/parser/singbox_config.dart`:

| Место | Что строит | Куда уходит тело |
|---|---|---|
| `_parseOne` (узлы конфига) | узел подписки, редактора JSON, Smart-Paste | подписка — `emit()` модели; `UserServer`/член папки с источником `singbox_*` — дословный объект (§455, `verbatimBodyOf`) |
| `_buildChain` (звенья detour) | хоп родной цепочки | всегда `emit()` модели |

Редактор JSON и Smart-Paste одиночного entry отдельного вызова не имеют:
документ идёт `parseAll` → `_parseJson` → `parseSingboxConfigs` → `_parseOne`.

Где сетка реально что-то решала: узлы sing-box-подписки и звенья detour
(тело из `emit()`). У дословного тела (§455) модель в ядро не идёт, но
по ней считаются подпись дедупа (§404), identity, показ полей и `toUri()`.

## Решение

Оба места строят модель по **очищенной** карте:
`RegistrySanitizer.sanitize(копия entry, source: BodySource.singbox,
applyCoreGates: false)` → `parseSingboxEntry(очищенная, rawSource: объект
как пришёл)`.

Границы, чтобы не нарушить §455/§473/§477:

1. **`rawSource` — исходный объект**, не очищенная карта. Дословное тело
   (§455), бэкап и повторный разбор видят то, что прислал автор.
2. **Вход `singbox`** — как у прохода по дословной карте
   (`annotateFromRawBody`) и у гарда сборки для дословного тела. На этом
   входе `max_when.except_sources` не подменяет написанный `mtu` (§473).
3. **Коды не собираются.** Их ставит `annotateFromRawBody` по той же карте
   с тем же входом; второй производитель дал бы дубли с другим порядком.
4. **Тела нет (`res.body == null`) — модель по сырой карте**, как раньше.
   Явный `drop_node` снимает узел `parseAll` по вердикту
   `annotateFromRawBody` (§477); недостающее обязательное поле узел при
   разборе не снимает — это решение §477, здесь не меняется.
5. **Реестр не загружен — сырая карта**, как раньше.
6. Санитайзер переписывает вложенные карты, поэтому ему даётся глубокая
   копия: исходный `entry` нужен дальше (`byTag`, резолв detour, группы).

После этого сетка в `emitVless` снимается: `flow` пишется, если в модели
стоит `xtls-rprx-vision`. Связь flow↔transport решает только реестр.

- `test/parser/json_parsers_test.dart`: тест сетки переписан на путь
  через санитайзер (`parseSingboxConfigs`): vision + ws без encryption →

## Риски и edge cases

- Модель узла с мусорным полем теперь строится без него, поэтому у такого
  узла меняются emit и подпись дедупа. Отметки выключения, завязанные на
  хеш, у него могут не совпасть (§529, «Риски»). Эталон публичных подписок
  не сдвинулся, значит у реальных подписок разница не проявилась.

## Нерешённое / follow-up

§529 п. 3(а) закрыт частично. Санитайзер на JSON-входе теперь есть; из
группы S красными остаются `singbox/socks_version_invalid`,
`list_non_string_items` и `outbound_array_tls_fields`, плюс
`socks_version_absent`. Им нужны свои правки из §529: `toString()` у
`alpn`/`server_ports`, явные `false` в TLS (после ответа лаунчера) и
отказ от материализации дефолтного `version`.
