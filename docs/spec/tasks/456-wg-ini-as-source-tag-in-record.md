## Проблема

Узел из `.conf` хранил источником не файл, а синтетическую ссылку
`wg://…#имя-файла`, в которую INI переводился ради тега (§243). Источник
переставал быть «тем, что пришло»: комментарии и порядок файла терялись,
вид записи был `uri` вместо `wg_ini`, лаунчер тот же файл хранит как INI.
Ради этого же существовал `memberRawFor` — функция, которая при добавлении в
папку решала, что записать члену, и при пустом источнике пересобирала текст
через `toUri()`. После §454 источник есть у всех узлов, функция лишняя.

## Решение

### 1. Источник WireGuard из INI — сам INI

`parseWireguardIni(config, {nameHint})` даёт узлу `rawSource = config`, байт в
байт. Синтетический `wg://` остаётся внутренним шагом парсера (`_iniToUri` →
`parseWireguardUri`), наружу не выходит. Поле `WireguardSpec.rawIni`
удалено — оно дублировало бы источник.

`vpn://` (Amnezia, §110): каждый узел контейнера получает источником свой
INI-текст (так уже делает `AmneziaConfig` → `parseWireguardIni`); общая
ссылка `vpn://` остаётся `origin.raw` записи-контейнера.

### 2. Имя узла из INI

INI тега не несёт. Начальное имя при разборе, по убыванию силы:

1. первый комментарий сразу под `[Peer]` без `=` — Proton пишет туда имя
   сервера (`# CH-FREE#11`); строки вида `# Bouncing = 0` в `[Interface]`
   не годятся;
2. `nameHint` — имя файла при импорте (§243), тег записи при чтении
   хранения (§3), поле Tag редактора при Save;
3. `WireGuard`.

### 3. Тег — поле записи

Запись хранения (`server`, член папки) и раньше писала `tag` (контракт 1.0).
Правило чтения «текст побеждает, расхождение — заметка» остаётся для
`uri`/`json`, где тег лежит в тексте. Для `origin.kind: wg_ini` тег записи
**применяется**: узел разбирается с `nameHint = tag`, заметка не пишется.

В памяти тег живёт в узле (как у всех). Чтобы он пережил перечитывание
текста, у `FolderMember` появляется `nameHint` (участвует в `==`/`hashCode`:
тот же INI под другим именем — другая запись), а `updateConnectionAt` /
`updateMemberAt` принимают `nameHint`. Экран узла при Save INI-источника
передаёт поле Tag.

Контракт не меняется: `tag` у записи был, `origin.kind: wg_ini` был; лаунчер
тег в дедупе не сравнивает, INI сравнивает текстом.

### 4. `memberRawFor` удалён

Член папки получает `raw: n.rawSource` и `nameHint` (тег узла, если источник
INI). Фолбэк имени файла (`nameFallback`) остаётся только для ссылок без
своего имени (`rawWithName` во фрагмент); INI и JSON несут имя сами: INI —
через `nameHint`, JSON — в теле.

Точки: `addMembersToFolder`, `addUrlSnapshotToFolder`, перенос одиночного
сервера в папку. Одиночный импорт `.conf`: `rawBody` = INI, тег — в узле и в
записи.

### 4a. Побочные находки (всплыли на тестах)

- **Авто-эмодзи (§090 G2b) у INI-узла.** `_autoEmoji` дописывал эмодзи в
  текст источника (фрагмент ссылки / поле `tag` JSON). У INI тега в тексте
  нет, дописать некуда — эмодзи молча терялось. Теперь на ветке `.conf`
  эмодзи ставится прямо в `tag` и `label` узла; тег — поле записи, поэтому
  переживает рестарт. `label` нужен отдельно: список серверов показывает
  его (`SubscriptionEntry.displayName` предпочитает `label` тегу).
- **`TailscaleSpec` без `rawSource`.** Конструктор зашивал `rawSource: ''`,
  и `parseSingboxEntry` единственным из всех веток не передавал `src`.
  Пока член папки собирался через `memberRawFor` (текст пересобирался
  `toUri()`), дыра была не видна; с `raw: n.rawSource` член Tailscale стал
  пустым и узел терялся. Узел теперь несёт свой объект outbound'а, как все
  остальные типы из JSON.

### 5. Старые записи

Записи с `wg://…#имя` остаются `uri` и читаются как раньше. Миграции нет:
исходного INI у них уже не было.

## Проверка

- `ini_parser_test`: `rawSource` = INI байт в байт; имя из `[Peer]`-комментария
  сильнее `nameHint`; без комментария — `nameHint`; без обоих — `WireGuard`;
  round-trip `parseWireguardIni(spec.rawSource, nameHint: tag)` даёт тот же
  узел и тег.
- `record_codec_sources_test`: запись `wg_ini` с `tag` → узел с этим тегом,
  заметки нет; `uri` — прежнее «текст побеждает».
- Папка: `addMembersToFolder(INI, nameFallback: 'file')` → член `raw` = INI,
  тег `file`, переживает запись/чтение; `vpn://` с двумя контейнерами →
  два члена со своими INI.
- `flutter analyze`, `flutter test`, l10n-чекеры.
- Устройство (PENDING): импорт Proton `.conf` → тег `CH-FREE#11`, Source
  показывает файл с комментариями; переименование через Tag → после
  рестарта имя на месте.
