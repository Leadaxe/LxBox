# §310 — Xray JSON array: импортировать все ноды элемента, а не только «main»

**Тип:** feature (смена задокументированного контракта парсера) · **Статус:** реализовано (2026-07-26, device-pending) · **Размер:** M · **Область:** `parseXrayOutbound` × §018 detour-chain × `PROTOCOLS.md` §11

Подписка в формате Xray JSON array отдаёт в одном элементе массива несколько равноправных
VLESS-серверов (основной + резервные). Импортировался **только один** — остальные молча
терялись, подписка приезжала без резерва.

## Репро (боевая панель Remnawave)

Подписка отдаёт массив из 2 элементов (`remarks`: `Main Server`, `Ru direct`), в каждом —
3 равноправных VLESS-outbound'а (`proxy`, `proxy-2`, `proxy-3`) на разные хосты:

```
node1.infomir.net:443   node3.infomir.net:443   node2n.infomir.net:443
```

Все три ноды живые (проверено прогоном трафика через `sing-box` с `-tags with_utls`:
каждая отдаёт наружу свой IP). После импорта в списке — **2 ноды вместо 6**, обе `node1`.
Ляжет `node1` — переключаться не на что.

## Причина

`parseXrayOutbound` по контракту сворачивал элемент в одну ноду —
[`json_parsers.dart:11`](../../../app/lib/services/parser/json_parsers.dart): «одно вхождение —
один узел». Из всех VLESS выбирался «main» (приоритет: `sockopt.dialerProxy` → тег `proxy` →
первый), остальные отбрасывались.

Это не баг, а осознанное решение под **detour-цепочки** ([`PROTOCOLS.md` §11](../../PROTOCOLS.md)):
дополнительные outbound'ы трактовались как кандидаты в jump-прокси, а не как альтернативные
серверы. Для подписок без `dialerProxy` такая трактовка теряет данные.

## Решение

`parseXrayOutbound` (одна нода) → `parseXrayElement` (список нод). Правила:

1. Собрать все VLESS-outbound'ы элемента.
2. **Исключить те, на кого ссылается `sockopt.dialerProxy`** — они уже приезжают как detour
   (`⚙ <tag>`) и не должны задваиваться самостоятельной нодой.
3. Каждый оставшийся → своя нода. Detour-цепочка (`dialerProxy`) сохраняется **только** у
   своего владельца — контракт §018 не меняется.
4. Порядок сохраняется: main-приоритет (`dialerProxy` → `proxy` → первый) даёт **первую**
   ноду списка, чтобы у существующих подписок первая нода осталась той же.

### Именование

`tagFromLabel` берёт `remarks` элемента → все ноды элемента получили бы один тег.
Для корректности конфига это не фатально (`EmitContext.allocateTag` разведёт суффиксом
`-1`/`-2` на build'е), но в UI получились бы три неразличимые строки `Main Server`.

Поэтому имя разводится **на парсинге**: первая нода — `remarks` как есть, последующие —
`remarks` + ` ` + тег outbound'а (`Main Server proxy-2`). Если тега нет — индекс (` 2`, ` 3`),
как в §243/`_indexedHint`. Одна нода в элементе → имя ровно как раньше (обратная совместимость).

## Что НЕ делается

- **Дедуп-guard в валидаторе не нужен** — уникальность тегов уже держит
  [`allocateTag`](../../../app/lib/services/builder/build_config.dart) (суффикс `-N`, тест
  `build_config_test.dart:166`). Отдельные дыры (`теги каналов`/template-outbounds мимо
  `_taken`, fallback §084 M5) к этой таске не относятся.
- SOCKS-outbound'ы самостоятельными нодами не становятся — остаются detour-only (§018).

## Приёмка

- [ ] Элемент с 3 равноправными VLESS → 3 ноды, имена различимы.
- [ ] Элемент с `dialerProxy` → 1 нода с detour (dialer-цель НЕ отдельной нодой) — регрессия §018.
- [ ] Элемент с 1 VLESS → 1 нода, имя и тег как до таски.
- [ ] Существующие тесты `json_parsers_test.dart` зелёные.
- [ ] Device: подписка с мультинодовым элементом импортируется, VPN стартует, ноды переключаются.
