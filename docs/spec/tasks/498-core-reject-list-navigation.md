# §498 — лист страховки: переход к узлу и жизнь плашки

| | |
|---|---|
| **Статус** | Реализовано (вкладка §501; дефект навигации выключенного узла — §503) |
| **Дата** | 2026-09-19 |
| **Источник** | решение владельца 19.09.2026: тап по строке листа «N servers disabled» должен открывать детали узла; плашка уходит после Stop |
| **Связанные** | фича 478, §497 (вкладка Notifications), §479 |

## Что было

После автовыключения узлов страховкой (фича 478) на главном экране
показывалась плашка «N servers disabled»; кнопка Show открывала нижний лист
с тем же заголовком, тегом узла, причиной от ядра и шевроном «›». **Тап по
строке открывал вторую шторку** с одним уведомлением `core_rejected` через
`showCoreRejectNodeWarnings` — не экран деталей узла. Заголовок плашки и листа
для одного узла был «1 servers disabled» (множественное число без singular
формы в EN). Плашка оставалась на экране после Stop/Disconnected, хотя
сообщает о событии прошедшего старта, а не о постоянном состоянии.

## Что сделано

1. **Навигация из листа.** Тап по активной строке закрывает лист и открывает
   экран деталей **этого** узла на вкладке Diagnostics (секция уведомлений
   сверху) — тот же путь, что тап по узлу в списке подписки
   (`NodeInspectScreen`) или настройки одиночного/члена папки
   (`NodeSettingsScreen`). **Дефект §503:** поиск только по `lastEmittedTagMap`
   ломал переход для узла, исключённого из текущей сборки (одиночный сервер).
   Исправлено в §503: идентичность в вердикте + поиск в хранилище. Хоп цепочки
   ведёт к владельцу. Удалённый узел — строка неактивна, без шеврона.
2. **Начальная вкладка.** `NodeInspectScreen` — `initialTab:
   NodeInspectTab.diagnostics`; `NodeSettingsScreen` — `diagnosticsTabIndex`
   (§501; раньше — вкладка Notifications).
3. **Plural заголовка.** `coreRejectBannerTitle`: «1 server disabled» /
   «%d servers disabled» через `getLocalText.s` / `.plural`; ключи в ru/zh.
4. **Жизнь плашки.** Скрывается при: ×, Stop/Disconnected (`HomeController`),
   следующем Start (`CoreRejectState.beginRun`), перезапуске приложения
   (как раньше). Вердикты узлов не снимаются. Debug API `/core_reject/banner`
   после Stop отдаёт `visible: false`.

## Критерии приёмки

- Тап по строке листа → детали узла на вкладке Diagnostics (уведомления сверху).
- Удалённый узел в листе — неактивная строка, без шеврона.
- Заголовок плашки и листа: «1 server disabled» / «2 servers disabled» (EN).
- После `started_with_disabled` плашка видна → Disconnected → плашки нет,
  список `disabled` прогона на месте.
- Виджет-тесты листа; l10n-чекеры `--strict`. Спека 478, CHANGELOG, debug API.
