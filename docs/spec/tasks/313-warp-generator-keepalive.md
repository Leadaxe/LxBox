# 313 — Persistent keepalive для узлов WARP-генератора

Продолжение [§304](304-warp-persistent-keepalive.md) (ручная регистрация). Сама
§304 не переписывается — здесь пересматривается только её граница «генератор не
затрагивается».

## Проблема

Узлы, созданные генератором (§284 «WARP GENERATOR»,
`app/lib/services/warp/scan/scan_node_builder.dart`), уходят в ядро **без**
`persistent_keepalive_interval`. Ядро sing-box-lx дефолт не подставляет:
`transport/wireguard/endpoint.go:524` пишет строку в IPC-конфиг устройства
только при `keepalive > 0`.

Пир без keepalive при простое не шлёт ничего →

1. NAT-маппинг оператора/роутера закрывается за 30–120с;
2. входящий трафик от WARP не доходит → пинг растёт до `err`;
3. дальше по таймерам wireguard-go: `RekeyAfterTime=120s`,
   `RejectAfterTime=180s`, обнуление ключей на `RejectAfterTime*3=540s`.

Полевой репорт (4PDA, `dewch`, #1289/#1298): примерно через час на мобильном
интернете все узлы генератора деградируют по пингу и перестают подключаться,
реконнект лечит. Сторонний клиент на том же канале в то же время живёт.

Точка бага — `scan_node_builder.dart`, AWG-ветка звала
`toWireguardConf(includeReserved: false)` без keepalive. Асимметрия внутри
одного билдера: MASQUE-ветка `_masqueUri` keepalive из аккаунта тянула
(`keepAlive: acc.keepAlive`).

## Почему §304 вывела генератор из скопа и почему это пересмотрено

§304 («Границы») формулировала так: «Генератор (§284 WARP GENERATOR,
`scan_node_builder.dart`) не затрагивается — он вызывает `toWireguardConf` без
нового параметра, дефолт параметра `null` → keepalive не добавляется».

Это решение было **про сигнатуру, а не про живучесть узлов**: §304 добавляла
новый опциональный параметр и фиксировала, что дефолт `null` сохраняет прежнее
поведение всех существующих вызовов. Генератор попал под «прежнее поведение»
автоматически, как побочный эффект выбора дефолта, — вопрос «а нужен ли
keepalive узлам генератора» отдельно не разбирался.

Пересмотр: причина деградации, описанная в §304 (NAT-маппинг + таймеры WG), к
транспорту генератора относится ровно так же — это тот же WireGuard/UDP поверх
той же регистрации. «Поведение по умолчанию не меняем» оказалось неверным
критерием: у генератора нет UI, где пользователь мог бы проставить keepalive
сам, поэтому «дефолт = как раньше» означало «неисправимо без keepalive».

## Решение

Значение keepalive живёт в файле эндпоинтов `app/assets/warp_endpoints.json`, в
секции `wireguard` — там же, где остальные параметры генерации (CIDR, порты,
SNI, uTLS-fp). Тогда оно правится через JSON-override окна эксперимента (§305)
без пересборки APK, если 25 окажется неоптимальным для мобильных операторов.

Константой в коде не делаем именно поэтому: 25 — типовое значение WARP, но
проверять его придётся полевым тестом на разных операторах.

## Изменения

### 1. `app/assets/warp_endpoints.json`

В секцию `wireguard` — ключ `keepalive: 25` (рядом с `ports`).

### 2. `ScanPool` (`app/lib/services/warp/scan/scan_pool.dart`)

- Поле `final int wgKeepalive` (дефолт `0`), рядом с `wgPorts`/`wgSniPool`.
- Парс в `fromFullJson` — хелпер `intOr0(wg, 'keepalive')`.

Тип `int` (не `int?`) с дефолтом `0`: `0` уже имеет ровно нужное значение
«keepalive не писать» — гейт `> 0` в `WarpAccount.toWireguardConf` (§304). Второе
состояние (`null` vs `0`) не несло бы смысла: у пула нет «наследования» значения
откуда-то ещё.

Хелпер терпим к входу: нет ключа (старый bundled asset, пользовательский
JSON-override, написанный до этой таски) → `0`; число → `toInt()`; строка
(`"25"` — JSON правит человек руками) → `int.tryParse` → `0` при неудаче. Ни
один вариант не кидает и не роняет генерацию.

На `hasData` keepalive **не влияет**: пригодность пула определяется наличием
источников кандидатов (CIDR + порты), keepalive — тюнинг уже собранного узла.
Пул без keepalive остаётся полностью рабочим.

### 3. `ScanNodeBuilder` (`app/lib/services/warp/scan/scan_node_builder.dart`)

- Конструктор: `ScanNodeBuilder({this.warp, this.masque, this.wgKeepalive = 0})`.
- `_wgUri` → `tuned.toWireguardConf(includeReserved: false, persistentKeepalive: wgKeepalive)`.

Передаём одно число, а не весь `ScanPool`: билдеру от пула больше ничего не
нужно, а зависимость от модели пула сделала бы его тесты тяжелее.

MASQUE-ветка не трогается — у неё свой QUIC-keepalive (`keepAlive`
`masque_account.dart`), это другое поле и другой ключ ядра (та же граница, что
в §304).

### 4. `SubscriptionController.generateWarp` (`subscription_controller.dart`)

`ScanNodeBuilder(warp: warpAcc, masque: masqueAcc, wgKeepalive: pool.wgKeepalive)`
— `pool` там уже есть (`poolOverride ?? WarpEndpointPicker.load()`), так что
JSON-override окна эксперимента автоматически перебивает и keepalive.

## UI-строки

Нет — видимых строк таска не добавляет.

## Ретроактивность (открытый вопрос владельцу)

Узлы, сгенерированные **до** этой таски, keepalive не получат: значение
подставляется в момент сборки URI, а сохранённые узлы — уже готовые URI/спеки.
Новое значение видят только вновь сгенерированные папки.

Варианты и цена:

- **(а) ничего** — пользователь жмёт GENERATE заново, папка «WARP GENERATOR»
  пересоздаётся (`_recreateScanFolder`), все узлы едут с keepalive. Ноль кода,
  ноль риска. Минус: молчаливое требование действия от пользователя.
- **(б) миграция** — пройти по узлам папки генератора и проставить
  `persistentKeepalive`. **Риск: сдвиг `nodeIdentityHash`.** Хеш считается от
  `emit(TemplateVars.empty).map` минус `tag`/`detour` (`node_hash.dart:65`), а
  `persistent_keepalive_interval` в этот map входит (`node_spec_emit.dart:564`).
  Значит правка узла меняет его хеш, и отметки «узел отключён» (§283,
  `disabledHashes`) перестают совпадать: отключённые узлы папки молча
  включатся, а осиротевшие отметки будут висеть до истечения TTL. Корректная
  миграция обязана переносить и `disabledHashes` (старый хеш → новый), то есть
  трогать storage-ключ, за симметрией которого следит §221 (allowlist ↔ export).

**Рекомендация — (а).** Папка генератора по своей природе одноразовая
(GENERATE её пересоздаёт целиком, узлы в ней — лотерейные кандидаты, которые
пользователь и так перетряхивает), а цена (б) — миграция, переписывающая
сохранённые узлы и ключ §283 ради узлов, которые пользователь всё равно
пересоздаст. Вариант (б) не реализован; ждёт решения владельца.

## Тесты

`app/test/warp/scan/scan_pool_test.dart`:
- `keepalive: 25` в JSON → `wgKeepalive == 25`;
- ключа нет → `wgKeepalive == 0`, `hasData` по-прежнему `true`;
- строка `"25"` → `25`; мусор → `0`.

`app/test/warp/scan/scan_node_builder_test.dart`:
- `wgKeepalive: 25` → в URI узла `keepalive=25`, после парса
  `persistent_keepalive_interval` в эмите;
- дефолт (`0`, ключа в пуле нет) → генерация не падает, keepalive в узле нет;
- MASQUE-ветка от `wgKeepalive` не зависит.
