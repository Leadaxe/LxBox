## Проблема

`parseSingboxEntry` читает поля тела вручную, по одному. Поле, которое автор
ветки забыл прочитать, молча исчезает: ни ошибки, ни предупреждения. Эмиттер
написан отдельно и поле писать умеет. Итог — человек вписал поле в
JSON-вкладке, сохранил, и узел ушёл в ядро без него.

За один день так нашлись `encryption` (vless), `plugin`/`plugin_opts`
(shadowsocks), `quic`/`quic_congestion_control` (naive),
`host_key_algorithms` (ssh), `min_idle_session` строкой (anytls), `version`
(socks); тем же классом был #140 (`tls.certificate` у naive). Каждый раз —
случайно, по ходу другой работы.

У лаунчера класса нет: тело идёт картой через реестр, списка читаемых
ключей не существует. У нас он есть, и его полноту никто не стережёт.

## Решение

Тест `app/test/contract/body_fields_roundtrip_test.dart` (реестр — из
зеркала `app/assets/contract`, гейта на `app/contract` не нужно: тест обязан
работать на CI).

Для каждого протокола реестра (`registry/protocols/*.json`, секция `body`),
который приложение поддерживает:

1. Собрать **полное тело**: каждое поле `body.fields` заполнено годным
   значением по его типу и ограничениям (`values` → первое значение; `format`
   → образец формата; `duration`, `listable_string`, `awg_range`,
   `int_array`, bool, int в пределах `min`/`max`; вложенные объекты —
   рекурсивно; общие блоки `tls`, `transport`, `multiplex`, dial-поля — по
   их схемам). Генератор значений — один, в тест-хелпере; негодное для
   генерации выражение реестра роняет тест с названием выражения, а не
   пропускается молча.
2. Взаимоисключающие поля (`conflicts`, `forbidden_for`, `requires`, варианты
   транспорта, `reality` против `ech`) — несколько тел на протокол: по
   одному на каждую несовместимую группу, так чтобы КАЖДОЕ поле побывало
   хотя бы в одном теле. Покрытие проверяется: поле, не попавшее ни в одно
   тело, — падение.
3. Круг: тело → санитайзер по реестру (как в конвейере) →
   `parseSingboxEntry` → `emit()`. Сравнение с телом после санитайзера:
   каждое поле на месте и с тем же значением (с учётом канонизации, которую
   реестр сам объявляет: `normalize`, listable → список, дефолты).
4. **Список немоделируемых** — `kNotModelled`: `«протокол.путь» → причина`.
   Только осознанные случаи (поле десктопное, `extension: desktop`; поле
   приложение выставляет само — `tag`, `detour`, `domain_resolver`; поле
   ядро LxBox не поддерживает). Запись без причины — падение. Запись, ставшая
   лишней (поле уже переживает круг), — падение: список не протухает.
5. То же для **узла `origin.kind: json`** проверять не нужно (он идёт
   дословно, §455) — отметить в докблоке теста, чтобы не искали.

Найденные потери — чинить в `json_parsers.dart`/модели/эмиттере с юнитом на
каждую; если починка меняет identity живых узлов или golden — не чинить,
внести в `kNotModelled` с причиной «ждёт решения владельца» и вынести в
отчёт. Ветки **wireguard и masque не трогать** (их сейчас переводит шаг 7
фичи 472): потери там — в `kNotModelled` с причиной «шаг 7, сверить после»,
списком в отчёт.

## Критерии приёмки

- тест зелёный; подсадка: убрать чтение одного поля в `parseSingboxEntry` —
  тест падает и называет поле (проверить и вернуть);
- каждое поле каждого поддерживаемого протокола покрыто хотя бы одним телом;
- `kNotModelled` — с причинами, без лишних записей;
- identity-фикстуры схем на конвейере и golden — без изменений;
- `flutter analyze` всего проекта; тесты затронутых каталогов; CI зелёный;
- CHANGELOG (Fixed — по каждой найденной потере, видимой пользователю),
  GUARDS.md (новый страж), ARCHITECTURE.md (абзац: почему список читаемых
  ключей есть у нас и чем он стережётся), спека 472 (ссылка из шага 9).

## Как сделано

### Устройство генератора

`app/test/contract/body_field_generator.dart` — значения выводятся ИЗ СХЕМЫ,
рукописных тел нет вовсе. Причина прямая: рукописное тело стареет молча, и
поле, приехавшее бампом контракта, в него никто не впишет — страж пропустил
бы ровно тот класс, ради которого заведён.

Незнакомое выражение реестра роняет генерацию (`UnsupportedExpression` с
именем выражения и путём поля). Санитайзер на незнакомое выражение реагирует
наоборот — оставляет значение как есть (24.1: реестр впереди кода это рабочее
состояние). Противоречия нет: у прода задача пережить бамп контракта, у
стража — заметить его.

Одним телом схему не покрыть, поэтому тела строятся по **семи осям**
совместимости; перемножать их не нужно — поле обязано побывать хотя бы в одном
теле, а не в каждом сочетании:

| Ось | Что разводит |
|---|---|
| 1. транспорт | шесть вариантов `transport.type`, поля у них разные |
| 2. `reality` ↔ `ech` | взаимный `conflicts` у обоих флагов |
| 3. без транспорта | поля, конфликтующие с `transport` (`vless.flow`) |
| 4. `requires` + `equals` | `obfs.min_packet_size` жив только при `obfs.type = gecko` |
| 5. эксклюзивные поля TLS | `disable_sni`, `spoof`, `certificate_public_key_sha256` — каждому тело, где уступает сосед, а не оно |
| 6. эксклюзивные поля корня | `i1`/`i2` (уступают `id`/`ip`/`ib`), `listen_port` |
| 7. эксклюзивные поля вложенных объектов | `xmux.max_concurrency` ↔ `max_connections` |

Получается **8–14 тел на протокол**, 13 протоколов. `chain` и `group` не
участвуют (тела узла у них нет), `tailscale` тоже (endpoint без сервера, §435).

Покрытие считается той же рекурсией, что и генерация, — так список ожидаемого
и список построенного заведомо считаются одним правилом. Поле, запрещённое
самим реестром (`forbidden_for`/`allowed_for` — у naive это почти весь блок
TLS, у QUIC-схем `utls`/`reality`), из требования покрытия исключается: его
отсутствие и есть исполнение правила. Поле с атрибутом `skip`
(`hysteria2.realm` — «структуру опишем вместе с поддержкой realm в лаунчере»)
не строится вовсе: значения для него не из чего взять.

### Что нашлось

Первый прогон до единой починки дал **110 различных путей-потерь**. После
разбора они делятся так:

**Починено (7 полей, все видны пользователю):**

| Поле | Что было |
|---|---|
| `tls.engine` | реестр числит полем `OutboundTLSOptions`, эмиттер писать умел, разбор не читал |
| `tls.spoof` | то же |
| `tls.spoof_method` | то же |
| `tls.handshake_timeout` | то же |
| `ws.headers` (кроме `Host`) | эмиттер сливал `Host` с картой и писал обе, разбор брал из карты только `Host` |
| `httpupgrade.headers` | поля не было в модели вовсе, хотя реестр его числит |
| `http.headers` (транспорт) | `HttpTransport.headers` существовало и эмитилось, ветка JSON его не заполняла |

Первые четыре — одной правкой: ключи дописаны в `kTlsPassthroughKeys` и в
`_kTlsEmitOrder` на места структуры ядра (`engine` сразу за `enabled`,
`spoof`/`spoof_method` за `record_fragment`, `handshake_timeout` перед `ech` —
туда, где его и так называл комментарий §459). Механизм сквозных ключей уже
был (§454, #140), поэтому починка свелась к списку.

**Немоделируемое осознанно (`kNotModelled`, с причиной у каждой записи).**
Крупных классов пять, и все они — НЕ потеря круга, а неподдержанная
возможность ядра: поля нет ни в модели, ни в эмиттере, то есть терять нечего.

- dial-поля ядра, кроме `tcp_keep_alive` (§453): `bind_interface`,
  `inet4/6_bind_address`, `connect_timeout`, `tcp_fast_open`, `udp_fragment`,
  `network_strategy`, `network_type`, `fallback_network_type`,
  `fallback_delay`, `disable_tcp_keep_alive`, `network`;
- мультиплекс целиком (`multiplex.*`) — ни модели, ни эмиссии;
- UDP-over-TCP (`udp_over_tcp.*`) — то же;
- тюнинг QUIC у hysteria2/tuic/naive: `*_receive_window`,
  `max_concurrent_streams`, `disable_path_mtu_discovery`,
  `initial_packet_size`, `keep_alive_period`, `idle_timeout`, `bbr_profile`,
  `brutal_debug`, `disable_chrome_parrot`, `hop_interval*`,
  `insecure_concurrency`, `udp_over_stream`;
- поля транспортов, которых нет в `TransportSpec`: `idle_timeout`,
  `ping_timeout`, `permit_without_stream`, `method`, `session_table`,
  `session_length`, `sc_max_concurrent_posts`, `server_max_header_bytes`, и
  сам вариант `quic` (его в `TransportSpec` нет, оттого пропадает и
  дискриминатор `transport.type`).

Точечно: `vmess.packet_encoding` (поле есть только у `VlessSpec`, эмиттер
vmess его не пишет), `vmess.authenticated_length`, `vmess.global_padding`,
`anytls.client_metadata`, `ssh.client_version`/`cipher`/`kex_algorithm`/`mac`/
`private_key_path`, `tls.kernel_tx`/`kernel_rx` (kTLS ядро LxBox на Android не
строит), `ssh.private_key` (реестр зовёт его `listable_string`, модель держит
строку — значение не теряется, расходится форма).

Отдельная группа — `tcp_keep_alive`/`tcp_keep_alive_interval` у hysteria2,
tuic, wireguard и masque: §453 завёл их только НОСИТЕЛЯМ TCP, конструкторы
этих четырёх их не принимают вовсе. Соединение у них QUIC/UDP, TCP-таймеров
там нет — поле не относится к узлу, а не теряется.

**Шаг 7 фичи 472 (не трогали, ветки за соседним заходом).** wireguard:
`system`, `name`, `listen_port`, `workers`, `udp_timeout`, `udp_mapping`,
`udp_filtering`, `udp_nat_max`. masque: весь блок `tls` (у `MasqueSpec` полей
TLS нет, кроме `sni`/`disable_sni`), `network_list`, `uri`, `ipv6`, плоские
legacy-ключи `sni`/`skip_cert_verify`/`network` (их «не принимаем» —
директива оператора, §393). Записи помечены «шаг 7 фичи 472, сверить после»:
что шаг 7 починит, из списка уйдёт само — лишняя запись роняет тест.

**Не потери, а канонизация.** Ключи WireGuard (`private_key`,
`peers[].public_key`, `peers[].pre_shared_key`, `header_protection_key`)
приводятся к std-base64 с паддингом (§106, D-030): те же 32 байта в другом
написании. Круг сравнивает строки и потому расхождение видит; записаны с этой
причиной.

**Ждёт владельца:** таких нет. Ни одна из найденных потерь не требовала
решения, которое сдвинуло бы identity живых узлов или golden.

`socks.version` в списке с причиной «§475» — отдельная задача, по заданию не
чинилась.

### Identity и golden

Не сдвинулись, и по построению не могли: `legacyNodeIdentityHash` считает
хеш от эмиссии, а все семь починок добавляют ключ ТОЛЬКО когда исходное тело
его несёт. У существующих узлов таких ключей нет — эмиссия прежняя байт в
байт. Проверено прогоном: identity-фикстуры одиннадцати схем на конвейере
(`test/fixtures/**/pipeline_identity_before.json`) — 0 расхождений, golden
без перегенерации, `lx_backup` не трогали (сквозные ключи TLS едут внутри
`tls.passthrough`, который в allowlist бэкапа уже был).

### Подсадка (критерий приёмки)

В `parseSingboxEntry` временно заменено `plugin: entry['plugin']…` на
`plugin: ''`. Тест упал и назвал поле:

```
'plugin: было sample, стало <нет> (тело base)'
'plugin_opts: было sample, стало <нет> (тело base)'
```

Чтение возвращено, тест снова зелёный.

### Прогон без копии контракта

`app/contract` временно убран — страж отработал ПОЛНОСТЬЮ (28 тестов, ни
одного skip): он читает зеркало `app/assets/contract`, которое лежит в git.
Гейта «контракт не синхронизирован» у него нет намеренно — пропущенный страж
не стережёт. После возврата `check_contract_lock.dart` зелёный.
