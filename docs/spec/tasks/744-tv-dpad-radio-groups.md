## Problem

На Android TV в App Settings → Appearance выбор темы (System / Light /
Dark) с пульта:

1. тема применяется при простом перемещении по пунктам — пройти «мимо»
   нельзя, приходится выбирать последний пункт;
2. из списка нельзя выйти пультом: вверх/вниз крутятся внутри, наружу —
   только мышью или кнопкой «Назад»;
3. после перехода мышью на другую вкладку (например, Subscriptions) фокус
   остаётся на списке тем, и стрелки продолжают менять тему, хотя вкладки
   Appearance на экране уже нет.

Автор просит «Apply» или иной способ подтверждения.

## Diagnosis

**П. 1–2.** Выбор темы — стандартный `RadioGroup` Flutter
(`appearance_tab.dart`). В Flutter 3.47 `RadioGroup`
(`widgets/radio_group.dart`, `_radioGroupShortcuts`) вешает на ←/→/↑/↓
`_selectNextRadio`/`_selectPreviousRadio`: стрелка сразу **выбирает**
соседний пункт (`onChanged`) и переводит на него фокус, на краю — по кругу
(`nextFocus ??= nodesInEffectiveOrder.first`). Выход из группы задуман
только по Tab (`_SkipUnselectedRadioPolicy`), а Tab у пульта нет. Это не
одна тема: прямой `RadioGroup<` в `app/lib` стоял в 14 местах (12 файлов) —
язык на той же вкладке, фоновый режим, режим detour подписки (2), меню
записи подписки, предпросмотр импорта, тип правила, DNS-ответ правила,
форма auto-группы, OpenConnect, политика TLS, masquerade, Tailscale. В
предпросмотре импорта (§622, `import_preview_dialog.dart`) это уже
обходили своим `Shortcuts` поверх `RadioGroup` — локально.

**П. 3.** Страница вкладки, на которой стоит фокус пульта, держит себя
живой: подсветка фокуса у `InkWell` (`RadioListTile`) — это keep-alive в
`PageView` `TabBarView`. Клик мышью по `TabBar` фокус не забирает, и после
смены вкладки он остаётся на скрытой странице Appearance; стрелки и OK
продолжают работать там. Касается любого `TabBarView` в приложении (16
экранов), не только радиогрупп: OK на скрытой вкладке так же щёлкнул бы
переключатель.

Отвергнуто:

- кнопка «Apply» (просьба автора) — лишний шаг на телефоне и в мыши;
  на TV после п. 2 выбор и так только по OK, случайно тему не поменять;
- своя реализация радиогруппы вместо `RadioGroup` — `Radio`/`RadioListTile`
  находят группу только через приватный scope `RadioGroup`; повторять его
  нельзя, и семантику для TalkBack пришлось бы дублировать;
- снимать фокус в `TabController`-слушателе руками на каждом экране —
  16 мест вместо одной обёртки.

## Solution

1. `app/lib/widgets/dpad_radio_group.dart` — `DpadRadioGroup<T>`: тот же
   `RadioGroup<T>` (регистрация радио, семантика радиогруппы, Space/OK как
   раньше), но между ним и пунктами — `Shortcuts`, где стрелки =
   `DirectionalFocusIntent`. Шорткаты ближе к фокусу срабатывают раньше
   шорткатов `RadioGroup`, поэтому стрелки только двигают фокус по
   геометрии экрана, как везде, и на краю уходят к соседнему виджету.
   Выбор — OK (`select`), Enter, Space, тап/клик. Обобщает приём §622.
2. Все 14 мест — `DpadRadioGroup<…>`; в `import_preview_dialog.dart` своё
   `Shortcuts` §622 снято (теперь в общем виджете). После правки
   `grep -rn "RadioGroup<" app/lib` находит только `dpad_radio_group.dart`.
3. `app/lib/widgets/focus_safe_tab_bar_view.dart` — `FocusSafeTabBarView`:
   `TabBarView` (те же `controller`/`children`), где каждая неактивная
   страница в `ExcludeFocus`. При смене вкладки фокус со скрытой страницы
   снимается, обход пультом на скрытые страницы не заходит. Подставлен во
   все 16 `TabBarView` приложения.

Тач и мышь не меняются; вид — тоже.

## Risks and edge cases

- Группы в строку (←/→): стрелки идут по геометрии к соседнему пункту той
  же строки, с крайнего — к виджету рядом. Так же ведут себя остальные
  элементы экрана.
- Вход в группу сверху попадает на ближайший пункт, а не на выбранный (у
  `RadioGroup` по Tab — на выбранный; Tab остаётся как был).
- Клавиатура на телефоне/планшете: стрелки больше не выбирают пункт —
  выбор Space/Enter. Это поведение обычных списков, отдельной настройки нет.
- `ExcludeFocus` переключается по `TabController.index`: при свайпе индекс
  меняется в конце жеста, при тапе по вкладке — сразу. Поля ввода на
  уходящей странице теряют фокус (клавиатура закрывается) — ожидаемо.

## Verification

**Тесты** — `app/test/widgets/dpad_radio_group_test.dart` (10): ↓ двигает
фокус и не меняет значение; с последнего пункта ↓ — к элементу после
группы, с первого ↑ — к элементу перед ней; пульт проходит группу сверху
вниз насквозь; Enter / Select (OK пульта) / Space выбирают; тап выбирает;
семантика радиогруппы на месте; `FocusSafeTabBarView` снимает фокус со

## Unresolved / follow-up

- Клик **мышью** (`adb shell input mouse tap`) по вкладке на эмуляторе
  вкладку не переключил — сценарий автора проверен касанием. Обёртка
  срабатывает по смене индекса вкладки, способ переключения ей неважен.
- OpenConnect: выход из группы вниз и выбор по OK не проверены — поля ввода
  над группой забирают ↑/↓ пульта, и до группы пультом не дойти.
- Найдено попутно, вне темы: многострочные и обычные `TextField` в формах
  (имя правила в редакторе правила, поля OpenConnect) держат ↑/↓ пульта —
  тот же класс, что §736 (`DpadFieldExit` стоит только у полей поиска).
  Пройти такую форму пультом насквозь нельзя. Отдельная задача.
