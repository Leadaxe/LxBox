## Проблема

Узел, который не попал ни в один список выбора, на главном экране не виден.
Главный пример: Tailscale без `exit_node`. Пользователь завёл узел, включил
VPN и не видит ни узла, ни его состояния, ни пути к диагностике.

## Решение владельца (27.09.2026)

На главном экране появляется псевдо-направление NETWORKS, когда в конфиге есть
endpoint, не попавший ни в один селектор.

Отвергнуто владельцем: отдельный блок Networks над списком узлов.

## Условия

### Какие узлы входят в NETWORKS

Узел входит, когда выполнены все условия:

1. запись узла есть в разделе `endpoints[]` собранного конфига;
2. тег узла не входит в `outbounds` ни одной группы конфига с типом
   `selector` или `urltest`.

Следствие: в NETWORKS попадает не только Tailscale без `exit_node`, но и
endpoint WireGuard, скрытый из списков как звено цепочки.

Не входят: записи раздела `outbounds[]`, даже если они не состоят ни в одной
группе.

### Когда NETWORKS показывается

1. в конфиге есть хотя бы один узел по условиям выше.

Иначе псевдо-направления нет, экран прежний.

## Решение

### 1. Что такое псевдо-направление

| Свойство | Значение |
|---|---|
| название | `NETWORKS`, не переводится |
| место | последним в перечне направлений главного экрана |
| в конфиге | отсутствует: группы с таким тегом в конфиге нет |
| в хранилище | отсутствует: направлением пользователя не является |
| в списках выбора цели правила, цели DNS, звена цепочки | отсутствует |
| переименование, удаление, настройка | недоступны |

Состав считается из собранного конфига, по которому работает ядро. При
выключенном VPN состав считается из последнего собранного конфига.

Тег `NETWORKS` у настоящего направления пользователя: псевдо-направление
называется так же, конфликта нет, потому что в конфиг оно не пишется.
Исполнитель проверяет, что перечень направлений экрана различает записи не
по названию.

### 2. Список узлов в NETWORKS

| Элемент строки | Значение |
|---|---|
| название | тег узла |
| протокол | как у обычного узла |
| отметка активного узла | нет |
| нажатие | открывает экран узла (тот же, что пункт «Подробности») |
| выбор узла | недоступен: нажатие не переключает выход |
| замер задержки | недоступен для узла, который реестр не считает выходом (`exit_capable_when` ложно); для остальных как у обычного узла |
| меню строки | пункты обычного узла, кроме выбора и замера по условию выше |

Общий замер задержки направления («проверить все») узлы без выхода пропускает.

### 3. Состояние узла

| Условие | Что показывается |
|---|---|
| VPN выключен | состояния нет |
| VPN включён, тег узла есть в ответе ядра `/proxies` | `active` |
| VPN включён, тега в ответе ядра нет | `not running` |

Состояние входа в tailnet (авторизация, связь с сетью) в этой задаче не
показывается.

### 4. Порядок работы исполнителя

1. Опись: откуда главный экран берёт перечень направлений и состав узлов,
   где строится строка узла и её меню. Опись вносится в спеку.
2. Функция отбора узлов NETWORKS из конфига: чистая, с тестом.
3. Встраивание в перечень направлений и список узлов.
4. Строки интерфейса на английском, переводы по `docs/l10n.md`.

## Риски и edge cases

- **Выбранное направление NETWORKS при перезапуске.** Если экран запоминает
  выбранное направление, а NETWORKS исчезло (узел удалён), выбирается первое
  настоящее направление.
- **Конфиг без настоящих направлений**, но с узлом NETWORKS: экран показывает
  одно псевдо-направление.
- **Узел стал выходом** (пользователь задал `exit_node`): после пересборки
  конфига узел уходит из NETWORKS в обычные списки.
- **Автоматизация и Debug API**, которые переключают направление по тегу:
  NETWORKS целью переключения не является, запрос отклоняется как для
  неизвестного направления.

## Верификация

Тесты (гонять только затронутые файлы):

- функция отбора: endpoint вне групп входит; endpoint в `selector` не входит;
  endpoint в `urltest` не входит; запись `outbounds[]` вне групп не входит;
  пустой итог означает отсутствие NETWORKS;
- экран: при узле по условиям NETWORKS есть и стоит последним; без таких
  узлов его нет; нажатие на узел не вызывает переключение выхода;
- замер «проверить все» пропускает узел без выхода.

Критерии приёмки:

1. Конфиг для любого состояния совпадает с прежним байт в байт.
2. Tailscale без `exit_node` виден на главном экране в NETWORKS, из строки
   открывается экран узла с вкладкой Diagnostics.
