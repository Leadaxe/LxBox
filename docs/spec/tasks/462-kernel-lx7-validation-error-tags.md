## Зачем тег в ошибке

Пожелание пользователя — заявка LxBox от 18.09. Текст ошибки ядра мы
показываем как есть; `initialize outbound[3]: ...` ничего не говорит человеку
с подпиской на полсотни узлов — порядковый индекс во внутреннем массиве
конфига не совпадает ни с чем, что он видит на экране. С lx.7 в той же строке
стоит тип и тег: `initialize outbound[3] trojan[nl-amsterdam-2]: ...` — узел
опознаётся сразу, без сопоставления с дампом конфига.

## Решение

- `app/android/libbox.version`: `v1.14.1-lx.5` → `v1.14.1-lx.7`
  (lx.6 пропущен как отдельный пин — целиком входит в lx.7);
  `scripts/fetch-libbox.sh` качает AAR с проверкой SHA256.
- Java-поверхность: javap-обход всех классов одной командой (память
  `kernel-bump-emulator-verify`; sha256 `classes.jar` не показатель),
  дифф lx.5 → lx.7 ожидается пустым. Непустой дифф — стоп и отчёт.
- `docs/KERNEL.md`: блок «The current pin» → lx.7 (что принесли lx.6 и lx.7,
  Java-поверхность), строка в «Version history»; абзац про lx.5 остаётся
  ниже как история.
- `CHANGELOG.md` → Unreleased / Changed: одна запись про бамп до lx.7,
  текст §461 остаётся внутри неё (в релиз уходит финальный пин, а не два
  промежуточных).
- Кода приложения задача не трогает: гарды §459 на месте, новых строк UI нет.

## Проверка

- javap-дифф lx.5 → lx.7 пуст (253 класса, списки классов совпадают).
- В собранном APK `lib/arm64-v8a/libbox.so` строка версии — ровно
  `1.14.1-lx.7`.
- `flutter analyze`, `flutter test`, четыре l10n-чекера (новых строк нет).
