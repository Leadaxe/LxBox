# §239 — Detour-симметрия папки с подпиской: интра-цепочки, ⚙, единый пикер

> СТАТУС: реализовано (04.07.2026). Продолжение §237 по логике юзера
> (device-обсуждение): «свободные + текущая папка» в пикере даёт папке
> полную append-симметрию с подпиской.
>
> **Update §245 (05.07.2026):** toggle «Replace existing chain» в
> Settings-табе заменён на radio «Replace all» / «Fill missing» (тексты
> адаптируются под folderMode: member/members). Поведение без изменений.

## Ключевое наблюдение (проверено)

Append «как у подписки» уже КОМПОЗИЦИОННО работает в §237-билдере, если
личный detour члена указывает на члена ТОЙ ЖЕ папки: `A(личный→B)` +
`B(без личного, получает папочный X)` = цепочка `A→B→X`. Папка владеет
обоими звеньями — ровно причина, по которой подписке можно дописывать
хвост. Не хватало дисциплины пикеров и обвязки.

## Правила пикера detour (единый виджет)

| Кто выбирает | Кандидаты |
|---|---|
| Член папки | свободные одиночки + **члены СВОЕЙ папки** (разворачиваемая секция) |
| Папка (override) | то же: свободные + свои члены |
| Одиночный сервер | только свободные |
| Подписка (override) | только свободные |

- Чужие папки — НЕЛЬЗЯ (их члены живут под чужой политикой: выключат/
  переименуют/Replace — цепочка молча развалится). Это откатывает §237-
  временное «папки как кандидаты» в пикерах одиночки/подписки.
- Self-exclude; AWG→wireguard guard (§130) сохраняется.
- UI: bottom-sheet, секция «This folder» — ExpansionTile (явное
  развернуть/свернуть).

## Хранение интра-ссылки

`member.detour` / `detour_policy.override_detour` папки хранят для
интра-цели **голый тег члена** (не display): resolve при сборке —
«сначала среди членов папки (bare tag), затем как внешний display-таг».
Смена префикса папки НЕ рвёт внутренние цепочки. Известные ограничения
(документированы): переименование члена-цели рвёт ссылку (heal снимет);
коллизия «bare-тег члена == display внешнего» решается в пользу члена
(папочная область видимости ближе).

## Билдер (FolderServers-ветка)

1. Резолюция интра-ссылок (bare → display с префиксом папки).
2. **Циклы**: контроллер отклоняет ребро, замыкающее цикл
   (`setMemberDetour` → error); билдер дополнительно рвёт цикл из
   ручного бэкапа (drop замыкающего ребра).
3. **Exempt-набор** при папочном override в СВОЕГО члена X: X и всё
   достижимое из него по интра-рёбрам ведут себя как policy=Use (личные
   сохраняются, папочный не применяется) — иначе `…→X→…→X` цикл.
   Действует в append И replace.
4. **Register-гейтинг** (симметрия с ⚙ подписки): член-цель чужого
   интра-detour попадает в selector/auto только при
   `register_detour_servers` / `register_detour_in_auto` папки.

## UI

- ⚙-бейдж у члена, который является интра-целью другого члена.
- Тексты Settings-таба адаптированы для папки (q1): «Use servers' own
  detours» и т.п.; register-тогглы остаются (q2 — теперь осмысленны).
- Большое detour-радио папки показывается при родных цепочках ИЛИ личных
  detour'ах членов (§237-fix).

## Унификация по пути (запрос юзера)

- Единый `showDetourTargetPicker` (widgets) вместо трёх копий пикера
  (subscription_detail / node_settings / folder_detail).
- Mixin `DetourModeHost` — общий detourMode/setDetourMode + persist для
  экранов подписки и папки (различие — только источник picker-контекста).
