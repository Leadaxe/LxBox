## Проблема

Ссылка `naive+https://onlypass@host` у нас разбирается как `username=onlypass`
с пустым паролем (SPEC 103 п. 6 — зеркало прежнего поведения Go). Эмиттер
`toUriNaive` при этом пишет узел «только пароль» как `password@host`. Ссылка,
которую приложение отдало само, читается им же наоборот: пароль становится
именем пользователя, узел не авторизуется.

Лаунчер внёс правку в W2d (вариант А, DRIFT §7.3): одиночный userinfo —
`password`, `username` пуст. В корпусе для нас оставлен override
`uri/naive/password_only_userinfo.expected.lxbox.json` со старым ожиданием.

## Решение

1. `naive_parser.dart`: userinfo без `:` → `password`, `username` пуст.
   `user:pass` — как раньше. `user:` (двоеточие есть, пароль пуст) —
   `username=user`, пароль пуст, как раньше.
2. Эмиттер `toUriNaive`: форма «только password» не меняется (`password@`),
   «оба» не меняется (`user:pass@`). Форма «только username» эмитилась как
   `user@` — после правки парсера это прочиталось бы паролем; эмитится как
   `user:@`, инвариант `parseUri(spec.toUri()) ≈ spec` держится для всех
   трёх форм.
3. Комментарий про SPEC 103 п. 6 в парсере заменить ссылкой на этот пункт.
4. Сохранённые узлы: хранение — текст ссылки (`origin.raw`), поэтому узел,
   сохранённый как `onlypass@host`, после обновления прочитается с паролем.
   Это и есть исправление; миграция не нужна. Узел, у которого пользователь
   руками задал только username, сохранён через `toUri()` как `user@` —
   после правки он прочитается паролем. Случай вырожденный (naive без пароля
   не авторизуется), отдельно не обрабатывается; упомянуть в CHANGELOG.

## Контракт

Override `password_only_userinfo.expected.lxbox.json` живёт в репо лаунчера.
До его снятия кейс корпуса у нас красный бы стал — поэтому порядок такой:
правка у нас → сообщение сессии лаунчера → он снимает override → синк на его
коммит.

В промежутке кейс не пропускается, а сверяется с ОБЩЕЙ базой
`password_only_userinfo.expected.json`, где уже `password=onlypass`: в
раннере `app/test/contract/contract_test.dart` заведён набор
`_overrideIgnored` (одна запись `naive/password_only_userinfo` с
комментарием «§465: ждёт снятия override у лаунчера, убрать при следующем
синке»). Кейс остаётся зелёным и продолжает проверять поведение, а не молчит.
Регенерация `UPDATE_CONTRACT=1` игнорируемый override не переписывает. Набор
опустошается тем же коммитом, что синк.

## Критерии приёмки

- `naive+https://onlypass@h` → `password=onlypass`, `username` пуст.
- `naive+https://u:p@h` и `naive+https://u:@h` — без изменений.
- round-trip `parseUri(toUri(spec))` для трёх форм: только пароль, только
  username, оба.
- `flutter analyze` всего проекта чистый, `flutter test` — «All tests passed».
- CHANGELOG, PROTOCOLS.md (раздел naive) обновлены.
