# §272 — энергосвязка idle-suspend × urltest: бамп ядра, reachable-порог, интервалы

| Поле | Значение |
|---|---|
| Статус | ТЗ (ядро готово на lx-1.14, релиз-тег ещё не срезан; клиент НЕ трогать до бампа libbox) |
| Связанные спеки | §215 (idle-suspend UI), §208 (round_robin/нагрев), §207 (pprof), ядро: SPEC 020 (ревизия 2026-07-15), SPEC 019 (журнал п.18), SPEC 007 (§3.3(c)/(d)) |
| Ядро | требуется первый релиз ПОСЛЕ v1.14.0-lx.4-rc.1 с ревизией SPEC 020 от 2026-07-15 |

## Контекст

Multi-agent аудит ядра (2026-07-15, 26 верифицированных находок) проверил связку
`route.lx_idle_suspend` (SPEC 020) с urltest/балансировщиком (SPEC 019) под цель
«минимум энергии на Android без ухудшения UX». Найденные дефекты **исправлены в
ядре**; часть выводов требует действий на стороне клиента — они собраны здесь.
Текущие дефолты клиента, влияющие на энергию (проверено по коду):

- `route_idle_suspend` — дефолт **'30s'**, фича ВКЛЮЧЕНА из коробки
  (`app/lib/services/settings_storage/network.dart:36`);
- auto-группы каналов — **least_test** (round_robin опционален), `interval`
  дефолт **'5m'** (`app/lib/models/channel.dart:96`,
  `app/lib/services/builder/build_config.dart:726`);
- `background_mode` — дефолт **never**, pause/wake ядра не вызывается никогда
  (`BootReceiver.kt`, задокументированное продукт-решение).

## Что исправлено в ядре (для понимания, клиенту делать ничего не надо)

1. **P1: pause/network-wake воскрешал уснувшие WG/AWG-устройства** и ломал
   state-machine до рестарта (один цикл screen-off/on отменял всю экономию;
   для guard-suspended AWG — риск kernel hang). ⚠️ Из-за этого бага режимы
   `background_mode = lazy/always` на СТАРОМ ядре контрпродуктивны при
   включённом idle-suspend — см. «Порядок действий».
2. **P0: дыры AWG-over-WG guard'а** — восстановленный из кэша WG-выбор
   селектора на рестарте и urltest-группы вообще проходили мимо guard'а.
3. **P2: обрыв живых соединений** — эндпоинт с активной закачкой, выпавший из
   активного дерева, гасился mid-transfer (теперь transfer-гейт по счётчикам).
4. **P2: 30-минутный probe-хвост** — после ухода селектора с группы пробы
   продолжали будить уснувшие ноды до idle_timeout (теперь пробы гейтятся по
   достижимости группы).
5. Края: lost-update первого auto-выбора, listen-mode, DNS-detour-сиды,
   32-bit counter panic, uint16 tolerance, lifecycle-гонки тика.
6. **Новая опция `route.lx_idle_suspend_reachable`** (см. ниже).

## Задачи клиента

### 1. Бамп libbox (блокирующий, первым)

Поднять `libbox.version` на первый релиз ядра с ревизией SPEC 020 2026-07-15.
До бампа: не продвигать `background_mode = lazy/always` пользователям с
включённым idle-suspend (п.1 выше) и не выпускать пп. 2–4.

### 2. `lx_idle_suspend_reachable` — усыпление достижимых (главный выигрыш в фоне)

Ядро: достижимые ноды (члены round_robin-пула, выбранный узел least_test, final)
по умолчанию НЕ усыпляются — при нулевом трафике часами держат recv-воркеры и
таймеры (§208: 3 живых WG = ~50 МБ GC-scan кучи + радио от keepalive). Новая
опция задаёт второе, ДЛИННОЕ окно простоя, после которого гаснут и они;
пробуждение — лениво первым дайлом (+1 handshake RTT на первый пакет).

- Генератор (`build_config.dart`): рядом с `lx_idle_suspend` писать
  `route.lx_idle_suspend_reachable` из новой настройки
  `route_idle_suspend_reachable`; `''` (выкл) → ключ не пишется.
- **Рекомендуемый дефолт: `'30m'`** — равен апстримному `idle_timeout` urltest
  (пробы группы к этому моменту уже заглохли → нет probe-флапа). Валидация
  ядра: требует включённого `lx_idle_suspend` и значения `>= lx_idle_suspend`;
  генератор не должен писать reachable-ключ, если основной порог пуст.
- UI: VPN Settings → System → Optimization, рядом с «Suspend idle tunnels»
  (§215): «Suspend idle pool tunnels after» (Off / 15m / 30m / 1h). Подсказка:
  «Гасит даже активные в маршруте туннели после долгого простоя; первое
  соединение после сна добавляет ~1 RTT».
- Если пользователь задаёт кастомный `idle_timeout` каналов — держать
  `lx_idle_suspend_reachable >= idle_timeout` (иначе пробы будут будить
  уснувший пул каждые `interval` — флап вместо экономии).

### 2b. `passive_check: true` для авто-групп (главное смягчение probe-цены)

Ядро (SPEC 019 «passive_check», ревизия 2026-07-15): успешный TCP-дайл через
узел = двустороннее доказательство живости; пока оно свежо (< interval), пробы
не нужны. least_test пропускает целые циклы, пока выбранный узел жив (спящие
члены НЕ будятся пробами при активном использовании — probe-флап исчезает);
round_robin не пробует пассивно подтверждённые слоты. Цена: delay в UI стареет
до лапса сигнала или ручного теста; переключение на «лучший» узел происходит
реже (пока текущий работает — это обычно желаемое поведение).

- Генератор: писать `"passive_check": true` в urltest-блоки авто-групп каналов
  (оба режима; при `pool_tolerance > 0` ядро пишет warn и игнорирует — UI это
  значение не выставляет).
- Ручной тест из UI (URLTestOutbound/CheckOutbounds) остаётся полным — кнопка
  «обновить delay» работает как раньше.

### 3. `urltest_interval` для WG/AWG-каналов: 5m → 15m (рекомендация)

Аудит: активная least_test-группа пробует ВСЕХ членов каждые `interval`; каждая
проба будит уснувшую ноду полным handshake (для AWG — с junk-обфускацией), тик
усыпляет обратно через ~30–45с. На дефолте '5m' и N нодах это N handshake'ов
каждые 5 минут, 24/7 при background_mode=never (пуши держат `lastActive` свежим
всю ночь: ~12 полных обходов/час). Действия:

- с `passive_check: true` (п. 2b) пробы при активном использовании и так не
  ходят — interval определяет только частоту проб при «тлеющем» трафике без
  TCP-дайлов и скорость реакции на смерть узла; 15m остаётся разумным;
- сменить дефолт `urltest_interval` для НОВЫХ каналов на **'15m'** (ядро
  рекомендует 15m для round_robin в SPEC 019 — для least_test на mobile тем
  более);
- существующие каналы не трогать (миграция настроек не нужна), но в UI канала
  у поля interval добавить подсказку «большие значения экономят батарею»;
- для каналов в режиме round_robin с `pool_tolerance: 0` пробы и так ограничены
  пулом (lazy) — там interval менее критичен, но 15m всё равно уместен.

### 4. `background_mode` — оставить дефолт, снять блокер

Дефолт `never` не меняем (продукт-решение: пуши/длинные сокеты > батарея).
После бампа ядра (п.1) режимы `lazy`/`always` перестают конфликтовать с
idle-suspend (pause-wake больше не воскрешает уснувшие туннели) — можно смело
рекомендовать их в подсказке настройки как «экономия батареи», особенно в
сочетании с п.2.

## Проверка (smoke на устройстве, после бампа)

1. Ночной фон, round_robin pool=3, reachable='30m': к утру recv-воркеры пула =
   0 (goroutine pprof §207), первый дайл будит одну ноду (~+1 RTT), без флапа.
2. Screen off/on при уснувших нодах: нет строк `lx idle: suspend` повторно
   (устройства не поднимались) — фикс P1 работает через клиентский pause-путь.
3. Селектор: выбрать WG-член при AWG-detour → рестарт приложения → AWG-нода не
   стартует с ошибкой в логе, ядро живёт (фикс P0).
4. Длинная закачка через ноду пула + вытеснение ноды из пула: закачка не рвётся
   (transfer-гейт).

## Вне скоупа

- `pool_tolerance > 0` на mobile (пробует всех кандидатов каждый interval —
  дорого по радио; UI это значение и так не выставляет).
- Изменение семантики least_test (апстрим бит-в-бит, ядро не трогает).
- Батарейный A/B-замер (batterystats) — отложен и в ядре (SPEC 020 «Отложено»).
