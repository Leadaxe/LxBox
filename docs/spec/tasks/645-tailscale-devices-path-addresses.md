# §645 — Tailscale Network: путь пира иконкой, адреса столбиком, живой опрос статуса

| Поле | Значение |
|------|----------|
| Тип | F (доработка UI), по образцу лаунчера SPEC 158 |
| Статус | N (новая), запрос владельца 14.10.2026, макет согласован |
| Фича | [030-TAILSCALE](../features/030-TAILSCALE/FEATURE.md) → `FUNCTIONS/tailscale-node.md` |
| Дата | 2026-10-14 |
| Связанные | §581 (вкладка Network), §613 (путь и health пиров), лаунчер SPEC 158 TAILSCALE_PEER_PATH, ядро SPEC 115 |

## Проблема

Вкладка **Network** узла Tailscale (`app/lib/widgets/tailscale_network_tab.dart`):

1. Блок **This device** выводит каждый адрес отдельной парой «Address / значение»,
   то есть заголовок повторяется.
2. Строка устройства в **Devices** четырёхэтажная: имя, затем `MagicDNS · IPv4`,
   затем `online · ОС · роли`, затем путь. Как подключено (напрямую или через
   посредника), с первого взгляда не видно. На телефоне владельца 14.10 у
   GL-MT2500, который используется как exit node, строки пути не было вовсе.
3. Путь берётся только из потока `SubscribeTailscaleStatus`. Поток событийный,
   тика в нём нет (ядро SPEC 115), поэтому путь — снимок на момент последнего
   события, он может быть пустым или устаревшим. Лаунчер решил это одиночным
   `GetTailscaleStatus(tag)` раз в 3 с, пока вкладка открыта. В нашем биндинге
   метод есть (`CommandClient.getTailscaleStatus(String)`, AAR lx.18), но мы его
   не вызываем.

## Решение

### 1. This device — один заголовок Address

```
 Address
 100.83.238.125
 fd7a:115c:a1e0::4e2d:ee7e
```

- Один заголовок `Address`, под ним все адреса `tailscaleIPs` устройства, каждый
  на своей строке, в порядке ядра.
- Адрес один — одна строка. Адресов нет — блок не показывается.
- Копирование: тап по строке адреса копирует этот адрес (как сейчас копируется
  одиночное значение).

### 2. Строка устройства в Devices

Макет (телефон, тёмная тема):

```
 Devices · 2 online / 6

 ●  GL-MT2500                         100.104.79.7
    linux · exit node     fd7a:115c:a1e0::9f01:4f07
    [cloud] relay ams

 ●  LexRouter                         100.89.58.52
    linux            fd7a:115c:a1e0::b201:3a34 +1 ▾
    [bolt] direct 31.184.97.44:41641

 ○  lxbox-emu-a                       100.80.67.87
    android               fd7a:115c:a1e0::5a01:4357
    last seen 33h ago · key expired
```

**Строка 1:** точка (зелёная — `online`, серая — нет, как сейчас), имя `hostName`;
справа первый адрес `tailscaleIPs[0]`.

**Строка 2:** слева ОС и роли через ` · `: `os`, `exit node` (если
`exitNodeOption`), `shared` (если `shareeNode`). Слово `online` отсюда убирается:
это показывает точка. Справа — второй адрес:
- адресов ≤ 1 — справа пусто;
- адресов ровно 2 — второй адрес;
- адресов > 2 — второй адрес и `+N` с иконкой `expand_more`, где N = адресов − 2.
  Тап по этому месту раскрывает остальные адреса (3-й и дальше) столбиком под
  строкой 2, справа; иконка меняется на `expand_less`, повторный тап сворачивает.
  Раскрытие живёт в состоянии вкладки, ключ — `stableId` устройства; тап по
  остальной строке, как и сейчас, открывает меню устройства.
- Не влезает по ширине — обрезается многоточием **левая** часть, адрес справа
  целый.

**Строка 3 — как подключено.** Условия по порядку, срабатывает первое:
1. `path == DIRECT` → иконка `Icons.bolt`, цвет зелёный (тот же, что у точки
   online); текст `direct <endpoint>`, при пустом `endpoint` — `direct`.
2. `path == DERP` → иконка `Icons.cloud_outlined`, цвет оранжевый
   (`Colors.orange`); текст `relay <derpRegionCode>`, при пустом коде — `relay`.
3. `path == PEER_RELAY` → иконка `Icons.device_hub`, оранжевая; текст `peer relay`.
4. Пути нет (`NONE`/пусто) и устройство не `online`, и `lastSeen > 0` → без
   иконки, `last seen <возраст> ago`, возраст относительный (`33h`, `17d`,
   `5m`), а не датой.
5. Иначе — ничего.

К результату через ` · ` дописывается `key expired`, если `expired`. Строка 3
пустая целиком → её нет. Иконка размером по высоте вторичного текста (≈14–15),
цветная только иконка, текст — вторичным цветом, как остальная подпись.

Возраст хендшейка в строке устройства **не** показывается. В подписи пункта
Exit node (`_exitSubtitle`) путь остаётся с хендшейком, как сейчас, но получает
ту же иконку и цвет.

**MagicDNS** из строки уходит в меню устройства: пункт `Copy MagicDNS name`
(если `dnsNameClean` не пуст), между `Copy name` и адресами. `Copy address`
становится по пункту на каждый адрес: при одном адресе пункт один —
`Copy address`; при нескольких — `Copy <адрес>` на каждый. `Ping` — как сейчас,
по первому адресу.

**Заголовок секции:** `Devices` и рядом вторичным цветом `· <в сети> online /
<всего>`, где «всего» — устройства, которые есть в списке.

### 3. Живой статус: опрос раз в 3 с

- Пока вкладка Network этого узла на экране **и** VPN запущен, раз в 3 с вызывать
  `getTailscaleStatus(tag)` ядра (через тот же канал, что и остальные вызовы
  CommandClient; Kotlin-обёртку добавить, если её нет). Ответ — та же запись
  `TailscaleEndpointStatus`, разбирается тем же конвертером, что и поток.
- На экране показывается самая свежая запись из двух источников (поток или
  опрос) — какая пришла последней.
- Вкладка ушла с экрана, узел закрыт, VPN остановлен → таймер останавливается.
  Вернулись → запускается заново, первый вызов сразу.
- Ошибка «метода нет» (старое ядро) → опрос останавливается до закрытия вкладки,
  в UI ничего, журнал без ошибок. Тег не найден, endpoint не запущен → пропуск
  тика, опрос продолжается. Вызов ещё не вернулся к следующему тику → тик
  пропускается (не копить параллельные вызовы).

## Не делаем

- Не меняем данные и порядок сортировки устройств, состав меню кроме описанного,
  блок Exit node кроме иконки у пути, Settings, health-предупреждения.
- Self-устройство в Devices не добавляем (оно в This device).
- Соединения по пиру (`Connection.tailscalePeerID`) — не здесь.

## Тексты и локализация

UI только английский. Новые строки (`last seen %s ago`, `Copy MagicDNS name`,
`Copy %s`, `%s online / %s` и т. п.) — с записями во всех языковых файлах l10n
(гейты per-language, см. §452). Неиспользуемые после правки строки (`last seen
%s` с датой, если не нужна больше нигде) — убрать вместе с переводами.

## Проверка

- Тесты на чистые функции: текст и вид пути по каждому из условий п. 2/строка 3
  (DIRECT с/без endpoint, DERP с/без кода, PEER_RELAY, NONE online/offline,
  `key expired`), правая часть строки 2 для 0/1/2/3 адресов, возраст `last seen`.
- Тест таймера опроса: старт/стоп по видимости и по VPN, остановка на
  «метода нет», пропуск тика при незавершённом вызове.
- Эмулятор с узлом Tailscale: строки как в макете, опрос идёт только при
  открытой вкладке.
