## Проблема

Лаунчер за v2.3.5→develop получил четыре вещи, которых у нас нет или они
половинчатые:

| Лаунчер | У нас |
|---|---|
| Фоновые ошибки — в журнал Errors (N), под списком узлов красная строка-счётчик, клик открывает журнал | `lastError` → SnackBar (`home_screen.dart:341`, §166); `AppLog` с буферами и экран Debug есть, счётчика и перехода нет |
| У каждого предупреждения карточка «что/почему/что делать» + кнопка копирования | карточка есть (`node_notifications_view.dart` ~424–445), копирования нет |
| Все JSON-поля — редактор с подсветкой, номерами строк, свёрткой, поиском | `LxCodeEditor` (re_editor, §554) только в Config и мастере; Source узла, DNS-сервер, правило маршрута, DNS-правило, направление, источник подписки — голые `TextField`; свёртки и поиска нет |
| Окно узла: тип · транспорт · защита одной строкой, значения выделяемые | `outbound_view_screen.dart` ~510–516: четыре `_kvRow`, `Text` не выделяется |

## Решения (Fable, автономно, 08.10.2026)

**A. Счётчик ошибок.**
1. SnackBar §166 не трогать. Добавить на главный экран под списком узлов
   строку **«Errors (N)»** красным, где N — число записей уровня error в
   `AppLog` (оба источника, `app` и `core`) с момента последнего открытия
   журнала (или с запуска приложения, если не открывали). N = 0 → строки нет.
2. Тап по строке → экран Debug (`debug_screen.dart`) с предустановленным
   фильтром «errors», счётчик обнуляется.
3. Ключ виджета для тестов, никаких новых хранилищ: «последнее открытие» —
   поле в памяти процесса.

**B. Копирование предупреждения.**
4. В карточке уведомления (`node_notifications_view.dart`) кнопка копирования:
   в буфер — код, заголовок, три секции (What happened / Why / What you can
   do) и params, plain text. Используется тот же механизм копирования, что в
   других местах приложения (найти по `Clipboard.setData`).

**C. Редактор JSON везде.**
5. `LxCodeEditor` (`widgets/lx_code_editor.dart`): добавить свёртку блоков
   (`re_editor`: chunk analyzer для JSON, индикаторы в gutter) и поиск
   (`CodeFindController`/`findBuilder`; вызов — иконка в правом верхнем углу
   поля либо жест, как даёт пакет). Обе возможности опциональны флагами, по
   умолчанию включены там, где показываются номера строк.
6. Перевести на `LxCodeEditor` с языком JSON: Source узла
   (`node_settings_screen.dart` ~667, язык — по `originKindOf(raw)`: `json`
   → подсветка JSON, `uri`/`wg_ini` → plain без подсветки, переключение
   на лету при вставке), DNS-сервер (`dns_server_edit/tabs/json_tab.dart`),
   правило маршрута (`custom_rule_edit/sections/json_section.dart`), DNS-правило
   (`dns_settings_screen/user_rule_editor_sheet.dart`), JSON-поля направления
   (`direction_edit_screen.dart` ~267, ~440), источник подписки
   (`subscription_source_tab.dart`), редактор пресетов, если он есть (найти по
   `preset` + `TextField`). Поведение полей (контроллеры, валидация, сохранение)
   не менять — только виджет ввода. Win7-оговорка лаунчера нас не касается.
7. Mobile: высота поля — как была (не «на весь экран» без нужды); клавиатура
   не должна перекрывать поле поиска.

**D. Строка узла.**
8. `outbound_view_screen.dart`: строки Type / Transport / Security заменить
   одной строкой `type · transport · security` (пустые части опускать, у
   endpoint — как сейчас `type · endpoint`), Server — отдельной строкой;
   `_kvRow` → значение `SelectableText`. Остальные два экрана узла (§392) —
   только если у них есть те же строки (по отчёту разведки — нет).

## Ограничения

- UI-строки английские; новые строки — в `ru`-каталог с переводом.
- `hardcoded_check`/`template_check` — один раз в конце, только
  относящийся к правке.
- Тесты на форматирование UI-строк не писать; тест на счётчик — виджетный
  по ключу; на копирование — проверка содержимого буфера через мок.
- `app/contract/**`, `pubspec.lock` не трогать; новые пакеты не добавлять
  (`re_editor` уже есть).
