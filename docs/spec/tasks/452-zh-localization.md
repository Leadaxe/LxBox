| Поле | Значение |
|------|----------|

## Проблема

Интерфейс существовал на двух языках — en (базовый, в коде) и ru. Issue #139
от пользователя из материкового Китая: без китайского приложением пользоваться
трудно.

Вторая, более тихая проблема вскрылась при приёмке PR: **гейты не
масштабировались на третий язык**. `ui_check` был зашит на
`assets/l10n/ru/ui.json`, `kotlin_check` — на `values-ru/strings.xml`. Оба
показывали «0 находок» при заведомо неполном zh-словаре: они его просто не
видели. Язык, добавленный по доке, оставался бы вне CI и тихо гнил бы с каждым
новым ключом.

## Решение

### 1. Локализация zh

Взята из PR #137 (cherry-pick коммита `873e2d70`), обвязка автора сохранена без
переделки — она следует доке буквально:

| Шаг доки | Что сделано |
|---|---|
| 1. UI-словарь | `app/assets/l10n/zh/ui.json` |
| 1a. Plural-resolver | `ZhPluralResolver` — по CLDR у китайского одна форма `other` |
| 2. Overlay шаблона | `app/assets/l10n/zh/template.json`, 205 ключей |
| 3. Native Android | `res/values-zh/strings.xml`, 43 ключа (`app_name` непереводим) |
| 4. Объявление локали | `locales_config.xml`, `LocaleController.supportedTags`/`supportedLocales`, `SettingsStorage.appLanguageValues`, `L10n.kt KNOWN`, `_supported` в `app_language_reconcile.dart` |
| 5. Пикер | `中文（简体）` в `general_tab.dart`, `// l10n-exempt: endonym` |
| 6. Гейты | см. раздел 3 |

Не взяты: `RELEASE_NOTES.md` и `docs/latest.json` — в PR это релизные файлы
форка (запись про несуществующий в апстриме «v2.23.2 (zh)»).

### 2. Доперевод

PR собирался на базе v2.23.1, за это время в v2.24.x приехали Tailscale и
секции узлов. Разрыв на момент приёмки: 58 ключей отсутствовали, 2 устарели
(`Interval must be ≤ idle timeout` и старая редакция строки про типы
серверов — в новой добавились Group / Tailscale). Недостающие переведены,
устаревшие удалены: **1598 ключей, множество совпадает с ru** поключно.

Терминология продолжает словарь автора PR: `节点` (node), `服务器` (server),
`订阅` (subscription), `路由` (routing), `分组` (group), `方向` (direction).
Латиницей остаются имена технологий (Tailscale, REALITY, uTLS, MagicDNS, SRS,
DoT/DoH/DoQ/DoH3), wire-теги в кавычках и `detour` — последний уже так
оформлен примерно в 25 записях словаря.

### 3. Гейты стали мультиязычными

Это содержательная часть задачи, а не оформление.

**`ui_check`** — вместо константы `_dictPath = 'assets/l10n/ru/ui.json'`
перечисляет каталоги `assets/l10n/*/` с `ui.json` и валидирует каждый против
одного скана `lib/`. Набор plural-форм берётся per-язык новой функцией
`formsForTag` (`src/ui_scan.dart`) — зеркало `switch` в
`LocaleController._buildGetLocalText`, так что для ru проверяются
one/few/many/other, для zh — единственная `other`. Находки префиксуются тегом,
сводка печатается по строке на язык.

**`kotlin_check`** — parity-гвард вместо пары `values/` ↔ `values-ru/`
перечисляет все каталоги `res/values-*` со `strings.xml`.

Оба теперь **обнаруживают язык по факту его каталога**: следующий переводчик
не сможет добавить язык мимо CI, и не придётся править чекеры — грабля, на
которую этот PR наступил первым.

Шаг 6 доки не изменился по составу команд, но его смысл стал полным: четыре
чекера под `--strict` действительно покрывают все языки.

### 4. Что НЕ менялось

Английские ключи, ru-словарь, `wizard_template.json`, движок `getLocalText`,
структура пайплайна переключения языка. `MaterialApp` читает
`supportedLocales`, кэш `TemplateLoader` ключуется тегом, нативный резолвер
берёт тег из prefs как есть — по доке новый язык структурных изменений не
требует, и он их не потребовал.

## Проверка

- `flutter analyze` — чисто.
- `ui_check --strict`: `ru: dict 1598, missing 0, orphan 0, arity 0` и
  `zh: dict 1598, missing 0, orphan 0, arity 0`.
- `template_check --strict`, `hardcoded_check --strict`,
  `kotlin_check --strict` (33 .kt + оба каталога переводов) — 0 находок.
- `flutter test` — прогон полного корпуса.
- Независимая сверка словаря: множество ключей zh == ru; арность
  printf-плейсхолдеров совпадает в каждой форме; ни одной plural-записи с
  формами кроме `other`; набор `special`-форм совпадает с ru поключно; пустых
  значений нет.

## Осталось

- **Полевая проверка**: переключение языка на устройстве, шторка/QS-тайл/
  ярлыки на zh, ширина китайского текста в узких местах (`TabBar` — см. §158).
- **Сопровождение**: третий язык означает, что каждый новый UI-ключ теперь
  требует двух переводов. `ui_check --strict` это принудит — пропустить нельзя,
  но заложить время нужно.
