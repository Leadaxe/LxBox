# §651 — WARP: блоки `8.x` обратно в пул WireGuard

| Поле | Значение |
|------|----------|
| Тип | D (данные пула) |
| Статус | D (done); выпущено в v2.25.16 |
| Фича | [015-WARP → endpoint-pool](../features/015-WARP/FUNCTIONS/endpoint-pool.ru.md) |
| Дата | 2026-10-14 |
| Связанные | §132 (откуда блоки), §136 (первое включение), коммит `2d2803b15` (удаление 18.06), PR [Leadaxe/LxBox#164](https://github.com/Leadaxe/LxBox/pull/164) |

## Проблема

В PR #164 предложено добавить в `wireguard.v4_cidr` восемь блоков `8.x` и убрать
`162.159.193.0/24` («доступна только с Zero Trust»). Эти же `8.x` уже были в
пуле с §136 и удалены коммитом `2d2803b15` (18.06.2026) с формулировкой
«мертвы/режутся на LTE-DPI». Сам PR влить нельзя: комментарии `//` внутри JSON
ломают разбор, `WarpEndpointPicker.load` молча остаётся пустым, в CI падают 18
тестов `warp_endpoint_picker_test.dart`.

## Диагностика — замеры 14.10.2026

Методика одна для всех точек: ядро sing-box-lx (`with_wireguard,with_awg`),
свежая регистрация WARP, WG-узел с `i1` через `ip=quic`, `ib=chrome`,
`id=www.google.com`, junk `4/40/70`, порт 2408, без `reserved`. На подсеть два
адреса (`.1` и `.10`), через туннель запрос `https://1.1.1.1/cdn-cgi/trace`,
успех = `warp=on`.

| Точка | Выход | Контроль `162.159.192/195`, `188.114.96/97` | Восемь `8.x` | `162.159.193` |
|---|---|---|---|---|
| Проводной интернет | не РФ | все живы | все живы | 0 из 4 попыток |
| Проводной интернет | РФ | все живы | все живы | 1 из 9 попыток |
| LTE РФ, ядро на телефоне, по одному узлу на запуск | РФ | все живы, 0,28–0,36 с | все живы, 0,29–0,39 с | 0 из 3 попыток |

- Задержка `8.x` на уровне контрольных блоков во всех точках.
- Голый WG-handshake без `i1` (проверялся с проводного интернета, оба выхода)
  не прошёл ни на один адрес: без маскировки такой замер ничего не показывает.
- Вывод `2d2803b15` («`8.x` мертвы на LTE») на 14.10.2026 не подтверждается.
- `162.159.193.0/24` почти не отвечает, но изредка поднимается. Почему —
  неизвестно (версия PR про Zero Trust не проверена), поэтому блок и пресет
  `162.159.193.1:2408` не трогаем.

## Решение

`app/assets/warp_endpoints.json` → `wireguard.v4_cidr`: добавлены `8.6.112.0/24`,
`8.34.70.0/24`, `8.34.146.0/24`, `8.35.211.0/24`, `8.39.125.0/24`,
`8.39.204.0/24`, `8.39.214.0/24`, `8.47.69.0/24`. `162.159.193.0/24` и
`endpoints_preset` без изменений. Код не меняется.

## Верификация

- `app/test/services/warp_endpoint_picker_test.dart` зелёный (тест «v4-хосты в
  известных Cloudflare-блоках» требует хотя бы один 162/188 — выполняется).
- CI develop зелёный.
