# §657 — ссылка поддержки `tg://` опознаётся как Telegram

| Поле | Значение |
|------|----------|
| Тип | B (дефект) |
| Статус | I (implemented) |
| Фича | [001-SUBSCRIPTIONS](../features/001-SUBSCRIPTIONS/FUNCTIONS/subscription-meta.md) |
| Дата | 2026-10-17 |
| Связанные | 006F (шапка подписки, иконка Telegram), §390 (`fallbackUrl` для custom-scheme) |

## Проблема

Провайдер (Remnawave) отдаёт заголовок
`support-url: tg://resolve?domain=<имя>`. Чип «Support» на экране подписки и
значок в строке списка показывают общую иконку «открыть ссылку», а не
Telegram: признак Telegram проверялся подстрокой `t.me`.

Вторая сторона той же ссылки: без установленного Telegram `tg://` некому
открыть, и ссылка только копируется в буфер.

## Решение

1. Ссылка считается Telegram, если выполнено одно из условий:
   - схема `tg:`;
   - хост `t.me`, `telegram.me` или `telegram.dog`, в том числе с `www.`.

   Прочие ссылки, в том числе с `t.me` внутри пути или в чужом домене
   (`https://not.me/...`, `https://example.com/t.me`), Telegram не считаются.
2. Для `tg://` строится веб-форма, которую native-сторона открывает, если
   Telegram не установлен (механизм `fallbackUrl` §390):
   - `tg://resolve?domain=X` → `https://t.me/X`;
   - `tg://resolve?domain=X&post=N` → `https://t.me/X/N`;
   - `tg://join?invite=H` → `https://t.me/+H`.

   Для других форм `tg://` веб-формы нет: поведение прежнее (буфер обмена).
3. Оба места показа (чип на экране подписки, значок в строке списка)
   пользуются одним признаком.
