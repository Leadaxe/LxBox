## TL;DR

Рабочая планка-2026 ушла от «ломаем сигнатуру случайным мусором» (наш текущий уровень — WG-decoy + SIP) к **позитивной мимикрии под живой протокол**: i1 = байт-в-байт снимок реального пакета (DNS-ответ / QUIC Initial / TLS ClientHello) с рандомизацией только изменчивых полей через CPS-теги. Плюс есть **3 тега, которых нет в публичной доке и нет у нас** (`<d>`, `<ds>`, `<dz>`) — это «секретный соус» 2.0. Наш генератор не использует `<t>` (timestamp) → повторные i1 байт-идентичны (потенциальный маркер). Конкретный план роста — в «Findings» и «Gap-анализе».

## CPS-теги — полный актуальный набор (source of truth: `amneziawg-go/device/obf.go`)

Прочитана карта `obfBuilders` из исходника ядра Amnezia (июнь 2026). **8 тегов**, не 6 как в публичной доке:

| Тег | Что эмитит | В доке? | У нас (§126)? |
|---|---|---|---|
| `<b 0xHEX>` | статические байты (литерал протокола) | ✅ | ✅ |
| `<r N>` | N криптослучайных байт (≤1000) | ✅ | ⚠️ косвенно (весь body random) |
| `<rc N>` | N случайных ASCII-букв `[A-Za-z]` | ✅ | ❌ |
| `<rd N>` | N случайных ASCII-цифр `[0-9]` | ✅ | ❌ |
| `<t>` | 4-байтовый UNIX timestamp (BigEndian) | ✅ | ❌ |
| `<d>` | вставляет **сам payload** пакета (copy src) | ❌ **не задокументировано** | ❌ |
| `<ds>` | payload в base64 RawStd | ❌ **не задокументировано** | ❌ |
| `<dz N>` | N-байтовое поле длины payload (BigEndian) | ❌ **не задокументировано** | ❌ |

`<d>/<ds>/<dz>` позволяют **обернуть реальную WG-нагрузку** в конверт формата другого протокола (а не просто слать decoy перед handshake) — это качественно сильнее нашего подхода. Парсер `newObfChain` толерантен: неизвестный тег → ошибка сборки конкретного i*, но эмитит понятное сообщение (см. `uapi.go` case `i1`..`i5`).

## Эталонный i1 от самой Amnezia = DNS-**ответ** (декодировано)

Официальный гайд апгрейда 1.0→1.5 даёт `I1`, который мы декодировали байт-в-байт:
```
I1 = <r 2><b 0x8580 0001 0001 0000 0000  04 'yabs' 06 'yandex' 02 'ru' 00  0001 0001  c00c 0001 0001 0000026d 0004 57fa27d1>
```
Это **DNS response** (не запрос!): flags `0x8580` (QR+AA+RD+RA), 1 question + 1 answer, QNAME `yabs.yandex.ru`, тип A, answer = реальный IP `87.250.39.209`. `<r 2>` рандомизирует только Transaction ID. **Урок:** рабочая мимикрия — это снимок настоящего ответа настоящего резолвера, а не синтетика. У нас DNS-шаблона нет вообще.

## Findings — что делают живые генераторы (2026)

### 1. warp-awg-gen (Skiro1) — ближайший к нам, AWG 2.0 + CPS
- i1 = **реальный захваченный WARP QUIC payload** (`<b 0xce00000001...>`, 1250+ байт) — не синтетика, а дамп настоящего рукопожатия QUIC к Cloudflare.
- i2–i5 = `<b 0x...>` random hex, структура под маски протоколов (QUIC/DNS/SIP).
- `--from-hex` — конвертит дамп Wireshark в i1 CPS (мин. 32 байта). То есть схема: **поймал реальный пакет → превратил в шаблон**.
- Поддержка CPS-выражений через `--i1 "<b 0x...><r 16>"` (т.е. b+r миксуют).
- Дефолты те же, что у нас: `Jc=4, Jmin=40, Jmax=70, S1..S4=0, H1..H4=1,2,3,4`.
- Авто-выбор endpoint по TCP-latency; кэш регистрации 90 дней (на случай блокировки WARP API); MTU 1280.

### 2. bash-warp-generator (ImMALWARE) — популярный для AmneziaVPN, ДРУГОЙ preset
Существенно отличается от нашего/Skiro1:
- `Jc=120, Jmin=23, Jmax=911` (у нас `4/40/70`) — **намного агрессивнее** по junk-train.
- `S1=0, S2=0, H1..H4=1,2,3,4` — как у нас.
- i1 = большой `<b 0xc2000000011419fa4b...>` (~1250+ байт, QUIC-подобный заголовок `0xc2` = QUIC long-header).
- `Endpoint = 162.159.192.1:500` (порт 500, не 2408 — пересекается с findings §132 про порты-fallback).
⚠️ `Jc=120` — это 120 junk-пакетов перед handshake: сильнее против сигнатурного DPI, но дороже по батарее/первому хендшейку. Диапазон значений — параметр для тюнинга, а не догма.

### 3. usque (Diniboy1123) — MASQUE, АЛЬТЕРНАТИВНЫЙ транспорт (не AWG)
- Реимплементация WARP поверх **MASQUE (Connect-IP, RFC 9484) на QUIC/HTTP3, порт 443**.
- DPI-преимущество: трафик неотличим от обычного HTTPS/HTTP3 (QUIC обязывает TLS 1.3) — нечего «фингерпринтить», в отличие от WG-handshake.
- Работает там, где WG/AWG к WARP уже мёртв («WireGuard doesn't work anymore on some networks»).
- Обфускация = кастомный SNI (дефолт `client-masque.cloudflareclient.com` палевен, меняется флагом `-s`). uTLS-рандомизации нет.
- Режимы: SOCKS5 / HTTP CONNECT / TUN.
- **Это не junk-генератор, а другой класс обхода** — фиксируем как стратегическую опцию: когда AWG-junk не спасает (DPI режет сам WG-паттерн на любом IP — см. §132 caveat), MASQUE-путь к WARP может быть единственным рабочим. Требует поддержки в ядре — у sing-box есть outbound, у нас НЕ заведён. Отдельная большая тема.

### 4. cf-knife / cfray — сканеры (комплемент к §132, не junk)
- Fragment-пресеты для DPI: light (100–200B / 10–20ms), medium (50–200B / 10–40ms), heavy (10–300B / 5–50ms) — это про TLS-фрагментацию (VLESS), не AWG, но идея «несколько профилей агрессивности» переносима на junk-preset.
- Чистые IP чаще в `104.16.0.0/13` и `172.64.0.0/13` (для VLESS/edge, не WARP-UDP — для WARP см. §132).

## Решения по принципам (НЕ менять без согласования)

- **Рандомизация обязательна** ([§126](126-warp-amneziawg-obfuscation.md)): копировать константный i1 из чужого генератора = общая сигнатура у всех юзеров + потенциальный beacon. Снимок реального протокола берём как *структуру*, изменчивые поля (ID/timestamp/nonce/payload) — рандомим тегами. Это уже наш принцип, расширяем его на новые шаблоны.
- **Не ломать Cloudflare** ([§126](126-warp-amneziawg-obfuscation.md)): `S1=S2=0`, `H1..H4=1,2,3,4` остаются — handshake = valid WG. Junk-пакеты (i*/Jc) Cloudflare игнорирует. Любой новый шаблон i* — это decoy/обёртка, не сам handshake.
- **i1–i5 шлёт только инициатор** (1.5 — client-only; в 2.0 — bidirectional с синком сервера). Для WARP сервер = Cloudflare (plain WG), синк i* невозможен → остаёмся в client-only 1.5-модели, даже используя 2.0-теги.
