## 1. Ошибки логики и нелогичности

Ключевые темы: рассинхрон валидации в билдере (dangling auto-tag), утечки
`http.Client`, потеря `outboundType`/`reserved` при копировании, гонки `_disposed`
в контроллере, устаревший индекс в экране деталей подписки, расхождения
форматирования времени.

### Билдер конфига

- 🔴 **[build_config.dart:342,486](../../../app/lib/services/builder/build_config.dart)** — **висячая ссылка на auto-tag при пустом наборе нод канала.** Строка 342 безусловно кладёт `c.autoTag` в `validFinals` для всех enabled/required каналов, а строка 486 эмитит auto-outbound только при `c.auto != null && nodes.isNotEmpty`. Если `nodeFilter` не даёт совпадений, `route.final = <ch>-auto` проходит валидацию, но outbound не появляется → sing-box падает на dangling-ссылке. **Верифицировано вручную.** Фикс: класть `autoTag` в `validFinals` только при `nodes.isNotEmpty` **или** проверять `route.final` в `validator.dart`.
- 🔴 **[validator.dart:15](../../../app/lib/services/builder/validator.dart)** *(PARTIAL)* — validator не проверяет `route.final` против `allTags` (в отличие от `dns.final`, строки 75-79). Фикс: симметричная проверка `route.final` в validator.
- 🟡 **[preset_expand.dart:249,273](../../../app/lib/services/builder/preset_expand.dart)** — тихое принятие некорректных `rule_set`: ветка `else` (273) принимает любой тип (int/bool/Map), а `refTag is String && refTag.isNotEmpty` (249) сбрасывает пустую строку в тот же fallback. ## 7. Пробелы аудита (критик полноты)

Что этот прогон **не** покрыл — кандидаты в §220+:

1. **`android-native/legacy` — 0 находок** при 29 Kotlin-файлах. Единственный юнит с явным нулём. При миграции §122+ там почти наверняка остался мёртвый код старой Clash-обвязки. **Перепроверить отдельно.**
2. **Desktop-платформы** (`app/ios/*.swift`, `app/macos`, `app/linux`, `app/windows` — 45/26/10/18 файлов) не имели своего юнита. Если это сток-Flutter boilerplate без кастома — задокументировать/удалить мёртвый груз; если есть кастом — аудировать.
3. **Не было измерений:** security (secrets в логах, TLS pinning, permission-модель Android, WARP-приватник на диске), performance/memory (в MEMORY.md — эпизоды OOM/heap/GRO), актуальность зависимостей (45 пакетов с несовместимыми новыми версиями — из `flutter pub outdated`).
   > ⚠️ **Проектное решение — НЕ находка:** Debug API by design даёт полный
   > root-доступ ко всему состоянию, включая секреты в открытом виде (`GET /config`
   > raw, `/backup`, `/state/subs?reveal=true`). Граница безопасности — **только**
   > Bearer-токен + bind `127.0.0.1` + default-OFF. Маскирование — UX-удобство, не
   > граница. Будущий security-прогон **не** должен помечать «прямой доступ к
   > секретам через Debug API» как уязвимость или закрывать его. См.
   > [`docs/api/debug-api-reference.md` → «Security model — root-доступ by design»](../../api/debug-api-reference.md#security-model--root-доступ-by-design).
   > Security-аудит проверяет границу (стойкость токена, bind, default-OFF, обход
   > auth), а не то, что за ней всё открыто.
4. **`docs/private/`** (маркетинг/legal/drafts) и `docs/USER_GUIDE_RU.md` — вне юнитов.
5. **Отсутствие тестового покрытия** (не качество существующих тестов, а его *отсутствие*) для `screens/live_events_tab`, `connections_screen`, `stats_screen`, `controllers/*`, `services/debug`, `services/support`, `vpn/box_vpn_client` — не зафиксировано.
