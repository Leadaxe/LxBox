## Проблема

Редактор узла принимает три формы текста и сохраняет в источник записи то,
что набрано. В источнике узла оказывается документ целого конфига или массив
тел. Источник узла хранит не узел.

Следствие: вид источника у правленого руками узла бывает разным
(`singbox_outbound`, `singbox_config`, `singbox_outbound_array`), и правило
«авторское тело» нельзя привязать к одному виду.

## Решение владельца (27.09.2026)

После ручной правки в источнике записи остаётся только узел. Вид источника
ровно один: `singbox_outbound`. Документ и массив являются формами ввода, а не
формами хранения.

## Диагностика

- Формы ввода разбирает `prepareNodeDocumentForSave`
  (`app/lib/screens/node_settings/node_document.dart`).
- В источник пишут `updateConnectionAt` и `updateMemberAt`
  (`app/lib/controllers/subscription_controller.dart`): `rawBody` получает
  текст целиком.
- Массив тел при неизменном теге сохраняется целиком, при изменённом
  сохраняется первый элемент.
- Дословность включает `verbatimBodyOf`
  (`app/lib/services/builder/verbatim_body.dart`) по мапперу источника
  `singbox`, то есть по любому из четырёх видов `singbox_*`.
- Разбор определяет вход узла без учёта контейнера: `bodySourceOf`
  (`app/lib/services/contract/parse_warnings.dart`).

## Решение

### 1. Что редактор пишет в источник

| Ввод на вкладке Source | В источник записи | Сообщение пользователю |
|---|---|---|
| голое тело: объект с ключом `type` | текст как набран, байт в байт; перекодируется только при смене тега | нет |
| документ: объект с `outbounds` или `endpoints` | тело первого узла, не служебного и не группы | если в документе было что-то кроме этого узла |
| массив тел | первый элемент | если элементов больше одного |
| ссылка | как сейчас | нет |
| INI | как сейчас | нет |

Тело, извлечённое из документа или массива, пишется JSON с отступом в два
пробела.

Сообщение одно на сохранение: узел сохранён, остальное содержимое не
сохранено. Текст на английском, ключ словаря по правилам `docs/l10n.md`.

Правило одинаково для своего сервера и для члена папки.

Кнопка Edit JSON не меняется: она и сейчас пишет в источник голое тело.

Проверка ядром при сохранении (`checkConfig`) остаётся.

### 2. Импорт своих узлов

Мастер добавления сервера, вставка из буфера, файл. Условия:

1. создаётся своя запись или член папки;
2. вход опознан маппером `singbox`.

Поведение: на каждый узел входа создаётся запись с голым телом этого узла в
источнике. Документ и массив в источник не попадают.

Подписки не затрагиваются: их источник это ответ провайдера.

### 3. Старые записи

Условия:

1. запись своего сервера или члена папки прочитана из хранилища;
2. вид источника `singbox_config`, `singbox_config_array` или
   `singbox_outbound_array`.

Поведение: источник заменяется телом узла этой записи (`rawSource` узла) при
чтении. Запись пишется в хранилище в новом виде при первом сохранении
состояния. Версия формы хранения не меняется.

Тело узла при этом то же, что уходило в ядро раньше. Меняется только обёртка.

### 4. Дословность

Узел уходит в ядро дословно, когда выполнены все четыре условия:

1. контейнер: свой сервер или член папки;
2. узел не группа автовыбора;
3. вид источника записи ровно `singbox_outbound`;
4. текст узла разбирается как JSON-объект.

Остальные виды источника идут через модель.

Что с телом делается, как и раньше: `detour` снимается, пустой `tag`
заполняется тегом модели.

### 5. Вход узла при разборе

`bodySourceOf` приводится к тому же условию: вход `singbox` получает только
узел своей записи или члена папки с видом источника `singbox_outbound`. Узел
подписки получает вход `other`.

Следствие: исключения реестра по входу (`except_sources`) перестают
действовать на узлы подписок и при разборе. На сборке они на них и не
действовали.

## Запрос в контракт

| Что | Норма |
|---|---|
| источник узла после ручной правки | только тело узла, вид `singbox_outbound` |
| дословное тело | четыре условия раздела 4 |
| вход `singbox` для исключений по входу | только свой сервер и член папки |
| текст о входе в описании `awg_mtu_high` | убрать слова «или подпиской» |

## Риски и edge cases

- **Документ с несколькими узлами в редакторе узла.** Сохраняется первый,
  остальные теряются. Сообщение обязательно.
- **Старая запись с массивом из нескольких тел.** После раздела 3 остаётся
  первый узел. Сейчас запись и так отдаёт в конфиг один узел.
- **Форматирование источника.** Текст, извлечённый из документа, теряет
  авторское форматирование. У голого тела оно сохраняется.
- **Identity узла** не сдвигается: хеш считается по телу с сортировкой ключей.
  Проверяется тестом на фикстуре, снятой до правок.

## Верификация

Тесты (гонять только затронутые файлы):

- `app/test/screens/node_settings/node_document_test.dart`: пять строк таблицы
  раздела 1;
- `app/test/models/record_codec_sources_test.dart`: три вида старого источника
  из раздела 3;
- тест дословности: четыре условия раздела 4, по одному отказу на каждое;
- тест `bodySourceOf`: узел подписки с sing-box JSON получает вход `other`;
- identity-хеш узла до и после раздела 3 совпадает.

Критерии приёмки:

1. После сохранения из редактора `sourceKindOf` источника своей записи и
   члена папки равен `singbox_outbound`, `uri_lines` или `wireguard_conf`.
   Других значений нет.
2. Конфиг для существующего состояния совпадает с прежним байт в байт.

## Реализация

- Синк контракта 1.1.89 (`870a4224`): 3e551430.
- Код и тесты: 52af717a.
- Раздел 1: `prepareNodeDocumentForSave` (`node_document.dart`) отдаёт только
  тело узла; документ без узла отклоняется («The document has no node to
  save.»); сообщение об остатке «Only the node is saved. The rest of the input
  is not kept.». `updateConnectionAt` и `updateMemberAt` дополнительно сводят
  текст через `bareNodeSourceOf`. Порядок выбора узла документа прежний:
  `endpoints`, затем `outbounds`.
- Раздел 2: `_addJsonNodes` для одного узла пишет голое тело (sing-box
  документ и массив); члены папки и раньше получали `rawSource` узла. Узел из
  документа теперь получает дефолтный эмодзи, как вставленное голое тело
  (`singbox_config_import_test` обновлён).
- Раздел 3: `bareNodeSourceOf` / `bareBodyTextOf` (`codec/source_record.dart`)
  на чтении записи сервера и члена папки и в чтении формы v0; пустой `tag`
  тела заполняется тегом узла.
- Раздел 4: `verbatimBodyOf` требует `isAuthoredNodeSource` (вид ровно
  `singbox_outbound`).
- Раздел 5: `parseAll(own: true)` у своих записей; признак авторского тела
  живёт на время разбора (`parser/authored_scope.dart`) и задаёт вход
  `_sanitizedEntry`, `annotateFromRawBody` и `bodySourceOf`. Узел подписки —
  `other`: корпус `body/singbox/endpoints_awg_mtu_high` проходит.
- Корпус: раннер `test/contract/node_edit_corpus_test.dart` (7 кейсов, `applied`
  не сверяется — §577); раздел `authored/` отложен до §577 пропуском с
  причиной; `origin_raw` в `backup_corpus_test.dart`.
