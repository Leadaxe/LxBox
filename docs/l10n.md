# Локализация — гайд переводчика/разработчика (§279 / §285)

Как устроена локализация L×Box и что трогать при типовых задачах: новый язык,
новая строка, правка существующей, перевод шаблона, hotfix. Архитектура и
решения — [спека §279](spec/features/279%20localization/spec.md) +
[ревизия getLocalText](spec/features/279%20localization/getlocaltext.md);
подсистема в кодовой базе —
[ARCHITECTURE.md → «Локализация»](ARCHITECTURE.md#локализация-l10n-279);
checker'ы — [`app/tool/l10n/README.md`](../app/tool/l10n/README.md).

Языки первой версии: **en** (базовый, источник истины) + **ru**.

## Модель: natural keys (§285)

С §285 искусственных ARB-ключей (`commonCancel` и т.п.) больше нет.
**Английский текст на call-site И ЕСТЬ ключ**; перевод берётся из
`assets/l10n/<tag>/ui.json`, а промах (нет словаря / нет ключа / нет формы)
деградирует в сам английский ключ с подставленными аргументами:

```dart
getLocalText.s("Cancel")                       // → "Отмена" (ru) / "Cancel" (en, fallback)
getLocalText.s("Connected to %s", host)         // printf-подстановка
getLocalText.plural("%d servers", n)            // множественное число
getLocalText.s(1, "OK")                         // особая форма №1 (special["1"])
getLocalText.plural(1, "%d items", n)           // особая форма + плюрал
```

`getLocalText` — глобальный getter (`services/l10n/locale_controller.dart`),
активную локаль отслеживает `LocaleController` (dict-reload в пайплайне смены
языка). BuildContext не нужен — доступно из сервисов/контроллеров/парсеров.
`GetLocalText.en` — пиненный английский рендерер для machine-поверхностей.

Движок: `services/l10n/get_local_text.dart` (printf `%s/%d/%1$s/%%`,
форма-индекс, fallback = ключ); plural-стратегии — `plural_resolver.dart`
(`RuPluralResolver` = CLDR one/few/many/other, `EnPluralResolver` = one/other).

### Формат словаря `assets/l10n/<tag>/ui.json`

Плоская карта `englishKey → entry`. Три вида записи:

```jsonc
// простая строка
"Save": { "value": "Сохранить" },

// плюрал: value — объект со всеми формами resolver'а языка (ru: one/few/many/other)
"%d servers": {
  "value": {
    "one":   "%d сервер",
    "few":   "%d сервера",
    "many":  "%d серверов",
    "other": "%d сервера"
  }
},

// коллизия: один английский текст → разные русские переводы по контексту.
// Корневой value — форма 0; special["N"] — особая форма N, вызывается
// getLocalText.s(N, "...") / .plural(N, "...", n).
"OK": {
  "value": "ОК",
  "special": { "1": { "value": "OK" } }
}
```

Отдельного en-словаря нет by design: английский — базовый язык, он живёт в коде
(ключ = сам английский текст call-site). Для `en` (и любого отсутствующего файла)
словарь = null → рендер идёт прямо по английскому ключу.

## Из чего состоит один язык

| Артефакт | en | ru (образец для нового языка) |
|---|---|---|
| Natural-key словарь UI-строк | — (базовый: английский текст в коде, он же ключ) | `app/assets/l10n/ru/ui.json` |
| Overlay display-текста шаблона | — (базовый: английский текст в `wizard_template.json`) | `app/assets/l10n/ru/template.json` (рукописный, ключ = английский текст) |
| Нативные строки Android | `app/android/app/src/main/res/values/strings.xml` | `.../res/values-ru/strings.xml` |
| Заявка локали для Android 13+ | — | `.../res/xml/locales_config.xml` |
| Список поддерживаемых локалей | — | `LocaleController.supportedTags` / `.supportedLocales` (`app/lib/services/l10n/locale_controller.dart`) |
| Пункт в language picker | — | `app/lib/screens/app_settings_screen/widgets/general_tab.dart` |

## Добавить новый язык (end-to-end)

На примере `de`:

1. **UI-словарь**: создать `app/assets/l10n/de/ui.json` — на каждый английский
   ключ, встречающийся в коде, запись `{ "value": ... }` (простая строка или
   plural-объект со всеми формами `de` по CLDR). Полный список ключей выдаёт
   `ui_check` (все missing — это ключи, которых нет в словаре). Каталог языка
   `assets/l10n/<tag>/` — directory-asset в `pubspec.yaml`; для `ru` он уже
   объявлен, а под новый язык `de` нужно добавить в `pubspec.yaml` отдельную
   запись `assets/l10n/de/` (иначе `ui.json`/`template.json` не попадут в бандл).
   - **Плюрал**: `value` — объект. Набор форм диктует resolver языка. Для нового
     языка добавить `<Lang>PluralResolver` в `plural_resolver.dart` и завести
     его в `LocaleController._buildGetLocalText` (сейчас: `ru → RuPluralResolver`,
     иначе `EnPluralResolver`). `ui_check` сверяет полноту форм по
     `resolver.forms`.
   - **Коллизии**: если один английский текст должен переводиться по-разному в
     разных местах — код зовёт `getLocalText.s(N, "...")` в отличающемся месте,
     а перевод кладётся в `special["N"].value`. См. ниже.
2. **Template-overlay**: создать `app/assets/l10n/de/template.json` — тот же
   shape, что UI-словарь, ключ = английский текст display-поля:
   ```json
   "Log level": { "value": "Protokollstufe" }
   ```
   Полный список ключей = display-строки, извлекаемые из `wizard_template.json`
   (английский текст узла = ключ; английский — базовый язык, отдельного en-файла
   нет); missing-ключи выдаёт `template_check`. Файл попадает в бандл через ту же
   directory-запись `assets/l10n/de/` в `app/pubspec.yaml` (шаг 1) — забытая
   запись красит flutter-тест rootBundle-загрузки overlay. Запреты (CI): `value` не начинается с `@` (иначе
   строка интерпретируется как var-ссылка — overlay применяется до substitution)
   и не содержит `{`.
3. **Android**: `res/values-de/strings.xml` — перевод каждого translatable-ключа
   из `values/strings.xml` (parity проверяет `kotlin_check`: наборы ключей и
   `%n$s`-placeholder'ов должны совпадать). Wire-значения (channel ID, actions,
   extras) в ресурсы не выносятся — их в strings.xml и нет.
4. **Заявка локали**: `<locale android:name="de"/>` в
   `res/xml/locales_config.xml` (Android 13+ per-app language) + `'de'` в
   `LocaleController.supportedTags` / `supportedLocales`.
5. **Picker**: пункт с эндонимом (`Deutsch`) в `general_tab.dart` — метка
   сознательно НЕ из словаря (каждый язык подписан на себе самом,
   `// l10n-exempt: endonym`).
6. Прогнать гейты: `flutter analyze && flutter test` + все четыре checker'а с
   `--strict` (см. README tool/l10n).

Структурных изменений не требуется: `MaterialApp` читает
`LocaleController.supportedLocales`, кэш `TemplateLoader` ключуется тегом,
native-резолвер `L10n.kt` использует тег из prefs как есть.

## Новая строка в UI (Dart)

1. В коде: `getLocalText.s("English text")` (виджеты, сервисы, контроллеры —
   BuildContext не нужен). Плюрал — `getLocalText.plural("%d English", n)` с
   printf `%d`. Аргументы: `%s`/`%d` последовательно или `%1$s`/`%2$d` явной
   позицией. Для хранимых ошибок/статусов — типизированный `UiMsg`, `render()`
   в момент показа (machine-дубль — `renderEn()`).
2. Перевод: запись в `assets/l10n/ru/ui.json` тем же английским текстом-ключом,
   с тем же набором плейсхолдеров (арность сверяет `ui_check`). Отсутствие
   записи → fallback на английский ключ; под `--strict` это **missing** = fail.
3. Hardcoded-литерал в display-позиции (включая ветки ternary/switch) не пройдёт
   CI — `hardcoded_check` с пустым baseline. `Text(getLocalText.s("..."))`
   легален (литерал — аргумент getLocalText, не прямой аргумент `Text`).
   Не-переводимое (wire-теги, юниты, эндонимы) помечается
   `// l10n-exempt: <причина>` на строке литерала или строкой выше.

Непереведённый ключ (missing) и orphan-ключ (в словаре, но не в коде) = fail
`ui_check --strict` (AST-скан обращений к `getLocalText`).

## Коллизии (одинаковый en → разный ru)

Один английский текст иногда должен переводиться по-разному в зависимости от
места (например `"OK"` как «ОК» в диалоге vs латинское «OK» как техтермин).
Решение — **особые формы**:

- корневой `value` — форма 0 (`getLocalText.s("OK")`);
- в отличающемся месте код зовёт `getLocalText.s(1, "OK")`, перевод — в
  `special["1"].value`.

`ui_check` держит это в синхроне: использованный в коде индекс N обязан иметь
`special["N"].value` (иначе **shape**-fail), а определённая, но не используемая
`special["N"]` — **orphan-special** (warn, strict→fail).

## Правка английского текста

- **UI-строка**: английский текст — это ключ. Меняешь литерал в коде → меняется
  ключ; старая запись в `ru.json` становится orphan (fail `ui_check --strict`),
  новый ключ — missing. Правь `ru.json`: переименуй ключ (и пересмотри перевод,
  если сменился смысл).
- **Шаблон** (`wizard_template.json` display-поля): ключ = сам английский текст
  (как UI-строка; английский — базовый, отдельного en-файла нет). Правишь текст в
  шаблоне → меняется ключ; отдельной регенерации нет — `template_check` извлекает
  ключи из шаблона на каждом прогоне. Сменившийся текст = новый ключ: старая
  запись в locale-файле становится unknown-key (fail `template_check`), новый
  ключ — missing (warn, strict→fail). Правь locale-файл: переименуй ключ (и
  пересмотри перевод, если сменился смысл) — тот же workflow, что у UI-строки.

## Hotfix-путь baseline (same-file replacement)

`hardcoded_baseline.json` пуст, но правило остаётся на случай временно
grandfathered-сайтов: baseline-гейт запрещает **рост** числа сайтов файла, а не
изменение hash'ей. Правка формулировки существующего литерала (опечатка, rename
переменной в интерполяции — hash канонизирован, `${...}` → `{}`) легальна:
`dart run tool/l10n/hardcoded_check.dart --write-baseline` заменяет hash,
счётчик файла не растёт. Запрещено только появление сайта в файле, которого в
baseline не было, и рост счётчика.

## `// l10n-exempt`

Точечное исключение из ratchet: комментарий на строке литерала или строкой выше,
с причиной. Легитимные случаи: wire-теги, показываемые как есть (`direct-out`),
юнит-виджеты (`'ms'`), эндонимы в language picker, протокольные термины. НЕ
легитимно: «переведём позже».

## Что не переводится никогда

Логи, Debug API-ответы, automation/Tasker-payload'ы, `emitWarnings`,
wire-значения и теги, имена файлов, user data (channel labels и т.п.), payload
OS/ядра (диагностический passthrough). Machine-поверхности рендерят английский
через `UiMsg.renderEn()` → `GetLocalText.en` (allowlist в
`tool/l10n/render_allowlist.json`). Единицы (`B/KB/MB/GB`, `Mbps`, `ms`) и
суффиксы длительности `d/h/m/s` — латиница во всех локалях.
