# Локализация — гайд переводчика/разработчика (§279)

Как устроена локализация L×Box и что трогать при типовых задачах: новый язык,
новая строка, правка существующей, перевод шаблона, hotfix. Архитектура и
решения — [спека §279](spec/features/279%20localization/spec.md); подсистема в
кодовой базе — [ARCHITECTURE.md → «Локализация»](ARCHITECTURE.md#локализация-l10n-279);
checker'ы — [`app/tool/l10n/README.md`](../app/tool/l10n/README.md).

Языки первой версии: **en** (базовый, источник истины) + **ru**.

## Из чего состоит один язык

| Артефакт | en | ru (образец для нового языка) |
|---|---|---|
| ARB-каталог UI-строк | `app/lib/l10n/app_en.arb` (template) | `app/lib/l10n/app_ru.arb` |
| Overlay display-текста шаблона | `app/assets/l10n/template/en.json` (генерируется) | `app/assets/l10n/template/ru.json` (рукописный, со `src`-hash) |
| Нативные строки Android | `app/android/app/src/main/res/values/strings.xml` | `.../res/values-ru/strings.xml` |
| Заявка локали для Android 13+ | — | `.../res/xml/locales_config.xml` |
| Список поддерживаемых локалей | — | `LocaleController.supportedTags` / `.supportedLocales` (`app/lib/services/l10n/locale_controller.dart`) |
| Пункт в language picker | — | `app/lib/screens/app_settings_screen/widgets/general_tab.dart` |

## Добавить новый язык (end-to-end)

На примере `de`:

1. **ARB**: скопировать `app_en.arb` → `app/lib/l10n/app_de.arb`, поставить
   `"@@locale": "de"`, перевести значения. `@`-метаданные (description,
   placeholders) остаются как в en. Плюралы — ICU, набор категорий языка
   (`one/few/many/other` — по CLDR). `flutter gen-l10n` (или `pub get`)
   регенерирует `lib/l10n/gen/`.
2. **Template-overlay**: создать `app/assets/l10n/template/de.json` в объектном
   формате — на каждый ключ из `en.json`:
   ```json
   "var.log_level.title": { "text": "Protokollstufe", "src": "1a2b3c4d" }
   ```
   `src` = первые 8 hex sha256 текущего английского значения — их выдаёт
   `template_check` (missing-ключи в отчёте) либо берутся из `en.json` хешем.
   Файл регистрируется в `app/pubspec.yaml` (assets) — забытая запись красит
   flutter-тест rootBundle-загрузки overlay.
   Запреты (CI): `text` не начинается с `@` (иначе строка интерпретируется как
   var-ссылка — overlay применяется до substitution) и не содержит `{`.
3. **Android**: `res/values-de/strings.xml` — перевод каждого translatable-ключа
   из `values/strings.xml` (parity проверяет `kotlin_check`: наборы ключей и
   `%n$s`-placeholder'ов должны совпадать). Wire-значения (channel ID, actions,
   extras) в ресурсы не выносятся — их в strings.xml и нет.
4. **Заявка локали**: `<locale android:name="de"/>` в
   `res/xml/locales_config.xml` (Android 13+ per-app language) + `'de'` в
   `LocaleController.supportedTags` / `supportedLocales`.
5. **Picker**: пункт с эндонимом (`Deutsch`) в `general_tab.dart` — метка
   сознательно НЕ из ARB (каждый язык подписан на себе самом,
   `// l10n-exempt: endonym`).
6. Прогнать гейты: `flutter analyze && flutter test` + все четыре checker'а с
   `--strict` (см. README tool/l10n).

Структурных изменений не требуется: `MaterialApp` читает
`LocaleController.supportedLocales`, кэш `TemplateLoader` ключуется тегом,
native-резолвер `L10n.kt` использует тег из prefs как есть.

## Новая строка в UI (Dart)

1. Ключ в `app_en.arb` (camelCase `<scope><Element>`: `home*`, `sub*`,
   `ruleEdit*`, …) + `@`-метаданные с description (обязательны:
   `required-resource-attributes: true`). Плюралы — всегда ICU с плейсхолдером
   `count`; никаких `'(s)'`-хаков.
2. Перевод в `app_ru.arb` — тем же ключом, с тем же набором placeholder'ов
   (равенство наборов проверяет `arb_check`).
3. В коде: `context.l.<key>` (виджеты); для хранимых ошибок/статусов —
   типизированный `UiMsg`, рендер в build. `L10n.current` вне allowlist — fail
   checker'а.
4. Hardcoded-литерал в display-позиции (включая ветки ternary/switch) не
   пройдёт CI — `hardcoded_check` с пустым baseline. Не-переводимое
   (wire-теги, юниты, эндонимы) помечается `// l10n-exempt: <причина>` на
   строке литерала или строкой выше.

Непереведённый ru-ключ = fail `arb_check --strict` (список — из
`build/l10n_untranslated.json`, генерируется gen_l10n). Orphan-ключ (никем не
используемый) — тоже fail (AST-скан использований `AppLocalizations`).

## Правка английского текста

- **ARB**: правишь значение в `app_en.arb` → ru-значение не протухает
  автоматически, это ответственность ревью PR (ключ тот же). Меняется смысл —
  правь оба файла.
- **Шаблон** (`wizard_template.json` display-поля): после правки —
  `dart run tool/l10n/template_check.dart --write-en` (регенерация `en.json`,
  byte-equal-гейт CI). У всех locale-файлов ключ **протухает durable**:
  `src`-hash записи больше не совпадает с hash'ем нового английского значения —
  fail на каждом прогоне CI, не только в PR, менявшем en. После пересмотра
  перевода: `--accept ru:<key>` (регенерирует `src`) — явный акт «перевод
  пересмотрен», либо поправить hash вручную.

## Hotfix-путь baseline (same-file replacement)

`hardcoded_baseline.json` с Phase 7 пуст, но правило остаётся на случай
временно grandfathered-сайтов: baseline-гейт запрещает **рост** числа сайтов
файла, а не изменение hash'ей. Правка формулировки существующего литерала
(опечатка, rename переменной в интерполяции — hash канонизирован, `${...}` →
`{}`) легальна: `dart run tool/l10n/hardcoded_check.dart --write-baseline`
заменяет hash, счётчик файла не растёт. Запрещено только появление сайта в
файле, которого в baseline не было, и рост счётчика.

## `// l10n-exempt`

Точечное исключение из ratchet: комментарий на строке литерала или строкой
выше, с причиной. Легитимные случаи: wire-теги, показываемые как есть
(`direct-out`), юнит-виджеты (`'ms'`), эндонимы в language picker, протокольные
термины. НЕ легитимно: «переведём позже».

## Что не переводится никогда

Логи, Debug API-ответы, automation/Tasker-payload'ы, `emitWarnings`,
wire-значения и теги, имена файлов, user data (channel labels и т.п.), payload
OS/ядра (диагностический passthrough). Machine-поверхности рендерят английский
через `UiMsg.renderEn()` (allowlist в `tool/l10n/render_allowlist.json`).
Единицы (`B/KB/MB/GB`, `Mbps`, `ms`) и суффиксы длительности `d/h/m/s` —
латиница во всех локалях.
