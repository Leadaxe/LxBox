## Что такое миксин

Приложение собирает конфиг sing-box из шаблона и настроек. Ручная правка в
Config Editor живёт только до следующей пересборки. Миксин применяется
последним шагом каждой сборки, поэтому пересборка его не теряет, а Lock
config не нужен.

Порядок сборки: пресеты, затем гарды и автоснятие битых узлов, затем
миксины, затем итоговая проверка. Поэтому миксины видят готовый конфиг со
всеми тегами на месте.

Один миксин — одна операция над одним путём. Изменение, которому нужны две
операции, — inbound и правило для него, — это два миксина.

Включённые миксины применяются в порядке списка, сверху вниз; каждый видит
результат тех, что выше. Выключенный миксин пропускается. Миксин может
целиться в узел, который создал миксин выше него.

## Формат записи

Debug API и LX Backup хранят миксин как JSON-объект:

```json
{"id": "…", "name": "DNS listener", "enabled": true,
 "target": "inbounds", "op": "append", "value": {"type": "direct", "tag": "dns-in"}}
```

| Поле | Тип | Смысл | В форме |
|---|---|---|---|
| `id` | строка | Назначает приложение, изменить нельзя | — |
| `name` | строка | Свободный текст; может быть пустым, тогда список показывает `target → op` | Name |
| `enabled` | bool | Выключенный миксин сборка пропускает | Тумблер в списке |
| `target` | строка | Путь на [языке пути](#язык-пути) | Target |
| `op` | строка | Одно из `append`, `prepend`, `before`, `after`, `set`, `merge`, `remove` | Action |
| `value` | JSON | Значение для действия; у `remove` — `true` или список ключей | Value или Keys у `remove` |

LX Backup сохраняет миксины в секции `mixins` без `id`. Импорт добавляет их
в конец списка и назначает новые `id`; миксин с теми же `target`, `op` и
`value`, что у существующего, пропускается.

Поле Value в форме принимает JSON5 (комментарии, висячие запятые); при Save
значение сохраняется как обычный JSON.

## Язык пути

Синтаксис пути — собственный, не JSONPath. Путь обозначает набор узлов, а не
первое совпадение: `outbounds[type=vless]` — все VLESS-outbound'ы.

### Грамматика

```
path       = "" | segment ("." segment)*
segment    = name | name "[" N "]" | name "[" conditions "]"
conditions = condition ("," condition)*
condition  = field "=" value
field      = name ("." name)*
```

### Правила сравнения

- Сегменты соединяются через `.`: `route.rules`, `dns.servers`, `log.level`.
- Пустой путь — корень конфига. В сообщениях он показывается как `(root)`.
- `name[0]` — элемент списка по индексу; `name.0` означает то же. Индекс за
  концом списка ни с чем не совпадает.
- `name[k=v]` — все элементы списка `name`, у которых поле `k` равно `v`.
  Несколько условий — через запятую, верны должны быть все.
- Поле в условии может уходить вглубь элемента:
  `outbounds[tls.enabled=true]`. Элемент без этого поля не совпадает.
- Сравнение: число с числом (`5` равно `5.0`), `true`/`false` с bool, строка
  со строкой с учётом регистра. Объект или `null` в поле не совпадает ни с
  чем.
- Если поле элемента — список, `=` означает «содержит»:
  `route.rules[rule_set=Ads]` совпадает с правилом
  `"rule_set": ["Ads", "Trackers"]`.
- Значение — всё до `,` или `]`. Пробелы внутри сохраняются, поэтому теги с
  пробелами пишутся как есть: `outbounds[tag=S2 Fastest]`. Пробелы вокруг
  поля, вокруг `=` и по краям значения отбрасываются.
- В значении не может быть `,`, `]` и `[`. В имени ключа не может быть
  пробелов и символов `. [ ] , =`.
- Регулярок, `!=` и `or` нет.
- Путь, начинающийся с `$`, зарезервирован и считается синтаксической
  ошибкой.

### Примеры путей

Теги ниже — из типичного конфига; в вашем конфиге теги другие, настоящие
показывают подсказки поля Target в форме.

| Путь | На что указывает |
|---|---|
| (пусто) | Корень конфига |
| `log.level` | Поле уровня журнала |
| `inbounds` | Список inbound'ов |
| `inbounds[tag=tun-in]` | TUN-inbound |
| `outbounds[0]`, `outbounds.0` | Первый outbound |
| `outbounds[type=vless]` | Все VLESS-outbound'ы |
| `outbounds[tag=PR DE-1]` | Outbound с тегом `PR DE-1` |
| `outbounds[tag=S2 Fastest]` | Группа urltest `S2 Fastest` |
| `outbounds[tls.enabled=true]` | Все outbound'ы с включённым TLS |
| `route.rules[action=hijack-dns]` | Правило перехвата DNS |
| `route.rules[action=resolve,strategy=prefer_ipv4]` | Правила resolve со стратегией `prefer_ipv4` |
| `route.rules[rule_set=Ads]` | Все правила, у которых `rule_set` равен `Ads` или содержит его |
| `route.rules[inbound=tun-in]` | Все правила, у которых список `inbound` содержит `tun-in` |
| `dns.servers[tag=google_udp]` | DNS-сервер `google_udp` |
| `dns.servers[tag=ru-direct:yandex_udp]` | Двоеточие в значении допустимо |

## Действия

### Что делает каждое действие

| Действие | Цель | Что делает |
|---|---|---|
| `append` | Один список | Ставит значение в конец; значение-список добавляет каждый свой элемент по очереди |
| `prepend` | Один список | То же в начало; порядок значения сохраняется |
| `before` | Элементы списка | Ставит значение (или каждый элемент значения-списка, по порядку) на тот же уровень перед **первым** совпавшим |
| `after` | Элементы списка | То же после **последнего** совпавшего |
| `set` | Любой узел | Заменяет узел целиком: скаляр, список или объект. В корне — только объект |
| `merge` | Объект(ы) | Слияние вглубь: ключи значения дописываются или заменяют свои, остальные ключи не трогаются; объект в объект — рекурсивно; список внутри значения заменяет список цели целиком. Значение — только объект |
| `remove`, Whole node (значение `true`) | Любой узел | Удаляет узел: элемент списка выбывает, ключ объекта исчезает. Корень удалить нельзя |
| `remove`, Keys (значение `["key", "a.b"]`) | Объект(ы) | Удаляет только названные ключи; ключ через точку — вглубь элемента; отсутствующий ключ — не ошибка |

`merge` дописывает новые ключи в конец объекта; ядру порядок ключей
безразличен.

### Число совпадений

| Действие | 0 совпадений | 1 совпадение | Несколько совпадений |
|---|---|---|---|
| `set`, `merge`, `remove` | Ошибка | Применяется | К каждому, одно и то же значение |
| `before` | Ошибка | Перед ним | Перед первым |
| `after` | Ошибка | После него | После последнего |
| `append`, `prepend` | Ошибка | В этот список | Ошибка |

### Ошибки типа цели

| Действие | Цель, на которой отказ | Причина |
|---|---|---|
| `append`, `prepend` | Не список или несколько совпадений | `needs a single list` |
| `before`, `after` | Ключ объекта, а не элемент списка (`inbounds`, `log.level`) | `not a list element` |
| `merge`, `remove` с Keys | Не объект | `not an object` |
| `merge` | Значение — не объект | `merge needs an object value` |
| `set` | Корень, значение — не объект | `the root can only be set to an object` |
| `remove`, Whole node | Корень | `cannot remove the root` |

## Примеры

В форме `target` — это Target, `op` — Action, `value` — Value.

**1. DNS-слушатель для другого приложения.** Сторонний файрвол вроде Rethink
отправляет DNS-запросы на заданный адрес резолвера, а отвечает на них
DNS-модуль sing-box по правилам, которые собрал L×Box. Два миксина, в таком
порядке:

```json
{"name": "DNS listener", "target": "inbounds", "op": "append",
 "value": {"type": "direct", "tag": "dns-in", "listen": "127.0.0.1",
           "listen_port": 5354, "override_address": "1.1.1.1", "override_port": 53}}
{"name": "Hijack DNS from dns-in", "target": "route.rules[action=hijack-dns]", "op": "before",
 "value": {"inbound": ["dns-in"], "action": "hijack-dns"}}
```

Первый добавляет inbound. Второй ставит правило перед существующим правилом
`hijack-dns`: всё, что приходит на `dns-in`, уходит в DNS-модуль. Порт 5353
на Android часто занят системным mDNS, поэтому в примере 5354; подойдёт любой
свободный порт. В файрволе DNS-сервер — `127.0.0.1`, порт `5354`. Проверка с
компьютера:

```
adb forward tcp:5354 tcp:5354
dig +tcp @127.0.0.1 -p 5354 example.com
```

Выключение первого миксина убирает `dns-in` из конфига; пару включают и
выключают вместе.

**2. Локальный домен — напрямую.** Правило встаёт сразу после правила resolve
со стратегией `prefer_ipv4`, перед правилами маршрутизации шаблона:

```json
{"name": "NAS direct", "target": "route.rules[action=resolve,strategy=prefer_ipv4]", "op": "after",
 "value": {"domain_suffix": [".nas.home"], "outbound": "direct-out"}}
```

**3. Поле у всех VLESS-outbound'ов:**

```json
{"name": "TFO on VLESS", "target": "outbounds[type=vless]", "op": "merge",
 "value": {"tcp_fast_open": true}}
```

**4. Настройки группы, которых нет в форме:**

```json
{"name": "Fastest: check every minute", "target": "outbounds[tag=S2 Fastest]", "op": "merge",
 "value": {"interval": "1m", "tolerance": 100}}
```

**5. Удалить ключи у одного узла.** В форме: Action `remove`, Keys,
`tcp_fast_open, tls.utls`:

```json
{"name": "PR DE-1 without uTLS", "target": "outbounds[tag=PR DE-1]", "op": "remove",
 "value": ["tcp_fast_open", "tls.utls"]}
```

**6. Удалить правило целиком:**

```json
{"name": "No ad blocking", "target": "route.rules[rule_set=Ads]", "op": "remove", "value": true}
```

**7. Заменить скаляр и добавить ключ верхнего уровня:**

```json
{"name": "Quiet log", "target": "log.level", "op": "set", "value": "warn"}
{"name": "Empty services", "target": "", "op": "merge", "value": {"services": []}}
```

## Ошибки

Миксин, который не удаётся применить, останавливает сборку: конфиг не
собирается, сборка сообщает о фатальной ошибке, под строкой миксина в списке
появляется `⚠ <причина>`. Ранее собранный конфиг остаётся на месте. Миксин
остаётся включённым: его исправляют или выключают. Миксины ниже упавшего
всё равно применяются, поэтому одна сборка может сообщить несколько ошибок.

Тексты ошибок — в том виде, в каком их отдают сборка и Debug API
(`rebuild_error`, `lastError`); в русском интерфейсе префикс читается как
`Миксин «<name>»:`, остальное то же:

| Текст | Причина |
|---|---|
| `Mixin "<name>": <target>: syntax: <message>` | Путь не разбирается |
| `Mixin "<name>": <target>: no match` | По пути ничего нет |
| `Mixin "<name>": <target>: needs a single list` | `append`/`prepend` на не-списке или на нескольких совпадениях |
| `Mixin "<name>": <target>: not a list element` | `before`/`after` на ключе объекта (`inbounds`, `log.level`) |
| `Mixin "<name>": <target>: not an object` | `merge` или `remove` с Keys на не-объекте |
| `Mixin "<name>": <target>: merge needs an object value` | Значение `merge` — не объект |
| `Mixin "<name>": (root): the root can only be set to an object` | `set` в корне со значением не-объектом |
| `Mixin "<name>": (root): cannot remove the root` | `remove` Whole node в корне |
| `Mixin "<name>": <target>: remove expects true or a list of keys` | Значение `remove` — ни `true`, ни список строк |
| `Mixin "<name>": duplicate tag "x" in outbounds` | Миксин добавил элемент с тегом, который в списке уже есть |

`<name>` — имя миксина или `target → op`, если имя пустое. Пустая цель
показывается как `(root)`.

Уникальность тегов проверяется после каждого миксина, отдельно в
`inbounds`, в `outbounds` вместе с `endpoints` (одно пространство имён, как
у ядра) и в `dns.servers`. Ошибка называет миксин, который внёс дубль.

Путь, который вчера совпадал, может перестать совпадать, когда обновление
подписки переименует узел; тогда сборка падает с `no match`.

## Ограничения и взаимодействие

- **Traffic Processing.** `prepend` на `route.rules` ставит правило перед
  Traffic Processing (sniff, hijack-dns). Это допустимо; такое правило видит
  соединения до сниффинга.
- **Гарды и автоснятие.** Миксины работают с готовым конфигом: автоснятие
  битых узлов и санитайзер outbound'ов идут раньше и не видят того, что
  миксины добавили. Дубль тега ловится до ядра; всё остальное, чего ядро не
  принимает (неизвестное поле, неверный тип), ядро сообщает при старте VPN.
  Для тегированного элемента ошибка называет его тег, для правила — только
  индекс.
- **Ручная правка в Config Editor.** Ручная правка на вкладке Config и
  миксины независимы. Следующая пересборка отбрасывает ручную правку и
  применяет миксины заново. Чтобы правка сохранялась, её записывают
  миксином.
- **Lock config.** Lock config останавливает пересборки совсем: конфиг
  остаётся тем, что сохранили, и до него не доходят ни настройки, ни
  миксины. Миксины пересборки сохраняют и меняют только свои узлы. Lock
  config остаётся для проверки конфига, загруженного через Debug API.
- **Нет предпросмотра до первой сборки.** После перезапуска приложения и до
  первой сборки форма показывает под Target `No config built yet`: без числа
  совпадений, без подсказок, без предпросмотра. Save проверяет только
  синтаксис пути и Value; совпадения проверит следующая сборка.
  Предпросмотр Debug API в том же состоянии отвечает 409.
- **Группировка.** Группировки миксинов и общего тумблера нет.
- **Десктопный лаунчер.** Схема бэкапа лаунчера пока не объявляет секцию
  `mixins`; при импорте такого бэкапа лаунчер предупреждает о неизвестном
  поле.

## Debug API

| Endpoint | Метод | Что делает |
|---|---|---|
| `/mixins` | GET | Список в порядке применения |
| `/mixins/{id}` | GET | Один миксин |
| `/mixins` | POST | Создание; миксин встаёт в конец списка |
| `/mixins/{id}` | PATCH | Смена `name`, `enabled`, `target`, `op`, `value`; `id` неизменяем |
| `/mixins/{id}` | DELETE | Удаление |
| `/mixins/reorder` | POST | Новый порядок: `{"order": [id, …]}` ровно с текущими id |
| `/mixins/{id}/preview` | GET | То же число совпадений, ошибка и фрагмент, что показывает форма |

Запись принимает `?rebuild=true`. Запись проверяет синтаксис пути и действие
и при ошибке отвечает 400; совпадение проверяет только сборка, потому что
цель может появиться после другого миксина. Тела запросов, форма ответов и
тексты ошибок —
[Debug API reference → Mixins](api/debug-api-reference.md#mixins-crud--mixins).
