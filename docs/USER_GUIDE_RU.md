# L×Box — как это работает

Руководство для пользователя: что есть что и за что отвечает. Не про код — про
**логику работы** и порядок настройки.

---

## Общая картина: как трафик проходит через L×Box

Трафик приложения проходит **четыре ступени** — каждая отвечает за свой вопрос:

```
   Приложения на телефоне
            │
            ▼
 ┌─────────────────────────┐
 │ 1. Allow-list           │   «КОГО вообще впускаем в L×Box?»
 │    (Tunnel apps)        │   Не впущен → идёт мимо, как будто VPN выключен.
 └─────────────────────────┘
            │  (впущенный трафик)
            ▼
 ┌─────────────────────────┐
 │ 2. Channels             │   «КАКИЕ есть каналы и КУДА по умолчанию?»
 │    (Default traffic)    │   VPN = через туннель · Direct = напрямую.
 └─────────────────────────┘
            │
            ▼
 ┌─────────────────────────┐
 │ 3. Rules                │   «ИСКЛЮЧЕНИЯ из умолчания»
 │                         │   Какой домен/приложение — в какой канал.
 └─────────────────────────┘
            │
            ▼
   VPN-канал (сервер) · Direct · Block
            │
            ▼
 ┌─────────────────────────┐
 │ 4. DNS                  │   «КАК резолвятся имена сайтов»
 └─────────────────────────┘
```

Ключевая идея: **это не дубли, а четыре разных вопроса** про один и тот же
трафик:

- **Allow-list** — *этот трафик вообще попадает в L×Box?*
- **Channels** — *каким выходным путём вести по умолчанию (через сервер или напрямую)?*
- **Rules** — *есть ли для него отдельное правило, переопределяющее умолчание?*
- **DNS** — *как для него узнать IP по имени сайта?*

Каждая ступень — отдельный фильтр, и они не заменяют друг друга.

---

## 1. Allow-list (Tunnel apps) — кого впускаем

**За что отвечает:** какие приложения вообще попадают под управление L×Box.

Три режима:

| Режим | Что значит |
|---|---|
| **Off** | Все приложения идут через L×Box (по умолчанию). |
| **Allow-list** | Через L×Box идут **только** выбранные. Остальные — мимо (обычная сеть). |
| **Deny-list** | Через L×Box идут **все, кроме** выбранных. |

Приложение, которое **не** захвачено (не в Allow-list / в Deny-list), L×Box
вообще не видит — его трафик идёт напрямую, как без VPN, и правила (Rules) к нему
**не применяются**.

> **Важно:** сам **L×Box добавлять в Allow-list НЕ нужно** — это ни на что не
> влияет. Приложение само через свой туннель не ходит (его служебные соединения
> и DNS идут мимо tun по физической сети). Если кажется, что «заработало после
> добавления себя» — почти всегда сработало что-то другое (обычно Default
> traffic = VPN, см. ниже).

---

## 2. Channels — выходные пути

**За что отвечает:** это **выходные пути** — куда трафик может уйти наружу, и
какой путь используется **по умолчанию**.

По умолчанию каналов **три**: один **VPN-канал** (`vpn-1` — ваш основной
туннель) + два служебных — **Direct** и **Block**. Можно **подключить ещё**
VPN-каналы (например разные серверы/группы под разные задачи).

Каждый канал — это «выход»:
- **VPN-канал** (группа серверов из ваших подписок) — наружу через сервер
  (туннель);
- **Direct** — наружу напрямую (мимо туннеля, но всё ещё через L×Box);
- **Block** — никуда (блокировка).

**Default traffic** — какой выходной путь по умолчанию: **VPN** (через сервер)
или **Direct** (напрямую). Применяется к захваченному трафику, для которого ни
одно правило (Rules) не сработало.

> **Это и есть причина частой путаницы.** Если приложение в Allow-list есть, но
> **Default traffic = Direct**, его трафик уходит **напрямую** — и кажется, что
> «VPN не работает». Поставьте **Default traffic = VPN** → пойдёт через туннель.
> Allow-list решает «впускать ли», Channels — «куда вести». Это две разные вещи.

---

## 3. Rules — как разруливаем

**За что отвечает:** исключения из умолчания. Какой конкретно трафик в какой
канал.

Правило матчит по полям (домены, приложения, подсети, порты, протоколы, Wi-Fi) и
направляет в выбранный канал (VPN-группа / Direct / Block). Внутри одной
категории — ИЛИ, между категориями — И (как в sing-box).

Типичные правила:
- реклама/трекеры → **Block**;
- российские домены (`.ru/.рф/…`) → **Direct** (быстрее и без нужды в VPN);
- BitTorrent → нужный канал;
- конкретное приложение → конкретный канал.

Порядок имеет значение: правила применяются сверху вниз, первое совпавшее
выигрывает; не совпало ни одно → **Default traffic** из Channels.

> **Presets** — read-only каталог готовых правил. Не применяются сами по себе:
> копируете нужное в Rules (Copy to Rules), дальше это ваше правило.

---

## 4. DNS — как резолвятся имена

**За что отвечает:** как имя сайта превращается в IP. Отдельный слой со своими
правилами.

- **DNS Final** — резолвер по умолчанию для запросов приложений, если ни одно
  DNS-правило не сматчило. По умолчанию `local_dns_resolver` (системный DNS —
  быстро и здесь безопасно для запросов приложений).
- **Default Domain Resolver** — внутренний резолв самого sing-box (адреса
  серверов, домены в правилах маршрутизации). По умолчанию `cloudflare_udp`.
  **Не ставьте сюда `local_dns_resolver`** — системный DNS течёт к провайдеру
  мимо VPN.
- **DNS-серверы** — каталог (Cloudflare/Google/Yandex/Quad9/AdGuard, UDP/DoT/DoH).
  У каждого выбирается, через какой канал он ходит (**Outbound/detour**) и
  IP/профиль. Хотите, чтобы DNS «нужных» приложений шёл через туннель (забугорный
  резолвер видел IP сервера, а не провайдера) — выберите серверу Outbound = ваш
  VPN-канал.
- **DNS Rules** — какие домены каким DNS-сервером резолвить. Правило
  маршрутизации может само завести DNS-правило (опция **DNS** в редакторе
  правила) — не нужно собирать вручную.

## Частые непонятки

**«Allow-list не работает — добавил приложение, а VPN на него не действует.»**
Проверьте **Channels → Default traffic = VPN**. Allow-list только впускает; куда
вести — решает Channels. С Default = Direct захваченные приложения идут напрямую.

**«Заработало, только когда добавил сам L×Box в Allow-list.»**
Скорее всего сработало не самодобавление, а Default traffic = VPN (если меняли
обе опции). Сам L×Box в туннеле не нуждается — его служебный трафик и DNS идут
мимо tun по дизайну.

**«Хочу: только браузер через VPN, остальное напрямую.»**
Allow-list = только браузер; Channels Default = VPN. Остальные приложения L×Box
не трогает.

**«Хочу: всё через VPN, но рекламу резать и .ru напрямую.»**
Allow-list = Off (или все нужные); Channels Default = VPN; Rules: реклама →
Block, `.ru` → Direct.

**«DNS-запросы видны провайдеру / идут мимо VPN.»**
Для приложений: DNS Final — зашифрованный сервер (`google_doh`/`cloudflare_dot`)
или сервер с Outbound = VPN-канал. Для внутреннего резолва: Default Domain
Resolver ≠ `local_dns_resolver`.

## Порядок настройки с нуля

1. **Подписки** — добавить (URL/буфер/QR). Появятся серверы и каналы.
2. **Channels** — проверить, что Default traffic = **VPN** (если хотите, чтобы по
   умолчанию всё шло через туннель).
3. **Allow-list** — по желанию: Off (всё через L×Box) или Allow-list (только
   выбранные приложения).
4. **Rules** — исключения: реклама → Block, локальные домены → Direct, и т.п.
   (можно скопировать из Presets).
5. **DNS** — по желанию: зашифрованный DNS Final, DNS через канал для приватности.
6. **Connect** — замочек. Готово.
