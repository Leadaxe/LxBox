# L×Box — как это работает

Руководство для пользователя: что есть что и за что отвечает. Не про код — про
**логику работы** и порядок настройки.

---

## Что есть что

Термины, в которых чаще всего путаются:

| Слово | Одной строкой | Аналогия |
|---|---|---|
| **Сервер** | Одна точка выхода (одна страна/узел), куда можно подключиться. | Дом, куда ведёт дорога. |
| **Подписка / папка** | **Откуда берутся** серверы: список от провайдера (подписка) или ваша ручная пачка (папка). | Адресная книга с домами. |
| **Канал** | **Группа серверов под задачу**: отбирает нужные серверы фильтром и переключает между ними. По каналам вы раскидываете трафик. | Полка, на которую вы ставите нужные дома. |
| **Tunnel apps** | **Кого впускаем** в L×Box вообще (какие приложения телефона). | Турникет на входе. |
| **Detour** («через») | Один сервер ходит **через** другой перед выходом в интернет (цепочка). | Дорога к дому идёт через другой дом. |
| **Правила (Rules / DNS)** | Исключения: какой трафик в какой канал и каким DNS резолвить. | Развилки на дорогах. |

Главное:

- **Сервер ≠ канал.** Сервер — это куда. Канал — это группа «куда» под конкретную
  задачу. Один и тот же сервер может входить в несколько каналов.
- **Подписка/папка — это НЕ канал.** Это просто источник серверов. Серверы из них
  сами по себе трафик никуда не гонят, пока не попадут в канал.
- **Detour — это не отдельный сервер и не канал.** Это надстройка «ходи через
  вот этого» поверх сервера/канала/папки.

## Общая картина: как трафик проходит через L×Box

Трафик приложения проходит **четыре ступени** — каждая отвечает за свой вопрос:

```
   Приложения на телефоне
            │
            ▼
 ┌─────────────────────────┐
 │ 1. Allow-list           │   «КОГО вообще впускаем в L×Box?»
 │    (Tunnel apps)        │   Не впущен → идёт мимо, как будто VPN выключен.
 └─────────────────────────┘
            │  (впущенный трафик)
            ▼
 ┌─────────────────────────┐
 │ 2. Channels             │   «КАКИЕ есть каналы и КУДА по умолчанию?»
 │    (Default traffic)    │   VPN = через туннель · Direct = напрямую.
 └─────────────────────────┘
            │
            ▼
 ┌─────────────────────────┐
 │ 3. Rules                │   «ИСКЛЮЧЕНИЯ из умолчания»
 │                         │   Какой домен/приложение — в какой канал.
 └─────────────────────────┘
            │
            ▼
   VPN-канал (сервер) · Direct · Block
            │
            ▼
 ┌─────────────────────────┐
 │ 4. DNS                  │   «КАК резолвятся имена сайтов»
 └─────────────────────────┘
```

Те же ступени одной строкой:

- **Allow-list** — *этот трафик вообще попадает в L×Box?*
- **Channels** — *каким выходным путём вести по умолчанию (через сервер или напрямую)?*
- **Rules** — *есть ли для него отдельное правило, переопределяющее умолчание?*
- **DNS** — *как для него узнать IP по имени сайта?*

Каждая ступень — отдельный фильтр, и они не заменяют друг друга.

## 1. Allow-list (Tunnel apps) — кого впускаем

**За что отвечает:** какие приложения вообще попадают под управление L×Box.

Три режима:

| Режим | Что значит |
|---|---|
| **Off** | Все приложения идут через L×Box (по умолчанию). |
| **Allow-list** | Через L×Box идут **только** выбранные. Остальные — мимо (обычная сеть). |
| **Deny-list** | Через L×Box идут **все, кроме** выбранных. |

Приложение, которое **не** захвачено (не в Allow-list / в Deny-list), L×Box
вообще не видит — его трафик идёт напрямую, как без VPN, и правила (Rules) к нему
**не применяются**.

> **Важно:** сам **L×Box добавлять в Allow-list НЕ нужно** — это ни на что не
> влияет. Приложение само через свой туннель не ходит (его служебные соединения
> и DNS идут мимо tun по физической сети). Если кажется, что «заработало после
> добавления себя» — почти всегда сработало что-то другое (обычно Default
> traffic = VPN, см. ниже).

### Allow VPN bypass — рядом по смыслу, но другое

Есть ещё один тумблер про «обход туннеля» — **Allow VPN bypass**
(**VPN Settings → Mode → Tunnel options**; виден в режимах с туннелем):

- **Выключен (по умолчанию)** — строгий туннель: весь впущенный трафик обязан
  идти через VPN, обойти его приложение не может.
- **Включен** — приложение, которое *само явно попросит систему* дать ему
  физическую сеть (через Android ConnectivityManager), сможет ходить мимо
  туннеля.

Разница с режимами выше: deny-list **принудительно** выводит выбранные
приложения из-под VPN, а Allow VPN bypass лишь **разрешает** обход тем, кто сам
попросит. Это разрешение, а не маршрут: включение само по себе ничего никуда не
переносит — обходить начнут только приложения, которые специально это умеют
(некоторые банковские клиенты, приложения операторов, звонилки).

Если цель «вывести конкретное приложение из VPN» — это deny-list. Bypass
включают, когда приложение конфликтует с VPN и умеет запрашивать обход само.
Большинству пользователей он не нужен. После переключения тумблера нужен
перезапуск VPN.

## Серверы, подписки и папки — откуда берутся выходы

> Эта часть — не про ступени трафика, а про то, **откуда в приложении вообще
> появляются серверы**. Люди путают три вещи: сервер, подписку и папку. Разница
> простая.

Всё, что даёт серверы, живёт на экране **≡ (меню) → Servers** («Subscriptions &
proxy»). Там три вида «источников», и они выглядят похоже, но ведут себя
по-разному:

| Источник | Что это | Сколько серверов | Обновляется |
|---|---|---|---|
| **Одиночный сервер** | Один сервер, добавленный вручную. | 1 | Никогда (вы его вставили руками). |
| **Подписка** | Список серверов **от провайдера** по ссылке. | много | Сама, по расписанию (или кнопкой «Update»). |
| **Папка** | **Ваша ручная пачка** серверов, сгруппированная под одним именем. | сколько положите | Никогда (вы ей управляете вручную). |

### Одиночный сервер

Один сервер. Вы его добавили, вставив ссылку (`vless://…`, `vmess://…`,
`wg://…`, QR-код и т.п.) или из файла. Обновлять нечего — это статичная запись.
Подходит, когда у вас «просто один конфиг от друга/провайдера».

### Подписка

Ссылка от VPN-провайдера, за которой прячется **целый список серверов**. L×Box:

- сам скачивает список и держит его свежим (по умолчанию раз в сутки; есть кнопка
  ручного обновления);
- при неудачном обновлении **не стирает** старые серверы — продолжает работать на
  прошлом списке;
- показывает от провайдера полезную мету, если он её отдаёт: остаток трафика, дату
  окончания, ссылку на сайт/поддержку.

Есть и **файловая подписка** — когда список серверов вы импортируете из файла, а
не по ссылке. Она ведёт себя как подписка (много серверов под одним именем), но
сама не обновляется — обновляете, подсунув новый файл (**Edit source**).

> **Нет своей подписки?** На том же экране есть **Get WARP** — он бесплатно
> регистрирует Cloudflare WARP и добавляет как сервер. Подробнее — в конце гайда.

### Папка

Папка — это **ваша собственная группа серверов**, которые вы собрали руками. Не
путать с каналом:

- **Папка** отвечает на вопрос «*где лежат* эти серверы» (как папка с файлами:
  общее имя, общий переключатель вкл/выкл, порядок перетаскиванием).
- **Канал** отвечает на вопрос «*какие* серверы использовать для задачи» (см.
  следующий раздел).

Внутри папки — **члены** (members). Каждый член — это ровно один сервер. Члена
можно по отдельности включить/выключить, переставить, а также задать ему
персональный **detour** (см. раздел про detour). Подписку внутрь папки положить
нельзя — папка только для ручных серверов.

**Когда что заводить:**

- один конфиг → **одиночный сервер**;
- ссылка от провайдера → **подписка**;
- набор своих `.conf`/ссылок, которые хочется держать вместе (например «мои
  Mullvad») → **папка**.

### Как всё это попадает в каналы

Серверы из подписок, папок и одиночек **сами по себе трафик не гонят**. Они
складываются в общий пул серверов, а уже **каналы** выбирают из этого пула нужные
(по фильтру) и подключаются. Поэтому порядок такой: сначала добавили
подписку/папку/сервер → потом канал их подхватил.

> **Про «tag prefix».** У подписки и папки в настройках можно задать префикс —
> короткую метку, которая приписывается к именам всех её серверов. Это удобно для
> фильтров каналов: например, папке дали префикс `mullvad-`, и канал с фильтром
> `^mullvad-` автоматически соберёт ровно её серверы. Если фильтрами каналов не
> пользуетесь — префикс можно не трогать.

## 2. Channels — выходные пути

**За что отвечает:** это **выходные пути** — куда трафик может уйти наружу, и
какой путь используется **по умолчанию**.

По умолчанию каналов **три**: один **VPN-канал** (`vpn-1` — ваш основной
туннель) + два служебных — **Direct** и **Block**. Можно **подключить ещё**
VPN-каналы (например разные серверы/группы под разные задачи).

Каждый канал — это «выход»:
- **VPN-канал** (группа серверов из ваших подписок) — наружу через сервер
  (туннель);
- **Direct** — наружу напрямую (мимо туннеля, но всё ещё через L×Box);
- **Block** — никуда (блокировка).

**Default traffic** — какой выходной путь по умолчанию: **VPN** (через сервер)
или **Direct** (напрямую). Применяется к захваченному трафику, для которого ни
одно правило (Rules) не сработало.

> **Это и есть причина частой путаницы.** Если приложение в Allow-list есть, но
> **Default traffic = Direct**, его трафик уходит **напрямую** — и кажется, что
> «VPN не работает». Поставьте **Default traffic = VPN** → пойдёт через туннель.
> Allow-list решает «впускать ли», Channels — «куда вести». Это две разные вещи.

**Авто-выбор узла.** У VPN-канала можно включить авто-двойник (`<канал>-auto`),
который сам выбирает узел из группы. В редакторе канала — два режима:

- **Fastest** — весь трафик идёт на один самый быстрый узел (по замеру задержки).
- **Load balance** — трафик распределяется по пулу из нескольких живых узлов;
  сессии «прилипают» к узлу (sticky), чтобы не рвать соединения при ротации.

**Как канал набирает серверы (фильтр).** Канал не хранит серверы внутри себя — он
**отбирает** их из общего пула (все ваши подписки + папки + одиночки). В редакторе
канала есть **Node filter** — фильтр по имени сервера:

- пусто → в канал попадают **все** серверы;
- текст/regex (например `🇩🇪` или `^mullvad-`) → только серверы, чьё имя совпало;
- галка инверсии → наоборот, все **кроме** совпавших.

Поэтому **один и тот же сервер может входить в несколько каналов сразу**. Канал — это не «место, где
лежит сервер», а «правило отбора серверов под задачу». Пример: канал «Стриминг» с
фильтром `🇩🇪` соберёт все немецкие серверы из всех источников; они же останутся
доступны и в основном канале `vpn-1`.

> **`vpn-1` — особенный.** Первый канал всегда есть, его нельзя удалить, и на него
> «падают» ссылки, если удалить другой канал. Считайте его каналом по умолчанию.
> Всего каналов может быть до 10.

## 3. Rules — как разруливаем

**За что отвечает:** исключения из умолчания. Какой конкретно трафик в какой
канал.

Правило матчит по полям (домены, приложения, подсети, порты, протоколы, Wi-Fi) и
направляет в выбранный канал (VPN-группа / Direct / Block). Внутри одной
категории — ИЛИ, между категориями — И (как в sing-box).

Типичные правила:
- реклама/трекеры → **Block**;
- российские домены (`.ru/.рф/…`) → **Direct** (быстрее и без нужды в VPN);
- BitTorrent → нужный канал;
- конкретное приложение → конкретный канал.

Порядок имеет значение: правила применяются сверху вниз, первое совпавшее
выигрывает; не совпало ни одно → **Default traffic** из Channels.

> **Presets** — read-only каталог готовых правил. Не применяются сами по себе:
> копируете нужное в Rules (Copy to Rules), дальше это ваше правило.

## 4. DNS — как резолвятся имена

**За что отвечает:** как имя сайта превращается в IP. Отдельный слой со своими
правилами.

- **DNS Final** — резолвер по умолчанию для запросов приложений, если ни одно
  DNS-правило не сматчило. По умолчанию `cloudflare_udp` (1.1.1.1) — запросы
  приложений идут на публичный резолвер, а не на системный DNS провайдера.
  Хотите приватности — поставьте зашифрованный (`google_doh` / `cloudflare_dot`)
  или сервер с Outbound = VPN-канал (см. ниже).
- **Default Domain Resolver** — внутренний резолв самого sing-box (адреса
  серверов, домены в правилах маршрутизации). По умолчанию `cloudflare_udp`.
  **Не ставьте сюда `local_dns_resolver`** — системный DNS течёт к провайдеру
  мимо VPN.
- **DNS-серверы** — каталог (Cloudflare/Google/Yandex/Quad9/AdGuard, UDP/DoT/DoH).
  У каждого выбирается, через какой канал он ходит (**Outbound/detour**) и
  IP/профиль. Хотите, чтобы DNS «нужных» приложений шёл через туннель (забугорный
  резолвер видел IP сервера, а не провайдера) — выберите серверу Outbound = ваш
  VPN-канал.
- **DNS Rules** — какие домены каким DNS-сервером резолвить. Правило
  маршрутизации может само завести DNS-правило (опция **DNS** в редакторе
  правила) — не нужно собирать вручную.

## Detour — «ходить через» (цепочки серверов)

**Что это.** Detour — это когда один сервер выходит в интернет **не напрямую, а
через другой сервер**. То самое «через», которым это обычно и объясняют:

```
  вы → [Сервер A] → [Сервер B] → интернет
                    ▲
              это detour A: «сервер A ходит ЧЕРЕЗ сервер B»
```

Зачем это нужно:

- **обойти блокировку по географии выхода** — заходите через сервер A (быстрый,
  близкий), а в интернет выходите с IP сервера B (нужная страна);
- **пробить блокировку самого сервера** — если до сервера B напрямую не достучаться
  из вашей сети, но до A — можно, а A видит B;
- **двойной прыжок ради приватности** — ни один сервер не видит одновременно и вас,
  и конечный сайт.

Detour — это **надстройка**, а не отдельная сущность. Вы берёте уже имеющийся
сервер и говорите ему «а ходи-ка ты через вот этого». Целью detour может быть:

- **другой сервер** (одиночка или член папки);
- **канал** — тогда цель не фиксирована: ядро само выберет лучший сервер из
  канала в момент подключения (это и есть **detour-канал**);
- **None (direct)** — без detour, сервер ходит напрямую (значение по умолчанию).

### Где настраивается

Detour задаётся **у источника серверов**, через единый пикер «выбери, через кого
ходить». Точка входа зависит от того, кому назначаете:

| Кому назначаете detour | Где | Действует на |
|---|---|---|
| **Одному серверу** | Node Settings (тап по серверу) | только этот сервер |
| **Всей подписке** | Subscription → вкладка **Settings** | все серверы подписки |
| **Всей папке** | Folder → вкладка **Settings** | всех членов папки |
| **Одному члену папки** | внутри папки, у члена | только этот член |

В пикере вы увидите разделы: **None (direct)**, **Channels** (если есть
detour-каналы), **This folder** (члены той же папки, когда настраиваете члена) и
**Standalone servers** (одиночки). Выбрали — сохранили.

### Цепочки

Detour можно выстраивать в **цепочку**: A через B, B через C — тогда трафик идёт
`вы → A → B → C → интернет`. Внутри папки можно строить такие цепочки прямо между
её членами (член ходит через другого члена той же папки). L×Box **сам защищает от
петель** — если случайно замкнёте цепочку в кольцо, замыкающее звено разорвётся.
Член, который служит промежуточным звеном для другого, помечается значком ⚙.

### Detour-каналы

Обычный канал можно пометить как **detour-канал** (галка в редакторе канала). Тогда
он перестаёт быть «пунктом назначения» для правил и становится **переключаемой
прослойкой**: любой сервер может ходить «через этот канал», а какой именно сервер
внутри канала будет использоваться — решает ядро (по скорости). Удобно, когда
промежуточный узел хочется иметь не жёстко прибитым, а «лучшим из группы».

### Ограничения

- **Нельзя строить цепочку из AmneziaWG в обычный WireGuard** — это подвешивает
  ядро, поэтому такие цели просто не показываются в пикере, а если старый выбор
  стал недопустимым — он сбрасывается на None.
- Detour **не превращается в VPN-поверх-VPN на уровне ОС** — вся цепочка живёт
  внутри одного туннеля L×Box, это выгоднее по ресурсам.

### Как проверить, что detour работает

Включите VPN, откройте **Statistics** (доступно при поднятом туннеле) и загляните
в детали соединения — там есть строка **Detour**, показывающая цепочку выходов
(`A → B → …`), и строка **Chain**. Так видно, реально ли трафик пошёл через
промежуточный сервер.

## IPv6 — когда включать (обычно — не надо)

По умолчанию IPv6 в туннеле **выключен**, а все стратегии резолва стоят в
`ipv4_only`. Это намеренно: на многих сетях (особенно мобильных) глобальный
IPv6 работает наполовину — адрес выдаётся, но соединения по нему виснут. Тогда
сайты, у которых есть IPv6-адрес, перестают открываться, хотя VPN формально
«работает». Если не уверены, что на вашей сети IPv6 живой, — не включайте.

Настроек, связанных с IPv6, несколько, и разложены они по разным местам:

| Настройка | Где | Что делает |
|---|---|---|
| **Enable IPv6** | VPN Settings → Core → TUN | Даёт туннелю IPv6-адрес. Главный тумблер. |
| **IPv6 address** | там же | IPv6-адрес туннеля. Применяется только при включённом Enable IPv6. |
| **Preferred IP version** | VPN Settings → Core → DNS | Какие адреса предпочитать при DNS-резолве (`ipv4_only` / `prefer_ipv4` / …). |
| **Resolve strategy** | VPN Settings → Core → Network | То же, но для резолва доменов внутри правил маршрутизации. |
| **Force IPv4** | галка в «российских» пресетах (Routing) | Резолвить российские домены только в IPv4. Включена по умолчанию. |

Руками всё это синхронизировать не нужно — главный тумблер делает это сам.
Включили **Enable IPv6** → обе стратегии переключаются в `prefer_ipv4` (IPv6
используется, но IPv4 в приоритете — безопасный режим). Выключили → обратно в
`ipv4_only`. Менять стратегии вручную имеет смысл, только если понимаете зачем
(например `prefer_ipv6` на сети с полноценным IPv6).

Порядок включения, если IPv6 действительно нужен:

1. Убедиться, что сеть отдаёт рабочий глобальный IPv6 (без VPN открываются
   IPv6-only ресурсы).
2. **VPN Settings → Core → TUN → Enable IPv6**.
3. **Перезапустить VPN** (Stop → Start, а не просто пересохранить): системный
   DNS-кэш Android сбрасывается только рестартом туннеля, иначе старые адреса
   ещё какое-то время будут всплывать.
4. Если после этого российские сайты стали виснуть — проверить, что в
   «российских» пресетах включена галка **Force IPv4**.

## Частые непонятки

**«Allow-list не работает — добавил приложение, а VPN на него не действует.»**
Проверьте **Channels → Default traffic = VPN**. Allow-list только впускает; куда
вести — решает Channels. С Default = Direct захваченные приложения идут напрямую.

**«Заработало, только когда добавил сам L×Box в Allow-list.»**
Скорее всего сработало не самодобавление, а Default traffic = VPN (если меняли
обе опции). Сам L×Box в туннеле не нуждается — его служебный трафик и DNS идут
мимо tun по дизайну.

**«Хочу: только браузер через VPN, остальное напрямую.»**
Allow-list = только браузер; Channels Default = VPN. Остальные приложения L×Box
не трогает.

**«Хочу: всё через VPN, но рекламу резать и .ru напрямую.»**
Allow-list = Off (или все нужные); Channels Default = VPN; Rules: реклама →
Block, `.ru` → Direct.

**«DNS-запросы видны провайдеру / идут мимо VPN.»**
Из коробки DNS приложений уже не идёт через системный резолвер провайдера
(DNS Final = `cloudflare_udp`). Хотите скрыть и сами домены — DNS Final ставьте
зашифрованный (`google_doh`/`cloudflare_dot`) или сервер с Outbound = VPN-канал.
Для внутреннего резолва: Default Domain Resolver ≠ `local_dns_resolver`.

**«Чем канал отличается от подписки/папки?»**
Подписка и папка — это **откуда берутся** серверы (источник). Канал — это **группа
серверов под задачу**, он отбирает нужные серверы из всех источников фильтром. Один
сервер может входить в несколько каналов. Добавили подписку/папку → серверы попали
в общий пул → каналы их подхватили.

**«Добавил папку/подписку — а трафик не идёт через неё.»**
Источник серверов сам по себе трафик не гонит. Проверьте, что её серверы попадают
в активный канал (фильтр канала пустой или совпадает с их именами) и что
**Default traffic = VPN**.

**«Что такое detour и зачем он?»**
Detour — это «ходить **через**»: сервер выходит в интернет не напрямую, а через
другой сервер (цепочка `вы → A → B → интернет`). Нужен, чтобы выйти с IP другой
страны, пробить блокировку самого сервера или сделать двойной прыжок. Задаётся у
сервера/подписки/папки в их настройках. Значение по умолчанию — None (без detour).

**«Выбрал сервер целью detour, а он пропал / сбросился на None.»**
Скорее всего цель — обычный WireGuard, а исходный сервер — AmneziaWG: такую цепочку
ядро не тянет, поэтому выбор недоступен. Возьмите целью не-WG сервер или канал.

**«Включил IPv6 — сайты (особенно российские) перестали открываться.»**
Признак сети с нерабочим IPv6: домен резолвится в IPv6-адрес, соединение виснет.
Выключите **Enable IPv6** (VPN Settings → Core → TUN) и перезапустите VPN.
Подробнее — раздел про IPv6 выше.

## Порядок настройки с нуля

> **Где что искать.** Разделы открываются из **бокового меню** — свайп от левого
> края или иконка **≡** на главном экране: *Servers* (серверы/подписки/папки),
> *Routing* (каналы, правила, tunnel apps), *DNS Settings*.

1. **Источник серверов** — меню → **Servers** → добавить, выбрав тип под ситуацию:
   - один конфиг → **одиночный сервер** (вставить ссылку/QR/файл);
   - ссылка провайдера → **подписка** (по URL — сама обновляется);
   - своя пачка серверов → **папка**.

   Нет подписки? **Get WARP** выдаст рабочий сервер без неё (см. ниже).
2. **Channels** (меню → Routing → Channels) — проверить, что Default traffic =
   **VPN** (если хотите, чтобы по умолчанию всё шло через туннель).
3. **Allow-list** (Routing → Tunnel apps) — по желанию: Off (всё через L×Box) или
   Allow-list (только выбранные приложения).
4. **Rules** (Routing → Rules) — исключения: реклама → Block, локальные домены →
   Direct, и т.п. (можно скопировать из Presets).
5. **DNS** (меню → DNS Settings) — по желанию: зашифрованный DNS Final, DNS через
   канал для приватности.
6. **Detour** — по желанию: если нужен выход через цепочку серверов, задайте его в
   настройках сервера/подписки/папки (см. раздел про detour).
7. **Connect** — замочек. Готово.

## Get WARP — сервер без подписки

Нет своей подписки? На экране подписок есть **Get WARP** — визард, который
регистрирует бесплатный Cloudflare WARP и добавляет его как сервер. Приватный
ключ генерируется на телефоне и его не покидает. Доступны транспорты WireGuard
и **MASQUE** (Cloudflare QUIC/CONNECT-IP) — MASQUE лучше проходит там, где
обычный WireGuard режут.

## Список серверов — поиск и метки

**Фильтры.** Над списком серверов на главном экране — фильтры: текстовый
(по имени/regex), чипы по подписке, по протоколу, по транспорту. Слева от
текстового поля есть тумблер **`!`** — он инвертирует фильтр (показать всё,
что **не** совпадает); такой же тумблер есть у чипов. Настройки фильтра
запоминаются отдельно для каждого канала.

**Эмодзи-метки.** У сервера есть эмодзи-метка в теге. Её можно поменять в
**Node Settings** (кнопка-пикер эмодзи), а при добавлении сервера метка
подставляется автоматически по стране/имени.

## Быстрое подключение

Не обязательно открывать приложение, чтобы включить VPN:

- **Плитка в шторке (Quick Settings).** Добавьте плитку L×Box в панель быстрых
  настроек (шторка → карандаш/редактирование плиток). Тап включает/выключает
  VPN последним использованным профилем.
- **Ярлык на рабочем столе.** Ярлык быстрого подключения так же переключает VPN
  одним нажатием, без открытия основного экрана.

При активном подключении в уведомлении есть кнопки **Stop** и **Reconnect** —
переподключиться можно прямо из шторки.

## Автоматизация — включать VPN по событиям

L×Box умеет управляться из приложений-автоматизаторов (**Tasker, MacroDroid,
Llama, Automate**) — телефон сам включает/выключает VPN и переключает серверы по
событиям, без вашего участия. Типичные сценарии:

- подключаться к домашнему Wi-Fi → **выключать** VPN, к чужому/публичному →
  **включать**;
- запуск конкретного приложения → переключиться на нужный сервер/канал;
- по расписанию или по геозоне — включать/выключать туннель.

Автоматизация **по умолчанию выключена**. Включается в **App Settings →
Automation** (там же можно разрешить L×Box отдавать наружу свои события —
подключился/отключился/обновилась подписка), после чего в автоматизаторе
выбираете L×Box как плагин и нужную команду (Start / Stop / Reconnect / выбрать
сервер и т.п.).

> **Полная инструкция** со списком всех команд, событий и готовыми рецептами
> (в том числе управление из shell/ADB) — в [AUTOMATION.md](AUTOMATION.md).

## Backup — перенос настроек

В приложении есть экран **Backup** (экспорт/импорт настроек). Он делает снапшот
вашей конфигурации: подписки, каналы, правила (Rules) и настройки приложения.
Экспорт сохраняет снапшот в файл, импорт — восстанавливает его (с предпросмотром
перед применением). Это удобный способ перенести настройки на новый телефон или
сохранить их перед переустановкой.
