# Руководство для агентов (L×Box)

Роутер для AI-агентов и автоматизации: правила по ссылкам ниже **обязательны**.

## Принцип: читать лениво, экономить процессорное время и токены

- Не читать файлы целиком, когда хватает `grep` / `sed -n`; доки — только по ссылке из задачи.
- Не гонять тесты, чекеры и сборки ради того, что проверит CI; вывод резать (`tail`/`grep`).
- Разведку и разбор вывода — дешёвым субагентам (Sonnet), думающие модели — на решения.
- Любой прогон тестов, который идёт минуты и даёт длинный вывод, **всегда**
  оформляется как ТЗ и запускается Sonnet-субагентом: он гоняет, резюмирует
  (статус, упавшие тесты с файлом и строкой, первый стек), в контекст — только
  резюме. Самому такой прогон не запускать, контекст не засорять.
- Подробно — `docs/DEVELOPMENT_GUIDE.md` → «Lazy reading: save CPU and tokens».

## Методология: spec-driven — как ставить задачи и вести процесс

- **Сначала спека, потом код** — `docs/DEVELOPMENT_GUIDE.md` → «The development
  process»: спека → реализация → проверка → коммит; там же, что делается только
  по явной команде оператора (force-push, `main`, теги, `gh pr create`).
- **Структура спек и соглашения** (фичи / задачи / процессы, нумерация, карта
  обновления документации) — `docs/spec/README.md`.
- **Фича** («что это и как работает», `NNN name/spec.md` + `plan.md` + `tasks.md`)
  — `docs/spec/features/README.md`.
- **Задача** (один рабочий цикл: проблема → диагностика → решение → проверка,
  `NNN-title.md`, шаблон и критерии) — `docs/spec/tasks/README.md`.
- **Повторяющиеся регламенты** — `docs/spec/processes/`.
