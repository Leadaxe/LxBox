# L×Box v2.5.0

**Полный отказ от Clash API.** Управляющий канал переведён с Clash HTTP на нативный libbox **CommandClient** (push-стримы из ядра вместо опроса по таймеру). Это закрытый порт, меньше расхода батареи, ядро **sing-box-lx 1.14**. На этом фундаменте — переработанный профайлер трафика, серия фиксов конфиг-падений и UI-улучшения.

## ✨ Что нового

| Что | Суть | Зачем |
|---|---|---|
| **Отказ от Clash API** (§121/§122) | UI работает напрямую через libbox CommandClient: статус, группы, соединения, URLTest — push-стримом из ядра, без HTTP-опроса | Закрыт TCP-порт `127.0.0.1` (его мог дёрнуть любой апп) → **безопаснее**. В фоне 0 опросов → **меньше батареи**. Доступ к возможностям ядра 1.14 |
| **Энергомодель** (§164) | Адаптивная частота обновлений (медленнее на главном, быстрее в Stats) + полный сон в фоне | Главный экран — 2 обновления/с вместо 10; в фоне — ноль. Заметно меньше расход на сотовой |
| **Профайлер: вкладка Profiler** (§044, бывш. Live) | Управление свёрнуто в одну строку; запись/пауза/экспорт; **настраиваемое окно хранения** (1/10/60 мин); фильтр вынесен в окно (по протоколу DNS/TCP/UDP и по приложению) | Видно весь трафик устройства в реальном времени — кто куда ходит, через какую ноду, какие DNS-резолвы. Удобный фильтр и история до часа |
| **Трассировка маршрута** (§181) | В деталях события — читаемая цепочка `приложение ⇒ правило ⇒ группа ⇒ нода → detour → домен` + полный detour-хвост (§178) | Сразу видно, через какое правило и какие серверы реально пошёл трафик |
| **DNS из ядра** (§180) | DNS-журнал берётся структурным потоком из ядра (атрибуция к приложению — из ядра, CNAME-цепочка одним событием) | Точнее, чем парсинг логов: видно какое приложение что резолвило, включая провалы |
| **Кнопки в уведомлении** (§182) | Stop / Reconnect прямо в шторке | Перезапустить туннель в один тап, даже при закрытом приложении |
| **Имена правил в Stats/Conns** (§165/§166) | Соединения показывают название правила (`Home wifi`), а не обрезок условий | Понятно, по какому правилу пошло соединение |
| **Ошибки — всплывашкой снизу** (§166) | Ошибки (включая пинг) показываются снизу, не красным баннером сверху | Не загораживает экран, привычнее |
| **Правила: source-IP / inbound** (§030) | Custom-правила по источнику (`source_ip_cidr`, приватный источник) и по входу (TUN / прокси) + быстрые CIDR-пресеты (localhost, подсеть, всё) | Гибче разделять трафик; меньше ручного ввода |

## 🐛 Исправлено

| # | Было | Стало |
|---|---|---|
| §169 | Битый REALITY-ключ из публичной подписки (`pbk=enabled`) ронял **весь** конфиг → VPN не вставал | REALITY включается только при валидном ключе, иначе деградация в обычный TLS — нода остаётся рабочей |
| §172 | Битый `detour` (на отсутствующий сервер) ронял **весь** конфиг как fatal | Снимается автоматически перед валидацией — конфиг валиден, нода идёт напрямую, в предупреждениях |
| §170 | Заход в Stats во время записи Live крашил процесс (гонка в ядре) | Обойдено по-клиентно — стабильно под трафиком и стрессом |
| §173 | После миграции не настраивался OOM-лимит и потерян crash-канал | `SetupOptions` с memory-лимитом + восстановлен crash-репорт |
| §143 | «Обрыв соединений при смене ноды» не работал после миграции | Восстановлен — старый трафик сразу уходит на новую ноду |
| §171 | DNS-резолвы не показывались в Live-журнале профайлера | Показываются — починен разбор conn_id (голые ESC-байты в логе ядра) |
| detour-схема | На экране подписки цепочка detour рисовалась задом наперёд | `Телефон → detour → ноды → Интернет` (detour входной, как и есть физически) |

(Полный список — в [CHANGELOG](../../CHANGELOG.md).)
